# K-STE 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한국어 업무 글을 위한 범용 Agent Skill `k-ste`를 만들고, 평가하고, 배포하고, 로컬에 적용한다.

**Architecture:** 스킬 본문(`SKILL.md`)에는 상시 규칙 11개만 둔다. 재작성 절차, 장르 패턴, 대체어 표는 `references/`에 둔다. 웹 채팅·자동화용 붙여넣기 프롬프트는 `prompts/system-prompt.md`에 둔다. 평가는 `claude -p` 격리 실행과 결함 계수기, 블라인드 판정으로 한다.

**Tech Stack:** Markdown, Bash, Python 3 표준 라이브러리, Claude Code CLI 2.1.300, `npx skills`.

**Spec:** `docs/superpowers/specs/2026-10-15-k-ste-design.md`

## Global Constraints

- 스킬 이름: `k-ste`. 경로: `skills/k-ste/SKILL.md`.
- 문체: 답변 합니다체, 문서 한다체. 저장소의 문서 파일은 한다체로 쓴다.
- 짧은판: 1,500자 이내.
- 다른 저장소의 문장과 국립국어원 예문을 복사하지 않는다. 규칙 문장과 예문은 직접 쓴다.
- 평가 격리: `claude -p ... --setting-sources "" --system-prompt "<조건>" --tools ""`.
- 평가 도구는 Python 표준 라이브러리만 쓴다.
- 모델: 생성 `sonnet`, `haiku`. 판정 `opus`.

## Review Focus

1. 코드 블록 안의 볼드·물결표·엠대시: 계수기가 세면 안 된다. `score.py` 자체 시험에 넣는다.
2. 표 행과 목록 항목의 명사형 종결: 목록과 표는 예외다. 본문 문장만 센다. `score.py` 자체 시험에 넣는다.
3. 범위 물결표와 "약 ~" 같은 일반 물결표: 숫자 사이 물결표만 센다. `score.py` 자체 시험에 넣는다.
4. 사용자가 영어 텍스트를 재작성해 달라고 할 때: 스킬은 한국어 전용이다. `SKILL.md`에 범위를 적는다.
5. 긴 대화에서 규칙이 흐려짐: S10이 확인한다.

### Task 1: 평가 하네스

**Files:**
- Create: `evals/scenarios.md`, `evals/scenarios/S1.txt` - `S10.txt`
- Create: `evals/score.py`, `evals/run.sh`, `evals/judge.py` (계획 당시 이름은 judge.sh)

**Interfaces:**
- Produces:
  - `evals/run.sh <condition> <model> [SID...]`. `condition`은 `base|short|full`이다. 결과는 `evals/results/<RUN>/<model>/<condition>/<SID>.md`에 쓴다. `RUN`은 환경 변수이고 기본값은 오늘 날짜다.
  - `python3 evals/score.py <dir>...`: 디렉터리마다 지표 합계를 표로 출력한다. `--self-test`는 내장 시험을 실행한다.
  - `python3 evals/judge.py <results-root>`: S5·S6·S7·S1·S2·S10 결과를 블라인드 판정한다. 결과는 `<results-root>/judge.jsonl`에 쓴다.
  - 프롬프트 블록 표지: `prompts/system-prompt.md` 안의 `<!-- short:start -->`/`<!-- short:end -->`, `<!-- full:start -->`/`<!-- full:end -->`.

- [ ] **Step 1:** `score.py`의 자체 시험을 먼저 쓴다. 시험 항목은 다음과 같다.
  - `**굵게**` 1개 → bold 1. 코드 블록 안의 `**x**` → 0.
  - `3~5개` → tilde_range 1. `약 ~10%`처럼 숫자 사이가 아닌 물결표 → 0.
  - 본문 `확인함.` → nominal 1. 목록 `- 확인함` → 0. 표 행 → 0.
  - `보여집니다` → double_passive 1.
  - `작업을 진행했습니다` → jinhaeng 1.
  - 한 텍스트에 `합니다.`와 `한다.`가 섞임 → style_mixed 1 이상.
  - `궁금한 점이 있으면` → closer 1.
- [ ] **Step 2:** `python3 evals/score.py --self-test`를 실행한다. 구현 전이므로 실패해야 한다.
- [ ] **Step 3:** 지표를 구현한다.

| 지표 | 정규식 / 규칙 |
|---|---|
| bold | `\*\*[^*\n]+\*\*` |
| emdash | `—` 또는 공백으로 둘러싼 `–` |
| header | `^#{1,6}\s` (S3·S4는 결함 합계에서 뺀다) |
| emoji | `[\U0001F300-\U0001FAFF☀-➿]` |
| tilde_range | `\d\s*~\s*\d` |
| closer | `궁금한 (점\|사항)\|도움이 되(었\|셨\|길)\|더 필요하(시면\|신)\|언제든(지)? \|좋은 질문\|물론입니다` |
| nominal | 본문 문장이 `(함\|됨\|음\|임\|바람)\.?$`로 끝남. 목록·표·헤더 제외 |
| double_passive | `되어지\|되어져\|보여지\|보여져\|불려지\|쓰여지\|잊혀지` |
| jinhaeng | `(진행\|실시\|수행)(하\|했\|합\|할\|해\|됩\|되\|된)` |
| not_but | `(이\|가) 아니라` |
| style_mixed | 합니다체 종결 수와 한다체 종결 수 중 작은 값 |
| max_eojeol | 본문 문장의 최대 어절 수 (보고용, 결함 합계 제외) |

  계수 전에 펜스 코드 블록과 인라인 코드를 지운다.
- [ ] **Step 4:** 자체 시험이 통과하는지 확인한다.
- [ ] **Step 5:** 시나리오 프롬프트 10개를 쓴다. 각 프롬프트는 사실을 모두 제공한다. 그래야 모델이 사실을 지어낼 이유가 없다.
- [ ] **Step 6:** `run.sh`와 `judge.sh`를 쓴다. `run.sh`는 `xargs -P 6`으로 병렬 실행한다.
- [ ] **Step 7:** `base` 조건으로 S1 하나만 실행해서 하네스를 확인한다.
- [ ] **Step 8:** 커밋한다.
