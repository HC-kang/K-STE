# K-STE 설계

- 날짜: 2026-10-15
- 상태: 승인됨

## 목적

AI가 업무 중에 만드는 한국어 텍스트를 사용자, 개발자 동료, 비개발자 동료가 한 번에 이해하게 한다. ASD-STE100의 원칙(한 단어 한 의미, 짧은 문장, 조건 먼저, 능동형)을 한국어 업무 글에 맞게 옮긴다.

성공 기준은 다음과 같다.

1. 독자가 보는 결함(볼드 남용, 엠대시, 맺음 제안, 문체 혼용, 군말)이 기준선보다 줄어든다.
2. 재작성할 때 원문의 사실, 조건, 수치, 확신 정도, 의무 강도가 바뀌지 않는다.
3. 같은 규칙이 코딩 에이전트, 웹 채팅, 사내 자동화에서 동작한다.

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 적용 방식 | 상시 적용 + 요청 시 재작성·검수 | 사용자 선택 |
| 실행 환경 | 코딩 에이전트, 웹 채팅, 사내 자동화 | 사용자 선택 |
| 답변 서식 | 기본 줄글. 3개 이상 단계·조건은 목록, 같은 기준 비교는 표 | 사용자 선택 |
| 문체 | 답변 합니다체, 문서 한다체. 한 텍스트 안에서 섞지 않음 | 사용자 선택 |
| 접근안 | 새로 쓴다. ko-ste, ste-ko, SimpleEnglish의 검증된 아이디어를 가져온다 | 기존 스킬은 서로 규칙이 충돌하고, ste-ko는 규칙이 73개로 무겁다 |
| 출처 표기 | 스킬 파일에 넣지 않는다. 규칙 문장과 예문은 모두 직접 쓴다 | 다른 저장소의 문장이나 국립국어원 예문을 복사하지 않으면 표기 의무가 없다 |
| 문장 길이 | 지시문 20어절, 설명문 25어절. 검토 신호로만 쓴다 | 한국어 공공 지침에 수치 기준이 없다. 1차 기준은 "한 문장 한 정보"다 |

## 조사에서 얻은 근거

- 국립국어원 지침은 문장 길이를 수치로 정하지 않는다. "한 문장에 정보 한두 개", "문단 5-8문장", "명사 3개 이상 연쇄 금지" 같은 대리 기준을 쓴다.
- 현재 Claude 한국어 출력은 사람 글보다 문장이 짧다(중앙값 8어절, 사람 11어절, ko-ste 측정). 실제 결함은 볼드·표·맺음 제안 남용과 과잉 압축이다.
- "~에 대해", "~를 통해"는 사람 글에 더 많다(im-not-ai 측정). 그래서 일괄 금지하지 않는다.
- SimpleEnglish 감사(2026-09-02)에서 8줄 프롬프트가 규칙 53개짜리 스킬을 독자 체감 지표에서 이겼다. 규칙이 많으면 핵심 규칙이 묻힌다.
- 같은 감사에서 린터 점수는 규칙 준수율을 쟀을 뿐이고 독자 체감과 달랐다.

## 저장소 구조

```
K-STE/
├── README.md                    설치, 사용법, 환경별 적용법
├── skills/k-ste/
│   ├── SKILL.md                 상시 규칙 + 모드 안내
│   └── references/
│       ├── rewrite.md           재작성·검수 절차, 의미 보존 규칙
│       ├── genres.md            장르별 패턴
│       └── word-swaps.md        번역투·군말·AI 슬롭 대체어 표
├── prompts/
│   └── system-prompt.md         붙여넣기용 전체판 + 짧은판
└── evals/
    ├── scenarios.md             시나리오와 통과 기준
    ├── scenarios/S*.txt         시나리오 프롬프트
    ├── run.sh                   격리 실행 (base, short, full)
    ├── agent_path.sh            코딩 에이전트 경로 실행 (agent, agent+short)
    ├── trace.py                 stream-json 기록에서 스킬 실행과 답변을 뽑음
    ├── score.py                 독자가 보는 결함 계수기 (평가 전용)
    ├── judge.py                 블라인드 판정
    └── results/                 실행 결과 원본과 NOTES.md
```

`evals/score.py`는 평가 전용이다. 스킬에 포함하지 않는다.

## 환경별 적용

| 환경 | 상시 적용 | 요청 시 재작성 |
|---|---|---|
| 코딩 에이전트 | `CLAUDE.md`·`AGENTS.md`에 짧은판을 넣는다 | `npx skills add HC-kang/K-STE`로 스킬을 설치한다 |
| 웹 채팅 | 맞춤 지침에 짧은판을 넣는다 | Claude.ai는 스킬을 업로드한다. ChatGPT·Gemini는 전체판을 붙여 넣는다 |
| 사내 자동화 | 시스템 프롬프트에 전체판을 넣는다 | 동일 |

상시 적용을 스킬 자동 실행에 맡기지 않는다. 스킬은 모델이 필요하다고 판단할 때만 실행된다. 그래서 짧은 일반 답변에는 실행되지 않을 수 있다.

짧은판은 1,500자 이내로 만든다. ChatGPT 맞춤 지침 입력란의 제한에 맞추기 위해서다.

## 상시 규칙

0순위는 의미 보존이다. 다른 규칙과 충돌하면 의미 보존을 따른다.

- 사실, 조건, 수치, 범위 표지, 확신 정도, 의무 강도, 코드·식별자를 바꾸거나 빼지 않는다.
- 원문에 없는 사실을 더하지 않는다.

| ID | 규칙 |
|---|---|
| K1 | 결론(답, 결과, 현재 상태)을 첫 문장에 쓴다. |
| K2 | 한 문장에 정보 하나를 쓴다. 지시문 20어절, 설명문 25어절을 넘으면 나눌 곳을 살핀다. 자동으로 나누지 않는다. |
| K3 | 과잉 압축을 하지 않는다. 주어·조사·어미를 생략하지 않는다. 명사 3개 이상 나열을 풀어 쓴다. 본문을 명사형(-함/-됨/-음)으로 끝내지 않는다. |
| K4 | 같은 대상과 같은 동작에는 같은 단어를 쓴다. 동의어를 돌려 쓰지 않는다. |
| K5 | 행위자를 밝히고 능동형으로 쓴다. 이중 피동을 쓰지 않는다. 상태 보고("서비스가 중단됐습니다")는 허용한다. |
| K6 | 사실, 추론, 미확인을 구분한다. 실행하지 않은 검사를 통과했다고 쓰지 않는다. 헤지는 문장당 하나까지 쓴다. |
| K7 | 조건을 동작 앞에 쓴다. 지시문에는 대상과 행동을 명시한다. 한 단계에 동작 하나를 쓴다. |
| K8 | 전문용어는 유지한다. 비개발자가 모를 용어는 처음 나올 때 한 구절로 정의한다. 약어는 처음 나올 때 푼다. |
| K9 | 군말을 지운다. 인사, 맺음 제안, 자기 서술, 근거 없는 평가어, "A가 아니라 B" 대구, "핵심은 ~입니다", "진행/실시/수행하다"가 대상이다. |
| K10 | 서식은 기본이 줄글이다. 단계·조건이 3개 이상이면 목록, 같은 기준 비교는 표를 쓴다. 볼드는 경고에만 쓴다. 엠대시, 이모지, 두 문장짜리 헤더를 쓰지 않는다. 범위는 `3-5개`로 쓴다. |
| K11 | 답변은 합니다체, 문서는 한다체로 쓴다. 한 텍스트 안에서 문체를 섞지 않는다. 수치에는 단위, 기준, 시점을 쓴다. |

적용 제외 대상은 다음과 같다.

- 코드, 로그, 직접 인용, 오류 원문은 그대로 둔다.
- 홍보 문구와 창작 글에는 적용하지 않는다. 모델은 범위 밖이라고 알린다.

## 모드

| 모드 | 트리거 | 출력 |
|---|---|---|
| 쓰기 | 기본 | 상시 규칙을 따른 글 |
| 재작성 | "쉽게 바꿔줘", "다듬어줘", "K-STE로" | 고친 글만. 해석이 갈리면 `확인 필요:` 최대 3개 |
| 검수 | "검사해줘", "어디가 문제야" | `\| 규칙 \| 원문 \| 고친 글 \|` 표 |

재작성 절차는 다음과 같다.

1. 보존 목록을 만든다. 출력하지 않는다.
2. 규칙을 어긴 부분만 고친다. 바꾼 문장마다 규칙 ID를 댈 수 있어야 한다.
3. 원문과 대조한다. 보존 목록이 모두 남았는지, 원문에 없는 것이 생겼는지 본다.
4. 원문이 두 가지로 읽히면 해석을 고르지 않는다. 그 부분을 그대로 두고 `확인 필요:`에 적는다.

## 평가

`writing-skills`의 TDD 방식을 따른다. 스킬을 쓰기 전에 기준선 실패를 먼저 기록한다.

### 실행 환경

웹 채팅·자동화 경로는 `claude -p`를 격리해서 실행한다.

```
claude -p "<시나리오>" --model <모델> --setting-sources "" \
  --system-prompt "<조건별 프롬프트>" --tools ""
```

2026-10-15에 시험한 결과, `--setting-sources ""`는 사용자 `CLAUDE.md`를 제외했다.

| 조건 | 시스템 프롬프트 |
|---|---|
| base | "You are a helpful assistant." |
| short | base + 짧은판 |
| full | base + 전체판 |
| agent | 임시 프로젝트에 스킬만 설치. Claude Code 기본 시스템 프롬프트 |
| agent+short | agent + 프로젝트 `CLAUDE.md`에 짧은판. 권장 로컬 구성 |

코딩 에이전트 경로는 임시 프로젝트의 `.claude/skills/k-ste/`에 스킬을 두고 `--setting-sources project`로 실행한다. 이 경로에서는 재작성·검수 요청에 스킬이 실행되는지 확인한다.

모델은 `sonnet`과 `haiku`를 쓴다. `haiku`는 지시를 덜 따르는 모델의 압력 시험이다.

### 시나리오

| ID | 유형 | 확인할 것 |
|---|---|---|
| S1 | 비개발자 설명 | 결론 먼저, 용어 정의, 서식 결함 |
| S2 | Slack 장애 공유 | 결론 먼저, 사실·미확인 구분, 수치 단위 |
| S3 | PR 설명 | 한다체, 미실행 검사 처리 |
| S4 | 롤백 절차 | 조건 먼저, 한 단계 한 동작, 경고 위치 |
| S5 | 재작성: 의미 보존 함정 | 헤지·의무 강도·범위 표지 보존 |
| S6 | 재작성: 모호한 원문 | 해석을 고르지 않음, `확인 필요:` |
| S7 | 압력: "최대한 짧게" | 조사·어미 생략 없음, 명사형 종결 없음 |
| S8 | 범위 밖: 홍보 문구 | 범위 밖 알림 |
| S9 | 검수 모드 | 표 출력, 존재하지 않는 규칙 ID 없음 |
| S10 | 긴 원인 진단 답변 | 긴 답변에서 서식·문체 유지 |

### 측정

- 기계 계수(`score.py`): 볼드 수, 엠대시 수, 헤더 수, 이모지 수, 물결표 범위, 맺음 제안, 명사형 종결, 이중 피동, "진행/실시/수행", 문체 혼용, 최장 문장 어절 수.
- 블라인드 판정(`claude -p`, opus): S5·S6·S7의 뜻 변경 여부와 S1·S2·S10의 결론 위치. 판정자는 어느 조건의 출력인지 모른다.

### 통과 기준

1. short와 full의 기계 계수 결함 합계가 base보다 50% 이상 적다.
2. full의 S5·S6·S7 출력에서 뜻 변경이 0건이다.
3. full의 S8 출력이 범위 밖이라고 알린다.
4. full의 S9 출력에 존재하지 않는 규칙 ID가 없다.
5. 코딩 에이전트 경로에서 S5·S6·S9 요청에 스킬이 실행된다.

기준을 못 넘으면 실패 원인을 기록하고, 규칙을 고친 뒤 다시 실행한다.

## 배포와 로컬 적용

- 배포: `HC-kang/K-STE`(public)에 push한다. 임시 디렉터리에서 `npx skills add HC-kang/K-STE`로 설치되는지 확인한다.
- 로컬 적용:
  1. 스킬을 사용자 전역으로 설치한다.
  2. `~/.claude/CLAUDE.md`의 "Writing Style (ASD-STE100 based)" 절을 짧은판으로 바꾼다.
  3. 새 세션에서 규칙이 적용되는지 확인한다.

## 범위 밖

- SessionStart 훅: Node.js 의존성이 생긴다. 긴 대화에서 규칙이 흐려지는 것이 평가에서 확인되면 그때 추가한다.
- Claude Code 플러그인 마켓플레이스: `npx skills add`로 충분하다.
- 배포용 정규식 린터: 린터 점수는 독자 체감과 다르다.
- 승인 어휘 사전: 관리 비용이 크다. 조직 용어집이 필요해지면 그때 추가한다.

| 가정 | 틀리면 생기는 문제 | 대응 |
|---|---|---|
| 짧은판만으로 상시 적용이 유지된다 | 긴 대화에서 규칙이 흐려진다 | S10으로 확인한다. 흐려지면 훅을 추가한다 |

| 기계 계수가 품질을 대표한다 | 계수만 좋아지고 읽기는 나빠진다 | 뜻 변경과 결론 위치는 블라인드 판정으로 잰다 |
| 판정자가 공정하다 | Claude가 Claude 출력을 판정한다 | 결과에 한계로 적는다 |

## 평가 후 변경

평가와 독립 리뷰의 결과로 위 설계에서 바뀐 결정이다. 근거와 실행 결과는 `evals/results/NOTES.md`에 있다. 현재 규칙의 원본은 `skills/k-ste/SKILL.md`다.

| 항목 | 처음 결정 | 바뀐 결정 | 이유 |
|---|---|---|---|
| K0 | 범위 표지 보존 | 정도·방식 한정어, 인과 관계, 빠진 주어·목적어 보존을 더함 | 재작성에서 "정상적으로" 삭제, "관련하여"를 "때문에"로 바꿈, 빠진 주어 채움을 관찰했다 |
| 문서/답변 판단 | 명시하지 않음 | 장르 우선(커밋·지시문 한다체, 오류·UI 합니다체), 문서 장르 지정 시 문서, 그 밖은 답변 | 런북을 합니다체로, 분석 답변을 문서로 쓴 실패를 관찰했다 |
| K1 | 제목으로 시작하지 않음 | 답변에만 적용. 문서는 제목 한 줄 허용 | 문서 틀과 충돌했다 |
