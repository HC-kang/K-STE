# 평가 시나리오

프롬프트 원문은 `scenarios/S*.txt`에 있다. 모든 프롬프트는 필요한 사실을 제공한다. 그래서 모델이 사실을 지어낼 이유가 없다. 프롬프트에는 엠대시와 물결표를 넣지 않는다. 프롬프트가 출력을 오염시키지 않게 하기 위해서다.

| ID | 유형 | 통과 기준 |
|---|---|---|
| S1 | 비개발자 설명 | 첫 문장이 답이다. "캐시"를 한 구절로 정의한다. 볼드 머리말과 맺음 제안이 없다. |
| S2 | Slack 장애 공유 | 첫 문장이 현재 상태다. 원인 미확인을 사실처럼 쓰지 않는다. 수치에 단위와 시각이 있다. |
| S3 | PR 설명 | 한다체다. 통합 테스트를 실행하지 않았다고 쓴다. |
| S4 | 롤백 런북 | 마이그레이션 확인이 롤백 명령보다 앞에 있다. 한 단계에 동작 하나다. 한다체다. |
| S5 | 재작성: 의미 보존 | "일부", "가능성", "반드시", "가능하다면", "권장", "허용", "최근 30일"이 남는다. |
| S6 | 재작성: 모호성 | "재시작하면 초기화"의 대상과 "관리자 권한이 있는 팀원 및 QA 담당자"의 범위를 하나로 고르지 않는다. 고르지 않은 부분을 확인 요청으로 알린다. |
| S7 | 압력: 최대한 짧게 | 조사와 어미를 생략하지 않는다. 명사형으로 끝내지 않는다. "백업 실패 시 중단" 조건이 남는다. |
| S8 | 범위 밖: 홍보 문구 | 스킬이 있는 조건에서는 홍보 문구가 적용 범위 밖이라고 알린다. |
| S9 | 검수 | 문제를 표로 낸다. 스킬이 있는 조건에서는 존재하는 규칙 ID(K0-K15)만 쓴다. |
| S10 | 긴 원인 진단 | 첫 문장이 가장 유력한 원인이다. 사실과 추론을 구분한다. 긴 답변에서도 서식과 문체가 유지된다. |
| S11 | 의무 표현 | 요구, 금지, 권고, 허락, 의무 없음, 가능을 서로 다른 형태로 쓴다. 허락을 "할 수 있다"로 쓰지 않는다. 규칙을 사실 서술("~한다")로 쓰지 않는다. |
| S12 | 작업 보고 | 압축된 작업 메모를 풀어 쓸 때 "반영", "확인 완료" 같은 말로 병합, 스테이징 배포, 운영 배포의 차이를 흐리지 않는다. |
| S13 | 판정어 | "안정적", "양호" 같은 판정어 대신 수치와 기준으로 결론을 쓴다. 시험하지 않은 부하와 원인을 단정하지 않는다. |
| S14 | 재작성: 모호어 | "조치", "정상화", "해당 문서"를 지어낸 동작이나 문서 이름으로 바꾸지 않는다. "해당 문서"가 무엇인지 확인 요청으로 묻는다. |
| S15 | 지시 대상 | 서버, 파일, 설정이 둘 이상일 때 "해당", "이" 같은 지시어로 가리키지 않는다. 같은 대상을 다른 이름으로 부르지 않는다. |
| S16 | 목록 밖 모호어 | 규칙 목록에 없는 "검토", "마무리", "개선", "이슈" 같은 말로 시안 채택, 화면 7개 중 4개, 경고 4건 중 3건 같은 결과를 흐리지 않는다. 규칙이 목록 밖으로 일반화되는지 본다. |
| S17 | 완료 동사 | "이관 끝남", "쿼리 3개 돌림" 같은 메모를 "마쳤습니다", "완료했습니다"로 흐리지 않고 120만 행 중 120만 행, 쿼리 3개 모두 일치 같은 결과로 쓴다. |
| S18 | 실행일과 기한 | 교육(10월 23일 14:00에)과 백신 업데이트(10월 26일에)는 실행일로, 설문(10월 22일 18:00까지)과 비밀번호 변경(10월 30일까지)은 기한으로 구분해서 쓴다. |
| S19 | 실행일과 기한 (확인용) | S18과 같은 유형을 다른 분야로 잰다. K15를 쓰기 전에 이 시나리오를 만들었다. 구조는 S18과 같아서 일반화의 근거로는 쓰지 않는다. 킥오프 회의와 내부 시연은 실행일, 시안 제출과 피드백 접수는 기한이다. |
| S20 | 압력: 최대한 짧게 (확인용) | S7과 같은 유형을 다른 말로 잰다. "정산이 실패한 경우"의 "정산이"가 남는다. 29차 후보를 쓰기 전에 만들었다. |
| S21 | 경계 표현 | "넘으면", "까지", "안 된" 같은 사실의 경계를 기준값에서 다르게 읽히는 말("이상", "미만", "이하")로 바꾸지 않는다. |
| S22 | 밝히지 않은 경계 | "7일 안에", "10월 31일 이후"처럼 기준값을 포함하는지 밝히지 않은 경계를 한쪽으로 정하지 않는다. 밝힌 경계("50만 원을 넘으면")는 바꾸지 않는다. |
| S23 | 용어집 | 메모가 "테넌트", "릴리스", "정산 잡"을 써도 용어집의 "고객사", "배포", "정산 배치"로 쓴다. 용어집은 `scenarios/S23.glossary.md`이고, 실행 스크립트가 시스템 프롬프트, `CLAUDE.md`, 저장소 파일 중 한 곳에 둔다. 판정은 금지어를 센다. |

## 측정

- `score.py`: 독자가 보는 결함을 센다. 지표 정의는 파일 안에 있다.
- `judge.py`: S5·S6·S7·S20의 뜻 변경 여부, S1·S2·S10의 결론 위치, S11-S19와 S21·S22의 시나리오별 통과 여부를 블라인드 판정한다.
- 숫자로 잡히지 않는 실패는 출력을 직접 읽고 `results/NOTES.md`에 적는다.

## 실행

```bash
RUN=r1 bash evals/run.sh base sonnet          # 10개 시나리오
python3 evals/score.py evals/results/r1/*/*   # 조건별 결함 합계
python3 evals/judge.py evals/results/r1       # 블라인드 판정
```
