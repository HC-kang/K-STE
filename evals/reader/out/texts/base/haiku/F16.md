# 정산 파일 재전송 런북 (다온결제넷 야간 정산)

| 항목 | 내용 |
|---|---|
| 문서 구분 | 야간 정산 운영 런북 |
| 대상 묶음 | 묶음 4 |
| 대상 시스템 | 다온결제넷 |
| 발생 원인 | 전송 게이트웨이 교체에 따른 정산 파일 수신 확인 지연 예상 |
| 적용 작업일 | 2026-11-12(목) 야간 |
| 대상 파일 | 2026-11-11(수) 매출 정산 파일 |
| 작업 위치 | 사내 운영 콘솔 '결빛' > 정산 > 전송 이력 |

## 1. 역할

| 역할 | 담당자 | 책임 |
|---|---|---|
| 실행자 | 민서준 (야간 정산 운영자) | 수신 상태 조회, 해시 확인, 재전송 실행, 작업일지 기록 |
| 확인자 | 배유림 (당직 책임자) | 해시 불일치·처리 중 파일 판단, 작업일지 검토 및 완료 표시 |

## 2. 문의처

| 구분 | 담당 | 연락처 |
|---|---|---|
| 수신 상태 조회 오류 | 플랫폼 당직 오하린 | 내선 4312 |
| 정산 대상 판단 | 배유림 | 내선 4318 |

## 3. 작업 시간표

| 시각 | 작업 | 담당 |
|---|---|---|
| 01:10 | 대상 파일 수신 상태 조회 (필수) | 민서준 |
| 01:10 이후 | 미수신 지속 여부 확인 후 재전송 대상 확정 | 민서준 |
| 01:20 | 재전송 대상 파일 첫 번째 재전송 | 민서준 |
| 01:25 (첫 재전송 후 5분) | 미수신 파일 두 번째 재전송 | 민서준 |
| 01:50 | 재전송 결과 및 실패 파일 목록을 결빛 작업일지에 기록 | 민서준 |
| 02:00 | 작업일지 확인, 완료 또는 '후속 조치 필요' 표시 | 배유림 |

## 4. 사전 확인

- [ ] 대상 파일이 2026-11-11(수) 매출 정산 파일인지 확인
- [ ] 결빛 콘솔 접속 및 '정산 > 전송 이력' 메뉴 접근 권한 확인
- [ ] 배유림 당직 상태 및 내선 4318 연결 가능 여부 확인
- [ ] 플랫폼 당직 오하린 내선 4312 연결 가능 여부 확인

## 5. 실행 절차

### 5.1 수신 상태 조회 (01:10)

1. 결빛 > 정산 > 전송 이력에서 2026-11-11(수) 매출 정산 파일 목록을 연다.
2. 각 파일의 수신 상태를 조회하고 기록한다.
3. 상태별 처리 방법은 아래와 같다.

| 수신 상태 | 처리 |
|---|---|
| 수신 완료 | 재전송하지 않는다. 단순 조회만 허용한다. |
| 처리 중 | 재전송하지 않는다. 배유림에게 확인을 요청한다. |
| 미수신 | 10분 연속 유지 여부를 확인한 뒤 재전송 대상으로 판단한다. |

### 5.2 재전송 대상 확정

- '미수신' 상태가 **10분 연속 유지된 파일만** 재전송 대상이다.
- 10분 연속 유지 여부는 01:10 조회 시점부터 01:20까지 상태 변화가 없는지로 확인한다.
  - *확인 필요: 10분 연속 유지 판단 기준 시각은 운영 측 확정이 필요하다. 이 런북은 01:10 이후 연속 미수신으로 해석했다.*

### 5.3 해시 확인 (재전송 전 필수)

1. 각 재전송 대상 파일에 대해 원본 파일 해시와 보관본 해시를 비교한다.
2. 두 해시가 **일치**하면 재전송을 진행한다.
3. 두 해시가 **불일치**하면:
   - 해당 파일 재전송을 **금지**한다.
   - 즉시 배유림에게 보고한다.
   - 작업일지에 '해시 불일치, 재전송 보류'로 기록한다.
   - *확인 필요: 해시 값을 콘솔에서 확인하는 방법은 현장 화면 기준으로 확정해야 한다.*

### 5.4 재전송 (01:20 / 01:25)

| 단계 | 시각 | 조건 | 처리 |
|---|---|---|---|
| 1차 재전송 | 01:20 | 해시 일치, 10분 연속 미수신 | 재전송 실행 |
| 2차 재전송 | 1차 후 5분 (01:25 전후) | 1차 재전송 후에도 미수신 | 재전송 실행 |
| 종결 | 2차 실패 후 | 2차도 실패 | 추가 전송 금지, 실패 파일로 기록 |

- 파일당 재전송은 **최대 2회**다.
- 2차 재전송 실패 후에는 어떤 경우에도 추가 전송하지 않는다.
- 재전송 후 '수신 완료'로 바뀐 파일은 더 이상 재전송하지 않는다.

## 6. 예외 처리

| 상황 | 조치 |
|---|---|
| 해시 불일치 | 재전송 금지, 배유림 보고 |
| 처리 중 상태 | 재전송 금지, 배유림에게 확인 요청 |
| 수신 상태 조회 오류 | 플랫폼 당직 오하린(내선 4312)에 문의 |
| 정산 대상 여부 판단이 필요한 경우 | 배유림(내선 4318)에 문의 |
| 2차 재전송 후에도 미수신 | 추가 전송 없이 실패 파일로 기록, 배유림 보고 |

## 7. 작업일지 기록 (01:50까지)

결빛 작업일지에 다음 항목을 기록한다.

- 조회 시각 및 파일별 수신 상태
- 재전송 실행 여부, 시각, 회차(1차/2차)
- 해시 확인 결과(일치/불일치)
- 실패 파일 목록 (파일명, 사유)
- **실패 파일이 없어도 '실패 0건'을 반드시 기록한다.**

## 8. 완료 확인 (02:00까지)

배유림이 작업일지를 확인하고 다음 중 하나로 표시한다.

| 조건 | 표시 |
|---|---|
| 모든 파일이 수신 완료이거나 정리 완료 | **완료** |
| 미해결 파일(실패, 해시 불일치, 처리 중 미확인 등)이 하나라도 있음 | **후속 조치 필요** |
