파드 안에서 실행 중인 애플리케이션은 `default` 네임스페이스의 `kubernetes` 서비스를 통해 쿠버네티스 API 서버에 접근할 수 있습니다. 따라서 파드에서는 `kubernetes.default.svc` 호스트 이름으로 API 서버에 요청을 보낼 수 있으며, 공식 클라이언트 라이브러리는 이 과정을 자동으로 처리합니다.

API 서버에 인증하는 방법으로는 서비스 어카운트 자격 증명을 사용하는 것을 권장합니다. 기본적으로 모든 파드는 서비스 어카운트와 연결되며, 이 서비스 어카운트의 자격 증명(토큰)은 파드 내 각 컨테이너의 파일시스템에서 다음 경로에 있습니다.

`/var/run/secrets/kubernetes.io/serviceaccount/token`

인증서 번들이 제공되는 경우에는 각 컨테이너의 다음 경로에 위치합니다. 이 번들은 API 서버의 인증서를 검증하는 데 사용해야 합니다.

`/var/run/secrets/kubernetes.io/serviceaccount/ca.crt`

네임스페이스 범위의 API 작업에서 사용할 기본 네임스페이스는 각 컨테이너의 다음 파일에 저장되어 있습니다.

`/var/run/secrets/kubernetes.io/serviceaccount/namespace`

주요 변경 사항:
- 문장을 짧게 나누고, 긴 경로는 별도 줄로 분리해 눈에 잘 띄게 했습니다.
- "API 서버를 인증하는"을 "API 서버에 인증하는"으로 고쳤습니다. 원문은 서버가 인증받는 것처럼 읽힐 수 있습니다.
- "제공 인증서"를 "API 서버의 인증서"로 풀어 의미를 분명히 했습니다.
- "~에 배치된다" 같은 번역투 표현을 자연스러운 문장으로 바꿨습니다.
- 문체는 원문의 "~한다"체에서 "~합니다"체로 바꿨습니다. 문서 스타일에 맞춰 "~한다"체가 필요하면 말씀해 주세요.
