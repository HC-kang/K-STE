# 네임스페이스(Namespace)

하나의 클러스터는 여러 사용자와 사용자 그룹(이하 '사용자 커뮤니티')의 요구를 충족할 수 있어야 한다.

쿠버네티스 **네임스페이스**는 여러 프로젝트, 팀, 고객이 하나의 클러스터를 공유할 수 있게 해 준다. 이를 위해 다음 두 가지를 제공한다.

1. 이름에 대한 범위(scope)
2. 인증과 정책을 클러스터의 하위 영역에 연결하는 메커니즘

네임스페이스를 여러 개 사용하는 것은 선택 사항이다.

## 사용자 커뮤니티의 요구

각 사용자 커뮤니티는 다른 커뮤니티와 격리된 상태로 작업하기를 원한다. 이를 위해 각 커뮤니티는 다음을 가진다.

1. **리소스**: 파드, 서비스, 레플리케이션 컨트롤러(replication controller) 등
2. **정책**: 커뮤니티 내에서 누가 어떤 작업을 수행할 수 있고 수행할 수 없는지에 대한 규정
3. **제약 조건**: 커뮤니티에 허용되는 쿼터의 크기 등

클러스터 운영자는 사용자 커뮤니티마다 네임스페이스를 하나씩 생성할 수 있다. 네임스페이스는 다음에 대한 고유한 범위를 제공한다.

1. 리소스 이름 지정 (기본적인 이름 충돌 방지)
2. 신뢰할 수 있는 사용자에게 관리 권한 위임
3. 커뮤니티의 리소스 소비량 제한

## 유스케이스

1. 클러스터 운영자로서, 단일 클러스터에서 여러 사용자 커뮤니티를 지원하고 싶다.
2. 클러스터 운영자로서, 클러스터 분할 관리 권한을 각 커뮤니티의 신뢰할 수 있는 사용자에게 위임하고 싶다.
3. 클러스터 운영자로서, 클러스터를 함께 사용하는 다른 커뮤니티에 미치는 영향을 제한하기 위해 각 커뮤니티가 사용할 수 있는 리소스의 양을 제한하고 싶다.
4. 클러스터 사용자로서, 다른 사용자 커뮤니티의 작업과 무관하게 내 커뮤니티와 관련된 리소스만 다루고 싶다.

**주요 수정 사항**
- 제목과 소제목을 추가해 구조를 명확히 했습니다.
- 흩어져 있던 문장을 흐름에 맞게 재배치했습니다. (예: "격리를 원한다" → "각 커뮤니티가 가지는 것" → "네임스페이스가 제공하는 범위")
- 리소스, 정책, 제약 조건에 굵은 글씨를 적용해 훑어보기 쉽게 했습니다.
- 닫히지 않았던 괄호를 바로잡고, 어색한 표현("명명된 리소스", "조치를 수행할 수 있거나 없는 사람")을 자연스럽게 고쳤습니다.
- 유스케이스의 줄바꿈과 들여쓰기를 정리했습니다.
