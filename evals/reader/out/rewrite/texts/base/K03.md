일반적으로 다음과 같은 상황에서 서비스 어카운트를 사용해 신원을 부여할 수 있습니다.

## 1. 파드가 쿠버네티스 API 서버와 통신해야 하는 경우
- **시크릿 접근**: 시크릿에 저장된 민감한 정보를 읽기 전용으로 조회하는 경우
- **네임스페이스 간 접근**: 예를 들어 `example` 네임스페이스의 파드가 `kube-node-lease` 네임스페이스의 리스(Lease) 오브젝트를 read, list, watch 할 수 있도록 허용하는 경우

## 2. 파드가 외부 서비스와 통신해야 하는 경우
- **외부 서비스 신원 필요**: 예를 들어 워크로드 파드가 상용 클라우드 API용 신원이 필요하고, 해당 제공자가 적절한 신뢰 관계 구성을 허용하는 경우
- **프라이빗 레지스트리 인증**: `imagePullSecret`을 사용해 프라이빗 이미지 레지스트리에 인증하는 경우

## 3. 외부 서비스가 쿠버네티스 API 서버와 통신해야 하는 경우
- 예를 들어 CI/CD 파이프라인의 일부로서 클러스터에 인증해야 하는 경우

## 4. 클러스터에서 서드파티 보안 소프트웨어를 사용하는 경우
- 이 소프트웨어가 다른 파드의 서비스어카운트(ServiceAccount) 신원에 의존하여 파드를 서로 다른 컨텍스트로 그룹화하는 경우

- "~하는 경우" 문장 구조를 유지하되, 굵은 글씨의 핵심어를 앞에 두어 훑어보기 쉽게 했습니다.
