# 묶음 5 · PR 5-1 · 노벨릿커머스 주문 중복 차단 변경

이 PR은 주문 API의 재시도 처리 모듈에서 동일 요청 키를 재사용하면 주문이 중복 생성되는 문제를 수정한다.

## 변경 내용

- 변경 위치는 주문 API의 재시도 처리 모듈이다.
- 새 중복 차단 기준은 동일 요청 키 수신 후 90초이다.
- 요청 키가 없는 요청은 기존 처리를 유지한다.
- 서버의 요청 로그 보관 기간을 48시간으로 변경한다.

## 담당과 문의

- 개발 담당은 서리안이다.
- 검증 담당은 주문QA팀이다.
- 문의는 사내 #주문변경 채널에 남긴다.

## 비교 시험

- 대상 환경은 스테이징 주문 서버와 스테이징 환불 서버이다.
- 두 서버를 모두 비교 시험에 사용한다.
- 주문QA팀이 11/10(화) 14:00~15:00에 비교 시험을 한다.
- 요청은 서버별 240건이다.
- 실패는 0건이다.
- 병합 전에 비교 시험 결과표를 이 PR의 첨부란에 업로드해야 한다.

## 리뷰와 병합

- 11/12(목) 리뷰 의견 등록이 예정돼 있다.
- 병합에는 코드 리뷰어 전원의 승인이 필요하다.
- 승인이 하나라도 없으면 병합을 보류한다.
- 개발 담당 서리안이 11/13(금) 10:00에 병합한다.

## 확인 필요

- 확인 필요: 요청 로그 보관 기간 48시간 변경이 스테이징 주문 서버, 스테이징 환불 서버, 그 밖의 서버 중 어디에 적용되는지 메모에 없다. 변경 전 보관 기간도 없다.
- 확인 필요: "동일 요청 키 수신 후 90초"가 최초 수신 후 90초 동안 같은 키의 요청을 차단한다는 뜻인지 메모에 명시돼 있지 않다.
- 확인 필요: 비교 시험이 11/10(화)에 예정돼 있어 아직 실행 전이다. "실패 0건"이 시험 결과인지 통과 기준인지 확인이 필요하다.
- 확인 필요: "11/12(목) 리뷰 의견 등록"이 리뷰어가 등록하는 날(실행일)인지 등록을 마쳐야 하는 기한인지 메모에 없다.
