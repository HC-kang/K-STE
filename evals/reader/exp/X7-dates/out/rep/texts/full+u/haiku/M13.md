# PR 5-1: 노벨릿커머스 주문 중복 차단 변경

주문 API의 재시도 처리 모듈에서 동일 요청 키를 재사용하면 주문이 중복 생성되는 문제를 수정한다. 새 중복 차단 기준은 동일 요청 키를 수신한 후 90초이며, 요청 키가 없는 요청은 기존 동작을 유지한다. 이 변경은 묶음 5에 속한다.

## 변경 내용

- 변경 위치: 주문 API의 재시도 처리 모듈
- 문제: 동일 요청 키를 재사용하면 주문이 중복 생성된다.
- 새 중복 차단 기준: 동일 요청 키를 수신한 후 90초
- 요청 키가 없는 요청은 기존 동작을 유지한다.
- 서버의 요청 로그 보관 기간을 48시간으로 변경한다.
  확인 필요: 서버의 요청 로그 보관 기간 변경. 대상이 주문 서버, 환불 서버 중 어느 쪽인지 원문에 없다.

## 검증

- 개발 담당: 서리안
- 검증 담당: 주문QA팀
- 대상 환경: 스테이징 주문 서버와 스테이징 환불 서버. 두 서버 모두 비교 시험에 사용한다.
- 비교 시험 일시: 11/10(화) 14:00~15:00
- 비교 시험 요청 수: 서버별 240건
- 실패 수: 0건
  확인 필요: 실패 수 0건. 목표 기준인지 시험 결과인지 원문에 없다.
- 병합 전에 비교 시험 결과표를 PR 첨부란에 업로드해야 한다.
