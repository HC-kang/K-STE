kubectl은 apiserver의 위치 파악과 인증을 처리한다. 만약 당신이 curl, wget, 웹브라우저 같은 http 클라이언트로 REST API에 직접 접근하려고 한다면, 위치 파악과 인증을 하는 방법이 몇 가지 있다.

- kubectl을 proxy 모드로 실행한다.
  - 이 방식을 권장한다.
  - kubectl은 저장된 apiserver 위치를 사용한다.
  - kubectl은 self-signed 인증서로 apiserver의 identity를 검증한다. 그래서 MITM은 불가능하다.
  - kubectl은 apiserver를 인증한다.
  - 앞으로는 클라이언트 측의 지능형 load balancing과 failover가 될 것이다.
- http 클라이언트에 위치정보와 인증정보를 직접 제공한다.
  - 이 방식은 대안적인 접근 방식이다.
  - 이 방식은 proxy 사용과 혼동되는 몇 가지 타입의 클라이언트 코드와 같이 동작한다.
  - MITM으로부터 보호하려면 root 인증서를 당신의 브라우저로 임포트해야 한다.

확인 필요: "apiserver 인증."은 kubectl이 apiserver에 인증한다는 뜻인지, apiserver가 클라이언트를 인증한다는 뜻인지 알 수 없습니다.
확인 필요: "앞으로는 ... failover가 될 것이다."에서 무엇이 load balancing과 failover가 되는지 주어가 없습니다.
확인 필요: "proxy 사용과 혼동되는 몇 가지 타입의 클라이언트 코드와 같이 동작한다."는 proxy 때문에 혼동되는 클라이언트 코드에서도 동작한다는 뜻인지, 다른 뜻인지 알 수 없습니다.
