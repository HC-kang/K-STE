- 조치: IaaS VM에 IaaS 제공자의 자동 VM 다시 시작 기능을 사용한다.
  - API 서버 VM 종료 또는 API 서버 충돌을 완화할 수 있다.
  - 지원 서비스 VM 종료 또는 충돌을 완화할 수 있다.

- 조치: API 서버와 etcd가 있는 VM에 IaaS 제공자의 안정적인 스토리지(예: GCE PD 또는 AWS EBS 볼륨)를 사용한다.
  - API 서버 백업 스토리지 손실을 완화할 수 있다.

- 조치: 고가용성 구성을 사용한다.
  - 컨트롤 플레인 노드 종료 또는 컨트롤 플레인 구성 요소(스케줄러, API 서버, 컨트롤러 매니저) 충돌을 완화할 수 있다.
    - 동시에 발생하는 하나 이상의 노드 또는 구성 요소 오류를 허용한다.
  - API 서버 백업 스토리지(i.e., etcd의 데이터 디렉터리) 손실을 완화할 수 있다.
    - 고가용성 etcd 구성을 사용하고 있다고 가정한다.

- 조치: API 서버 PD/EBS 볼륨의 스냅샷을 주기적으로 만든다.
  - API 서버 백업 스토리지 손실을 완화할 수 있다.
  - 일부 운영자 오류 사례를 완화할 수 있다.
  - 일부 쿠버네티스 소프트웨어 오류 사례를 완화할 수 있다.

- 조치: 파드 앞에 레플리케이션 컨트롤러와 서비스를 사용한다.
  - 노드 종료를 완화할 수 있다.
  - Kubelet 소프트웨어 오류를 완화할 수 있다.

- 조치: 애플리케이션(컨테이너)이 예기치 않은 재시작을 허용하도록 설계한다.
  - 노드 종료를 완화할 수 있다.
  - Kubelet 소프트웨어 오류를 완화할 수 있다.
