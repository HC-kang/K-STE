- 구성을 정의할 때, 안정된 최신 API 버전을 명시한다.

- 구성 파일들은 클러스터에 적용되기 전에 버전 컨트롤에 저장되어 있어야 한다. 이는 필요하다면 구성의 변경 사항을 빠르게 되돌릴 수 있도록 해준다. 이는 또한 클러스터의 재생성과 복원을 도와준다.

- JSON보다는 YAML을 사용해 구성 파일을 작성한다. 비록 이러한 포맷들은 대부분의 모든 상황에서 통용될 수 있지만, YAML이 좀 더 사용자 친화적이다.

- 의미상 맞다면 가능한 한 연관된 오브젝트들을 하나의 파일에 모아 놓는다. 때로는 여러 개의 파일보다 하나의 파일이 더 관리하기 쉽다. 이 문법의 예시로 guestbook-all-in-one.yaml 파일을 참고한다.

- 많은 `kubectl` 커맨드를 디렉터리에 대해 호출할 수 있다. 예를 들어, 구성 파일들의 디렉터리에 대해 `kubectl apply`를 호출할 수 있다.

- 불필요하게 기본값을 명시하지 않는다. 간단하고 최소한의 설정은 에러를 덜 발생시킨다.

- 더 나은 인트로스펙션(introspection)을 위해서 어노테이션에 오브젝트의 설명을 넣는다.
