다듬은 글은 아래와 같습니다.

쿠버네티스는 다음과 같은 방식으로 장애에 대응합니다.

- **컨테이너 단위 재시작:** 파드 안의 컨테이너가 실패하면 쿠버네티스가 `재시작 정책`에 따라 해당 컨테이너를 재시작합니다.

- **레플리카 교체:**
  - 디플로이먼트(Deployment)나 스테이트풀셋(StatefulSet)의 파드가 실패하면, 지정된 레플리카 수를 유지하기 위해 대체 파드를 생성합니다.
  - 데몬셋(DaemonSet)의 파드가 실패하면, 컨트롤 플레인이 같은 노드에서 실행될 대체 파드를 생성합니다.

- **영구 스토리지 복구:** 퍼시스턴트볼륨(PersistentVolume)이 연결된 파드가 실행 중인 노드에 장애가 발생하면, 쿠버네티스는 다른 노드의 새 파드에 해당 볼륨을 다시 연결할 수 있습니다.

- **서비스 로드 밸런싱:** 서비스 뒤에 있는 파드에 장애가 발생하면, 쿠버네티스가 서비스 엔드포인트에서 해당 파드를 자동으로 제거합니다. 그러면 트래픽은 정상 파드로만 전달됩니다.

자가 치유를 담당하는 주요 컴포넌트는 다음과 같습니다.

- **kubelet:** 컨테이너가 실행 중인지 확인하고, 실패한 컨테이너를 재시작합니다.

- **레플리카셋(ReplicaSet), 스테이트풀셋, 데몬셋 컨트롤러:** 파드 레플리카 수를 원하는 수준으로 유지합니다.

- **퍼시스턴트볼륨 컨트롤러:** 상태 저장 워크로드의 볼륨 연결과 해제를 관리합니다.

주요 수정 사항은 다음과 같습니다.

- 도입 문장을 추가해 첫 목록의 맥락을 분명히 했습니다.
- 원문 문체가 "~한다"와 "~하며"로 섞여 있어 정중한 "~합니다" 체로 통일했습니다. 기존 문서가 "~한다" 체라면 어미만 되돌리시면 됩니다.
- "떄"를 "때"로 고치려 했으나, 문장을 다듬으면서 해당 표현은 "실행 중인 노드에 장애가 발생하면"으로 바꿨습니다. 이때 원문의 "파드를 실행 중일 때 노드에 장애가 발생하면"이라는 표현이 어색해 의미를 명확히 했습니다.
- 레플리카 교체 항목은 두 경우(디플로이먼트·스테이트풀셋 / 데몬셋)를 하위 목록으로 나눴습니다.
- 서비스 로드 밸런싱 항목은 문장을 둘로 나눠 원인과 결과를 구분했습니다.
- 마지막 목록 앞 문장을 "자가 치유를 담당하는"으로 줄였습니다.

원문 중 "다른 노드에 있는 새로운 파드에 다시 연결"은 기술적으로는 볼륨이 새 파드에 연결되는 것이므로 "해당 볼륨을 다시 연결"로 목적어를 분명히 했습니다.
