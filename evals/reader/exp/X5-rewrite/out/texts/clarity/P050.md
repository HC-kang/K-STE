원문의 오타("파마리터", "자동 오토스케일러")와 어색한 표현을 바로잡아 다듬었습니다.

* cluster-proportional-autoscaler 애플리케이션은 DNS 서비스와 별도로 배포됩니다.

* 오토스케일러 파드는 클라이언트를 실행하며, 이 클라이언트는 쿠버네티스 API 서버를 폴링(polling)하여 클러스터의 노드 수와 코어 수를 확인합니다.

* 오토스케일러는 주어진 스케일링 파라미터로 의도한 레플리카 수를 계산하고, 스케줄 가능한 노드와 코어 수를 기반으로 이를 DNS 백엔드에 적용합니다.

* 스케일링 파라미터와 데이터 포인트는 컨피그맵(ConfigMap)을 통해 오토스케일러에 제공됩니다. 오토스케일러는 폴링 간격마다 파라미터 표를 갱신하여, 항상 최신 스케일링 파라미터가 반영되도록 합니다.

* 스케일링 파라미터는 오토스케일러 파드를 다시 빌드하거나 재시작하지 않고도 변경할 수 있습니다.

* 오토스케일러는 *linear*와 *ladder* 두 가지 제어 패턴을 지원하는 컨트롤러 인터페이스를 제공합니다.

수정한 부분은 다음과 같습니다.

* **문체 통일**: "~된다"와 "~한다"가 섞여 있던 것을 "~합니다" 체로 맞췄습니다. 기존 문서가 "~한다" 체라면 그에 맞춰 바꾸셔도 됩니다.
* **오타 수정**: "파마리터"는 "파라미터"로, "자동 오토스케일러"는 "오토스케일러"로 고쳤습니다. "자동"은 "오토(auto)"와 뜻이 겹치는 군더더기로 보고 뺐습니다.
* **"예약 가능한" → "스케줄 가능한"**: 원문은 schedulable node를 옮긴 표현으로 보이며, 쿠버네티스에서는 "스케줄 가능한 노드"가 일반적입니다.
* **세 번째 항목**: 원문에서 "예약 가능한 노드 및 코어를 기반으로"가 계산에 걸리는지 적용에 걸리는지 모호했습니다. 공식 문서 취지에 맞춰 계산의 기준으로 읽히도록 문장을 정리했습니다.
* **네 번째 항목**: "의도한 최근 스케일링 파라미터로 최신 상태가 되도록"은 의미가 겹치고 모호해서 "항상 최신 스케일링 파라미터가 반영되도록"으로 간결하게 줄였습니다.

원문의 의도와 다르게 해석된 부분이 있으면 알려 주세요.
