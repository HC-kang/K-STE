kubectl은 apiserver의 위치 파악과 인증을 대신 처리해 줍니다. curl, wget, 웹 브라우저 같은 HTTP 클라이언트로 REST API에 직접 접근하려면, 위치 파악과 인증을 직접 해결해야 합니다. 방법은 크게 두 가지입니다.

## 1. kubectl을 proxy 모드로 실행 (권장)

- 저장된 apiserver 위치를 사용합니다.
- self-signed 인증서로 apiserver의 신원(identity)을 검증하므로 MITM(중간자) 공격이 불가능합니다.
- apiserver 인증을 처리합니다.
- 향후에는 클라이언트 측의 지능형 로드 밸런싱과 failover를 지원할 예정입니다.

## 2. HTTP 클라이언트에 위치 정보와 인증 정보를 직접 제공 (대안)

- proxy를 사용할 때 혼동을 일으키는 일부 유형의 클라이언트 코드에서도 동작합니다.
- MITM을 방지하려면 root 인증서를 브라우저에 임포트해야 합니다.

- 두 방법을 제목으로 구분하고, 개조식 문장을 서술형 어미로 통일했습니다.
- "앞으로는 ... 될 것이다"는 원문이 어색해서 "향후 ... 지원할 예정"으로 바꿨습니다. 원문 의도가 "현재는 미지원, 향후 지원 예정"이라고 보고 해석한 것이니, 다르다면 알려 주세요.
- "proxy 사용과 혼동되는 ... 클라이언트 코드와 같이 동작한다"는 의미가 모호합니다. 원문(Kubernetes 공식 문서)은 proxy를 쓰면 혼란을 일으키는 일부 클라이언트 코드에서도 동작한다는 뜻이므로 그렇게 풀어 썼습니다.
