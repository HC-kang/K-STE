**다듬은 글**

이 방식은 "워커" 프로그램이 작업 대기열을 인식하도록 수정하지 않아도 된다는 장점이 있습니다.

다만 메시지 대기열 서비스를 직접 실행해야 합니다. 이것이 부담된다면 다른 잡 패턴을 고려해 보세요.

또한 이 방식은 작업 아이템마다 파드를 하나씩 생성합니다. 작업 아이템 하나가 몇 초밖에 걸리지 않는다면, 매번 파드를 생성하는 오버헤드가 상당히 클 수 있습니다. 이런 경우에는 하나의 파드가 여러 작업 아이템을 처리하는 다른 예제를 참고하세요.

이 예제에서는 `amqp-consume` 유틸리티로 대기열에서 메시지를 읽어 실제 프로그램을 실행합니다. 덕분에 프로그램이 메시지 대기열을 인식하도록 수정할 필요가 없습니다. 클라이언트 라이브러리로 작업 대기열과 통신하는 방법은 다른 예제에서 다룹니다.

**주요 변경 사항**

- "이러한 접근", "이 접근을 이용하려면" 등을 "이 방식"으로 통일하고, 문장을 짧게 나눴습니다.
- "~해야만 한다", "~고려해보자" 같은 표현을 "~해야 합니다", "~ 보세요"로 바꿔 문체를 합쇼체로 통일했습니다.
- 마지막 문단의 "실행했다"는 시제가 어색해서 현재형으로 고쳤습니다.
- "오직 몇 초밖에"는 중복 표현이라 "몇 초밖에"로 줄였습니다.

**확인이 필요한 부분**

원문의 "하나의 파드가 여러 작업 아이템을 수행하는 이 예제"는 지금 설명 중인 예제가 아니라 다른 예제를 가리키는 것으로 보여서 "다른 예제"로 바꿨습니다. 같은 예제를 뜻하셨다면 알려 주세요. 또한 문서에 해당 예제의 이름이 있다면(예: "세밀한 병렬 처리 작업 대기열") 링크나 이름을 넣는 편이 독자에게 더 명확합니다.
