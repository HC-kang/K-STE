아래처럼 다듬었습니다. 의미는 유지하면서 중복 표현과 어색한 번역투를 줄였습니다.

- 구성을 정의할 때는 안정된 최신 API 버전을 명시합니다.

- 구성 파일은 클러스터에 적용하기 전에 버전 컨트롤에 저장합니다. 그러면 필요할 때 변경 사항을 빠르게 되돌릴 수 있고, 클러스터를 다시 만들거나 복원하는 데에도 도움이 됩니다.

- 구성 파일은 JSON보다 YAML로 작성합니다. 두 포맷은 대부분의 상황에서 모두 사용할 수 있지만, YAML이 더 사용자 친화적입니다.

- 의미상 적절하다면 연관된 오브젝트를 하나의 파일에 모읍니다. 여러 파일보다 파일 하나가 관리하기 더 쉬울 때가 있습니다. 예시는 `guestbook-all-in-one.yaml` 파일을 참고하세요.

- 많은 `kubectl` 명령은 디렉터리를 대상으로 실행할 수 있습니다. 예를 들어 구성 파일이 들어 있는 디렉터리에 `kubectl apply`를 실행할 수 있습니다.

- 기본값은 불필요하게 명시하지 않습니다. 설정이 간단하고 최소할수록 오류가 덜 발생합니다.

- 더 나은 인트로스펙션(introspection)을 위해 오브젝트의 설명을 어노테이션에 넣습니다.

참고로 원문의 문체(`~한다`)를 유지하려면 어미만 `~한다`로 바꾸면 됩니다. 원문에서 "이 문법의 예시로서"는 문맥상 "이 방식의 예시"를 뜻하는 것으로 보여 "예시는 … 참고하세요"로 단순화했습니다.
