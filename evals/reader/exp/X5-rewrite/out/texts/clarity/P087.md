다음은 다듬은 글입니다.

게이트웨이 API의 설계와 아키텍처는 다음 원칙을 기반으로 합니다.

* **역할 지향:** 게이트웨이 API의 리소스 종류는 쿠버네티스 서비스 네트워킹을 관리하는 조직 내 역할을 기준으로 모델링되었습니다.
  * **인프라 제공자:** 여러 테넌트가 격리된 다수의 클러스터를 사용할 수 있도록 인프라를 관리합니다. 클라우드 제공자가 대표적인 예입니다.
  * **클러스터 운영자:** 클러스터를 관리하며, 주로 정책, 네트워크 접근, 애플리케이션 권한에 관심을 둡니다.
  * **애플리케이션 개발자:** 클러스터에서 실행되는 애플리케이션을 관리하며, 주로 애플리케이션 수준의 구성과 서비스 조합에 관심을 둡니다.
* **이식성:** 게이트웨이 API 사양은 커스텀 리소스로 정의되며, 다양한 구현체에서 지원됩니다.
* **표현력:** 게이트웨이 API의 리소스 종류는 헤더 기반 매칭, 트래픽 가중치 설정처럼 일반적인 트래픽 라우팅 사용 사례를 기본 기능으로 지원합니다. 인그레스에서는 이러한 기능을 쓰려면 커스텀 어노테이션이 필요했습니다.
* **확장성:** API의 여러 계층에 커스텀 리소스를 연결할 수 있습니다. 이를 통해 API 구조 안에서 필요한 위치에 세밀한 사용자 정의를 적용할 수 있습니다.

주요 변경 사항은 다음과 같습니다.

* 원문의 "기반이 되었다"를 "기반으로 합니다"로 바꿔 문장을 간결하게 했습니다. 원칙이 현재도 유효하다는 의미에 맞춰 현재형으로 썼습니다.
* 긴 문장을 나누고, "~하며 예를 들어 ~"처럼 이어지던 부분을 끊어 읽기 쉽게 했습니다.
* "표현력" 항목은 원문의 "인그레스에서 커스텀 어노테이션을 사용해야만 가능했던"이라는 긴 수식을 별도 문장으로 분리해 의미가 분명해지게 했습니다.
* 문체는 "~합니다"로 통일했습니다. 원문이 "~한다"체였다면 문서 전체 스타일에 맞게 다시 바꿔 주세요.
