**1. IaaS VM 자동 재시작 사용**
- 조치: IaaS 공급자가 제공하는 VM 자동 재시작 기능을 사용합니다.
- 완화 대상:
  - API 서버 VM 종료 또는 API 서버 충돌
  - 지원 서비스 VM 종료 또는 충돌

**2. 안정적인 스토리지 사용**
- 조치: API 서버와 etcd가 있는 VM에 IaaS 공급자의 안정적인 스토리지(예: GCE PD, AWS EBS 볼륨)를 사용합니다.
- 완화 대상:
  - API 서버 백업 스토리지 손실

**3. 고가용성 구성 사용**
- 조치: 고가용성 구성을 사용합니다.
- 완화 대상:
  - 컨트롤 플레인 노드 종료 또는 컨트롤 플레인 구성 요소(스케줄러, API 서버, 컨트롤러 매니저) 충돌
    - 동시에 발생하는 하나 이상의 노드 또는 구성 요소 장애를 허용할 수 있습니다.
  - API 서버 백업 스토리지(etcd 데이터 디렉터리) 손실
    - 고가용성 etcd 구성을 사용하는 경우를 전제로 합니다.

**4. 주기적인 볼륨 스냅샷**
- 조치: API 서버 PD/EBS 볼륨의 스냅샷을 주기적으로 생성합니다.
- 완화 대상:
  - API 서버 백업 스토리지 손실
  - 일부 운영자 오류 사례
  - 일부 쿠버네티스 소프트웨어 오류 사례

**5. 레플리케이션 컨트롤러와 서비스 사용**
- 조치: 파드 앞단에 레플리케이션 컨트롤러와 서비스를 사용합니다.
- 완화 대상:
  - 노드 종료
  - Kubelet 소프트웨어 오류

**6. 재시작에 견디는 애플리케이션 설계**
- 조치: 예기치 않은 재시작을 허용하도록 애플리케이션(컨테이너)을 설계합니다.
- 완화 대상:
  - 노드 종료
  - Kubelet 소프트웨어 오류
