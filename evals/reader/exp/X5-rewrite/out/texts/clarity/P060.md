DRA는 핵심 할당 기능을 제공하기 위해 다음 쿠버네티스 API 종류를 사용한다. 이 API 종류는 모두 `resource.k8s.io/v1` API 그룹에 속한다.

디바이스클래스(DeviceClass)
: 클레임할 수 있는 디바이스의 범주와, 클레임에서 특정 디바이스 속성을 선택하는 방법을 정의한다. 디바이스클래스 파라미터는 리소스슬라이스에 있는 디바이스 중 0개 이상과 일치할 수 있다. 디바이스클래스에 속한 디바이스를 클레임하려면, 리소스클레임에서 원하는 디바이스 속성을 선택한다.

리소스클레임(ResourceClaim)
: 클러스터에서 디바이스처럼 연결된 리소스에 접근하기 위한 요청이다. 리소스클레임을 통해 파드가 특정 리소스에 접근할 수 있다. 리소스클레임은 워크로드 운영자가 직접 만들 수도 있고, 리소스클레임템플릿을 기반으로 쿠버네티스가 만들 수도 있다.

리소스클레임템플릿(ResourceClaimTemplate)
: 쿠버네티스가 워크로드의 파드별 리소스클레임을 생성할 때 사용하는 템플릿이다. 이 템플릿을 사용하면 각 파드가 서로 분리된, 유사한 리소스에 접근할 수 있다. 템플릿에서 생성된 리소스클레임은 각각 특정 파드에 바인딩되며, 파드가 종료되면 쿠버네티스가 해당 리소스클레임을 삭제한다.

리소스슬라이스(ResourceSlice)
: 디바이스처럼 노드에 연결된 하나 이상의 리소스를 나타낸다. 리소스슬라이스는 드라이버가 클러스터에 생성하고 관리한다. 리소스클레임이 생성되어 파드에서 사용되면, 쿠버네티스는 리소스슬라이스를 이용해 클레임된 리소스에 접근할 수 있는 노드를 찾는다. 이후 해당 리소스를 리소스클레임에 할당하고, 그 리소스에 접근할 수 있는 노드에 파드를 스케줄링한다.

**주요 수정 사항**
- 줄바꿈을 없애고 문장을 자연스럽게 이어, 본문이 한 흐름으로 읽히도록 했다.
- "이러한 API 종류는 모두 ~에 포함된다"를 "이 API 종류는 모두 ~에 속한다"로 간결하게 바꿨다.
- 정의 항목의 서술을 통일했다(~을 정의한다, ~이다, ~를 나타낸다).
- 리소스클레임의 "생성하거나 ~ 생성할 수 있다"처럼 반복되는 표현을 "직접 만들 수도 있고 ~ 만들 수도 있다"로 정리했다.
- 리소스슬라이스 마지막 문장에 "이후"를 넣어 처리 순서(노드 탐색 → 할당 → 스케줄링)가 분명하게 드러나게 했다.

원문의 "디바이스클래스에서 디바이스를 클레임하려면"은 "디바이스클래스에 속한 디바이스를 클레임하려면"으로 바꿨는데, 의미를 명확히 하려는 해석이므로 원문 의도와 다르면 알려 주세요.
