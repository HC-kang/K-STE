다듬은 글은 다음과 같습니다.

---

애그리게이션 레이어는 kube-apiserver 프로세스 안에서 동작합니다. 확장 리소스가 등록되기 전까지는 아무 일도 하지 않습니다. 사용자가 API를 등록하려면 쿠버네티스 API 안의 특정 URL 경로를 "요구(claim)"하는 APIService 오브젝트를 추가해야 합니다. 이후 애그리게이션 레이어는 해당 API 경로(예: `/apis/myextensions.mycompany.io/v1/...`)로 들어오는 모든 요청을 등록된 APIService로 프록시합니다.

APIService를 구현하는 가장 일반적인 방법은 클러스터 안에서 실행 중인 파드에 *extension API server*를 띄우는 것입니다. extension API server(*extension-apiserver*라고도 함)로 클러스터의 리소스를 관리할 때는, 보통 하나 이상의 컨트롤러와 함께 구성합니다. apiserver-builder 라이브러리는 extension API server와 이에 연관된 컨트롤러의 스켈레톤 코드를 제공합니다.

---

주요 변경 사항은 다음과 같습니다.

- 문체를 "~한다"에서 "~합니다"로 바꿨습니다. 원문 문체를 유지해야 한다면 말씀해 주세요.
- 긴 문장을 나누고 중복 표현을 정리했습니다. "클러스터 내에 실행되고 있는" → "클러스터 안에서 실행 중인", "extension API server를 사용해서 … 경우 extension API server는" → 반복을 줄였습니다.
- "이때"처럼 흐름에 맞지 않던 접속 표현을 "이후"로 바꿨습니다. 등록 뒤에 일어나는 동작이기 때문입니다.
- "모든 것"을 "모든 요청"으로 구체화했습니다.
- 오타 "컨틀로러"를 "컨트롤러"로 바로잡았습니다.
- "쌍을 이룬다"는 "함께 구성한다"로 풀어 썼습니다.
- API 경로는 코드 서식(`...`)으로 표시했습니다.
