다듬은 글입니다.

---

워크로드 관리에 쓰이는 각 API 종류(kind)를 설명한 문서를 읽을 수 있을 뿐만 아니라, 다음과 같은 특정 작업을 수행하는 방법도 확인할 수 있습니다.

* 디플로이먼트로 스테이트리스(stateless) 애플리케이션 실행
* 스테이트풀(stateful) 애플리케이션을 단일 인스턴스 또는 복제된 세트로 실행
* 크론잡으로 자동화된 작업 실행

코드를 구성(configuration)과 분리하는 쿠버네티스의 메커니즘을 알아보려면 [구성](#)을 참고하세요.

다음 두 가지 개념은 쿠버네티스가 애플리케이션의 파드를 어떻게 관리하는지 이해하는 데 도움이 됩니다.

* 가비지(garbage) 수집: _소유하는 리소스_ 가 제거된 후, 클러스터에 남은 오브젝트를 정리합니다.
* _time-to-live after finished_ 컨트롤러: 잡이 완료된 후 정의된 시간이 지나면 해당 잡을 제거합니다.

애플리케이션이 실행되면 서비스를 통해 인터넷에 노출할 수 있습니다. 웹 애플리케이션이라면 인그레스(Ingress)를 사용할 수도 있습니다.

주요 수정 사항:

- **문장 구조**: 첫 문장의 "각 API 종류에 대해 읽을 수 있을 뿐만 아니라"는 어색해서, 무엇을 읽는지 분명하게 풀어 썼습니다. 원문에 없는 "설명한 문서"라는 표현을 보탰으니 실제 문서 맥락에 맞는지 확인해 주세요.
- **용어 표기**: "스테이트리스"에도 "스테이트풀"처럼 원문(stateless)을 병기해 통일했습니다. "가비지(Garbage)"는 "가비지(garbage)"로 소문자 처리했습니다.
- **어투**: "~바란다"는 "~참고하세요"로, 평서형 "~있다"는 "~있습니다"로 바꿔 읽는 사람에게 말하는 어조로 통일했습니다. 기술 문서 스타일(해라체)을 유지하려면 "~한다" 형태로 되돌리면 됩니다.
- **목록 형식**: 두 번째 목록의 항목을 "개념: 설명" 형태로 맞춰 구조를 분명히 했습니다.
- **마지막 문장**: 원문의 "서비스로 사용하거나, 웹 애플리케이션의 경우에만 인그레스를 이용하여 사용할 수 있다"는 "사용"이 반복되고 "~의 경우에만"이 서비스는 웹 앱에 쓸 수 없다는 뜻으로 오해될 수 있어서, "서비스로 노출하고, 웹 애플리케이션이라면 인그레스도 가능하다"는 의미로 정리했습니다.
- **링크**: "[구성](#)"의 링크는 자리표시자이므로 실제 경로로 바꿔 주세요.
