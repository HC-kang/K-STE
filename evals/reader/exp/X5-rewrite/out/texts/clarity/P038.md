기본적으로 쿠버네티스 API 서버는 로컬호스트가 아닌 첫 번째 네트워크 인터페이스의 6443 포트에서 요청을 받으며, 이 통신은 TLS로 보호됩니다. 일반적인 프로덕션 클러스터에서는 API가 443 포트로 제공됩니다. 포트는 `--secure-port` 플래그로, 수신 대기 IP 주소는 `--bind-address` 플래그로 변경할 수 있습니다.

API 서버는 클라이언트에 인증서를 제시합니다. 이 인증서는 사설 인증 기관(CA)이 서명한 것일 수도 있고, 공인 CA와 연결된 공개 키 인프라(PKI)를 기반으로 한 것일 수도 있습니다. 인증서와 해당 개인 키는 `--tls-cert-file`과 `--tls-private-key-file` 플래그로 지정합니다.

클러스터가 사설 CA를 사용한다면, 해당 CA 인증서의 사본을 클라이언트의 `~/.kube/config`에 설정해야 합니다. 그래야 클라이언트가 API 서버의 인증서를 신뢰할 수 있고, 중간에서 연결을 가로채는 공격이 없었음을 확인할 수 있습니다.

이 단계에서 클라이언트도 TLS 클라이언트 인증서를 제시할 수 있습니다.

**수정한 부분**
- 문체를 "~한다"에서 "~합니다"로 바꿨습니다. 문서 성격에 따라 원래 문체가 필요하면 알려 주세요.
- "서명되거나, … 기반한다"처럼 어색한 병렬 구조를 "~한 것일 수도 있고, ~한 것일 수도 있습니다"로 정리했습니다.
- "공개키 인프라스트럭처"를 일반적으로 쓰는 "공개 키 인프라(PKI)"로 바꿨습니다.
- "연결을 신뢰하고 … 확신할 수 있다"는 주어가 불분명해, 클라이언트가 서버 인증서를 신뢰하고 중간자 공격이 없었음을 확인한다는 의미로 풀었습니다.

마지막 문장의 "이 단계"는 원문에서도 TLS 연결 과정을 가리키는 것으로 보이지만, 앞 문맥만으로는 다소 모호합니다. 원문 앞뒤에 "TLS 핸드셰이크" 같은 설명이 있다면 "TLS 핸드셰이크 단계에서"처럼 구체적으로 쓰는 편이 더 정확합니다.
