쿠버네티스는 필드를 쉽게 제거하거나 리소스 표현을 재구성할 수 있도록, `/api/v1`이나 `/apis/rbac.authorization.k8s.io/v1alpha1`처럼 서로 다른 API 경로에서 여러 API 버전을 지원한다.

버전 규칙은 리소스나 필드 수준이 아니라 API 수준에서 적용된다. 이를 통해 API는 시스템 리소스와 동작을 명확하고 일관되게 보여 주며, 수명이 끝났거나 실험적인 API에 대한 접근도 제어할 수 있다.

또한 API를 더 쉽게 발전시키고 확장할 수 있도록, 쿠버네티스는 활성화하거나 비활성화할 수 있는 API 그룹을 제공한다.

API 리소스는 API 그룹, 리소스 타입, 네임스페이스(네임스페이스에 속하는 리소스의 경우), 이름으로 구분된다. API 서버는 API 버전 간 변환을 투명하게 처리한다. 모든 버전은 사실상 동일한 저장 데이터를 각각 다르게 표현한 것이며, API 서버는 여러 API 버전을 통해 같은 기본 데이터를 제공할 수 있다.

예를 들어 같은 리소스에 `v1`과 `v1beta1`이라는 두 API 버전이 있다고 하자. `v1beta1`로 오브젝트를 만들었다면, `v1beta1`이 사용 중단(deprecated)되어 제거되기 전까지는 `v1beta1`과 `v1` 어느 쪽으로든 그 오브젝트를 읽고, 업데이트하고, 삭제할 수 있다. `v1beta1`이 제거된 이후에는 `v1` API로 계속 오브젝트에 접근하고 수정할 수 있다.

**주요 수정 사항**
- 긴 문장을 나누고 어순을 정리했다. (예: "수명 종료 및/또는 실험적 API" → "수명이 끝났거나 실험적인 API")
- "명확하고 일관된 보기"를 "명확하고 일관되게 보여 주며"로 풀어 썼다.
- "서로 다른 모든 버전은 실제로 동일한 저장된 데이터의 표현이다"를 "같은 저장 데이터를 각각 다르게 표현한 것"으로 바꿔 의미를 분명히 했다.
- 마지막 문단에서 "그 이후부터는"이 가리키는 시점을 "`v1beta1`이 제거된 이후"로 명시했다.
