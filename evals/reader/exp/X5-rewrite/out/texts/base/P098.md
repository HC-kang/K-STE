# 레플리케이션 컨트롤러

## 동작 방식

레플리케이션 컨트롤러는 파드 수를 항상 일정하게 유지한다.

- 파드가 **너무 많으면** 초과한 파드를 제거한다.
- 파드가 **너무 적으면** 부족한 만큼 새 파드를 시작한다.

수동으로 생성한 파드와 달리, 레플리케이션 컨트롤러가 관리하는 파드는 실패하거나 삭제되거나 종료되면 자동으로 교체된다. 예를 들어 커널 업그레이드 같은 파괴적인 유지 보수 작업을 마친 노드에서도 파드가 다시 생성된다.

따라서 애플리케이션에 파드가 하나만 필요하더라도 레플리케이션 컨트롤러를 사용하는 것이 좋다.

레플리케이션 컨트롤러는 프로세스 감시자(supervisor)와 비슷하다. 다만 프로세스 감시자는 단일 노드에서 개별 프로세스를 감시하지만, 레플리케이션 컨트롤러는 **여러 노드에 걸친 여러 파드**를 감시한다.

## 약어

레플리케이션 컨트롤러는 논의할 때 흔히 "rc"로 줄여 부르며, kubectl 명령에서도 이 약어를 단축어로 사용한다.

## 사용 사례

- **단순한 경우:** 레플리케이션 컨트롤러 오브젝트 하나를 생성해, 파드 인스턴스 한 개를 안정적으로 계속 실행한다.
- **복잡한 경우:** 웹 서버처럼 복제된 서비스의 동일한 레플리카를 여러 개 실행한다.
