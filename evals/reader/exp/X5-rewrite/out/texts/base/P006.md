## 완화 조치와 대응 가능한 장애

### 1. IaaS 공급자의 자동 VM 재시작 사용
IaaS VM에 대해 공급자의 자동 재시작 기능을 활성화합니다.
- API 서버 VM 종료 또는 API 서버 충돌
- 지원 서비스 VM 종료 또는 충돌

### 2. 안정적인 스토리지 사용
API 서버와 etcd가 있는 VM에 IaaS 제공자의 안정적인 스토리지(예: GCE PD, AWS EBS 볼륨)를 사용합니다.
- API 서버 백업 스토리지 손실

### 3. 고가용성(HA) 구성 사용
- **컨트롤 플레인 노드 종료 또는 구성 요소(스케줄러, API 서버, 컨트롤러 매니저) 충돌**
  - 동시에 발생하는 하나 이상의 노드 또는 구성 요소 오류를 허용합니다.
- **API 서버 백업 스토리지(etcd 데이터 디렉터리) 손실**
  - 고가용성 etcd 구성을 사용하는 경우에 해당합니다.

### 4. API 서버 PD/EBS 볼륨의 주기적 스냅샷
- API 서버 백업 스토리지 손실
- 일부 운영자 오류
- 일부 쿠버네티스 소프트웨어 오류

### 5. 파드 앞에 레플리케이션 컨트롤러와 서비스 사용
- 노드 종료
- Kubelet 소프트웨어 오류

### 6. 예기치 않은 재시작을 허용하도록 애플리케이션(컨테이너) 설계
- 노드 종료
- Kubelet 소프트웨어 오류

**주요 변경 사항**
- "조치 / 다음을 완화할 수 있음"의 반복 표현을 제목과 목록으로 정리했습니다.
- 반복되던 "다음을 완화할 수 있음"은 각 조치 아래 장애 목록으로 단순화했습니다.
- "i.e.,"를 제거하고 문장 어미를 통일했습니다.

원하시면 표 형식(조치 | 완화 가능한 장애)으로도 정리해 드릴 수 있습니다.
