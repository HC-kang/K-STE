# kube-scheduler

kube-scheduler는 쿠버네티스의 기본 스케줄러로, 컨트롤 플레인의 일부로 실행됩니다. 필요하다면 직접 스케줄링 컴포넌트를 만들어 kube-scheduler 대신 사용할 수도 있도록 설계되었습니다.

## 동작 방식

### 1. 노드 필터링
kube-scheduler는 새로 생성되었거나 아직 스케줄링되지 않은(unscheduled) 파드를 실행할 최적의 노드를 선택합니다. 파드와 그 안의 컨테이너는 각기 다른 요구사항을 가질 수 있으므로, 스케줄러는 파드의 스케줄링 요구사항을 충족하지 못하는 노드를 모두 걸러냅니다.

참고로 API를 사용해 파드를 생성할 때 노드를 직접 지정할 수도 있지만, 이는 드물고 특별한 경우에만 사용합니다.

### 2. 실행 가능한 노드 확인
파드의 스케줄링 요구사항을 충족하는 노드를 *실행 가능한(feasible)* 노드라고 합니다. 적합한 노드가 하나도 없으면, 스케줄러가 파드를 배치할 수 있을 때까지 파드는 스케줄링되지 않은 상태로 유지됩니다.

### 3. 점수 측정 및 노드 선택
스케줄러는 실행 가능한 노드를 찾은 뒤, 각 노드의 점수를 측정하는 일련의 기능을 수행합니다. 그리고 점수가 가장 높은 노드를 골라 파드를 실행합니다.

### 4. 바인딩
마지막으로 스케줄러는 *바인딩(binding)* 이라는 프로세스를 통해 이 결정을 API 서버에 알립니다.

## 스케줄링 시 고려 요소

- 개별 및 집단 리소스 요구사항
- 하드웨어 / 소프트웨어 / 정책 제한조건
- 어피니티(affinity) 및 안티-어피니티(anti-affinity) 명세
- 데이터 지역성(data locality)
- 워크로드 간 간섭

**주요 변경점**
- 전체 흐름을 4단계(필터링 → 실행 가능 노드 확인 → 점수 측정 → 바인딩)로 나누어 소제목을 붙였습니다.
- 긴 문장을 짧게 나누고, 어색한 표현("기능 셋을 수행하고" 등)을 자연스럽게 바꿨습니다.
