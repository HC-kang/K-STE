## 다듬은 글

애그리게이션 레이어는 kube-apiserver 프로세스 안에서 동작합니다. 확장 리소스가 등록되기 전까지는 아무 일도 하지 않습니다.

API를 등록하려면 쿠버네티스 API 안에서 특정 URL 경로를 "요구(claim)"하는 APIService 오브젝트를 추가해야 합니다. 이후 애그리게이션 레이어는 해당 API 경로(예: `/apis/myextensions.mycompany.io/v1/...`)로 들어오는 모든 요청을 등록된 APIService로 프록시합니다.

APIService를 구현하는 가장 일반적인 방법은 클러스터 내 파드에서 *extension API server*를 실행하는 것입니다. extension API server(*extension-apiserver*라고도 함)로 클러스터 리소스를 관리할 때는, 보통 하나 이상의 컨트롤러와 함께 구성합니다. apiserver-builder 라이브러리는 extension API server와 관련 컨트롤러의 스켈레톤 코드를 제공합니다.

### 주요 변경점
- 문장을 "~한다" 체에서 "~합니다" 체로 통일해 읽기 편하게 했습니다.
- "API를 등록하기 위해서, 사용자는 ~ 추가해야 한다"를 "API를 등록하려면 ~ 추가해야 합니다"로 간결하게 바꿨습니다.
- "이때" 같은 불필요한 접속어를 정리하고, "해당 경로로 전송되는 모든 것"을 "들어오는 모든 요청"으로 명확히 표현했습니다.
- 길고 끊긴 문장("~관리하는 경우 / extension API server는 ~ 쌍을 이룬다")을 하나의 흐름으로 합쳤습니다.
- 오타 "컨틀로러"를 "컨트롤러"로 바로잡았습니다.

원문의 문체(~다 체)를 유지하고 싶으시면 그 형태로도 다시 정리해 드릴 수 있습니다.
