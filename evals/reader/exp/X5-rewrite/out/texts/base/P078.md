아래는 의미는 유지하면서 문장을 짧게 나누고 표현을 자연스럽게 다듬은 버전입니다.

---

쿠버네티스는 필드를 쉽게 제거하거나 리소스 표현을 재구성할 수 있도록, `/api/v1`이나 `/apis/rbac.authorization.k8s.io/v1alpha1`처럼 서로 다른 API 경로에서 여러 API 버전을 지원합니다.

버전 규칙은 리소스나 필드 수준이 아니라 API 수준에서 적용됩니다. 이를 통해 API는 시스템 리소스와 동작에 대해 명확하고 일관된 관점을 제공하며, 지원 종료되었거나 실험적인 API에 대한 접근을 제어할 수 있습니다.

또한 API를 더 쉽게 발전시키고 확장할 수 있도록, 쿠버네티스는 활성화하거나 비활성화할 수 있는 API 그룹을 제공합니다.

API 리소스는 API 그룹, 리소스 타입, 네임스페이스(네임스페이스에 속한 리소스의 경우), 이름으로 구분됩니다. API 서버는 API 버전 간 변환을 투명하게 처리합니다. 모든 버전은 사실 같은 저장 데이터를 표현하는 방식일 뿐이며, API 서버는 여러 API 버전을 통해 동일한 데이터를 제공할 수 있습니다.

예를 들어, 같은 리소스에 `v1`과 `v1beta1`이라는 두 API 버전이 있다고 가정해 봅시다. `v1beta1`로 오브젝트를 만들었다면, `v1beta1`이 사용 중단(deprecated)되어 제거되기 전까지는 `v1beta1`과 `v1` 중 어느 쪽으로든 해당 오브젝트를 읽거나 수정하거나 삭제할 수 있습니다. 이후에는 `v1` API로 계속 오브젝트에 접근하고 수정할 수 있습니다.
