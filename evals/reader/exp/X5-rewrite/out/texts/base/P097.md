## API 서버 → kubelet 연결

API 서버에서 kubelet으로의 연결은 다음 용도로 사용된다.

* 파드 로그 가져오기
* 실행 중인 파드에 연결하기 (보통 `kubectl`을 통해)
* kubelet의 포트 포워딩 기능 제공

이 연결은 kubelet의 HTTPS 엔드포인트에서 종료된다. 기본적으로 API 서버는 kubelet의 제공(serving) 인증서를 확인하지 않는다. 이 때문에 연결이 중간자 공격(man-in-the-middle)에 노출될 수 있으며, 신뢰할 수 없는 네트워크나 공용 네트워크에서는 **안전하지 않다**.

### 보안 강화 방법

1. **인증서 확인 활성화 (권장)**
   `--kubelet-certificate-authority` 플래그로 API 서버에 루트 인증서 번들을 제공하면, kubelet의 제공 인증서를 확인할 수 있다.

2. **SSH 터널링 (인증서 확인이 어려운 경우)**
   인증서 확인이 불가능하고 신뢰할 수 없는 네트워크나 공용 네트워크를 거쳐야 한다면, API 서버와 kubelet 사이에 SSH 터널링을 사용한다.

3. **kubelet API 보호**
   kubelet 인증 및/또는 인가를 활성화한다.

- 나열 항목의 문장 형식을 통일했습니다.
- "이것이 가능하지 않은 경우…"처럼 길고 모호한 문장을 조건과 조치가 분명하게 드러나도록 풀어 썼습니다.
- 마지막 문장을 보안 조치 목록에 포함해 구조를 일관되게 했습니다.
