다음 원칙들은 게이트웨이 API의 설계와 아키텍처의 기반이 되었습니다.

* __역할 지향:__ 게이트웨이 API의 리소스 종류(Kind)는 쿠버네티스 서비스 네트워킹을 관리하는 조직 내 역할을 기준으로 모델링되었습니다.
  * __인프라 제공자:__ 여러 테넌트를 서비스할 수 있도록 격리된 다수의 클러스터를 지원하는 인프라를 관리합니다. 클라우드 제공자가 대표적인 예입니다.
  * __클러스터 운영자:__ 클러스터를 관리하며, 주로 정책, 네트워크 접근, 애플리케이션 권한 등에 관심을 둡니다.
  * __애플리케이션 개발자:__ 클러스터에서 실행되는 애플리케이션을 관리하며, 주로 애플리케이션 수준의 구성과 서비스 조합에 관심을 둡니다.
* __이식성:__ 게이트웨이 API 사양은 커스텀 리소스로 정의되며, 다양한 구현체에서 지원됩니다.
* __표현력:__ 게이트웨이 API의 리소스 종류는 헤더 기반 매칭, 트래픽 가중치 설정 등 일반적인 트래픽 라우팅 사용 사례를 기본으로 지원합니다. 인그레스에서는 이러한 기능을 사용하려면 커스텀 어노테이션이 필요했습니다.
* __확장성:__ 게이트웨이 API는 여러 계층에서 커스텀 리소스를 연결할 수 있도록 합니다. 덕분에 API 구조 내 적절한 위치에서 세밀하게 사용자 정의를 할 수 있습니다.

**주요 변경 사항**
* "기반이 되었다" → "~의 기반이 되었습니다"로 수정하고, 문체를 존댓말(합니다체)로 통일했습니다.
* 긴 문장을 나누어 인프라 제공자 설명을 간결하게 정리했습니다.
* 표현력 항목은 "인그레스에서는 커스텀 어노테이션이 필요했다"는 내용을 별도 문장으로 분리해 의미가 더 분명해지도록 했습니다.
* 어색한 줄바꿈을 제거하고 "애플리케이션 레벨"을 "애플리케이션 수준"으로 다듬었습니다.
