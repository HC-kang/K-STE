네임스페이스에 리소스 쿼터가 설정되어 있다면, CPU 상한(limit)의 기본값을 함께 설정하는 것이 좋다. CPU 리소스 쿼터는 네임스페이스에 다음 두 가지 제한을 적용하기 때문이다.

* 네임스페이스에서 실행되는 모든 파드의 모든 컨테이너에는 CPU 상한이 있어야 한다.
* CPU 상한은 파드가 스케줄링될 노드에 리소스를 예약한다. 따라서 해당 네임스페이스의 모든 파드에 예약된 CPU 총량이 지정된 상한을 초과해서는 안 된다.

이를 위해 리밋레인지(LimitRange)를 추가할 때는 다음 사항을 고려해야 한다.

파드의 컨테이너가 자체 CPU 상한을 지정하지 않으면, 컨트롤 플레인이 해당 컨테이너에 기본 CPU 상한을 적용한다. 그러면 이 파드는 CPU 리소스 쿼터가 적용된 네임스페이스에서도 실행될 수 있다.

**주요 변경 사항**
- 끊어진 문장을 자연스럽게 합치고, 불필요한 줄바꿈을 제거했습니다.
- "~하는 것이 좋다. 다음은 ~" 구조를 원인을 밝히는 한 문장으로 연결했습니다.
- "CPU 상한"에 (limit), "리밋레인지"에 (LimitRange)를 병기해 용어를 명확히 했습니다.
- "~될 수 있다"로 끝나던 마지막 문장을 인과 관계가 드러나도록 두 문장으로 나눴습니다.
