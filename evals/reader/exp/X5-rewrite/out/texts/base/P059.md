파드는 앱을 실행하는 여러 컨테이너를 포함할 수 있으며, 앱 컨테이너가 실행되기 전에 동작하는 초기화 컨테이너도 하나 이상 포함할 수 있다.

## 초기화 컨테이너의 특징

초기화 컨테이너는 아래 두 가지를 제외하면 일반 컨테이너와 매우 유사하다.

* 초기화 컨테이너는 항상 완료될 때까지 실행된다.
* 각 초기화 컨테이너는 이전 컨테이너가 성공적으로 완료된 후에야 시작된다.

## 실패 시 동작

* 초기화 컨테이너가 실패하면 kubelet은 성공할 때까지 해당 컨테이너를 반복해서 재시작한다.
* 단, 파드의 `restartPolicy`가 `Never`인 경우에는 초기화 컨테이너가 실패하는 즉시 쿠버네티스가 파드 전체를 실패한 것으로 처리한다.

## 초기화 컨테이너 지정 방법

파드 스펙에 `initContainers` 필드를 추가하고, 앱 컨테이너의 `containers` 필드와 같은 형식으로 `container` 항목들을 배열로 나열한다. 컨테이너에 대한 자세한 내용은 API 레퍼런스를 참고한다.

## 상태 확인

초기화 컨테이너의 상태는 `.status.initContainerStatuses` 필드에 컨테이너 상태의 배열로 반환된다. 이는 `.status.containerStatuses` 필드와 유사한 형태이다.
