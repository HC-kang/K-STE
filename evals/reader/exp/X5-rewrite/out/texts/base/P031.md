다듬은 글입니다.

---

포그라운드 캐스케이딩 삭제에서는 삭제하려는 소유자 오브젝트가 먼저 *삭제 중* 상태가 된다. 이 상태에서는 소유자 오브젝트에 다음과 같은 일이 일어난다.

* 쿠버네티스 API 서버가 오브젝트의 `metadata.deletionTimestamp` 필드를 오브젝트가 삭제 표시된 시간으로 설정한다.
* 쿠버네티스 API 서버가 `metadata.finalizers` 필드를 `foregroundDeletion`으로 설정한다.
* 삭제 과정이 완료되기 전까지 오브젝트를 쿠버네티스 API를 통해 조회할 수 있다.

소유자 오브젝트가 삭제 중 상태가 되면, 컨트롤러는 종속 오브젝트를 먼저 삭제한다. 모든 종속 오브젝트가 삭제되면 컨트롤러가 소유자 오브젝트를 삭제한다. 이 시점부터는 오브젝트를 쿠버네티스 API를 통해 조회할 수 없다.

포그라운드 캐스케이딩 삭제 중에 소유자 오브젝트의 삭제를 막는 종속 오브젝트는 `ownerReference.blockOwnerDeletion=true` 필드를 가진 오브젝트다. 더 자세한 내용은 [포그라운드 캐스케이딩 삭제 사용하기](https://kubernetes.io/ko/docs/tasks/administer-cluster/use-cascading-deletion/#use-foreground-cascading-deletion)를 참고한다.

**주요 변경 사항**

- 문장 끝의 콜론(`:`)을 마침표로 바꾸고, 불필요한 들여쓰기와 줄바꿈을 정리했습니다.
- "일어난다" 앞의 "에게"를 "에"로 고쳐 무생물 주어에 맞게 자연스럽게 했습니다.
- `foregroundDeletion`로 → `foregroundDeletion`으로 (조사 교정)
- 세 번째 항목은 어순을 바꿔 읽기 쉽게 했습니다.
- "삭제 중 상태가 된 이후" → "삭제 중 상태가 되면"으로 간결하게 줄이고, "종속 오브젝트를 먼저 삭제한다"로 순서를 분명히 했습니다.
- "삭제되고나면"의 띄어쓰기를 바로잡고 "삭제되면"으로 단순화했습니다.
- "종속 오브젝트는`ownerReference...`"처럼 붙어 있던 코드 표기 앞뒤에 공백을 넣었습니다.
- 영문 "Use foreground cascading deletion"은 한국어 문서 제목으로 옮기고 링크 형태로 표시했습니다. 링크 주소는 공식 한국어 문서 구조를 기준으로 한 것이니, 실제 사용 전에 확인해 주세요.
