## LimitRange 동작 방식

**기본 흐름**
1. 관리자가 네임스페이스에 `LimitRange`를 생성한다.
2. 사용자가 해당 네임스페이스에서 파드, 퍼시스턴트볼륨클레임(PVC) 등의 오브젝트를 생성(또는 생성 시도)한다.

**`LimitRange`가 하는 일**
- **기본값 적용**: `LimitRange` 어드미션 컨트롤러는 컴퓨팅 리소스 요구사항을 설정하지 않은 파드(및 해당 컨테이너)에 기본 요청(request)과 제한(limit) 값을 적용한다.
- **제약 조건 검증**: 사용량을 추적하여, 네임스페이스의 `LimitRange`에 정의된 리소스 최솟값, 최댓값, 비율을 초과하지 않는지 확인한다.

**제약 조건 위반 시**
- 파드, 컨테이너, PVC를 생성하거나 업데이트할 때 `LimitRange` 제약 조건을 위반하면 API 서버 요청이 실패한다.
- 이때 HTTP 상태 코드 `403 FORBIDDEN`과 함께 위반된 제약 조건을 설명하는 메시지가 반환된다.

**유의 사항**
- **컴퓨팅 리소스 지정**: `cpu`, `memory` 같은 컴퓨팅 리소스에 `LimitRange`가 설정된 네임스페이스에서는 사용자가 해당 값의 요청 또는 제한을 지정해야 한다. 그렇지 않으면 파드 생성이 거부될 수 있다.
- **기존 파드는 영향 없음**: `LimitRange` 유효성 검사는 파드 어드미션 단계에서만 수행되며, 실행 중인 파드에는 적용되지 않는다. `LimitRange`를 추가하거나 수정해도 이미 존재하는 파드는 변경 없이 유지된다.
- **복수의 `LimitRange`**: 한 네임스페이스에 `LimitRange`가 둘 이상 있으면 어떤 기본값이 적용될지 결정적이지 않다(예측할 수 없다).

**주요 개선점**
- 흐름, 기능, 위반 시 동작, 유의 사항으로 묶어 구조화했다.
- 긴 문장을 나누고 "리밋레인지"를 `LimitRange`로 통일했다.
- 원문 의미는 그대로 유지했다.
