파드 스펙의 컨테이너를 시작하기 전에, 파드는 정해진 순서대로 초기화 컨테이너를 먼저 실행합니다.

첫 번째 초기화 컨테이너인 `init-mysql`은 파드의 인덱스에 따라 MySQL 설정 파일을 생성합니다.

이 스크립트는 `hostname` 명령이 반환하는 파드 이름의 마지막 부분에서 인덱스를 추출합니다. 그런 다음 이 인덱스에 오프셋 숫자를 더해(이미 사용 중인 값과 겹치지 않도록) MySQL `conf.d` 디렉토리의 `server-id.cnf` 파일에 저장합니다. 이렇게 하면 스테이트풀셋이 부여한 고유하고 안정적인 신원이, 같은 속성을 요구하는 MySQL 서버 ID로 변환됩니다.

또한 `init-mysql` 컨테이너의 스크립트는 컨피그맵의 설정 파일을 `conf.d`로 복사해 `primary.cnf` 또는 `replica.cnf`를 적용합니다. 이 예제의 토폴로지는 하나의 주 MySQL 서버와 여러 레플리카로 구성되므로, 스크립트는 인덱스 `0`을 주 서버로, 나머지를 레플리카로 지정합니다. 여기에 스테이트풀셋 컨트롤러의 [디플로이먼트와 스케일링 보증](https://kubernetes.io/ko/docs/concepts/workloads/controllers/statefulset/#배포와-스케일링-보증)이 더해지면, 복제용 레플리카를 생성하기 전에 주 서버가 Ready 상태가 되도록 보장할 수 있습니다.

**주요 변경 사항**
- 긴 문장을 나누고 어순을 정리했습니다. (예: "인덱스(…오프셋 숫자와 함께)를 저장한다" → "인덱스에 오프셋 숫자를 더해 저장합니다")
- "스테이트풀셋에게서 제공된"을 "스테이트풀셋이 부여한"으로 바꾸는 등 어색한 표현을 자연스럽게 고쳤습니다.
- 문체를 "~한다"에서 "~합니다"로 통일했습니다. 원문 문체를 유지하려면 알려 주세요.
- 링크는 제가 임의로 추가한 것이니, 필요 없으면 제거하세요.
