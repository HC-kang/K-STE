kubelet은 각 자격 증명 공급자의 `matchImages` 필드를 사용해, 파드가 사용하는 이미지에 대해 플러그인을 호출할지 결정합니다.

## Glob 사용 규칙

- Glob은 도메인에서만 사용할 수 있으며, 포트나 경로에서는 사용할 수 없습니다.
- 서브도메인(`*.k8s.io`, `k8s.*.io`)과 최상위 도메인(`k8s.*`)에서 사용할 수 있습니다.
- `app*.k8s.io`처럼 서브도메인의 일부만 매칭하는 것도 지원합니다.
- 각 Glob은 하나의 하위 도메인 세그먼트하고만 일치합니다. 따라서 `*.io`는 `*.k8s.io`와 일치하지 않습니다.

## 매치 조건

이미지 이름과 `matchImages` 항목은 아래 조건을 모두 만족할 때 일치합니다.

- 두 값의 도메인 파트 수가 같고, 각 파트가 서로 일치합니다.
- `matchImages` 항목의 URL 경로가 대상 이미지 URL 경로의 접두사입니다.
- `matchImages` 항목에 포트가 있으면, 이미지에도 같은 포트가 있어야 합니다.

## `matchImages` 패턴 예시

- `123456789.dkr.ecr.us-east-1.amazonaws.com`
- `*.azurecr.io`
- `gcr.io`
- `*.*.registry.io`
- `foo.registry.io:8080/path`

## 주요 변경 사항

- "Globs는 … 사용할 수 있지만"을 "Glob은 … 사용할 수 있으며"로 바꿔 표기를 통일하고 문장을 간결하게 했습니다.
- 분산되어 있던 Glob 관련 설명을 목록으로 정리했습니다.
- 원문의 `imageMatch`는 `matchImages`의 오기로 보여 `matchImages`로 통일했습니다.
- 매치 조건이 "모두" 충족되어야 한다는 점을 명시했습니다.
