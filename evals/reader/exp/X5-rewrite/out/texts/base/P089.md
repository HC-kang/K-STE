다듬은 글입니다.

---

워크로드 관리에 사용하는 각 API 종류(kind)를 이해하는 데 그치지 않고, 특정 작업을 수행하는 방법도 확인할 수 있습니다.

* 디플로이먼트로 스테이트리스(stateless) 애플리케이션 실행하기
* 스테이트풀(stateful) 애플리케이션을 단일 인스턴스 또는 복제된 세트로 실행하기
* 크론잡(CronJob)으로 자동화된 작업 실행하기

코드와 구성(configuration)을 분리하는 쿠버네티스의 메커니즘이 궁금하다면 [구성](#) 문서를 참고하세요.

다음 두 가지 개념을 알아 두면 쿠버네티스가 애플리케이션의 파드를 어떻게 관리하는지 이해하는 데 도움이 됩니다.

* **가비지(Garbage) 수집**: _소유하는 리소스_ 가 제거된 후, 클러스터에 남은 오브젝트를 정리합니다.
* **TTL-after-finished 컨트롤러**: 잡이 완료된 뒤 정해진 시간이 지나면 해당 잡을 제거합니다.

애플리케이션이 실행된 후에는 서비스(Service)를 통해 인터넷에 노출할 수 있습니다. 웹 애플리케이션이라면 인그레스(Ingress)를 이용할 수도 있습니다.

- 마지막 문장은 의미가 모호해서 "서비스로 노출, 웹 애플리케이션은 인그레스도 가능"으로 풀어 썼습니다. 원문 의도와 다르면 알려 주세요.
- 문체는 "~합니다/하세요" 형태의 존댓말로 통일했습니다. 원문 문서 스타일에 맞춰 "~한다"체가 필요하면 바꿔 드리겠습니다.
