kubectl은 apiserver의 위치 파악과 인증을 대신 처리해 줍니다. curl, wget, 웹 브라우저 같은 HTTP 클라이언트로 REST API에 직접 접근하려면, 위치 파악과 인증을 직접 해결해야 하며 방법은 크게 두 가지입니다.

## 1. kubectl을 proxy 모드로 실행 (권장)

- 저장된 apiserver 위치를 사용합니다.
- self-signed 인증서로 apiserver의 신원(identity)을 검증하므로 MITM(중간자 공격)이 불가능합니다.
- apiserver 인증을 대신 처리합니다.
- 향후에는 클라이언트 측의 지능형 로드 밸런싱과 failover도 지원될 예정입니다.

## 2. HTTP 클라이언트에 위치 및 인증 정보를 직접 제공 (대안)

- proxy 사용 시 혼동을 일으키는 일부 클라이언트 코드에서도 동작합니다.
- MITM을 방지하려면 root 인증서를 브라우저로 임포트해야 합니다.
