# 묶음 5-1: 결제 승인 재시도 시 고객 알림 중복 발송 수정

## 배경
중복 승인 요청이 발생하면 고객에게 결제 알림이 두 번 나갑니다. 이 PR은 이 문제를 수정합니다.

- 담당 개발자: 서다온
- 대상 독자: 결제 백엔드 개발자, 배포 검토자

## 변경 내용
변경 대상은 아래 두 작업이며, 둘 다 결제 운영 콘솔에서 실행합니다.

| 작업 | 재시도 간격 | 최대 횟수 |
|---|---|---|
| 승인 재시도 | 30초 | 3회 |
| 알림 재전송 | 60초 | 2회 |

## DB 변경
- 주문 DB와 정산 DB에 각각 조회 인덱스를 추가합니다.
- 기존 컬럼은 삭제하지 않습니다.
- 배포 전에 DB 스냅샷을 반드시 보관합니다.

## 일정
| 항목 | 일시 |
|---|---|
| 검토 완료 기한 | 11/11(수) 17:00 |
| 사전 검사 | 11/12(목) 13:30 |
| 배포 | 11/12(목) 14:00 |

배포 담당은 문해솔입니다.

## 사전 검사
이번 배포의 사전 검사 작업은 결제 무결성 검사(페이체크) 하나입니다.

- 실행자: 서다온
- 방법: 표본 240건 대조
- 실패 시: 배포를 중단합니다.

## 배포 검토자 확인 사항
- 재시도 테스트 통과 기록을 첨부해야 합니다.
- 내부 시험 상점은 테스트 대상에서 제외합니다.
- 문의는 #결제-변경 채널로 남겨 주세요.

## 배포 후 주의
배포 직후 20분 동안은 승인 재시도 작업과 알림 재전송 작업을 수동으로 실행하지 않습니다.

## 병합 조건
- PM 승인 댓글을 받은 뒤에 병합합니다.
- 이번 결제 개편에는 제품 관리자 이나루와 프로젝트 관리자 강도윤이 참여합니다.

---

**작성 전 확인이 필요한 부분**
1. "배포 직후 20분 수동 실행 금지"의 대상을 "그거"로만 적으셨습니다. 앞뒤 맥락으로 보아 승인 재시도와 알림 재전송 두 작업으로 해석했습니다. 사전 검사만 해당한다면 수정이 필요합니다.
2. "결제 무결성 검사"와 "페이체크"는 같은 작업으로 보고 하나로 묶었습니다. 별개의 작업이라면 "단일 사전 검사"라는 설명과 맞지 않으니 알려 주세요.
3. PM 승인 댓글을 누가 남기는지는 적혀 있지 않아서 이나루, 강도윤을 승인자로 단정하지 않고 참여자로만 적었습니다. 승인자가 정해져 있다면 병합 조건에 이름을 넣겠습니다.
