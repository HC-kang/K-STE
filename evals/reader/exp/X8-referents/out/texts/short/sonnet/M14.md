# 출고 파동 조정 PR: 긴급 주문 피킹 지연 수정

문서 식별자: 묶음 5-2

이 PR은 피킹 대기열에서 긴급 주문이 뒤로 밀리는 문제를 수정한다. 개발 담당은 배시온이다. 독자는 모래결로지스의 창고 운영 책임자와 물류 서비스 QA 담당자이다.

## 변경 내용

- 피킹 순서 화면과 포장 대기 화면을 변경한다.
- 두 화면은 모두 서부 시험창고 운영 포털에서 사용한다.
- 피킹 묶음 상한은 80건이다.
- 포장 묶음 상한은 50건이다.
- 상한을 초과한 주문은 다음 묶음으로 이동한다.

## 일정

| 항목 | 일시 |
|---|---|
| QA 결과 등록 기한 | 11/18(수) 16:00 |
| 시험 적용 | 11/19(목) 09:00 |
| 출고 누락 대조표 첫 보고서 생성 | 11/19(목) 10:00 |

## 시험 환경

시험창고 서버와 교육창고 서버에 같은 버전을 설치한다. 두 서버의 입력 방식은 다르다.

| 서버 | 입력 방식 |
|---|---|
| 시험창고 서버 | 실물 스캐너 연결 |
| 교육창고 서버 | 모의 입력 사용 |

## 신규 보고서

이번 PR의 유일한 신규 보고서는 출고 누락 대조표이다. 담당은 오라겸이다. 11/19(목) 10:00에 첫 보고서를 생성하고, 이때 주문 600건을 대조한다.

**누락이 1건 이상이면 시험을 중단한다.**

## QA 안내

- QA 담당자는 긴급 주문 우선 배치 결과를 등록해야 한다.
- 예약 출고 주문은 우선 배치에서 제외한다.
- 문의는 #창고-QA 채널로 한다.

## 운영 조건

- 서버를 재시작할 때는 창고 운영 책임자가 입회해야 한다.
- 시험을 시작하려면 DR(재해 복구) 완료 기록을 PR에 첨부해야 한다.
- 이번 변경에는 재해 복구 담당 유재하와 설계 검토 담당 노세린이 참여한다.

## 확인 필요

- 원문 "거기는 첫날 현장 작업자 계정 접근 차단"에서 "거기"가 가리키는 곳이 어디인지 확인이 필요하다. 시험창고 서버, 교육창고 서버, 운영 포털 중 어느 대상인지 알 수 없어 이 항목은 본문에 쓰지 않았다.
- 원문의 "웨이브북"이 "출고 누락 대조표"와 같은 보고서인지 확인이 필요하다. 담당, 일시, 대조 건수가 같지만 이름이 달라 같은 보고서로 단정하지 않았다.
