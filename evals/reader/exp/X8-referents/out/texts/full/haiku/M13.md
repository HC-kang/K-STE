# 결제 재시도 PR 설명 (묶음 5-1)

이 PR은 중복 승인 요청 때문에 고객 결제 알림이 두 번 나가는 문제를 수정한다. 담당 개발자는 서다온이다. 변경 대상은 승인 재시도 작업과 알림 재전송 작업이며, 두 작업은 모두 결제 운영 콘솔에서 실행한다. 배포는 11/12(목) 14:00에 하고, 배포 담당은 문해솔이다. 검토는 11/11(수) 17:00까지 마쳐야 한다.

## 변경 내용

재시도 설정은 다음과 같다.

| 작업 | 재시도 간격 | 최대 횟수 |
|---|---|---|
| 승인 재시도 작업 | 30초 | 3회 |
| 알림 재전송 작업 | 60초 | 2회 |

주문 DB와 정산 DB에 조회 인덱스를 각각 추가한다. 기존 컬럼은 삭제하지 않는다.

## 일정

- 검토 기한: 11/11(수) 17:00까지
- 사전 검사 실행: 11/12(목) 13:30에
- 배포 실행: 11/12(목) 14:00에

## 배포 절차

1. 배포 전에 DB 스냅샷을 보관해야 한다.
2. 서다온이 11/12(목) 13:30에 사전 검사를 실행하여 표본 240건을 대조한다. 사전 검사가 실패하면 배포를 중단해야 한다.
3. 11/12(목) 14:00에 배포한다.
4. 배포 직후 20분 동안 확인 필요 1의 대상 작업을 수동으로 실행하면 안 된다.

## 검토 요건

- 검토자는 재시도 테스트 통과 기록을 PR에 첨부해야 한다.
- 내부 시험 상점은 테스트 대상에서 제외한다.
- 문의는 #결제-변경 채널로 한다.

## 병합 조건

PM 승인 댓글을 받은 뒤 병합한다. 제품 관리자 이나루와 프로젝트 관리자 강도윤이 이번 결제 개편에 참여했다.

## 확인 필요

- 확인 필요 1: "그거는 배포 직후 20분 동안 수동 실행 금지"의 "그거". 승인 재시도 작업과 알림 재전송 작업을 모두 가리키는지, 사전 검사 작업을 가리키는지 원문에 없다.
- 확인 필요 2: 사전 검사 명칭. 원문에 "결제 무결성 검사"와 "페이체크"가 각각 쓰였다. 두 이름이 같은 작업을 가리키는지 원문에 없다.
- 확인 필요 3: DB 스냅샷 대상. "DB"가 주문 DB와 정산 DB를 모두 가리키는지, 하나만 가리키는지 원문에 없다.
