# [묶음 5 · PR 5-1] 노벨릿커머스 주문 중복 차단 변경

## 개요

주문 API의 재시도 처리 모듈에서 **동일한 요청 키가 재사용되면 주문이 중복 생성되는 문제**를 수정합니다. 중복 차단 기준을 명확히 정의하고, 요청 키가 없는 요청의 처리 방식은 기존과 동일하게 유지합니다.

- **개발 담당:** 서리안
- **검증 담당:** 주문QA팀
- **문의:** 사내 #주문변경 채널
- **변경 위치:** 주문 API 재시도 처리 모듈
- **대상 환경:** 스테이징 주문 서버, 스테이징 환불 서버 (두 서버 모두 비교 시험에 사용)

## 변경 내용

1. **중복 차단 기준 추가**
   - 동일한 요청 키를 수신한 뒤 **90초 동안** 같은 키의 요청을 중복으로 판단하고 새 주문 생성을 차단합니다.
   - 요청 키가 없는 요청은 **기존 처리 방식을 그대로 유지**합니다.

2. **서버 요청 로그 보관 기간 변경**
   - 서버의 요청 로그 보관 기간을 **48시간**으로 변경합니다.
   - 이 변경은 중복 차단 로직과 별도 항목입니다. 리뷰 시 함께 확인해 주세요.

## 검증 계획

- **담당:** 주문QA팀
- **일시:** 11/10(화) 14:00 ~ 15:00
- **방식:** 서버별 요청 240건씩 비교 시험
- **합격 기준:** 실패 0건

## 리뷰 요청 사항

- 90초 차단 구간이 재시도 처리 흐름과 맞는지 확인해 주세요.
- 요청 키가 없는 요청이 기존 경로로 그대로 처리되는지 확인해 주세요.
- 로그 보관 기간 48시간 변경이 의도한 설정인지 확인해 주세요.
