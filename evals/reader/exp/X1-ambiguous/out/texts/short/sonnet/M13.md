# 묶음 5 PR 5-1: 노벨릿커머스 주문 중복 차단 변경

이 PR은 주문 API의 재시도 처리 모듈에서 동일 요청 키를 재사용하면 주문이 중복 생성되는 문제를 수정한다.

## 담당

- 개발 담당은 서리안이다.
- 검증 담당은 주문QA팀이다.
- 문의는 사내 #주문변경 채널로 한다.

## 변경 내용

- 변경 위치는 주문 API의 재시도 처리 모듈이다.
- 새 중복 차단 기준은 동일 요청 키 수신 후 90초이다.
- 요청 키가 없는 요청은 기존 처리를 유지한다.
- 서버의 요청 로그 보관 기간을 48시간으로 변경한다.

## 검증

- 대상 환경은 스테이징 주문 서버와 스테이징 환불 서버이다. 두 서버를 모두 비교 시험에 사용한다.
- 주문QA팀이 11/10(화) 14:00~15:00에 비교 시험을 한다.
- 요청은 서버별 240건이다.
- 실패는 0건이다.

## 일정과 병합 조건

- 리뷰 의견은 11/12(목)에 등록한다.
- 병합 전에 비교 시험 결과표를 PR 첨부란에 업로드해야 한다.
- 코드 리뷰어 전원이 승인해야 한다.
- 서리안이 11/13(금) 10:00에 병합한다.
- 승인이 하나라도 없으면 병합을 보류한다.

## 확인 필요

- 90초 기준이 동일 요청 키를 수신한 뒤 90초 동안 중복 요청을 차단한다는 뜻인지 확인이 필요하다.
- 요청 로그 보관 기간 48시간이 어느 서버에 적용되는지, 변경 전 기간이 얼마인지 확인이 필요하다.
- 11/12(목)이 리뷰 의견 등록 기한인지 확인이 필요하다.
- 비교 시험 결과표를 누가 업로드하는지 확인이 필요하다.
- 비교 시험 일시가 11/10(화)인데 오늘은 10/18이다. 실패 0건이 실제 실행 결과인지, 예상치인지 확인이 필요하다.
