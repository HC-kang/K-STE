# PR 5-1: 노벨릿커머스 주문 중복 차단 변경

## 개요

이 PR은 노벨릿커머스 주문 플랫폼에서 동일한 요청 키를 재사용하면 주문이 중복 생성되는 문제를 수정한다. 변경 위치는 주문 API의 재시도 처리 모듈이다.

## 담당

- 개발 담당은 서리안이다.
- 검증 담당은 주문QA팀이다.
- 문의는 사내 #주문변경 채널에 한다.

## 변경 내용

- 재시도 처리 모듈의 중복 차단 기준을 새로 적용한다.
- 새 중복 차단 기준은 동일 요청 키를 수신한 뒤 90초이다.
- 요청 키가 없는 요청은 기존 처리 방식을 그대로 둔다.
- 서버의 요청 로그 보관 기간을 48시간으로 변경한다.

확인 필요: 요청 로그 보관 기간 변경 대상이 주문 서버인지, 환불 서버인지, 두 서버 모두인지 확인이 필요하다.

## 대상 환경

- 스테이징 주문 서버
- 스테이징 환불 서버

두 서버 모두 비교 시험에 사용한다.

## 비교 시험

주문QA팀은 11/10(화) 14:00-15:00에 서버별 요청 240건으로 비교 시험을 한다.

확인 필요: "실패 0건"이 실제 시험 결과인지, 통과 기준인지 확인이 필요하다.

## 병합 전 필요 사항

- 비교 시험 결과표는 병합 전에 PR 첨부란에 업로드해야 한다.
- 코드 리뷰어 전원이 승인해야 한다.
- 승인이 하나라도 없으면 병합을 보류한다.
- 리뷰어는 11/12(목)에 리뷰 의견을 등록한다.

## 일정

- 주문QA팀은 11/10(화) 14:00-15:00에 비교 시험을 한다.
- 리뷰어는 11/12(목)에 리뷰 의견을 등록한다.
- 서리안은 11/13(금) 10:00에 병합한다.
