# 노벨릿커머스 주문 중복 차단 변경 (묶음 5 · PR 5-1)

주문 API의 재시도 처리 모듈에서 동일 요청 키를 다시 쓰면 주문이 중복 생성되던 문제를 수정한다. 주문QA팀이 스테이징 주문 서버와 스테이징 환불 서버에서 비교 시험을 했고, 서버별 요청 240건에서 실패는 0건이었다. 병합은 코드 리뷰어 전원이 승인해야 한다.

## 변경 내용

- 변경 위치: 주문 API의 재시도 처리 모듈
- 수정한 문제: 동일 요청 키를 다시 쓰면 주문이 중복 생성되는 문제
- 새 중복 차단 기준: 동일 요청 키 수신 후 90초
- 요청 키가 없는 요청은 기존 처리 방식을 유지한다.
- 서버의 요청 로그 보관 기간을 48시간으로 변경한다.

## 검증

- 대상 환경: 스테이징 주문 서버, 스테이징 환불 서버
- 시험 방식: 두 서버 모두 비교 시험에 사용
- 시험 일시: 11/10(화) 14:00~15:00
- 시험 규모: 서버별 요청 240건
- 시험 결과: 실패 0건
- 검증 담당: 주문QA팀

## 리뷰와 병합

- 리뷰 의견 등록: 11/12(목)
- 병합 일시: 11/13(금) 10:00
- 병합 담당: 개발 담당 서리안

병합 전에 비교 시험 결과표를 PR 첨부란에 업로드해야 한다. 코드 리뷰어 전원이 승인해야 한다. 승인이 하나라도 없으면 병합을 보류한다.
