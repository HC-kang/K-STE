# PR #133: 게임 패치 재개 기능(패치 복구 패널)

이 PR은 게임 패치 다운로드를 중단한 뒤 이어서 재개하는 기능을 추가한다. 다운로드 중 연결이 끊기면 패치를 처음부터 다시 받던 동작을 고친다. 개발 담당은 한루온이고, 게임 클라이언트 저장소에서 리뷰한다. 정식 명칭은 패치 복구 패널이며, 팀에서는 이어받기창이라고 부른다.

## 변경 내용

이어받기창은 남은 용량을 MB 단위로 보여 준다. 예상 완료 시각은 이번 변경에 포함하지 않는다.

## 수정 원인

중단 재현 보고서에 따르면 다운로드 중 연결이 끊기면 패치를 처음부터 다시 받았다. 정나겸이 이 보고서를 작성했고, PR #133에 첨부한다.

## 저장 공간 기준

남은 공간이 500MB 미만이면 재개를 차단해야 한다. 개발 전용 계정은 공간 검사에서 제외해야 한다. 저장 공간 보고서는 유서안이 작성했고, PR #133에 첨부한다.

## 일정

1. 12/01(화) 11:00에 출시 후보 빌드를 시험 배포한다.
2. 12/02(수) 18:00까지 중단 후 재개 20회를 전부 성공시켜야 한다.
3. 12/03(목) 14:00에 출시 위원회가 열린다. 의장은 배시온이며, 위원회가 정식 배포 여부를 심의한다.
4. 12/04(금) 10:00에 정식 배포를 예정하며, 한루온이 진행한다.

앞서 올린 문서는 출시 위원회 시작 1시간 전까지 배시온에게 보내야 한다.

## 검증 계획

1. 검증용 계정 8개를 실험실에 전달해야 한다. 확인 필요: 실험실. 두 실험실 모두에 전달하는지, 하나에만 전달하는지 원문에 없다. 전달 담당자도 원문에 없다.
2. 계정 전달이 끝난 뒤 리뷰를 시작해야 한다.
3. 모바일 실험실에서는 휴대전화로 패치 재개를 검증한다. 담당은 정나겸이다.
4. 콘솔 실험실에서는 거치형 기기로 패치 재개를 검증한다. 담당은 유서안이며, 검증 결과는 PR #133에 댓글로 올린다.
5. 검증 담당자는 내부 시험 환경 '별무리-패치'에서 중단 후 재개를 20회 실행하고, 12/02(수) 18:00까지 전부 성공시켜야 한다.

**실패가 한 번이라도 나오면 병합하면 안 된다.**

## 병합 조건

RC 검토 기록은 병합 전에 PR #133의 출시 검토 칸에 연결해야 한다. 이 연결은 필수다.

## 배포 후 확인

배포 후 첫 30분 동안 다운로드 실패율을 5분마다 기록해야 한다. 확인 필요: 기록 담당자. 원문에 누가 기록하는지 없다.

## 문의

기능 문의는 클라이언트개발 채널의 한루온에게 한다.
