# 결제 재시도 중복 알림 수정 (묶음 5-1)

이 PR은 중복 승인 요청 때문에 고객 결제 알림이 두 번 나가는 문제를 수정한다. 담당 개발자는 서다온이다. 변경 대상은 승인 재시도 작업과 알림 재전송 작업이며, 두 작업 모두 결제 운영 콘솔에서 실행한다. 배포는 11/12(목) 14:00에 실행하며, 배포 담당은 문해솔이다.

## 변경 내용

승인 재시도 작업과 알림 재전송 작업의 재시도 간격과 최대 횟수는 다음과 같다.

| 작업 | 재시도 간격 | 최대 횟수 |
|---|---|---|
| 승인 재시도 | 30초 | 3회 |
| 알림 재전송 | 60초 | 2회 |

주문 DB와 정산 DB에 각각 조회 인덱스를 추가한다. 기존 컬럼은 삭제하지 않는다.

## 일정

| 구분 | 일시 | 성격 |
|---|---|---|
| 사전 검사 | 11/12(목) 13:30 | 실행일 |
| 배포 | 11/12(목) 14:00 | 실행일 |
| 검토 기한 | 11/11(수) 17:00까지 | 기한 |

## 배포 절차

1. 배포 전에 DB 스냅샷을 보관해야 한다.
2. 서다온이 11/12(목) 13:30에 결제 무결성 검사를 실행하고, 표본 240건을 대조한다.
3. 검사가 실패하면 배포를 중단해야 한다.
4. 문해솔이 11/12(목) 14:00에 배포한다.

확인 필요: 페이체크. 결제 무결성 검사와 같은 작업인지 원문에 밝혀져 있지 않다.

확인 필요: 그거는 배포 직후 20분 동안 수동 실행 금지. 가능한 해석은 승인 재시도 작업과 알림 재전송 작업 전체, 또는 결제 무결성 검사 중 하나다.

## 검토 요건

- 배포 검토자는 재시도 테스트 통과 기록을 첨부해야 한다.
- 내부 시험 상점은 테스트 대상에서 제외한다.
- 문의는 #결제-변경 채널로 한다.
