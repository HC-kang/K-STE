# 누리펄스 캐시 전환 런북

이 런북은 11월 12일(목) 23시 10분부터 23시 40분까지 진행하는 검색 캐시와 추천 캐시 전환 작업의 절차를 정한다. 실행 담당은 야간 당직자 문세린이다. 캐시 갱신 지연으로 검색 결과 누락이 발생하였으므로, 전환 전후의 오류율을 측정하고 그 결과에 따라 복원 여부를 판정한다. 작업 기록은 운영 포털의 야간 작업함에 저장한다.

## 1. 작업 개요

- 일시: 11월 12일(목) 23시 10분 시작, 23시 40분 종료
- 대상: 검색 캐시, 추천 캐시
- 실행 담당: 야간 당직자 문세린
- 작업 위치: 사내 운영 포털의 검색 탭과 추천 탭 각각
- 작업 기록 저장 위치: 운영 포털의 야간 작업함

## 2. 역할과 연락처

- 문세린: 실행 담당. 복원 지점 2개 등록, 서버 재시작 승인.
- 나도윤(제품 관리자), 서이안(프로젝트 관리자): 작업 시간 동안 사내 메신저에서 대기한다.
- 윤하민(플랫폼지원팀): 오류율 조회 불가 또는 복원 실패 시 내선 4726으로 즉시 연락한다.

확인 필요: PM. 프로젝트 관리자 서이안을 가리키는 경우와 원문에 없는 다른 인물을 가리키는 경우가 있다.

## 3. 작업 전 준비

1. 검색 캐시의 전환 전 오류율을 5분간 측정하고, 측정값을 작업 기록에 남긴다.
2. 추천 캐시의 전환 전 오류율을 5분간 측정하고, 측정값을 작업 기록에 남긴다.

확인 필요: 전환 전 5분 측정의 시작 시각. 23시 10분 전 5분인지, 23시 10분 이후인지 원문에 없다.

3. 전환 직전 스냅샷을 1개 추가로 저장한다.

확인 필요: 스냅샷 1개의 범위. 검색 캐시와 추천 캐시를 합쳐 1개인지, 캐시별로 1개씩인지 원문에 없다. 저장 담당자도 지정되어 있지 않다.

4. 운영 포털의 장비 탭에서 검색 로그 서버와 추천 로그 서버의 상태를 각각 조회한다. 검색 로그 서버와 추천 로그 서버는 별도 장비다.

확인 필요: 서버 상태의 판단 기준. 원문에 상태를 판단하는 기준이 없다.

## 4. 복원 지점 등록 (23시 20분)

1. 캐시 복원 작업의 실행 화면은 복원 제어판 1개만 사용한다.
2. 23시 20분에 문세린이 복원 지점 2개를 등록한다.
3. 되돌림 데스크에 복원 지점 2개가 표시되는지 개수를 대조한다. 표시 개수 대조는 필수다.

확인 필요: 되돌림 데스크 개수 대조의 담당자. 표시 개수가 2개가 아닐 때의 조치도 원문에 없다.

## 5. 전환 실행 (23시 10분부터 23시 40분까지)

1. 23시 10분에 검색 캐시와 추천 캐시의 전환 작업을 시작한다.
2. 작업 시간 동안 나도윤과 서이안은 사내 메신저에서 대기한다.
3. 23시 40분에 전환 작업을 종료한다.

서버를 재시작해야 할 때는 문세린의 승인을 받은 뒤에만 재시작한다. 승인 전에는 서버를 재시작하면 안 된다.

## 6. 전환 후 오류율 판정

1. 전환 후 오류율을 측정한다.

확인 필요: 전환 후 오류율의 측정 시각과 측정 기간. 원문에 시점이 없다.

2. 오류율이 2%를 초과하면 즉시 복원해야 한다. 복원은 복원 제어판에서 등록된 복원 지점으로 진행한다.
3. 오류율이 2% 이하이면 복원하지 않고 관찰을 유지한다.
4. 후속 점검은 11월 13일(금) 09시에 한다.

확인 필요: 후속 점검의 담당자.

## 7. 예외 상황

- 오류율을 조회할 수 없으면 플랫폼지원팀 윤하민에게 내선 4726으로 즉시 연락한다.
- 복원이 실패하면 플랫폼지원팀 윤하민에게 내선 4726으로 즉시 연락한다.

## 8. 작업 기록과 보고

1. 작업 기록은 운영 포털의 야간 작업함에 저장한다.
2. 전환 완료 보고서를 PM에게 전달한다.
3. 전환 완료 보고서를 PM에게 전달하기 전에는 당직을 교대하면 안 된다.

확인 필요: PM의 대상. 위 2항의 PM이 누구를 가리키는지 원문에 없다. 당직 교대 금지가 풀리는 조건도 전달 완료 시점으로 충분한지 원문에 없다.
