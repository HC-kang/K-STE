# 결제 재시도 PR 설명 (묶음 5-1)

문서 식별자: 묶음 5-1

이 PR은 중복 승인 요청 때문에 고객 결제 알림이 두 번 나가는 문제를 고친다. 담당 개발자는 서다온이다. 배포는 11/12(목) 14:00에 하고, 배포 검토는 11/11(수) 17:00까지 끝내야 한다.

## 변경 내용

변경 대상은 승인 재시도 작업과 알림 재전송 작업이다. 두 작업 모두 결제 운영 콘솔에서 실행한다.

| 작업 | 재시도 간격 | 최대 횟수 |
|---|---|---|
| 승인 재시도 | 30초 | 3회 |
| 알림 재전송 | 60초 | 2회 |

주문 DB와 정산 DB에 각각 조회 인덱스를 추가한다. 기존 컬럼은 삭제하지 않는다.

## 일정

| 일시 | 구분 | 내용 | 담당 |
|---|---|---|---|
| 11/11(수) 17:00 | 기한 | 배포 검토를 끝내야 하는 시각 | 배포 검토자 |
| 11/12(목) 13:30 | 실행일 | 결제 무결성 검사 | 서다온 |
| 11/12(목) 14:00 | 실행일 | 배포 | 문해솔 |

## 배포 전 요구사항

- DB 스냅샷을 배포 전에 보관해야 한다.
- 결제 무결성 검사(페이체크)를 배포 전에 해야 한다. 서다온이 11/12(목) 13:30에 표본 240건을 대조한다. 이번 배포의 사전 검사 작업은 이 검사 하나이다.
- 결제 무결성 검사에 실패하면 배포를 중단해야 한다.
- 배포 검토자는 재시도 테스트 통과 기록을 첨부해야 한다.
- 내부 시험 상점은 테스트 대상에서 제외해야 한다.

## 배포 후 제한

배포 직후 20분 동안 수동 실행을 하면 안 된다.

## 병합

PM 승인 댓글을 받은 뒤 병합해야 한다. 제품 관리자 이나루와 프로젝트 관리자 강도윤은 모두 이번 결제 개편에 참여한다.

## 문의

#결제-변경 채널에 문의한다.

확인 필요: "그거는 배포 직후 20분 동안 수동 실행 금지". 수동 실행을 금지하는 대상이 승인 재시도 작업과 알림 재전송 작업인지, 결제 무결성 검사인지 원문에 없다.

확인 필요: "PM 승인 댓글". 승인 댓글을 쓸 사람이 제품 관리자 이나루인지, 프로젝트 관리자 강도윤인지 원문에 없다. 두 사람 모두의 댓글이 필요한지도 알 수 없다.

확인 필요: "DB는 배포 전에 스냅샷 보관". 스냅샷을 보관할 DB가 주문 DB와 정산 DB 둘 다인지, 다른 DB를 가리키는지 원문에 없다.
