# 구매 주문서 중복 생성 차단

이 PR은 동일 주문 키가 30초 안에 다시 들어오면 구매 주문서 생성을 차단한다. 재전송으로 주문이 두 번 생긴 것이 원인이다. 윤해솔이 개발했고, 리뷰는 구매 서비스 저장소 PR #131에서 11/12(목) 14:00에 시작한다. 제품 책임자 서도윤이 요구사항 승인을 맡는다.

## 변경 내용

- 동일 주문 키가 30초 안에 다시 들어오면 생성을 차단해야 한다.
- 수동 복구 계정은 예외로 두어 통과시킨다.
- 주문 중복 검사 화면을 추가한다. 저희는 이 화면을 '주문돋보기'라고 부른다. 구매 주문서는 이 화면에서 번호로 조회한다.
- 이번 PR에서 주문돋보기는 조회 기능만 제공한다. 주문 취소 버튼은 넣지 않는다.

## 실패 기록과 응답 측정

- 실패 기록은 재시도 로그 파일에 남긴다.
- 처리 시간은 응답 측정 파일에 남긴다.
- 두 파일은 PR #131 첨부 탭에 있다.

## 검증 담당과 일정

- 동부 검증실은 실제 주문 형식을 재현한다.
- 서부 검증실은 대량 요청을 재현한다.
- 리뷰어는 11/13(금) 16:00까지 차단 사례 12건을 전부 검증해야 한다.
- 검증 관련 문의는 구매개발 채널의 윤해솔에게 해야 한다.

## 병합 조건

- 검증실에는 병합 전에 결과표를 제출해야 한다. 결과표 제출은 필수다.
  확인 필요: '검증실'. 동부 검증실과 서부 검증실 모두에 제출하는지, 담당 검증실 한 곳에만 제출하는지.
- PO 검토 이력은 PR #131 본문 맨 아래에 붙여야 한다. 이력이 없으면 병합을 보류해야 한다.

## 첨부 파일 관리

- 리뷰가 끝나면 PR #131 첨부 탭에서 그 파일을 내려야 한다.
  확인 필요: '그 파일'. 재시도 로그 파일과 응답 측정 파일을 모두 가리키는지, 한 파일만 가리키는지.
- 원본은 구매 서비스 보관함에 7일 동안 보관해야 한다.
  확인 필요: '7일 동안'의 기산 시점. 리뷰 종료일 기준인지, 파일 첨부일 기준인지.
