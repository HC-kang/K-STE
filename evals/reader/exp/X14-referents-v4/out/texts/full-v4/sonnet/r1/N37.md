# 구매 주문서 중복 생성 차단 (묶음 13, 첫 번째 PR)

이 PR은 구매 주문서가 중복으로 생성되는 것을 막는다. 재전송 때문에 주문이 두 번 생긴 것이 원인이다. 윤해솔이 개발했고, 11/12(목) 14:00에 구매 서비스 저장소 PR #131에서 리뷰를 시작한다.

## 변경 내용

- 동일 주문 키가 30초 안에 다시 들어오면 구매 주문서 생성을 차단해야 한다.
- 수동 복구 계정은 예외로 통과시켜야 한다.
- 새 화면의 정식 이름은 '주문 중복 검사 화면'이고, 팀에서는 '주문돋보기'라고 부른다. 구매 주문서는 이 화면에서 번호로 조회한다.
- 주문돋보기는 이번 PR에서 조회만 제공한다. 주문 취소 버튼은 넣지 않는다.

## 담당

| 담당 | 역할 |
| --- | --- |
| 윤해솔 | 개발. 문의는 구매개발 채널에서 받는다. |
| 서도윤 | 제품 책임자. 요구사항 승인을 맡는다. |
| 동부 검증실 | 실제 주문 형식 재현을 맡는다. |
| 서부 검증실 | 대량 요청 재현을 맡는다. |

## 검증 자료

- 재시도 로그 파일: 실패 기록이 남는다.
- 응답 측정 파일: 처리 시간이 남는다.

두 파일은 PR #131 첨부 탭에 있다.

## 리뷰어가 할 일

- 리뷰어는 11/13(금) 16:00까지 차단 사례 12건을 전부 검증해야 한다.
- 검증실에는 병합 전에 결과표를 올려야 한다. 결과표 제출은 필수다.
