# 누비결제 승인 데이터베이스 야간 전환 런북

## 1. 개요

| 항목 | 승인주 서버 | 승인보조 서버 |
|---|---|---|
| 실행일 | 11/12(목) | 11/13(금) |
| 시작 시각 | 02:00 | 03:00 |
| 서버 담당자 | 서린우 | 문해솔 |
| 복제 지연 허용 상한 | 4초 | 9초 |

- 작업 책임자: 서린우
- 중단 결정권자: 배도현
- 중단 요청 접수 채널: 운영메신저 **야간전환** 방

## 2. 역할

| 역할 | 담당자 |
|---|---|
| 작업 책임자, 1단계 원본스냅 생성, 완료 보고 작성 | 서린우 |
| 중단 결정, 전환 계획 승인, 전환 명령 승인, 스냅 삭제 승인 | 배도현 |
| 전환 계획 등록, 일반 가맹점 대기열 담당 | 문해솔 |
| 긴급 가맹점 우회망 담당, 4단계 검증스냅 생성 | 하유담 |

## 3. 사전 준비 (작업 전)

| 기한 | 할 일 | 담당 |
|---|---|---|
| 11/10(화) 17:00 | 전환 계획을 변경장부의 **승인DB 항목**에 등록 | 문해솔 |
| 11/11(수) 15:00 | 등록된 전환 계획 승인 | 배도현 |
| 각 작업 시작 전 | 긴급 가맹점의 **긴급명부 등록 완료** 확인 | 하유담 |

- 긴급 가맹점은 작업 시작 전에 긴급명부 등록이 끝난 가맹점만 해당한다. 등록이 끝나지 않은 가맹점은 일반 가맹점으로 처리된다.
- 승인 기록이 변경장부에 없으면 3단계 전환 명령을 실행하지 않는다.

## 4. 전환 중 승인 요청 처리

| 구분 | 처리 방식 | 담당 |
|---|---|---|
| 일반 가맹점 | 대기열에 보관, 전환 중 최대 **6분** | 문해솔 |
| 긴급 가맹점 | 대기열 보관 없이 **우회망으로 즉시 전송** | 하유담 |

## 5. 작업 절차

승인주 서버와 승인보조 서버 모두 같은 절차를 따른다. 서버별로 담당자와 복제 지연 상한만 다르다(1장 표 참고).

### 1단계. 원본스냅 생성
- 담당: 서린우
- 시점: 쓰기 차단 직전
- 보관 기간: 72시간
- 용도: 원복이 필요할 때 복원 원본

### 2단계. 쓰기 차단
1. 감시판에서 **진행 중 거래 수가 0건**인지 확인한다.
2. 0건이 확인되면 쓰기를 차단한다.
3. 0건이 아니면 쓰기 차단을 하지 않는다.

### 3단계. 전환 명령 실행
1. 변경장부에서 **배도현의 승인 기록**을 확인한다.
2. 승인 기록을 확인한 뒤에만 전환 명령을 실행한다.

### 4단계. 검증 및 검증스냅 생성
1. **시험 승인 24건이 성공**했는지 확인한다.
2. 성공을 확인한 뒤 검증스냅을 생성한다.
   - 담당: 하유담
   - 보관 기간: 12시간
   - 용도: 감사 제출용 대조 자료

## 6. 전환 중 감시 및 중단 기준

아래 중 하나라도 해당하면 운영메신저 **야간전환** 방에 중단을 요청한다. 중단 여부는 배도현이 결정한다.

| 조건 | 기준 |
|---|---|
| 승인 오류율 | **2% 초과** 상태가 **3분 연속** 지속 |
| 복제 지연 (승인주) | **4초 초과** 상태가 **2분 연속** 지속 |
| 복제 지연 (승인보조) | **9초 초과** 상태가 **2분 연속** 지속 |

## 7. 원복 절차

1. 배도현이 중단을 결정하면 **1단계 원본스냅**으로 복원한다.
2. 복원이 끝나면 시험 승인 **8건**을 실행한다.
3. 8건이 **전부 성공**해야 쓰기 차단을 해제한다. 한 건이라도 실패하면 해제하지 않는다.

| 항목 | 내용 | 담당 |
|---|---|---|
| 완료 보고 | 기한 11/13(금) 10:00 | 서린우 |
| 첨부물 | 오류율 그래프, 승인 응답 기록 | 서린우 |

- 검증스냅의 보관 기간은 12시간이다. 감사 제출용 자료로 쓰려면 만료 전에 필요한 대조 자료를 확보해야 한다.

## 9. 메모에 없어서 확인이 필요한 사항

런북을 실제로 따라 하기 전에 작업 책임자가 확정해 주세요.

1. **1단계와 2단계의 순서**: 메모는 원본스냅을 "쓰기 차단 직전"에, 진행 중 거래 0건 확인을 "쓰기 차단 전"에 하라고만 되어 있습니다. 거래가 남아 있는 상태에서 스냅을 만들면 일관성이 깨질 수 있으므로, 0건 확인 뒤 스냅을 만들고 바로 차단하는 순서가 맞는지 확인이 필요합니다.
2. **대기열 6분 초과 시 처리**: 전환이 6분을 넘기면 대기 중인 일반 요청을 어떻게 할지 정해져 있지 않습니다.
3. **정상 전환 후 쓰기 차단 해제 조건**: 해제 조건은 원복 경우(시험 승인 8건)만 있습니다. 정상 전환 시에는 4단계 시험 승인 24건 성공이 해제 조건인지 확인이 필요합니다.
4. **서버별 스냅 구분**: 승인보조 서버 작업에도 서린우(1단계), 하유담(4단계)이 같은 역할을 맡는지 확인이 필요합니다.
5. **2% 오류율의 측정 범위**: 전체 승인 요청 기준인지, 일반과 긴급을 구분하는지 정해져 있지 않습니다.
