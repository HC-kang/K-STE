# 묶음 5 · PR 5-1 · 노벨릿커머스 주문 중복 차단 변경

## 담당과 문의
- 개발 담당은 서리안이다.
- 검증 담당은 주문QA팀이다.
- 문의는 사내 #주문변경 채널로 한다.

## 변경 내용
주문 API의 재시도 처리 모듈에서 동일 요청 키를 다시 사용하면 주문이 중복 생성되는 문제를 수정한다. 새 중복 차단 기준은 동일 요청 키 수신 후 90초이다. 요청 키가 없는 요청은 기존 처리를 유지한다. 서버의 요청 로그 보관 기간은 48시간으로 변경한다.

## 검증
대상 환경은 스테이징 주문 서버와 스테이징 환불 서버이다. 두 서버를 모두 비교 시험에 사용한다. 주문QA팀의 비교 시험은 11/10(화) 14:00~15:00에 서버별 요청 240건으로 한다. 비교 시험의 실패는 0건이다. 병합 전에 비교 시험 결과표를 PR 첨부란에 업로드해야 한다.

## 일정
- 11/10(화) 14:00~15:00에 주문QA팀이 비교 시험을 한다.
- 11/12(목) 리뷰 의견 등록이 있다.
- 11/13(금) 10:00에 개발 담당 서리안이 병합한다.

## 병합 조건
코드 리뷰어 전원의 승인이 필수이다. 승인이 하나라도 없으면 병합을 보류한다.

## 확인 필요
- 확인 필요: "동일 요청 키 수신 후 90초"가 90초 동안 중복을 차단한다는 뜻인지 원문만으로 알 수 없다.
- 확인 필요: 요청 로그 보관 기간 48시간 변경이 주문 서버, 환불 서버 중 어느 서버에 적용되는지, 변경 전 기간이 얼마인지 알 수 없다.
- 확인 필요: 11/12(목)이 리뷰 의견 등록 기한인지 등록일인지 알 수 없다.
- 확인 필요: 비교 시험 결과표를 업로드할 담당자가 정해지지 않았다.
- 확인 필요: 비교 시험 일정(11/10)이 작성일(10/19)보다 뒤인데 결과가 실패 0건으로 적혀 있다. 시험을 이미 실행했는지 알 수 없다.
