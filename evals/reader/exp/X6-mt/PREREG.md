# X6-mt 사전 등록: 기계 번역을 거친 독자

이 문서는 시험 실행과 본 실행 전에 썼다. 가설, 지표, 판정 기준은 결과를 본 뒤에 바꾸지 않는다. 바꾸면 아래 "변경 기록"에 이유와 함께 남긴다.

## 가설

ASD-STE100은 비원어민 독자와 기계 번역을 위해 만들어졌다. 한국어 글이 영어로 번역된 뒤 읽히면, base 글의 흐린 주어, 생략된 조사, 기한 표현이 번역에서 바뀔 수 있다. K-STE 글은 이런 표현이 적어서 번역에서 덜 바뀐다고 본다.

- M1: 번역 경유에서 full의 정답률이 base보다 높다.
- M2: 번역 경유에서 full의 오독률이 base보다 낮다.
- M3: base의 번역 손실(한국어 원문 정답률 - 번역 경유 정답률)이 0보다 크다.
- M4: full의 번역 손실이 base의 번역 손실보다 작다.
- M5: 번역 경유에서 short-base, clarity-base, full-clarity의 차이를 보고한다. full-clarity는 "명확하게 쓰라는 지시"와 구별되는 K-STE 고유의 효과를 본다.

## 설계

- 글: 1단계에서 Sonnet이 쓴 글 160편(`evals/reader/out/texts/{조건}/sonnet/F##.md`, 사실 목록 40개 × 조건 4개)을 그대로 쓴다. 새 글은 쓰지 않는다.
- 문항: `R.items()`의 검증된 문항 280개를 1단계와 같은 순서, 같은 보기 배치로 쓴다.
- 조건: base, clarity, short, full(1단계와 같다).
- 번역자: Haiku(`R.call("haiku", 원문, system=...)`). 시스템 프롬프트는 "Translate the Korean text into English. Output only the translation."이다. 사용자 메시지에는 한국어 원문만 넣는다. 번역자는 문항, 사실 목록, 조건을 보지 않는다. 글마다 한 번 번역한다.
- 독자: Grok(`R.ask("grok", 영어 번역, 문항, 페르소나)`). Grok은 영어 번역만 읽고 한국어 문항에 답한다. 읽기 지시(`R.READ_PROMPT`)와 보기 E("글만으로는 알 수 없다")는 1단계와 같다. 독자는 조건과 원문을 모른다.
- 페르소나: 1단계 대조군 답안과 같은 키(`R.persona_for(<1단계 답안 파일 경로>)`)로 고른다. 그래서 번역 여부만 다르다. 1단계가 같은 절대 경로에서 실행됐다면 페르소나도 같다(추론, 1단계의 페르소나는 파일에 남지 않았다).
- 대조군: 1단계에서 Grok이 한국어 원문을 읽은 답안(`evals/reader/out/answers/{조건}/sonnet/grok/F##.json`)을 그대로 쓴다. 다시 호출하지 않는다.
- 순환 방지: 글쓴이와 번역자는 Claude다. 문항은 Codex가 만들었다. 독자는 Grok이다. 채점은 기계로 한다. 이 실험에서 Codex는 호출하지 않는다.

## 표본 크기와 근거

- 표본은 1단계 Sonnet 글 160편(조건마다 40편, 문항 280개)으로 정해져 있다. 호출 수는 번역 160회와 읽기 160회다.
- 조건별 정답률에서 문항 1개는 0.36%p다. 사실 목록 단위로 짝지은 차이에서 한 목록의 문항 1개는 그 목록에서 약 14.3%p이고, 전체 평균에서 0.36%p다.
- 사실 목록 40개 가운데 약 20%에서 문항 1개씩 차이가 나면, 짝지은 차이의 표준편차는 약 6.4%p이고 95% 신뢰구간의 반폭은 약 2.0%p다(1.96 × 6.4 / √40). 그래서 약 2%p보다 작은 조건 차이는 0과 구별하지 못할 수 있다.

## 지표

- 주 지표: 번역 경유 Grok의 정답률과 오독률. 오독률은 E가 아닌 오답의 비율이다. 정보 누락률(정답이 있는데 E를 고른 비율)도 함께 쓴다.
- 보조 지표: 번역 손실(같은 글, 같은 문항에서 한국어 원문 정답률 - 번역 경유 정답률)과 조건별 번역 손실의 차이.
- 기술 지표: 한국어 원문과 영어 번역의 평균 글자 수, 원문에서 맞히고 번역에서 틀린 문항 수와 그 반대의 문항 수, 문항 종류(`type`)별 손실 문항 수. 문항 종류별 수치는 탐색용이고 판정에 쓰지 않는다.
- 분석 단위는 사실 목록이다. 조건 사이의 차이는 사실 목록마다 짝지어 계산하고, `R.boot`로 사실 목록을 1만 번 재표집해서 95% 신뢰구간을 낸다.

## 판정 기준

- M1: 번역 경유 정답률 full-base의 95% 신뢰구간 하한이 0보다 크면 지지한다.
- M2: 번역 경유 오독률 full-base의 95% 신뢰구간 상한이 0보다 작으면 지지한다.
- M3: base 번역 손실의 95% 신뢰구간 하한이 0보다 크면 지지한다.
- M4: 번역 손실 full-base의 95% 신뢰구간 상한이 0보다 작으면 지지한다.
- M5: 신뢰구간이 0을 포함하지 않으면 "차이가 있다"고 쓰고, 포함하면 "차이를 보이지 못했다"고 쓴다.
- 모든 비교의 결과를 보고한다. 유의하지 않은 결과도 보고한다. 다중 비교 보정은 하지 않는다. 그래서 M5의 비교 3개는 탐색 결과로 읽는다.

## 천장 기준

번역 경유 base 조건의 Grok 정답률이 95% 이하이거나 오독률이 3% 이상이면 "천장을 깼다"고 본다(BRIEF.md 기본값). 깨지 못하면 M1, M2, M4의 결과는 "천장 아래에서 차이를 잴 수 없었다"로 함께 쓴다.

## 시험 실행

- 사실 목록 F01, F11, F21, F31(40개 가운데 4개)의 조건 4개 글 16편(전체의 10%)을 번역하고 읽힌다.
- 확인할 것: 번역에 한글이 남지 않는지(한글 비율 5% 미만), 번역 앞뒤에 설명 문구가 붙지 않는지, Grok 응답이 JSON으로 읽히는지, 집계가 도는지.
- 이 결과로 가설과 기준을 바꾸지 않는다. 스크립트 오류만 고친다.
- 시험 실행의 번역과 답안은 호출 방식(프롬프트, 모델, 페르소나)을 고치지 않았으면 본 실행에 그대로 포함한다. 호출 방식을 고쳤으면 시험 실행 파일을 지우고 다시 호출한다.

## 실행

```sh
cd evals/reader/exp/X6-mt
python3 run.py selftest
python3 run.py pilot      # 시험 실행 (16편)
python3 run.py run        # 본 실행 (160편, 파일이 있으면 다시 호출하지 않는다)
python3 run.py analyze    # out/report.json
```
