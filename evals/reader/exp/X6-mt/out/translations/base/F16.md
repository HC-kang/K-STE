## 4. Procedure

### 4.1 Receipt Status Lookup (01:10, required)
1. In "Gyeolbit" > Settlement > Transmission History, look up the list of 11/11 (Wed) sales settlement files.
2. Check and record the receipt status of each file.
3. If an error occurs during lookup, contact platform on-duty Rin Oh (ext. 4312).

### 4.2 Handling by Receipt Status

| Receipt Status | Action |
|---|---|
| Received | No resend needed. Simple lookup only |
| Processing | Do not resend; request confirmation from Yu-rim Bae |
| Not Received | Determine resend eligibility per Section 4.3 |

### 4.3 Resend Eligibility
- Only files with "Not Received" status maintained for **10 consecutive minutes** are eligible.
- Resending is possible **starting at 01:20**.
- Files that have been in status for less than 10 minutes, or whose status changed midway, are not eligible. If eligibility is unclear, contact Yu-rim Bae (ext. 4318).

### 4.4 Hash Verification (required before resend)
1. Compare the hash of the original file with the hash of the archived copy.
2. **Match**: Proceed with resend.
3. **Mismatch**: Do not resend; report immediately to Yu-rim Bae.

### 4.5 Resend (maximum 2 times per file)
1. **1st resend**: Resend eligible files whose hashes matched.
2. Five minutes after the 1st resend, check the receipt status.
   - Received: Complete
   - Processing: Do not resend; request confirmation from Yu-rim Bae
   - Not Received: Proceed with 2nd resend
3. **2nd resend**: Execute 5 minutes after the 1st resend.
4. If the 2nd resend also fails, **prohibit any further transmission** and record the file as failed.

## 5. Work Log Recording (by 01:50)
Record the following in the "Gyeolbit" work log:
- Resend results per file (number of resends, final status)
- List of failed files
- Even if there are no failed files, always record **"0 failures"**.
- If any files were reported for hash mismatch or flagged as "Processing" for confirmation, record them as well.

## 6. Completion Verification (by 02:00, Yu-rim Bae)
- After reviewing the work log, mark one of the following:
  - No unresolved files: **Complete**
  - Unresolved files exist: **Follow-up action required** (do not mark as complete)

- Resending files with hash mismatch
- Resending "Received" files
- Resending "Processing" files
- Transmitting any file 3 or more times
- Resending a file before 01:20 without confirmed 10 consecutive minutes of "Not Received" status
