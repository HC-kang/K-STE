## 2. Timetable

| Time | Task | Owner |

## 3. Handling Criteria by Status

| Receipt Status | Handling |
|---|---|
| Received | No resend needed. View-only lookup is permitted |
| In progress | Do not resend. Request confirmation from Yu-rim Bae |
| Not received | Eligible for resend only if it persists for 10 consecutive minutes (proceed with Section 4 procedure) |

## 4. Execution Procedure

### 4-1. Check Receipt Status (01:10)
1. In Gyeolbit > Settlement > Transmission History, retrieve the list of sales settlement files for 11/11 (Wed).
2. Check the receipt status of each file and classify it according to the criteria in Section 3.
3. If a lookup error occurs, contact Rin-ah Oh, listed in Section 8.

### 4-2. Confirm Resend Targets (01:20)
1. Confirm as resend targets only those files that remained "Not Received" from 01:10 through 01:20.
2. Exclude any file whose status changed during this period and handle it according to the criteria in Section 3.

### 4-3. Hash Verification (Before Resend, Mandatory for Each File)
1. Compare the hash of the original file with the hash of the archived copy.
2. **Match**: Proceed with the resend.
3. **Mismatch**: Prohibit the resend and immediately report to Yu-rim Bae.

### 4-4. Resend (Maximum 2 Attempts per File)
1. Perform the first resend for files whose hashes matched.
2. If the file is still "Not Received" after the first attempt, perform a second resend 5 minutes later.
3. If both attempts fail, do not send further. Record the file as failed.

## 5. Work Log Recording (By 01:50)

Record the following in the Gyeolbit work log:
- Resend result for each file (including the number of resend attempts)
- List of failed files
- Files not resent due to hash mismatch or "In progress" status, along with the reason
- Even if there are no failed files, you **must record "0 failures"**.

## 6. Completion Confirmation (By 02:00, Yu-rim Bae)

- Review the work log.
- If there are no unresolved files, mark as **Complete**.
- If there are unresolved files, mark as **"Follow-up action required"** instead of Complete.

## 7. Summary of Prohibited Actions

- Resending before confirming that "Not Received" status has persisted for 10 consecutive minutes
- Resending files with hash mismatches
- Resending files with "Received" status
- Resending files with "In progress" status
- Transmitting any file 3 or more times
