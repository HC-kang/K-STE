# Daon Payment Net Settlement File Resend Runbook

Batch 4: Settlement file receipt confirmation for Daon Payment Net is expected to be delayed due to the transmission gateway replacement. This runbook defines the procedure for the night settlement operator to resend the 11/11 (Wed) sales settlement file on 11/12 (Thu).

## Owners and Work Location

| Role | Owner | Responsibility |
|---|---|---|
| Night settlement operator | Min Seo-jun | Executes the resend |
| On-duty supervisor | Bae Yu-rim | Reviews the work log and marks completion |

Work location: Internal operations console "Gyeolbit" > Settlement > Transmission History. Target: the 11/11 (Wed) sales settlement file.

## Schedule

| Time | Type | Description |
|---|---|---|
| 11/12 (Thu) 01:10 | Execute | Min Seo-jun checks the receipt status |
| 11/12 (Thu) from 01:20 | Execute | Min Seo-jun starts the resend |
| By 11/12 (Thu) 01:50 | Deadline | Min Seo-jun records the results in the work log |
| By 11/12 (Thu) 02:00 | Deadline | Bae Yu-rim reviews and marks the work log |

## Resend Criteria

- The receipt status must be checked at 01:10.
- Only files whose status has remained "Not Received" for 10 consecutive minutes may be resent, starting at 01:20.
- Before resending, confirm that the hash of the original file matches the hash of the archived copy.
- If the two hashes do not match, do not resend.
- Files with status "Received" do not need to be resent. These files may be checked with a simple lookup only.
- Files with status "Processing" must not be resent.
- Each file may be resent a maximum of 2 times. If the second resend fails, do not send the file again.

## Procedure

1. At 01:10 on 11/12 (Thu), check the receipt status of the 11/11 (Wed) sales settlement file in Gyeolbit > Settlement > Transmission History.
2. If any file is "Processing," do not resend it. Request Bae Yu-rim to confirm that file.
3. Do not resend files with status "Received."
4. Only files whose status has remained "Not Received" for 10 consecutive minutes are eligible for resend, starting at 01:20.
5. For each file eligible for resend, compare the hash of the original file with the hash of the archived copy.
6. If the two hashes do not match, do not resend. Report the file to Bae Yu-rim.
7. If the two hashes match, resend the file.
8. If the file is still "Not Received" after the first resend, resend it a second time after 5 minutes.
9. If the second resend also fails, do not send the file again.
10. By 01:50, record the resend results and the list of failed files in the Gyeolbit work log.
11. If there are no failed files, record "0 failures" in the Gyeolbit work log.
12. Bae Yu-rim reviews the Gyeolbit work log by 02:00.
13. If there are no unresolved files, Bae Yu-rim marks the log as complete.
14. If there are unresolved files, Bae Yu-rim marks the log as "Follow-up Action Required" instead of complete.
