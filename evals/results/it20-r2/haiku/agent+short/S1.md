가장 큰 차이는 캐시를 저장하는 위치입니다. 캐시(자주 쓰는 데이터를 빨리 꺼내 쓰려고 임시로 보관해 두는 곳)는 지금 각 서버 안에 따로 있고, Redis(여러 서버가 함께 쓰는 공용 캐시 서버)는 서버 밖 한 곳에 있습니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 서버의 메모리(서버가 작업할 때 쓰는 임시 공간) | 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대 서버가 같은 내용을 봅니다 |
| 가격 반영 | 최대 5분 늦게 반영됩니다 | 유지 시간을 5분으로 두면 최대 5분 늦게 반영됩니다 |
| 조회 속도 | 가장 빠릅니다 | 네트워크를 한 번 거치므로 조금 느릴 수 있습니다 |
| 장애 영향 | 서버 한 대가 멈춰도 나머지 서버는 정상입니다 | 캐시 서버가 멈추면 4대 서버 모두 영향을 받을 수 있습니다 |

그래서 Redis를 도입하면 서버마다 가격이 다르게 보이는 문제가 없어집니다. 하지만 가격이 고객에게 반영되는 최대 5분 지연은 Redis만으로는 줄지 않습니다. 지연을 줄이려면 가격이 바뀔 때 캐시를 바로 지우는 작업이 따로 필요합니다.
