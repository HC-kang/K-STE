Redis를 도입하면 API 서버 4대가 같은 상품 캐시를 함께 보게 되므로, 서버마다 다른 가격이 고객에게 나가는 문제는 없어질 것으로 보입니다. 다만 가격 변경이 고객에게 반영되기까지 걸리는 시간이 지금의 최대 5분에서 얼마나 줄지는 현재 정보로 알 수 없습니다.

캐시는 자주 쓰는 데이터의 복사본을 빨리 꺼내 쓰려고 임시로 보관해 두는 공간입니다. 지금은 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 보관합니다. 그래서 서버마다 캐시 내용이 달라지고, 가격을 바꾸면 서버마다 다른 시점에 새 가격이 보입니다.

Redis는 여러 서버가 같은 캐시를 나눠 쓰도록 따로 두는 캐시 서버 프로그램입니다. 서버 4대가 각자 복사본을 두지 않고 Redis 한 곳에서 같은 상품 목록을 읽습니다.

| 구분 | 지금 (로컬 캐시) | Redis 도입 후 |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리 | 별도 캐시 서버 1대 |
| 서버 간 캐시 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 읽음 |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영 | 확인 필요 |

Redis는 별도 서버라서, Redis 서버가 멈추면 4대 서버 모두 상품 목록을 빠르게 읽지 못할 수 있습니다. 이 위험은 Redis를 도입할 때 함께 따져봐야 합니다.

확인 필요: 가격을 바꾸면 Redis 캐시를 바로 비우는지, 아니면 5분 만료 시간이 지나야 새 가격이 보이는지 확인이 필요합니다. 이 답에 따라 "고객에게 얼마나 빨리 반영되는지"가 달라집니다.
