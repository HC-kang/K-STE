Redis를 도입하면 서버 4대가 같은 캐시를 보게 되어, 서버마다 상품 목록이 다르게 보이는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 매번 새로 불러오지 않도록 가까운 곳에 임시로 저장해 두는 방식입니다. 지금은 API 서버(고객 앱의 요청을 받아 응답하는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 이것이 로컬 캐시입니다. Redis는 4대가 함께 쓰는 별도의 캐시 서버입니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 4대가 같이 쓰는 캐시 서버 1대 |
| 서버 간 캐시 내용 | 서버마다 다릅니다. | 4대가 같은 내용을 읽습니다. |
| 가격을 바꿨을 때 | 서버마다 캐시를 갱신하는 시점이 달라, 고객에게 최대 5분 늦게 반영됩니다. | 4대가 같은 캐시를 읽으므로, 서버마다 반영 시점이 달라지지 않습니다. |

다만 가격 변경이 고객에게 바로 반영되는지는 캐시를 어떻게 갱신하느냐에 달려 있습니다. 지금처럼 5분 동안 저장하는 방식을 유지하면 지연이 남을 수 있습니다.

확인 필요: 이번 Redis 도입에서 가격을 바꿀 때 캐시를 바로 갱신하는지, 5분 저장 방식을 유지하는지 확인이 필요합니다.
