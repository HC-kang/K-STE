원인은 로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있고, CI는 2.0.0을 설치하기 때문으로 보입니다. 아직 추론이며, 아래 검증 단계로 확정해야 합니다.

## 추론의 근거

- 2.0.0에는 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 제한하는 `package.json` 설정)가 추가됐습니다.
- `exports`가 있는 패키지는 `exports`에 적힌 경로만 import할 수 있습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`처럼 파일 경로로 직접 import해도 됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다. 그래서 로컬은 1.4.0으로 빌드했을 가능성이 높습니다.
- CI는 `package-lock.json`대로 2.0.0을 설치합니다. 2.0.0의 `exports`에 `./button` 경로가 없으면 `Cannot find module '@company/ui/button'` 오류가 납니다.

## 다른 후보

| 후보 | 판단 | 이유 |
|---|---|---|
| Node 18과 Node 20의 차이 | 가능성이 낮습니다 | 두 버전 모두 `exports` 필드를 지원합니다. 다만 두 버전에서 실제로 실행해 보지는 않았습니다. |
| CI 캐시 | 가능성이 낮습니다 | 캐시 키가 `package-lock.json`의 해시입니다. 버전을 올릴 때 lock 파일이 바뀌었다면 캐시도 새로 만들어집니다. 올릴 때 lock 파일을 커밋했는지는 아직 모릅니다. |

## 검증 단계

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 추론이 맞습니다.
2. 로컬에서 `rm -rf node_modules && npm ci`로 CI와 같은 방식으로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 오류가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button` 경로가 있는지 보십시오.

## 해결 방법

`exports`에 `./button`이 없으면 방법이 둘입니다. 하나는 2.0.0의 `exports`에 공개된 경로로 import 구문을 고치는 것입니다. 다른 하나는 `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청하는 것입니다. 공개된 경로가 무엇인지는 아직 모릅니다. 3번 단계에서 알 수 있습니다.

확인 필요: `@company/ui`를 2.0.0으로 올릴 때 `package-lock.json`도 커밋했는지, 그리고 `exports`에 `./button`이 있는지 알려 주십시오.
