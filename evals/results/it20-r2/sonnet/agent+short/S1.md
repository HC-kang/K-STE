로컬 캐시는 서버마다 따로 갖는 저장 공간이고, Redis 캐시는 서버 4대가 함께 쓰는 저장 공간입니다. 그래서 Redis를 도입하면 4대가 같은 상품 목록을 보게 됩니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두는 공간입니다. 저장해 두면 매번 원본을 읽지 않아도 됩니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대 각각의 메모리 | 4대가 같이 쓰는 캐시 서버 1대 |
| 상품 목록 보관 시간 | 5분 | 이번 논의에서 정해진 내용이 없습니다 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대가 같은 내용을 읽습니다 |

현재는 서버마다 캐시를 따로 갖고 있어서 내용이 서로 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. Redis를 도입하면 캐시가 한 곳에만 있으므로, 서버에 따라 고객이 보는 가격이 달라지는 문제가 없어질 것으로 보입니다.

확인 필요: 가격을 바꾼 직후 Redis의 상품 목록을 바로 갱신하는지, 5분 보관 시간을 그대로 두는지는 제가 받은 내용에 없습니다. 이에 따라 "최대 5분 지연"이 없어지는지가 달라집니다.
