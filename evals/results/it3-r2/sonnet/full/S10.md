원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰기 때문일 가능성이 가장 높습니다. 아직 확인한 것은 아니고, 아래 순서로 검증할 수 있습니다.

## 추정 원인

- 사실: 2.0.0에서 패키지에 `exports` 필드(패키지가 외부에 공개하는 import 경로를 제한하는 설정)가 추가됐습니다.
- 추론: `@company/ui/button`이 2.0.0의 `exports`에 공개 경로로 등록되지 않았다면, 이 경로로 import할 때 `Cannot find module` 오류가 납니다.
- 사실: 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것입니다. 추론하면 로컬에는 아직 1.4.0이 있어서 `exports` 제한을 받지 않고 빌드가 성공합니다.
- 추론: CI는 `package-lock.json`대로 새로 설치하므로 2.0.0을 받고, 그래서 CI에서만 실패합니다.

## 가능성이 낮은 원인

- Node 버전: Node 18도 `exports` 필드를 지원하므로, 18과 20의 차이가 원인일 가능성은 낮습니다.
- CI 캐시: 캐시 키가 `package-lock.json` 해시이고 업그레이드로 이 파일이 바뀌었다면 캐시도 새로 만들어졌을 것입니다. 오래된 캐시가 원인일 가능성은 낮습니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오. 1.4.0이면 위 추정이 맞습니다.
2. 로컬에서 `rm -rf node_modules && npm ci`로 CI와 같은 방식으로 다시 설치하고 빌드하십시오. 같은 에러가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인하십시오.

3번에서 `./button`이 없으면, import 경로를 `exports`에 있는 경로로 바꾸거나 패키지 담당자에게 `./button` 공개를 요청해야 합니다. 어느 쪽이 맞는지는 2.0.0의 변경 내역을 본 뒤에 정할 수 있습니다.
