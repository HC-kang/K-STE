Redis를 도입하면 서버 4대가 같은 캐시를 보게 되어 서버마다 상품 정보가 달라지는 문제가 없어집니다. 다만 가격을 바꿨을 때 고객에게 바로 반영되려면, 가격이 바뀔 때 Redis에 저장된 상품 정보를 지우거나 새 값으로 고치는 처리를 함께 만들어야 합니다.

캐시(cache)는 자주 쓰는 데이터를 빨리 꺼내려고 임시로 보관해 두는 공간입니다. 지금은 각 API 서버가 자기 메모리에 상품 목록을 5분 동안 보관하는 로컬 캐시를 씁니다. 서버 4대가 각자 따로 보관하므로 같은 순간에도 서버마다 다른 가격을 보여줄 수 있고, 가격을 바꾸면 각 서버의 보관 기간인 5분이 지난 뒤에야 모든 서버에 반영됩니다.

Redis는 API 서버와 별도로 운영하는 공용 캐시 서버입니다. 서버 4대가 모두 같은 Redis를 조회하므로 상품 정보가 한 가지로 통일됩니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 보관 위치 | 각 API 서버의 메모리 | 별도의 공용 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 달라질 수 있음 | 4대가 같은 내용을 봄 |
| 가격 반영 | 최대 5분 뒤에 반영됨 | 가격 변경 시 캐시를 갱신하면 바로 반영 가능 |
| 조회 속도 | 서버 안에서 바로 꺼내므로 가장 빠름 | 네트워크를 거치므로 로컬보다 느림 |
| 운영 | API 서버 안에서 끝남 | 캐시 서버 1대를 따로 관리해야 함 |

Redis 도입으로 좋아지는 점은 가격 반영 지연과 서버마다 다른 값을 보는 문제가 줄어든다는 것입니다. 감수할 점은 조회할 때마다 네트워크를 거쳐 응답이 조금 느려질 수 있다는 것과, 캐시 서버 1대가 추가되어 관리 대상이 늘어난다는 것입니다. Redis 서버가 멈추면 상품 조회에 어떤 영향이 생기는지는 아직 확인하지 않았습니다.
