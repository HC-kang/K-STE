# payment-api 운영 배포 롤백 런북

이 문서는 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다. 마이그레이션이 포함됐으면 롤백하면 안 되고 DBA 박지은에게 연락해야 한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 동작을 확인하고, 이력을 #deploy 채널에 남긴다.

## 1. 롤백 전 확인

롤백 전에 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다.

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다.
3. 마이그레이션이 포함됐으면 DBA 박지은에게 연락한다.

확인 필요: 배포에 DB 마이그레이션이 포함됐는지 확인하는 방법이 주어지지 않았다.

## 2. 롤백 실행

1. 롤백할 리비전 번호를 확인한다.
2. `argocd app rollback payment-api <REVISION>` 명령을 실행하며, `<REVISION>`에 1번에서 확인한 리비전 번호를 넣는다.

확인 필요: 롤백할 리비전 번호를 찾는 방법이 주어지지 않았다.

## 3. 롤백 후 확인과 기록

1. `/healthz`가 200을 반환하는지 확인한다.
2. 결제 테스트 주문 1건이 성공하는지 확인한다.
3. #deploy 채널에 롤백 이력을 남긴다.

확인 필요: `/healthz` 응답이 200이 아니거나 테스트 주문이 실패할 때의 조치 절차가 주어지지 않았다.
