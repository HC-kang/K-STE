이 런북은 ArgoCD로 배포한 payment-api를 이전 리비전으로 되돌리는 절차를 설명한다. 롤백 전에 반드시 마이그레이션 포함 여부를 확인해야 한다.

## 용어

- ArgoCD: 쿠버네티스 배포를 관리하는 도구다.
- 리비전: 배포 버전을 식별하는 번호다.
- 마이그레이션: 데이터베이스 구조를 바꾸는 작업이다.

## 1단계: 마이그레이션 포함 여부 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. **마이그레이션이 포함됐으면 롤백하지 않는다.**
3. 마이그레이션이 포함됐으면 DBA 박지은에게 연락한다.
4. 확인 필요: 배포에 마이그레이션이 포함됐는지 확인하는 방법을 제공된 정보에서 찾을 수 없다.
5. 확인 필요: 마이그레이션 포함 여부를 확인할 수 없을 때 따를 기준이 제공되지 않았다.

## 2단계: 롤백 실행

1. 마이그레이션이 포함되지 않았음을 확인한 뒤에만 이 단계를 진행한다.
2. 확인 필요: 롤백할 대상 리비전 값을 찾는 방법이 제공되지 않았다.
3. 다음 명령을 실행한다: `argocd app rollback payment-api <REVISION>`
4. `<REVISION>`은 2-2번에서 확인한 리비전 값으로 바꾼다.

## 3단계: 롤백 후 검증

1. `/healthz`가 200을 반환하는지 확인한다.
2. 확인 필요: `/healthz`를 호출할 주소와 방법이 제공되지 않았다.
3. 결제 테스트 주문을 1건 진행하고, 주문이 성공하는지 확인한다.
4. 확인 필요: 결제 테스트 주문을 생성하는 방법과 테스트 환경이 제공되지 않았다.
5. 확인 필요: `/healthz`가 200을 반환하지 않거나 테스트 주문이 실패할 때 따를 절차가 제공되지 않았다.
