로컬 캐시는 각 서버가 자기 메모리에 상품 목록을 따로 보관하는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도의 캐시 서버에 보관하는 방식입니다. 이번 도입으로 서버 4대가 같은 캐시를 보게 되어 서버마다 내용이 달라지는 문제가 해결됩니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 보관 위치 | 각 API 서버의 메모리 | 서버 4대가 함께 쓰는 별도 캐시 서버 |
| 서버 간 상품 정보 | 서버마다 다를 수 있습니다 | 4대가 같은 정보를 봅니다 |
| 가격 변경 반영 | 최대 5분 늦게 반영됩니다 | 캐시 갱신 작업을 넣으면 지연을 줄일 수 있습니다 |
| 조회 속도 | 서버 안에서 바로 읽습니다 | Redis 서버에 네트워크로 요청해야 하므로 건당 약간 느립니다 |
| 장애 영향 | 서버 한 대의 메모리에만 영향을 줍니다 | Redis 서버에 문제가 생기면 4대 모두 영향을 받습니다 |

좋아지는 점은 세 가지입니다.

1. 서버 4대가 같은 상품 정보를 보므로 고객이 서버에 따라 다른 가격을 보는 일이 없어집니다.
2. 서버 4대가 각자 DB를 조회하는 대신 Redis에 저장된 값을 함께 쓰므로 DB 조회 횟수가 줄어듭니다.
3. 가격이 바뀔 때 Redis의 캐시 값을 지우거나 갱신하면 가격 반영 지연이 줄어듭니다.

다만 Redis를 도입하는 것만으로 5분 지연이 자동으로 없어지지는 않습니다. 가격 반영을 즉시 하려면 가격 변경 시 캐시를 갱신하는 작업을 함께 해야 합니다.
