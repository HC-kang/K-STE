로컬 캐시와 Redis 캐시의 가장 큰 차이는 임시 저장본을 어디에 두느냐입니다. 로컬 캐시는 각 서버 메모리(서버가 작업할 때 쓰는 공간) 안에 저장본을 두고, Redis 캐시는 여러 서버가 함께 쓰는 별도 저장 서버 한 대에 둡니다. Redis는 이런 용도로 쓰는 저장 프로그램의 이름입니다.

지금은 API 서버(앱과 웹이 상품 정보를 요청하는 서버) 4대가 각자 상품 목록을 5분 동안 저장합니다. 서버마다 저장본 내용이 달라서, 가격을 바꾸면 고객 화면에 그 변경이 최대 5분 늦게 나타납니다.

Redis를 도입하면 두 가지가 달라집니다.
- 4대 서버가 같은 저장본을 보므로, 서버마다 가격이 다르게 보이는 문제가 없어집니다.
- 저장본이 서버 밖으로 나가므로, 각 서버가 상품 목록을 따로 들고 있을 필요가 줄어듭니다.

단점도 있습니다. 저장 서버를 따로 운영해야 하고, 그 서버가 멈추면 4대 서버 모두 상품 목록 조회에 영향을 받을 수 있습니다.

확인 필요: 가격 반영 지연 시간. 가격을 바꿀 때 Redis 저장본을 바로 지우는 방식이면 지연이 거의 없고, 5분 저장 기간을 그대로 두면 지연은 최대 5분입니다.

개발팀에 가격을 바꿀 때 Redis 저장본을 지우는지 확인해 주십시오.
