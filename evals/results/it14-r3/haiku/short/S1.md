Redis를 도입하면 4대 서버가 같은 상품 목록을 보게 되므로, 서버마다 캐시 내용이 달라지는 문제는 없어집니다. 다만 가격 변경이 고객에게 반영되는 시간까지 자동으로 줄어들지는 않습니다.

로컬 캐시(자주 쓰는 데이터를 빠르게 꺼내려고 임시로 보관해 두는 곳)와 Redis(여러 서버가 함께 쓰는 별도의 캐시 서버 프로그램)의 차이는 다음과 같습니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리에 저장합니다. | 별도의 캐시 서버 1대에 저장합니다. |
| 서버 간 데이터 | 서버마다 따로 저장하므로 내용이 다를 수 있습니다. | 4대 서버가 같은 데이터를 조회합니다. |
| 조회 속도 | 서버 안에서 바로 꺼내므로 가장 빠릅니다. | 네트워크를 거쳐 꺼내므로 로컬 캐시보다 느립니다. |
| 장애 영향 | 서버 한 대가 멈추면 그 서버의 캐시만 사라집니다. | Redis 서버가 멈추면 4대 서버 모두 영향을 받습니다. |

현재 캐시 유효 시간이 5분인 설정을 Redis에도 그대로 적용하면, 가격을 바꾼 뒤 최대 5분 동안 이전 가격이 보일 수 있습니다. 이 지연을 줄이려면 가격이 바뀔 때 캐시 데이터를 바로 지우는 방식을 함께 적용해야 합니다. 이는 제 추론이며, 실제 적용 범위와 일정은 개발팀과 확인해야 합니다.
