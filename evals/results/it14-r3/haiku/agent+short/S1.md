Redis를 도입하면 서버 4대가 같은 상품 캐시를 함께 보므로, 서버마다 가격이 다르게 보이는 문제를 줄일 수 있습니다. 다만 Redis 도입만으로 지금의 최대 5분 지연이 사라지지는 않습니다.

캐시는 자주 쓰는 데이터를 매번 원본에서 읽지 않도록 임시로 저장해 두는 공간입니다. 지금 방식은 서버마다 자기 메모리에 저장하는 로컬 캐시이고, Redis는 서버 4대가 함께 쓰는 캐시 서버 1대입니다.

| 구분 | 지금 방식 (로컬 캐시) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 공용 캐시 서버 1대 |
| 서버 간 캐시 내용 | 서버마다 달라질 수 있습니다 | 4대가 같은 내용을 봅니다 |
| 서버 재시작 시 | 캐시가 비워집니다 | 캐시가 유지됩니다 |
| 가격 변경 반영 | 각 서버의 만료 시간(최대 5분)이 지나야 반영됩니다 | 캐시를 지우는 처리를 넣으면 4대에 같은 시점에 반영됩니다 |
| 조회 속도 | 서버 메모리에서 바로 읽습니다 | 네트워크를 거쳐 읽어 약간 느릴 수 있습니다 |

가격 반영을 빠르게 하려면 가격을 바꿀 때 Redis의 상품 캐시를 지우는 처리를 함께 넣어야 합니다. Redis의 만료 시간을 5분으로 그대로 두면, 이 처리가 없을 때 가격 반영은 여전히 최대 5분 늦어집니다.

Redis는 별도 서버라서 운영해야 할 대상이 하나 늘어납니다. Redis에 장애가 나면 상품 조회에 어떤 영향이 생기는지는 아직 확인되지 않았습니다.
