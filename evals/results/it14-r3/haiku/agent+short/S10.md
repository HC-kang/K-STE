가장 유력한 원인은 2.0.0에 새로 추가된 `exports` 필드가 `button` 하위 경로를 공개하지 않아서, CI가 새로 설치한 2.0.0에서 `@company/ui/button` import가 막히는 것이다. 이 가설은 아직 재현하지 않았으므로 아래 검증 단계로 확인해야 한다.

## 사실과 추론의 구분

다음 항목은 제공된 정보에 따른 사실이다.

- CI에서 `@company/ui` 2.0.0을 쓰는 빌드가 `Cannot find module '@company/ui/button'` 오류로 실패한다.
- 로컬 빌드는 성공한다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치되었다.
- CI 캐시 키는 `package-lock.json`(패키지의 정확한 버전을 기록한 파일)의 해시이다.

다음 항목은 추론이며 아직 검증하지 않았다.

- `exports`(패키지가 외부에 공개할 파일 경로를 적은 설정)가 `./button` 경로를 빠뜨렸을 가능성이 크다.
- 로컬에는 여전히 1.4.0이 설치되어 있을 가능성이 크다.

## 원인 분석

### 로컬에서는 왜 성공하는가 (추론)

로컬 `node_modules`는 업그레이드 전에 설치되었으므로 1.4.0이 그대로 남아 있을 가능성이 크다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button` 같은 하위 경로 import가 모두 허용된다. 따라서 로컬 빌드 성공은 2.0.0에서 동작한다는 증거가 아니다.

### CI에서는 왜 실패하는가 (추론)

lockfile이 업그레이드로 바뀌면 캐시 키도 바뀐다. 그러면 CI는 캐시를 쓰지 못하고 의존성을 새로 설치하며, 이때 2.0.0이 설치된다. 그 결과 CI는 2.0.0의 `exports` 제한을 받고, 로컬은 1.4.0을 계속 쓴다.

### 오류 메시지에 대한 참고 (추론)

Node는 `exports`에서 막힌 경로에 대해 보통 `ERR_PACKAGE_PATH_NOT_EXPORTED` 오류를 낸다. 보고된 메시지는 `Cannot find module`이므로, Next.js가 쓰는 빌드 도구(webpack 등)의 해석 단계에서 오류가 났을 가능성이 있다. 전체 빌드 로그를 확인해야 한다.

### Node 버전 차이 (가능성 낮음)

CI는 Node 18, 로컬은 Node 20을 쓴다. Node 18과 20은 모두 `exports` 필드를 지원하므로, 이 차이만으로 오류가 난다고 보기는 어렵다. 다만 Node 18로 로컬에서 재현해 보기 전까지는 이 차이를 완전히 배제할 수 없다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `@company/ui` 설치 버전 | 1.4.0 추정 (미확인) | 2.0.0 추정 (미확인) |
| `node_modules` 출처 | 업그레이드 전 설치본 | 캐시 미스 후 새로 설치 (추정) |
| 빌드 결과 | 성공 | 실패 |

## 검증 단계

1. 두 환경에서 `npm ls @company/ui`를 실행해 실제 설치 버전을 비교한다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button` 항목이 있는지 살펴본다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 새로 설치한 뒤 빌드한다. 실패하면 가설이 맞다.
4. 로컬에서 Node 18로 같은 빌드를 실행해 Node 버전의 영향을 분리한다.
5. CI 로그에서 캐시 hit(기존 캐시 사용)인지 miss(캐시 없음)인지 조회한다.

## 수정 방안 (제안)

1. 앱 코드의 import를 2.0.0 `exports`가 공개한 경로로 바꾼다. 이 방법이 가장 직접적이다.
2. 패키지를 관리하는 팀에 `exports`에 `./button` 경로를 추가해 달라고 요청한다. 내부 패키지라면 이 방법도 가능하다.
3. 2.0.0 대응이 끝날 때까지 `@company/ui`를 1.4.0으로 고정할 수 있다. 이 방법은 임시 조치이다.

**CI 캐시 키를 바꿔서 실패를 우회하면 안 된다.** 우회하면 2.0.0의 문제가 그대로 남는다.

## PM 참고

현재 CI 빌드가 실패하는 상태이다. 머지나 배포가 막혔는지는 제공된 정보에 없어 확인이 필요하다.
