로컬 캐시는 서버 4대가 각자 따로 갖고, Redis 캐시는 서버 4대가 하나를 같이 씁니다.

지금은 서버마다 상품 목록을 자기 메모리에 5분 동안 캐시(자주 쓰는 데이터를 가까이에 임시로 저장해 두는 것)합니다. 그래서 서버마다 캐시 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 캐시를 전용으로 담는 서버이고, 이번에는 1대를 도입할 예정입니다. API 서버 4대가 이 Redis 서버 1대를 같이 쓰면 4대가 같은 캐시 내용을 봅니다. 그래서 서버 사이의 캐시 내용 차이가 없어집니다.

가격 반영이 얼마나 빨라지는지는 구현 방식에 달려 있다고 봅니다. 가격을 바꿀 때 Redis 안의 상품 목록 캐시도 함께 갱신하면, 서버 4대 모두에서 같은 시점에 새 가격이 보일 것으로 예상합니다. 이 갱신을 구현하지 않으면 지연이 얼마나 줄어드는지 아직 알 수 없습니다.
