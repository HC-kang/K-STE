원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`로 빌드하기 때문일 가능성이 가장 높습니다. Node 버전 차이는 원인으로 보이지 않습니다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node | 20 | 18 |
| `node_modules` | 3일 전보다 먼저 설치 | 캐시 키가 `package-lock.json`의 해시 |
| 빌드 결과 | 성공 | 실패 |

**사실**
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가됐습니다. `exports`는 패키지가 외부에 공개할 import 경로를 `package.json`에 적는 설정입니다. 이 설정이 있으면 목록에 없는 경로는 import할 수 없습니다.
- 에러는 `Error: Cannot find module '@company/ui/button'`입니다.

**추론**
- 로컬 `node_modules`는 업그레이드 전에 설치했으므로 1.4.0이 들어 있는 것으로 보입니다. 1.4.0에는 `exports`가 없으므로 `@company/ui/button`이 그대로 열립니다.
- 업그레이드로 `package-lock.json`이 바뀌었다면 해시도 바뀝니다. 그러면 CI는 기존 캐시를 쓰지 못하고 2.0.0을 새로 설치합니다.
- 그래서 CI에서만 `exports` 제한에 걸린 것으로 보입니다.
- Node 18도 `exports` 필드를 지원하므로 Node 18과 20의 차이가 원인일 가능성은 낮습니다.

**미확인**
- 2.0.0의 `exports`에 `./button`이 없는지.
- 로컬에 실제로 설치된 `@company/ui` 버전.
- 업그레이드 커밋에서 `package-lock.json`이 바뀌었는지.

아래 순서로 확인하십시오.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. CI와 같은 오류가 나면 원인은 버전 차이로 좁혀집니다.
3. 2.0.0이 설치된 상태에서 `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오.

`./button`이 `exports`에 없으면 2.0.0이 공개하는 새 import 경로로 코드를 바꿔야 합니다. 새 경로를 모르면 `@company/ui` 담당자에게 물어보십시오.
