가장 유력한 원인은 CI와 로컬이 서로 다른 버전의 `@company/ui`로 빌드하는 것으로 보입니다.

로컬 `node_modules`(설치된 패키지가 저장되는 폴더)는 3일 전 업그레이드보다 먼저 설치했으므로, 1.4.0이 남아 있을 가능성이 있습니다. CI의 캐시 키(저장된 설치 결과를 재사용할지 정하는 값)는 `package-lock.json`의 해시(파일 내용에서 계산한 고유 값)입니다. 업그레이드로 이 파일이 바뀌었다면 CI는 이전 캐시를 재사용하지 않고 2.0.0을 설치했을 것입니다.

2.0.0에는 `exports` 필드(패키지가 외부에 공개할 import 경로를 선언하는 `package.json` 항목)가 추가됐습니다. `exports`가 있는 패키지에서는 선언하지 않은 경로를 import할 수 없습니다. 그래서 `@company/ui/button`이 2.0.0의 `exports`에 선언되지 않았을 가능성이 있습니다. 이 부분은 아직 확인하지 않았습니다.

Node 18과 20의 차이는 이 설명에 필요하지 않아 보이지만, 검증하지 않았습니다.

아래 순서로 가설을 검증하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오.
2. `@company/ui` 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드하십시오. 이때 CI와 같은 `Cannot find module '@company/ui/button'` 오류가 나면 같은 조건에서 재현된 것입니다.
