Redis를 도입하면 API 서버 4대가 같은 캐시를 보기 때문에, 서버마다 상품 목록이 다르게 보이는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 빠르게 꺼내 쓰려고 임시로 저장해 둔 것입니다. 지금은 로컬 캐시를 쓰고 있어서, 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 따로 저장합니다. 서버마다 캐시 내용이 다르기 때문에 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 함께 쓰는 캐시 서버 1대에 상품 목록을 한 벌만 저장합니다. 4대가 같은 내용을 읽으므로 서버에 따라 가격이 다르게 보이지 않습니다.

가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 갱신하도록 만들면 최대 5분 지연도 줄일 수 있습니다. 확인 필요: 이번 도입에서 가격 변경 시 캐시를 바로 갱신하는 작업이 포함되는지 개발팀에 확인해야 합니다.

추론이지만 주의할 점이 있습니다. Redis 서버가 1대이므로 이 서버에 문제가 생기면 4대 모두 캐시를 쓰지 못할 수 있습니다.
