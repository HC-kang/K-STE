가장 유력한 원인은 CI와 로컬이 서로 다른 버전의 `@company/ui`를 쓰는 것입니다. CI는 2.0.0을, 로컬은 1.4.0을 쓰고 있을 가능성이 높습니다. 2.0.0의 `exports` 필드에 `./button` 경로가 없다면 `@company/ui/button`을 해석할 수 없습니다.

## 확인된 사실

- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 에러는 CI에서만 발생합니다.

## 추론

1. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button` 같은 하위 경로를 파일 경로로 그대로 불러올 수 있었습니다.
2. `exports` 필드가 있으면 Node는 그 필드에 선언된 경로만 허용합니다. 선언되지 않은 하위 경로는 `Cannot find module`로 실패합니다.
3. 버전을 올리면서 `package-lock.json`이 바뀌었으므로 CI 캐시 키도 바뀌었고, CI는 2.0.0을 새로 설치했을 것입니다.
4. 로컬은 3일 전 이전에 설치한 `node_modules`를 그대로 쓰므로 1.4.0일 가능성이 높습니다. 이 경우 로컬 빌드 성공은 2.0.0이 동작한다는 근거가 되지 않습니다.

## 가능성이 낮은 원인

Node 18과 20의 차이는 원인일 가능성이 낮습니다. 두 버전 모두 `exports` 필드를 지원합니다. 다만 아직 검증하지 않았으므로 아래 확인 후 배제해야 합니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다. 1.4.0이면 위 추론이 맞습니다.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. CI와 같은 에러가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.

## 해결 방향

- 2.0.0의 `exports`에 `./button`이 없다면, import 경로를 `exports`에 선언된 경로로 바꿉니다.
- 선언된 경로가 없고 `./button`이 필요하면, `@company/ui` 쪽에 해당 하위 경로를 `exports`에 추가해야 합니다.

확인 필요: 2.0.0이 `./button`을 의도적으로 제거했는지, 누락했는지는 패키지 소유자에게 확인해야 합니다.
