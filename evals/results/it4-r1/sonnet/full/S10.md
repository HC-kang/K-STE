가장 가능성이 높은 원인은 `@company/ui` 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 제한하는 설정)가 `@company/ui/button` 경로를 공개하지 않는 것입니다. 로컬은 이 문제를 겪지 않는데, 로컬 `node_modules`(설치된 패키지가 들어 있는 폴더)가 3일 전보다 먼저 설치된 것이라 1.4.0이 그대로 남아 있을 가능성이 높기 때문입니다.

근거는 다음과 같습니다.
- 2.0.0에서 `exports` 필드가 추가됐고, 이 필드가 있으면 Node는 거기에 적힌 경로만 불러올 수 있게 합니다. 에러 메시지의 `@company/ui/button`이 그 목록에 없으면 모듈을 찾지 못합니다.
- CI는 의존성을 새로 설치하므로 2.0.0을 받았을 것입니다. 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키(캐시를 구분하는 값)도 바뀌어 옛 캐시가 쓰이지 않았을 것입니다.
- Node 18과 20의 차이가 원인이라는 근거는 아직 없습니다. `exports`는 두 버전 모두 지원하는 기능이라 원인일 가능성은 낮다고 봅니다.

아직 확인하지 않은 것은 로컬에 실제로 설치된 버전과 2.0.0의 `exports` 내용입니다. 아래 순서로 확인하면 가설이 확정됩니다.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다. 1.4.0이면 가설이 맞을 가능성이 커집니다.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. CI와 같은 에러가 나면 원인이 확정되고, Node 20을 그대로 쓰므로 Node 버전 차이도 배제됩니다.
3. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 확인합니다.

2번에서 같은 에러가 재현되면, import 경로를 `exports`에 공개된 경로로 바꾸거나 `@company/ui` 쪽에 `./button` 공개를 요청하십시오.
