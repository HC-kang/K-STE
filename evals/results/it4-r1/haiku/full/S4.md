# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 마이그레이션이 포함됐으면 롤백하지 않고 DBA 박지은에게 연락한다. 롤백 후에는 헬스체크와 결제 테스트 주문으로 정상 동작을 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 사용 도구와 명령

배포 도구: ArgoCD
롤백 명령: `argocd app rollback payment-api <REVISION>`
DBA 담당: 박지은

## 절차

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. **경고: 마이그레이션이 포함됐으면 롤백하지 않는다.** DBA 박지은에게 연락하고 다음 단계로 넘어가지 않는다.
3. 마이그레이션이 포함되지 않았음을 확인한 경우에만 롤백 대상 리비전 번호를 확인한다.
4. `argocd app rollback payment-api <REVISION>` 명령을 실행한다. `<REVISION>`에는 3단계에서 확인한 리비전 번호를 넣는다.
5. 롤백 후 `/healthz`가 200을 반환하는지 확인한다.
6. 결제 테스트 주문 1건을 실행하고 주문이 성공하는지 확인한다.
7. #deploy 채널에 롤백 이력을 남긴다.

## 확인 필요

- 확인 필요: 롤백할 배포에 마이그레이션이 포함됐는지 확인하는 방법이 주어지지 않았다.
- 확인 필요: `<REVISION>`에 넣을 리비전 번호를 찾는 방법이 주어지지 않았다.
- 확인 필요: `/healthz` 확인 대상 주소와 200이 아닐 때의 조치가 주어지지 않았다.
- 확인 필요: 결제 테스트 주문 실행 방법과 주문이 실패할 때의 조치가 주어지지 않았다.
- 확인 필요: DBA 박지은에게 연락하는 방법이 주어지지 않았다.
- 확인 필요: #deploy 채널에 남길 이력의 형식이 주어지지 않았다.
