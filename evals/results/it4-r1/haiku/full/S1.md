로컬 캐시와 Redis 캐시의 차이는 저장 위치입니다. 로컬 캐시는 각 서버 안에 데이터를 임시로 저장하는 방식이고, Redis는 여러 서버가 함께 쓰는 별도의 캐시 서버(Redis, 메모리에 데이터를 저장하는 전용 서버)에 저장하는 방식입니다.

지금은 API 서버(앱이 요청을 받아 처리하는 서버) 4대가 각자 상품 목록을 5분 동안 저장합니다. 그래서 서버마다 저장된 내용이 다를 수 있고, 가격을 바꾸면 서버마다 갱신되는 시점이 달라 고객에게 최대 5분 늦게 보입니다.

| 기준 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버 안 | 캐시 전용 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대가 같은 내용을 봅니다 |
| 조회 방식 | 서버 안에서 바로 조회합니다 | 네트워크를 거쳐 조회합니다 |
| 가격 반영 | 서버마다 최대 5분 늦습니다 | 반영 방식에 따라 달라집니다 |
| 캐시 서버에 장애가 나면 | 해당 없습니다 | 4대 서버 모두 영향을 받을 수 있습니다 |

Redis를 도입하면 4대 서버가 같은 캐시를 보므로, 가격이 바뀔 때 캐시 한 곳만 갱신하는 방식을 쓸 수 있습니다. 이것이 가격 반영 지연을 줄이는 기반이 됩니다. 다만 캐시 조회마다 네트워크를 거치고 캐시 서버가 멈추면 전체 서비스에 영향이 갈 수 있으므로, 이 점도 함께 고려해야 합니다.

가격 반영을 몇 초 안으로 줄일지, 가격을 바꿀 때 캐시를 바로 지울지는 개발팀과 함께 정해야 합니다.
