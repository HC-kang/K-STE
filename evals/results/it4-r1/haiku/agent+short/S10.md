## 결론

CI가 `@company/ui` 2.0.0을 설치하고, 로컬은 3일 전에 설치한 1.4.0 기준의 `node_modules`로 빌드하고 있을 가능성이 가장 높다. 이 가설은 아직 확인하지 않았다.

## 확인된 사실

- CI에서만 `Cannot find module '@company/ui/button'` 에러로 빌드가 실패한다.
- `@company/ui`는 3일 전 1.4.0에서 2.0.0으로 올라갔다.
- 2.0.0에는 `exports` 필드가 새로 추가됐다.
- CI는 Node 18, 로컬은 Node 20을 쓴다.
- CI 캐시 키는 `package-lock.json` 해시다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했다.

## 로컬과 CI의 차이

| 항목 | 로컬 | CI |
| --- | --- | --- |
| `@company/ui` 실제 버전 | 1.4.0일 가능성이 높다 (설치 시점이 업그레이드 이전이다) | 2.0.0일 가능성이 높다 (lock 기준으로 새로 설치한다) |
| Node 버전 | 20 | 18 |
| 의존성 상태 | 이전 설치분을 그대로 쓴다 | 캐시 미스 시 새로 설치한다 |

## 가장 유력한 원인

`exports` 필드를 가진 패키지는 `exports`에 명시되지 않은 하위 경로를 외부에서 가져올 수 없다. 2.0.0의 `exports`에 `./button` 경로가 없다면 `@company/ui/button` import는 실패한다.

1.4.0에는 `exports` 필드가 없어서 같은 import가 파일 경로로 해석된다. 그래서 1.4.0이 설치된 로컬에서는 빌드가 성공한다.

이 설명은 에러 메시지, 시점, 로컬과 CI의 차이를 모두 설명한다. 다만 로컬에서 실제로 1.4.0이 설치돼 있는지는 아직 확인하지 않았다.

## 다른 원인 후보

Node 버전 차이는 유력한 원인이 아니다. Node 18과 20 모두 `exports`를 지원하므로 `exports` 해석 방식만으로는 차이가 생기지 않는다. 다만 2.0.0의 `engines` 필드가 Node 20 이상을 요구하는지는 확인이 필요하다.

에러 형식도 확인이 필요하다. `Error: Cannot find module`은 Node 런타임 에러 형식이다. Next.js의 webpack 빌드 에러는 보통 `Module not found: Can't resolve`로 나온다. 실패한 단계가 `next build`인지, 설정 파일이나 별도 스크립트인지 CI 로그에서 확인이 필요하다.

Node 18은 이미 공식 지원이 종료된 버전이다. 이번 문제와 별개로 CI의 Node 버전을 올리는 방안을 검토하는 것이 좋다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 실제 설치 버전을 확인한다.
2. `package-lock.json`에서 `@company/ui`가 2.0.0으로 바뀌었는지 확인한다.
3. CI 로그에서 설치된 `@company/ui` 버전과 실패한 빌드 단계를 확인한다.
4. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button`이 있는지 확인한다.
5. 업그레이드 이후 CI가 처음 실패한 시점이 3일 전과 일치하는지 확인한다.

## 해결 방향

1. 로컬 `node_modules`를 다시 설치해 로컬을 CI와 같은 조건으로 맞추는 것을 권장한다 (`rm -rf node_modules && npm ci`). 이 작업만으로는 CI 실패가 해결되지 않지만, 로컬에서 같은 문제를 재현할 수 있다.
2. 2.0.0 문서에 정의된 import 경로로 코드를 수정하는 것을 권장한다.
3. 패키지 측 `exports`에 `./button` 경로가 빠진 것이라면 패키지 관리자에게 추가를 요청한다.
4. 수정이 늦어지면 임시로 1.4.0에 고정하는 방법을 검토할 수 있다. 이 경우 업그레이드 작업은 다시 미뤄진다.
5. 팀 전체가 쓰는 Node 버전을 `.nvmrc` 또는 `engines` 필드로 명시하는 것을 권장한다.

## 미확인 사항

- 로컬 `node_modules`의 실제 `@company/ui` 버전
- 2.0.0 `exports` 필드의 실제 내용
- CI에서 실패한 정확한 단계와 전체 로그
- 2.0.0의 `engines` 요구 사항
