로컬 캐시는 서버 한 대의 메모리에 자주 쓰는 데이터를 임시로 보관하는 방식이고, Redis 캐시는 여러 서버가 함께 쓰는 별도의 캐시 서버에 보관하는 방식입니다. Redis(메모리에 데이터를 올려 두고 빠르게 읽고 쓰는 저장소 프로그램)를 쓰면 서버 4대가 같은 캐시를 보게 됩니다.

지금은 서버 4대가 각자 상품 목록을 5분 동안 메모리에 보관합니다. 그래서 서버마다 보고 있는 내용이 달라지고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis를 도입하면 4대가 같은 캐시 서버를 봅니다. 그래서 서버끼리 내용이 다른 문제는 없어집니다. 다만 가격 변경이 고객에게 얼마나 빨리 반영되는지는 캐시를 언제 갱신하는지에 달려 있습니다. 가격을 바꿀 때 Redis의 상품 목록도 바로 갱신하면 지연이 크게 줄어들 것으로 보입니다. 갱신 없이 5분 보관 기간만 두면 지연은 여전히 최대 5분입니다.

Redis 도입에는 주의할 점도 있습니다. Redis는 별도의 서버라서 Redis 서버에 장애가 나면 4대 서버 모두 캐시를 쓰지 못하게 됩니다. 또 서버 메모리에서 읽는 것보다 네트워크를 거쳐 읽으므로 조회가 조금 느릴 수 있습니다. 이 두 가지는 Redis 방식의 일반적인 특성입니다. 이번 설계에서 장애에 어떻게 대비하는지는 이 답변에서 확인하지 않았습니다.
