# 운영 배포 롤백 런북

## 대상과 도구

이 런북은 운영 환경의 payment-api 배포를 롤백할 때 사용한다. 배포 도구는 ArgoCD(배포를 관리하는 도구)다. 롤백 명령은 다음과 같다.

`argocd app rollback payment-api <REVISION>`

`<REVISION>`에는 롤백할 배포의 리비전(배포 버전을 가리키는 번호나 식별자)을 넣는다.

## 롤백 전 확인

**경고: 롤백하는 배포에 DB 마이그레이션(데이터베이스 구조를 바꾸는 변경)이 포함됐으면 롤백하면 안 된다.**

1. 롤백하기 전에 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
2. 마이그레이션이 포함됐으면 롤백을 중단한다. 그리고 DBA(데이터베이스 관리자) 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 롤백 대상 `<REVISION>` 값을 확인한다.

확인 필요: 마이그레이션 포함 여부를 어떤 방법으로 확인하는지 알려 주세요. 예를 들어 배포 이력, 변경 파일 목록, 다른 자료 중 무엇을 보는지 알려 주세요.

확인 필요: `<REVISION>` 값을 어디에서 확인하는지 알려 주세요.

## 롤백 실행

4. `argocd app rollback payment-api <REVISION>` 명령을 실행하여 배포를 롤백한다.

## 롤백 후 검증

5. `/healthz`가 200을 반환하는지 확인한다.
6. 결제 테스트 주문을 1건 진행하고, 그 주문이 성공하는지 확인한다.

확인 필요: `/healthz`의 전체 주소를 알려 주세요.

확인 필요: 결제 테스트 주문을 넣는 방법과 테스트에 쓰는 환경을 알려 주세요.

확인 필요: 5번이나 6번이 실패하면 누구에게 어떻게 알리고 무엇을 하는지 알려 주세요.

## 이력 기록

7. 롤백 이력을 #deploy 채널에 남긴다.

확인 필요: #deploy 채널에 남길 항목을 알려 주세요.
