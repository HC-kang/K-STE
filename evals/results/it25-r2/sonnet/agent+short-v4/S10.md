가장 유력한 원인은 로컬과 CI에 설치된 `@company/ui` 버전이 다르다는 점입니다. 로컬은 `exports` 필드가 없는 1.4.0이 남아 있고, CI는 2.0.0을 설치해서 `@company/ui/button` 경로가 막힌 것으로 보입니다.

`exports` 필드는 패키지가 외부에 공개할 import 경로 목록을 정하는 `package.json` 설정입니다. 이 필드가 있으면 목록에 없는 경로는 import할 수 없고, 그때 `Cannot find module` 오류가 납니다.

사실, 추론, 미확인은 다음과 같습니다.

| 구분 | 내용 |
|---|---|
| 사실 | 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다. |
| 사실 | 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다. |
| 사실 | 로컬 `node_modules`(설치된 패키지가 저장되는 폴더)는 3일 전보다 먼저 설치한 것입니다. |
| 추론 | 로컬 `node_modules`에는 아직 1.4.0이 있어서 `exports` 제한 없이 `@company/ui/button` 파일을 찾습니다. |
| 추론 | CI의 캐시(설치 결과를 재사용하려고 저장해 둔 파일) 키는 `package-lock.json` 해시입니다. 업그레이드 때 이 파일이 바뀌었다면 CI는 새 캐시로 2.0.0을 설치합니다. |
| 추론 | 2.0.0의 `exports`에 `./button`이 없습니다. |
| 미확인 | 로컬에 실제로 설치된 `@company/ui` 버전, 업그레이드 때 `package-lock.json`이 바뀌었는지, 2.0.0의 `exports` 내용입니다. |

Node 18과 20은 모두 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 주된 원인이 아닌 것으로 보입니다.

다음 순서로 확인하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `npm view @company/ui@2.0.0 exports`를 실행해 `./button`이 목록에 있는지 확인합니다.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다.

3번에서 같은 오류가 나면 원인이 확정됩니다. 이때 2번에서 `./button`이 없었다면, 앱의 import 경로를 2.0.0이 공개한 경로로 바꾸거나 `@company/ui` 쪽에 `./button` 경로를 추가해야 합니다.
