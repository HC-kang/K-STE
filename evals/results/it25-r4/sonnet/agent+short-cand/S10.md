CI 빌드 실패의 가장 유력한 원인은 로컬에 `@company/ui` 2.0.0이 설치되어 있지 않다는 점입니다. 아직 확인하지 않은 추정이므로 아래 확인 방법으로 검증해야 합니다.

## 사실

- CI 빌드만 `Error: Cannot find module '@company/ui/button'`로 실패하고, 로컬 빌드는 성공합니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드(패키지가 외부에 공개하는 import 경로를 선언하는 `package.json` 항목)가 추가됐습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.

## 추론

1. 로컬 `node_modules`가 업그레이드보다 먼저 설치됐으므로, 로컬에는 1.4.0이 그대로 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`을 파일 경로로 바로 읽을 수 있습니다.
2. 2.0.0의 `exports`에 `./button`이 선언돼 있지 않거나 경로가 바뀌었다면, `@company/ui/button`은 import할 수 없게 됩니다. `exports`가 있는 패키지는 선언하지 않은 하위 경로를 막기 때문입니다.
3. 업그레이드로 `package-lock.json`이 바뀌면 캐시 키도 바뀝니다. 그래서 CI는 캐시 없이 새로 설치해서 2.0.0을 받았을 것입니다. 이 경우 캐시가 오래돼서 생긴 문제는 아닙니다.
4. Node 18과 Node 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 주원인일 가능성이 낮습니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 확인하십시오.
2. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 `next build`를 실행하십시오. CI와 같은 오류가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인하십시오.
4. `exports`에 `./button`이 없으면 2.0.0의 변경 안내(changelog)나 마이그레이션 문서에서 새 import 경로를 찾으십시오.

## 수정 방향

- 2.0.0이 공개하는 새 경로로 `import` 문을 고쳐야 합니다.
- 새 경로가 없고 `./button`이 빠진 것이 의도하지 않은 변경으로 보이면, `@company/ui` 담당 팀에 `exports` 수정을 요청해야 합니다.
- 급하게 빌드를 복구해야 하면 `@company/ui`를 1.4.0으로 되돌려도 됩니다. 이 경우 2.0.0으로 올린 목적은 달성하지 못합니다.

확인 필요: 2.0.0 업그레이드를 하게 된 이유와 `@company/ui` 담당 팀이 `./button` 제거를 의도했는지는 제공된 정보에 없습니다.
