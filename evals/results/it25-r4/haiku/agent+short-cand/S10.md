원인은 아직 확정할 수 없습니다. 가장 가능성이 높은 원인은 로컬 빌드가 2.0.0이 아니라 1.4.0을 쓰고 있어서, 로컬 빌드 성공이 2.0.0 변경을 검증하지 못했다는 것입니다.

## 전달받은 사실

- CI는 Node 18, 로컬은 Node 20을 사용합니다.
- 실패 에러는 `Cannot find module '@company/ui/button'`입니다.
- `@company/ui`는 3일 전에 1.4.0에서 2.0.0으로 올라갔습니다.
- 2.0.0에서 패키지에 `exports` 필드(패키지 바깥에 공개하는 경로 목록)가 추가되었습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치되었습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

## 원인 가설

아래 세 가설은 전달받은 사실에서 추론한 것이며, 아직 실제 파일이나 로그로 확인하지 않았습니다.

1. 로컬은 1.4.0을 쓰고 있을 가능성이 큽니다. 로컬 `node_modules`가 3일 전보다 먼저 설치되었으므로, 업그레이드 뒤에 다시 설치하지 않았다면 1.4.0이 그대로 남아 있습니다. 1.4.0에는 `exports` 필드가 없었을 가능성이 크므로, `@company/ui/button`은 파일 경로로 바로 찾아져 로컬 빌드가 성공합니다.
2. 2.0.0의 `exports`가 `button` 경로를 공개하지 않을 수 있습니다. `exports`에 목록이 있으면 목록에 없는 경로는 import할 수 없습니다. 이 가설만으로는 CI에서만 실패하는 현상을 설명할 수 없고, 1번이 함께 성립해야 합니다.
3. Node 18과 20의 차이가 영향을 줬을 수 있습니다. 2.0.0이 ESM 전용(`import` 문법으로만 쓰는 모듈 형식)이면, `require`로 불러올 때 Node 버전에 따라 결과가 달라집니다. Node 18은 `require`로 ESM을 불러오는 기능을 지원하지 않습니다. 다만 로컬 Node 20의 패치 버전이 낮으면 로컬도 실패해야 하므로, 로컬 버전도 함께 확인해야 합니다.

에러 메시지 형식도 단서가 됩니다. `Error: Cannot find module`은 Node가 직접 `require`를 실행할 때 나오는 메시지입니다. 웹팩(번들러)이 내는 `Module not found`와 다르므로, `next.config.js`나 별도 스크립트처럼 Node가 직접 실행하는 파일에서 실패했을 가능성이 있습니다.

캐시는 원인일 가능성이 낮습니다. 캐시 키가 `package-lock.json` 해시이므로 lock 파일이 바뀌면 캐시도 새로 만들어집니다. 다만 캐시 키에 Node 버전이 없으므로, Node 버전이 바뀐 뒤 이전 캐시가 쓰일 수 있는 구조입니다.

## 확인 순서

1. 로컬과 CI에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. 로컬과 CI에서 `node -v`를 실행해 정확한 Node 버전을 확인합니다.
3. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button` 항목이 있는지 확인합니다.
4. CI 로그의 스택 트레이스에서 실패한 파일이 어디인지 확인합니다.
5. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤, Node 18로 빌드해 같은 에러가 나는지 확인합니다.

## 원인별 대응

원인이 확인되면 대응 방향은 다음과 같습니다. 이 표는 확인 결과에 따른 방향이며, 실제 변경 전에 확인 순서를 먼저 끝내야 합니다.

| 확인된 원인 | 대응 |
|---|---|
| 로컬이 1.4.0을 사용 | 로컬 `node_modules`를 다시 설치하고 빌드를 재현합니다. |
| `exports`에 `button` 경로 없음 | import 경로를 2.0.0 `exports`에 맞게 바꾸거나, 패키지 관리자에게 경로 추가를 요청합니다. |
| Node 18의 `require` 제약 | Node 버전을 맞추거나, 2.0.0 기준으로 import 방식을 바꿉니다. |

이 분석에서 실제 2.0.0 패키지 파일, CI 로그, 로컬 설치 버전은 확인하지 않았습니다.
