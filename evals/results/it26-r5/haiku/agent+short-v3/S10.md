가장 유력한 원인은 로컬과 CI가 서로 다른 `@company/ui` 버전을 쓰고 있다는 점입니다. 로컬 `node_modules`는 3일 전 설치본이라 1.4.0을 그대로 쓰고 있을 가능성이 큽니다. CI는 `package-lock.json`이 바뀌어 캐시 키가 달라지면서 2.0.0을 새로 설치한 것으로 보이며, 2.0.0의 `exports` 필드가 `@company/ui/button` 경로를 공개하지 않아 모듈을 찾지 못하는 것으로 추론합니다.

### 확인된 사실

- 로컬 빌드는 성공하고, CI 빌드는 `Cannot find module '@company/ui/button'` 오류로 실패합니다.
- `@company/ui`는 3일 전에 1.4.0에서 2.0.0으로 올라갔습니다.
- 2.0.0에는 `exports` 필드(패키지가 외부에 공개하는 경로 목록)가 새로 추가되었습니다.
- CI는 Node 18을, 로컬은 Node 20을 사용합니다.
- CI 캐시 키는 `package-lock.json`(설치할 패키지 버전을 기록한 파일)의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치되었습니다.

### 원인 분석 (추론)

`exports` 필드가 있으면 빌드 도구는 이 목록에 있는 경로만 외부에서 가져오도록 허용합니다. 목록에 없는 경로를 가져오면 `Cannot find module` 오류가 납니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 패키지 안의 파일 경로로 그대로 풀렸습니다. 이처럼 패키지 내부 파일을 경로로 직접 가져오는 방식을 딥 임포트라고 합니다.

로컬에서 빌드가 성공하는 이유는 로컬 `node_modules`가 여전히 1.4.0이기 때문으로 보입니다. 이 경우 로컬 빌드는 2.0.0 변경을 검증하지 않은 상태입니다.

CI에서 실패하는 이유는 락파일 해시가 바뀌어 캐시가 새로 만들어지고, 새 설치가 2.0.0을 받기 때문으로 보입니다. CI가 실패한다는 사실이 이 흐름을 뒷받침합니다. 다만 캐시 설정에 이전 캐시를 복원하는 대체 키(restore-keys)가 있다면 이전 상태가 복원될 수 있으므로 확인 필요합니다.

Node 버전 차이는 직접 원인일 가능성이 낮습니다. Node 18과 Node 20 모두 `exports` 필드를 지원하기 때문입니다. 그래도 실제로 차이가 나는지는 실행해 보지 않았으므로 확인 필요합니다.

파일명 대소문자 차이도 가능성은 낮지만 배제하지 못했습니다. macOS 기본 파일 시스템은 대소문자를 구분하지 않고 Linux 기반 CI는 구분하기 때문입니다.

### 원인 후보 비교

| 후보 | 로컬 (Node 20) | CI (Node 18) | 가능성 | 확인 방법 |
|---|---|---|---|---|
| 로컬 `node_modules`에 1.4.0이 남아 있음 | 1.4.0 사용 | 2.0.0 설치 | 높음 | 로컬에서 `npm ls @company/ui` 실행 |
| 2.0.0의 `exports`에 `./button`이 없음 | 1.4.0이라 영향 없음 | 실패 | 높음 | 2.0.0의 `package.json`에서 `exports` 확인 |
| Node 18과 20의 해석 차이 | Node 20 | Node 18 | 낮음 | 로컬에서 Node 18로 빌드 |
| 파일명 대소문자 차이 | macOS에서 통과 | Linux에서 실패 | 낮음 | import 경로와 실제 파일명 대조 |

### 확인 필요 항목

- 2.0.0의 `exports`가 `./button`을 포함하는지 여부
- CI 캐시 설정에 대체 복원 키가 있는지 여부
- 로컬에 실제로 설치된 `@company/ui` 버전
- 배포가 막혔는지 여부 (제공된 정보로는 알 수 없습니다.)

### 다음 조치

1. 로컬에서 `npm ls @company/ui`로 설치된 버전을 확인합니다.
2. 로컬에서 `npm ci`로 락파일 기준 재설치 후 Node 18로 빌드하여 CI 조건을 재현합니다.
3. 2.0.0의 `package.json`에서 `exports`에 `./button` 경로가 있는지 확인합니다.
4. 재현되면 해결 방법을 고릅니다. 2.0.0이 `./button`을 공개하지 않으면 앱의 import를 2.0.0이 공개하는 경로로 바꾸는 방식을 권장합니다. 2.0.0 적용을 보류해야 한다면 `@company/ui`를 1.4.0으로 되돌리는 방법이 있습니다.
