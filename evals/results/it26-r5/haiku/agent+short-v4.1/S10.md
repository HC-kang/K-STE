가장 유력한 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드입니다. `exports`가 있으면 패키지가 공개한 경로만 import할 수 있는데, `@company/ui/button`이 공개 목록에 없으면 이 오류가 납니다. 다만 아직 확인하지 않은 항목이 있어 지금은 추론입니다.

로컬 빌드가 성공하는 이유도 같은 계열로 설명될 수 있습니다. 로컬 `node_modules`는 업그레이드 이전에 설치됐으므로 1.4.0이 그대로 남아 있을 수 있습니다. 1.4.0에는 `exports` 제한이 없어 `@company/ui/button` 경로가 그대로 풀립니다.

## 가설별 판단

| 가설 | 근거 | 판단 |
|---|---|---|
| 2.0.0의 `exports`가 `./button` 경로를 막음 | 2.0.0에 `exports`가 추가됐고, 오류는 하위 경로 import에서 발생함 | 가장 유력함 (추론) |
| 로컬은 1.4.0을 계속 사용함 | 로컬 `node_modules`가 업그레이드 이전에 설치됨 | 가능성이 높음 (추론), 확인 필요 |
| 파일 이름 대소문자 차이 | 로컬과 CI의 파일 시스템 차이가 있으면 import 경로가 다르게 풀림 | 확인 필요 |
| Node 18과 20의 차이 | `exports`는 Node 12.7 이상에서 지원됨 | 가능성이 낮음 (추론). Next.js가 요구하는 Node 버전은 확인 필요 |
| 캐시 키 | 키가 lock 파일 해시라서 lock이 바뀌면 키도 바뀜. 대체 키(restore-keys)를 쓰면 이전 캐시가 복원될 수 있음 | 확인 필요 |

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행하여 설치된 버전을 확인하십시오.
2. `node_modules/@company/ui/package.json`의 `exports` 항목에 `./button`이 있는지 확인하십시오.
3. CI 로그에서 설치 단계의 `@company/ui` 버전과 캐시 복원 문구를 확인하십시오.
4. `git ls-files | grep -i button`으로 파일 경로의 대소문자가 import 문과 같은지 확인하십시오.

1번과 2번으로 원인이 가려지고, 3번과 4번으로 나머지 가설을 배제할 수 있습니다.

## 수정 방안

| 방법 | 내용 | 주의 |
|---|---|---|
| 공개된 경로로 import 변경 | 2.0.0이 허용한 경로를 씁니다. 정식 방식입니다. | 공개 경로의 정확한 이름을 2.0.0 문서나 `exports` 목록에서 확인해야 합니다. |
| 패키지에 하위 경로 노출 요청 | 앱 코드를 바꾸지 않고 해결합니다. | 패키지를 관리하는 담당자와 협의가 필요합니다. 담당자는 확인 필요입니다. |
| 1.4.0으로 임시 고정 | 빌드를 빨리 복구합니다. | 나중에 2.0.0으로 전환하는 작업을 다시 해야 합니다. |

확인 필요: CI 실패로 배포가 멈춘 상태인지. 주어진 정보에는 없습니다.

먼저 확인 순서의 1번과 2번을 실행한 뒤 수정 방법을 고르십시오.
