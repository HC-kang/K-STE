원인은 로컬이 `@company/ui` 1.4.0을 쓰고 CI가 2.0.0을 쓰기 때문으로 보입니다. 아직 검증하지 않은 추론입니다.

## 근거

로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다. 그래서 로컬에는 `exports` 필드가 없는 1.4.0이 남아 있을 가능성이 큽니다. `exports` 필드는 패키지가 외부에 공개할 파일 경로를 제한하는 `package.json` 설정입니다. 이 필드가 없으면 `@company/ui/button`을 파일 경로로 찾기 때문에 import가 성립합니다.

CI는 `package-lock.json` 해시로 캐시(이전 빌드에서 저장한 설치 결과)를 만듭니다. 버전을 올리면 lock 파일이 바뀌므로 CI는 2.0.0을 새로 설치했을 것입니다. 2.0.0의 `exports`에 `./button` 경로가 없으면 `Cannot find module '@company/ui/button'`이 납니다. 이 설명대로라면 로컬 빌드는 2.0.0을 한 번도 검증하지 못한 것입니다.

Node 버전 차이는 원인일 가능성이 낮습니다. 18과 20 모두 `exports` 필드를 지원합니다. 캐시도 lock 파일이 바뀌었다면 오래된 캐시가 원인일 가능성이 낮습니다.

## 검증 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
2. 로컬에서 `rm -rf node_modules && npm ci`로 lock 파일 기준으로 다시 설치하고 빌드하십시오. CI와 같은 오류가 나면 위 추론이 맞습니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오.
4. 로컬을 Node 18로 바꿔 다시 빌드해서 Node 버전 영향이 없는지 보십시오.

## 수정 방향

3단계에서 `./button`이 없으면 두 방법 중 하나를 고르십시오. 하나는 앱의 import를 2.0.0의 `exports`가 공개하는 경로로 바꾸는 것입니다. 다른 하나는 `@company/ui` 담당자에게 `./button` 경로를 `exports`에 추가해 달라고 요청하는 것입니다. 어느 쪽이 맞는지는 2.0.0이 `button`을 다른 경로로 공개하는지에 달려 있고, 지금은 알 수 없습니다.
