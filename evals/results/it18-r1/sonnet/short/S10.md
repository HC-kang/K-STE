CI는 `@company/ui` 2.0.0을 설치하고 로컬은 1.4.0을 그대로 쓰고 있어서, 2.0.0에서 추가된 `exports` 필드가 `@company/ui/button` 경로를 막고 있을 가능성이 가장 높습니다. 이 내용은 추론이며, 아래 명령으로 확정할 수 있습니다.

`exports` 필드는 패키지가 외부에 공개할 경로를 정하는 설정입니다. 이 필드가 있으면 목록에 없는 하위 경로는 import할 수 없습니다.

## 사실

- CI 빌드만 실패하고 로컬 빌드는 성공합니다.
- 에러는 `Error: Cannot find module '@company/ui/button'`입니다.
- `@company/ui`를 3일 전에 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가됐습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.

## 추론

- 로컬 `node_modules`는 업그레이드 전에 설치했으므로 `@company/ui` 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 파일 경로로 그대로 열립니다.
- `package-lock.json`이 바뀌면 CI 캐시 키도 바뀝니다. 그래서 CI는 업그레이드 커밋부터 2.0.0을 새로 설치했을 것입니다.
- 2.0.0의 `exports`에 `./button`이 없거나 경로 이름이 바뀌었다면, CI에서 위 에러가 납니다.
- Node 18과 Node 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이가 원인일 가능성은 낮습니다.

## 미확인

- 로컬에 실제로 설치된 `@company/ui` 버전.
- 2.0.0의 `exports`에 `./button`이 있는지 여부.
- 업그레이드 커밋에 `package-lock.json` 변경이 포함됐는지 여부.

## 원인을 확정하는 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다. 1.4.0이면 로컬이 업그레이드를 받지 않은 것입니다.
2. `npm view @company/ui@2.0.0 exports`를 실행해 공개 경로 목록을 봅니다. 목록에 `./button`이 없으면 원인이 확정됩니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. 로컬에서도 같은 에러가 나면 CI 환경 문제가 아니라 2.0.0 자체의 문제입니다.

## 해결 방법

- 2.0.0의 `exports`에 공개된 경로로 import 문을 바꿉니다. 이 방법을 권장합니다.
- `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.
- 위 두 방법이 준비되기 전까지 급하면 `@company/ui`를 1.4.0으로 되돌려도 됩니다.

**로컬 `node_modules`가 오래된 상태에서는 로컬 빌드 성공이 2.0.0 호환성의 증거가 되지 않습니다.** 앞으로는 업그레이드 후 `npm ci`로 다시 설치한 뒤 빌드해야 합니다.
