로컬 캐시는 서버마다 따로 갖는 저장소이고, Redis 캐시는 서버 4대가 함께 쓰는 저장소입니다. 그래서 Redis를 도입하면 서버마다 상품 목록이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 방식입니다. 지금은 API 서버 4대가 각자 자기 메모리(서버 안의 임시 저장 공간)에 상품 목록을 5분 동안 저장합니다. 서버마다 저장한 시점이 달라서 캐시 내용도 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 캐시 전용 서버입니다. 이번에는 Redis 서버 1대를 도입하고, API 서버 4대가 이 서버 하나를 같이 씁니다. 4대가 같은 캐시를 보므로 어느 서버에 접속해도 고객은 같은 상품 목록을 봅니다.

가격 변경 반영은 개발 방식에 따라 달라집니다. 가격을 바꿀 때 Redis의 캐시도 함께 갱신하도록 만들면, 4대 모두 새 가격을 보여줄 수 있습니다. 갱신 방식을 정하기 전에는 "최대 5분 지연"이 없어진다고 말할 수 없습니다.

Redis 서버가 1대이므로, 이 서버가 멈추면 API 서버 4대가 모두 Redis 캐시를 쓸 수 없습니다.
