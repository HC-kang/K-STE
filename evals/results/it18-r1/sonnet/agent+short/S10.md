로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있고 CI는 2.0.0을 새로 설치해서 결과가 갈린 것으로 보입니다. 이 설명은 추론이고, 아래 확인 단계로 검증해야 합니다.

**근거 (사실)**
- `@company/ui` 2.0.0부터 패키지에 `exports` 필드가 있습니다. `exports`는 패키지가 외부에 공개하는 import 경로를 제한하는 `package.json` 필드입니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20입니다.

**추론**
- 로컬 `node_modules`가 업그레이드 전에 설치됐으므로, 로컬은 1.4.0으로 빌드하고 있을 가능성이 큽니다.
- 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 파일 경로로 그대로 열립니다.
- 2.0.0에서 `exports`가 `./button` 경로를 공개하지 않으면 같은 import가 `Cannot find module` 오류를 냅니다. 2.0.0의 `exports` 내용은 아직 보지 않았습니다.
- 업그레이드가 `package-lock.json`을 바꿨으므로 캐시 키도 바뀌었을 것입니다. 그래서 CI가 오래된 캐시를 쓰고 있을 가능성은 낮습니다.
- Node 18과 20은 둘 다 `exports`를 지원하므로, Node 버전 차이는 주된 원인이 아닌 것으로 보입니다.

**확인 단계**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 확인하십시오.
2. 2.0.0 패키지의 `package.json`에서 `exports` 필드에 `./button`이 있는지 확인하십시오.
3. 로컬에서 `node_modules`와 `package-lock.json` 기준으로 `npm ci`를 실행한 뒤 빌드하십시오. 이때 CI와 같은 오류가 나면 추론이 맞습니다.

**수정 방향**
`./button`이 2.0.0의 `exports`에 없으면, 앱의 import를 2.0.0이 공개하는 경로로 바꾸거나 `@company/ui` 담당 팀에 `./button` 공개를 요청해야 합니다. 어느 쪽을 택할지는 2.0.0의 `exports` 내용을 본 뒤에 정해야 합니다.
