로컬 캐시는 각 서버가 자기 메모리에 상품 목록 복사본을 따로 저장하는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도 캐시 서버 1대에 그 복사본을 저장하는 방식입니다. (캐시는 자주 찾는 데이터를 빨리 꺼내려고 임시로 저장해 두는 복사본입니다.)

| 구분 | 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 사이의 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 조회 방식 | 서버 안에서 바로 읽음 | 네트워크를 거쳐 읽음 |

현재는 서버마다 캐시 내용이 달라서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. Redis를 도입하면 4대 서버가 같은 캐시를 보므로, 서버에 따라 가격이 다르게 보이는 문제는 없어집니다.

다만 Redis는 별도 서버라서 서버가 캐시를 읽을 때마다 네트워크를 거칩니다. 그래서 로컬 메모리보다 조회가 조금 느리고, 캐시 서버 자체를 운영하고 점검해야 합니다.

확인 필요: 가격 변경이 5분 안에 반영되는 지연이 완전히 사라지는지는 아직 정해지지 않았습니다. 이는 가격을 바꿀 때 Redis의 캐시를 바로 지우는지, 아니면 기존처럼 5분 뒤에 만료되도록 두는지에 따라 달라집니다.
