Redis를 도입하면 4대 서버가 같은 캐시를 보게 되므로, 서버마다 다른 가격이 고객에게 보이는 문제가 없어집니다. 다만 가격 변경이 고객에게 반영되는 시간이 지금의 최대 5분에서 얼마나 줄어드는지는 아직 정해지지 않았습니다.

캐시는 자주 쓰는 데이터를 빨리 꺼내 쓰려고 임시로 보관해 두는 곳입니다. 지금 방식과 Redis 방식의 차이는 다음과 같습니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 캐시가 있는 곳 | 각 API 서버의 메모리 | 캐시 전용 서버 1대를 4대 서버가 함께 사용 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 모든 서버가 같은 내용을 봄 |
| 조회 방식 | 서버 안에서 바로 읽음 | 네트워크를 거쳐 읽음 (로컬보다 약간 느릴 수 있음) |
| 가격 반영 시간 | 서버별로 최대 5분 | 캐시를 갱신하는 방식에 따라 다름 |

Redis로 좋아지는 점은 서버 사이의 일관성입니다. 반대로 캐시 서버가 한 대 더 생기므로 운영할 대상이 늘고, Redis가 멈추면 어떤 기능이 영향을 받는지 따로 확인해야 합니다.

확인 필요: 고객에게 가격이 반영되는 시점. 캐시를 5분마다 다시 읽는 방식인지, 가격이 바뀔 때 캐시를 바로 지우는 방식인지에 따라 반영 시점이 달라집니다.

가격 반영 시점을 외부에 약속하시기 전에 개발팀에 캐시 갱신 방식을 확인하십시오.
