원인은 2.0.0에 새로 추가된 `exports` 필드로 보입니다. `exports` 필드가 있으면 외부에서 import할 수 있는 경로가 그 목록으로 제한되고, 목록에 없는 `@company/ui/button`은 Node 해석기가 찾지 못합니다. 에러 메시지와 업그레이드 시점이 이 설명과 맞지만, 2.0.0의 `exports` 목록에 `./button`이 있는지는 아직 확인하지 않았습니다.

로컬에서만 빌드가 성공하는 이유는 로컬 `node_modules`가 3일 전 이전에 설치되어 1.4.0이 그대로 남아 있을 가능성이 크기 때문입니다(추론). 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 파일 경로대로 해석됩니다. CI는 캐시 키가 `package-lock.json`의 해시이므로, 락 파일이 2.0.0으로 갱신되었다면 캐시가 무효화되고 2.0.0을 새로 설치합니다. 즉, 두 환경이 서로 다른 버전의 패키지를 쓰고 있을 가능성이 있습니다.

Node 버전 차이(CI 18, 로컬 20)는 원인일 가능성이 낮습니다. Node 18도 `exports` 필드를 지원하기 때문입니다. 다만 번들러가 조건부 export를 해석하는 방식에 버전 차이가 영향을 줄 수 있으므로 배제하지는 않습니다.

확인할 항목은 다음과 같습니다.

- 로컬 `node_modules/@company/ui/package.json`의 `version`이 1.4.0인지 확인하십시오.
- CI 로그에서 실제로 설치된 `@company/ui` 버전을 확인하십시오.
- 2.0.0 패키지의 `exports` 필드에 `./button` 경로가 있는지 확인하십시오. 없다면 import 경로를 바꿀지, 패키지 쪽에서 경로를 추가할지 정해야 합니다.
- 3일 전 업그레이드 커밋에 `package-lock.json` 변경이 포함되었는지 확인하십시오.
- CI 실패가 처음 발생한 시점을 확인하십시오.

원인을 확정하려면 로컬에서 `rm -rf node_modules && npm ci`로 2.0.0을 새로 설치한 뒤 빌드를 재현하십시오. 로컬에서도 같은 에러가 나면 버전 차이가 원인이라는 것이 확정됩니다. 이후 `exports` 목록과 import 경로를 대조해 수정 방향을 정하십시오.
