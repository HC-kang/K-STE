# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 하며, 포함됐으면 롤백하지 않고 DBA 박지은에게 연락해야 한다.

## 1. 롤백 전 확인

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인한다.
   확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 확인 위치.
2. **마이그레이션이 포함됐으면 롤백하면 안 된다.** DBA 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 롤백할 리비전 번호(REVISION)를 확인한다.
   확인 필요: 리비전 번호를 확인하는 방법과 롤백 대상 리비전을 고르는 기준.

## 2. 롤백 실행

4. 다음 명령으로 롤백한다. `<REVISION>` 자리에 1단계에서 확인한 리비전 번호를 넣는다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 검증

5. payment-api의 `/healthz`가 200을 반환하는지 확인한다.
   확인 필요: `/healthz`를 호출할 주소와 호출 방법.
6. 결제 테스트 주문을 1건 진행하고, 주문이 성공하는지 확인한다.
   확인 필요: 결제 테스트 주문을 실행하는 방법과 담당자. 주문이 실패했을 때 할 조치.

## 4. 이력 기록

7. 롤백 이력을 #deploy 채널에 남긴다.
   확인 필요: 이력에 포함할 항목.
