가장 가능성이 높은 원인은 CI(코드 변경 때마다 자동으로 빌드하는 환경)가 `@company/ui` 2.0.0으로 빌드하고, 로컬은 1.4.0이 남은 `node_modules`(설치된 패키지가 들어 있는 폴더)로 빌드하는 것입니다. 이는 주어진 사실에서 끌어낸 추론입니다.

근거는 세 가지입니다.

- 에러는 `@company/ui/button`이라는 하위 경로를 찾지 못한다는 내용입니다. 2.0.0에서 패키지에 `exports` 필드(패키지가 외부에 공개하는 경로 목록)가 추가됐고, `exports`가 있는 패키지에서는 목록에 없는 하위 경로를 불러올 수 없습니다. 2.0.0의 `exports`에 `./button`이 없다면 이 에러가 납니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것이므로 1.4.0이 남아 있을 수 있습니다. 1.4.0에는 `exports` 필드가 없어 이 경로가 막히지 않았을 것입니다.
- CI 캐시 키(저장해 둔 설치 결과를 다시 쓸지 정하는 값)는 `package-lock.json`의 해시입니다. 업그레이드로 이 파일이 바뀌었다면 키도 바뀌어 CI가 2.0.0을 새로 설치했을 것입니다.

Node 18과 20 모두 `exports` 필드를 지원하므로, Node 버전 차이만으로는 이 에러를 설명하기 어렵습니다.

아직 사실로 확정되지 않은 것은 로컬에 설치된 `@company/ui`의 실제 버전, 2.0.0의 `exports` 내용, `package-lock.json`에 기록된 버전입니다. 다음 순서로 확인하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오. 로컬이 1.4.0이면 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 보십시오.
3. 다시 설치한 로컬에서 `npm run build`를 실행해 CI와 같은 에러가 나는지 보십시오.
