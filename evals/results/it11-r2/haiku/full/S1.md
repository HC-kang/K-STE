로컬 캐시는 각 API 서버 안에 상품 목록을 저장하고, Redis는 서버 4대가 함께 쓰는 별도의 캐시 서버 1대에 저장합니다. 캐시(자주 쓰는 데이터를 미리 저장해 두고 꺼내 쓰는 공간)의 위치가 달라지는 것입니다.

지금은 서버 4대가 각자 상품 목록을 5분 동안 저장합니다. 그래서 가격을 바꾸면 서버마다 옛 값을 가지고 있는 시간이 달라지고, 고객은 최대 5분 뒤에야 새 가격을 볼 수 있습니다.

Redis를 쓰면 상품 목록이 한 곳에만 저장되므로 4대 서버가 같은 값을 봅니다. 가격을 바꿀 때 Redis에 저장된 상품 값을 새 가격으로 고치거나 지우면, 모든 서버가 같은 시점에 새 가격을 읽게 됩니다.

다만 서버가 상품 목록을 읽을 때마다 서버 바깥의 Redis에 요청을 보내야 하므로, 서버 안 메모리에서 바로 읽을 때보다 느릴 수 있습니다. Redis 서버가 멈추면 상품 목록 조회에도 영향이 갑니다.

고객이 새 가격을 보는 정확한 시점은 가격 변경 시 Redis 값을 어떻게 갱신하느냐에 따라 달라집니다. 이 부분은 구현 방식을 확인한 뒤 다시 알려드리겠습니다.
