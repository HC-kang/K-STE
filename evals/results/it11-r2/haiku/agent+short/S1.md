Redis를 도입해도 가격 변경이 고객에게 최대 5분 늦게 보이는 문제는 그대로 남을 수 있습니다. Redis로 바뀌면서 확실히 달라지는 점은 4대 서버가 같은 캐시 내용을 보게 된다는 것입니다.

캐시(자주 쓰는 데이터를 미리 저장해 두는 임시 공간)를 두는 위치에 따라 차이가 생깁니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 캐시를 두는 곳 | 각 API 서버의 메모리(서버 안의 임시 저장 공간) | Redis(캐시 전용 서버) 1대 |
| 서버 4대가 보는 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 가격 변경 후 고객에게 보이는 시점 | 서버마다 최대 5분 | 캐시 설정에 따라 다름 |

유효 시간을 5분 그대로 두면 Redis를 써도 가격 반영은 최대 5분 늦습니다. 대신 서버 4대가 같은 가격 정보를 보므로, 한 서버에서는 새 가격이 나오고 다른 서버에서는 옛 가격이 나오는 상황은 없어집니다.

Redis 도입에는 단점도 있습니다. Redis 서버 1대가 멈추면 4대 서버가 함께 영향을 받을 수 있습니다.

확인 필요: Redis 도입 후 가격 반영 시점. 캐시 유효 시간을 5분으로 그대로 두는지, 가격을 바꿀 때 캐시를 지우는지에 따라 반영 시점이 달라집니다.
