Redis를 도입하면 서버 4대가 같은 캐시 내용을 읽으므로 서버마다 상품 정보가 달라지는 문제는 없어집니다. 다만 가격을 바꾼 뒤 고객 화면에 반영되기까지 최대 5분 걸리는 지연은 Redis를 도입하는 것만으로 자동으로 줄어들지 않습니다.

캐시(자주 쓰는 데이터를 미리 복사해 두고 꺼내 쓰는 임시 저장 공간)는 원본 데이터를 매번 다시 읽지 않으려고 쓰는 방식입니다. 로컬 캐시는 각 API 서버의 메모리 안에 저장하고, Redis는 서버 4대가 함께 쓰는 별도 캐시 서버 1대에 저장합니다.

| 항목 | 지금: 서버별 로컬 캐시 | 도입 후: Redis 캐시 |
|---|---|---|
| 저장 위치 | API 서버 4대의 각자 메모리 | 별도 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 달라질 수 있음 | 서버 4대가 같은 내용을 읽음 |
| 가격 변경 반영 | 최대 5분 지연 | 캐시 유효 시간 설정에 따라 달라짐 |

가격 반영을 5분보다 빠르게 하려면 가격을 바꿀 때 해당 상품의 캐시를 지우는 방식(캐시 삭제)을 함께 검토할 수 있습니다. 이렇게 하면 다음 조회 때 새 가격을 읽습니다.

확인 필요: Redis 도입 후에도 캐시 유효 시간을 5분으로 유지할지, 가격 변경 시 캐시를 지울지는 주어진 정보로 알 수 없습니다.
