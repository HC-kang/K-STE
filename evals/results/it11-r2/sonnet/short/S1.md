캐시를 저장하는 위치가 다르고, Redis를 도입하면 API 서버 4대가 같은 캐시 내용을 보게 됩니다.

캐시는 자주 쓰는 데이터를 매번 원본에서 가져오지 않도록 임시로 저장해 두는 방식입니다. 지금은 API 서버(고객 요청을 받아 처리하는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 이것이 로컬 캐시입니다. 서버마다 따로 저장하기 때문에 캐시 내용이 서버마다 다릅니다. 그래서 가격을 바꾸면 고객에게 반영되기까지 최대 5분이 걸립니다.

Redis 캐시는 별도의 캐시 서버 1대에 상품 목록을 저장하고, API 서버 4대가 그 한 곳을 같이 읽습니다. 그래서 서버마다 캐시 내용이 달라지는 문제가 없어집니다. 고객은 어느 서버로 연결되든 같은 상품 목록을 보게 됩니다.

아직 확인하지 못한 점이 두 가지 있습니다.

- Redis 도입만으로 가격 반영 지연(최대 5분)이 없어지는지는 확인하지 못했습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 갱신하는 방식이 이번 도입 범위에 들어 있는지 개발팀에 확인해야 합니다.
- Redis 서버가 1대라서, 이 서버가 멈추면 API 서버 4대가 모두 영향을 받을 수 있습니다. 이 경우를 어떻게 대비하는지도 개발팀에 확인해야 합니다.
