가장 유력한 원인은 CI만 `@company/ui` 2.0.0을 설치하고, 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 경로 목록)에 `./button`이 없어서 `@company/ui/button`을 찾지 못하는 것입니다. 이 결론은 주어진 사실에서 추론한 것이고, 아직 확인하지 않았습니다.

| 항목 | 로컬 | CI |
|---|---|---|
| `@company/ui` 버전 | 1.4.0일 가능성이 큼 (미확인) | 2.0.0으로 추정 (미확인) |
| Node | 20 | 18 |
| 설치 방식 | 3일 전보다 먼저 설치한 `node_modules` 유지 | `package-lock.json` 해시로 캐시 키 결정 |

추론 과정은 다음과 같습니다.

1. 3일 전에 버전을 올렸으므로 `package-lock.json`(설치할 정확한 버전을 기록한 파일)도 바뀌었을 것입니다. 그러면 CI 캐시(이전 설치 결과를 재사용하는 저장소) 키가 달라지고, CI는 `@company/ui` 2.0.0을 새로 설치합니다.
2. 로컬 `node_modules`는 3일 전보다 먼저 설치했으므로 1.4.0이 그대로 남아 있을 가능성이 큽니다.
3. 1.4.0에는 `exports` 필드가 없어서 Node가 `@company/ui/button`을 파일 경로로 읽습니다. 그래서 로컬 빌드는 성공합니다.
4. 2.0.0에는 `exports` 필드가 있어서 Node가 목록에 없는 경로를 모두 막습니다. 그래서 `./button`이 목록에 없으면 CI 빌드는 `Cannot find module` 에러로 실패합니다.

Node 18과 20은 둘 다 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 주원인이 아닌 것으로 보입니다.

확인 필요: 위 추론이 맞는지 아래 순서로 확인해야 합니다.

1. 로컬과 CI에서 각각 `npm ls @company/ui`를 실행해 설치된 버전을 비교합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 봅니다.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. 로컬에서도 같은 에러가 나면 원인이 확정됩니다.

2.0.0의 `exports`에 `./button`이 없다면 해결 방법은 두 가지입니다. 하나는 앱의 import 경로를 2.0.0이 공개한 경로로 바꾸는 것입니다. 다른 하나는 `@company/ui` 담당자에게 `./button` 추가를 요청하는 것입니다. 급하면 `@company/ui`를 1.4.0으로 되돌려도 됩니다. 2.0.0의 변경 내역에 경로 변경이 적혀 있는지도 함께 확인하길 권장합니다.
