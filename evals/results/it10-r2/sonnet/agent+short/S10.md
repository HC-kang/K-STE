가장 유력한 원인은 `@company/ui` 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 경로 목록)가 `@company/ui/button` 경로를 허용하지 않는 것입니다. 로컬은 2.0.0 이전 버전이 설치된 상태여서 같은 문제가 드러나지 않았을 가능성이 큽니다. 아직 코드나 설치 파일을 열어 검증하지 않았으므로 아래 내용은 모두 주어진 정황에서 나온 추론입니다.

## 추론 근거

`exports` 필드가 있으면 Node는 그 목록에 적힌 경로만 불러오게 합니다. 목록에 없는 하위 경로는 파일이 실제로 있어도 `Cannot find module` 오류가 납니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로 그대로 동작했을 것입니다.

CI와 로컬의 차이는 다음과 같습니다.

| 항목 | CI | 로컬 |
|---|---|---|
| Node 버전 | 18 | 20 |
| `@company/ui` 설치 시점 | 2.0.0 승격 이후로 보임 | 3일 전보다 이전 |
| `@company/ui` 버전 | 2.0.0으로 보임 | 1.4.0으로 보임 |
| 캐시 | `package-lock.json` 해시가 바뀌어서 새로 설치했을 것으로 보임 | 해당 없음 |

CI는 캐시 키가 `package-lock.json`의 해시입니다. 버전 승격으로 락 파일이 바뀌었다면 캐시가 갱신되어 CI가 2.0.0을 설치했을 것입니다. 반면 로컬 `node_modules`는 승격 전에 설치한 것이어서 옛 버전이 남아 있을 가능성이 큽니다.

## 가능성이 낮은 원인

Node 18과 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이가 이번 오류의 주원인일 가능성은 낮습니다. 다만 Node 버전 차이가 아무 영향도 없다고 확인한 것은 아닙니다.

## 확인되지 않은 사항

- 로컬 `node_modules`에 설치된 `@company/ui`의 실제 버전
- 2.0.0의 `exports`에 `./button`이 들어 있는지, 다른 이름으로 바뀌었는지
- CI 로그에 설치된 `@company/ui`의 버전

## 검증 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봐야 합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 봐야 합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 CI와 같은 방식으로 다시 설치한 뒤 `next build`를 실행해야 합니다.
4. 3번에서 같은 오류가 나면 Node 18로도 한 번 더 빌드하는 것을 권장합니다.

3번에서 CI와 같은 오류가 재현되면 원인은 확정됩니다.

## 수정 방향

수정은 둘 중 하나입니다. 어느 쪽을 고를지는 `exports` 내용을 본 뒤에 정해야 합니다.

- `exports`에 `./button`에 해당하는 경로가 있으면 앱의 import 경로를 그 경로로 고칩니다.
- 공개 경로가 없으면 `@company/ui` 담당자에게 `./button` 경로를 `exports`에 추가해 달라고 요청합니다.

2.0.0을 쓰기로 한 결정을 되돌리는 방법도 있지만, 근본 원인을 해결하지는 못합니다.

PM은 일정 판단에 다음 사실을 참고하십시오. 이번 오류는 인프라 장애가 아니고, 로컬 환경이 CI보다 오래된 상태여서 생긴 불일치로 보입니다. 위 1-3단계는 확정까지 오래 걸리지 않을 것으로 예상하지만, 소요 시간은 측정하지 않았습니다.
