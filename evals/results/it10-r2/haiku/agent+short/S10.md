# `@company/ui/button` CI 빌드 실패 원인 분석

현재 원인은 확정되지 않았다. 가장 가능성이 높은 설명은 로컬 `node_modules`가 아직 `@company/ui` 1.4.0을 담고 있어서, 로컬 빌드가 2.0.0 변경을 검증하지 못한다는 것이다. 이 설명은 추론이며 `npm ls @company/ui`로 확인해야 한다. CI 실패는 2.0.0에 추가된 `exports` 필드가 `./button` 경로를 허용하지 않는 것과 관련이 있는 것으로 보인다.

이 분석은 전달받은 정보만 근거로 한다. 저장소, CI 로그, 패키지 소스는 직접 확인하지 않았다.

## 확인된 사실

- 3일 전 `@company/ui`를 1.4.0에서 2.0.0으로 올렸다.
- 2.0.0에서 패키지에 `exports` 필드가 추가됐다.
- CI는 Node 18을, 로컬은 Node 20을 사용한다.
- CI 캐시 키는 `package-lock.json`의 해시다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치됐다.
- CI에서 `Error: Cannot find module '@company/ui/button'`이 발생한다.

## 원인 후보

| 후보 | 근거 | 확인 방법 | 가능성 |
|---|---|---|---|
| 로컬이 1.4.0을 사용 중이다 | 로컬 `node_modules`가 업그레이드 이전에 설치됐다. 1.4.0은 `exports`가 없어서 `button` 파일을 직접 찾을 수 있다. | 로컬에서 `npm ls @company/ui`를 실행한다. | 높음(추론) |
| 2.0.0의 `exports`에 `./button`이 없다 | 실패 시점이 `exports` 추가 시점과 일치한다. | 2.0.0 `package.json`의 `exports` 항목을 확인한다. | 높음(추론) |
| 대소문자가 다르다 | 로컬 macOS는 기본적으로 대소문자를 구분하지 않고, CI의 Linux는 구분한다. 로컬만 통과하는 현상을 설명할 수 있다. | 2.0.0의 파일명과 import 경로의 대소문자를 비교한다. | 중간(추론) |
| Node 버전 차이 | `exports`는 Node 18에서도 지원된다. 이 차이만으로는 실패를 설명하기 어렵다. | CI 또는 로컬에서 Node 18로 재현한다. | 낮음(추론) |
| 캐시가 이전 `node_modules`를 복원한다 | 캐시 키는 lockfile 해시라서 업그레이드 커밋에서 키가 바뀐다. 부분 일치 키(`restore-keys`)가 있으면 이전 설치본이 복원될 수 있다. | CI 워크플로의 캐시 설정을 확인한다. | 낮음(추론) |

첫 번째 후보가 맞다면 로컬 빌드 성공은 2.0.0 검증 결과가 아니다. 에러 문구 `Cannot find module`은 Node의 CommonJS 해석기 형식이다. `exports`가 차단하면 Node는 보통 `ERR_PACKAGE_PATH_NOT_EXPORTED`를 낸다. 그러므로 실패를 낸 도구가 Next.js 번들러인지 Node 실행인지는 CI 로그 전체로 확인해야 한다.

## 권장 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인한다.
2. 2.0.0 패키지의 `exports`에 `./button` 항목이 있는지 확인한다.
3. CI 로그 전체를 열어 에러를 낸 단계와 도구를 확인한다.
4. 로컬에서 `npm ci`로 lockfile 기준 설치를 다시 한 뒤 빌드한다.
5. 로컬에서 Node 18을 사용해 빌드를 재현한다.
6. 2.0.0 파일명과 import 경로의 대소문자가 일치하는지 확인한다.

## 조치 방향

확인 결과에 따라 조치가 달라진다. `./button`이 `exports`에 없다면 패키지 쪽에 항목을 추가하거나, 앱의 import 경로를 2.0.0이 허용하는 경로로 바꿔야 한다. 대소문자 문제라면 import 경로나 파일명 중 하나를 맞춰야 한다.

재현 환경은 CI와 같게 맞춰야 한다. 로컬 `node_modules`는 삭제한 뒤 다시 설치하는 것을 권장한다. Node 18은 2025년 4월에 지원이 종료됐으므로, CI의 Node 버전을 올리는 방안도 함께 검토하는 것을 권장한다.

## 미확인 사항

배포 차단 여부와 영향 범위는 전달받은 정보에 없다. 2.0.0의 실제 `exports` 내용, CI 전체 로그, 캐시 설정, lockfile의 `@company/ui` 기록은 아직 확인하지 않았다.
