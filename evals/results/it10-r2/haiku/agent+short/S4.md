# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 그 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 마이그레이션이 포함됐으면 롤백하면 안 된다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다. 확인 필요: 마이그레이션 포함 여부를 확인할 위치와 방법.
2. **경고:** 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때는 DBA 박지은에게 연락해야 한다. 확인 필요: DBA 박지은의 연락 수단.
3. 마이그레이션이 포함되지 않았으면 롤백할 `<REVISION>` 값을 확인한다. 확인 필요: `<REVISION>` 값을 얻는 방법.

## 롤백 절차

4. 마이그레이션이 포함되지 않았음을 확인했으면 다음 명령으로 롤백한다. `<REVISION>`은 3번에서 확인한 값으로 바꾼다.

```
argocd app rollback payment-api <REVISION>
```

## 롤백 후 확인

5. `/healthz`가 200을 반환하는지 확인한다. 확인 필요: `/healthz`를 호출할 주소.
6. 결제 테스트 주문 1건을 넣고 결제가 성공하는지 확인한다. 확인 필요: 테스트 주문을 넣는 방법과 사용할 테스트 결제 수단.

## 기록

7. 롤백 이력을 #deploy 채널에 남긴다. 확인 필요: 이력에 적을 항목과 양식.
