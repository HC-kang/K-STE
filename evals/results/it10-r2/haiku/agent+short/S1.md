로컬 캐시는 각 서버가 자기 안에 따로 두는 임시 보관 공간이고, Redis 캐시는 서버 4대가 함께 쓰는 별도의 캐시 서버 1대입니다. Redis를 도입하면 4대 서버가 같은 상품 목록을 보게 되지만, 그것만으로 가격 변경이 고객 화면에 바로 보이지는 않습니다.

| 구분 | 현재: 서버별 로컬 캐시 | 도입 예정: Redis 캐시 |
|---|---|---|
| 보관 위치 | 서버 4대 각각의 메모리(서버가 작업할 때 쓰는 임시 공간) | 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대 서버가 같은 내용을 봅니다 |
| 가격 변경 후 고객 화면 반영 | 최대 5분 | 유효 시간을 5분으로 두면 최대 5분입니다 |
| 응답 속도 | 서버 안에서 바로 꺼냅니다 | 네트워크로 캐시 서버에 요청해야 하므로 로컬보다 느릴 수 있습니다 |
| 장애 영향 | 서버 한 대에 문제가 생겨도 다른 서버에는 영향이 없습니다 | 캐시 서버가 멈추면 4대 서버 모두 영향을 받습니다 |

Redis 도입의 가장 큰 이점은 서버 4대가 같은 상품 목록과 같은 가격을 보게 된다는 점입니다. 지금은 서버마다 캐시 내용이 달라서, 가격이 바뀐 직후에는 서버에 따라 옛 가격과 새 가격이 섞여 보일 수 있습니다.

다만 Redis를 도입하는 것만으로 가격 반영 지연이 없어지지는 않습니다. 캐시에 담긴 상품 목록은 유효 시간(캐시 자료를 유지하는 시간)이 지나야 버려지기 때문입니다. 지연을 줄이려면 가격을 바꿀 때 Redis의 상품 목록을 바로 지우는 작업을 함께 넣는 것을 권장합니다.
