## 결론

현재 가장 유력한 원인은 `@company/ui` 2.0.0의 `exports` 필드가 `@company/ui/button` 경로를 노출하지 않는 것이다. 로컬 빌드가 성공하는 이유는 로컬 `node_modules`에 1.4.0이 남아 있기 때문으로 보인다. 아직 재현하거나 패키지 내용을 확인하지 않았으므로 이 결론은 추론이며 확정되지 않았다.

## 현상

CI의 Next.js 빌드가 `Cannot find module '@company/ui/button'` 오류로 실패한다. 같은 코드는 로컬에서 성공한다. 실패는 `@company/ui`를 2.0.0으로 올린 3일 전 이후에 시작됐다.

## 원인 추정 (추론)

`exports` 필드는 패키지 외부에 공개할 경로를 명시한다. 이 필드가 있으면 Node와 번들러는 목록에 없는 경로를 파일 경로로 직접 찾지 않는다. 1.4.0에는 이 필드가 없었으므로 `@company/ui/button`이 파일 경로로 그대로 해석됐다. 2.0.0에서 `exports`가 추가되었고, 그 목록에 `./button`이 없다면 같은 import가 실패한다. `./button`이 목록에 있는지는 아직 확인하지 않았다.

로컬과 CI의 환경 차이는 다음과 같다.

| 항목 | 로컬 | CI |
|---|---|---|
| `@company/ui` 버전 | 1.4.0으로 추정 (3일 전 이전에 설치) | 2.0.0으로 추정 (lock 파일 기준 새로 설치) |
| Node 버전 | 20 | 18 |
| `node_modules` | 3일 전 설치분이 그대로 남음 | 캐시 키 변경으로 새로 설치된 것으로 추정 |

로컬 `node_modules`가 오래된 1.4.0을 가리키고 있어서 로컬 빌드가 문제를 드러내지 않았을 가능성이 크다. 이 추정은 `npm ls @company/ui`로 바로 확인할 수 있다.

## Node 버전 차이에 대한 평가

Node 18과 20은 모두 `exports` 필드를 지원한다. 따라서 Node 버전 차이만으로 이 오류가 생길 가능성은 낮다고 본다(추론). 다만 Node 18은 2025년 4월에 지원이 종료되었으므로, CI의 런타임 버전은 별도로 점검할 필요가 있다.

오류 메시지 형식도 확인이 필요하다. `Cannot find module`은 Node의 `require` 해석 오류 형식이다. Next.js 빌드 중 번들링 단계에서는 보통 `Module not found`로 표시된다. 따라서 이 오류가 `next build` 과정에서 나온 것인지, `next.config.js` 같은 Node 스크립트에서 나온 것인지 CI 로그로 확인해야 한다.

## 확인 필요 사항

- CI 로그에서 오류가 발생한 단계와 파일 경로
- CI가 실제로 설치한 `@company/ui` 버전이 2.0.0인지
- 2.0.0 패키지의 `package.json` `exports`에 `./button` 항목이 있는지
- CI 캐시가 `restore-keys`로 이전 `node_modules`를 복원했는지

## 확인 방법

1. 로컬에서 `node_modules`를 삭제하고 `npm ci`로 다시 설치한 뒤 빌드한다. 같은 오류가 나오면 원인이 재현된 것이다.
2. `npm ls @company/ui`로 실제 설치된 버전을 확인한다.
3. 2.0.0 패키지의 `package.json`에서 `exports` 목록을 확인한다.
4. Node 18 환경에서 빌드를 재현한다.

## 조치 방향 (권장)

재현과 확인이 끝난 뒤에 조치를 정하는 것을 권장한다. 조치 후보는 두 가지다. 첫째, 앱의 import를 2.0.0이 공개한 경로에 맞게 바꾼다. 둘째, `@company/ui` 측에 `./button` 경로를 `exports`에 추가하도록 요청한다. CI의 Node 버전은 지원 중인 버전으로 올리는 것을 권장한다.
