Redis로 바꾸면 4대 서버가 같은 캐시를 보게 되어, 서버마다 상품 정보가 다르게 보이는 문제가 없어집니다. 다만 가격 반영이 최대 5분 늦는 문제는 Redis 도입만으로는 줄지 않습니다. 가격을 바꿀 때 캐시를 지우는 작업을 함께 넣어야 고객에게 바로 반영됩니다.

| 항목 | 지금 (서버별 로컬 캐시) | Redis 도입 후 (공용 캐시) |
|---|---|---|
| 캐시 위치 | 각 API 서버의 메모리 안 | 서버 4대가 함께 쓰는 캐시 서버 1대 |
| 서버 간 상품 정보 | 서버마다 다를 수 있음 | 4대 서버가 같은 정보를 봄 |
| 가격 변경 반영 | 최대 5분 늦게 반영됨 | 캐시를 지우는 작업이 없으면 여전히 최대 5분 늦게 반영됨 |

캐시는 자주 쓰는 데이터를 매번 원래 자리에서 읽지 않도록 가까운 곳에 임시로 저장해 두는 방식입니다. 로컬 캐시는 각 서버가 자기 메모리에 저장하고, Redis는 데이터를 메모리에 두는 별도 서버를 여러 서버가 같이 씁니다.
