# payment-api 운영 배포 롤백 런북

이 문서는 ArgoCD로 운영 환경의 payment-api 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 포함됐으면 롤백하면 안 되고, DBA 박지은에게 연락해야 한다.

## 적용 범위

- 배포 도구: ArgoCD
- 대상 애플리케이션: payment-api
- 롤백 명령: `argocd app rollback payment-api <REVISION>`

## 롤백 전 확인

롤백할 배포에 DB 마이그레이션이 포함됐는지 먼저 확인해야 한다. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다. 마이그레이션이 포함되지 않았을 때만 아래 롤백 절차를 진행한다.

## 롤백 절차

1. 롤백할 리비전 번호(`<REVISION>`)를 확인한다.
2. `argocd app rollback payment-api <REVISION>` 명령을 실행한다.
3. `/healthz`가 200을 반환하는지 확인한다.
4. 결제 테스트 주문 1건을 실행하고, 주문이 성공하는지 확인한다.

## 롤백 이력 기록

롤백을 마치면 #deploy 채널에 롤백 이력을 남긴다.

## 확인 필요 사항

- 확인 필요: 배포에 DB 마이그레이션이 포함됐는지 확인하는 방법이 주어지지 않았다.
- 확인 필요: 롤백할 리비전 번호를 찾는 방법이 주어지지 않았다.
- 확인 필요: `/healthz`를 호출할 주소와 방법이 주어지지 않았다.
- 확인 필요: 결제 테스트 주문을 실행하는 방법과 대상 환경이 주어지지 않았다.
- 확인 필요: 3단계나 4단계가 실패했을 때 조치가 주어지지 않았다.
- 확인 필요: #deploy 채널에 남길 롤백 이력의 항목과 형식이 주어지지 않았다.
