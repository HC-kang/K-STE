로컬은 `@company/ui` 1.4.0 상태로 빌드하고 CI는 2.0.0으로 빌드해서, 같은 import가 CI에서만 실패했을 가능성이 높습니다.

사실로 주어진 내용은 다음과 같습니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것입니다.
- 2.0.0부터 `@company/ui`에 `exports` 필드(패키지가 외부에 공개할 파일 경로를 지정하는 설정)가 있습니다.
- CI(코드를 올리면 자동으로 빌드하는 서버)의 캐시 키는 `package-lock.json`(설치할 패키지 버전을 고정한 파일)의 해시입니다.

추정 경로는 다음과 같습니다.
1. 로컬 `node_modules`를 업그레이드 뒤에 다시 설치하지 않았다면, 로컬에는 `exports`가 없는 1.4.0이 남아 있습니다. 이 경우 Node는 `@company/ui/button`을 파일 경로로 직접 찾으므로 빌드가 통과합니다.
2. 업그레이드 커밋에서 `package-lock.json`이 바뀌었다면, CI 캐시 키도 바뀌어 CI가 2.0.0을 새로 설치합니다.
3. 2.0.0에서 Node는 `exports`에 적힌 경로만 외부에 공개합니다. `exports`에 `./button`이 없으면 `Cannot find module '@company/ui/button'`이 발생합니다.

Node 18과 20의 차이는 원인일 가능성이 낮습니다. Node 18도 `exports` 필드를 지원하기 때문입니다.

아래 순서로 추정을 검증하십시오.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 조회하십시오. 1.4.0이 나오면 위 추정과 일치합니다.
2. `@company/ui` 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드하십시오. CI와 같은 오류가 나면 로컬과 CI의 차이는 설치 버전입니다.

2번에서 `./button`이 없으면, import 경로를 `exports`가 공개하는 경로로 바꾸거나 `@company/ui`의 `exports`에 해당 경로를 추가해야 합니다.
