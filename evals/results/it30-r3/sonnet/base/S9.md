## 문제점

1. **회의가 특정되지 않음**: "금일 회의"는 일시, 안건, 참석자를 알 수 없습니다. "금일"은 읽는 시점에 따라 날짜가 달라지므로 날짜를 적어야 합니다.
2. **공유한다면서 내용이 없음**: "논의된 내용을 공유드립니다"라고 했지만 실제 논의 내용은 "성능 이슈 → 개선 예정"뿐입니다.
3. **"신규 API"가 불명확함**: 어떤 API인지 식별할 수 없습니다. 이름, 엔드포인트, 버전 중 하나가 필요합니다.
4. **"성능 이슈"가 모호함**: 응답 지연, 처리량, 메모리, 오류율 중 무엇인지 알 수 없고 수치도 없습니다.
5. **"보여지며"는 이중 피동이고 근거가 없음**: "보이다"에 "-어지다"가 겹친 표현입니다. 누가 어떤 근거로 판단했는지 모르고, 확인된 사실인지 추정인지도 구분되지 않습니다.
6. **"개선 작업"에 담당자, 범위, 기한이 없음**: 누가 무엇을 언제까지 하는지 알 수 없습니다.
7. **"추후 공유드릴 수 있도록 하겠습니다"는 약속이 아님**: "추후"는 시점이 없고, "~수 있도록 하겠습니다"는 공유하겠다는 건지 노력하겠다는 건지 불분명합니다.
8. **군더더기**: "~에 대해", "~의 경우", "자세한 사항" 같은 표현이 문장을 늘립니다.

## 수정 예시

> 10월 28일 백엔드 정기회의 결과를 공유합니다.
> 결제 API v2의 평균 응답 시간이 800ms로 목표(300ms)를 넘었습니다. 원인은 DB 조회 쿼리로 추정하며, 김OO 님이 11월 4일까지 쿼리 최적화를 진행합니다. 개선 결과는 11월 5일에 공유하겠습니다.

위 예시의 API 이름, 수치, 담당자, 날짜는 임의로 채운 값입니다. 실제 값으로 바꿔 쓰시면 됩니다.
