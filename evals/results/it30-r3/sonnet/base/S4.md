# 운영 배포 롤백 런북 (payment-api)

## 적용 범위
- 배포 도구: ArgoCD
- 대상 애플리케이션: `payment-api`

## 1. 롤백 전 확인 (필수)

### 1-1. DB 마이그레이션 포함 여부 확인
롤백 대상 배포(현재 배포)에 DB 마이그레이션이 포함됐는지 반드시 확인한다.

- **마이그레이션이 포함됨 → 롤백하지 않는다.** DBA 박지은에게 연락하고, 이후 절차는 박지은의 지시를 따른다.
- **마이그레이션이 포함되지 않음 →** 1-2로 진행한다.

### 1-2. 롤백할 REVISION 확인
```
argocd app history payment-api
```
출력에서 되돌아갈 REVISION 번호를 확인한다.

## 2. 롤백 실행
```
argocd app rollback payment-api <REVISION>
```
`<REVISION>`에는 1-2에서 확인한 번호를 넣는다.

> 참고: ArgoCD는 자동 동기화(auto-sync)가 켜져 있으면 롤백을 거부한다. 이 경우 자동 동기화 설정을 확인한다.

## 3. 롤백 후 검증
아래 두 가지를 모두 확인한다.

1. `/healthz`가 HTTP 200을 반환한다.
2. 결제 테스트 주문 1건이 성공한다.

둘 중 하나라도 실패하면 롤백이 완료된 것으로 보지 않고, #deploy 채널에 실패 사실을 남긴 뒤 담당자에게 에스컬레이션한다.

## 4. 이력 기록
롤백 이력을 **#deploy** 채널에 남긴다. 아래 항목을 포함한다.

- 롤백 시각
- 롤백 전 REVISION → 롤백 후 REVISION
- 롤백 사유
- 마이그레이션 미포함 확인 결과
- `/healthz` 및 결제 테스트 주문 결과
