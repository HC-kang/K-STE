로컬 캐시는 서버마다 따로 저장하고, Redis 캐시는 서버 4대가 하나를 같이 씁니다. 이번 도입으로 서버마다 상품 목록 내용이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 매번 새로 가져오지 않도록 임시로 저장해 두는 방식입니다. 지금은 API 서버(고객 요청을 받아 처리하는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 이 방식이 로컬 캐시입니다. 서버마다 저장한 시점이 다르기 때문에, 가격을 바꾼 직후에는 서버에 따라 고객에게 보이는 가격이 다를 수 있습니다. 그래서 가격 변경이 고객에게 최대 5분 늦게 반영됩니다.

Redis는 여러 서버가 함께 쓰는 캐시 전용 서버입니다. 이번에는 Redis 서버 1대를 두고, API 서버 4대가 모두 여기에 저장된 상품 목록을 읽습니다. 그래서 4대가 항상 같은 내용을 고객에게 보여 줍니다.

가격 변경이 빨리 반영되는지는 Redis 도입만으로 정해지지 않습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지우도록 만들면, 새 가격이 최대 5분 늦게 보이는 문제를 줄일 수 있습니다.

확인 필요: 이번 도입 범위에 가격 변경 시 Redis의 상품 목록을 바로 지우는 작업이 들어 있는지.

**주의:** Redis 서버가 1대이므로, 이 서버가 멈추면 API 서버 4대가 모두 영향을 받을 수 있습니다.
