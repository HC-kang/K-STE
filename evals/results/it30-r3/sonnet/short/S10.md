가장 가능성이 높은 원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰는 것입니다. 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치했으므로 1.4.0이 남아 있다고 추정합니다. CI는 `package-lock.json`이 바뀌어 캐시 키가 달라졌으므로 2.0.0을 새로 설치했다고 추정합니다.

2.0.0에는 `exports` 필드(패키지가 외부에 공개할 import 경로를 지정하는 package.json 설정)가 추가됐습니다. `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로 그대로 열렸습니다. 2.0.0의 `exports`에 `./button`이 없거나 다른 이름으로 바뀌었다면 `Cannot find module '@company/ui/button'` 에러가 나는 것이 자연스럽습니다.

Node 18과 Node 20의 차이는 원인일 가능성이 낮습니다. 두 버전 모두 `exports`를 지원하기 때문입니다. 다만 Node 버전을 맞춰 직접 실행해 보지는 않았습니다.

**구분**
- 사실: 에러 메시지, 2.0.0 업그레이드, `exports` 추가, Node 버전 차이, 캐시 키, 로컬 설치 시점은 질문에 적힌 내용입니다.
- 추론: 로컬에 1.4.0이 설치돼 있다는 점과 CI에 2.0.0이 설치된다는 점입니다.
- 미확인: 2.0.0 `exports`의 실제 내용과 `package-lock.json`에 기록된 버전입니다.

**확인 순서**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 확인합니다.
2. 로컬 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. 같은 에러가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.

**해결 방법**
- `exports`에 `./button`이 다른 이름으로 있으면, 앱의 import 경로를 그 이름으로 고칩니다.
- `exports`에 해당 경로가 없으면, `@company/ui` 담당 팀에 경로 추가를 요청합니다.
- 급하면 `@company/ui`를 1.4.0으로 되돌려 CI를 먼저 복구할 수 있습니다.

PM이 알아둘 점은 로컬 빌드 성공이 현재 의존성 상태를 보증하지 않는다는 것입니다. 이번 건은 2.0.0 업그레이드가 호환되지 않는 변경(breaking change)을 포함했는데, 로컬에서는 그 변경이 드러나지 않았습니다.
