Redis를 도입하면 4대 서버가 같은 캐시를 함께 쓰므로, 서버마다 상품 목록이 달라지는 문제가 없어집니다. 가격 변경이 고객에게 5분 안에 반영되는지는 Redis 도입만으로 정해지지 않고, 캐시를 언제 지우느냐에 따라 달라집니다.

두 방식의 차이는 다음과 같습니다. 현재 방식은 각 서버가 자기 메모리(컴퓨터가 작업할 때 쓰는 임시 저장 공간)에 상품 목록을 저장하는 로컬 캐시(자주 쓰는 데이터를 가까이에 미리 저장해 두는 방식)입니다. Redis는 서버 4대가 함께 쓰는 별도의 캐시 서버입니다.

| 항목 | 현재: 서버별 로컬 캐시 | Redis 도입 후 |
|---|---|---|
| 저장 위치 | 각 API 서버 안에 저장합니다. | 별도의 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 4대 서버가 같은 내용을 봅니다. |
| 조회 속도 | 서버 안에서 바로 꺼내므로 빠릅니다. | 네트워크를 거쳐 꺼내므로 로컬보다 느립니다. |
| 장애 영향 | 해당 서버의 캐시에만 문제가 생깁니다. | Redis 서버에 문제가 생기면 4대 서버 모두 영향을 받습니다. |

가격 반영 지연은 캐시를 보관하는 시간(만료 시간)과 가격을 바꿀 때 캐시를 지우는지에 따라 정해집니다. 만료 시간을 5분으로 두고 가격 변경 시 캐시를 지우지 않으면, Redis로 바꿔도 최대 5분 지연은 그대로입니다. 가격 변경 시 캐시를 바로 지우도록 하면 반영이 빨라질 수 있습니다. 이 작업이 이번 도입 범위에 들어가는지는 개발팀에 확인해야 합니다.
