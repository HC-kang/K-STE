# payment-api 운영 배포 롤백 런북

- **대상 서비스:** payment-api (운영)
- **배포 도구:** ArgoCD
- **롤백 명령:** `argocd app rollback payment-api <REVISION>`
- **DBA 담당:** 박지은
- **이력 기록 채널:** #deploy

---

## 0. 원칙

- **DB 마이그레이션이 포함된 배포는 롤백하지 않는다.** 1단계에서 이를 확인하지 못하면 다음 단계로 넘어가지 않는다.
- 마이그레이션이 포함된 경우 롤백하지 말고 **박지은(DBA)에게 즉시 연락**한다.
- 모든 단계의 결과와 시각을 #deploy 채널에 남긴다.

---

## 1. 롤백 전 확인 (게이트)

### 1-1. 현재 배포와 롤백 대상 REVISION 확인

```sh
argocd app get payment-api
argocd app history payment-api
```

- 현재 배포된 리비전(ID, 커밋 SHA)을 기록한다.
- 롤백할 `<REVISION>`(이력 ID)을 정하고 기록한다.

### 1-2. DB 마이그레이션 포함 여부 확인 (필수)

현재 배포 커밋과 롤백 대상 커밋 사이의 변경에 마이그레이션이 있는지 확인한다.

```sh
git log --oneline <롤백대상_커밋>..<현재_커밋>
git diff --stat <롤백대상_커밋> <현재_커밋> -- <마이그레이션_경로>
```

- `<마이그레이션_경로>`는 프로젝트의 마이그레이션 디렉터리로 바꾼다. (예: `db/migrations/`)
- 판단이 애매하면(새 테이블, 컬럼 변경, 데이터 변경 스크립트 등) **마이그레이션 포함으로 간주**한다.

**판정**

| 결과 | 조치 |
|---|---|
| 마이그레이션 **포함** | **롤백 중단.** 박지은(DBA)에게 연락한다. 아래 4번으로 이동해 기록한다. |
| 마이그레이션 **미포함** | 1-3으로 진행한다. |

### 1-3. 자동 동기화 상태 확인

자동 동기화(auto-sync)가 켜져 있으면 롤백이 실패하거나 되돌려질 수 있다. 상태를 확인하고 필요하면 팀 절차에 따라 끈다.

```sh
argocd app get payment-api -o yaml | grep -A3 syncPolicy
```

---

## 2. 롤백 실행

```sh
argocd app rollback payment-api <REVISION>
```

- 실행 후 동기화가 끝날 때까지 기다린다.

```sh
argocd app wait payment-api --health --sync --timeout 300
argocd app get payment-api
```

- 상태가 `Synced`이고 `Healthy`인지 확인한다.
- 실패하면 즉시 3-3(에스컬레이션)으로 이동한다.

---

## 3. 롤백 후 검증

### 3-1. 헬스체크

```sh
curl -s -o /dev/null -w "%{http_code}\n" https://<운영_호스트>/healthz
```

- 기대 결과: **200**
- 200이 아니면 3-3으로 이동한다.

### 3-2. 결제 테스트 주문 1건

- 운영 테스트 절차에 따라 결제 테스트 주문을 **1건** 진행한다. (절차: `<테스트_주문_절차_링크>`)
- 기대 결과: **주문 성공**
- 실패하면 3-3으로 이동한다.

### 3-3. 실패 시 에스컬레이션

- 헬스체크 또는 테스트 주문이 실패하면 롤백 상태를 그대로 두고 담당 온콜 및 팀 리드에게 알린다.
- 원인 파악 전에 추가 배포나 추가 롤백을 하지 않는다.

---

## 4. 이력 기록 (#deploy 채널)

모든 롤백 시도(중단 포함)를 아래 형식으로 남긴다.

```
[payment-api 롤백] <완료 | 중단 | 실패>
- 시각: YYYY-MM-DD HH:MM
- 수행자: <이름>
- 현재 리비전: <ID / 커밋 SHA>
- 롤백 대상 REVISION: <ID / 커밋 SHA>
- 마이그레이션 포함 여부: <포함 / 미포함>
- 헬스체크(/healthz): <200 / 기타>
- 테스트 주문 1건: <성공 / 실패>
- 비고: <중단 사유, DBA 연락 여부 등>
```

- 마이그레이션 포함으로 **중단한 경우**에도 반드시 기록하고, 박지은(DBA) 연락 사실을 비고에 적는다.
