Redis를 도입하면 서버 4대가 같은 캐시를 함께 보므로, 서버마다 가격이 다르게 보이는 문제가 없어집니다.

로컬 캐시는 각 서버의 메모리(프로그램이 실행 중에 데이터를 잠시 담아 두는 공간)에 상품 목록을 저장합니다. 그래서 서버가 4대면 상품 목록 사본도 4개가 있고, 각 서버는 5분이 지나야 자기 사본을 새로 받습니다.

Redis는 캐시 전용 서버입니다. 서버 4대가 이 한 대에서 상품 목록을 가져오므로, 사본은 하나만 있습니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 각각의 메모리 | 캐시 서버 1대 |
| 서버 4대의 값 | 서버마다 달라질 수 있습니다 | 항상 같습니다 |
| 가격 변경 반영 | 최대 5분 늦게 반영됩니다 | 변경 시 Redis 값을 갱신하면 바로 반영됩니다 |
| 응답 속도 | 서버 안에서 읽어 가장 빠릅니다 | 네트워크를 거치므로 로컬보다 조금 느립니다 |
| 캐시 서버 장애 | 각 서버가 독립적으로 동작합니다 | Redis가 멈추면 대비책이 필요합니다 |

가격 변경을 바로 반영하려면 가격을 바꿀 때 Redis에 저장된 해당 상품의 값을 지우거나 새 가격으로 바꾸는 코드(프로그램 명령문)를 넣어야 합니다. 확인 필요: 가격 변경 기능이 이 갱신 코드를 호출하도록 설계되는지는 이 글에서 알 수 없으므로 개발팀에 확인이 필요합니다.

정리하면, Redis는 4대 서버의 캐시를 한곳에 모아 서버 간 값 차이를 없애고, 갱신 코드를 넣는 경우 가격 반영 지연을 5분에서 줄일 수 있는 구조입니다.
