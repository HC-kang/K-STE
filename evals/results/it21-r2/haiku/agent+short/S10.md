가장 유력한 원인은 2.0.0에서 추가된 `exports` 필드(패키지가 바깥에 공개하는 경로 목록)입니다. 2.0.0의 `exports`에 `./button` 경로가 없거나 경로가 바뀌어서 `@company/ui/button`을 찾지 못하는 것으로 보입니다(추론). 말씀해 주신 정보만으로 세운 추론이므로, 패키지 코드와 CI 로그는 확인하지 않았습니다.

## 사실과 추론

말씀해 주신 사실은 다음과 같습니다.

- `@company/ui`를 3일 전에 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가되었습니다.
- CI는 Node 18, 로컬은 Node 20을 사용합니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 업그레이드 3일 전에 설치되었습니다.

## 원인 분석

Node는 `exports` 필드가 있으면 그 목록에 있는 경로만 가져오게 합니다. 이는 Node의 표준 동작입니다. 그래서 1.4.0에서 되던 `@company/ui/button`이 2.0.0에서 막힐 수 있습니다.

로컬 빌드가 성공하는 이유는 로컬에 1.4.0이 남아 있기 때문으로 보입니다(추론). 말씀해 주신 대로라면 로컬 `node_modules`는 업그레이드 전에 설치되었으므로, 로컬에서는 2.0.0으로 빌드된 적이 없습니다.

에러 문구의 형식은 Node 방식에 가깝습니다. Next.js의 번들러 webpack은 보통 `Module not found`라는 문구를 냅니다(추론). 따라서 에러가 Node가 직접 실행하는 단계(예: `next.config.js` 로드, 테스트 러너, 스크립트)에서 났을 수 있습니다. 확인 필요: 전체 스택 트레이스에서 에러가 발생한 파일.

Node 18과 20은 모두 `exports`를 지원합니다. 따라서 Node 버전 차이만으로 이 에러를 설명하기는 어렵습니다(추론).

CI 캐시 키가 lock 파일 해시이므로, lock 파일이 2.0.0으로 바뀌었다면 캐시가 새로 만들어지는 것이 맞습니다. 다만 캐시를 `restore-keys`로 이전 캐시에서 복원하거나, 캐시 키에 Node 버전이 없으면 이전 설치 결과가 섞일 수 있습니다. 확인 필요: 워크플로 파일의 캐시 설정과 CI 로그의 `@company/ui` 설치 버전.

## 가설 비교

| 가설 | 맞는 점 | 확인 방법 |
|---|---|---|
| 2.0.0의 `exports`에 `./button` 경로가 없거나 바뀌었습니다 | 업그레이드 시점과 실패 시점이 맞습니다 | `cat node_modules/@company/ui/package.json`으로 `exports` 확인 |
| 로컬 `node_modules`에 1.4.0이 남아 있습니다 | 로컬에서만 통과하는 이유를 설명합니다 | 로컬에서 `npm ls @company/ui` 실행 |
| CI 캐시에 이전 설치 결과가 남아 있습니다 | CI에서만 실패하는 이유를 설명합니다 | CI 로그에서 설치 버전과 캐시 복원 기록 확인 |
| Node 18과 20의 차이입니다 | CI와 로컬의 Node 버전이 다릅니다 | 로컬에서 Node 18로 `npm ci` 후 빌드 |

## 해결 방법

1. 로컬에서 먼저 재현해 주세요. `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드합니다. 로컬에서도 실패하면 원인은 2.0.0 쪽에 있습니다.
2. 2.0.0의 README나 변경 로그에서 `button` 경로가 바뀌었는지 확인해 주세요.
3. 경로가 바뀌었다면 import 경로를 새 경로로 고치는 것을 권장합니다.
4. 새 경로가 없고 `button` 경로를 계속 써야 한다면, `@company/ui` 패키지 담당자에게 `exports`에 `./button` 항목을 추가해 달라고 요청해야 합니다.
5. 당장 빌드를 살려야 하면 `@company/ui`를 1.4.0으로 되돌릴 수 있습니다(롤백). 이 경우 2.0.0의 다른 변경은 받지 못합니다.
6. 재발을 막으려면 CI에서 설치 뒤 `npm ls @company/ui`를 실행해 설치된 버전을 로그에 남기는 것을 권장합니다.

## 확인 필요

- 확인 필요: 2.0.0 변경 로그에 `button` 경로 변경이 적혀 있는지.
- 확인 필요: CI 워크플로의 캐시 설정(`restore-keys` 포함).
- 확인 필요: CI 로그에 찍힌 `@company/ui` 설치 버전과 에러가 난 파일.
