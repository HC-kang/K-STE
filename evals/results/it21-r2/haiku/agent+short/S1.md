Redis(여러 서버가 함께 쓰는 임시 저장소 프로그램)를 도입해도 가격 반영 지연이 자동으로 줄지는 않습니다. 지연 시간은 캐시(자주 쓰는 데이터를 빨리 꺼내려고 잠시 저장해 두는 곳)의 유효 기간과 캐시를 갱신하는 방식으로 정해지기 때문입니다.

지금은 각 서버가 자기 메모리(서버가 작업할 때 쓰는 임시 공간)에 상품 목록을 5분 동안 저장해 둡니다. 그래서 서버마다 저장된 내용이 달라지고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 서버 4대가 함께 쓰는 캐시 1대를 따로 두는 방식입니다. 서버 4대가 같은 캐시를 보기 때문에 서버마다 내용이 달라지는 문제는 줄어듭니다.

| 구분 | 현재 로컬 캐시 | Redis 도입 후 |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리 | 공용 캐시 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있습니다 | 4대가 같은 데이터를 봅니다 |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영됩니다 | 설계에 따라 달라집니다 |

Redis 도입으로 확실히 좋아지는 점은 서버 4대가 같은 상품 정보를 보게 되는 것입니다. 다만 Redis에서도 유효 기간을 5분으로 두면 가격 반영 지연은 최대 5분으로 그대로 남습니다. 또한 Redis 서버 1대가 멈추면 이 캐시를 쓰는 서버 4대가 함께 영향을 받을 수 있습니다.

확인 필요: 이번 도입 설계에서 가격을 바꿀 때 캐시를 바로 지우는지, 유효 기간을 몇 분으로 두는지 확인이 필요합니다. 이 두 가지에 따라 고객에게 가격이 바로 반영되는지가 결정됩니다.
