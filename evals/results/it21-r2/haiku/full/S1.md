Redis를 도입하면 4대 서버가 같은 캐시를 보게 되므로, 서버마다 상품 정보가 다른 문제는 없어집니다. 다만 가격을 바꾼 뒤 고객 화면에 새 가격이 나타나는 시점이 지금보다 빨라지는지는 캐시 저장 기간과 캐시를 지우는 방식에 따라 달라서, 아직 확정할 수 없습니다.

차이를 정리하면 다음과 같습니다. 로컬 캐시는 각 서버 안에 자료를 임시로 저장해 두는 방식(캐시)이고, 지금 구조가 여기에 해당합니다. 서버마다 따로 저장하므로 저장된 내용이 서로 다를 수 있고, 가격을 바꾸면 각 서버의 저장 기간인 5분이 지나야 고객에게 바뀐 가격이 보입니다. Redis는 여러 서버가 함께 쓰는 별도의 캐시 서버입니다. 4대가 같은 곳을 조회하므로 서버 사이에 내용이 어긋나지 않습니다. 대신 서버가 매번 Redis에 요청을 보내야 해서 서버 안 메모리를 읽는 것보다 조금 느릴 수 있고, Redis 서버 한 대가 멈추면 4대 모두 영향을 받습니다.

가격 변경을 바로 고객에게 보이게 하려면 Redis 저장 기간을 줄이는 것만으로는 부족하고, 가격을 바꿀 때 해당 캐시를 지우는 절차가 함께 있어야 한다고 봅니다. 도입 범위에 이 절차를 넣을지 먼저 정해야 합니다.
