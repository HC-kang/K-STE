# payment-api 운영 배포 롤백 런북

이 문서는 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 되돌리는 절차다. 롤백 전에 대상 배포에 DB 마이그레이션이 포함되었는지 반드시 확인해야 한다. 마이그레이션이 포함되었으면 롤백하면 안 되며, DBA 박지은에게 연락해야 한다. 롤백 후에는 `/healthz` 응답 코드와 결제 테스트 주문 결과를 확인해야 하며, 롤백 이력은 #deploy 채널에 남겨야 한다.

## 1. 사전 확인

1. 롤백 대상 배포에 DB 마이그레이션이 포함되었는지 확인해야 한다.
2. 마이그레이션이 포함되었으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 다음 단계로 진행한다.

## 2. 롤백 실행

4. 다음 명령으로 롤백한다. `<REVISION>`에는 롤백할 리비전 값을 넣는다.

   `argocd app rollback payment-api <REVISION>`

## 3. 롤백 후 확인

5. `/healthz` 응답 코드가 200인지 확인해야 한다.
6. 결제 테스트 주문 1건이 성공하는지 확인해야 한다.

## 4. 이력 기록

7. 롤백 이력을 #deploy 채널에 남겨야 한다.

## 확인 필요

- 확인 필요: 롤백 이력. 기록에 담을 항목이 원문에 지정되지 않았다.
- 확인 필요: 5번 또는 6번이 실패했을 때의 대응. 원문에 지정되지 않았다.
