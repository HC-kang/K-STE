Redis를 도입하면 API 서버 4대가 같은 상품 목록을 보게 됩니다. 그래서 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 임시로 저장해 두고 빠르게 꺼내 쓰는 방식입니다. 저장 위치에 따라 로컬 캐시와 Redis 캐시로 나뉩니다.

| 구분 | 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | API 서버 각자의 메모리입니다. | 서버 4대가 같이 쓰는 캐시 서버 1대입니다. |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 4대가 같은 내용을 읽습니다. |

지금은 로컬 캐시를 씁니다. 서버 4대가 상품 목록을 각자 5분 동안 캐시하고, 서버마다 캐시 내용이 다릅니다. 그래서 가격을 바꾸면 고객 화면의 가격이 최대 5분 늦게 바뀝니다.

확인 필요: Redis를 도입하면 가격 변경이 고객 화면에 바로 보이는지는 알 수 없습니다. 가격을 바꿀 때 Redis의 캐시를 어떻게 갱신할지 정해야 답할 수 있습니다.
