CI 빌드 실패의 원인은 `@company/ui` 2.0.0의 `exports` 필드로 보입니다. 로컬 빌드는 2.0.0이 아닌 이전 버전으로 돌고 있을 가능성이 큽니다. 아래 원인은 모두 추론이고, 아직 확인한 것은 없습니다.

## 추론한 원인

`exports` 필드(패키지가 외부에서 import할 수 있는 경로를 정하는 `package.json` 설정)가 있으면 Node는 그 목록에 없는 경로를 막습니다. 2.0.0의 `exports`에 `./button`이 없다면 `@company/ui/button`을 import할 때 `Cannot find module` 오류가 납니다. 1.4.0에는 `exports`가 없었으므로 같은 import가 성공했습니다.

CI는 `package-lock.json`(설치할 정확한 버전을 기록한 파일)에 적힌 2.0.0을 설치하므로 오류가 납니다. 3일 전에 버전을 올리면서 lock 파일이 바뀌었고, 캐시 키가 lock 파일의 해시이므로 캐시도 새로 만들어졌을 것입니다.

로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다. 그래서 로컬에는 1.4.0이 남아 있을 가능성이 큽니다. 로컬 빌드가 성공하는 이유도 이것으로 설명됩니다.

## Node 버전의 영향

Node 18과 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 이 오류의 원인일 가능성이 낮습니다. 다만 Node 버전이 원인이 아니라는 것도 확인하지 않았습니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오. 1.4.0이면 위 추론이 맞습니다.
2. `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 로컬에서 빌드하십시오. 이때 CI와 같은 Node 18을 쓰는 것을 권장합니다. 로컬에서도 같은 오류가 나면 원인이 확정됩니다.
3. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 확인하십시오.

## 해결 방향

3번에서 `./button`이 없으면 두 가지 방법이 있습니다. `@company/ui` 쪽에서 `exports`에 `./button`을 추가하거나, 앱의 import 경로를 2.0.0의 `exports`에 있는 경로로 바꿔야 합니다. 어느 쪽이 맞는지는 2.0.0의 의도된 변경 내용을 알아야 하므로 `@company/ui` 담당자에게 확인이 필요합니다.
