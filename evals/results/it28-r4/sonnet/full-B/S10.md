로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰고 있을 것으로 보이며, CI가 쓰는 2.0.0의 `exports` 필드(패키지가 외부에 공개할 파일 경로를 제한하는 설정)에 `./button` 경로가 없어서 실패한 것으로 추정합니다.

로컬 `node_modules`(설치된 패키지 폴더)는 3일 전 업그레이드보다 먼저 설치한 것이므로 1.4.0일 것으로 보입니다. CI(코드가 올라올 때마다 빌드를 자동으로 돌리는 서버)는 `package-lock.json`의 해시(파일 내용에서 계산한 고유 문자열)를 캐시 키로 씁니다. 업그레이드로 `package-lock.json`이 바뀌었다면 CI는 캐시를 새로 만들고 2.0.0을 설치합니다.

2.0.0에는 `exports` 필드가 추가됐습니다. `exports`가 있으면 Node는 그 필드에 적힌 경로만 불러오게 하므로, `./button`이 없으면 `Cannot find module '@company/ui/button'`이 납니다. 1.4.0에는 `exports`가 없었기 때문에 같은 import가 로컬에서는 성공했을 것으로 보입니다.

Node 18과 20은 둘 다 `exports`를 지원하므로 Node 버전 차이가 원인일 가능성은 낮아 보입니다.

이 설명은 추정이므로 아래 순서로 검증하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
2. CI 로그에서 설치된 `@company/ui` 버전이 2.0.0인지 보십시오.
3. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
4. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 같은 에러가 나면 버전 차이가 원인이라는 추정이 뒷받침됩니다.

3번에서 `./button`이 없다면 `@company/ui` 쪽에서 경로를 추가하거나, 앱의 import 경로를 2.0.0이 공개한 경로로 바꿔야 합니다.
