Redis를 도입하면 4대 서버가 같은 캐시 값을 보게 되므로, 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 가격을 바꾼 뒤 고객 화면에 보이기까지 걸리는 시간은 Redis를 쓴다는 사실만으로는 정해지지 않습니다.

캐시는 자주 조회하는 데이터를 가까운 곳에 복사해 두는 임시 보관 장소입니다. 지금은 각 API 서버 안의 메모리(컴퓨터가 작업 중인 자료를 올려 두는 공간)에 상품 목록을 따로 보관하는 로컬 캐시를 씁니다. Redis는 서버 바깥에 따로 두고 4대 서버가 함께 쓰는 캐시 서버입니다.

| 항목 | 지금 방식 (로컬 캐시) | Redis 도입 후 |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리 | 별도 캐시 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있음 | 4대가 같은 값을 봄 |
| 조회 속도 | 서버 안에서 바로 읽음 | 서버 밖으로 요청을 보내므로 메모리 조회보다 느림 |
| 가격 변경 후 고객에게 보이는 시간 | 최대 5분 | 확인 필요 (아래 참고) |

확인 필요: 가격을 바꿀 때 Redis의 값을 바로 갱신하는지, 아니면 5분 유효 시간이 그대로 남는지. 바로 갱신하면 가격 변경이 고객에게 바로 보이고, 5분 유효 시간이 남으면 최대 5분 늦게 보입니다.
