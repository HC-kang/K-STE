# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 DB 마이그레이션 포함 여부를 확인해야 하며, 포함됐으면 롤백하면 안 되고 DBA 박지은에게 연락해야 한다. 롤백 후에는 `/healthz`와 결제 테스트 주문으로 상태를 검증하고, 롤백 이력을 #deploy 채널에 남겨야 한다.

## 절차

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
2. 마이그레이션이 포함됐으면 DBA 박지은에게 연락해야 한다. 이 경우 롤백하면 안 된다.
3. 마이그레이션이 포함되지 않은 것을 확인한 경우에만 `argocd app rollback payment-api <REVISION>` 명령으로 롤백해야 한다.
4. 롤백 후 `/healthz`가 HTTP 200을 반환하는지 확인해야 한다.
5. 롤백 후 결제 테스트 주문 1건을 실행해 주문이 성공하는지 확인해야 한다.
6. 롤백 이력을 #deploy 채널에 남겨야 한다.

## 확인 필요

- 확인 필요: `<REVISION>`에 넣을 값. 되돌릴 리비전 번호를 얻는 방법이 주어진 사실에 없다.
- 확인 필요: 마이그레이션 포함 여부. 이를 확인하는 방법과 기준이 주어진 사실에 없다.
- 확인 필요: 4번 또는 5번이 실패했을 때의 조치. 주어진 사실에 없다.
