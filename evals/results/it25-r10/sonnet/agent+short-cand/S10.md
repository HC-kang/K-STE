원인은 로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있고, CI는 2.0.0을 설치하기 때문일 가능성이 가장 높습니다. 아래 내용은 추론이고, 아직 재현해서 검증하지 않았습니다.

사실로 확인된 것은 다음과 같습니다. 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다. 2.0.0부터 패키지에 `exports` 필드(패키지가 외부에 공개하는 import 경로의 목록)가 생겼습니다. 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.

추론은 다음과 같습니다.

- 로컬은 업그레이드 전에 설치했으므로 1.4.0이 그대로 있을 것으로 보입니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`을 파일 경로로 바로 찾을 수 있습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드 때 `package-lock.json`이 바뀌어 커밋됐다면 캐시 키도 바뀌었으므로, CI는 2.0.0을 새로 설치했을 것입니다.
- 패키지에 `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 경로가 다르면 `Cannot find module '@company/ui/button'`이 나옵니다.
- Node 18과 20은 모두 `exports`를 지원하므로, Node 버전 차이는 원인일 가능성이 낮다고 봅니다.

| 항목 | 로컬 | CI |
|---|---|---|
| `@company/ui` 버전 | 1.4.0으로 추정 | 2.0.0으로 추정 |
| `exports` 필드 | 없음 | 있음 |
| Node | 20 | 18 |

원인을 확정하려면 다음 순서로 실행하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 같은 에러가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인하십시오.

원인이 확정되면 수정 방향은 두 가지입니다. 앱의 import 경로를 `exports`가 공개하는 경로로 바꾸거나, `@company/ui` 쪽 `exports`에 `./button`을 추가해야 합니다. 어느 쪽이 맞는지는 2.0.0이 `./button`을 일부러 공개하지 않았는지에 달려 있으므로, `@company/ui` 담당자에게 확인해야 합니다.
