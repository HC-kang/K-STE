# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정리한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다. 마이그레이션이 포함됐으면 롤백하지 않고 DBA 박지은에게 연락한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 정상 동작을 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 롤백 절차

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. **경고: 마이그레이션이 포함됐으면 롤백하지 않는다. DBA 박지은에게 연락하고, 이 런북의 나머지 단계를 진행하지 않는다.**
3. 마이그레이션이 포함되지 않았으면 롤백할 리비전 값을 `<REVISION>`에 넣는다.
4. 다음 명령을 실행하여 롤백한다.

   `argocd app rollback payment-api <REVISION>`

5. `/healthz`를 호출하여 응답이 200인지 확인한다.
6. 결제 테스트 주문을 1건 실행하여 주문이 성공하는지 확인한다.
7. 롤백 이력을 #deploy 채널에 남긴다.

## 확인 필요

- 확인 필요: 마이그레이션 포함 여부를 확인하는 방법. 원문에 확인 방법이 지정되지 않았다.
- 확인 필요: `/healthz`가 200을 반환하지 않을 때의 조치. 원문에 지정된 조치가 없다.
- 확인 필요: 결제 테스트 주문을 실행하는 방법과 #deploy 채널에 남길 기록의 양식. 원문에 지정되지 않았다.
