로컬 캐시는 각 API 서버가 자기 메모리(서버가 작업할 때 바로 읽는 임시 공간)에 데이터를 저장하는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도의 캐시 서버 1대에 데이터를 저장하는 방식입니다. 캐시는 자주 쓰는 데이터를 미리 저장해 두고 꺼내 쓰는 것을 말합니다.

Redis를 도입하면 4대 서버가 같은 상품 목록을 보므로 서버마다 캐시 내용이 달라지는 문제는 없어집니다. 다만 Redis 도입만으로 가격 변경이 즉시 반영되지는 않습니다. 가격이 바뀌었을 때 Redis에 저장된 옛 상품 정보를 지우는 작업이 따로 있어야 고객에게 바로 반영됩니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버 안 | 공용 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 조회 속도 | 가장 빠름 | 네트워크를 거쳐 조회하므로 약간 느림 |
| 가격 변경 반영 | 서버마다 최대 5분 늦음 | 캐시를 지우는 방식에 따라 달라짐 |
| 캐시 서버 장애 시 | 서버 각각 독립적으로 동작 | 캐시 서버가 멈추면 4대 모두 영향을 받음 |

정리하면, Redis를 도입하면 4대 서버의 가격 정보가 일치하고, 가격 변경을 반영하는 시점을 우리가 직접 관리할 수 있습니다. 반영 시점을 짧게 하려면 가격 변경 시 캐시를 지우는 작업을 구현해야 합니다.
