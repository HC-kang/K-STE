이 런북은 ArgoCD로 배포한 payment-api를 이전 리비전(revision, 배포 버전 식별 값)으로 되돌리는 절차다. 아래 중지 조건을 먼저 확인하고, 그 다음 절차를 순서대로 수행한다.

## 중지 조건

**롤백 전에 해당 배포에 DB 마이그레이션(데이터베이스 구조 변경 작업)이 포함됐는지 반드시 확인한다. 마이그레이션이 포함됐으면 롤백하지 않는다. DBA(데이터베이스 관리자) 박지은에게 연락한다.**

## 절차

1. 해당 배포에 DB 마이그레이션이 포함됐는지 확인한다. 확인 방법은 확인 필요: 원문에 정해진 방법이 없다.
2. 마이그레이션이 포함됐으면 롤백을 중단하고 DBA 박지은에게 연락한다.
3. 마이그레이션이 포함되지 않았으면 다음 명령으로 롤백한다. `<REVISION>`에는 롤백할 리비전 값을 넣는다.

   `argocd app rollback payment-api <REVISION>`

4. 롤백 후 `/healthz`가 200을 반환하는지 확인한다. 확인 대상 주소는 확인 필요: 원문에 기준 주소가 없다.
5. 결제 테스트 주문 1건이 성공하는지 확인한다. 테스트 주문 방법은 확인 필요: 원문에 절차가 없다.
6. #deploy 채널에 롤백 이력을 남긴다. 기록 형식은 확인 필요: 원문에 정해진 양식이 없다.

## 확인 필요 항목

운영자가 실행 전에 다음 항목을 채워야 한다.

- 롤백할 리비전 값을 찾는 방법을 정해야 한다.
- 마이그레이션 포함 여부를 확인하는 방법과 담당자를 정해야 한다.
- `/healthz` 확인 주소와 결제 테스트 주문 절차를 정해야 한다.
- #deploy 채널에 남길 이력의 기록 형식을 정해야 한다.
