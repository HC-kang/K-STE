원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰고 있기 때문일 가능성이 가장 높습니다. 아래 내용 중 원인 부분은 아직 확인하지 않은 추론입니다.

확인된 사실은 다음과 같습니다.
- `@company/ui` 2.0.0부터 패키지에 `exports` 필드(패키지가 외부에 공개하는 import 경로를 지정하는 package.json 설정)가 있습니다. `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다.
- 로컬 `node_modules`(설치된 패키지가 저장되는 폴더)는 3일 전 업그레이드보다 먼저 설치했습니다.
- CI(빌드와 검사를 자동으로 실행하는 환경)의 캐시 키는 `package-lock.json`의 해시입니다.

추론은 다음과 같습니다. 업그레이드로 `package-lock.json`이 바뀌었다면 CI 캐시가 무효화되어 CI는 2.0.0을 새로 설치합니다. 로컬은 `node_modules`를 다시 설치하지 않았다면 1.4.0이 남아 있어서 `exports` 제한이 없고, 그래서 빌드가 통과합니다. 2.0.0의 `exports`에 `./button`이 없거나 이름이 바뀌었다면 CI에서만 `Cannot find module '@company/ui/button'`이 나는 현상이 설명됩니다.

Node 18과 20은 모두 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 원인일 가능성이 낮다고 봅니다.

다음 순서로 확인하십시오.
1. `node_modules/@company/ui/package.json`을 열어 `version`과 `exports`에 `./button`이 있는지 확인하십시오.
2. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 확인하십시오.
3. 1번에서 버전이 1.4.0이면 `node_modules`를 지우고 `npm ci`를 실행한 뒤 빌드하십시오. 같은 에러가 로컬에서 나면 원인이 확정됩니다.

2.0.0의 `exports`에 `./button`이 없는 것으로 확인되면, 앱의 import 경로를 바꿀지 `@company/ui` 쪽에 export를 추가할지 정해야 합니다.
