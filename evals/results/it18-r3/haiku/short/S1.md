Redis를 도입하면 서버 4대가 같은 캐시를 보게 되어, 서버마다 상품 목록이 달라지는 문제가 없어집니다. 다만 캐시 유효 시간(캐시 데이터를 다시 가져오기 전까지 쓰는 기간)을 5분으로 그대로 두면, 가격은 여전히 최대 5분 늦게 반영됩니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두고 꺼내 쓰는 임시 저장소입니다. 지금 방식과 Redis 방식의 차이는 다음과 같습니다.

| 구분 | 로컬 캐시 (각 서버 안의 메모리에 저장) | Redis 캐시 (서버 밖의 별도 캐시 서버에 저장) |
|---|---|---|
| 저장 위치 | 서버 4대가 각자 가집니다. | 캐시 서버 1대에 모입니다. |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 4대가 같은 내용을 봅니다. |
| 읽는 속도 | 로컬 메모리라서 가장 빠릅니다. | 네트워크를 거쳐야 해서 로컬보다 느립니다. |
| 장애 영향 | 서버 1대에만 영향을 줍니다. | 캐시 서버에 문제가 생기면 4대가 함께 영향을 받을 수 있습니다. |

확인 필요: Redis 캐시의 유효 시간을 5분으로 유지할지, 가격을 바꿀 때 캐시를 바로 지울지 확인해야 합니다.
