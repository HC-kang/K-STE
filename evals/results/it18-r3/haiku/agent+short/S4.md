# 운영 배포 롤백 런북

이 런북은 ArgoCD로 `payment-api`의 운영 배포를 이전 리비전으로 롤백하는 절차를 정리한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 마이그레이션이 포함된 배포는 롤백하면 안 된다.

## 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법이 원문에 없다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았을 때만 다음 단계로 넘어가야 한다.

## 롤백 실행

4. 롤백할 리비전 번호(`<REVISION>`)를 정해야 한다. 확인 필요: 리비전 번호를 찾는 방법이 원문에 없다.
5. 다음 명령을 실행해야 한다.

```
argocd app rollback payment-api <REVISION>
```

## 롤백 후 확인

6. `/healthz`가 200을 반환하는지 확인해야 한다. 확인 필요: `/healthz`를 호출할 대상 주소가 원문에 없다.
7. 결제 테스트 주문 1건이 성공하는지 확인해야 한다. 확인 필요: 테스트 주문을 넣는 방법이 원문에 없다.

## 이력 기록

8. 롤백 이력을 #deploy 채널에 남겨야 한다.
