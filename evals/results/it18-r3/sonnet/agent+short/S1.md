서버 4대가 같은 캐시를 보게 되어, 서버마다 상품 목록이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 빨리 꺼내려고 미리 저장해 둔 사본입니다. 로컬 캐시와 Redis 캐시는 이 사본을 어디에 두느냐가 다릅니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대가 각자 자기 메모리에 저장합니다. | 서버 4대가 같이 쓰는 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 저장한 시점이 달라서 내용이 다를 수 있습니다. | 4대가 같은 사본을 읽습니다. |
| 가격 변경 시 | 서버마다 자기 캐시가 만료될 때까지 기다려야 해서, 고객에게 최대 5분 늦게 반영됩니다. | 사본이 한 곳에 있어서 그 사본만 갱신하면 4대가 모두 새 가격을 읽습니다. |

가격 반영 지연이 실제로 얼마나 줄지는 가격을 바꿀 때 Redis의 사본을 어떻게 갱신하도록 만드느냐에 따라 달라집니다. 이 부분은 개발팀과 정해야 합니다.
