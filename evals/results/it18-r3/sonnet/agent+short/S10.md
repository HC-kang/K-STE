로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있고, CI는 2.0.0을 설치하기 때문으로 보입니다. 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 경로를 제한하는 설정)에 `./button` 경로가 없을 가능성이 가장 높습니다. 아직 확인하지 않은 추론입니다.

근거는 다음과 같습니다.

- 1.4.0에는 `exports` 필드가 없습니다. 그래서 `@company/ui/button`은 패키지 안의 파일 경로로 바로 찾아집니다.
- 2.0.0부터는 `exports`에 적힌 경로만 import할 수 있습니다. 목록에 `./button`이 없으면 파일이 있어도 `Cannot find module '@company/ui/button'` 오류가 납니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것입니다. 그래서 로컬 빌드는 1.4.0으로 성공했을 것으로 보입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드 때 lock 파일이 바뀌었다면 캐시도 갱신되므로, 캐시는 원인일 가능성이 낮습니다.
- Node 18과 20은 둘 다 `exports` 필드를 지원합니다. Node 버전 차이는 원인일 가능성이 낮습니다.

다음 순서로 추론을 검증하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
2. 로컬에서 `rm -rf node_modules && npm ci`로 2.0.0을 새로 설치한 뒤 빌드하십시오. 같은 오류가 나면 원인이 맞습니다.
3. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button`이 있는지 보십시오.

원인이 맞다면 두 가지 방법이 있습니다. 코드의 import 경로를 2.0.0의 `exports`에 있는 경로로 바꾸는 방법과, `@company/ui` 담당자에게 `./button` 공개 여부를 묻는 방법입니다.

확인 필요: 2.0.0의 `exports`에 `./button`이 있는지 아직 모릅니다. 있는데도 CI가 실패한다면 원인은 다른 곳에 있으므로 CI 로그에서 설치된 `@company/ui` 버전부터 보십시오.
