가장 유력한 원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰는 것입니다. 로컬은 1.4.0으로 보이고 CI는 2.0.0을 설치합니다. 2.0.0의 `exports` 필드에 `./button` 경로가 없어서 CI에서 모듈을 찾지 못하는 것으로 보입니다.

## 확인된 사실

- CI에서만 빌드가 실패하고, 로컬 빌드는 성공합니다.
- 에러는 `Cannot find module '@company/ui/button'`입니다.
- `@company/ui`를 3일 전에 1.4.0에서 2.0.0으로 올렸고, 2.0.0에는 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20입니다.

## 추론

- 로컬 `node_modules`가 업그레이드 전에 설치됐으므로, 로컬에는 아직 1.4.0이 있을 가능성이 큽니다.
- 버전을 올리면 `package-lock.json`이 바뀌므로 캐시 키도 바뀝니다. 그래서 CI는 캐시 없이 새로 설치했고 2.0.0을 받았을 것입니다.
- 패키지에 `exports` 필드가 생기면, 그 필드에 적힌 경로만 외부에서 import할 수 있습니다. 1.4.0에서는 `@company/ui/button`이 파일 경로로 바로 열렸지만, 2.0.0에서는 `exports`에 `./button`이 없으면 열리지 않습니다.
- Node 18과 20은 둘 다 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 주된 원인일 가능성이 낮습니다.

## 확인 필요

- 로컬에 실제로 설치된 `@company/ui` 버전이 1.4.0인지 확인해야 합니다.
- `package-lock.json`에 2.0.0이 기록돼 있는지 확인해야 합니다.
- 2.0.0의 `exports` 필드에 `./button`이 있는지, 있다면 어떤 경로로 연결되는지 확인해야 합니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. 로컬에서 `node_modules`를 지우고 `npm ci`를 실행한 뒤 빌드합니다. Node 18에서도 같은 방법으로 빌드합니다.
3. `node_modules/@company/ui/package.json`의 `exports` 필드에서 `./button` 항목을 찾습니다.

2번에서 로컬 빌드도 실패하면 원인은 버전 차이로 확정됩니다. 3번에서 `./button`이 없으면 다음 중 하나를 선택해야 합니다.

- `@company/ui` 쪽에서 `exports`에 `./button`을 추가해 다시 배포합니다.
- 앱의 import 경로를 `exports`가 노출하는 경로로 바꿉니다.
- 임시로 `@company/ui`를 1.4.0으로 되돌립니다.

3번에서 `./button`이 있는데도 실패하면, 그때는 Node 18의 해석 방식이나 빌드 설정을 추가로 조사해야 합니다.
