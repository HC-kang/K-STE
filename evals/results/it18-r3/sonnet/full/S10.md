CI(코드를 올릴 때 자동으로 빌드하는 환경, GitHub Actions)에서만 실패하는 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드로 보입니다. 로컬은 2.0.0이 아닌 이전 버전으로 빌드하고 있을 가능성이 높습니다.

`exports`는 패키지가 외부에 공개할 경로를 적은 목록입니다. 이 필드가 있으면 목록에 없는 경로는 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없으면 `@company/ui/button`을 찾지 못해 `Cannot find module` 오류가 납니다. 1.4.0에는 `exports`가 없었으므로 같은 import가 파일 경로로 그대로 풀렸습니다.

근거는 다음과 같습니다.
- 로컬 `node_modules`(설치된 패키지가 저장되는 폴더)는 3일 전 업그레이드보다 먼저 설치했으므로 1.4.0이 남아 있을 것으로 보입니다.
- CI 캐시 키(저장된 설치 결과를 재사용할지 정하는 기준값)가 `package-lock.json`의 해시이므로, 업그레이드로 이 파일이 바뀌었다면 CI는 캐시 없이 2.0.0을 새로 설치했을 것으로 보입니다.
- Node 18도 `exports`를 지원하므로 Node 18과 20의 차이는 원인일 가능성이 낮습니다.

원인이 맞으면 import 경로를 `exports`에 공개된 경로로 바꾸거나, `@company/ui`의 `exports`에 `./button`을 추가해도 됩니다.

먼저 로컬의 `node_modules/@company/ui/package.json`에서 `version`이 1.4.0인지, `exports`에 `./button`이 있는지 보십시오. 그다음 `node_modules`를 지우고 `package-lock.json` 기준으로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 오류가 나면 이 추정이 맞습니다.
