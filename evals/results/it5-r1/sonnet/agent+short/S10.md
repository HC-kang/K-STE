로컬이 아직 `@company/ui` 1.4.0을 쓰고 있어서 로컬만 성공하고 CI만 실패한 것으로 보입니다. 이는 추론이며, 아래 확인 단계로 검증해야 합니다.

## 사실

- CI는 `package-lock.json` 해시를 캐시 키로 쓰므로, 3일 전 버전 변경으로 키가 바뀌었고 CI는 새로 설치했을 것입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것이어서 1.4.0이 남아 있을 가능성이 높습니다.
- 2.0.0부터 패키지에 `exports` 필드(패키지가 외부에 공개하는 import 경로 목록을 정하는 `package.json` 항목)가 있습니다.

## 추론

- `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로로 바로 열렸습니다.
- 2.0.0의 `exports`에 `./button`이 없거나 다른 경로로 바뀌었다면, CI에서 `Cannot find module '@company/ui/button'`이 납니다.
- Node 18과 Node 20은 둘 다 `exports`를 지원합니다. Node 버전 차이는 이 에러의 원인일 가능성이 낮지만, 확인하지 않았습니다.

## 확인 단계

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 봅니다.
2. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 봅니다.
3. 로컬에서 `rm -rf node_modules && npm ci`(lock 파일 그대로 새로 설치하는 명령)를 실행하고 빌드해 CI와 같은 에러가 나는지 봅니다.

## 해결 방향

`exports`에 공개된 경로로 import를 바꾸거나, `@company/ui` 쪽에서 `./button`을 `exports`에 추가해야 합니다. 어느 쪽이 맞는지는 2번 결과로 정합니다.

확인 필요: 2.0.0이 `./button`을 다른 이름으로 옮겼는지, 아예 공개하지 않는지는 이 정보만으로 알 수 없습니다.
