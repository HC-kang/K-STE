가장 유력한 원인은 `@company/ui` 2.0.0의 `exports` 필드가 `./button` 경로를 공개하지 않는 것입니다. 로컬 빌드는 2.0.0을 쓰지 않아서 통과했을 가능성이 높습니다.

근거는 다음과 같습니다.

- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했습니다. 그래서 로컬에는 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없으므로 `@company/ui/button`이 파일 경로 그대로 해석됩니다.
- CI(코드를 올릴 때마다 자동으로 빌드하는 서버)는 `package-lock.json`을 기준으로 설치합니다. 업그레이드 후 lock 파일이 바뀌어 캐시 키도 바뀌었을 테니, CI는 2.0.0을 새로 설치했을 것입니다.
- `exports` 필드(패키지가 외부에 공개할 경로를 지정하는 `package.json` 항목)가 생기면, 거기에 적지 않은 경로는 import할 수 없습니다. 이때 `Cannot find module` 오류가 납니다.

Node 18과 Node 20의 차이는 원인일 가능성이 낮습니다. 두 버전 모두 `exports`를 지원하므로, 같은 패키지 버전이면 같은 방식으로 해석합니다. 다만 이 부분은 직접 확인하지 않았습니다.

아직 확인하지 않은 것은 두 가지입니다. 로컬에 설치된 실제 버전이 1.4.0인지, 2.0.0의 `exports`에 `./button`이 빠져 있는지입니다.

확인 순서는 다음과 같습니다.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인하십시오.
3. `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 로컬에서 빌드하십시오. 같은 오류가 나면 원인이 확정됩니다.

`./button`이 `exports`에 없다면, 2.0.0이 안내하는 새 import 경로로 바꾸거나 패키지 쪽에서 `exports`에 경로를 추가해야 합니다. 어느 쪽을 택할지는 `@company/ui` 2.0.0의 릴리스 노트를 확인한 뒤 정하십시오.
