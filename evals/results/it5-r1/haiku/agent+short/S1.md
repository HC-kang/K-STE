Redis를 도입하면 4대 서버가 같은 캐시를 읽게 되므로, 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 가격이 고객에게 반영되는 시간은 Redis를 도입하는 것만으로 줄지 않으며, 캐시를 언제 갱신할지 따로 정해야 합니다.

지금은 각 API 서버가 상품 목록을 자기 메모리(서버가 작업할 때 쓰는 임시 작업 공간)에 캐시(자주 쓰는 데이터를 빠르게 꺼내 쓰려고 미리 저장해 둔 복사본)로 보관합니다. 그래서 서버마다 저장된 내용이 다를 수 있고, 가격을 바꾸면 각 서버의 캐시가 만료되는 최대 5분 뒤에야 고객에게 반영됩니다.

Redis는 캐시 전용 서버 1대에 데이터를 저장하고, 4대 서버가 이 한 곳을 함께 읽습니다. 이렇게 바뀌면 다음이 좋아집니다.

- 4대 서버가 항상 같은 상품 정보를 보여 줍니다.
- 서버마다 같은 데이터를 따로 저장하지 않으므로 서버 메모리를 아낄 수 있습니다.
- 가격을 바꿀 때 Redis에 저장된 캐시를 지우는 작업을 함께 하면, 4대 서버가 모두 새 가격을 읽습니다. 이 작업을 넣으면 5분 지연을 줄일 수 있습니다.

주의할 점도 있습니다. 일반적으로 Redis 서버가 멈추면 4대 서버 모두 캐시를 쓰지 못하므로, 장애에 대비한 구성이 필요합니다. 또 서버가 매번 Redis에 네트워크로 접속해야 하므로, 서버 메모리에서 바로 꺼내 쓰는 지금 방식보다 조회가 조금 느릴 수 있습니다.
