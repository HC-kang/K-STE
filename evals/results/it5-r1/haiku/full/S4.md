# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다. 마이그레이션이 포함됐으면 롤백하지 않고 DBA 박지은에게 연락한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 정상 동작을 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다.
2. 마이그레이션이 포함됐으면 롤백하지 않는다.
3. 마이그레이션이 포함됐으면 DBA 박지은에게 연락한다.
4. 마이그레이션이 포함되지 않았으면 2단계로 넘어간다.

**경고: 마이그레이션이 포함된 배포는 ArgoCD로 롤백하지 않는다.**

## 2. 롤백 실행

5. 롤백할 리비전 번호를 확인한다.
6. 아래 명령으로 롤백을 실행한다. `<REVISION>`에는 5단계에서 확인한 리비전 번호를 넣는다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 확인

7. `/healthz`가 200을 반환하는지 확인한다.
8. 결제 테스트 주문 1건을 실행하고 주문이 성공하는지 확인한다.

## 4. 이력 기록

9. 롤백 이력을 #deploy 채널에 남긴다.

## 확인되지 않은 항목

- 마이그레이션 포함 여부를 확인하는 방법은 정하지 않았다. 확인 방법을 정한 뒤 1단계에 추가한다.
- `<REVISION>`에 넣을 리비전 번호를 찾는 방법은 정하지 않았다.
- `/healthz`가 200을 반환하지 않을 때의 조치는 정하지 않았다.
- 결제 테스트 주문이 실패할 때의 조치는 정하지 않았다.
- #deploy 채널에 남길 이력의 형식은 정하지 않았다.
