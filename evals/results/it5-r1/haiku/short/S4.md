이 런북은 ArgoCD(배포를 관리하는 도구)로 `payment-api`를 이전 리비전(배포 이력 번호)으로 되돌리는 절차를 정한다.

## 1. 마이그레이션 포함 여부 확인

롤백 전에 되돌릴 배포에 DB 마이그레이션(DB 구조를 바꾸는 변경 작업)이 포함되었는지 반드시 확인한다.

**마이그레이션이 포함되었으면 롤백하지 않는다.** 이 경우 DBA(데이터베이스 관리자) 박지은에게 연락한다.

## 2. 롤백 실행

마이그레이션이 포함되지 않았음을 확인한 경우에만 다음 순서로 진행한다.

1. 롤백할 대상 리비전 번호를 확인한다.
2. 확인한 번호를 `<REVISION>`에 넣어 다음 명령을 실행한다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 확인

롤백이 끝나면 다음 두 가지를 모두 확인한다.

1. `/healthz`가 200을 반환하는지 확인한다.
2. 결제 테스트 주문 1건이 성공하는지 확인한다.

## 4. 이력 기록

롤백 이력은 #deploy 채널에 남긴다.

## 확인 필요

- 확인 필요: 리비전 번호를 확인하는 방법이 주어지지 않았다.
- 확인 필요: 배포에 마이그레이션이 포함되었는지 확인하는 방법이 주어지지 않았다.
- 확인 필요: DBA 박지은에게 연락하는 수단이 주어지지 않았다.
- 확인 필요: `/healthz`를 요청할 주소가 주어지지 않았다.
- 확인 필요: 결제 테스트 주문을 만드는 방법과 담당자가 주어지지 않았다.
- 확인 필요: `/healthz`가 200을 반환하지 않거나 테스트 주문이 실패했을 때의 대응 절차가 주어지지 않았다.
- 확인 필요: #deploy 채널에 남길 기록 항목이 주어지지 않았다.
