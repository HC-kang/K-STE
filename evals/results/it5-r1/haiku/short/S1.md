로컬 캐시와 Redis 캐시의 가장 큰 차이는 캐시를 어디에 두고 누가 같이 쓰느냐입니다. 캐시(자주 찾는 데이터를 빨리 꺼내 쓰려고 따로 저장해 둔 사본)는 지금까지 각 API 서버의 메모리 안에 있었습니다. Redis(레디스, 여러 서버가 함께 쓰는 데이터 저장 전용 서버)는 서버 밖에 따로 둔 캐시이므로 4대의 서버가 같은 캐시를 봅니다.

Redis를 도입하면 두 가지가 좋아집니다. 첫째, 서버마다 캐시 내용이 달라지는 문제가 없어집니다. 둘째, 가격을 바꾸면 모든 서버가 같은 값을 보므로 서버마다 반영 시점이 달라지는 문제가 없어집니다.

다만 고객에게 가격이 반영되기까지의 시간이 줄어드는지는 설정에 따라 달라집니다. 확인 필요: Redis에 저장한 상품 목록도 5분 뒤에 만료되도록 설정하면 최대 5분 지연은 그대로 남습니다. 가격을 바꿀 때 Redis 캐시를 바로 지우는 방식을 함께 적용할지도 확인이 필요합니다.

Redis를 쓰면 부담도 생깁니다. 서버가 자기 메모리에서 바로 꺼내던 데이터를 이제 네트워크를 거쳐 Redis에서 가져오므로 응답이 조금 느려질 수 있습니다. Redis 서버가 멈추면 캐시를 쓸 수 없으므로 Redis 장애에 대비한 대응 계획이 필요합니다.
