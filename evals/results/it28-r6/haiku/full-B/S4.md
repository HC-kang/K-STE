# 운영 배포 롤백 런북: payment-api

이 문서는 ArgoCD로 payment-api 운영 배포를 롤백하는 절차를 설명한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 마이그레이션이 포함된 배포는 롤백하면 안 되며, DBA 박지은에게 연락해야 한다. 롤백 후에는 `/healthz`와 결제 테스트 주문으로 검증하고, 롤백 이력을 #deploy 채널에 남긴다.

## 롤백 절차

**경고:** DB 마이그레이션이 포함된 배포는 롤백하면 안 된다. 아래 1번에서 포함 여부를 확인하기 전에는 롤백 명령을 실행하지 않는다.

1. 롤백하려는 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하지 않는다. DBA 박지은에게 연락한다.
3. 마이그레이션이 포함되지 않았으면 다음 명령으로 롤백한다. `<REVISION>` 자리에 롤백 대상 리비전을 넣는다.
   ```
   argocd app rollback payment-api <REVISION>
   ```
4. 롤백 후 `/healthz`의 응답 코드가 200인지 확인한다.
5. 결제 테스트 주문을 1건 실행하고, 주문이 성공하는지 확인한다.
6. 롤백 이력을 #deploy 채널에 남긴다.

확인 필요: 1번의 마이그레이션 포함 여부를 확인하는 방법. 주어진 사실에 확인 방법이 없다.
