가장 유력한 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드입니다. 로컬 빌드는 2.0.0이 아니라 1.4.0으로 돌고 있을 수 있습니다. 아래 내용은 주어진 정황에서 추론한 것이고, 코드와 설치 상태를 직접 열어 보지는 않았습니다.

## 추론 경위

`exports`는 패키지가 외부에 공개할 import 경로를 선언하는 `package.json` 항목입니다. 이 항목이 있으면 선언하지 않은 경로는 import할 수 없습니다. 1.4.0에는 `exports`가 없었으므로 `@company/ui/button`을 파일 경로로 바로 가져올 수 있었을 것입니다. 2.0.0의 `exports`에 `./button` 항목이 없거나 경로가 다르면 같은 import가 `Cannot find module '@company/ui/button'`으로 실패합니다.

로컬과 CI의 차이는 다음과 같이 추정합니다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `node_modules` | 3일 전보다 먼저 설치해서 1.4.0이 남아 있을 것으로 추정 | 캐시 키가 `package-lock.json` 해시이므로, 버전을 올리며 lock 파일이 바뀌었다면 캐시를 쓰지 않고 2.0.0을 새로 설치했을 것으로 추정 |
| 빌드 결과 | 성공 | 실패 |

Node 18과 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이가 원인일 가능성은 낮습니다.

## 검증 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이 나오면 로컬 성공은 2.0.0을 검증하지 못한 결과입니다.
2. 2.0.0이 설치된 `node_modules/@company/ui/package.json`을 열어 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `node_modules`를 지우고 CI와 같은 설치 명령으로 다시 설치한 뒤 `next build`를 실행하십시오. 이때 같은 오류가 나면 원인이 확정됩니다.

2번에서 `./button`이 없으면 2.0.0의 새 import 경로로 코드를 고치거나, `@company/ui` 담당 팀에 `./button` 추가를 요청해야 합니다. 새 import 경로가 무엇인지는 2.0.0 문서나 `exports` 내용에서 찾아야 합니다.
