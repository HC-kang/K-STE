Redis를 도입하면 서버 4대가 같은 상품 목록을 읽게 됩니다. 그래서 서버마다 가격이 다르게 보이는 문제가 없어집니다.

캐시(자주 읽는 데이터를 빨리 꺼내 쓰려고 잠시 저장해 두는 것)는 저장하는 위치에 따라 두 가지로 나뉩니다. 로컬 캐시는 API 서버 각각이 자기 메모리에 데이터를 따로 저장하는 방식입니다. 지금 우리 서비스가 이 방식으로 서버 4대가 상품 목록을 각자 5분 동안 저장합니다. 그래서 서버마다 저장된 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 함께 쓰는 캐시 서버 1대에 데이터를 저장하는 방식입니다. 4대가 모두 같은 저장소를 읽으므로 고객이 어느 서버에 접속하든 같은 상품 목록을 봅니다.

가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 갱신하도록 만들면 최대 5분 지연도 줄일 수 있습니다. Redis만 도입하고 갱신 방식을 바꾸지 않으면 이 지연이 줄어드는지는 아직 알 수 없습니다.
