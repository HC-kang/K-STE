# 운영 배포 롤백 런북

배포 도구는 ArgoCD다. 이 런북은 `payment-api`를 이전 리비전으로 되돌리는 절차를 다룬다.

## 절차

1. 롤백 전에 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
2. 배포에 DB 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락한다.
3. 배포에 DB 마이그레이션이 포함되지 않았으면 아래 명령을 실행한다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

4. 롤백이 끝나면 `/healthz`가 200을 반환하는지 확인한다.
5. 결제 테스트 주문 1건이 성공하는지 확인한다.
6. 롤백 이력을 #deploy 채널에 남긴다.

## 확인 필요

- 배포에 DB 마이그레이션이 포함됐는지는 어디서 어떻게 확인하는가?
- `<REVISION>` 값은 어디서 찾는가?
- `/healthz`가 200을 반환하지 않거나 결제 테스트 주문이 실패하면 어떻게 하는가?
