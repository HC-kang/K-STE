가장 큰 차이는 캐시를 서버마다 따로 갖느냐, 서버 4대가 하나를 같이 쓰느냐입니다. Redis를 도입하면 서버마다 상품 목록이 달라지는 문제가 없어집니다.

지금은 로컬 캐시를 씁니다. 캐시는 자주 쓰는 데이터를 빠르게 꺼내 쓰려고 임시로 저장해 두는 곳입니다. 로컬 캐시에서는 API 서버 4대가 각자 메모리에 상품 목록을 5분 동안 따로 저장합니다. 서버마다 저장한 시점이 달라서 캐시 내용도 서로 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 캐시 전용 서버 1대에 상품 목록을 한 벌만 저장합니다. API 서버 4대는 모두 이 한 벌을 읽습니다. 그래서 어느 서버가 요청을 받아도 같은 상품 목록이 나갑니다.

가격 반영 지연이 줄어드는지는 아직 알 수 없습니다. Redis를 도입하고도 캐시 보관 시간을 5분으로 두면, 가격 변경이 최대 5분 늦게 반영될 수 있습니다. 가격을 바꿀 때 Redis의 상품 목록을 바로 지우도록 만들면 이 지연을 줄일 수 있습니다.

Redis 서버는 1대이므로, 이 서버가 멈추면 API 서버 4대가 모두 Redis 캐시를 쓰지 못합니다.

확인 필요: 이번 도입에 캐시 보관 시간 변경이나 가격 변경 시 캐시 삭제가 포함되는지, Redis 서버가 멈췄을 때 API 서버가 어떻게 동작하는지.
