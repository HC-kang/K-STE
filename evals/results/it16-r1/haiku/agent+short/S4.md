# 운영 payment-api 배포 롤백 런북

이 런북은 ArgoCD로 배포한 운영 payment-api를 이전 리비전으로 되돌리는 절차를 정리한다. 롤백 전에 대상 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 롤백한 뒤에는 `/healthz` 응답과 결제 테스트 주문 1건으로 결과를 확인한다.

## 1. 롤백 전 확인

**DB 마이그레이션이 포함된 배포는 롤백하면 안 된다.**

1. 롤백하려는 배포에 DB 마이그레이션이 포함됐는지 확인한다. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 위치.
2. 마이그레이션이 포함됐으면 롤백하지 않는다. DBA 박지은에게 연락해야 한다.

## 2. 롤백 실행

1. 마이그레이션이 포함되지 않았다고 확인한 경우에만 다음 명령을 실행한다.
2. `argocd app rollback payment-api <REVISION>` 명령을 실행한다. 확인 필요: `<REVISION>`에 넣을 값과 그 값을 확인하는 방법.

## 3. 롤백 후 확인

1. `/healthz`가 200을 반환하는지 확인한다. 확인 필요: `/healthz`의 전체 주소.
2. 결제 테스트 주문 1건을 실행하고, 그 주문이 성공하는지 확인한다. 확인 필요: 결제 테스트 주문을 실행하는 방법.

## 4. 이력 기록

#deploy 채널에 롤백 이력을 남긴다.
