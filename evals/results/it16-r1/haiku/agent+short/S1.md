로컬 캐시는 서버마다 따로 저장하고, Redis는 서버 4대가 함께 쓰는 공용 캐시입니다. Redis를 도입하면 서버마다 가격이 다르게 보이는 문제는 없어지지만, 가격을 바꾼 뒤 바로 반영하려면 캐시를 지우는 작업이 따로 필요합니다.

캐시는 자주 쓰는 데이터를 매번 원본에서 다시 가져오지 않도록 임시로 저장해 두는 곳입니다. 지금은 각 API 서버(고객 요청을 받아 처리하는 서버)가 자기 메모리(서버가 작업할 때 쓰는 임시 공간)에 상품 목록을 5분 동안 보관합니다.

| 구분 | 현재: 로컬 캐시 | 도입 예정: Redis 캐시 |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리에 저장합니다. | 캐시 서버 1대에 저장합니다. |
| 서버 간 데이터 | 서버마다 다를 수 있습니다. | 4대가 같은 데이터를 봅니다. |
| 조회 속도 | 서버 안에서 바로 꺼냅니다. | 네트워크를 거쳐 요청하므로 조금 느립니다. |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영됩니다. | 캐시를 지우면 4대가 모두 새 가격을 봅니다. |

Redis는 네트워크를 거쳐 요청하므로 로컬 캐시보다 응답이 조금 느립니다. 대신 4대가 같은 데이터를 보므로 고객이 서버에 따라 다른 가격을 보는 일이 없어집니다.

확인 필요: 이번 Redis 도입 계획에 가격을 바꿀 때 Redis의 상품 캐시를 지우는 작업이 포함되어 있는지 개발팀에 확인해야 합니다. 포함되어 있지 않고 캐시 유지 시간이 5분 그대로라면, Redis를 도입해도 가격 반영은 지금처럼 최대 5분 늦을 수 있습니다.
