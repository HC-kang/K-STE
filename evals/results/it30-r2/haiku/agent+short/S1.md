Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되어, 지금처럼 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 상품 목록을 캐시(자주 쓰는 데이터를 임시로 저장해 두고 꺼내 쓰는 곳)에 5분 동안 보관하는 설정을 그대로 두면, 가격을 바꾼 뒤 고객에게 보이기까지 최대 5분이 걸리는 문제는 남습니다.

로컬 캐시와 Redis 캐시의 차이는 아래 표와 같습니다. Redis(레디스, 여러 서버가 함께 쓰는 별도 캐시 서버 프로그램)는 이번에 도입할 방식입니다.

| 구분 | 로컬 캐시 (지금 방식) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 안에 저장합니다. | 서버 4대가 함께 쓰는 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 내용이 달라질 수 있습니다. | 4대 서버가 같은 내용을 봅니다. |
| 조회 속도 | 서버 안에서 바로 읽어 빠릅니다. | 네트워크를 거쳐 읽어서 일반적으로 로컬 캐시보다 조금 느립니다. |
| 캐시 서버에 문제가 생길 때 | 서버마다 따로 동작하여 다른 서버에 영향을 주지 않습니다. | 4대 서버가 모두 영향을 받습니다. |

확인 필요: 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지울지, 보관 시간을 5분보다 짧게 할지 정해야 합니다. 이 결정에 따라 고객에게 가격이 늦게 보이는 시간이 달라집니다. 실제 지연 시간은 도입 후 측정해야 확인할 수 있습니다.
