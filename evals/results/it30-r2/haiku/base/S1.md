## PM에게 보낼 답변

> **로컬 캐시 vs Redis 캐시**
>
> 캐시는 자주 쓰는 데이터를 빠르게 꺼내 쓰려고 임시로 저장해 두는 곳이에요.
>
> - **지금 방식(로컬 캐시):** 서버 4대가 각자 자기 메모리에 상품 목록을 보관해요. 그래서 서버마다 보고 있는 내용이 달라질 수 있고, 가격을 바꾸면 각 서버가 5분 뒤에 갱신하기 때문에 고객에게 최대 5분 늦게 보일 수 있어요.
> - **Redis 방식:** 서버 4대가 같은 캐시 서버 1대를 함께 봐요. 모든 서버가 같은 데이터를 보니까 서버마다 가격이 다르게 보이는 문제가 없어져요.
>
> **도입하면 좋아지는 점**
> 1. **가격 불일치 해소:** 어느 서버로 접속하든 같은 가격이 보여요.
> 2. **가격 변경 반영 속도 개선:** 가격을 바꿀 때 Redis의 캐시만 지우면 4대 서버 모두에 바로 반영돼요. 5분을 기다릴 필요가 없어요.
> 3. **서버 메모리 절약:** 서버마다 같은 데이터를 복사해 두지 않아도 돼요.
>
> **주의할 점**
> - Redis를 도입하는 것만으로는 즉시 반영이 되지 않아요. 가격을 바꿀 때 캐시를 지우는 처리를 함께 만들어야 해요. 이 작업이 있어야 "즉시 반영"이 실현돼요.
> - Redis 서버가 한 대 더 생기므로 운영 관리가 필요해요. Redis가 멈추면 캐시가 비어 DB에 요청이 몰릴 수 있어서, 장애 대비도 계획에 넣어야 해요.
> - 로컬 메모리보다는 Redis 조회가 조금 느리지만, 보통 DB를 직접 조회하는 것보다는 훨씬 빨라요.

---

**참고:** 가격 반영 지연 문제만 보면 Redis보다 "가격 변경 시 캐시 삭제"가 핵심이에요. Redis를 도입하면서 TTL(5분 만료)을 그대로 두고 삭제 로직을 빼면 지연 문제가 그대로 남아요. 개발팀에 이 부분을 확인해 보시길 권해요.
