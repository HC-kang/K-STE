Redis를 도입하면 4대 서버가 같은 상품 목록을 보게 되어, 서버마다 가격이 다르게 보이는 문제가 없어집니다.

지금은 각 서버가 자기 메모리에 상품 목록을 5분 동안 저장해 두는 캐시(자주 쓰는 데이터를 빠르게 꺼내 쓰려고 임시로 저장해 두는 공간)를 씁니다. 그래서 서버마다 캐시 내용이 달라지고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. Redis는 4대 서버가 함께 쓰는 별도의 캐시 서버입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 조회 속도 | 가장 빠름 | 네트워크를 거치므로 로컬보다 느림 |
| 장애 영향 | 해당 서버의 캐시만 사라짐 | Redis 서버가 멈추면 4대 모두 영향을 받을 수 있음 |

다만 Redis를 도입한다고 가격 반영이 바로 빨라지지는 않습니다. 캐시 유지 시간이 5분 그대로라면 가격 반영은 여전히 최대 5분 늦을 수 있습니다. 가격을 바꿀 때 캐시를 바로 지우는 방식까지 이번 도입 범위에 넣을지는 개발팀에 확인하는 것을 권장합니다.
