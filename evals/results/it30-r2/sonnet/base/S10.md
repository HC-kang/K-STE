# 원인 분석: CI에서만 `Cannot find module '@company/ui/button'` 빌드 실패

## 요약 (PM용)
- **가장 유력한 원인**: 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰고 있다. 로컬은 1.4.0, CI는 2.0.0이다.
- 2.0.0부터 패키지 내부 경로를 `exports` 필드로 제한한다. `@company/ui/button` 같은 하위 경로 import가 더 이상 자동으로 허용되지 않는다.
- 로컬은 업그레이드 이전에 설치한 `node_modules`를 그대로 써서 문제가 가려졌다. 즉 **CI가 오히려 실제 상태를 정확히 보여주고 있다.**
- 이 상태로 배포하면 프로덕션 빌드도 실패할 가능성이 높다.

## 근거

| 사실 | 해석 |
|---|---|
| 3일 전 1.4.0 → 2.0.0 업그레이드 | 변경 시점이 실패 시점과 일치한다. |
| 2.0.0에서 `exports` 필드 추가 | `exports`가 있으면 패키지가 명시한 경로만 import할 수 있다. 명시하지 않은 `./button`은 해석되지 않는다. |
| 로컬 `node_modules`는 업그레이드 이전 설치 | 로컬에는 아직 1.4.0이 있고, 1.4.0에는 `exports`가 없어 `button` 파일을 직접 찾는다. |
| CI 캐시 키 = `package-lock.json` 해시 | 락파일이 바뀌면 캐시가 갱신되어 CI는 2.0.0을 새로 설치한다. 캐시 자체는 원인이 아니다. |
| Node 18(CI) vs Node 20(로컬) | 두 버전 모두 `exports`를 지원하므로 주원인으로 보기 어렵다. 부차적 변수로만 둔다. |

## 확신 수준과 미확인 사항
- "버전 불일치 + `exports` 제한"은 주어진 정보로 강하게 추정되지만 **아직 직접 확인하지 않았다.**
- 일반적인 `exports` 위반 에러는 `ERR_PACKAGE_PATH_NOT_EXPORTED`이다. 실제 메시지가 `Cannot find module`이므로 다음 가능성도 확인해야 한다.
  - `exports`에 `./button`은 있지만 `require` 조건이 없어 CJS 경로에서 해석이 실패한다.
  - `exports`가 가리키는 파일(예: `dist/button.js`)이 배포물에 없다.

## 확인 방법 (각각 몇 분 내)
1. 로컬에서 `npm ls @company/ui`를 실행하고 `node_modules/@company/ui/package.json`의 `version`을 확인한다. 1.4.0이면 가설이 확정된다.
2. 로컬에서 `rm -rf node_modules && npm ci` 후 `next build`를 실행한다. CI와 같은 에러가 재현되어야 한다.
3. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지, 가리키는 파일이 실제로 존재하는지 확인한다.
4. 필요하면 CI 로그에서 `npm ci` 단계가 설치한 `@company/ui` 버전을 확인한다.

## 해결 옵션

| 옵션 | 내용 | 비용 |
|---|---|---|
| A. import 경로 수정 | 2.0.0 마이그레이션 가이드에 맞춰 `@company/ui/button`을 지원되는 경로로 변경한다. | 장기적으로 가장 올바름. 사용처 수만큼 수정이 필요하다. |
| B. 패키지에 `./button` 추가 | `@company/ui` 담당자에게 `exports`에 해당 하위 경로를 추가한 2.0.1을 요청한다. | 패키지 릴리스 대기가 필요하다. |
| C. 1.4.0으로 임시 고정 | 즉시 CI를 복구하고 A 또는 B를 계획한다. | 가장 빠르지만 업그레이드가 지연된다. |

## 재발 방지
- 로컬 의존성 설치는 `npm install` 대신 `npm ci`를 쓴다. 락파일 기준으로 CI와 동일한 상태가 된다.
- 업그레이드 후에는 클린 설치로 로컬 빌드를 한 번 검증한다.
- `.nvmrc` 또는 `engines`로 Node 버전을 통일한다. 이번 원인은 아니지만 비슷한 "CI에서만 실패"를 줄여준다.
- 메이저 버전 업그레이드 PR에는 CI 통과를 머지 조건으로 둔다.

원하시면 1~3번 확인을 직접 실행하고 결과를 이 문서에 반영하겠습니다.
