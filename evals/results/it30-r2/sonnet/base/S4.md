# 운영 배포 롤백 런북 (payment-api)

## 1. 적용 범위
- 배포 도구: ArgoCD
- 대상 애플리케이션: `payment-api`

## 2. 롤백 전 확인 (필수)
롤백할 배포(롤백 대상이 되는 현재 배포)에 **DB 마이그레이션이 포함됐는지** 확인한다.

| 확인 결과 | 조치 |
|---|---|
| 마이그레이션 **포함** | **롤백하지 않는다.** DBA 박지은에게 연락하고 안내에 따른다. 이 문서의 3단계로 넘어가지 않는다. |
| 마이그레이션 **미포함** | 3단계로 진행한다. |

## 3. 롤백 실행
1. 되돌릴 리비전(`<REVISION>`)을 정한다. 이력은 `argocd app history payment-api`로 조회할 수 있다.
2. 아래 명령을 실행한다.

```sh
argocd app rollback payment-api <REVISION>
```

## 4. 롤백 후 검증
아래 두 항목을 모두 통과해야 롤백 완료로 본다.

1. `/healthz`가 HTTP 200을 반환하는지 확인한다.
2. 결제 테스트 주문 1건이 성공하는지 확인한다.

둘 중 하나라도 실패하면 롤백 완료로 처리하지 않고 #deploy 채널에 실패 사실을 남긴다.

## 5. 이력 기록
롤백 이력을 **#deploy** 채널에 남긴다. 기록 항목은 다음과 같다.
- 롤백한 리비전(`<REVISION>`)
- 2단계 마이그레이션 확인 결과
- 4단계 검증 결과(`/healthz` 응답, 테스트 주문 성공 여부)

## 요약 흐름
마이그레이션 포함 여부 확인 → (포함) 중단 후 박지은에게 연락 / (미포함) `argocd app rollback` → `/healthz` 200 확인 → 테스트 주문 1건 성공 확인 → #deploy에 기록
