**한 줄 요약**
로컬 캐시는 서버 4대가 각자 따로 갖는 메모장이고, Redis 캐시는 4대가 함께 보는 공용 메모장입니다. 공용으로 바꾸면 가격 변경이 고객에게 늦게 보이는 문제가 해결됩니다.

**지금 방식 (로컬 캐시)**
- 서버마다 상품 목록을 자기 메모리에 5분간 저장합니다.
- 저장 시점이 서버마다 달라서, 같은 시각에 서버 A는 새 가격을, 서버 B는 옛 가격을 보여줄 수 있습니다.
- 가격을 바꿔도 각 서버의 캐시가 만료될 때까지 최대 5분은 옛 가격이 노출됩니다.

**바뀌는 방식 (Redis 캐시)**
- 캐시 서버 1대를 4대가 함께 씁니다. 캐시 내용이 한 곳에만 있으므로 서버끼리 내용이 어긋나지 않습니다.
- 가격을 바꿀 때 Redis의 해당 캐시를 바로 지우거나 갱신하면, 4대 모두 다음 요청부터 새 가격을 보여줍니다.

**우리 서비스에 좋아지는 점**
1. **가격 반영 지연 해소**: 최대 5분이던 지연이 거의 즉시로 줄어듭니다. 서버 간 가격 불일치도 사라집니다.
2. **DB 부하 감소**: 지금은 서버 4대가 각자 DB에서 상품 목록을 읽어 와 캐시를 채웁니다. 이후에는 한 번 채워진 캐시를 4대가 같이 쓰므로 DB 조회가 줄어듭니다.
3. **배포·재시작 후 안정성**: 로컬 캐시는 서버를 재시작하면 비워져서 그동안 응답이 느려질 수 있습니다. Redis 캐시는 서버와 별개로 유지됩니다.

**알아둘 점**
- "즉시 반영"은 가격 변경 시 캐시를 지우는 처리를 함께 구현해야 성립합니다. Redis만 도입한다고 저절로 되지는 않습니다.
- 서버 메모리보다 Redis 접근이 아주 조금 느립니다(네트워크 경유). 다만 DB 조회보다는 훨씬 빠르므로 고객이 체감할 차이는 거의 없을 것으로 봅니다.
- Redis 서버가 1대이므로, 이 서버에 장애가 나면 요청이 DB로 몰릴 수 있습니다. 장애 대비 방안은 개발팀과 따로 확인해 두는 편이 좋습니다.
