원인은 CI가 `@company/ui` 2.0.0을 설치하는데, 2.0.0의 `exports` 필드에 `@company/ui/button` 경로가 없기 때문일 가능성이 가장 높습니다. 아래 내용은 알려주신 정보에서 추론한 것이며, 실제 설치 버전과 `exports` 내용은 아직 확인하지 않았습니다.

## 추정 원인

`exports` 필드는 패키지가 외부에 공개할 파일 경로를 직접 지정하는 설정입니다. 이 필드가 있으면 목록에 없는 경로는 import(모듈 불러오기)할 수 없습니다. 1.4.0에는 이 필드가 없어서 `@company/ui/button`처럼 패키지 안쪽 파일을 직접 가리켜도 동작했습니다. 2.0.0의 `exports`에 `./button`이 없거나 다른 이름으로 바뀌었다면, 같은 import가 `Cannot find module` 오류로 실패합니다.

로컬 빌드가 성공하는 이유는 로컬 `node_modules`가 3일 전보다 먼저 설치된 것이라 1.4.0이 남아 있을 가능성이 높기 때문입니다. CI는 `package-lock.json`을 기준으로 새로 설치하므로 2.0.0을 받습니다. 이 때문에 로컬과 CI가 서로 다른 버전을 쓰고 있다고 봅니다.

## 가능성이 낮은 원인

- Node 버전: Node 18과 20 모두 `exports`를 지원하므로, 버전 차이가 직접 원인일 가능성은 낮습니다.
- CI 캐시: 캐시 키가 `package-lock.json` 해시이므로, 버전을 올리면 키가 바뀌어 새로 설치합니다. 그래서 오래된 캐시가 원인일 가능성은 낮습니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. 로컬에서 `rm -rf node_modules && npm ci`로 CI와 같은 방식으로 다시 설치한 뒤 빌드합니다. 같은 오류가 나오면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.

Node 버전 영향까지 배제하려면 2번을 로컬 Node 18에서 실행하면 됩니다.

## 수정 방향

`exports`에 정의된 새 경로로 import를 바꿔야 합니다. 새 경로가 없으면 `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청해야 합니다. 2.0.0 변경 내용(changelog)에 import 경로 변경이 적혀 있는지도 확인해야 합니다.
