Redis를 도입하면 API 서버(고객 요청을 받아 상품 정보를 돌려주는 서버) 4대가 캐시(자주 쓰는 데이터를 미리 저장해 두는 곳) 하나를 같이 쓰게 됩니다. 그래서 서버마다 고객에게 다른 상품 정보를 보여 주는 상황이 없어집니다.

현재는 로컬 캐시를 씁니다. 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 그래서 서버마다 저장된 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 별도의 캐시 서버 1대에 상품 목록을 저장하고, 서버 4대가 모두 이 캐시 서버를 읽습니다.

| 항목 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 캐시 내용 | 서버마다 다릅니다 | 4대가 같은 내용을 읽습니다 |

Redis만 도입해서는 가격 변경의 5분 지연이 줄지 않습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 갱신하거나 지우는 기능을 따로 만들어야 지연이 줄어듭니다.

확인 필요: 이번 Redis 도입 범위에 가격 변경 시 캐시를 갱신하거나 지우는 기능이 들어 있는지.
