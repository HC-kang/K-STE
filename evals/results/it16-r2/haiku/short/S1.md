Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되어, 서버마다 내용이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 매번 원본에서 가져오지 않도록 임시로 저장해 둔 사본입니다. 지금 방식은 각 서버가 자기 메모리에 사본을 저장하는 로컬 캐시(서버 한 대 안에만 두는 저장 공간)입니다. 이번에 도입하는 Redis는 서버 4대가 함께 쓰는 별도의 캐시 서버입니다.

| 구분 | 현재 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 공용 캐시 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있음 | 4대가 같은 데이터를 봄 |
| 읽기 속도 | 서버 안에서 바로 읽어 가장 빠름 | 네트워크를 거쳐 읽어 로컬보다 느림 |
| 장애 영향 | 서버 한 대의 캐시만 사라짐 | 캐시 서버가 멈추면 4대가 함께 영향을 받음 |

가격 반영 지연은 Redis를 도입한다고 저절로 줄지 않습니다. 캐시 사본의 유효 시간(저장된 데이터를 원본에서 다시 가져오기 전까지의 시간)을 5분으로 그대로 두면, 가격을 바꾼 뒤 고객에게 최대 5분 늦게 반영되는 문제는 그대로 남습니다.

확인 필요: Redis 도입 계획에 가격을 바꿀 때 Redis 캐시를 바로 지우는 작업이 포함되어 있는지, 그리고 유효 시간을 몇 분으로 정하는지 확인해야 합니다.
