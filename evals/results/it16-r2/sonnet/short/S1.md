로컬 캐시는 서버 4대가 각자 따로 기억하는 방식이고, Redis 캐시는 서버 4대가 한 곳을 같이 보는 방식입니다. 캐시는 자주 쓰는 데이터를 미리 가까운 곳에 저장해 두는 기능입니다.

| 항목 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 서버마다 자기 메모리에 저장합니다. | 캐시 전용 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 서버 4대가 같은 내용을 봅니다. |
| 가격 변경 반영 | 고객에게 최대 5분 늦게 반영됩니다. | 가격을 바꿀 때 Redis의 상품 목록도 함께 갱신하면 지연을 줄일 수 있습니다. |

현재는 서버마다 상품 목록을 5분 동안 따로 저장합니다. 그래서 가격을 바꿔도 서버마다 옛 가격을 보여 주는 시간이 다를 수 있습니다. Redis를 도입하면 서버 4대가 같은 캐시를 읽으므로, 같은 시점에 고객마다 다른 가격을 보는 문제가 줄어듭니다.

가격 변경이 바로 반영될지는 Redis 도입만으로 정해지지 않습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 갱신하거나 지우도록 개발해야 합니다. 이 부분은 추론이며, 구현 방식은 아직 확인하지 않았습니다.

확인 필요: Redis 서버가 1대이므로, 이 서버가 멈출 때 API 서버 4대가 어떻게 동작할지 정해졌는지 개발팀에 확인해야 합니다.
