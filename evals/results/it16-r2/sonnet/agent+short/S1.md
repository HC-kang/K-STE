Redis를 도입하면 서버 4대가 같은 캐시를 보기 때문에, 서버마다 상품 목록이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 방식입니다. 지금은 로컬 캐시를 씁니다. 로컬 캐시는 API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장하는 방식입니다. 서버마다 저장한 시점이 달라서 캐시 내용도 서로 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. 같은 고객이 요청할 때마다 다른 서버에 연결되면 서로 다른 가격을 볼 수도 있습니다.

Redis 캐시는 캐시 전용 서버 1대를 4대가 함께 쓰는 방식입니다. 상품 목록이 한 곳에만 있으므로 어느 서버에 연결돼도 고객은 같은 내용을 봅니다. 가격을 바꿀 때 Redis에 저장된 상품 목록도 함께 갱신하거나 지우면, 5분을 기다리지 않고 4대 모두 새 가격을 보여 줍니다.

Redis 서버가 1대이므로 이 서버가 멈추면 4대 모두 캐시를 쓰지 못합니다. 또 서버 메모리가 아니라 네트워크를 거쳐 읽기 때문에 응답이 로컬 캐시보다 약간 느릴 수 있습니다.
