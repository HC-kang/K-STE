`@company/ui`를 2.0.0으로 올린 뒤 `exports` 필드가 `@company/ui/button` 경로를 막은 것이 원인으로 보입니다. 로컬은 아직 1.4.0을 쓰고 있어서 이 문제가 드러나지 않았을 가능성이 높습니다. 이 내용은 추론이고, 아래 확인 방법으로 검증하지 않았습니다.

## 추론의 근거

`exports` 필드는 패키지가 외부에 공개하는 import 경로를 정하는 목록입니다. 필드가 있으면 목록에 없는 경로는 패키지 안에 파일이 있어도 불러올 수 없습니다. 2.0.0에 이 필드가 추가됐으므로, `button` 경로가 목록에 없거나 다른 이름으로 바뀌었으면 `Cannot find module` 에러가 납니다.

로컬과 CI의 차이는 설치 시점에서 생깁니다.

- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다. 그래서 1.4.0이 들어 있을 가능성이 높고, 1.4.0에는 `exports` 필드가 없어서 빌드가 성공합니다.
- CI 캐시(설치한 패키지를 저장해 재사용하는 기능)의 키는 `package-lock.json`의 해시입니다. 버전을 올리면서 lock 파일이 바뀌었으므로 캐시가 새로 만들어졌고, CI는 2.0.0을 설치했을 것입니다.

Node 18과 20의 차이는 원인이 아닌 것으로 보입니다. `exports` 필드는 두 버전이 모두 지원합니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오. 1.4.0이면 추론이 맞습니다.
2. CI 로그에서 설치된 `@company/ui` 버전이 2.0.0인지 확인하십시오.
3. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button`이 있는지 확인하십시오.
4. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. CI와 같은 에러가 나면 원인이 확정됩니다.

3번에서 `./button`이 없으면, `@company/ui` 2.0.0의 마이그레이션 안내에서 새 import 경로를 찾아 코드의 import를 바꿔야 합니다. 안내에 해당 내용이 없으면 `@company/ui` 담당자에게 문의하십시오.
