로컬 캐시는 각 서버가 자기 메모리에 데이터를 따로 보관하는 방식이고, Redis 캐시는 서버 바깥의 공용 저장소에 데이터를 보관하는 방식입니다. Redis를 도입하면 서버 4대가 같은 캐시를 보게 되므로, 서버마다 상품 정보가 다르게 보이는 문제는 없어집니다.

캐시는 자주 쓰는 데이터를 가까운 곳에 임시로 복사해 두는 장치입니다. 매번 원본 데이터베이스를 조회하지 않아도 되어 응답이 빨라집니다. 지금은 고객 요청을 처리하는 API 서버 4대가 각자 메모리에 상품 목록을 5분 동안 보관합니다. 그래서 서버마다 다른 시점의 상품 목록을 가질 수 있고, 가격을 바꾸면 고객에게 최대 5분 늦게 보입니다.

Redis는 서버 4대가 함께 쓰는 캐시 서버 1대입니다. 서버는 상품 목록을 Redis에서 가져오므로 4대가 같은 내용을 봅니다. 다만 Redis는 네트워크를 거쳐 데이터를 가져오기 때문에, 서버 메모리에서 바로 읽는 것보다 일반적으로 느립니다. 그러므로 Redis 도입으로 속도가 좋아진다고 기대하지 않으시는 것이 좋습니다. 얻는 이점은 서버 사이의 내용 차이가 없어진다는 점입니다.

가격 변경이 고객에게 5분 늦게 보이는 문제는 Redis 도입만으로 해결되지 않습니다. 캐시를 5분 동안 유지할지, 가격을 바꿀 때 Redis의 상품 캐시를 바로 지울지에 따라 달라집니다. 가격 변경을 즉시 고객에게 보여 줘야 하는지 PM님께서 정해 주시면, 개발팀이 그 기준에 맞춰 캐시 방식을 정하겠습니다.
