# 운영 payment-api 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 되돌리는 절차를 정의한다. 롤백 전에 DB 마이그레이션 포함 여부를 반드시 확인해야 한다.

## 1. 롤백 전 DB 마이그레이션 확인

롤백 대상 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.

**마이그레이션이 포함됐으면 롤백하면 안 된다.** 이 경우 DBA 박지은에게 연락해야 한다.

확인 필요: 배포에 마이그레이션이 포함됐는지 확인하는 방법과 확인할 위치가 주어지지 않았다.

## 2. 롤백 실행

마이그레이션이 포함되지 않은 것을 확인한 뒤 아래 명령으로 롤백한다.

```
argocd app rollback payment-api <REVISION>
```

확인 필요: `<REVISION>`에 넣을 값을 확인하는 방법이 주어지지 않았다.

## 3. 롤백 후 검증

롤백 후 다음 두 가지를 순서대로 확인한다.

1. `/healthz`가 200을 반환하는지 확인해야 한다.
2. 결제 테스트 주문 1건이 성공하는지 확인해야 한다.

확인 필요: `/healthz`를 호출할 주소와 결제 테스트 주문을 실행하는 방법이 주어지지 않았다.

## 4. 롤백 이력 기록

롤백 이력은 #deploy 채널에 남겨야 한다.

확인 필요: 이력에 포함할 항목과 양식이 주어지지 않았다.
