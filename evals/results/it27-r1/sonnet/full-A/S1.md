로컬 캐시는 서버마다 따로 저장하고 Redis 캐시는 서버 4대가 하나를 같이 쓰기 때문에, Redis를 도입하면 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 임시로 저장해 두고 다시 꺼내 쓰는 방식입니다. 현재는 API 서버(고객 요청을 받아 응답하는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 캐시합니다. 이것이 로컬 캐시입니다. 서버마다 캐시 내용이 달라서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 캐시를 저장하는 별도 서버입니다. 이번에는 Redis 서버 1대를 도입하고, API 서버 4대가 이 서버의 캐시를 같이 씁니다. 그래서 4대가 모두 같은 캐시 내용을 보게 됩니다.
