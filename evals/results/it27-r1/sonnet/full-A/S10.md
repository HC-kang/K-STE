CI에서만 실패하는 가장 유력한 원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰는 것으로 보입니다.

- CI(코드를 올릴 때마다 자동으로 빌드하는 환경)의 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 이 파일이 바뀌었다면 CI는 기존 캐시를 쓰지 않고 `@company/ui` 2.0.0을 새로 설치합니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했으므로 1.4.0이 남아 있을 수 있습니다.
- `@company/ui` 2.0.0은 `exports` 필드(패키지가 외부에 공개하는 import 경로를 제한하는 `package.json` 설정)를 추가했습니다. `exports`에 `./button` 경로가 없다면 `@company/ui/button`을 찾지 못합니다.
- Node 18과 20은 모두 `exports`를 지원하므로 Node 버전 차이는 원인일 가능성이 낮습니다.

원인을 가르려면 아래 순서로 진행하십시오.

1. CI와 로컬에서 각각 `npm ls @company/ui`를 실행해 설치된 버전을 비교하십시오.
2. 설치된 `@company/ui` 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 찾아 보십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드해, CI와 같은 오류가 나는지 보십시오.

2번에서 `./button`이 없으면 `@company/ui` 2.0.0의 import 경로가 바뀐 것이므로, 앱의 import 경로를 고치거나 패키지 담당자에게 `exports` 추가를 요청해야 합니다.
