가장 유력한 원인은 CI가 `@company/ui` 2.0.0을 설치하고, 로컬은 1.4.0이 남아 있는 것입니다. 이것은 주어진 사실에서 낸 추론이고, 아래 세 가지는 아직 검증하지 않았습니다.

**사실**
- CI 빌드만 실패하고, 오류는 `Error: Cannot find module '@company/ui/button'`입니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0 패키지에는 `exports` 필드가 추가됐습니다. `exports`는 패키지가 외부에 공개하는 경로 목록을 정하는 `package.json` 필드입니다. 목록에 없는 경로는 import할 수 없습니다.
- CI는 Node 18, 로컬은 Node 20입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.

**추론**
1. 로컬 `node_modules`는 업그레이드 전에 설치했으므로 1.4.0이 들어 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 파일 경로 그대로 열립니다. 그래서 로컬 빌드는 성공합니다.
2. CI는 `package-lock.json`이 바뀌면 캐시 키가 달라져 의존성을 새로 설치합니다. 업그레이드 커밋에 lock 파일이 들어 있었다면 CI는 2.0.0을 받습니다.
3. 2.0.0의 `exports`에 `./button`이 없거나 이름이 달라졌다면 Node가 그 경로를 막고 위 오류를 냅니다.
4. Node 18과 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 원인일 가능성이 낮습니다.

**미확인**
- 로컬 `node_modules/@company/ui/package.json`의 실제 `version` 값
- 2.0.0 `package.json`의 `exports`에 `./button`이 있는지, 있다면 어떤 이름과 파일로 매핑되는지
- 업그레이드 커밋에 `package-lock.json` 변경이 들어 있는지

**검증 순서**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 추론 1이 맞습니다.
2. `node_modules`와 `.next`를 지우고 `npm ci`로 다시 설치한 뒤 로컬에서 `npm run build`를 실행하십시오. 이때 같은 오류가 나면 CI 환경이 원인이 아니라 2.0.0이 원인입니다.
3. 2.0.0의 `exports`에 `./button`이 없으면 import 경로를 2.0.0이 공개한 경로로 바꾸십시오. 경로를 공개해야 하는 쪽이 패키지라면 `@company/ui` 담당자에게 `exports`에 `./button` 추가를 요청하십시오.

PM이 알아야 할 점은 하나입니다. 이 문제는 CI 설정 오류가 아니라 2.0.0 업그레이드에서 생긴 호환성 문제일 가능성이 높습니다. 그리고 로컬 빌드 성공은 2.0.0 검증이 되지 않았습니다.
