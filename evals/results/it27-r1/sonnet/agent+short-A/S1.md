로컬 캐시(서버가 자기 메모리에 임시로 저장해 두는 공간)는 서버마다 따로 가지고, Redis 캐시는 서버 4대가 하나를 같이 쓴다는 점이 다릅니다.

지금은 API 서버 4대가 각자 상품 목록을 5분 동안 자기 메모리에 저장합니다. 그래서 서버마다 캐시 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis를 도입하면 캐시 서버 1대에 상품 목록을 저장하고, 서버 4대가 그 같은 내용을 읽습니다. 그래서 서버마다 캐시 내용이 달라지는 문제가 없어집니다. 고객은 어느 서버에 연결되든 같은 상품 목록을 봅니다.

가격 변경이 반영되는 시간이 5분에서 얼마로 줄어드는지는 아직 정해지지 않았습니다. 가격을 바꿀 때 Redis의 캐시 내용을 바로 바꾸는지, 5분이 지나 캐시가 만료되기를 기다리는지에 따라 달라집니다.

확인 필요: Redis 도입 후 가격 변경 시 캐시를 갱신하는 방식. 이 방식을 정해야 PM에게 반영 시간을 수치로 안내할 수 있습니다.
