CI 실패의 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드로 보입니다. 로컬 `node_modules`에는 아직 1.4.0이 남아 있어서 로컬 빌드만 성공했을 것으로 보입니다. 아래 내용은 모두 추론이고, 아직 재현하거나 확인한 것은 없습니다.

## 근거

`exports`는 패키지가 외부에 공개할 import 경로를 `package.json`에 제한해서 적는 필드입니다. 이 필드가 있으면 Node와 번들러(코드를 묶어 주는 빌드 도구)는 `exports`에 적힌 경로만 불러옵니다. 2.0.0의 `exports`에 `./button`이 없으면 `@company/ui/button`을 찾지 못하고, 이 에러가 납니다. 1.4.0에는 `exports`가 없어서 같은 import가 성공했습니다.

로컬 `node_modules`는 3일 전보다 먼저 설치했습니다. 그래서 로컬에는 1.4.0이 그대로 있을 것으로 보입니다.

CI 캐시 키는 `package-lock.json`의 해시입니다(캐시 키는 저장해 둔 설치 결과를 다시 쓸지 정하는 이름입니다). 버전을 올렸으니 lock 파일도 바뀌었을 것이고, 그러면 CI는 캐시를 쓰지 않고 2.0.0을 새로 설치했을 것으로 보입니다.

Node 18과 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 원인으로 보기 어렵습니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 위 추론이 맞습니다.
2. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 에러가 나면 재현된 것입니다.

## 수정 방향

2.0.0의 `exports`에 `./button`이 없으면 방법은 두 가지입니다. 앱의 import 경로를 2.0.0이 공개한 경로로 바꾸거나, `@company/ui`의 `exports`에 `./button`을 추가해야 합니다. 어느 쪽이 맞는지는 2.0.0에서 `button` 경로를 일부러 없앴는지에 달려 있습니다.

확인 필요: 2.0.0에서 `./button` 경로를 의도적으로 비공개로 바꿨는지, 아니면 `exports`에 넣는 것을 빠뜨렸는지.
