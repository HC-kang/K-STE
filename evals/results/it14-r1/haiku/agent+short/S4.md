# payment-api 운영 배포 롤백 런북

배포 도구는 ArgoCD이며, 대상 애플리케이션은 `payment-api`다. 롤백 전에 DB 마이그레이션 포함 여부를 반드시 확인해야 한다. 마이그레이션이 포함된 배포는 롤백하면 안 된다.

## 1. 롤백 전 DB 마이그레이션 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
2. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 자료.
3. 마이그레이션이 포함됐으면 롤백하면 안 된다.
4. 마이그레이션이 포함됐으면 DBA 박지은에게 연락해야 한다.
5. 마이그레이션이 포함되지 않았다고 확인된 경우에만 2장으로 넘어간다.

**경고: 마이그레이션이 포함된 배포를 롤백하면 안 된다. 반드시 DBA 박지은에게 먼저 연락해야 한다.**

## 2. 롤백 실행

1. 되돌릴 배포의 리비전을 확인 필요: 리비전 번호를 찾는 방법을 통해 확인한다.
2. 아래 명령의 `<REVISION>`을 확인한 리비전 번호로 바꾼 뒤 실행한다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 검증

1. `/healthz` 응답이 200인지 확인한다. 확인 필요: 요청할 주소와 확인 방법.
2. 결제 테스트 주문 1건이 성공하는지 확인한다. 확인 필요: 테스트 주문 방법과 성공 판정 기준.
3. 1번 또는 2번이 실패하면 롤백 결과를 정상으로 보면 안 된다. 확인 필요: 실패 시 후속 조치 담당자와 절차.

## 4. 롤백 이력 기록

롤백 이력은 #deploy 채널에 남겨야 한다. 확인 필요: 기록에 포함할 항목과 양식.

---

**확인 필요 항목 요약:** 마이그레이션 포함 여부 확인 방법, 리비전 번호 조회 방법, `/healthz` 요청 주소와 확인 방법, 테스트 주문 절차와 성공 기준, 검증 실패 시 후속 조치, #deploy 기록 양식. 이 항목들은 제공된 사실에 없어서 비워 두었다. 알려 주시면 해당 부분을 채워 드릴 수 있다.
