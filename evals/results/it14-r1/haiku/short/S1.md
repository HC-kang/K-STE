로컬 캐시는 각 서버가 자기 메모리(작업용 임시 기억 공간) 안에 데이터를 따로 보관하는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도의 공용 캐시 서버(자주 쓰는 데이터를 임시로 모아 두는 저장소)에 데이터를 보관하는 방식입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 보관 위치 | 각 API 서버 안 | 별도의 Redis 서버 1대 |
| 서버 4대가 보는 값 | 서버마다 다를 수 있습니다 | 4대가 같은 값을 봅니다 |
| 가격 변경 반영 | 서버마다 5분씩 따로 보관하므로 최대 5분 늦게 반영됩니다 | 확인 필요: 이 글을 쓰는 시점에 가격 변경 때 Redis 값을 바로 지우는지 확인되지 않았습니다 |

Redis를 도입하면 4대의 서버가 같은 저장소를 보기 때문에 서버마다 가격이 다르게 보이는 문제가 생기지 않습니다. 다만 Redis는 별도의 서버여서 API 서버가 값을 가져올 때마다 네트워크를 거칩니다. 그래서 자기 메모리에서 바로 꺼내는 로컬 캐시보다 조회가 느릴 수 있습니다.

최대 5분 지연이 줄어드는지는 가격을 바꿀 때 Redis 값을 어떻게 갱신하는지에 따라 달라집니다. 확인 필요: 가격 변경 시 Redis 값을 즉시 지우거나 새 값으로 바꾸는 처리를 설계에 포함하는지 개발팀에 확인해야 합니다.
