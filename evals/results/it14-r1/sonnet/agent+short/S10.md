원인은 로컬 빌드가 2.0.0이 아니라 1.4.0으로 돌았기 때문으로 보입니다. 이 내용은 추론이며, 아래 검증 절차로 확인해야 합니다.

## 사실

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `node_modules` 설치 시점 | 3일 전보다 이전 | 캐시 키에 따라 결정 |
| 빌드 결과 | 성공 | `Cannot find module '@company/ui/button'`으로 실패 |

- `@company/ui`를 3일 전에 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 패키지에 `exports` 필드(패키지 밖에서 import할 수 있는 경로를 패키지가 직접 정하는 설정)가 추가됐습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

## 추론

1. 로컬 `node_modules`는 업그레이드보다 먼저 설치했으므로 `@company/ui` 1.4.0이 그대로 들어 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 파일 경로로 바로 열립니다.
2. 업그레이드로 `package-lock.json`이 바뀌었으므로 캐시 키도 바뀌었습니다. 그래서 CI는 캐시를 쓰지 않고 2.0.0을 새로 설치했을 것입니다.
3. 2.0.0에는 `exports` 필드가 있으므로, 이 필드에 `./button` 항목이 없거나 경로가 다르면 `Cannot find module`이 납니다.

Node 버전 차이는 원인일 가능성이 낮아 보입니다. Node 18과 20 모두 `exports` 필드를 지원합니다. 다만 두 버전을 직접 비교해 보지는 않았습니다.

## 검증 절차

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 본다.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 다시 빌드한다. CI와 같은 에러가 나면 원인이 맞다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button` 항목이 있는지 본다.
4. 항목이 없거나 경로가 다르면 두 가지 중 하나를 선택한다.
   - import 경로를 2.0.0의 `exports`에 있는 경로로 바꾼다.
   - `@company/ui` 쪽에서 `./button`을 `exports`에 추가하고 새 버전을 배포한다.

2번 결과가 에러 없이 성공하면 이 추론은 틀린 것이므로, Node 18과 20의 차이를 다시 조사해야 합니다.
