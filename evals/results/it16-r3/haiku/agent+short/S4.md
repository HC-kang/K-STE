# 운영 배포 롤백 런북: payment-api

이 문서는 ArgoCD로 payment-api의 운영 배포를 이전 리비전(revision)으로 되돌리는 절차를 정한다. 롤백 전에 배포에 DB 마이그레이션이 포함됐는지 확인해야 하며, 마이그레이션이 포함됐으면 롤백하면 안 된다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. DBA 박지은에게 연락해야 한다.
3. 롤백할 이전 리비전 번호를 정한다.

확인 필요: 마이그레이션 포함 여부를 확인하는 방법.
확인 필요: 리비전 번호를 찾는 방법.

## 롤백

4. 다음 명령으로 롤백한다. `<REVISION>` 자리에 3단계에서 정한 리비전 번호를 넣는다.

```
argocd app rollback payment-api <REVISION>
```

## 결과 확인

5. `/healthz`를 호출해 응답이 200인지 확인한다.
6. 결제 테스트 주문을 1건 넣고 주문이 성공하는지 확인한다.

확인 필요: `/healthz`를 호출할 호스트 주소.
확인 필요: 결제 테스트 주문을 넣는 방법.

## 기록

7. 롤백 이력을 #deploy 채널에 남긴다.
