Redis를 도입하면 서버 4대가 같은 캐시를 보게 되지만, 가격이 고객에게 바로 반영되는지는 Redis 도입만으로 해결되지 않습니다.

캐시(자주 찾는 데이터를 빨리 꺼내려고 임시로 저장해 두는 곳)는 지금 각 API 서버의 메모리에 있습니다. 이를 로컬 캐시라고 합니다. Redis(여러 서버가 함께 쓰는 데이터 저장 서버)는 서버 밖에 있는 캐시 서버 한 대입니다.

| 항목 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대가 같은 내용을 봅니다 |
| 가격 반영 | 최대 5분 늦습니다 | Redis 도입만으로는 여전히 최대 5분 늦습니다 |
| 단점 | 서버마다 내용이 어긋납니다 | 캐시 서버를 따로 운영해야 하며, 서버 밖으로 요청을 보내므로 조금 느립니다 |

가격을 바꾸는 즉시 고객에게 보이게 하려면 가격을 바꿀 때 Redis의 상품 캐시를 지우는 작업을 함께 해야 합니다. 캐시 보관 시간을 5분으로 그대로 두면 최대 5분 늦는 문제가 남습니다. Redis 서버가 멈추면 4대 모두 캐시를 쓰지 못하므로 이에 대한 대비가 필요합니다.
