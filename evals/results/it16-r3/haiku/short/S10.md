현재 가장 유력한 원인은 2.0.0에 새로 추가된 `exports` 필드(패키지가 외부에 공개하는 경로 목록)에 `@company/ui/button` 경로가 빠져 있는 것입니다. 이는 추론이며, 제공된 정보만으로 정리한 것이어서 2.0.0의 실제 `exports` 내용과 로그는 직접 확인하지 않았습니다.

### 확인된 사실

- 3일 전 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0부터 패키지에 `exports` 필드가 있습니다.
- CI는 Node 18을, 로컬은 Node 20을 사용합니다.
- CI 캐시 키(캐시를 구분하는 식별값)는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치됐습니다.

### 추론

- `exports` 필드가 있으면 Node와 번들러는 목록에 있는 서브패스(`@company/ui/button`처럼 패키지 안의 특정 경로)만 허용합니다. 목록에 없는 경로는 `Cannot find module` 에러로 실패합니다.
- 로컬 `node_modules`는 3일 전 이전에 설치된 것이므로 1.4.0 파일이 남아 있을 가능성이 높습니다. 따라서 로컬 빌드 성공은 2.0.0이 정상 동작한다는 증거가 되지 않습니다.
- `package-lock.json`이 2.0.0으로 갱신됐다면 해시가 바뀌어 CI 캐시가 무효화되고, CI는 2.0.0을 새로 설치합니다. 이 때문에 CI에서만 실패가 재현되는 것으로 보입니다.
- Node 18과 20의 차이는 보조 변수로 보는 것이 맞습니다. `exports` 해석 방식만으로는 두 버전의 차이가 크지 않으므로, Node 버전이 단독 원인일 가능성은 낮습니다.

### 미확인 사항

- 2.0.0의 `exports`에 `./button` 항목이 실제로 있는지는 확인하지 않았습니다.
- 로컬 `node_modules`에 실제로 설치된 버전은 확인하지 않았습니다.
- `package-lock.json`이 실제로 2.0.0으로 바뀌었는지는 확인하지 않았습니다.
- 2.0.0이 ESM(최신 모듈 방식) 전용 패키지인지 확인하지 않았습니다. 맞다면 Node 18에서 `require`가 실패할 수 있습니다.

### 확인 순서

1. 로컬과 CI 각각에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button` 항목이 있는지 확인합니다.
3. 로컬 `node_modules`를 삭제한 뒤 `npm ci`로 다시 설치하고 빌드합니다.
4. Node 18로 로컬에서 같은 빌드를 실행해 실패가 재현되는지 확인합니다.
