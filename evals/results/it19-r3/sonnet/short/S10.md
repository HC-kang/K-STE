가장 유력한 원인은 로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있고, CI만 2.0.0을 설치해서 생기는 차이입니다. 이 내용은 추론이며, 아래 방법으로 확인해야 합니다.

**근거가 되는 사실**

- 2.0.0에는 `exports` 필드(패키지가 외부에 공개하는 경로 목록)가 추가됐습니다.
- `exports`가 있는 패키지는 목록에 없는 경로를 import할 수 없습니다.
- 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로로 그대로 열렸습니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했으므로 1.4.0일 가능성이 높습니다.
- CI는 새로 설치하므로 2.0.0을 받을 가능성이 높습니다.

**추론**

2.0.0의 `exports`에 `./button`이 없거나 경로 이름이 달라졌다면, CI에서 `Cannot find module '@company/ui/button'`이 나는 것이 설명됩니다. 로컬은 1.4.0이라서 같은 import가 계속 성공했을 것입니다.

**가능성이 낮은 후보**

- Node 18과 20의 차이: 두 버전 모두 `exports`를 지원합니다. 이 차이만으로 이 에러가 생긴다는 근거는 없습니다.
- CI 캐시: 캐시 키가 `package-lock.json` 해시이므로 업그레이드로 lock 파일이 바뀌었다면 새 캐시가 만들어집니다. 다만 업그레이드 커밋에 lock 파일이 포함됐는지는 확인하지 못했습니다.

**확인 순서**

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다. 1.4.0이면 추론이 맞습니다.
2. 2.0.0의 `package.json`에서 `exports`에 `./button` 항목이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치하고 빌드합니다. CI와 같은 에러가 나면 원인이 확정됩니다.
4. 가능하면 로컬도 Node 18로 맞춰 다시 빌드해서 Node 차이를 배제합니다.

**수정 방향**

수정은 2.0.0의 `exports` 내용에 따라 둘 중 하나입니다.

- `exports`에 버튼 경로가 다른 이름으로 있으면, 앱의 import 경로를 그 이름으로 바꿉니다.
- `exports`에 버튼 경로가 없으면, `@company/ui` 쪽에서 `./button`을 `exports`에 추가해야 합니다.

PM 관점에서는 이 문제가 CI 환경 오류가 아니라 2.0.0 업그레이드의 호환성 문제일 가능성이 높습니다. 같은 import를 쓰는 다른 앱이나 파일에도 같은 에러가 생길 수 있으므로, 수정 전에 `@company/ui/` 하위 경로를 import하는 곳을 모두 찾아봐야 합니다.
