CI 빌드가 실패하는 원인은 CI가 `@company/ui` 2.0.0을 설치하고 로컬은 1.4.0을 쓰기 때문으로 보입니다. Node 18과 20의 차이는 원인이 아닌 것으로 보입니다.

## 근거

- `@company/ui` 2.0.0부터 패키지에 `exports` 필드가 있습니다. `exports`는 패키지가 외부에 공개하는 import 경로를 선언하는 `package.json` 항목입니다.
- `exports`가 있으면 Node와 번들러(빌드 도구)는 여기에 적힌 경로만 불러옵니다.
- `@company/ui/button`은 패키지 안의 하위 경로를 직접 가리킵니다. 2.0.0의 `exports`에 `./button`이 없으면 이 import는 `Cannot find module` 오류를 냅니다.
- 1.4.0에는 `exports`가 없었습니다. 그래서 같은 import가 파일 경로로 바로 해석됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다. 그래서 로컬에는 1.4.0이 남아 있는 것으로 보입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 2.0.0으로 올린 변경이 lockfile에 들어 있다면 키가 바뀌므로, CI는 캐시 없이 2.0.0을 새로 설치했을 것입니다.
- Node 18과 20은 모두 `exports`를 지원합니다. 그래서 두 버전 사이에서 이 오류가 갈릴 이유는 없습니다.

## 아직 확인하지 않은 것

- 2.0.0의 `exports`에 `./button`이 있는지
- 로컬에 실제로 설치된 `@company/ui` 버전
- 2.0.0으로 올린 변경이 `package-lock.json`에 들어 있는지

## 다음 단계

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 원인 추정이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button`이 있는지 보십시오. 로컬이 1.4.0이면 `rm -rf node_modules && npm ci`로 2.0.0을 설치한 뒤 보십시오.
3. 로컬에서 `npm ci` 후 빌드를 실행하십시오. CI와 같은 오류가 나면 원인이 확정됩니다.
4. `./button`이 `exports`에 없으면 2.0.0이 공개하는 경로로 import를 바꾸거나, `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청하십시오.

PM께 전달할 사항은 하나입니다. 2.0.0 업그레이드에 import 경로 변경이 필요하면 코드 수정 작업이 생깁니다. 4단계 결과가 나오면 작업량을 알 수 있습니다.
