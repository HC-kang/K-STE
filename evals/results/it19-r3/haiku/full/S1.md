Redis를 도입하면 4대 서버가 같은 캐시 내용을 보게 되므로, 서버마다 상품 정보가 달라지는 문제가 없어집니다.

캐시(자주 보는 데이터를 빨리 꺼내 쓰려고 잠시 복사해 둔 저장 공간)는 지금 각 서버의 메모리 안에 있습니다. Redis는 서버들 바깥에 따로 둔 공용 캐시 서버 1대이며, 서버 4대가 이 한 곳을 함께 봅니다.

| 구분 | 지금 (서버별 캐시) | Redis 도입 후 (공용 캐시) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 공용 캐시 서버 1대 |
| 서버 간 내용 | 서로 다를 수 있음 | 같은 내용을 봄 |
| 데이터를 꺼내는 방식 | 서버 안에서 바로 꺼냄 | 네트워크를 거쳐 Redis에서 꺼냄 |

지금은 가격을 바꾸면 서버마다 따로, 최대 5분 늦게 고객에게 반영됩니다. Redis를 쓰면 서버끼리 가격이 어긋나는 문제는 없어지지만, 고객에게 반영되기까지 걸리는 시간은 Redis의 캐시를 언제 새로 고치는지에 따라 달라집니다. 공용 캐시 서버 1대가 멈추면 4대 서버 모두 영향을 받을 수 있습니다.

확인 필요: 가격 변경 후 Redis 캐시를 바로 지우는지, 5분이 지난 뒤에 지우는지.
