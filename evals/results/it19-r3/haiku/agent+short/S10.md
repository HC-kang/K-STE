원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드로 보입니다. 이 필드 때문에 `@company/ui/button` 같은 하위 경로 import가 막혔을 가능성이 높습니다. 로컬 빌드는 3일 전에 설치한 1.4.0 기반 `node_modules`를 그대로 써서 통과하는 것으로 추정합니다. 전달해 주신 정보만으로 분석했고, 저장소 코드와 CI 로그는 아직 확인하지 않았습니다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `@company/ui` 버전 | 1.4.0 (추정) | 2.0.0 (추정) |
| `node_modules` 출처 | 업그레이드 전에 설치된 본 | `package-lock.json` 기준으로 새로 설치 (추정) |
| 빌드 결과 | 성공 | 실패 |

### 확인된 사실

- CI 빌드는 `@company/ui` 2.0.0 업그레이드 이후 `Cannot find module '@company/ui/button'` 에러로 실패합니다.
- 2.0.0 패키지에는 `exports` 필드가 추가되었습니다.
- CI는 Node 18을, 로컬은 Node 20을 사용합니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 업그레이드 이전에 설치되었습니다.

### 원인 추론

`exports` 필드가 있는 패키지에서는 목록에 없는 하위 경로를 import하면 실패합니다. 앱 코드가 `@company/ui/button`을 직접 import하고 2.0.0의 `exports`에 `./button` 경로가 없다면, 2.0.0을 설치한 CI에서 이 import가 실패합니다. 로컬에는 `exports`가 없는 1.4.0이 남아 있으므로 같은 import가 통과합니다. CI는 `package-lock.json`에 2.0.0이 기록되어 있다면 2.0.0을 새로 설치합니다.

캐시는 실패의 원인으로 보기 어렵습니다. lock 파일이 바뀌면 캐시 키도 바뀌어 새 설치가 일어나고, 그 설치본이 2.0.0이기 때문입니다.

Node 버전 차이도 원인일 가능성이 낮습니다. Node 18과 20은 모두 `exports` 필드를 지원합니다(일반적인 동작이며 확인 필요).

에러 문구도 확인해야 합니다. `Cannot find module`은 Node의 `require` 로더가 내는 문구입니다. Node가 `exports` 때문에 막으면 보통 `is not defined by "exports"` 문구가 나오고, webpack은 `Module not found` 문구를 냅니다. 따라서 에러가 앱 번들이 아닌 다른 스크립트(설정 파일, 빌드 도구 등)에서 나왔을 수도 있습니다.

### 확인 필요

- CI 로그에서 실제로 설치된 `@company/ui` 버전이 2.0.0인지 확인해야 합니다.
- 2.0.0 패키지의 `exports`에 `./button` 경로가 있는지 확인해야 합니다.
- 에러가 어느 단계(앱 빌드, 설정 스크립트, 타입 검사 등)에서 출력되었는지 확인해야 합니다.
- CI가 캐시를 복원한 뒤 설치하는지, `restore-keys` 설정이 있는지 확인해야 합니다.
- 로컬 `node_modules`의 실제 버전이 1.4.0인지 `npm ls @company/ui`로 확인해야 합니다.

### 권장 조치

1. 로컬에서 CI와 같은 조건으로 재현합니다. Node 18로 바꾼 뒤 `node_modules`를 지우고 `npm ci`로 다시 설치하고, `npm ls @company/ui`로 버전을 확인합니다.
2. 2.0.0 패키지의 `package.json`에서 `exports` 항목을 열어 `./button` 경로가 있는지 봅니다.
3. `./button` 경로가 없다면 앱의 import 경로를 2.0.0이 허용하는 경로로 바꿉니다. 패키지가 루트에서 `Button`을 내보낸다면 `import { Button } from '@company/ui'` 형태를 씁니다. 그 외에는 패키지 관리 담당자에게 `./button` 경로 추가를 요청합니다.
4. CI와 로컬의 Node 버전을 `.nvmrc` 또는 `engines` 필드로 맞추는 것을 권장합니다. 두 환경의 차이가 줄어들어 재현이 쉬워집니다.
