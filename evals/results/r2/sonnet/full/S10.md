원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰는 것일 가능성이 가장 높습니다. 로컬은 1.4.0, CI는 2.0.0으로 빌드하고 있을 수 있습니다.

로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것입니다. 그래서 로컬에는 `exports` 필드가 없는 1.4.0이 남아 있을 가능성이 큽니다. `exports`가 없으면 `@company/ui/button`은 파일 경로로 바로 찾아지므로 빌드가 성공합니다.

CI는 `package-lock.json`의 해시로 캐시 키를 만듭니다. 업그레이드로 lockfile이 바뀌었으므로 CI는 2.0.0을 새로 설치합니다. 2.0.0은 `exports` 필드를 가지므로, `exports`에 선언하지 않은 하위 경로는 import할 수 없습니다. `@company/ui/button`이 2.0.0의 `exports`에 없거나 이름이 바뀌었다면 이 에러가 납니다.

Node 18과 20의 차이는 원인이 아닐 가능성이 높습니다. 두 버전 모두 `exports`를 지원하기 때문입니다. 다만 두 버전에서 실제로 같은 결과가 나오는지는 확인하지 않았습니다.

아직 확인하지 않은 사항은 다음과 같습니다.
- 로컬에 설치된 `@company/ui`의 실제 버전
- 2.0.0 `package.json`의 `exports` 내용
- `button` 하위 경로가 2.0.0에서 제거됐는지, 이름이 바뀌었는지

확인 순서는 다음과 같습니다.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치 버전을 확인하십시오.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 다시 빌드하십시오. CI와 같은 에러가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에서 `./button` 항목이 있는지 확인하십시오.
4. 항목이 없으면 2.0.0 릴리스 노트나 변경 이력에서 새 import 경로를 찾아 코드를 고치십시오.

2번을 먼저 실행하십시오. 로컬에서 에러가 재현되면 CI 설정은 건드릴 필요가 없습니다.
