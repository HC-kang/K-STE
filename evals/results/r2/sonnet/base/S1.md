**한 줄 요약**
지금은 서버 4대가 각자 따로 기억을 갖고 있어서 서로 다른 정보를 보여줄 수 있는데, Redis를 도입하면 4대가 하나의 기억을 같이 쓰게 되어 가격 변경이 바로 반영됩니다.

**로컬 캐시 vs Redis 캐시**

- **로컬 캐시 (지금 방식)**: 서버 4대가 각자 자기 메모장에 상품 목록을 적어두고 씁니다. 빠르지만 메모장이 서버마다 따로라서, 한 곳에서 가격을 고쳐도 나머지 메모장은 그대로입니다.
- **Redis 캐시 (도입 예정)**: 4대가 공용 화이트보드 하나를 같이 봅니다. 한 번 고치면 모두가 같은 내용을 봅니다.

**우리 서비스에서 좋아지는 점**

1. **가격 변경이 즉시 반영됩니다.** 지금은 가격을 바꿔도 고객에게 최대 5분까지 예전 가격이 보일 수 있습니다. Redis 도입 후에는 변경 시점에 공용 캐시를 갱신하므로 이 지연이 사실상 사라집니다.
2. **고객마다 다른 가격을 보는 일이 줄어듭니다.** 지금은 새로고침할 때 어느 서버로 연결되느냐에 따라 가격이 달라 보일 수 있는데, 모든 서버가 같은 내용을 보게 됩니다.
3. **DB 부담이 줄어듭니다.** 지금은 서버 4대가 각자 DB에서 데이터를 가져와 캐시를 채우지만, 공용 캐시는 한 번만 채우면 됩니다.

**알아두실 점**

- Redis는 네트워크를 거치므로 서버 메모리를 직접 읽는 것보다 아주 조금 느립니다. 다만 DB를 조회하는 것에 비하면 훨씬 빠르고, 사용자가 체감할 수준은 아닙니다.
- 캐시 서버가 1대라서, 이 서버에 문제가 생기면 영향이 큽니다. 장애 시 DB로 대체 조회하는 방안과 모니터링은 함께 준비하겠습니다.
