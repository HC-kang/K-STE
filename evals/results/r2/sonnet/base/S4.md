# 운영 배포 롤백 런북 (payment-api)

## 개요
- **대상 서비스**: `payment-api`
- **배포 도구**: ArgoCD
- **목적**: 운영 환경 배포에 문제가 있을 때 이전 리비전으로 안전하게 되돌린다.

---

## 1. 롤백 전 확인 (필수)

### 1-1. DB 마이그레이션 포함 여부 확인
롤백 대상 배포(문제가 된 배포)에 **DB 마이그레이션이 포함되었는지 반드시 확인**한다.

- 배포 PR/커밋 내역, 마이그레이션 디렉터리 변경 사항, 릴리스 노트를 확인한다.

### 1-2. 판단

| 상황 | 조치 |
|---|---|
| 마이그레이션 **없음** | 2단계(롤백 실행)로 진행 |
| 마이그레이션 **포함됨** | **롤백하지 않는다.** 즉시 DBA **박지은**에게 연락하고 안내를 따른다. |

> ⚠️ 마이그레이션이 포함된 배포를 임의로 롤백하면 스키마와 애플리케이션 버전이 불일치해 장애가 커질 수 있다.

---

## 2. 롤백 실행

### 2-1. 롤백할 리비전 확인
```bash
argocd app history payment-api
```
정상 동작이 확인된 직전 리비전 번호(`<REVISION>`)를 확인한다.

### 2-2. 롤백 명령
```bash
argocd app rollback payment-api <REVISION>
```

### 2-3. 진행 상태 확인
```bash
argocd app get payment-api
```
Sync/Health 상태가 정상(`Synced` / `Healthy`)이 될 때까지 확인한다.

---

## 3. 롤백 후 검증 (필수)

1. **헬스체크**: `/healthz`가 **200**을 반환하는지 확인한다.
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" https://<운영-호스트>/healthz
   ```
2. **결제 테스트 주문**: 테스트 주문 **1건**이 성공적으로 결제되는지 확인한다.

둘 중 하나라도 실패하면 상황을 즉시 공유하고 추가 대응을 에스컬레이션한다.

---

## 4. 기록

롤백 이력을 **#deploy** 채널에 남긴다.

포함할 내용 예시:
- 롤백 일시 및 수행자
- 롤백 전/후 리비전
- 롤백 사유
- 마이그레이션 포함 여부 확인 결과
- `/healthz` 및 결제 테스트 주문 결과
