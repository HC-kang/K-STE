로컬 캐시는 각 API 서버가 자기 메모리(작업용 임시 저장 공간)에 상품 목록 사본을 따로 보관하는 방식이고, Redis는 서버 4대가 함께 쓰는 별도 캐시 서버(자주 쓰는 데이터를 빨리 꺼내려고 따로 저장해 두는 프로그램) 1대에 사본을 보관하는 방식입니다. Redis를 도입하면 서버 4대가 같은 값을 보게 되어, 서버마다 상품 정보가 달라지는 문제가 없어집니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리에 저장한다. | 별도 캐시 서버 1대에 저장한다. |
| 서버 간 값 | 서버마다 값이 다를 수 있다. | 4대 서버가 같은 값을 본다. |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영된다. | 가격 변경 시 Redis 값을 지우거나 바꾸는 작업을 해야 바로 반영된다. |
| 운영 부담 | 추가로 관리할 서버가 없다. | 캐시 서버 1대를 따로 관리해야 한다. |

Redis를 도입해도 가격 변경이 고객에게 바로 보이는지는 자동으로 정해지지 않습니다. 확인 필요: 가격을 바꿀 때 Redis 값을 지우거나 갱신하는 작업이 이번 계획에 포함되어 있는지 확인이 필요합니다. 또한 Redis 서버가 멈추면 서버 4대가 모두 영향을 받을 수 있으므로, 장애가 났을 때 대응 방법을 함께 정해야 합니다.
