# 운영 배포 롤백 런북

이 문서는 운영 환경의 payment-api 배포를 ArgoCD로 롤백하는 절차를 정리한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다. 마이그레이션이 포함됐으면 롤백하지 않고 DBA 박지은에게 연락한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 정상 동작을 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 1. 롤백 전 확인

1. 롤백할 대상 REVISION 값을 확인한다.
2. 현재 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다.

**마이그레이션이 포함됐으면 롤백하지 않는다. 롤백을 중단하고 DBA 박지은에게 연락한다.**

3. 마이그레이션이 포함되지 않은 경우에만 2단계로 진행한다.

## 2. 롤백 실행

4. 1번에서 확인한 값을 `<REVISION>` 자리에 넣고 다음 명령을 실행한다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 확인

5. `/healthz`가 200을 반환하는지 확인한다.
6. 결제 테스트 주문을 1건 진행하고 주문이 성공하는지 확인한다.

## 4. 기록

7. 롤백 이력을 #deploy 채널에 남긴다.

## 확인 필요

- 마이그레이션 포함 여부를 확인할 수 없는 경우의 처리가 지정되지 않았다.
- 5번 또는 6번이 실패한 경우의 조치가 지정되지 않았다.
