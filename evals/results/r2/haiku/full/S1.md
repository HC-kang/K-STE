로컬 캐시는 각 서버가 자기 메모리에 데이터를 임시로 보관하는 방식이고, Redis는 서버 4대가 함께 쓰는 별도의 캐시 서버입니다. 두 방식의 차이는 아래 표와 같습니다.

| 기준 | 로컬 캐시 (지금) | Redis 캐시 (도입 예정) |
|---|---|---|
| 캐시를 두는 곳 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 사이의 데이터 | 서버마다 내용이 다를 수 있음 | 4대가 같은 데이터를 봄 |
| 가격 변경 반영 | 서버마다 최대 5분 뒤 반영 | 가격 변경 처리 방식에 따라 달라짐 |
| 새로 생기는 부담 | 없음 | 캐시 서버 1대를 따로 운영해야 함 |

Redis를 쓰면 4대가 같은 상품 정보를 보기 때문에 서버마다 가격이 다르게 보이는 문제가 없어집니다. 다만 가격을 바꾼 뒤 바로 반영되려면 가격이 바뀔 때 Redis에 저장된 값을 지우거나 새로 고치는 처리가 함께 들어가야 합니다. 이 처리를 넣을지는 아직 정해지지 않았습니다. 캐시 서버가 멈추면 4대 서버 모두 영향을 받으므로, 이 점도 함께 검토해야 합니다.

확인 필요: 가격 변경 시 Redis 값을 지우는 처리를 이번 도입 범위에 포함하는지.
