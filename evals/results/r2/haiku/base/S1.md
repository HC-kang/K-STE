**Q. 로컬 캐시와 Redis 캐시는 뭐가 다른가요? Redis를 도입하면 우리 서비스에 뭐가 좋아지나요?**

**로컬 캐시**는 각 API 서버가 자기 메모리에 데이터 사본을 가지고 있는 방식입니다. 서버가 4대이므로 사본도 4개이고, 각 사본은 따로 갱신됩니다. 그래서 가격을 바꿔도 서버마다 반영 시점이 달라서, 지금은 고객이 최대 5분 동안 예전 가격을 볼 수 있습니다.

**Redis 캐시**는 서버 4대가 함께 보는 별도의 캐시 서버 1대에 데이터를 두는 방식입니다. 사본이 하나뿐이니 가격을 바꾸면 4대 서버가 같은 값을 보게 됩니다.

**Redis 도입으로 좋아지는 점**
- **가격 등 정보 반영이 빨라집니다.** 상품 정보가 바뀌면 캐시를 바로 갱신할 수 있어, 5분 지연 없이 거의 즉시 고객 화면에 반영할 수 있습니다.
- **서버마다 다른 데이터를 보는 문제가 사라집니다.** 같은 요청이 어느 서버로 가든 같은 결과를 줍니다.
- **서버를 늘리거나 재시작해도 캐시를 다시 채울 필요가 적습니다.** 새 서버는 빈 메모리에서 시작하지 않고 공용 캐시를 바로 사용합니다.

**주의할 점**
- 캐시 서버가 별도로 생기므로 **운영 부담이 늘고, 이 서버가 멈추면 영향이 커집니다.** 이중화 구성을 함께 검토해야 합니다.
- 서버가 Redis에 네트워크로 접속하므로, 메모리에서 바로 읽는 것보다 **아주 약간 느릴 수** 있습니다. 대부분의 경우 체감 차이는 작습니다.
- "가격 변경 시 캐시를 즉시 지운다"는 규칙을 개발 단계에서 정확히 구현해야 원하는 효과가 나옵니다.

**정리하면**, Redis 도입의 핵심 가치는 **"4대 서버가 같은 최신 데이터를 보게 하는 것"**입니다. 가격처럼 즉시 반영이 중요한 정보에 특히 효과가 큽니다.
