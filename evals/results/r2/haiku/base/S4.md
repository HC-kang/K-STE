# 운영 배포 롤백 런북: payment-api

| 항목 | 내용 |
|---|---|
| 대상 서비스 | payment-api (운영) |
| 배포 도구 | ArgoCD |
| 롤백 명령 | `argocd app rollback payment-api <REVISION>` |
| 필수 연락처 | DBA 박지은 (마이그레이션 포함 시) |
| 이력 기록 채널 | #deploy |

> **중요 규칙**
> 1. **DB 마이그레이션이 포함된 배포는 절대 롤백하지 않는다.** 마이그레이션이 포함됐다면 롤백을 중단하고 DBA 박지은에게 연락한다.
> 2. 롤백 전에 반드시 마이그레이션 포함 여부를 확인한다. 확인하지 않은 상태에서 롤백하지 않는다.

---

## 1. 사전 확인

### 1-1. 현재 상태와 배포 이력 확인
```bash
argocd app get payment-api
argocd app history payment-api
```
- 현재 배포된 리비전(Revision)과 롤백 대상 리비전을 기록한다.
- 롤백 대상 리비전은 직전 정상 배포 리비전이다. ID는 `argocd app history` 출력에서 확인한다.

### 1-2. DB 마이그레이션 포함 여부 확인 (필수, 롤백 전 반드시 수행)
현재 리비전과 롤백 대상 리비전 사이에 포함된 변경을 확인한다.

- 두 리비전 사이의 커밋/PR 목록을 확인한다.
- 마이그레이션 파일 변경이 있는지 확인한다. 예: `migrations/` 등 프로젝트의 마이그레이션 경로에 신규/변경 파일이 있는지 본다. (경로는 팀 프로젝트 구조에 맞게 수정한다.)
- 배포 PR 설명, 릴리스 노트에 DB 스키마 변경이 언급되었는지 확인한다.

**판단 기준**

| 결과 | 조치 |
|---|---|
| 마이그레이션 **포함** | **롤백 중단.** DBA 박지은에게 연락하고 5단계로 이동 |
| 마이그레이션 **미포함** 이 명확함 | 2단계로 진행 |
| 확인이 **불명확함** | 롤백하지 않는다. DBA 박지은 또는 배포 담당자에게 확인 후 진행 |

### 1-3. 롤백 가능 조건 확인
- ArgoCD 앱의 auto-sync가 꺼져 있어야 롤백 상태가 유지된다. 켜져 있다면 롤백 전에 비활성화하거나 팀 절차에 따른다.

---

## 2. 롤백 실행

```bash
argocd app rollback payment-api <REVISION>
argocd app wait payment-api --health --timeout 300
```

- `<REVISION>`은 1-1에서 확인한 롤백 대상 리비전 ID로 바꾼다.
- 완료 후 `argocd app get payment-api`로 Sync/Health 상태가 정상인지 확인한다.

---

## 3. 롤백 후 검증

### 3-1. 헬스체크
```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<payment-api 운영 호스트>/healthz
```
- **기대 결과: `200`**
- 200이 아니면 즉시 원인을 확인하고, 필요 시 에스컬레이션한다.

### 3-2. 결제 테스트 주문 1건
- 운영 결제 테스트 절차에 따라 **테스트 주문 1건**을 실행한다.
- **기대 결과: 주문 성공** (결제 승인, 주문 상태 정상 반영)
- 실패하면 롤백을 되돌리는 것을 포함해 즉시 대응 방안을 논의한다.

두 항목이 모두 통과해야 롤백 완료로 본다.

---

## 4. 이력 기록 (#deploy 채널)

롤백 후 #deploy 채널에 다음 내용을 남긴다.

```
[롤백] payment-api
- 시각: YYYY-MM-DD HH:MM (KST)
- 롤백 전 리비전: <REVISION_FROM>
- 롤백 후 리비전: <REVISION_TO>
- 롤백 사유: <사유>
- 마이그레이션 포함 여부: 미포함 (확인 방법: <확인 내용>)
- 검증: /healthz 200 확인 / 결제 테스트 주문 1건 성공
- 수행자: <이름>
```

---

## 5. 마이그레이션 포함 시 (롤백 중단)

1. **롤백하지 않는다.** 아무 명령도 실행하지 않는다.
2. DBA **박지은**에게 즉시 연락한다.
   - 전달 내용: 대상 서비스(payment-api), 현재 리비전, 롤백 대상 리비전, 포함된 마이그레이션 내용
3. DBA 판단에 따라 대응 방안을 정한다. (예: 마이그레이션 호환 처리, 순방향 수정 배포 등)
4. #deploy 채널에 롤백 중단 사실과 사유를 기록한다.
