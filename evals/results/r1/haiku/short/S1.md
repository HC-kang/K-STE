Redis는 4대 서버가 함께 쓰는 캐시 서버 1대이므로, 도입하면 서버마다 다른 상품 정보를 보는 문제가 없어집니다. 다만 Redis를 도입한다고 가격 변경이 바로 반영되지는 않습니다.

지금은 서버 4대가 각자 메모리(프로그램이 데이터를 임시로 올려 두는 공간)에 상품 목록 사본을 5분씩 보관합니다. 그래서 가격을 바꾸면 서버마다 사본이 갱신되는 시점이 달라서, 고객이 어느 서버에 연결되느냐에 따라 최대 5분 동안 다른 가격을 볼 수 있습니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 4곳 | 별도 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있다 | 4대 서버가 같은 데이터를 읽는다 |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영된다 | 가격 변경 시 Redis 캐시를 지우거나 갱신하면 모든 서버에 같은 시점에 반영된다 |
| 응답 속도 | 서버 안에서 바로 읽으므로 가장 빠르다 | 네트워크로 Redis에 접속하므로 로컬 메모리보다 느리다 |
| 장애 영향 | 서버 1대가 멈추면 그 서버의 사본만 사라진다 | Redis 서버가 멈추면 4대 서버 모두 캐시를 쓸 수 없게 된다 |

이번 도입으로 좋아지는 점은 서버 사이의 가격 불일치가 없어진다는 것입니다. 가격 반영 지연을 줄이려면 가격을 바꿀 때 Redis 캐시를 함께 지우는 작업이 필요합니다.

확인 필요: 이번 도입 범위에 가격 변경 시 Redis 캐시를 지우는 로직이 포함되는지 확인이 필요합니다. 포함되지 않으면 가격 반영은 여전히 캐시 만료 시점인 최대 5분 뒤에 이루어집니다.
