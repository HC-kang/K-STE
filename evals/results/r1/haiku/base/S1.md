**로컬 캐시 vs Redis 캐시 차이**

**지금 방식 (서버별 로컬 캐시)**
- 각 API 서버가 자기 메모리에 상품 목록을 5분간 저장해 둡니다.
- 서버 4대가 각자 따로 저장하기 때문에, 같은 시점이라도 서버마다 보는 데이터가 다를 수 있습니다.
- 가격을 바꾸면 각 서버의 캐시가 만료될 때까지 최대 5분 동안 옛날 가격이 보일 수 있습니다.

**Redis 도입 후 (공용 캐시 서버 1대)**
- 4대의 API 서버가 같은 캐시 서버를 함께 봅니다. 그래서 어느 서버에 접속하든 같은 데이터를 봅니다.
- 캐시를 한 곳에서 관리하므로, 가격을 바꿀 때 그 캐시만 지우거나 갱신하면 모든 서버에 한 번에 반영됩니다.
- 서버를 늘리거나 재시작해도 캐시가 각 서버에 따로 쌓이지 않아서 관리가 단순해집니다.

**우리 서비스에 좋아지는 점**
1. **가격 반영 지연 해소**: 가격 변경을 즉시 캐시에 반영하면 고객이 최대 5분 늦게 보던 문제가 줄어듭니다.
2. **데이터 일관성**: 서버마다 다른 상품 정보를 보여주는 문제가 없어집니다. 고객 입장에서는 같은 상품이 새로고침할 때마다 다르게 보이는 일이 줄어듭니다.
3. **서버 확장이 쉬워짐**: 나중에 서버를 더 늘려도 각 서버가 캐시를 따로 채울 필요가 없습니다.

**주의할 점**
- Redis만 도입한다고 가격이 자동으로 바로 반영되지는 않습니다. 가격을 수정할 때 Redis 캐시도 함께 지우거나 갱신하는 작업이 추가로 필요합니다. 이 작업이 들어가야 "즉시 반영"이 가능합니다.
- 캐시를 메모리에서 가져올 때보다 네트워크를 한 번 거치므로 조회가 아주 약간 느려질 수 있습니다. 다만 보통 수 밀리초 수준이라 체감은 거의 없습니다.
- Redis 서버가 멈추면 캐시를 쓸 수 없게 되므로, 장애 대비(이중화 등)를 함께 준비해야 합니다.

**한 줄 요약**
> Redis를 쓰면 서버 4대가 같은 상품 정보를 보게 되고, 가격 변경을 5분 기다리지 않고 바로 고객에게 반영할 수 있게 됩니다. 단, 가격 변경 시 캐시를 함께 갱신하는 작업이 같이 들어가야 합니다.
