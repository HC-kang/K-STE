로컬 캐시는 각 서버가 자기 메모리에 상품 목록을 따로 보관하는 방식이고, Redis는 캐시를 서버 밖의 공용 저장소 한 곳에 모아 두고 4대 서버가 함께 쓰는 방식입니다. 캐시는 자주 보는 데이터를 미리 복사해 두어 매번 원본을 조회하지 않게 하는 임시 보관 공간입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리 | 별도 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대 서버가 같은 내용을 봄 |
| 가격 변경 반영 | 각 서버의 5분 만료를 기다림 | 가격이 바뀔 때 캐시를 지우는 처리를 넣으면 4대에 같은 시점에 반영됨 |
| 조회 속도 | 가장 빠름 | 네트워크를 거쳐 가져오므로 로컬보다 느림 |

Redis 도입의 가장 큰 이점은 4대 서버가 같은 상품 정보를 보는 것입니다. 다만 이 효과는 가격이 바뀔 때 Redis의 캐시 데이터를 지우거나 고치는 처리를 넣어야 나타납니다. 이 처리를 넣지 않으면 Redis 데이터도 5분이 지나야 바뀌므로 지금과 차이가 없습니다. 현재 코드에 이 처리가 있는지는 확인하지 않았습니다.

조회 속도는 로컬 캐시보다 느립니다. 서버가 네트워크를 거쳐 Redis에서 데이터를 받아 오기 때문입니다. 이 차이가 고객 체감에 얼마나 영향을 주는지는 측정하지 않았습니다.

Redis 서버가 1대뿐이라서 이 서버가 멈추면 4대 서버 모두 캐시를 쓸 수 없습니다. 이때 서버가 원본 데이터를 가진 데이터베이스를 직접 조회하는지는 확인하지 않았습니다.

PM께서는 가격 변경이 고객 화면에 몇 분 안에 반영되어야 하는지 기준을 정해 주십시오. 개발팀이 그 기준에 맞춰 가격 변경 시 캐시를 처리하는 방식을 정합니다.
