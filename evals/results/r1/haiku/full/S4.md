# payment-api 운영 배포 롤백 런북

이 문서는 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정의한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인한다. **마이그레이션이 포함됐으면 롤백하지 않고 DBA 박지은에게 연락한다.**

## 1. 롤백 전 확인

1. 롤백할 대상 리비전 값을 `<REVISION>`에 준비한다.
2. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인한다.
3. 마이그레이션이 포함됐으면 롤백하지 않는다. DBA 박지은에게 연락한다.
4. 마이그레이션이 포함되지 않았음을 확인한 경우에만 다음 단계로 진행한다.

## 2. 롤백 실행

5. 아래 명령으로 롤백한다. `<REVISION>`은 1단계에서 준비한 리비전 값으로 바꾼다.

   `argocd app rollback payment-api <REVISION>`

## 3. 롤백 후 확인

6. `/healthz` 엔드포인트가 200을 반환하는지 확인한다.
7. 결제 테스트 주문을 1건 넣고 주문이 성공하는지 확인한다.

## 4. 이력 기록

8. #deploy 채널에 롤백 이력을 남긴다.

## 확인 필요

- 마이그레이션 포함 여부를 확인하는 방법이 주어지지 않았다. 확인 방법을 정한 뒤 1단계 2번에 추가해야 한다.
- 대상 리비전 값을 찾는 방법이 주어지지 않았다.
- `/healthz`를 확인할 대상 주소와 환경이 주어지지 않았다.
- 6번 또는 7번 확인이 실패했을 때의 조치 기준이 주어지지 않았다.
- #deploy 채널에 남길 이력의 형식과 항목이 주어지지 않았다.
