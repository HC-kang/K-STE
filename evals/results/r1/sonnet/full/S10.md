원인은 로컬 `node_modules`가 아직 `@company/ui` 1.4.0이고, CI만 2.0.0을 설치해서 `exports` 필드의 제약을 처음 받은 것으로 추정합니다. 주어진 정보에서 낸 추론이며 아직 확인하지 않았습니다.

근거는 다음과 같습니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했습니다. 로컬 빌드는 1.4.0으로 돌았을 가능성이 높습니다.
- 1.4.0에는 `exports` 필드가 없습니다. `@company/ui/button`은 패키지 안의 파일 경로로 그대로 풀립니다.
- 2.0.0에는 `exports` 필드가 있습니다. Node는 `exports`가 있는 패키지에서 거기에 선언한 서브패스만 허용합니다. `./button`이 선언되지 않았거나 이름이 바뀌었다면 `Cannot find module`이 납니다.
- CI 캐시 키가 `package-lock.json` 해시입니다. 락파일이 바뀐 시점부터 CI는 2.0.0을 새로 설치합니다.

Node 18과 20은 둘 다 `exports`를 지원합니다. Node 버전 차이는 주원인일 가능성이 낮지만 검증하지 않았습니다.

아직 확인하지 않은 것은 세 가지입니다. 로컬에 실제 설치된 `@company/ui` 버전, 락파일에 기록된 버전, 2.0.0의 `exports`에 `./button`이 있는지입니다.

확인 절차는 다음과 같습니다.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치 버전을 확인하십시오.
2. 2.0.0의 `package.json`에서 `exports`에 `./button`이 선언돼 있는지 확인하십시오.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드하십시오. CI와 같은 에러가 나면 원인이 확정됩니다.
4. 원인이 맞으면 `import` 경로를 `exports`에 선언된 경로로 바꾸십시오. 선언된 경로가 없으면 `@company/ui` 담당자에게 `./button` 서브패스 추가를 요청하십시오.

PM 기준으로 정리하면, 현재 로컬 빌드 성공은 2.0.0 업그레이드가 검증됐다는 뜻이 아닙니다. 위 3단계 결과가 나올 때까지 CI 빌드는 실패 상태로 남습니다.
