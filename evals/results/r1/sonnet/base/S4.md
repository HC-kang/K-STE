# 운영 배포 롤백 런북 (payment-api)

## 개요
- **배포 도구:** ArgoCD
- **대상 앱:** `payment-api`
- **목적:** 운영 배포에 문제가 생겼을 때 이전 리비전으로 안전하게 되돌린다.

## 1. 롤백 전 확인 (필수)

**롤백하려는 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다.**

- **마이그레이션이 포함됐다면: 롤백하지 않는다.** DBA **박지은**에게 즉시 연락하고 안내에 따른다.
- **마이그레이션이 포함되지 않았다면:** 2단계로 진행한다.

> ⚠️ 마이그레이션이 포함된 배포를 롤백하면 애플리케이션 코드와 DB 스키마가 어긋나 장애가 커질 수 있다. 확신이 없으면 롤백 전에 박지은에게 확인한다.

## 2. 롤백 대상 리비전 확인

```bash
argocd app history payment-api
```

되돌릴 `<REVISION>`을 확인한다. 보통 직전의 정상 배포 리비전이다.

## 3. 롤백 실행

```bash
argocd app rollback payment-api <REVISION>
```

## 4. 롤백 후 검증

1. **헬스체크:** `/healthz`가 **200**을 반환하는지 확인한다.
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" https://<운영-호스트>/healthz
   ```
2. **결제 테스트:** 테스트 주문 **1건**이 성공하는지 확인한다.

둘 중 하나라도 실패하면 아래 에스컬레이션 절차를 따른다.

## 5. 이력 기록

롤백 이력을 **#deploy** 채널에 남긴다. 기록할 내용은 다음과 같다.

- 롤백 시각
- 롤백 전/후 리비전
- 롤백 사유
- 마이그레이션 포함 여부 확인 결과
- `/healthz` 및 결제 테스트 주문 결과
- 실행자

## 에스컬레이션

| 상황 | 조치 |
|---|---|
| 배포에 DB 마이그레이션이 포함됨 | 롤백 중단, DBA 박지은에게 연락 |
| 롤백 후 `/healthz`가 200이 아님 | #deploy에 공유하고 담당자에게 에스컬레이션 |
| 결제 테스트 주문 실패 | #deploy에 공유하고 담당자에게 에스컬레이션 |
