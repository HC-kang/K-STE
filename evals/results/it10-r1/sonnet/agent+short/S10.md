로컬이 `@company/ui` 1.4.0을 계속 쓰고 있고 CI는 2.0.0을 설치하기 때문에 결과가 달라진 것으로 보입니다. 아직 검증하지 않은 추론입니다.

## 근거

- 3일 전 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다. 2.0.0에는 `exports` 필드(패키지가 바깥에 공개하는 import 경로 목록)가 추가됐습니다.
- `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 다른 경로로 바뀌었다면 `@company/ui/button`을 찾지 못합니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치했습니다. 그래서 로컬에는 `exports`가 없는 1.4.0이 남아 있을 가능성이 큽니다. 1.4.0은 파일 경로로 직접 import할 수 있으므로 로컬 빌드는 성공합니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 lockfile이 바뀌었으므로 CI는 캐시를 쓰지 않고 2.0.0을 새로 설치했을 것입니다. 그래서 CI에서만 실패합니다.

## Node 버전의 영향

Node 18과 Node 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 원인일 가능성이 낮습니다. 이 판단도 실제로 실행해서 검증하지 않았습니다.

## 아직 모르는 것

- 로컬 `node_modules/@company/ui/package.json`의 실제 버전
- 2.0.0 `exports`에 `./button`이 들어 있는지, 들어 있다면 어떤 경로인지

## 검증 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다. 1.4.0이면 위 추론이 맞습니다.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 오류가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에서 `./button` 항목을 찾습니다.

## 해결 방향

`exports`에 `./button`이 없거나 경로가 바뀌었으면 import 경로를 2.0.0이 공개한 경로로 바꿔야 합니다. 2.0.0에서 `./button`이 빠진 것이 의도가 아니라면 `@company/ui` 담당자에게 `exports` 수정을 요청해야 합니다. 두 방향 중 무엇이 맞는지는 3번 결과를 본 뒤 정할 수 있습니다.
