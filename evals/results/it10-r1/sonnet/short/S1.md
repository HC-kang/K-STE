로컬 캐시는 서버 4대가 각자 따로 저장해 두는 방식이고, Redis 캐시는 서버 4대가 하나를 같이 쓰는 방식입니다. 그래서 Redis를 도입하면 서버마다 상품 목록이 다르게 보이는 문제가 없어집니다.

지금은 서버마다 자기 메모리에 상품 목록을 5분 동안 캐시(자주 쓰는 데이터를 미리 저장해 두고 빨리 꺼내 쓰는 곳)합니다. 서버마다 캐시 내용이 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 캐시 전용 서버 1대에 상품 목록을 저장하고, API 서버 4대가 그 서버를 같이 읽습니다. 그래서 고객 요청이 어느 서버로 가도 같은 상품 목록이 보입니다.

가격 반영 지연이 얼마나 줄어드는지는 아직 확인하지 못했습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지우도록 만들면 지연을 줄일 수 있습니다. 5분 만료만 기다리면 최대 5분 지연은 그대로 남을 수 있습니다.

Redis 서버를 1대만 두기 때문에, 이 서버에 문제가 생기면 API 서버 4대가 모두 영향을 받을 수 있습니다. 이 경우에 서비스가 어떻게 동작하는지도 아직 확인하지 못했습니다.
