CI(코드 변경 때 자동으로 빌드하는 환경)에서만 나는 실패의 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개할 import 경로를 정하는 설정)로 보입니다. 로컬 `node_modules`(설치된 패키지를 담는 폴더)는 3일 전 업그레이드보다 먼저 설치한 것이므로, 로컬 빌드는 1.4.0으로 실행됐을 수 있습니다. 이 경우 로컬 빌드 성공은 2.0.0에서 빌드가 된다는 근거가 되지 못합니다.

2.0.0의 `exports`에 `./button` 경로가 없으면, `@company/ui/button`을 import할 때 `Cannot find module` 오류가 납니다. 이 분석에는 2.0.0의 `exports` 내용이 없으므로 이 부분은 추론입니다.

Node 18도 `exports`를 지원하므로 Node 버전 차이가 원인일 가능성은 낮습니다. CI 캐시 키가 `package-lock.json`의 해시(파일 내용에서 계산한 값)이므로, 업그레이드 때 이 파일이 바뀌었다면 CI는 오래된 캐시를 쓰지 않았을 것입니다.

추론을 검증하려면 다음 순서로 진행하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 조회하십시오.
2. `node_modules`를 지우고 `npm ci`로 다시 설치하십시오.
3. 로컬에서 빌드를 다시 실행하십시오.
4. 빌드가 실패하면 `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오.

로컬에서 같은 오류가 재현되고 `exports`에 `./button`이 없으면, `@company/ui`의 `exports`에 `./button`을 추가하거나 import 경로를 2.0.0이 공개한 경로로 바꿔야 합니다.
