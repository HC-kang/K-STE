# 운영 배포 롤백 런북

ArgoCD로 배포한 `payment-api`의 운영 배포를 롤백하는 절차를 설명한다. 롤백 전에 그 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 롤백한 뒤에는 `/healthz` 응답과 결제 테스트 주문을 확인해야 하고, 롤백 이력은 #deploy 채널에 남겨야 한다.

## 절차

**마이그레이션이 포함된 배포는 롤백하면 안 된다.**

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하지 않고 DBA 박지은에게 연락한다.
3. 마이그레이션이 포함되지 않았으면 아래 명령을 실행한다. `<REVISION>` 자리에는 롤백할 리비전을 쓴다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

4. 롤백이 끝나면 `/healthz`가 200을 반환하는지 확인한다.
5. 결제 테스트 주문 1건이 성공하는지 확인한다.
6. 롤백 이력을 #deploy 채널에 남긴다.

## 이 런북에 없는 정보

- 배포에 마이그레이션이 포함됐는지 확인하는 방법
- `<REVISION>` 값을 찾는 방법
- `/healthz`의 호출 주소와 결제 테스트 주문을 넣는 방법
- 박지은에게 연락하는 방법
- #deploy 채널에 적어야 할 내용
