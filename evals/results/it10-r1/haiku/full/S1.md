Redis를 도입해도 가격 변경이 고객에게 늦게 보이는 문제는 Redis만으로 해결되지 않습니다. Redis를 도입하면 4대 서버가 같은 캐시를 보게 되지만, 캐시를 5분 동안 유지하는 설정이 그대로 남으면 가격 반영은 여전히 최대 5분 늦어집니다.

로컬 캐시는 각 API 서버(앱과 웹이 상품 정보를 요청하는 서버) 자기 메모리에 임시로 저장해 둔 데이터입니다. 서버마다 따로 저장하므로 서버 A가 가진 내용을 서버 B는 알지 못합니다. 그래서 가격을 바꾼 뒤에도 서버에 따라 이전 가격이 잠시 보일 수 있습니다.

Redis는 여러 서버가 함께 쓰는 별도의 캐시 서버입니다. 4대 서버가 같은 곳을 보므로 서버마다 내용이 달라지는 문제가 없어집니다. 대신 서버가 Redis에 요청을 한 번 더 보내야 하므로 로컬 캐시보다 응답이 조금 느릴 수 있습니다.

가격을 바꾸자마자 고객에게 보이게 하려면 가격이 바뀔 때 Redis의 캐시 데이터를 바로 지우거나 새로 저장하는 작업이 필요합니다. 이 작업을 넣을지, 아니면 캐시 유지 시간을 5분보다 짧게 줄일지는 개발팀이 정해야 합니다.

확인 필요: 이번 Redis 도입 범위에 가격 변경 시 캐시를 바로 지우는 작업이 포함되는지, 또는 캐시 유지 시간을 줄이는지 개발팀에 물어봐 주십시오. 두 방법 중 무엇을 택하느냐에 따라 고객에게 가격이 바로 보이는 시점이 달라집니다.
