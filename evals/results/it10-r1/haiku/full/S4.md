# payment-api 배포 롤백 런북

이 문서는 ArgoCD로 배포한 payment-api를 이전 리비전으로 되돌리는 절차를 정한다. 배포에 DB 마이그레이션이 포함되었으면 롤백하지 않고 DBA에게 연락해야 한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 정상 동작을 확인하고, 이력을 #deploy 채널에 남긴다.

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락하고 다음 단계로 넘어가지 않는다.
3. 마이그레이션이 포함되지 않았으면 4번 단계로 진행한다.

## 2. 롤백 실행

4. 터미널에서 `argocd app rollback payment-api <REVISION>`을 실행한다. `<REVISION>`에는 되돌릴 대상 리비전을 넣는다.

## 3. 롤백 후 확인

5. `/healthz`가 200을 반환하는지 확인한다.
6. 결제 테스트 주문 1건이 성공하는지 확인한다.

## 4. 이력 기록

7. #deploy 채널에 롤백 이력을 남긴다.

## 확인 필요

- 확인 필요: 대상 리비전(`<REVISION>`) 값을 어디서 확인하는지. 예를 들어 ArgoCD 이력 화면인지 배포 기록인지 알 수 없다.
- 확인 필요: 배포에 마이그레이션이 포함됐는지 어떤 방법으로 확인하는지. 변경 내역을 보는지, 마이그레이션 파일을 보는지 정해져 있지 않다.
- 확인 필요: `/healthz`를 호출할 주소와 결제 테스트 주문을 실행하는 방법. 주소와 방법이 정해져 있지 않다.
