이 런북은 운영 환경의 payment-api 배포를 ArgoCD(배포를 자동화하는 도구)로 이전 리비전(revision, 배포 버전 식별자)으로 되돌리는 절차를 정한다.

## 절차

1. 롤백 대상 배포에 DB 마이그레이션(데이터베이스 구조를 바꾸는 변경 스크립트)이 포함되었는지 확인한다.
2. 마이그레이션이 포함되었으면 **롤백하면 안 된다.** 이 경우 DBA 박지은에게 연락한다.
3. 마이그레이션이 포함되지 않았으면 롤백 명령을 실행한다: `argocd app rollback payment-api <REVISION>`
4. 롤백 후 `/healthz`가 200을 반환하는지 확인한다.
5. 결제 테스트 주문 1건이 성공하는지 확인한다.
6. #deploy 채널에 롤백 이력을 남긴다.

## 확인 필요

- 롤백 대상 배포에 마이그레이션이 포함되었는지 확인하는 구체적인 방법과 도구를 확인 필요: 사용할 도구나 조회 위치가 정해져 있지 않다.
- `<REVISION>`에 넣을 값을 찾는 방법을 확인 필요: 배포 이력을 조회하는 명령이나 화면이 정해져 있지 않다.
- 결제 테스트 주문을 실행하는 방법을 확인 필요: 테스트 주문 절차나 테스트 계정이 정해져 있지 않다.
- 롤백 후 `/healthz`가 200을 반환하지 않거나 테스트 주문이 실패하면 어떻게 할지 확인 필요: 이 상황의 대응 절차가 정해져 있지 않다.
