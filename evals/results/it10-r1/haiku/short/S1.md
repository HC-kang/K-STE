로컬 캐시는 서버 한 대의 메모리에 상품 목록을 따로 저장하고, Redis 캐시는 서버 4대가 함께 쓰는 공용 저장 서버 1대에 상품 목록을 저장합니다. Redis를 도입하면 4대 서버가 같은 상품 목록을 보게 되어, 서버마다 가격이 다르게 보이는 문제가 줄어듭니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버마다 각자의 메모리 | 공용 Redis 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영됨 | 캐시를 갱신하는 시점에 함께 반영됨 |

우리 서비스에서 좋아지는 점은 고객이 어느 서버에 연결되든 같은 가격을 보게 된다는 것입니다. 다만 Redis를 쓴다고 가격이 즉시 바뀌는 것은 아닙니다. 반영 시점은 가격을 바꿀 때 Redis의 상품 목록을 지우거나 새로 쓰는 방식에 달려 있습니다. 확인 필요: 가격을 바꿀 때 Redis 캐시를 바로 갱신하도록 설계되어 있는지 개발팀에 확인해야 합니다.

Redis를 쓰면 조회 한 번마다 네트워크를 거치므로 로컬 메모리보다 응답이 조금 느려질 수 있습니다. 또한 Redis 서버 1대에 문제가 생기면 4대 서버가 모두 영향을 받을 수 있습니다(추론). 이 두 가지는 도입 전에 검토가 필요합니다.
