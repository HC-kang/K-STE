Redis를 도입하면 서버 4대가 같은 캐시를 보게 되어, 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 Redis만 도입해서는 가격 변경이 바로 반영되지 않습니다. 가격이 바뀔 때 캐시를 지우거나 새 값으로 바꾸는 처리가 따로 있어야 즉시 반영됩니다.

두 방식의 차이는 다음과 같습니다. 캐시는 자주 쓰는 데이터를 빠르게 꺼내 쓰려고 임시로 저장해 두는 곳입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 캐시 위치 | 각 API 서버 안의 메모리(임시 작업 공간) | 캐시 전용 서버 1대 |
| 서버 간 데이터 | 서버마다 따로 저장돼 내용이 다를 수 있습니다 | 4대가 같은 캐시를 함께 봅니다 |
| 가격 변경 후 반영 | 서버마다 최대 5분 늦게 반영됩니다 | 캐시 유지 시간을 5분으로 두면 최대 5분 늦게 반영됩니다 |
| 데이터 이동 | 서버 안에서 바로 꺼냅니다 | 네트워크를 거쳐 꺼내므로 로컬 캐시보다 느립니다 |
| 운영 부담 | 추가 서버가 없습니다 | Redis 서버를 따로 관리해야 합니다 |

확인 필요: 이번 도입 계획에 가격 변경 시 캐시를 갱신하는 처리가 포함돼 있는지 개발팀에 확인해야 합니다. 이 처리가 있어야 가격 반영 시간이 5분에서 줄어듭니다.
