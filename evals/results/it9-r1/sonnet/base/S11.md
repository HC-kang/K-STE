# API 키 관리 지침

## 1. 목적과 적용 범위

이 문서는 API 키의 교체, 저장, 보관에 관한 규칙을 정한다. 운영 환경 API 키와 개발 환경 API 키에 모두 적용하되, 환경별로 적용되는 규칙이 다르다. 규칙별 적용 환경은 아래 요약표에서 확인한다.

## 2. 규칙 요약

| 구분 | 규칙 | 운영 환경 | 개발 환경 |
|---|---|---|---|
| 필수 | 90일마다 키를 교체한다. 예외는 없다. | 적용 | 적용하지 않음 |
| 금지 | API 키를 Git 저장소에 커밋하지 않는다. | 적용 | 적용 |
| 필수 | 교체한 키를 Vault `prod/api-keys` 경로에 저장한다. | 적용 | 해당 없음 |
| 권장 | 평일 업무 시간(10:00-18:00)에 키를 교체한다. | 적용 | 해당 없음 |

## 3. 규칙 상세

### 3.1 교체 주기 (필수)

- 운영 환경 API 키는 **90일마다 교체해야 한다.** 이 규칙에는 예외가 없다.
- 개발 환경 API 키에는 90일 교체 규칙을 적용하지 않는다.

### 3.2 Git 커밋 금지 (금지)

- API 키를 Git 저장소에 **커밋해서는 안 된다.**
- 이 규칙은 운영 환경과 개발 환경 키에 모두 적용된다.

### 3.3 교체 시간대 (권장)

- 키 교체는 평일 업무 시간(10:00-18:00)에 하는 것을 **권장한다.** 필수 사항은 아니다.
- 장애 대응 중이라면 업무 시간 밖에 교체해도 된다.

### 3.4 저장 위치 (필수)

- 교체한 키는 Vault의 `prod/api-keys` 경로에 **저장해야 한다.**

## 4. 참고: Vault 웹 화면의 키 발급 기능

Vault 웹 화면에는 키를 직접 발급하는 기능이 있다. 이 항목은 기능의 존재를 알리는 설명이며, 사용을 요구하거나 금지하는 규칙이 아니다.

---

작성 시 다음 사항을 반영했습니다.

- 원문의 강도를 구분해 "필수 / 금지 / 권장 / 허용"으로 표기했습니다. "장애 대응 중 업무 시간 외 교체"는 허용으로, "Vault 웹 화면 발급 기능"은 규칙이 아닌 사실 설명으로 두었습니다.
- "개발 환경 키는 90일 규칙을 지킬 필요가 없다"는 개발 환경에 대한 면제이므로, 90일 규칙의 "예외 없음"과 충돌하지 않도록 적용 범위를 표에 분리해 적었습니다.
- Git 커밋 금지는 원문에 환경 구분이 없어 두 환경 모두에 적용되는 것으로 적었습니다. 개발 환경 키를 커밋해도 되는지 의도가 다르다면 알려주세요.
- 저장 경로 `prod/api-keys`는 이름상 운영 환경 키용으로 보여, 개발 환경 키의 저장 위치는 "해당 없음"으로 두었습니다. 개발 환경 키의 저장 위치가 따로 정해져 있다면 추가하겠습니다.
