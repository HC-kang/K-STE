원인은 로컬 `node_modules`가 아직 `@company/ui` 1.4.0이고, CI는 2.0.0을 설치하기 때문으로 보입니다. 아직 확인하지 않은 추론입니다.

**사실**
- CI에서만 `Cannot find module '@company/ui/button'` 에러가 납니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0부터 패키지에 `exports` 필드가 있습니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치했습니다.
- CI 캐시 키는 `package-lock.json` 해시입니다.
- CI는 Node 18, 로컬은 Node 20입니다.

**추론**
- `package.json`에 `exports`가 있으면 Node와 번들러는 `exports`에 적은 경로만 import할 수 있게 합니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`처럼 파일 경로로 바로 import할 수 있었습니다.
- 2.0.0의 `exports`에 `./button` 항목이 없으면 같은 import가 실패합니다.
- 로컬은 `node_modules`를 다시 설치하지 않았으므로 1.4.0으로 빌드하고 있을 가능성이 큽니다.
- 업그레이드로 `package-lock.json`이 바뀌었다면 해시도 바뀌어서 CI 캐시가 무효가 됩니다. 그러면 CI는 lockfile 기준으로 2.0.0을 새로 설치합니다. 확인 필요: 업그레이드 커밋에 `package-lock.json` 변경이 포함됐는지.
- Node 18과 20의 차이는 원인일 가능성이 낮다고 봅니다. 두 버전 모두 `exports`를 지원합니다. 다만 아직 배제하지 못했습니다.

| 항목 | 로컬 | CI |
|---|---|---|
| `@company/ui` 버전 | 1.4.0으로 추정 | 2.0.0 |
| `exports` 적용 | 적용 안 됨 | 적용됨 |
| Node | 20 | 18 |

확인 순서는 다음과 같습니다. 아직 아무것도 실행하지 않았습니다.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인한다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인한다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 `npm run build`를 실행해 같은 에러가 나는지 확인한다.
4. 3번에서 에러가 나지 않으면 Node 18로 3번을 반복한다.

3번에서 에러가 재현되고 `exports`에 `./button`이 없다면, 해결 방법은 둘 중 하나입니다.
- 앱의 import 경로를 2.0.0 `exports`에 있는 경로로 바꾸는 방법입니다.
- `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청하는 방법입니다.

앱 import 경로를 바꾸는 쪽을 권장합니다. 2.0.0에서 `./button`을 뺀 것이 의도인지는 담당자에게 확인해야 합니다.

PM께 알립니다. 원인이 확인되기 전까지는 CI 실패가 일시적인 문제가 아니라 2.0.0 업그레이드에 따른 변경일 가능성이 큽니다. 같은 import를 쓰는 다른 화면도 영향을 받을 수 있습니다.
