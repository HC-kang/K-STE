원인은 `@company/ui` 2.0.0의 `exports` 필드에 `./button` 경로가 없기 때문으로 보입니다. 로컬은 2.0.0 이전 버전이 설치된 상태라서 같은 문제가 드러나지 않았습니다. 이 결론은 추론이며, 아래 확인 단계로 검증해야 합니다.

**확인된 사실**
- 빌드는 CI에서만 실패하고 로컬에서는 성공합니다.
- 에러는 `Cannot find module '@company/ui/button'`입니다.
- `@company/ui`를 3일 전에 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가됐습니다. `exports`는 패키지가 외부에 공개하는 경로의 목록입니다.
- 로컬 `node_modules`는 업그레이드보다 먼저 설치했습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

**추론**
- 로컬 `node_modules`에는 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports`가 없으므로 `@company/ui/button`처럼 파일 경로를 직접 지정한 import가 동작합니다.
- 업그레이드로 `package-lock.json`이 바뀌었으므로 CI 캐시 키도 바뀌었습니다. 그래서 CI는 2.0.0을 새로 설치했을 것입니다.
- `exports`가 있는 패키지에서는 Node와 번들러(코드를 하나로 묶는 도구)가 `exports`에 적힌 경로만 허용합니다. 2.0.0의 `exports`에 `./button`이 없으면 이 에러가 납니다.
- Node 18과 20은 모두 `exports`를 지원합니다. 그래서 Node 버전 차이가 주원인일 가능성은 낮습니다. 다만 직접 검증하지는 않았습니다.

**확인 필요:** 2.0.0의 `exports`에 `./button`이 실제로 있는지, 그리고 로컬에 실제로 설치된 버전이 무엇인지 확인해야 합니다. `./button`이 있어도 조건(`import`, `require` 등)이 맞지 않아 실패할 가능성이 있습니다.

**검증 순서**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다.
2. `node_modules/@company/ui/package.json`의 `exports`에서 `./button` 항목을 찾습니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 에러가 나면 위 추론이 맞습니다.

원인이 확인되면 대응 방법은 세 가지입니다.
- `exports`에 공개된 경로로 import를 바꿉니다.
- `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.
- 배포가 급하면 1.4.0으로 되돌립니다.
