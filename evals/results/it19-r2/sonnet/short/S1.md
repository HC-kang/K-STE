가장 큰 차이는 캐시(자주 쓰는 데이터를 미리 저장해 둔 사본)를 서버마다 따로 갖는지, 서버 4대가 함께 쓰는지입니다.

지금은 API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 서버마다 저장한 시점이 달라서 캐시 내용이 서로 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis를 도입하면 캐시 서버 1대를 API 서버 4대가 같이 씁니다. 그래서 서버마다 캐시 내용이 달라지는 문제가 없어집니다. 고객은 어느 서버에 접속해도 같은 상품 목록을 봅니다.

가격 반영 지연은 가격을 바꿀 때 Redis의 캐시를 바로 지우거나 새로 쓰면 줄일 수 있습니다. Redis를 도입하는 것만으로 지연이 없어지지는 않습니다.

확인 필요: 가격을 바꿀 때 Redis 캐시를 바로 갱신하는지, 5분 만료를 기다리는지 정해져 있습니까?

주의할 점도 두 가지 있습니다. Redis는 네트워크를 거쳐 읽기 때문에 서버 자기 메모리보다 응답이 조금 느립니다. Redis 서버가 1대라서, 이 서버가 멈추면 상품 목록 조회에 어떤 영향이 있는지도 확인이 필요합니다.
