로컬 캐시는 서버 4대가 각자 자기 메모리에 따로 저장하고, Redis는 4대가 함께 쓰는 공용 캐시 서버 1대에 저장합니다. 캐시(자주 쓰는 데이터를 빠르게 꺼내려고 미리 보관해 두는 곳)를 어디에 두느냐가 두 방식의 차이입니다.

| 구분 | 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | 서버마다 자기 메모리에 저장합니다 | 공용 서버 1대에 저장합니다 |
| 서버 4대가 보는 내용 | 서버마다 달라질 수 있습니다 | 같은 내용을 봅니다 |
| 가져오는 속도 | 서버 안에서 바로 꺼냅니다 | 네트워크를 거쳐 가져오므로 조금 느립니다 |
| 장애 시 영향 | 문제가 생긴 서버만 영향을 받습니다 | 공용 서버가 멈추면 4대 모두 영향을 받습니다 |

Redis를 도입하면 서버끼리 캐시 내용이 어긋나는 문제는 없어집니다. 캐시를 4대가 함께 쓰므로 상품 정보를 저장한 데이터베이스(DB)를 조회하는 횟수도 줄어들 수 있습니다.

다만 가격 변경이 고객에게 늦게 반영되는 문제는 Redis 도입만으로 해결되지 않습니다. 캐시 유효 시간이 5분으로 그대로라면 최대 5분 지연은 남습니다. 가격을 바꿀 때 Redis에 저장된 캐시를 지우거나 새 값으로 바꾸면 다음 조회부터 새 가격이 보입니다. 확인 필요: 이번 도입 범위에 가격 변경 시 캐시를 지우는 작업이 포함되는지 개발팀에 확인해야 합니다.
