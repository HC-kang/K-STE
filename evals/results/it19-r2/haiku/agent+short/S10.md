지금 받은 정보만으로는 원인을 확정할 수 없습니다. 가능성이 가장 높은 원인은 로컬 `node_modules`에 업그레이드 전 버전(1.4.0)이 남아 있어서, 로컬 빌드가 2.0.0 변경을 검증하지 못했다는 것입니다. 이것은 추론이며, 명령 한 줄로 확인할 수 있습니다.

### 입력으로 받은 사실

- `@company/ui`는 3일 전 1.4.0에서 2.0.0으로 올라갔습니다.
- 2.0.0에는 `exports` 필드(패키지 외부에 공개할 파일 경로를 정한 설정)가 새로 생겼습니다.
- CI는 Node 18을, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시(파일 내용을 줄인 식별값)입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치됐습니다.
- 에러는 CI 빌드에서만 나며, 메시지는 `Cannot find module '@company/ui/button'`입니다.

### 원인 가설 (가능성 순)

| 순위 | 가설 | 근거 | 확인 방법 |
|---|---|---|---|
| 1 | 로컬에 1.4.0이 남아 있습니다 | 로컬 `node_modules`가 업그레이드 전에 설치됐습니다. | `npm ls @company/ui` 실행 |
| 2 | 2.0.0의 `exports`에 `button` 경로가 없습니다 | `exports`가 있으면 공개된 경로만 가져올 수 있습니다. | 2.0.0의 `package.json`과 실제 파일 경로 비교 |
| 3 | CI가 예전 설치 결과를 씁니다 | 캐시 키가 lock 파일 해시이므로, 이전 키로 복원하는 설정이 있으면 예전 `node_modules`가 쓰입니다. | CI 로그에서 캐시 적중 여부와 설치 명령 확인 |
| 4 | 대소문자 차이가 있습니다 | macOS는 기본적으로 대소문자를 구분하지 않고, Linux 기반 CI는 구분합니다. | import 경로와 패키지 파일명의 대소문자 비교 |
| 5 | Node 18 차이가 있습니다 | Node 18과 20은 모두 `exports`를 지원하므로 버전 차이만으로는 설명이 어렵습니다. | Node 18 환경에서 로컬 재현 |

에러 메시지도 단서입니다. Node 자체가 `exports` 규칙 위반을 감지하면 보통 `ERR_PACKAGE_PATH_NOT_EXPORTED` 같은 다른 메시지를 냅니다. 따라서 `Cannot find module` 메시지는 번들러(Next.js가 쓰는 빌드 도구)가 냈을 가능성이 있습니다. 어느 쪽인지는 실패 위치를 보여 주는 스택 트레이스(에러가 발생한 호출 경로 기록)로 판단할 수 있습니다.

### 미확인 항목

- 전체 스택 트레이스가 없어서 실패한 파일과 호출 위치를 알 수 없습니다.
- 2.0.0의 `exports` 내용과 실제 파일 목록을 아직 보지 않았습니다.
- 확인 필요: 2.0.0 업그레이드 커밋에 `package-lock.json`이 함께 들어갔는지 알 수 없습니다.
- CI의 설치 명령이 `npm ci`인지 `npm install`인지, 캐시 복원 설정에 이전 키 대체 규칙이 있는지 알 수 없습니다.

### 권장 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다. 1.4.0이면 로컬 빌드 성공을 2.0.0의 증거로 쓰면 안 됩니다.
2. 2.0.0 패키지의 `exports`에 `./button` 경로가 있는지 봅니다. 없다면 이 경로가 원인입니다.
3. Node 18 환경에서 `npm ci`로 새로 설치한 뒤 빌드합니다. 이렇게 하면 Node 버전과 설치 상태를 함께 재현할 수 있습니다.
4. CI 로그에서 설치 명령과 캐시 적중 여부를 봅니다.

### 해결 방향 (추론이며 아직 실행하지 않았습니다)

- import 경로를 2.0.0이 공개한 경로로 바꿉니다. 공개된 대체 경로가 있을 때만 가능합니다.
- 2.0.0 패키지 관리자에게 `./button` 경로를 `exports`에 추가해 달라고 요청합니다.
- 2.0.0 업그레이드를 되돌려 1.4.0을 유지합니다. 가장 빠른 방법이지만 업그레이드 목적을 잃으므로 PM과 결정해야 합니다.

PM께 전할 핵심은 두 가지입니다. 로컬 빌드가 성공했다는 사실은 2.0.0에 문제가 없다는 근거가 되지 않습니다. 참고로 Node 18은 2025년 4월 말에 지원이 끝났으므로, 원인과 별개로 CI의 Node 버전을 로컬과 맞추는 것도 검토해 볼 만합니다.
