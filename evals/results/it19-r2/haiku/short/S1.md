로컬 캐시는 각 서버가 자기 메모리에 캐시(자주 쓰는 데이터를 임시로 저장해 두는 곳)를 따로 두는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도의 캐시 서버를 두는 방식입니다.

| 구분 | 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 | 공용 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 서버 재시작 시 | 저장된 내용이 사라짐 | 캐시 서버가 살아 있으면 내용이 남음 |
| 장애 영향 | 해당 서버 1대에만 영향 | 캐시 서버에 문제가 생기면 4대 모두 영향 |

Redis를 도입하면 서버 4대가 같은 상품 목록을 보므로 서버마다 내용이 달라지는 문제가 없어집니다. 서버를 재시작해도 공용 캐시에 남은 내용을 그대로 쓸 수 있습니다.

다만 Redis를 도입하는 것만으로 가격 반영 지연이 자동으로 없어지지는 않습니다. 캐시를 5분 동안 유지하는 설정이 그대로라면 가격을 바꾼 뒤 고객에게 반영되기까지 최대 5분이 걸립니다. 가격을 바꿀 때 캐시를 바로 지우는 작업이 있어야 반영 지연을 줄일 수 있습니다.
