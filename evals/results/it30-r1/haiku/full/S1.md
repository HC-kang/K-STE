로컬 캐시와 Redis 캐시의 차이는 임시 데이터를 서버 안에 두느냐, 여러 서버가 함께 쓰는 별도 서버에 두느냐입니다. Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되어, 서버마다 가격이 다르게 보이는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 빨리 꺼내려고 임시로 복사해 두는 저장소입니다. 지금은 각 API 서버(고객 요청을 받아 처리하는 서버)가 자기 메모리에 상품 목록을 5분 동안 보관합니다. 서버마다 보관하는 시점이 달라서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

| 구분 | 지금 (로컬 캐시) | 도입 후 (Redis 캐시) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 서버 사이 데이터 | 서버마다 다를 수 있음 | 4대가 같은 데이터를 읽음 |
| 조회 속도 | 같은 서버 메모리에서 읽어 가장 빠름 | 네트워크를 거쳐 읽으므로 약간 느려짐 |
| 캐시 서버 장애 시 | 서버 각자 독립적으로 동작함 | 캐시 서버가 멈추면 4대 모두 영향을 받음 |

즉 Redis로 얻는 것은 서버 사이의 데이터 일치입니다. 대신 캐시 서버를 따로 운영해야 하고, 조회가 약간 느려집니다.

확인 필요: Redis 도입 후 가격 변경이 고객에게 반영되기까지 걸리는 최대 시간. 이 시간은 Redis 안의 상품 목록을 얼마나 자주 갱신하느냐에 따라 달라지며, 현재 정보에는 그 기준이 없습니다.
