Redis를 도입하면 서버 4대가 같은 캐시(자주 쓰는 데이터를 빨리 꺼내 쓰려고 임시로 복사해 둔 공간)를 보므로, 서버마다 상품 정보가 달라지는 문제는 없어집니다. 다만 가격 변경이 고객에게 최대 5분 늦게 반영되는 문제는 Redis 도입만으로는 해결되지 않습니다.

지금 방식인 로컬 캐시는 각 서버의 메모리 안에 상품 목록을 따로 저장합니다. 그래서 서버마다 갱신 시점이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. Redis 캐시(여러 서버가 네트워크로 함께 접속해 쓰는 별도의 캐시 서버)는 상품 목록을 한 곳에만 둡니다. 그래서 서버 4대가 모두 같은 내용을 읽습니다.

가격이 반영되는 시점은 캐시를 언제 비우고 다시 채우는지에 따라 달라집니다. 가격을 바꿀 때 Redis의 상품 캐시를 바로 비우도록 만들면 고객에게 즉시 반영됩니다. 이 작업이 이번 도입 범위에 들어가는지는 확인 필요: Redis 도입 범위에 가격 변경 시 캐시를 바로 비우는 작업이 포함되는지.
