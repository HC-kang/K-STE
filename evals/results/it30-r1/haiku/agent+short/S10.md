원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드일 가능성이 큽니다. 1.4.0에서는 되던 `@company/ui/button` import가 2.0.0의 `exports`에 정의되지 않은 경로라서 막혔을 것으로 보입니다. 아직 package.json과 전체 오류 로그를 확인하지 않았으므로 이 내용은 추론입니다.

로컬이 성공하는 이유는 로컬 `node_modules`가 3일 전에 설치된 것이라서 아직 1.4.0일 가능성이 높기 때문입니다. 업그레이드 후에 `npm install`을 다시 실행하지 않았다면 로컬은 2.0.0을 쓰지 않습니다. 이 점도 아직 확인하지 않았습니다.

CI가 실패하는 이유는 `package-lock.json`이 바뀌면서 캐시 키도 바뀌어 CI가 의존성을 새로 설치하기 때문입니다. 이때 2.0.0이 설치되어 `exports`에 막힌 import가 실패한 것으로 보입니다.

Node 버전 차이는 원인일 가능성이 낮습니다. `exports` 필드는 Node 18과 Node 20에서 모두 지원됩니다. 다만 2.0.0의 모듈 형식(ESM 또는 CJS)과 Node 버전의 조합은 확인하지 않았으므로 확인 필요합니다.

오류 메시지 `Cannot find module`은 확정 단서가 아닙니다. Node가 `exports`로 막힌 경로를 `require`할 때는 보통 `ERR_PACKAGE_PATH_NOT_EXPORTED` 코드를 냅니다. 이 메시지는 번들러나 다른 해석기에서 나왔을 수 있으므로 확인 필요합니다.

확인 방법은 다음과 같습니다.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button` 항목이 있는지 확인합니다.
3. CI 로그에서 전체 스택 트레이스를 확인해 오류 코드와 import가 있는 파일을 찾습니다.
4. 로컬에서 `rm -rf node_modules && npm ci` 후 빌드해 실패가 재현되는지 확인합니다.

조치 옵션은 다음과 같습니다. 아직 아무것도 실행하지 않았습니다.

1. `exports`가 허용하는 경로로 import를 바꿉니다. 2번에서 `./button`이 없으면 이 방법은 쓸 수 없습니다.
2. 패키지 관리자에게 `./button` 경로 export 추가를 요청합니다.
3. 임시로 `@company/ui`를 1.4.0에 고정합니다.

원인이 확정되면 1번을 먼저 검토하고, 바로 막아야 한다면 3번을 임시 조치로 쓰는 것을 권장합니다.
