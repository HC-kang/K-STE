가장 유력한 원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고, CI는 2.0.0을 설치해서 `exports` 필드의 제한을 받는 것입니다. `exports`는 패키지가 외부에 공개하는 import 경로를 제한하는 설정입니다. 아래 내용 중 "추론"은 아직 검증하지 않았습니다.

## 사실

- CI에서만 빌드가 실패하고, 에러는 `Cannot find module '@company/ui/button'`입니다.
- `@company/ui`를 3일 전에 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

## 추론

- 로컬 `node_modules`는 업그레이드 전에 설치했으므로, 로컬에는 1.4.0이 남아 있을 가능성이 높습니다.
- 1.4.0에는 `exports`가 없으므로, `@company/ui/button`은 패키지 안의 파일 경로로 바로 해석됩니다.
- 2.0.0은 `exports`에 정의한 경로만 허용합니다. `./button`이 `exports`에 없거나 이름이 바뀌었다면 CI에서 모듈을 찾지 못합니다.
- Node 18과 20은 모두 `exports`를 지원하므로, Node 버전 차이가 원인일 가능성은 낮습니다.
- `package-lock.json`이 업그레이드와 함께 바뀌었다면 캐시 키도 바뀝니다. 그래서 오래된 캐시가 원인일 가능성은 낮습니다.

## 확인 필요

- 로컬에 실제로 설치된 `@company/ui` 버전이 무엇인지 확인해야 합니다.
- 2.0.0의 `exports`에 `./button`이 있는지 확인해야 합니다.
- `package-lock.json`을 업그레이드 커밋에 포함했는지 확인해야 합니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치 버전을 봅니다. 1.4.0이면 로컬 성공의 원인이 확정됩니다.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. 같은 에러가 나면 CI와 같은 조건을 재현한 것입니다.
3. `npm view @company/ui@2.0.0 exports`를 실행해 공개 경로 목록에서 `./button`을 찾습니다.
4. 2.0.0의 변경 내역에서 `button`의 경로가 바뀌었는지 봅니다.

## 해결 방향

- 3번에서 `./button`이 없고 대체 경로가 있으면, 앱의 import를 새 경로로 바꿔야 합니다.
- `./button`이 있어야 하는데 빠졌다면, `@company/ui` 쪽에서 `exports`에 추가하는 것을 권장합니다.
- 재발을 막으려면 로컬도 `npm ci`로 설치하고, 로컬 Node 버전을 CI와 맞추는 것을 권장합니다.
