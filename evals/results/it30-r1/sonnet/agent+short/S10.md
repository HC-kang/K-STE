CI 빌드가 실패한 원인은 `@company/ui` 2.0.0이 새로 추가한 `exports` 필드(패키지가 외부에 공개하는 경로 목록)로 보입니다. 로컬 `node_modules`에는 아직 1.4.0이 남아 있어서 로컬 빌드만 성공한 것으로 보입니다. 아직 실제 파일을 열어 확인하지는 않았으므로 아래 내용 중 추론과 미확인을 구분해서 적습니다.

사실은 다음과 같습니다.
- 빌드는 CI에서만 실패하고, 에러는 `Error: Cannot find module '@company/ui/button'`입니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

추론은 다음과 같습니다.
- 1.4.0에는 `exports`가 없어서 `@company/ui/button`을 패키지 안의 `button` 파일 경로로 직접 찾을 수 있었습니다.
- 2.0.0에는 `exports`가 있어서 Node는 `exports`에 적힌 경로만 허용합니다. `@company/ui/button`이 `exports`에 없으면 같은 import도 "모듈을 찾을 수 없다"로 실패합니다.
- 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀝니다. 그러면 CI는 캐시 없이 2.0.0을 새로 설치합니다. 반면 로컬은 재설치하지 않아서 1.4.0을 계속 씁니다.
- Node 18과 20의 차이는 원인으로 보지 않습니다. `exports`는 Node 18과 20이 모두 지원하는 기능입니다. 이것은 제가 알고 있는 지식에 근거한 판단이고, 이 프로젝트에서 실행해 본 결과는 아닙니다.

아직 확인하지 않은 것은 세 가지입니다.
- 로컬 `node_modules/@company/ui`의 실제 버전
- 2.0.0의 `exports`에 `./button` 경로가 있는지
- 업그레이드 커밋에 `package-lock.json` 변경이 들어 있는지

확인 순서는 다음과 같습니다.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 봅니다.
2. 2.0.0의 `package.json`에서 `exports` 항목에 `./button`이 있는지 봅니다.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. CI와 같은 에러가 나면 원인이 확정됩니다.

3번에서 같은 에러가 나면 둘 중 하나로 고칩니다.
- 앱의 import를 2.0.0 `exports`에 있는 경로로 바꿉니다.
- `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.

어느 쪽이 맞는지는 2번 결과로 정해집니다. 2.0.0이 `./button`을 일부러 공개하지 않았다면 앱의 import를 바꿔야 합니다. 공개 대상인데 빠뜨렸다면 패키지를 고쳐야 합니다.
