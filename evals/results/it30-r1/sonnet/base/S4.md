# 운영 배포 롤백 런북 (payment-api)

## 1. 롤백 전 확인 (필수)

롤백할 배포에 **DB 마이그레이션이 포함됐는지** 먼저 확인한다.

- **포함됨 → 롤백하지 않는다.** DBA 박지은에게 연락하고 그 지시를 따른다.
- **포함되지 않음 →** 2단계로 진행한다.

## 2. 롤백 실행

돌아갈 대상 리비전을 확인한다.

```
argocd app history payment-api
```

롤백한다.

```
argocd app rollback payment-api <REVISION>
```

`<REVISION>`은 복구할 정상 배포의 리비전 ID다.

## 3. 롤백 후 검증

아래 두 항목을 모두 확인한다.

1. `/healthz`가 HTTP 200을 반환한다.
2. 결제 테스트 주문 1건이 성공한다.

하나라도 실패하면 롤백이 완료된 것이 아니다. 실패 사실을 #deploy 채널에 남기고 담당자에게 에스컬레이션한다.

## 4. 이력 기록

롤백 이력을 **#deploy 채널**에 남긴다. 아래 항목을 포함한다.

- 롤백 시각
- 롤백 전 리비전과 롤백 후 리비전
- 롤백 사유
- 검증 결과 (`/healthz`, 결제 테스트 주문)

---
