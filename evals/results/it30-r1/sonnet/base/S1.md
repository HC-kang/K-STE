**로컬 캐시와 Redis 캐시의 차이**

- **로컬 캐시**: 서버 4대가 각자 자기 메모리에 상품 목록을 따로 저장합니다. 직원 4명이 각자 책상 위 메모를 보는 것과 같습니다.
- **Redis 캐시**: 서버 4대가 캐시 서버 1대를 같이 씁니다. 모두가 같은 공용 게시판을 보는 것과 같습니다.

**우리 서비스에서 좋아지는 점**

1. **가격 변경이 바로 반영됩니다.**
   - 지금은 서버마다 5분 동안 옛 가격을 들고 있어서, 가격을 바꿔도 고객에게는 최대 5분 늦게 보입니다.
   - Redis 캐시에서는 가격을 바꿀 때 캐시를 한 번만 지우거나 갱신하면 서버 4대가 동시에 새 가격을 보여 줍니다.
   - 단, 가격 변경 시 캐시를 지우는 동작을 개발에서 같이 넣어야 합니다. 넣지 않으면 5분 지연은 그대로 남습니다.

2. **서버마다 가격이 다르게 보이는 현상이 사라집니다.** 지금은 고객이 새로고침할 때 어느 서버로 연결되느냐에 따라 가격이 달라 보일 수 있습니다. Redis 캐시에서는 모든 서버가 같은 내용을 봅니다.

3. **데이터베이스 부하가 줄어듭니다.** 지금은 서버 4대가 각자 상품 목록을 데이터베이스에서 읽어 와 캐시를 채웁니다. Redis 캐시에서는 한 번 채우면 4대가 같이 씁니다. 서버를 새로 띄우거나 재시작해도 캐시가 비어 있지 않습니다.

**알아둘 점**

- Redis 캐시 서버는 1대라서, 이 서버가 멈추면 모든 서버가 영향을 받습니다. 이 경우 데이터베이스로 우회하는 대비책이 필요합니다.
- 서버 메모리를 읽는 것보다 네트워크를 거치는 만큼 아주 조금 느립니다. 고객이 체감할 수준은 아닙니다.

**한 줄 요약**: 가격을 바꾸면 5분 뒤가 아니라 바로, 모든 고객에게 같은 가격이 보이게 됩니다.
