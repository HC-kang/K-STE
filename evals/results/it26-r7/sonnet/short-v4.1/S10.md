CI 실패의 가장 유력한 원인은 `@company/ui` 2.0.0의 `exports` 필드(패키지가 외부에 공개할 파일 경로를 제한하는 설정)가 `@company/ui/button` 경로를 공개하지 않는 것으로 보입니다. 로컬 빌드는 2.0.0이 아니라 이전 버전으로 하고 있을 가능성이 높아서 이 문제를 보지 못했습니다.

**사실**
- CI에서만 `Cannot find module '@company/ui/button'` 에러가 납니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

**추론**
- `exports`가 없는 1.4.0에서는 `@company/ui/button`이 파일 경로로 바로 해석됩니다. `exports`가 있는 2.0.0에서는 `exports`에 적힌 경로만 해석됩니다.
- 로컬 `node_modules`는 업그레이드 전에 설치했으므로 아직 1.4.0일 가능성이 높습니다. 그러면 로컬 빌드 성공은 2.0.0을 검증한 결과가 아닙니다.
- CI는 `package-lock.json` 기준으로 2.0.0을 새로 설치하므로 `exports` 제한을 그대로 받습니다.
- 업그레이드로 `package-lock.json`이 바뀌었으므로 캐시 키도 바뀝니다. 그래서 오래된 캐시가 원인일 가능성은 낮습니다.
- Node 18과 Node 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이가 직접 원인일 가능성도 낮습니다.

**미확인**
- 로컬에 실제로 설치된 `@company/ui` 버전.
- 2.0.0의 `exports`에 `./button`이 없는지, 다른 이름으로 바뀌었는지.
- CI가 실제로 설치한 버전.

**확인 순서**
1. 로컬과 CI 양쪽에서 `npm ls @company/ui`를 실행해 설치된 버전을 비교합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에서 `./button` 항목이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci && npm run build`를 실행합니다. 로컬에서도 같은 에러가 나면 원인이 확정됩니다.

**수정 방향**
- `./button`이 다른 경로로 바뀌었다면 import 경로를 2.0.0의 공개 경로로 고쳐야 합니다.
- `./button`이 빠졌다면 `@company/ui` 담당자에게 `exports`에 추가해 달라고 요청해야 합니다.
- 로컬과 CI의 Node 버전이 다르므로 `.nvmrc` 등으로 맞추는 것을 권장합니다. 이번 에러의 원인은 아닌 것으로 보입니다.
