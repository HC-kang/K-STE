가장 유력한 원인은 CI가 `@company/ui` 2.0.0을 새로 설치하고, 2.0.0의 `exports` 필드가 `@company/ui/button` 같은 하위 경로 import를 허용하지 않기 때문입니다. 이는 추론이며 아직 확인하지 않았습니다.

**원인 추정**

로컬 빌드가 성공하는 이유는 3일 전 이전에 설치한 `node_modules`에 1.4.0이 그대로 남아 있기 때문으로 보입니다. 1.4.0에는 `exports` 필드가 없어서 파일 경로로 `button` 모듈을 찾을 수 있습니다. CI는 `package-lock.json` 해시를 캐시 키로 쓰므로, 버전을 올린 커밋에서 lock 파일이 바뀌면 캐시가 무효화되고 2.0.0이 새로 설치됩니다. Node 버전 차이는 주된 원인일 가능성이 낮습니다. Node 18과 20 모두 `exports` 필드를 지원합니다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `@company/ui` 버전 (추정) | 1.4.0 | 2.0.0 |
| 의존성 출처 | 3일 전 이전 설치본 | lock 해시 기준 새 설치 |

**확인하지 않은 것**

로컬 `node_modules`를 3일 이후에 다시 설치했다면 로컬 버전도 2.0.0일 수 있으며, 이 경우 추정이 틀립니다. 2.0.0의 `exports` 맵에 `./button` 항목이 있는지도 확인하지 않았습니다. CI 로그에서 실제 설치된 버전도 확인하지 않았습니다.

**확인 방법**

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. CI 로그에서 설치된 `@company/ui` 버전을 찾아 로컬 결과와 비교합니다.
3. 2.0.0 패키지의 `package.json`에서 `exports` 필드에 `./button` 경로가 있는지 확인합니다.
4. 2.0.0이 원인으로 확인되면 import 경로를 `exports`가 허용하는 경로로 바꿀지 결정합니다.

PM은 3일 전 버전 상향이 이번 실패의 직접 원인인지 여부를 위 확인 결과로 판단하면 됩니다.
