가장 유력한 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드입니다. 이 필드는 패키지 바깥에 공개할 경로의 목록입니다. 목록에 `./button`이 없으면 `@company/ui/button` 형태의 import가 해석되지 않습니다. 아래 내용은 아직 검증하지 않은 추론이므로 확인 후에 확정하십시오.

CI와 로컬의 차이는 설치된 패키지 버전으로 설명됩니다. CI는 캐시 키인 `package-lock.json` 해시를 기준으로 캐시를 쓰므로, lock 파일이 2.0.0으로 갱신되었다면 캐시가 무효화되고 2.0.0을 새로 설치합니다. 로컬 `node_modules`는 3일 전보다 먼저 설치된 것이므로 1.4.0이 들어 있을 가능성이 큽니다. 1.4.0에는 `exports`가 없어서 서브경로 import가 그대로 동작합니다. 로컬 빌드가 성공하는 이유를 이것으로 설명할 수 있습니다.

Node 18과 20의 차이는 이 원인과 직접 관련이 없어 보입니다. 일반적으로 `exports`는 두 버전 모두 지원하므로, 버전 차이를 원인으로 보기에는 근거가 약합니다.

원인을 확정하려면 다음을 확인하십시오.
1. 로컬에서 `node_modules/@company/ui/package.json`의 `version` 값을 확인하십시오. 1.4.0이면 로컬은 이전 버전으로 빌드되고 있는 것입니다.
2. 2.0.0 패키지의 `exports` 필드에 `./button`이 있는지 확인하십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 여기서 실패하면 원인은 Node 버전이 아니라 패키지 버전입니다.
4. CI 로그에서 설치된 `@company/ui` 버전과 에러 전문을 확인하십시오. 에러가 `ERR_PACKAGE_PATH_NOT_EXPORTED`로 나오면 `exports` 제한이 원인이라는 근거가 됩니다.

원인이 확인되면 조치는 세 가지 중 하나입니다. 팀에서 정하십시오.
- 라이브러리 쪽: 2.0.0의 `exports`에 `./button`을 추가해 새 버전을 내십시오.
- 앱 쪽: import 경로를 2.0.0이 공개한 경로로 바꾸십시오.
- 임시 조치: `@company/ui`를 1.4.0으로 되돌리십시오.
