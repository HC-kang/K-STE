# payment-api 운영 배포 롤백 런북

이 문서는 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 DB 마이그레이션 포함 여부를 확인하고, 포함됐으면 롤백하지 않는다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문을 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 1. 롤백 전 확인

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
   확인 필요: DB 마이그레이션 포함 여부. 포함 여부를 확인하는 방법과 그 결과를 볼 위치가 주어지지 않았다.
2. DB 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다.
   확인 필요: DBA 박지은 연락 방법. 연락 수단과 연락처가 주어지지 않았다.
3. DB 마이그레이션이 포함되지 않았을 때만 2단계로 넘어간다.

## 2. 롤백 실행

4. 다음 명령으로 롤백한다. `<REVISION>`에는 되돌릴 리비전 값을 넣는다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

## 3. 롤백 후 검증

5. `/healthz`가 200을 반환하는지 확인한다.
6. 결제 테스트 주문 1건을 실행하고, 주문이 성공하는지 확인한다.

## 4. 이력 기록

7. #deploy 채널에 롤백 이력을 남긴다.
