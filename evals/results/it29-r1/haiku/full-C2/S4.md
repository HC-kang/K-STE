# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 지정한 리비전으로 되돌리는 절차다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 마이그레이션이 포함됐으면 롤백하면 안 되고 DBA 박지은에게 연락해야 한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 결과를 확인해야 하며, 롤백 이력은 #deploy 채널에 남겨야 한다.

## 절차

1. 롤백하려는 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
   확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 위치가 사실에 없다.

2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 하며, 이후 단계는 진행하지 않는다.
   **경고: 마이그레이션이 포함된 배포는 롤백하면 안 된다.**

3. 마이그레이션이 포함되지 않은 것을 확인한 경우에만 다음 명령으로 롤백해야 한다. `<REVISION>`에는 롤백할 리비전 번호를 넣는다.
   ```
   argocd app rollback payment-api <REVISION>
   ```
   확인 필요: 롤백할 리비전 번호를 찾는 방법이 사실에 없다.

4. 롤백이 끝나면 `/healthz`의 응답 코드가 200인지 확인해야 한다.
   확인 필요: `/healthz`의 접속 주소와 200이 아닐 때 할 일이 사실에 없다.

5. 결제 테스트 주문 1건을 실행해 주문이 성공하는지 확인해야 한다.
   확인 필요: 테스트 주문을 실행하는 방법과 성공 기준이 사실에 없다.

6. 롤백 이력을 #deploy 채널에 남겨야 한다.
   확인 필요: 기록을 남기는 시점과 기록할 내용이 사실에 없다.
