현재 자료로 가장 유력한 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드가 `button` 하위 경로 가져오기를 막았기 때문입니다. 다만 로그와 패키지 내용을 아직 보지 않았으므로, 아래 검증을 먼저 실행하십시오.

**PM을 위한 요약**: 3일 전 공용 UI 패키지를 메이저 버전(2.0.0)으로 올렸습니다. 새 버전은 외부에서 가져올 수 있는 경로를 제한하는 설정(`exports`)을 도입했는데, 앱 코드의 `@company/ui/button` 경로가 그 설정에 없을 가능성이 큽니다. 로컬 개발 환경은 업그레이드 전에 설치된 옛 버전(1.4.0)을 계속 쓰고 있어서 빌드가 성공하고, CI는 새 버전을 받아서 실패하는 것으로 보입니다.

## 현재 자료로 설명되는 점

- 로컬과 CI가 다른 패키지 버전을 쓰는 것이 차이의 가장 큰 이유로 보입니다. 로컬 `node_modules`가 업그레이드 전에 설치된 것이므로 1.4.0을 쓰고 있을 가능성이 높습니다. 실제 버전은 아직 확인하지 않았습니다.
- CI는 `package-lock.json` 해시를 캐시 키로 쓰므로, 업그레이드로 lock 파일이 바뀌었다면 새 버전을 설치하는 것이 맞습니다.
- Node 18과 20의 차이는 가능성이 낮아 보입니다. 두 버전 사이에서 `exports` 해석이 다르다는 근거가 현재 자료에는 없습니다. 그래도 버전을 맞춘 재현으로 배제해야 합니다.

## 주의할 점

에러 메시지 `Cannot find module`은 원인을 단정하기 어렵습니다. `exports`가 경로를 막을 때 Node의 기본 해석기는 보통 "is not defined by exports" 계열의 메시지를 냅니다. 반면 파일이 실제로 없을 때는 `Cannot find module`이 나옵니다. Next.js 빌드 도구의 메시지는 또 다를 수 있습니다. 따라서 두 원인을 로그로 구분해야 합니다.

| 가설 | 근거 | 살펴볼 방법 |
|---|---|---|
| 2.0.0의 `exports`에 `./button` 경로가 없음 | 2.0.0에서 `exports`가 추가됨 | 2.0.0의 `package.json`에서 `exports` 항목을 읽기 |
| 2.0.0에서 `button` 파일의 경로가 바뀌었거나 없어짐 | 메시지가 `Cannot find module`임 | 설치된 패키지 안의 파일 목록 보기 |
| 로컬과 CI의 패키지 버전이 다름 | 로컬 `node_modules`가 업그레이드 전 설치본임 | 로컬과 CI에서 `npm ls @company/ui` 실행 |
| Node 버전 차이 | CI는 Node 18, 로컬은 Node 20 | 로컬에서 Node 18로 빌드 재현 |

## 검증 순서

1. 로컬에서 `npm ls @company/ui`를 실행하여 실제 설치 버전이 1.4.0인지 보십시오.
2. CI 로그에서 같은 명령의 출력을 찾아 CI가 2.0.0을 받았는지 보십시오.
3. 2.0.0 패키지의 `exports` 항목에 `./button`이 있는지 보십시오.
4. 로컬에서 `node_modules`를 지우고 `npm ci`로 2.0.0을 설치한 뒤 빌드하십시오. 실패하면 패키지 쪽 원인이 확정됩니다.
5. 4번에서 실패한 상태에서 Node 18로 바꿔 같은 빌드를 실행하십시오. 결과가 같으면 Node 버전은 원인이 아닙니다.

## 가능한 해결 방향

- 앱 코드에서 `@company/ui/button` 대신 패키지 루트에서 가져올 수 있는지 살펴보십시오. 루트 경로에서 `Button`을 내보내는지는 아직 모릅니다.
- 패키지 관리자에게 `./button` 경로를 `exports`에 추가해 달라고 요청하는 방법이 있습니다.
- 당장 막아야 한다면 `@company/ui`를 1.4.0으로 고정하는 방법이 있습니다. 다만 2.0.0의 변경 사항을 나중에 따라가야 합니다.

## 아직 모르는 것

- 2.0.0의 `exports` 내용
- CI 로그의 전체 에러 메시지
- Next.js 버전과 `tsconfig.json`의 경로 설정
- 2.0.0 변경 사항 문서에 이 변경이 언급되어 있는지 여부
