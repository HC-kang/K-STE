가장 유력한 원인은 로컬 빌드가 `@company/ui` 1.4.0으로 돌고, CI만 2.0.0을 설치해서 `exports` 제한에 걸리는 것입니다. 이 판단은 주어진 정황에서 낸 추론이며 아직 확인하지 않았습니다.

**사실**
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0 패키지에는 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 지정하는 설정)가 추가됐습니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`(설치할 버전을 고정한 파일)의 해시이므로, 업그레이드로 lockfile이 바뀌면 캐시 키도 바뀝니다.

**추론**
- 로컬 `node_modules`가 업그레이드 전에 설치됐으므로 로컬에는 1.4.0이 남아 있을 수 있습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`을 파일 경로로 그대로 읽고 성공합니다.
- CI는 lockfile대로 2.0.0을 새로 설치합니다. 2.0.0의 `exports`에 `./button`이 없으면 이 경로를 찾지 못하고 실패합니다.
- 캐시 키가 lockfile 해시이므로 캐시가 오래된 버전을 제공했을 가능성은 낮습니다.
- Node 18과 20은 둘 다 `exports`를 지원하므로 Node 버전 차이가 원인일 가능성도 낮습니다.

**미확인**
- 로컬에 실제로 설치된 `@company/ui` 버전을 확인하지 않았습니다.
- 2.0.0의 `exports`에 `./button`이 있는지, 경로가 바뀌었는지 확인하지 않았습니다.
- `exports` 제한 위반이면 보통 `ERR_PACKAGE_PATH_NOT_EXPORTED`가 나오는데 이번 메시지는 `Cannot find module`입니다. 확인 필요: CI 로그에서 어느 단계(Next.js 번들러 또는 Node)가 이 에러를 냈는지 봐야 합니다.

**확인 순서**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.
3. 로컬에서 Node 18로 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. 같은 에러가 나면 원인이 확정됩니다.

3단계에서 재현되면 import 경로를 `exports`에 정의된 경로로 바꾸거나, 패키지 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.
