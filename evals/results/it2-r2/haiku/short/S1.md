Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되어, 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 가격 반영이 언제 되는지는 Redis를 어떻게 설정하고 운영하느냐에 따라 달라집니다.

두 방식의 차이는 다음과 같습니다. 캐시는 자주 쓰는 데이터를 빠르게 꺼내려고 임시로 저장해 둔 것입니다.

| 구분 | 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 | 별도의 캐시 서버 1대 |
| 사용 범위 | 해당 서버 한 대만 사용 | 서버 4대가 함께 사용 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 항상 같음 |
| 가격 변경 반영 | 최대 5분 뒤 반영 | 캐시를 지우거나 갱신하는 방식에 따라 다름 |

Redis를 쓰면 좋아지는 점은 서버마다 다른 가격이 보이는 상황이 사라진다는 것입니다. 하지만 Redis를 도입한다고 가격 반영이 자동으로 빨라지지는 않습니다. 캐시를 5분 뒤에 지우는 설정을 그대로 두면 최대 5분 지연도 그대로 남습니다. 가격을 바꾸는 순간 Redis의 캐시도 바로 지우는 작업이 함께 있어야 고객에게 즉시 반영됩니다. 이 작업이 설계에 포함되는지는 확인이 필요합니다.

또한 Redis는 서버와 캐시 서버 사이를 오가는 시간이 추가되고, 캐시 서버가 멈추면 서버 4대 모두 영향을 받을 수 있습니다.
