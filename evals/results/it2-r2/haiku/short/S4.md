운영 `payment-api` 배포를 롤백하는 절차는 아래 6단계입니다. 1단계에서 DB 마이그레이션(데이터베이스 구조를 바꾸는 변경 작업)이 포함된 것을 확인하면 롤백하지 않습니다.

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인합니다.
2. 마이그레이션이 포함됐으면 롤백하지 않고, DBA 박지은에게 연락합니다.
3. 마이그레이션이 포함되지 않은 것을 확인한 경우에만 `argocd app rollback payment-api <REVISION>` 명령으로 롤백합니다. `<REVISION>`에는 롤백할 대상 리비전(배포 버전 번호)을 넣습니다.
4. 롤백한 뒤 `/healthz`가 200을 반환하는지 확인합니다.
5. 롤백한 뒤 결제 테스트 주문 1건이 성공하는지 확인합니다.
6. 롤백 이력을 #deploy 채널에 남깁니다.

**마이그레이션이 포함된 배포는 롤백하지 않습니다.**

확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 자료가 정해져 있지 않습니다. 확인 필요: `<REVISION>`에 넣을 값을 찾는 방법이 정해져 있지 않습니다. 확인 필요: `/healthz` 확인 주소와 결제 테스트 주문을 넣는 방법이 정해져 있지 않습니다. 확인 필요: `/healthz`가 200을 반환하지 않거나 테스트 주문이 실패할 때 조치가 정해져 있지 않습니다. 확인 필요: 이력을 남기는 시점과 기록할 내용이 정해져 있지 않습니다.
