로컬 빌드가 성공하는 이유는 로컬에 `@company/ui` 1.4.0이 남아 있고, CI는 2.0.0을 설치하기 때문으로 보입니다. 아직 실행해서 확인한 내용은 아닙니다.

## 사실

- 에러는 `Error: Cannot find module '@company/ui/button'`이고, CI에서만 납니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0부터 패키지에 `exports` 필드(패키지가 외부에 공개할 경로를 제한하는 `package.json` 설정)가 있습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20입니다.

## 추론

1. 로컬 `node_modules`는 업그레이드보다 먼저 설치했으므로 1.4.0일 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 파일 경로로 그대로 열립니다.
2. 업그레이드로 `package-lock.json`이 바뀌었으므로 캐시 키도 바뀌었고, CI는 캐시 없이 새로 설치했을 것입니다. 이때 2.0.0이 설치됩니다.
3. 패키지에 `exports`가 있으면 `exports`에 적힌 경로만 불러올 수 있습니다. 2.0.0의 `exports`에 `./button`이 없으면 `@company/ui/button`을 찾지 못하고 위 에러가 납니다.

Node 18과 Node 20은 모두 `exports`를 지원하므로, 이 차이가 주원인일 가능성은 낮다고 봅니다. 다만 Node 버전 차이의 영향은 따로 검증하지 않았습니다.

## 미확인

- 로컬에 실제로 설치된 `@company/ui` 버전
- 2.0.0 `package.json`의 `exports`에 `./button`이 있는지
- 2.0.0에서 `button`의 경로나 이름이 바뀌었는지

## 다음 단계

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 로컬 성공은 옛 버전 덕분입니다.
2. `node_modules/@company/ui/package.json`의 `exports`에서 `./button`을 찾으십시오.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드하십시오. CI와 같은 조건에서 같은 에러가 나는지 볼 수 있습니다.
4. `./button`이 `exports`에 없으면 2.0.0의 마이그레이션 문서를 보고 새 import 경로로 바꾸십시오.
