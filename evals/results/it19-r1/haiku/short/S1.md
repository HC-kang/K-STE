로컬 캐시는 서버마다 따로 데이터를 저장하고, Redis 캐시는 서버 4대가 함께 쓰는 하나의 저장소입니다. 두 방식 모두 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 캐시(임시 저장소)입니다.

| 구분 | 로컬 캐시 | Redis 캐시 (공용 캐시 서버) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있습니다 | 4대가 같은 데이터를 봅니다 |
| 읽는 속도 | 가장 빠릅니다 | 네트워크를 거치므로 로컬보다 조금 느립니다 |
| 장애 영향 | 한 서버의 캐시만 사라집니다 | 캐시 서버가 멈추면 4대 모두 영향을 받습니다 |

현재 서버 4대는 각자 5분 동안 상품 목록을 보관합니다. 그래서 가격을 바꾸면 서버마다 새 가격이 반영되는 시점이 달라지고, 고객은 최대 5분 늦게 새 가격을 볼 수 있습니다.

Redis를 도입하면 4대가 같은 캐시를 보므로 서버마다 내용이 달라지는 문제는 없어집니다. 하지만 가격 변경이 고객 화면에 바로 나타나는지는 캐시를 언제 비우고 새로 채우는지에 따라 달라집니다.

확인 필요: 이번 도입에서 가격을 바꾸면 캐시를 즉시 비우는지, 아니면 여전히 5분마다 갱신하는지 확인이 필요합니다.

확인 필요: 캐시 서버가 멈추는 상황에 대비해 예비 서버를 두는지(한 대가 멈추면 다른 대가 이어받는 구성) 확인이 필요합니다. 예비 서버가 없으면 캐시 서버 1대의 장애가 4대 전체에 영향을 줍니다.
