# payment-api 운영 롤백 런북

이 문서는 ArgoCD로 배포한 payment-api의 운영 배포를 롤백하는 절차를 정리한다. DB 마이그레이션이 포함된 배포는 롤백하면 안 된다.

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 2단계로 넘어간다.

## 2. 롤백 실행

4. 롤백할 리비전 번호를 확인한다.
5. 4단계에서 확인한 리비전 번호를 `<REVISION>` 자리에 넣고 다음 명령을 실행한다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 확인

6. `/healthz` 엔드포인트가 200을 반환하는지 확인한다.
7. 결제 테스트 주문 1건을 실행하고, 그 주문이 성공하는지 확인한다.

## 4. 이력 기록

8. #deploy 채널에 롤백 이력을 남긴다.

## 확인 필요

- 확인 필요: 마이그레이션 포함 여부를 확인하는 방법(배포 diff, 마이그레이션 디렉터리 등)이 원문에 없다.
- 확인 필요: 리비전 번호를 찾는 위치가 원문에 없다.
- 확인 필요: `/healthz`를 호출할 호스트 주소가 원문에 없다.
- 확인 필요: 결제 테스트 주문의 방법과 테스트 계정이 원문에 없다.
- 확인 필요: DBA 박지은에게 연락하는 방법이 원문에 없다.
- 확인 필요: #deploy 채널에 남길 이력 항목(리비전, 시각, 담당자 등)이 원문에 없다.
- 확인 필요: 롤백 후 확인이 실패했을 때의 대응 절차가 원문에 없다.
