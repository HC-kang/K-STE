가장 큰 차이는 서버 4대가 캐시(자주 보는 데이터를 미리 저장해 두고 빨리 꺼내 쓰는 곳)를 따로 갖느냐, 같이 쓰느냐입니다.

| 항목 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대가 각자 자기 메모리에 저장합니다. | 서버 4대가 같이 쓰는 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 캐시 내용이 다릅니다. | 서버 4대가 같은 캐시 내용을 봅니다. |

현재는 서버마다 상품 목록을 5분 동안 따로 캐시합니다. 그래서 가격을 바꾸면 서버마다 새 가격으로 바뀌는 시점이 달라지고, 고객에게는 최대 5분 늦게 반영됩니다.

Redis(여러 서버가 같이 쓰는 캐시 전용 서버)를 도입하면 서버 4대가 같은 캐시를 보기 때문에, 서버마다 가격이 다르게 보이는 문제가 없어집니다. 같은 고객이 새로 고침할 때 서버가 바뀌어도 상품 목록이 달라지지 않습니다.

다만 Redis를 도입하는 것만으로 5분 지연이 없어지는지는 알 수 없습니다. 캐시 보관 시간이 5분 그대로이고 가격을 바꿀 때 캐시 내용을 갱신하지 않으면, 지연은 남을 수 있습니다.
