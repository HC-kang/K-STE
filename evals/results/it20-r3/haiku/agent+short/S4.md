이 런북은 운영 환경의 `payment-api` 배포를 ArgoCD로 롤백하는 절차를 설명한다. 롤백 전에 대상 배포에 DB 마이그레이션이 포함됐는지 확인해야 하며, 포함됐으면 롤백하면 안 된다.

## 사전 확인

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때 DBA 박지은에게 연락해야 한다.
3. 아래 롤백 절차는 마이그레이션이 포함되지 않은 배포에만 적용한다.

## 롤백 절차

1. 롤백할 리비전 번호를 `<REVISION>` 자리에 준비한다.
2. `argocd app rollback payment-api <REVISION>` 명령을 실행한다.

## 롤백 후 확인

1. `/healthz`의 응답 코드가 200인지 확인한다.
2. 결제 테스트 주문을 1건 실행하고, 주문이 성공하는지 확인한다.

## 이력 기록

1. 롤백 이력을 #deploy 채널에 남긴다.

## 확인 필요

- 확인 필요: 대상 배포에 DB 마이그레이션이 포함됐는지 확인하는 방법과 기준이 원문에 없다.
- 확인 필요: `<REVISION>` 값을 어디서 찾는지 원문에 없다.
- 확인 필요: `/healthz`가 200을 반환하지 않거나 결제 테스트 주문이 실패할 때 할 조치가 원문에 없다.
