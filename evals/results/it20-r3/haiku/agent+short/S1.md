Redis를 도입하면 API 서버 4대가 같은 상품 목록 캐시(자주 쓰는 데이터를 빠르게 꺼내 쓰려고 임시로 보관해 두는 곳)를 함께 쓰게 됩니다. 그래서 지금처럼 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

| 구분 | 지금 (서버별 로컬 캐시) | Redis 도입 후 |
|---|---|---|
| 캐시를 두는 곳 | 서버마다 자기 메모리 | 캐시 서버 1대 |
| 서버 4대의 캐시 내용 | 서버마다 다를 수 있습니다 | 4대가 같은 내용을 봅니다 |
| 읽는 속도 | 서버 안에서 바로 읽어서 빠릅니다 | 네트워크를 거쳐 읽어서 로컬보다 느립니다 |
| 캐시가 멈출 때 | 서버 1대가 멈춰도 다른 서버는 영향을 받지 않습니다 | 캐시 서버 1대가 멈추면 4대 모두 영향을 받습니다 |

가격을 바꾼 뒤 고객에게 반영되는 시점은 캐시를 지우는 방식에 따라 달라집니다.

확인 필요: 가격을 바꿨을 때 Redis의 캐시를 바로 지우는지, 아니면 5분이 지나 자동으로 지워지기를 기다리는지 정해야 합니다. 바로 지우지 않으면 고객에게 가격이 최대 5분 늦게 반영되는 문제가 그대로 남습니다.

Redis 서버가 멈췄을 때 서비스가 어떻게 동작할지 미리 정해 두는 것을 권장합니다.
