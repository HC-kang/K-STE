Redis를 도입하면 API 서버 4대가 상품 목록 캐시(자주 쓰는 데이터를 임시로 저장해 두는 곳)를 하나로 같이 쓰므로, 서버마다 내용이 달라지는 문제가 없어집니다.

| 항목 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리에 저장합니다. | 서버 4대가 같이 쓰는 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 캐시 내용이 다릅니다. | 서버 4대가 같은 캐시를 읽습니다. |

현재는 서버마다 상품 목록을 5분 동안 따로 저장합니다. 그래서 가격을 바꾸면 바뀐 가격이 고객에게 최대 5분 늦게 보입니다.

Redis에서는 캐시가 한 곳에만 있습니다. 그래서 캐시를 한 번 갱신하면 서버 4대가 모두 같은 값을 읽을 수 있습니다. 가격 변경 지연이 얼마나 줄어드는지는 가격을 바꿀 때 Redis 캐시를 어떻게 갱신하느냐에 따라 달라집니다.
