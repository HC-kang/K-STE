Redis를 도입하면 API 서버 4대가 캐시 하나를 같이 보게 되어, 서버마다 상품 목록이 달라지는 문제가 없어집니다.

캐시(자주 쓰는 데이터를 가까운 곳에 임시로 저장해 두는 방식)는 두 가지로 나눠서 비교할 수 있습니다.

- 로컬 캐시는 서버 한 대가 자기 메모리에 따로 가진 캐시입니다. 지금 우리 서비스가 이 방식으로 상품 목록을 5분 동안 캐시합니다. 서버가 4대이므로 캐시도 4개이고, 서버마다 저장된 시점이 달라서 내용이 다를 수 있습니다.
- Redis 캐시는 서버 4대가 같이 쓰는 캐시 서버(캐시 전용 서버 프로그램) 1대에 저장한 캐시입니다. 캐시가 1개이므로 어느 서버에 요청이 가도 같은 내용을 봅니다.

지금은 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. 서버마다 캐시를 따로 가지고 있어서, 어떤 서버는 새 가격을 보여 주고 다른 서버는 옛 가격을 보여 줄 수 있기 때문입니다. Redis를 도입하면 서버 4대가 같은 캐시를 보므로, 같은 시점에 서버마다 가격이 다르게 보이는 일이 없어집니다.

확인 필요: 가격 변경이 고객에게 반영되기까지 걸리는 시간이 5분보다 짧아지는지는 아직 정해진 바가 없습니다. 이 시간은 Redis 캐시의 유효 시간과, 가격을 바꿀 때 캐시를 어떻게 갱신하는지에 따라 달라집니다.
