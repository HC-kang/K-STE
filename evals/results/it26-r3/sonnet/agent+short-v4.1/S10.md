원인은 `@company/ui` 2.0.0의 `exports`(패키지가 외부에 공개하는 경로 목록) 필드로 보입니다. 로컬은 아직 1.4.0을 쓰고 있고, CI는 2.0.0을 설치해서 결과가 다릅니다. 아래 내용 중 사실은 전달받은 정보이고, 나머지는 추론입니다.

## 로컬과 CI의 차이

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `node_modules` | 3일 전보다 먼저 설치함 | 캐시 키가 `package-lock.json` 해시임 |
| `@company/ui` 버전 | 1.4.0으로 보임 | 2.0.0으로 보임 |
| 빌드 결과 | 성공 | `Cannot find module '@company/ui/button'` |

## 추론한 원인

1. 로컬 `node_modules`는 업그레이드 전에 설치했으므로 `@company/ui` 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`처럼 패키지 안쪽 파일 경로로 직접 가져오는 방식이 동작합니다.
2. 업그레이드로 `package-lock.json`이 바뀌었을 것이므로 CI 캐시 키도 바뀌었을 것입니다. 그래서 CI는 캐시를 쓰지 않고 2.0.0을 새로 설치했을 것으로 보입니다.
3. `exports` 필드가 있으면 Node는 그 목록에 적힌 경로만 허용합니다. 2.0.0의 `exports`에 `./button`이 없으면 같은 import가 `Cannot find module`로 실패합니다.

## 미확인 사항

- 로컬에 설치된 `@company/ui`의 실제 버전을 확인하지 않았습니다.
- 2.0.0의 `exports`에 `./button`이 있는지 확인하지 않았습니다.
- Node 18과 20의 차이가 원인인지 확인하지 않았습니다. 이 오류는 `exports` 필드로 설명되므로 Node 버전은 원인이 아닐 가능성이 높다고 봅니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오.
2. 로컬 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 이때 로컬에서도 같은 오류가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports` 필드에서 `./button`이 있는지 보십시오.
4. `./button`이 없으면 2.0.0이 공개하는 경로로 import를 바꾸십시오. 공개하는 경로가 없으면 `@company/ui` 담당 팀에 `./button`을 `exports`에 추가해 달라고 요청하십시오.

2번 결과가 나오기 전에는 로컬 빌드 성공을 근거로 코드가 정상이라고 판단하면 안 됩니다.
