CI 빌드는 2.0.0을 설치해서 실패하고, 로컬 빌드는 1.4.0이 남아 있어서 성공한 것으로 보입니다. 이 내용은 추론이고, 아래 확인 3가지로 검증해야 합니다.

## 추론의 근거

- 2.0.0에서 `@company/ui`에 `exports` 필드(패키지가 외부에 공개하는 import 경로 목록)가 생겼습니다.
- `exports`가 있는 패키지는 목록에 적힌 경로만 import할 수 있습니다. 목록에 `./button`이 없으면 `@company/ui/button`을 import할 때 `Cannot find module` 오류가 납니다.
- 1.4.0에는 `exports`가 없어서 `@company/ui/button`을 파일 경로로 바로 찾을 수 있었습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했으므로 1.4.0일 가능성이 높습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 버전을 올릴 때 lockfile이 바뀌었으므로 이전 캐시를 쓰지 않고 2.0.0을 새로 설치했을 것으로 보입니다.

## 다른 요인의 가능성

| 요인 | 판단 | 이유 |
|---|---|---|
| CI 캐시 | 원인일 가능성이 낮습니다 | lockfile이 바뀌면 캐시 키도 바뀝니다. |
| Node 18과 Node 20의 차이 | 원인일 가능성이 낮습니다 | 두 버전 모두 `exports` 필드를 지원한다고 알고 있습니다. 이 부분은 이번에 확인하지 않았습니다. |

## 확인할 것

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오. 1.4.0이면 추론이 맞습니다.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 오류가 나면 Node 버전과 캐시는 원인이 아닙니다.
3. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오. 없으면 import 경로를 `exports`에 적힌 경로로 바꾸거나, `@company/ui` 담당자에게 `./button` 추가를 요청해야 합니다.

확인 필요: 2.0.0의 `exports`에 어떤 경로가 있는지는 전달받은 내용에 없습니다. 3번 결과에 따라 수정 주체가 앱 팀인지 `@company/ui` 팀인지 달라집니다.
