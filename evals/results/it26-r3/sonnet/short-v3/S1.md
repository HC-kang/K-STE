Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되어, 서버마다 가격이 다르게 보이는 문제가 사라집니다.

캐시는 자주 쓰는 데이터를 빨리 꺼내 쓰려고 잠시 저장해 둔 사본입니다. 지금 쓰는 로컬 캐시는 서버 한 대의 메모리에 있는 캐시입니다. 우리 API 서버는 4대이고, 서버마다 상품 목록을 5분 동안 따로 저장합니다. 그래서 가격을 바꾸면 서버마다 새 가격을 가져오는 시점이 달라지고, 고객에게는 최대 5분 늦게 반영됩니다.

Redis 캐시는 캐시 전용 서버 1대를 API 서버 4대가 함께 쓰는 방식입니다. 상품 목록을 한 곳에만 저장하므로, 4대 모두 같은 내용을 읽습니다.

다만 Redis를 도입하는 것만으로 최대 5분 지연이 없어지는지는 알 수 없습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지우도록 만들어야 지연이 줄어듭니다.

확인 필요: 이번 Redis 도입 범위에 가격 변경 시 캐시를 지우는 작업이 포함되는지 개발팀에 확인해야 합니다.
