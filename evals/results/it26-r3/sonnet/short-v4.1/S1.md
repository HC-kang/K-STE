Redis를 도입하면 서버 4대가 같은 캐시를 함께 보게 되어, 서버마다 상품 목록이 다르게 보일 수 있는 문제가 줄어듭니다. 캐시는 자주 쓰는 데이터를 빨리 꺼내 쓰려고 임시로 저장해 두는 곳입니다. Redis는 서버 여러 대가 함께 쓰는 캐시 전용 서버입니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대가 각자 자기 메모리에 저장합니다. | 캐시 서버 1대에 저장하고 API 서버 4대가 같이 씁니다. |
| 캐시 내용 | 서버마다 달라질 수 있습니다. | 4대가 같은 내용을 봅니다. |
| 가격 변경 시 | 서버마다 캐시가 따로 만료되어, 고객에게 최대 5분 늦게 반영됩니다. | 캐시 한 곳만 갱신하면 4대에 같이 반영됩니다. |

현재는 서버마다 상품 목록을 5분 동안 따로 저장합니다. 그래서 가격을 바꿔도 서버마다 새 가격이 보이는 시점이 다르고, 최대 5분까지 늦어집니다. 같은 고객이 요청마다 다른 서버에 연결되면 가격이 다르게 보일 수도 있습니다. 이 부분은 추론입니다.

Redis는 캐시가 한 곳에 있으므로 이 차이가 생기지 않습니다.

확인 필요: 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지우거나 갱신하는지, 5분이 지나 만료되기를 기다리는지 정해야 합니다. 바로 지우거나 갱신하면 반영 지연이 줄어들 수 있습니다. 만료를 기다리면 지연은 최대 5분으로 그대로 남습니다.

Redis 서버를 1대로 두므로, 이 서버에 문제가 생기면 API 서버 4대가 모두 영향을 받을 수 있습니다. 이 부분도 추론이며, 대비책은 아직 확인하지 못했습니다.
