Redis를 도입해도 가격 지연이 자동으로 없어지지는 않습니다. 서버 4대가 같은 캐시를 함께 쓰면 서버마다 값이 달라지는 문제는 없어지지만, 가격이 고객에게 보이는 속도는 캐시를 언제 비우는지에 따라 정해집니다.

캐시(cache, 자주 쓰는 데이터를 빠르게 꺼내 쓰려고 미리 복사해 두는 임시 보관소)는 지금 각 서버 안에 있습니다. Redis(여러 서버가 함께 쓰는 빠른 임시 보관 서버)는 이 보관소를 서버 밖의 한 곳으로 옮기는 방식입니다.

| 구분 | 로컬 캐시 (지금) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버 안의 메모리에 저장합니다. | 서버 4대가 함께 쓰는 별도 서버 1대에 저장합니다. |
| 서버 간 값 | 서버마다 다를 수 있습니다. | 서버 4대가 같은 값을 봅니다. |
| 가격 변경이 고객에게 보이기까지 | 서버마다 최대 5분 걸립니다. | 캐시를 비우는 방식에 따라 달라집니다. |
| 새로 관리할 것 | 없습니다. | Redis 서버를 따로 운영해야 합니다. |

Redis 캐시 만료 시간을 5분으로 그대로 두면, 가격이 고객에게 보이기까지 최대 5분 걸리는 점은 같습니다. 가격을 바꿀 때 Redis 캐시를 바로 비우는 작업을 넣으면 이 지연을 줄일 수 있습니다.

Redis 서버 1대가 멈추면 4대 서버 모두 영향을 받을 수 있습니다. 이 부분은 설계에서 따로 확인해야 합니다.
