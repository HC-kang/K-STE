로컬 빌드가 성공하는 이유는 로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있기 때문으로 보입니다. CI는 2.0.0을 새로 설치하고, 2.0.0의 `exports` 필드가 `@company/ui/button` 경로를 막는 것으로 보입니다. 두 내용 모두 추론이며, 아래 확인 단계로 검증해야 합니다.

## 근거

- 사실: 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸고, 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- 사실: 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다. 그래서 로컬에 1.4.0이 남아 있을 수 있습니다.
- 사실: CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 이 파일이 바뀌었다면 캐시 키도 바뀌어서 CI가 의존성을 새로 설치합니다.
- 일반 동작: `exports` 필드(패키지가 외부에 공개하는 import 경로의 목록)가 있으면 Node는 목록에 없는 경로를 `Cannot find module` 오류로 거절합니다. 1.4.0에는 이 필드가 없어서 `@company/ui/button`이 파일 경로 그대로 열렸을 것입니다.
- 추론: 2.0.0의 `exports`에 `./button`이 없거나 조건이 맞지 않으면 CI에서만 이 오류가 납니다.

## Node 버전의 영향

`exports`는 Node 18과 20이 모두 지원합니다. 그래서 Node 버전 차이가 주원인일 가능성은 낮아 보입니다. 다만 `exports` 안의 조건(`import`, `require`)을 두 버전이 다르게 처리하는지는 확인하지 않았습니다.

## 확인 단계

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인한다. 1.4.0이면 추론이 맞다.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드한다. 같은 오류가 나면 CI와 로컬의 차이는 설치된 버전이다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 본다.
4. 3번에서 `./button`이 있는데도 2번에서 오류가 나면 Node 18로 로컬 빌드를 다시 해서 Node 버전의 영향을 따로 본다.

## 해결 방향

3번에서 `./button`이 없으면 방법은 둘입니다. 앱 코드의 import 경로를 `exports`가 공개하는 경로로 바꾸거나, `@company/ui` 관리자에게 `./button`을 `exports`에 추가해 달라고 요청해야 합니다. 어느 쪽이 맞는지는 2.0.0이 `button`을 다른 경로로 공개했는지에 달려 있고, 이 정보는 아직 없습니다.

확인 필요: 2.0.0의 `exports`가 `button`을 의도적으로 비공개로 바꿨는지 여부.
