로컬 캐시는 서버마다 따로 갖는 임시 저장소이고, Redis 캐시는 서버 4대가 함께 쓰는 임시 저장소입니다. Redis를 도입하면 서버끼리 상품 목록이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 미리 가까운 곳에 저장해 두는 기능입니다. 지금은 API 서버(고객 요청을 받아 응답하는 서버) 4대가 각자 메모리에 상품 목록을 5분 동안 저장합니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대가 각자의 메모리에 저장합니다. | 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 저장 시점이 달라 내용이 다릅니다. | 서버 4대가 같은 내용을 읽습니다. |
| 가격을 바꿨을 때 | 서버마다 캐시가 만료돼야 새 가격이 보여서, 고객에게 최대 5분 늦게 반영됩니다. | Redis의 상품 목록을 갱신하면 서버 4대가 모두 새 가격을 읽습니다. |

가격을 바꾼 직후 어떤 서버를 거치느냐에 따라 고객이 보는 가격이 달라지던 문제가 사라집니다. 가격 변경이 고객에게 보이기까지 걸리는 시간은 Redis 캐시를 언제 어떻게 갱신하도록 만드느냐에 따라 정해집니다.

확인 필요: 가격 변경 후 Redis 캐시를 즉시 갱신할지, 기존처럼 5분 만료를 둘지는 아직 정해진 내용이 없습니다. 개발팀에 확인하십시오.
