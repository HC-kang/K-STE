로컬 `node_modules`에 아직 `@company/ui` 1.4.0이 남아 있고 CI는 2.0.0을 설치해서 결과가 갈린 것으로 보입니다. 이 내용은 추론이며, 아래 검증 단계로 확인해야 합니다.

## 사실

- CI에서만 `Cannot find module '@company/ui/button'` 에러가 납니다.
- `@company/ui` 2.0.0부터 패키지에 `exports` 필드(패키지가 외부에 공개하는 파일 경로 목록)가 생겼습니다.
- 로컬 `node_modules`는 2.0.0으로 올리기 전에 설치한 것입니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

## 추론

1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 실제 파일 경로 `button`으로 바로 연결됩니다. 2.0.0에는 `exports` 필드가 있어서 목록에 없는 경로는 파일이 있어도 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 이름이 바뀌었다면, CI는 위 에러를 냅니다. 로컬은 1.4.0이 남아 있어서 같은 import가 성공합니다.

## 가능성이 낮은 원인

- **Node 버전:** Node 18도 `exports` 필드를 지원하므로 Node 18과 20의 차이가 원인일 가능성은 낮습니다.
- **CI 캐시:** 버전을 올리면 `package-lock.json`의 해시가 바뀌므로 캐시가 새로 만들어졌을 가능성이 높습니다. 다만 락 파일이 이 버전 변경과 함께 커밋됐는지는 아직 모릅니다. 확인 필요: 3일 전 커밋에 `package-lock.json` 변경이 포함됐는지.

## 검증 단계

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 봅니다.
2. `node_modules/@company/ui/package.json`과 CI에 설치된 2.0.0의 `package.json`을 비교해 `exports`에 `./button`이 있는지 봅니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드합니다. 같은 에러가 나면 추론이 맞습니다.

## 해결 방향

`exports`에 `./button`이 없으면 import 경로를 2.0.0이 공개한 경로로 바꿔야 합니다. 공개된 경로로 바꿀 수 없으면 `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청해야 합니다. 로컬과 CI의 환경 차이를 줄이려면 Node 버전을 맞추는 것을 권장합니다.
