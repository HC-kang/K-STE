Redis를 도입하면 API 서버 4대가 같은 캐시(자주 쓰는 데이터를 빠르게 꺼내려고 임시로 저장해 두는 곳)를 함께 쓰므로, 서버마다 상품 정보가 다르게 보이는 문제가 없어집니다.

지금의 로컬 캐시는 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장하는 방식입니다. 서버마다 캐시 내용이 달라서, 같은 상품이라도 고객이 접속한 서버에 따라 다른 정보를 볼 수 있습니다. 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 같이 쓰는 캐시 서버 1대에 상품 목록을 저장하는 방식입니다. 4대가 같은 저장소를 읽기 때문에, 고객은 어느 서버에 접속해도 같은 상품 정보를 봅니다.

확인 필요: 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지우는지, 5분 보관 시간을 그대로 두는지는 아직 확인하지 못했습니다. 이 방식에 따라 가격 변경이 고객에게 반영되는 시간이 달라집니다.

단점도 두 가지 있습니다. Redis 서버가 1대이므로, 이 서버에 문제가 생기면 API 서버 4대가 모두 영향을 받을 수 있습니다. 그리고 Redis는 네트워크를 거쳐 읽기 때문에, 서버 자기 메모리를 읽을 때보다 조금 느릴 수 있습니다.
