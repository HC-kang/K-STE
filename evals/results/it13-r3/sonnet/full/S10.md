원인은 로컬 빌드가 `@company/ui` 2.0.0을 쓰지 않기 때문일 가능성이 가장 높습니다.

로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것이어서, 로컬에는 1.4.0이 남아 있을 것으로 보입니다. 1.4.0에는 `exports` 필드가 없습니다. CI(코드를 올릴 때마다 자동으로 빌드하는 시스템)는 `package-lock.json`(설치할 패키지 버전을 고정한 파일)의 해시를 캐시 키로 씁니다. 업그레이드와 함께 이 파일이 바뀌었다면 캐시가 새로 만들어지고, CI는 2.0.0을 설치합니다.

`exports` 필드(패키지가 외부에 열어 두는 import 경로를 지정하는 package.json 설정)가 있으면, 목록에 없는 경로는 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 다른 경로로 바뀌었다면 `Cannot find module '@company/ui/button'` 에러가 납니다.

Node 18과 20은 둘 다 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 이 에러의 직접 원인이 아닐 것으로 보입니다.

원인을 가르려면 아래 순서로 실행하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 조회하십시오. 1.4.0이면 위 추정이 맞습니다.
2. `@company/ui` 2.0.0의 `package.json`에서 `exports` 안에 `./button`이 있는지 조회하십시오.
3. 로컬 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 에러가 나면 CI와 로컬의 차이는 설치된 버전입니다.

2번에서 `./button`이 없으면, `@company/ui`의 import 경로를 2.0.0의 `exports`에 맞게 바꾸거나 `@company/ui` 쪽에 `./button` 추가를 요청해야 합니다.
