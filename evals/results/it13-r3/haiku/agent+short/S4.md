# 운영 배포 롤백 런북

이 런북은 운영 `payment-api`를 ArgoCD로 이전 REVISION에 되돌리는 절차를 정한다. 롤백하기 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 마이그레이션이 포함된 배포는 롤백하면 안 된다.

- 대상 애플리케이션: `payment-api` (운영)
- 배포 도구: ArgoCD
- 롤백 명령: `argocd app rollback payment-api <REVISION>`

## 롤백 절차

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 위치.
2. **마이그레이션이 포함됐으면 롤백하면 안 된다.** 이 경우 DBA 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 `argocd app rollback payment-api <REVISION>` 명령으로 롤백한다. 확인 필요: 롤백할 `<REVISION>` 값을 찾는 방법.
4. 롤백한 뒤에는 `/healthz`가 200을 반환하는지 확인한다.
5. `/healthz`가 200을 반환한 뒤에는 결제 테스트 주문을 1건 진행하고, 그 주문이 성공하는지 확인한다. 확인 필요: 결제 테스트 주문을 실행하는 방법과 대상 환경.
6. 롤백 이력을 #deploy 채널에 남긴다.
