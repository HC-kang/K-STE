# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 대상 배포에 DB 마이그레이션이 포함됐으면 롤백하면 안 되고 DBA 박지은에게 연락해야 한다. 롤백한 뒤에는 `/healthz` 응답과 결제 테스트 주문을 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 사용 도구와 명령

- 배포 도구: ArgoCD
- 롤백 명령: `argocd app rollback payment-api <REVISION>`
- `<REVISION>`: 롤백할 대상 리비전 값이다. 리비전 값을 찾는 방법은 정보 없음.

## 1. 롤백 전 점검

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인한다. 확인에 쓰는 도구와 위치는 정보 없음.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락한다. 연락처는 정보 없음.
3. 마이그레이션이 포함되지 않았을 때만 2장의 롤백 명령을 실행한다.

## 2. 롤백 실행

4. 롤백 명령 `argocd app rollback payment-api <REVISION>`을 실행한다. `<REVISION>`에는 1단계에서 확인한 대상 리비전 값을 넣는다.

## 3. 롤백 후 확인

5. `/healthz`가 200을 반환하는지 확인한다. 요청을 보낼 주소는 정보 없음.
6. 결제 테스트 주문 1건을 진행하고 주문이 성공하는지 확인한다. 테스트 주문 방법과 테스트 결제 수단은 정보 없음.

## 4. 이력 기록

7. #deploy 채널에 롤백 이력을 남긴다. 기록 형식과 포함할 항목은 정보 없음.
