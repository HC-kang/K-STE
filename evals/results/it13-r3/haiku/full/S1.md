Redis를 쓰면 4대 서버가 같은 캐시 내용을 보게 되므로, 가격을 바꿨을 때 서버마다 다른 가격이 나가는 문제를 줄일 수 있습니다.

캐시는 자주 쓰는 데이터를 빨리 꺼내려고 따로 저장해 둔 사본이고, Redis는 여러 서버가 함께 쓰는 별도 캐시 저장 서버입니다. 두 방식의 차이는 다음과 같습니다.

| 기준 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버 안 | 캐시 서버 1대 |
| 서버 간 값 | 서버마다 다름 | 4대가 같은 값을 봄 |
| 조회 속도 | 가장 빠름 | 네트워크를 거치므로 조금 느림 |
| 추가로 관리할 것 | 없음 | 캐시 서버 1대를 따로 운영해야 함 |

다만 Redis를 도입한다고 가격 반영 지연이 자동으로 없어지지는 않습니다. 캐시 유효 시간을 지금처럼 5분으로 두면, 가격 반영은 여전히 최대 5분 늦을 수 있습니다. 가격을 바꾼 뒤 캐시를 언제 지우거나 갱신하는지에 따라 반영 시점이 정해집니다.

고객에게 가격 변경이 몇 분 안에 보여야 하는지 기준을 정해 주십시오.
