가장 유력한 원인은 `@company/ui` 2.0.0의 `exports` 필드(패키지가 외부에 공개할 진입 경로를 정한 설정)에 `button` 경로가 없어서, `@company/ui/button` 같은 하위 경로 import(패키지 안의 특정 파일을 경로로 직접 가져오는 방식)가 막힌 것으로 보입니다. 다만 2.0.0의 `exports` 내용을 아직 확인하지 않았으므로 이는 추론입니다.

### 제공된 사실

- 3일 전 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 새로 추가됐습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치됐습니다.

### 추론

1. 로컬 `node_modules`에는 아직 1.4.0이 남아 있을 가능성이 큽니다. 이 경우 `@company/ui/button`이 정상적으로 해석되므로 로컬 빌드가 성공합니다. `exports` 필드가 2.0.0에서 처음 추가됐으므로, 1.4.0에는 하위 경로를 제한하는 설정이 없었던 것으로 보입니다.
2. `package-lock.json`이 2.0.0으로 갱신됐다면, 해시가 바뀌어 CI 캐시가 무효화되고 CI는 2.0.0을 새로 설치합니다. 이 때문에 CI에서만 오류가 나타나는 현상을 설명할 수 있습니다.
3. Node 18과 20의 차이는 주된 원인으로 보기 어렵습니다. Node 18도 `exports` 필드를 지원하므로, 버전 차이만으로 이 오류가 생긴다고 보기는 어렵습니다. 다만 Next.js나 TypeScript의 모듈 해석 방식이 Node 버전에 따라 달라지는지는 확인하지 않았습니다.

### 미확인

- 2.0.0의 `exports` 필드에 `button` 경로가 포함돼 있는지 확인하지 않았습니다.
- CI 로그에서 실제로 설치된 `@company/ui` 버전을 확인하지 않았습니다.
- 로컬에서 설치된 버전을 확인하지 않았습니다.
- 로컬 `node_modules`를 새로 설치해도 같은 오류가 나는지 확인하지 않았습니다.

### 다음 확인 단계

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports` 항목에 `./button` 또는 `./*` 패턴이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 새로 설치한 뒤 빌드해, 같은 오류가 재현되는지 확인합니다.
4. CI 로그에서 `@company/ui`의 설치 버전을 확인합니다.

### 해결 방안

확인 결과에 따라 다음 중 하나를 선택할 수 있습니다.

- `@company/ui/button`을 2.0.0이 공개한 경로로 바꿉니다.
- `@company/ui` 관리 팀에 `button` 경로를 `exports`에 추가해 달라고 요청합니다.
- 일시적으로 `@company/ui`를 1.4.0에 고정합니다.
