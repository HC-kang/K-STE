이 문서는 payment-api 운영 배포를 ArgoCD로 롤백하는 절차를 설명한다. 절차는 사전 확인, 롤백 실행, 롤백 후 확인, 이력 기록 순서로 한다.

## 1. 사전 확인

롤백 전에 대상 배포에 DB 마이그레이션(DB 구조 변경 스크립트)이 포함됐는지 반드시 확인해야 한다.
확인 필요: 마이그레이션 포함 여부를 확인하는 도구와 절차.

**마이그레이션이 포함됐으면 롤백하면 안 된다.** 이 경우 DBA 박지은에게 연락해야 한다.

마이그레이션이 포함되지 않은 경우에만 2단계로 넘어간다.

## 2. 롤백 실행

다음 명령으로 롤백한다.

`argocd app rollback payment-api <REVISION>`

`<REVISION>` 자리에는 롤백할 대상 리비전을 넣는다.
확인 필요: 대상 리비전 값을 찾는 방법.

## 3. 롤백 후 확인

롤백 후 다음 두 가지를 확인한다.

1. `/healthz`가 200을 반환하는지 확인한다.
   확인 필요: `/healthz` 요청을 보낼 주소.
2. 결제 테스트 주문 1건이 성공하는지 확인한다.
   확인 필요: 결제 테스트 주문을 실행하는 방법.

## 4. 이력 기록

롤백 이력은 #deploy 채널에 남긴다.
