# 운영 배포 롤백 런북: payment-api

payment-api의 운영 배포를 ArgoCD(배포 도구)로 이전 리비전(배포 버전 번호)으로 되돌린다. 롤백 전에 이 배포에 DB 마이그레이션(데이터베이스 구조를 바꾸는 작업)이 포함됐는지 반드시 확인해야 한다. 마이그레이션이 포함됐으면 롤백하면 안 되고, DBA(데이터베이스 관리자) 박지은에게 연락해야 한다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법.
2. **경고:** 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때 DBA 박지은에게 연락해야 한다. 확인 필요: 박지은에게 연락하는 방법.
3. 마이그레이션이 포함되지 않았을 때만 다음 단계로 진행한다. 롤백할 리비전 번호를 확인한다. 확인 필요: 리비전 번호를 확인하는 방법.

## 롤백

4. 마이그레이션이 포함되지 않았는지 확인한 뒤 다음 명령으로 롤백한다.

```
argocd app rollback payment-api <REVISION>
```

`<REVISION>`에는 3단계에서 확인한 리비전 번호를 넣는다.

## 결과 확인

5. `/healthz`가 200을 반환하는지 확인한다. 확인 필요: `/healthz`를 호출하는 주소와 방법.
6. 결제 테스트 주문을 1건 실행하고, 주문이 성공하는지 확인한다. 확인 필요: 테스트 주문 방법과 사용할 계정.

## 기록

7. 롤백 이력을 #deploy 채널에 남긴다. 확인 필요: 이력에 담을 항목과 형식.
