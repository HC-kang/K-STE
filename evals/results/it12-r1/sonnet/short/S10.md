원인은 `@company/ui` 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 제한하는 `package.json` 설정)일 가능성이 가장 높습니다. 로컬과 CI가 서로 다른 버전을 설치해서 결과가 갈렸다고 추정하며, 아직 확인하지 않았습니다.

**추론 근거**

- `exports` 필드가 있는 패키지는 `exports`에 적힌 경로만 불러올 수 있습니다. 2.0.0의 `exports`에 `./button`이 없으면 파일이 실제로 있어도 `Cannot find module '@company/ui/button'`이 발생합니다.
- 1.4.0에는 `exports`가 없으므로 같은 경로가 파일 위치 그대로 풀립니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했으므로 1.4.0일 가능성이 높습니다. 그래서 로컬 빌드는 성공합니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 2.0.0으로 올리면서 lock 파일이 바뀌었다면 캐시가 새로 만들어지고 CI는 2.0.0을 설치합니다. 그래서 CI 빌드는 실패합니다.
- Node 18과 20은 모두 `exports`를 지원하므로 Node 버전 차이가 주원인일 가능성은 낮습니다. 다만 배제하지는 못했습니다.

**확인되지 않은 것**

- 로컬에 실제로 설치된 `@company/ui` 버전
- CI가 설치한 버전과 `package-lock.json`에 고정된 버전
- 2.0.0의 `exports`에 `./button`이 있는지 여부

**확인 순서**

1. 로컬과 CI 양쪽에서 `npm ls @company/ui`를 실행해 설치된 버전을 비교합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.
3. 로컬에서 `node_modules`를 지우고 Node 18로 `npm ci`를 실행한 뒤 빌드합니다. 로컬에서도 같은 에러가 나면 원인이 확정되고, Node 버전 차이도 함께 가려집니다.

**수정 방향**

`exports`에 `./button`이 없다면 방향은 세 가지입니다. 패키지 담당자가 `exports`에 `./button`을 추가하거나, 앱의 import 경로를 `exports`에 정의된 경로로 바꾸거나, 임시로 1.4.0으로 되돌릴 수 있습니다. `./button`이 이미 있다면 `exports`의 조건 설정(`import`, `require` 등)을 추가로 확인해야 합니다.
