Redis를 도입하면 서버 4대가 같은 캐시를 같이 읽으므로, 서버마다 상품 목록이 다르게 보이는 문제가 사라집니다. 캐시는 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 방식입니다.

지금 쓰는 로컬 캐시는 API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 그래서 서버마다 캐시 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 캐시 전용 서버 1대에 상품 목록을 저장하고, API 서버 4대가 이 서버를 같이 읽습니다. 그래서 고객은 어느 API 서버에 연결돼도 같은 상품 목록을 봅니다.

가격 반영 지연은 Redis만 도입한다고 줄지 않습니다. 저장 시간을 5분으로 그대로 두면 가격 반영은 여전히 최대 5분 늦을 수 있습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지우거나 갱신하는 동작을 함께 만들어야 지연이 줄어듭니다. 이 동작을 넣을지는 개발팀과 정해야 합니다.

Redis 서버가 1대이므로, 이 서버가 멈추면 API 서버 4대가 모두 Redis 캐시를 쓰지 못합니다.
