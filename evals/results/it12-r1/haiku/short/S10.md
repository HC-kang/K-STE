본 건의 가장 유력한 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지 외부에 공개할 경로를 정한 설정)다. 이 설정으로 `@company/ui/button`처럼 패키지 하위 경로를 직접 가져오는 import가 CI에서 해석되지 않는 것으로 보인다. 다만 이는 추론이며 아래 확인 절차로 검증해야 한다.

## 확인된 사실

CI 빌드는 Node 18 환경에서 `Error: Cannot find module '@company/ui/button'` 에러로 실패한다.
로컬 빌드는 Node 20 환경에서 성공한다.
`@company/ui`는 3일 전에 1.4.0에서 2.0.0으로 올라갔다.
2.0.0에는 `exports` 필드가 추가됐다.
CI 캐시 키(저장된 설치 결과를 찾을 때 쓰는 식별값)는 `package-lock.json`(설치 버전을 고정하는 파일)의 해시다.
로컬 `node_modules`(설치된 패키지가 담긴 폴더)는 3일 전보다 먼저 설치됐다.

## 추론

로컬 `node_modules`가 3일 전보다 먼저 설치됐으므로 로컬에는 1.4.0이 남아 있을 가능성이 높다. 1.4.0에는 `exports` 필드가 없어 하위 경로 import가 그대로 동작한다. 따라서 로컬 빌드는 2.0.0을 검증하지 못했을 가능성이 크다.

CI 캐시 키가 `package-lock.json` 해시이므로 버전 변경 후 캐시가 새로 만들어졌을 가능성이 높다. 그러면 CI는 2.0.0을 새로 설치했고, 그 시점에 문제가 드러났을 것이다.

보고된 에러 문구는 Node에서 `exports`가 경로를 차단할 때 보통 나오는 문구(`ERR_PACKAGE_PATH_NOT_EXPORTED`)와 다르다. 그러므로 `exports` 외에 2.0.0 패키지 안에 `button` 파일이 실제 경로에 없을 가능성도 남아 있다.

Node 18과 20의 차이가 원인일 가능성은 낮다고 본다. Node 18도 `exports` 필드를 지원하기 때문이다.

## 미확인 사항

2.0.0 패키지의 `exports` 필드에 `./button` 경로가 포함되어 있는지 확인되지 않았다.
CI가 실제로 설치한 `@company/ui` 버전이 2.0.0인지 확인되지 않았다.
로컬에 설치된 `@company/ui` 버전이 실제로 1.4.0인지 확인되지 않았다.
CI의 설치 명령(`npm ci` 또는 `npm install`)과 Next.js 버전이 확인되지 않았다.
로컬과 CI가 같은 `package-lock.json` 커밋을 쓰는지 확인되지 않았다.

## 확인 절차

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인해야 한다.
2. CI 로그에서 설치된 `@company/ui` 버전을 확인해야 한다.
3. 2.0.0 패키지의 `package.json`에서 `exports` 필드를 열어 `./button` 항목이 있는지 확인해야 한다.
4. 2.0.0 변경 로그에서 하위 경로 import가 바뀌었는지 확인해야 한다.
5. 로컬에서 Node 18로 2.0.0 기준 빌드를 실행해 CI 에러를 재현해야 한다.

## 권장 조치

`exports`에 `./button` 항목이 없으면 import 경로를 2.0.0이 공개한 경로로 바꾸는 방안을 권장한다. 경로 수정이 어렵거나 시급하면 `@company/ui`를 1.4.0으로 되돌리는 방안도 검토할 수 있다. 재현 결과가 `exports` 원인과 맞지 않으면 파일 경로 문제를 먼저 확인해야 한다.
