Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되어, 서버마다 가격이 다르게 보이는 문제는 사라집니다. 하지만 가격을 바꾼 뒤 고객에게 최대 5분 늦게 반영되는 지연은 Redis만으로 자동으로 없어지지 않습니다.

지금은 서버 4대 각각이 상품 목록을 자기 메모리(작업 중인 데이터를 잠시 두는 공간)에 따로 저장하는 로컬 캐시(자주 쓰는 데이터를 미리 복사해 두는 임시 저장소)를 씁니다. Redis(여러 서버가 함께 쓰는 캐시 전용 프로그램)는 캐시 전용 서버 1대에 상품 목록을 한 벌만 두고, 서버 4대가 모두 그 한 벌을 읽습니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있음 | 4대가 같은 값을 봄 |
| 가격 변경 반영 | 서버마다 최대 5분 늦음 | 캐시 유효 시간 동안 최대 5분 늦음 |
| 조회 속도 | 서버 안에서 읽어 가장 빠름 | 네트워크를 거쳐 읽어 로컬보다 느림 |
| 장애 영향 | 서버 한 대가 멈추면 그 서버만 영향 | Redis 서버가 멈추면 4대 모두 영향 |

지연을 줄이려면 가격을 바꿀 때 Redis 캐시를 바로 지우는 작업을 함께 넣는 방식을 검토하기를 권장합니다. 이렇게 하면 캐시 유효 시간을 기다리지 않고 가격이 바로 반영됩니다.

확인 필요: Redis 서버가 멈출 때 대비하는 방안이 정해져 있는지 확인해야 합니다.
