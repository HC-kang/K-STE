Redis를 도입하고 가격을 바꿀 때 Redis에 있는 상품 정보도 함께 바꾸면, 4대 서버가 같은 가격을 같은 시점에 보게 됩니다.

캐시(자주 보는 데이터를 미리 복사해 두는 임시 저장소)는 매번 원본 데이터베이스(DB)를 다시 읽지 않도록 사본을 두는 장치입니다. 지금은 서버 4대가 각자 사본을 가지고 있고, 도입 예정인 Redis(여러 서버가 함께 쓰는 공용 캐시 서버 프로그램)는 사본을 1개만 둡니다.

| 구분 | 로컬 캐시 (지금 방식) | Redis 캐시 (도입 예정) |
|---|---|---|
| 사본을 두는 곳 | 서버 4대 각각의 메모리(서버가 작업할 때 쓰는 공간) | 공용 캐시 서버 1대 |
| 사본 개수 | 4개 | 1개 |
| 서버끼리 값 일치 | 값이 서로 다를 수 있습니다 | 모든 서버가 같은 값을 읽습니다 |
| 읽는 속도 | 서버 안에서 바로 읽어서 가장 빠릅니다 | 다른 서버를 거치므로 로컬보다 느립니다 |
| 가격 변경 후 고객 화면 | 서버마다 만료 시점이 달라 최대 5분 늦게 보입니다 | Redis 값을 함께 바꾸면 모든 서버가 같은 가격을 봅니다 |

Redis를 도입해도 가격을 바꿀 때 Redis 값을 함께 바꾸지 않으면, 지금처럼 최대 5분 늦게 보입니다. 그래서 좋아지는 점은 Redis 도입 자체보다 가격 변경 때 Redis 값을 바꾸는 작업을 함께 할 때 생깁니다.

Redis 서버가 멈추면 4대 서버 모두 이 캐시를 쓸 수 없으므로, 멈췄을 때의 대비가 필요합니다.

확인 필요: 가격 변경 때 Redis 값도 함께 바꾸는 작업을 이번 도입 범위에 넣을지 정해야 합니다.
