# 운영 배포 롤백 런북

## 목적

이 런북은 ArgoCD(배포 도구)로 배포한 payment-api를 이전 리비전으로 되돌리는 절차를 설명한다. 롤백 전에 해당 배포에 DB 마이그레이션(데이터베이스 구조를 바꾸는 변경 스크립트)이 포함됐는지 반드시 확인해야 한다.

## 절차

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다. 확인 필요: 포함 여부를 확인하는 방법과 도구.
2. 1번에서 마이그레이션이 포함됐으면 롤백하면 안 된다. DBA 박지은에게 연락해야 한다.
3. 1번에서 마이그레이션이 포함되지 않았으면 다음 명령으로 롤백한다: `argocd app rollback payment-api <REVISION>`. 확인 필요: `<REVISION>`에 넣을 값의 형식(배포 이력 번호인지 커밋 해시인지).
4. 롤백한 뒤 `/healthz`가 200을 반환하는지 확인한다. 확인 필요: `/healthz`를 호출할 주소.
5. 롤백한 뒤 결제 테스트 주문 1건이 성공하는지 확인한다. 확인 필요: 테스트 주문을 진행하는 방법과 성공 기준.
6. 롤백 이력을 #deploy 채널에 남긴다. 확인 필요: 이력에 적을 항목.

## 확인 필요 시 조치

확인 필요: 4번 또는 5번이 실패했을 때 따를 조치. 원문에 없는 내용이라 이 런북에 적지 않았다.
