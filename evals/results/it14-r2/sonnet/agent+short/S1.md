Redis를 도입하면 서버 4대가 같은 캐시(자주 쓰는 데이터를 임시로 저장해 두는 곳)를 쓰므로, 서버마다 상품 목록이 다르던 문제를 없앨 수 있습니다.

지금은 API 서버(앱의 요청을 받아 응답하는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 이것이 로컬 캐시입니다. 서버마다 저장된 내용이 달라서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 함께 쓰는 캐시 서버 1대에 상품 목록을 저장합니다. 4대가 같은 저장소를 읽으므로 모두 같은 내용을 봅니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 함께 갱신하면, 지금처럼 최대 5분 늦게 반영되는 지연을 줄일 수 있습니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대 각자의 메모리 | 서버 4대가 같이 쓰는 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대가 같은 내용을 봅니다 |
| 가격 변경 시 | 고객에게 최대 5분 늦게 반영됩니다 | Redis의 상품 목록을 함께 갱신하면 지연을 줄일 수 있습니다 |

확인 필요: Redis 서버가 1대이므로, 이 서버가 멈출 때 서비스가 어떻게 동작하는지는 제가 가진 정보에 없습니다.
