원인은 로컬 빌드와 CI 빌드가 서로 다른 버전의 `@company/ui`를 쓰기 때문일 가능성이 가장 높습니다. 아래 내용 중 사실이 아닌 부분은 추론이며, 아직 실행해서 검증한 것은 없습니다.

사실은 다음과 같습니다. 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸고, 2.0.0부터 패키지에 `exports` 필드(패키지 밖에서 import할 수 있는 경로를 패키지가 직접 정하는 설정)가 있습니다. 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다. CI는 Node 18, 로컬은 Node 20을 씁니다. CI 캐시 키는 `package-lock.json`의 해시입니다.

추론은 다음과 같습니다.

- 로컬 `node_modules`에는 아직 1.4.0이 있을 가능성이 높습니다. 1.4.0에는 `exports`가 없으므로 `@company/ui/button`을 파일 경로로 찾아 성공했을 수 있습니다.
- CI는 `package-lock.json`이 바뀌어 캐시 키가 달라졌으므로, 2.0.0을 새로 설치했을 가능성이 높습니다. 2.0.0에서는 `exports`에 `./button`이 없으면 `Cannot find module '@company/ui/button'` 오류가 납니다.
- Node 18과 Node 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 주된 원인일 가능성이 낮습니다. 다만 배제하지는 못했습니다.
- 캐시는 원인이 아닐 가능성이 높습니다. 락 파일이 바뀌어 캐시 키도 바뀌었기 때문입니다. 락 파일에 2.0.0이 실제로 반영됐는지는 아직 보지 않았습니다.

아래 순서로 검증하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 위 추론이 맞을 가능성이 높습니다.
2. CI 로그에서 설치된 `@company/ui` 버전을 보십시오.
3. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
4. 로컬 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 오류가 나면 원인이 Node 버전이 아니라 패키지 버전이라는 근거가 됩니다.
5. 4번에서 로컬 오류가 재현되지 않으면 Node 18로 같은 빌드를 실행하십시오.

3번에서 `exports`에 `./button`이 없으면 다음 두 가지 중 하나를 해야 합니다. 앱의 import 경로를 2.0.0이 공개한 경로로 바꾸거나, `@company/ui` 관리자에게 `./button` 경로를 `exports`에 추가해 달라고 요청하십시오. 어느 쪽이 맞는지는 2.0.0의 변경 내역을 봐야 정할 수 있습니다.

확인 필요: 2.0.0이 `button`을 다른 경로로 옮겼는지, 아니면 공개 경로에서 뺐는지 현재 정보로는 알 수 없습니다.
