Redis를 도입하면 API 서버 4대가 같은 상품 목록을 보게 됩니다. 지금은 서버마다 캐시 내용이 다릅니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두고 다시 꺼내 쓰는 방식입니다. 지금은 API 서버 4대가 각자 자기 메모리(서버 한 대 안의 작업 공간)에 상품 목록을 5분 동안 저장합니다. 이것이 로컬 캐시입니다. 서버마다 캐시 내용이 달라서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 캐시 전용 서버 1대에 상품 목록을 저장하고, API 서버 4대가 그 서버를 같이 읽는 방식입니다. 그래서 어느 API 서버에 접속하든 고객은 같은 상품 목록을 봅니다.

확인 필요: 가격 반영이 늦는 시간이 얼마나 줄어드는지는 Redis에 상품 목록을 얼마 동안 저장하는지, 가격을 바꿀 때 Redis의 상품 목록을 바로 지우는지에 달려 있습니다. 저는 이 설계를 아직 모릅니다. Redis에 상품 목록을 5분 동안 저장하고 가격을 바꿀 때 지우지 않으면, 최대 5분 늦게 반영되는 현상은 그대로 남습니다.
