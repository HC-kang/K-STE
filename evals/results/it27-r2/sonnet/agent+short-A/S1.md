Redis를 도입하면 API 서버 4대가 같은 캐시를 보게 되므로, 서버마다 캐시 내용이 달라서 생기는 문제가 사라집니다.

캐시는 자주 쓰는 데이터를 매번 새로 가져오지 않도록 임시로 저장해 두는 공간입니다. 지금은 API 서버(고객 요청을 받아 응답하는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 이것이 로컬 캐시입니다. Redis 캐시는 캐시 전용 서버 1대를 따로 두고, API 서버 4대가 그 서버 하나를 같이 쓰는 방식입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대가 각자 자기 메모리에 저장합니다. | 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 서버 4대가 같은 내용을 봅니다. |

현재는 서버마다 캐시를 따로 가지고 있어서, 가격을 바꾸면 서버에 따라 고객에게 최대 5분 늦게 반영됩니다. Redis를 도입하면 캐시가 한 곳에만 있으므로, 같은 시점에 어느 서버로 요청이 가도 고객이 같은 가격을 보게 됩니다.

다만 가격 변경이 고객에게 반영되는 시간이 5분에서 얼마로 줄어드는지는 알려 주신 정보에 없습니다. 이 시간은 가격을 바꿀 때 캐시를 어떻게 갱신하느냐에 달려 있는 것으로 보입니다.

확인 필요: Redis 도입 후 가격 변경 시 캐시를 즉시 갱신하는지, 지금처럼 5분 보관 시간이 지나야 갱신하는지.
