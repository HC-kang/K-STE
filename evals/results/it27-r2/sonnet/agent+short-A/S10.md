로컬 빌드가 1.4.0으로 돌고 CI 빌드만 2.0.0으로 돌기 때문에 실패가 CI에서만 나는 것으로 보입니다. 아래 내용은 모두 추론이고, 실제 원인은 아직 확인하지 않았습니다.

로컬 `node_modules`는 3일 전보다 먼저 설치했고, `@company/ui`를 올린 것은 3일 전입니다. 그래서 로컬에는 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없습니다. `exports`는 패키지가 바깥에 공개하는 import 경로를 직접 정하는 필드입니다. `exports`가 없으면 `@company/ui/button`처럼 패키지 안쪽 파일 경로를 자유롭게 import할 수 있습니다.

CI 캐시 키는 `package-lock.json`의 해시입니다. 버전을 올리면서 lock 파일이 바뀌었으므로 캐시가 맞지 않았을 것이고, CI는 `@company/ui` 2.0.0을 새로 설치했을 것입니다. 2.0.0에는 `exports`가 있습니다. `exports`에 `./button` 항목이 없거나 경로가 달라졌다면, Node가 `@company/ui/button`을 찾지 못해 `Cannot find module` 오류가 납니다.

Node 18과 Node 20의 차이는 원인으로 보이지 않습니다. 두 버전 모두 `exports`를 지원합니다. 다만 이 부분도 실행해서 확인하지 않았습니다.

원인을 확정하려면 다음 순서로 확인해야 합니다.

1. 로컬에서 `node_modules/@company/ui/package.json`의 `version`이 1.4.0인지 봅니다.
2. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button` 항목이 있는지 봅니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 2.0.0을 새로 설치한 뒤 빌드합니다. CI와 같은 오류가 나면 원인이 확정됩니다.

3번에서 같은 오류가 나면 두 가지 중 하나로 고칩니다.

- 2.0.0 문서에 나온 새 import 경로로 코드를 바꿉니다.
- `@company/ui` 담당 팀에 `./button` 공개를 요청합니다.

확인 필요: 2.0.0 업그레이드가 의도한 변경인지, 그리고 `exports`에서 `./button`을 뺀 것이 의도한 변경인지 `@company/ui` 담당 팀에 물어봐야 합니다. 이 답에 따라 어느 쪽을 고칠지 달라집니다.
