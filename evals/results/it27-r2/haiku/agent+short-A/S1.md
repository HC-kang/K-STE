Redis를 도입하면 서버 4대가 같은 캐시를 함께 쓰므로, 서버마다 캐시 내용이 달라지는 문제가 없어집니다. 다만 Redis 도입만으로 가격 변경이 고객에게 보이는 시점이 빨라지지는 않습니다.

차이를 설명하겠습니다. 캐시는 자주 쓰는 자료를 빨리 꺼내 쓰려고 잠시 저장해 두는 공간입니다. 지금 방식인 로컬 캐시는 각 API 서버 안의 메모리(프로그램이 작업할 때 쓰는 공간)에 상품 목록을 저장합니다. 서버 4대가 각자 5분 동안 저장하므로, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 여러 서버가 함께 쓰는 별도의 캐시 서버입니다. 서버 4대가 같은 Redis를 조회하므로, 저장된 상품 목록은 하나입니다.

가격 변경이 고객에게 늦게 보이는 문제는 Redis를 어떻게 운영하느냐에 따라 달라집니다. 보관 시간 5분이 지난 뒤에만 자료를 새로 가져오는 방식이면 지연은 여전히 최대 5분입니다. 가격을 바꿀 때 Redis에 저장된 캐시를 바로 지우면 지연을 줄일 수 있습니다.
