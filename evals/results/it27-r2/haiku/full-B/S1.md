Redis(여러 서버가 함께 쓰는 공용 캐시 서버)를 도입하면 서버 4대가 같은 상품 정보를 보게 되어 서버마다 내용이 달라지는 문제는 없어집니다. 다만 가격이 고객에게 몇 분 안에 반영되는지는 Redis를 어떻게 설정하느냐에 따라 달라지므로, 반영 시간이 얼마나 줄어드는지는 지금 단정할 수 없습니다.

지금 방식은 각 API 서버(고객 요청을 받아 응답하는 서버)가 자기 메모리(작업 중에 쓰는 임시 공간)에 상품 목록을 5분 동안 캐시(자주 쓰는 데이터를 미리 저장해 두는 것)합니다. 서버 4대가 각자 따로 저장하므로 서버마다 가진 내용이 다를 수 있고, 가격을 바꾸면 고객에게 최대 5분 늦게 보입니다.

Redis 방식은 4대 서버가 같은 캐시 서버에서 상품 목록을 읽으므로 서버끼리 내용이 어긋나지 않습니다. 대신 서버가 Redis까지 네트워크로 한 번 다녀와야 해서 메모리에서 읽을 때보다 조금 느릴 수 있고, Redis 서버에 문제가 생기면 4대 서버 모두 영향을 받을 수 있습니다.

가격 반영을 더 빠르게 하려면 가격을 바꿀 때 Redis에 저장된 상품 캐시를 바로 지우는 방식을 개발팀과 정해야 합니다.
