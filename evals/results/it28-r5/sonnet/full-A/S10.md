원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰기 때문일 가능성이 높습니다. 로컬은 1.4.0, CI는 2.0.0으로 보입니다.

근거는 네 가지입니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했으므로 1.4.0이 그대로 남아 있을 수 있습니다.
- CI(코드를 올리면 자동으로 빌드하는 서버)의 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 이 파일이 바뀌었다면 CI는 캐시 없이 2.0.0을 새로 설치합니다.
- 2.0.0에서 추가된 `exports` 필드는 패키지가 외부에 공개할 파일 경로의 목록입니다. 목록에 없는 경로는 import할 수 없습니다.
- 2.0.0의 `exports`에 `./button` 항목이 없거나 형태가 다르면 `Cannot find module '@company/ui/button'`이 발생합니다.

Node 18과 20은 모두 `exports` 필드를 지원하므로, Node 버전 차이는 원인일 가능성이 낮습니다.

원인을 좁히려면 다음 순서로 진행하십시오.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
2. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드하십시오. CI와 같은 오류가 나면 위 원인이 맞습니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button` 항목이 있는지 보십시오. 없으면 패키지에 항목을 추가하거나, import 경로를 `exports`에 있는 경로로 바꾸는 방법이 있습니다.
