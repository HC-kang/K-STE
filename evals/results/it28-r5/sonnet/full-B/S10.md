로컬 빌드는 성공하고 CI(코드가 바뀔 때마다 자동으로 빌드를 돌리는 환경)에서만 실패하는 이유는, 두 환경이 서로 다른 버전의 `@company/ui`를 쓰기 때문으로 보입니다.

사실은 다음과 같습니다. 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다. 2.0.0에는 `exports` 필드(패키지가 외부에 공개하는 경로를 정하는 `package.json` 항목)가 추가됐습니다. 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다. CI 캐시 키는 `package-lock.json`의 해시입니다. CI는 Node 18, 로컬은 Node 20을 씁니다.

추론은 다음과 같습니다. 로컬 `node_modules`가 업그레이드 전에 설치됐으므로, 로컬에는 `exports` 필드가 없는 1.4.0이 남아 있을 가능성이 큽니다. 이 경우 `@company/ui/button`처럼 패키지 안쪽 경로를 직접 가져오는 import가 그대로 동작합니다. 반면 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀝니다. 그러면 CI는 캐시를 쓰지 않고 2.0.0을 새로 설치합니다. 2.0.0에서는 `exports`에 없는 경로를 가져올 수 없으므로, `./button` 경로가 `exports`에 없다면 `Cannot find module '@company/ui/button'`이 발생합니다.

Node 버전 차이는 원인일 가능성이 낮아 보입니다. Node 18과 Node 20 모두 `exports` 필드를 지원하기 때문입니다.

먼저 2.0.0의 `package.json`에서 `exports`에 `./button` 항목이 있는지 보십시오. 그다음 로컬에서 `node_modules`를 지우고 lockfile 기준으로 다시 설치한 뒤 같은 에러가 재현되는지 보십시오.
