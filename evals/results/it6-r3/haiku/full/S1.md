로컬 캐시는 각 API 서버가 자기 메모리에 상품 목록을 임시로 저장해 두는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도의 캐시 서버(Redis는 데이터를 메모리에 두고 빠르게 꺼내 쓰는 서버 프로그램입니다)에 저장하는 방식입니다.

Redis를 도입하면 서버 4대가 같은 데이터를 보게 되므로, 지금처럼 서버마다 상품 목록이 달라지는 문제가 없어집니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있음 | 4대가 같은 데이터를 봄 |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영 | 캐시를 언제 갱신하는지에 따라 달라짐 |

다만 가격 변경이 고객 화면에 반영되는 시간은 Redis를 도입한다고 자동으로 줄어들지 않습니다. 가격이 바뀌었을 때 캐시를 비우거나 갱신하는 방식은 아직 확인하지 않았습니다. 이 방식이 정해져야 고객에게 반영되는 시간을 말씀드릴 수 있습니다.
