가장 유력한 원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고 있고, CI만 2.0.0을 설치해서 `@company/ui/button` 경로가 막힌 것입니다. 이 내용은 추론이며, 아래 절차로 확인해야 합니다.

근거는 다음과 같습니다.

- 2.0.0에서 `exports` 필드(패키지가 외부에 공개하는 경로의 목록)가 추가됐습니다.
- `exports`가 있으면 Node는 목록에 없는 하위 경로 import를 막고 `Cannot find module`을 냅니다.
- 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로 그대로 열렸습니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것이므로 1.4.0이 남아 있을 가능성이 높습니다.
- CI 캐시 키는 `package-lock.json` 해시입니다. 업그레이드로 lock 파일이 바뀌었다면 캐시가 갱신되어 CI는 2.0.0을 설치합니다.

Node 18과 20은 둘 다 `exports`를 지원하므로 Node 버전 차이는 원인일 가능성이 낮습니다.

확인 필요: 2.0.0의 `exports`에 `./button`이 없는지, 있지만 경로 이름이 바뀌었는지는 아직 모릅니다. 어느 쪽이든 에러는 같게 나타납니다.

확인 절차는 다음과 같습니다.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다. 1.4.0이면 가설과 일치합니다.
2. CI와 같은 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드합니다. CI와 같은 에러가 나면 재현된 것입니다.

재현되면 해결 방법은 둘 중 하나입니다. `exports`에 공개된 경로로 import를 바꾸거나, `@company/ui` 담당자에게 `./button` 공개를 요청합니다.

PM이 알아둘 점은, 업그레이드 이후 로컬 빌드 성공이 CI 성공을 보장하지 않았다는 것입니다. 원인이 확인되기 전까지 이 앱의 배포는 CI 결과를 기준으로 판단해야 합니다.
