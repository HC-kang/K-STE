로컬에 `@company/ui` 1.4.0이 남아 있고 CI는 2.0.0을 설치하기 때문일 가능성이 가장 높습니다. 아직 확인하지 않은 추론입니다.

## 추론의 근거

- 2.0.0에서 `exports` 필드(패키지가 외부에 공개하는 import 경로 목록)가 추가됐습니다. `exports`가 있으면 Node는 목록에 없는 하위 경로의 import를 막습니다.
- 1.4.0에는 `exports`가 없어서 `@company/ui/button`을 파일 경로로 import할 수 있었습니다. 2.0.0의 `exports`에 `./button`이 없거나 다르게 정의돼 있으면 `Cannot find module '@company/ui/button'` 오류가 납니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 lockfile(설치할 정확한 버전을 기록한 파일)이 바뀌었다면, CI는 캐시 없이 2.0.0을 새로 설치합니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다. 그 뒤에 다시 설치하지 않았다면 로컬은 1.4.0을 쓰고 있습니다.

## Node 버전 차이

Node 18과 Node 20은 모두 `exports`를 지원합니다. 그래서 Node 버전 차이가 직접 원인일 가능성은 낮습니다. 다만 이것도 확인하지 않았습니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다. 1.4.0이면 위 추론이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. 로컬에서도 같은 오류가 나면 원인이 확정됩니다.

## 대응 방향

원인이 확정되면 두 방법 중 하나를 고릅니다.

- import 경로를 2.0.0이 공개하는 경로로 바꿉니다.
- `@company/ui` 담당자에게 `./button` 공개를 요청합니다.

어느 쪽이 맞는지는 2.0.0 변경 내역을 봐야 알 수 있습니다. 변경 내역은 아직 확인하지 않았습니다.
