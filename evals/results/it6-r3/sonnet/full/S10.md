원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개할 파일 경로를 제한하는 설정)로 보입니다. 로컬은 3일 전보다 먼저 설치한 `node_modules`(설치된 패키지가 들어 있는 폴더)를 쓰므로 아직 1.4.0일 가능성이 높습니다. CI(푸시할 때 자동으로 빌드하는 환경)는 새로 설치하므로 2.0.0을 받습니다.

1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로 그대로 열립니다. 2.0.0은 `exports`에 적힌 경로만 열립니다. `exports`에 `./button`이 없으면 같은 import가 실패합니다.

Node 버전 차이와 캐시는 원인일 가능성이 낮습니다. Node 18도 `exports`를 지원하므로 18과 20의 차이로 이 증상이 생기지는 않습니다. 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀌어서 옛 캐시는 쓰이지 않습니다.

아직 확인하지 않은 것은 세 가지입니다.

1. 로컬 `node_modules/@company/ui/package.json`의 `version`이 1.4.0인지 확인하십시오.
2. CI 설치 로그에서 `@company/ui`가 2.0.0으로 설치됐는지 확인하십시오.
3. 2.0.0 `package.json`의 `exports`에 `./button`이 있는지 확인하십시오.

먼저 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 같은 에러가 재현되면 원인이 확정됩니다. 해결 방법은 import 경로를 2.0.0 `exports`에 있는 경로로 바꾸거나, 패키지 쪽 `exports`에 `./button`을 추가하는 두 가지입니다.
