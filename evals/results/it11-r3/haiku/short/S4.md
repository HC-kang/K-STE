이 런북은 ArgoCD로 `payment-api`의 운영 배포를 롤백하는 절차를 정리한다. 롤백 전에 DB 마이그레이션 포함 여부를 먼저 확인해야 하며, 포함됐으면 롤백하지 않는다.

## 사전 확인

롤백 명령을 실행하기 전에 되돌릴 배포에 DB 마이그레이션(데이터베이스 구조를 바꾸는 변경 스크립트)이 포함됐는지 확인해야 한다. 이 확인은 롤백 명령보다 먼저 끝내야 한다. 확인 방법은 아래 확인 필요 항목에 적는다.

**경고: 배포에 DB 마이그레이션이 포함됐으면 롤백하면 안 된다.** 이 경우 DBA 박지은에게 연락해야 한다.

## 롤백 절차

1. 마이그레이션이 포함되지 않았다고 확인되면 `argocd app rollback payment-api <REVISION>` 명령을 실행한다.
2. 명령을 실행한 뒤 롤백이 끝날 때까지 기다린다.
3. `/healthz`가 200을 반환하는지 확인한다.
4. 결제 테스트 주문 1건이 성공하는지 확인한다.
5. 롤백 이력을 #deploy 채널에 남긴다.

3번이나 4번이 실패하면 롤백 결과를 정상으로 보지 않는다.

확인 필요: 마이그레이션 포함 여부를 확인하는 도구나 명령이 주어지지 않았다.
확인 필요: `<REVISION>`에 넣을 값을 찾는 방법이 주어지지 않았다.
확인 필요: `/healthz`를 호출할 주소와 방법이 주어지지 않았다.
확인 필요: 결제 테스트 주문을 만드는 절차가 주어지지 않았다.
확인 필요: #deploy 채널에 남길 이력 항목이 주어지지 않았다.
확인 필요: DBA 박지은에게 연락하는 수단이 주어지지 않았다.
