로컬 캐시는 각 API 서버가 자기 메모리(작업용 임시 저장 공간)에 데이터를 보관하는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도 캐시 서버 1대에 데이터를 보관하는 방식입니다. 캐시는 자주 쓰는 데이터를 미리 저장해 두어 매번 원본을 조회하지 않게 하는 장치입니다.

지금은 서버 4대가 각자 상품 목록을 5분 동안 저장하므로 서버마다 저장된 내용이 다를 수 있습니다. 그래서 가격을 바꾸면 서버마다 반영 시점이 달라지고, 고객은 최대 5분 늦게 새 가격을 볼 수 있습니다.

Redis를 도입하면 서버 4대가 같은 저장소를 보므로 서버마다 내용이 달라지는 문제는 없어집니다. 다만 가격이 고객에게 얼마나 빨리 반영되는지는 캐시를 언제 갱신하거나 비우는지에 따라 달라집니다. 따라서 지금은 반영이 5분보다 빨라진다고 확정할 수 없으며, 개발팀에 갱신 방식을 확인해야 합니다.

| 항목 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버 메모리 | 별도 캐시 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있음 | 4대 서버가 같은 데이터를 봄 |
| 가격 반영 지연 | 최대 5분 | 캐시 갱신 방식에 따라 다름 (확인 필요) |
| 캐시 장치 장애 시 | 장애 난 서버만 영향을 받음 | 캐시 서버가 멈추면 4대 서버가 함께 영향을 받을 수 있음 |

정리하면 Redis 도입으로 확실히 좋아지는 점은 서버 간 데이터 일치입니다. 가격 반영 지연을 줄이는 효과는 갱신 방식을 정한 뒤에 수치로 확인해야 합니다. 캐시 서버가 멈출 때에 대비한 방안도 함께 논의하는 것을 권장합니다.
