Redis를 도입하면 서버 4대가 같은 캐시를 함께 쓰므로, 서버마다 가격 정보가 달라지는 문제가 없어집니다. 다만 캐시 유효 시간 5분을 그대로 두면 가격 반영 지연은 최대 5분으로 남습니다. 가격을 바꿀 때 Redis 캐시를 바로 지우는 작업을 함께 해야 4대 서버에 같은 시점부터 새 가격이 보입니다.

캐시는 자주 쓰는 데이터를 빠르게 꺼내 쓰도록 임시로 보관해 두는 공간이고, Redis는 여러 서버가 함께 쓰는 별도의 캐시 서버입니다. 두 방식의 차이는 다음과 같습니다.

| 구분 | 지금 방식(서버별 로컬 캐시) | 도입 예정(Redis 캐시) |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 가격 반영 | 서버마다 최대 5분 뒤 반영 | 캐시를 지우면 4대에 같은 시점에 반영 |
| 추가 운영 | 없음 | Redis 서버를 따로 관리해야 함 |

Redis를 쓰면 캐시를 조회할 때마다 네트워크를 거치므로 서버 메모리에서 바로 꺼내는 것보다 느립니다. Redis 서버가 멈추면 캐시를 쓸 수 없으므로, 그때 상품 목록을 DB에서 직접 읽도록 대비해야 합니다.

확인 필요: 이번 도입 범위에 가격 변경 시 Redis 캐시를 지우는 작업이 포함되는지는 제가 알 수 없습니다. 포함되지 않으면 가격 반영 지연은 최대 5분으로 그대로 남습니다.
