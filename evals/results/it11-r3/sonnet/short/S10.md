원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 제한하는 설정)로 보입니다. CI는 2.0.0을 설치하고, 로컬은 1.4.0이 남아 있어서 결과가 갈렸다고 추정합니다. 아직 확정은 아니며, 아래 확인이 필요합니다.

`@company/ui/button`은 패키지 안쪽 파일을 직접 가리키는 경로입니다. 1.4.0에는 `exports` 필드가 없어서 이 경로가 실제 파일 위치대로 열립니다. 2.0.0에서는 `exports`에 적힌 경로만 열리므로, `exports`에 `./button`이 없으면 `Cannot find module` 에러가 납니다.

로컬 빌드가 성공하는 이유는 로컬 `node_modules`를 3일 전보다 먼저 설치했기 때문으로 보입니다. 그러면 로컬에는 1.4.0이 그대로 있어서 `exports` 제한을 받지 않습니다. CI는 `package-lock.json`대로 새로 설치하므로 2.0.0을 받습니다. CI 캐시 키가 `package-lock.json`의 해시이고 업그레이드 때 이 파일이 바뀌었으므로, CI가 1.4.0 캐시를 재사용했을 가능성은 낮습니다.

Node 버전 차이는 원인일 가능성이 낮습니다. Node 18과 Node 20은 둘 다 `exports` 필드를 지원합니다.

아직 확인하지 않은 항목은 다음과 같습니다.

- 로컬에 실제로 설치된 `@company/ui` 버전
- 2.0.0의 `exports`에 `./button`이 있는지
- `./button`이 있다면 Next.js 빌드가 쓰는 조건(import 또는 require)과 맞는지

확인은 다음 순서로 하면 됩니다.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치 버전을 확인합니다.
2. `npm view @company/ui@2.0.0 exports`를 실행해 공개된 경로 목록에 `./button`이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. 같은 에러가 나면 원인이 재현된 것입니다.
4. 재현되면 `exports`에 `./button`이 없는 경우, 앱의 import 경로를 `exports`에 있는 경로로 바꾸거나 `@company/ui` 쪽에 `./button` 추가를 요청합니다.

2.0.0이 메이저 버전 업그레이드이므로, `@company/ui/button` 같은 안쪽 경로 import가 앱의 다른 곳에도 있으면 같은 에러가 추가로 나올 수 있습니다. 이 가능성도 3단계에서 함께 확인하는 것이 좋습니다.
