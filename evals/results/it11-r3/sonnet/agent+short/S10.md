로컬에서는 옛 버전 `@company/ui`를 쓰고 CI에서는 2.0.0을 쓰기 때문에 빌드 결과가 다른 것으로 보입니다. 아래 내용 중 사실은 전달받은 상황이고, 원인은 추론입니다. 추론은 아직 검증하지 않았습니다.

추론한 원인은 다음과 같습니다.

- 2.0.0에서 추가된 `exports` 필드(패키지가 외부에 공개하는 import 경로 목록)는 목록에 없는 경로의 import를 막습니다.
- `@company/ui/button`이 2.0.0의 `exports`에 정의돼 있지 않으면 `Cannot find module '@company/ui/button'` 에러가 납니다.
- CI는 `package-lock.json` 기준으로 2.0.0을 설치하므로 이 에러를 만납니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것이어서 아직 1.4.0일 가능성이 높습니다. 1.4.0에는 `exports`가 없으므로 같은 import가 성공합니다.

나머지 두 조건은 원인으로 보기 어렵습니다.

- Node 18과 20 차이: 두 버전 모두 `exports` 필드를 지원하므로 주원인으로 보기 어렵습니다.
- CI 캐시: 캐시 키가 `package-lock.json` 해시이고 업그레이드로 lock 파일이 바뀌었으므로, 캐시가 옛 버전을 붙잡고 있을 가능성은 낮습니다.

확인 필요: 2.0.0의 `exports`에 `./button`이 있는지는 전달받은 내용에 없습니다. 아래 순서로 확인하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 확인하십시오.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드하십시오. 같은 에러가 나면 CI와 같은 원인입니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오.
4. `./button`이 없으면 `@company/ui` 쪽에서 `exports`에 경로를 추가하거나, 앱의 import를 `exports`에 정의된 경로로 바꾸십시오.

2.0.0은 major 버전이므로 `button` 외에 다른 서브패스 import도 같은 에러를 낼 수 있습니다. 3번에서 `exports` 목록을 볼 때 앱이 import하는 `@company/ui/*` 경로를 함께 대조하는 것을 권장합니다.
