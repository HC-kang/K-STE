로컬 캐시는 서버 4대가 각자 따로 저장하고, Redis 캐시는 서버 4대가 하나를 같이 씁니다. 그래서 Redis를 도입하면 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두고 꺼내 쓰는 방식입니다. 지금 API 서버는 상품 목록을 5분 동안 각자 자기 메모리에 저장합니다. Redis는 여러 서버가 같이 쓰는 캐시 전용 서버이고, 이번에 1대를 도입할 예정입니다.

| 기준 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대의 각자 메모리 | 캐시 서버 1대 |
| 서버 간 캐시 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 가격을 바꿨을 때 | 고객에게 최대 5분 늦게 반영됨 | 서버마다 다르게 보이는 문제는 없어짐 |

지금은 서버마다 캐시를 저장한 시각이 달라서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. Redis를 도입하면 서버 4대가 같은 캐시를 읽습니다. 그래서 같은 상품이 서버에 따라 다른 가격으로 보이는 일이 없어집니다.

확인 필요: 5분 지연이 Redis 도입만으로 줄어드는지는 지금 정보로 알 수 없습니다. 지연이 줄어드는지는 가격을 바꿀 때 Redis에 저장된 캐시를 어떻게 갱신하는지에 달려 있습니다. 이 갱신 방식은 개발팀에 물어봐야 합니다.
