CI에서만 빌드가 실패한 원인은 `@company/ui` 2.0.0의 `exports` 필드일 가능성이 높습니다. `exports`는 패키지가 외부에 공개하는 경로를 정하는 설정이며, 목록에 없는 경로는 가져올 수 없습니다. 2.0.0에 `./button` 경로가 없다면 `@company/ui/button`을 찾지 못합니다.

로컬 `node_modules`(설치된 패키지가 저장되는 폴더)는 업그레이드 전에 설치했으므로 1.4.0이 남아 있을 것으로 보입니다. 이 경우 로컬 빌드는 2.0.0의 `exports` 제한을 받지 않습니다.

다른 차이는 원인일 가능성이 낮습니다. Node 18과 20은 둘 다 `exports`를 지원하므로 Node 버전 차이는 원인이 아닐 것입니다. 업그레이드 때 `package-lock.json`이 바뀌었다면 CI 캐시 키도 바뀌므로, 오래된 캐시가 원인일 가능성도 낮습니다.

원인을 가리려면 다음을 순서대로 하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
2. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드해, CI와 같은 오류가 나는지 보십시오.
