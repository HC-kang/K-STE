# 운영 배포 롤백 런북 (payment-api)

## 목적

이 문서는 ArgoCD(배포 도구)로 payment-api 운영 배포를 롤백하는 절차를 설명한다. 롤백 전 DB 마이그레이션(데이터베이스 스키마 변경 작업) 포함 여부를 반드시 확인해야 한다.

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
2. 마이그레이션이 포함됐으면 **롤백하면 안 된다.** 이 경우 DBA(데이터베이스 관리자) 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 2단계로 넘어간다.

확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 확인 위치

## 2. 롤백 실행

1. 아래 명령으로 롤백한다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

2. `<REVISION>`에는 롤백할 배포의 REVISION(배포 버전 식별자) 값을 넣는다.

확인 필요: `<REVISION>`에 넣을 값을 확인하는 방법

## 3. 롤백 후 검증

1. `/healthz`가 200을 반환하는지 확인해야 한다.
2. 결제 테스트 주문 1건이 성공하는지 확인해야 한다.

확인 필요: 테스트 주문을 실행하는 방법
확인 필요: 1번 또는 2번이 실패했을 때 따를 절차

## 4. 이력 기록

1. 롤백 이력을 #deploy 채널에 남겨야 한다.

확인 필요: 이력에 포함할 항목
