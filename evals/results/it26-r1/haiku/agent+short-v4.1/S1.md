로컬 캐시는 서버 4대가 각각 따로 저장하고, Redis 캐시는 서버 4대가 함께 쓰는 한 곳에 저장합니다. 캐시(자주 쓰는 데이터를 빨리 꺼내려고 임시로 저장해 둔 사본)는 저장 위치가 달라도 목적은 같습니다.

현재 구조에서는 서버마다 캐시 내용이 달라서, 가격을 바꾸면 고객이 서버에 따라 다른 가격을 볼 수 있습니다. 모든 서버에서 새 가격이 보이기까지 최대 5분이 걸립니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 캐시 저장 위치 | 서버 4대 각각 | 캐시 서버 1대 |
| 서버마다 보는 값 | 달라질 수 있음 | 모든 서버가 같은 값 |
| 가격 변경이 고객에게 보이기까지 | 최대 5분 | 캐시 삭제 작업을 함께 하면 바로 |
| 조회 속도 | 서버 안에서 바로 꺼냄 | 네트워크를 거쳐 꺼내서 약간 느림 |
| 캐시 서버에 장애가 나면 | 장애 난 서버 한 대만 영향 | 서버 4대 모두 영향을 받을 수 있음 |

Redis를 도입하면 서버 4대가 같은 캐시를 보므로, 서버 사이의 가격 차이가 줄어듭니다. 다만 Redis를 도입하는 것만으로는 가격 변경이 바로 보이지 않습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록 캐시를 지우는 작업을 함께 해야 합니다. 이렇게 해야 가격 변경이 고객에게 바로 보입니다.

확인 필요: 가격 변경 시 Redis 캐시를 지우는 작업이 이번 도입 범위에 포함되는지. 포함되지 않으면 위 메시지의 "함께 해야 합니다" 부분을 실제 계획에 맞게 고쳐야 합니다.
