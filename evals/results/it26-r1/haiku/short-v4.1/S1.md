Redis를 도입하면 서버 4대가 같은 상품 목록을 함께 보므로, 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 고객 화면에 가격 변경이 보이기까지 걸리는 시간은 Redis 도입만으로 줄지 않습니다.

캐시는 자주 보는 데이터를 빠르게 꺼내 쓰려고 임시로 저장해 두는 공간입니다. 현재 방식은 각 서버 안에 캐시를 두는 로컬 캐시이고, 도입 예정인 Redis(여러 서버가 함께 쓰는 별도 저장 서버 프로그램)는 캐시를 한 곳에 모읍니다.

| 항목 | 현재 (서버별 로컬 캐시) | 도입 예정 (Redis 캐시) |
|---|---|---|
| 저장 위치 | 서버 4대 각자의 메모리 | 캐시 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있음 | 4대가 같은 값을 봄 |
| 가격 변경 후 최대 지연 | 5분 | 캐시를 언제 지우는지에 따라 다름 |
| 추가 비용 | 없음 | 서버가 캐시 서버에 요청하는 시간이 더해짐 |

Redis를 써도 캐시 유효 시간을 5분으로 그대로 두면 가격 변경은 최대 5분 늦게 보일 수 있습니다. 가격을 바꿀 때 Redis에 저장된 상품 정보를 바로 지우도록 구성하면, 고객은 변경 직후 새 가격을 보게 됩니다.
