가장 유력한 원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고, CI는 2.0.0을 설치해서 `exports` 필드(패키지가 외부에 공개하는 import 경로 목록)의 제한을 받는 것입니다. 이는 주어진 정황에서 추론한 결론이며, 아직 직접 확인하지 않았습니다.

**사실**
- 빌드는 CI에서만 실패하고, 에러는 `Cannot find module '@company/ui/button'`입니다.
- 2.0.0에 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것입니다.

**추론**
1. 로컬 `node_modules`는 업그레이드 전에 설치했으므로 1.4.0일 가능성이 높습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로 그대로 열립니다.
2. CI는 `package-lock.json`이 바뀌어 캐시 키도 바뀌었을 것이므로 2.0.0을 새로 설치했을 것입니다.
3. `exports`가 있는 패키지는 `exports`에 적힌 경로만 import할 수 있습니다. 2.0.0의 `exports`에 `./button`이 없거나 다른 이름으로 있으면 Node가 이 모듈을 찾지 못합니다.

**가능성이 낮은 원인**
- Node 18과 20의 차이: `exports`는 Node 12 이후부터 지원하므로 이 차이만으로는 설명하기 어렵습니다. 다만 Next.js나 번들러 버전에 따른 해석 차이는 확인하지 않았습니다.
- CI 캐시: 키가 lockfile 해시이므로 lockfile이 바뀌었다면 이전 캐시를 쓰지 않습니다.

**확인 방법**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다. 1.4.0이면 추론 1이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 봅니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 에러가 나면 재현에 성공한 것입니다.

**대응 방향**
추론이 맞다면 CI 실패는 2.0.0 업그레이드의 영향을 드러낸 것이고, 로컬 빌드 성공은 구버전 때문입니다. 수정 방법은 두 가지입니다.
- 앱의 import 경로를 2.0.0의 `exports`에 있는 경로로 바꿉니다.
- `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.

2.0.0이 `./button` 경로를 의도적으로 없앴는지는 모릅니다. 확인 필요: 2.0.0 변경 기록(changelog)에 import 경로 변경이 있는지 봐야 두 방법 중 하나를 고를 수 있습니다.
