원인은 `@company/ui` 2.0.0의 `exports` 필드에 `./button` 경로가 없기 때문으로 보입니다. 로컬은 2.0.0 이전 버전을 쓰고 있어서 같은 오류가 나지 않았을 가능성이 높습니다. 아래 표의 근거는 받은 정보이고, 버전 판단은 추론입니다.

`exports`는 패키지가 외부에 공개하는 import 경로의 목록입니다(`package.json`에 적는 항목). 패키지에 `exports`가 있으면 Node와 번들러는 목록에 적힌 경로만 허용합니다. 그래서 파일이 실제로 있어도 목록에 없는 `@company/ui/button`은 `Cannot find module` 오류가 납니다. 1.4.0에는 `exports`가 없었으므로 같은 import가 파일 경로로 풀렸습니다.

| 항목 | CI | 로컬 |
|---|---|---|
| `@company/ui` 버전 | 2.0.0으로 보입니다 | 1.4.0으로 보입니다 |
| 근거 | 캐시 키가 `package-lock.json` 해시입니다. 업그레이드로 lock 파일이 바뀌었다면 캐시를 새로 만들어 2.0.0을 설치합니다. | `node_modules`를 3일 전보다 먼저 설치했습니다. |
| Node | 18 | 20 |

Node 버전 차이는 원인일 가능성이 낮습니다. Node 18과 20은 둘 다 `exports`를 지원합니다.

다음 순서로 원인을 확인하십시오.

1. CI 로그에서 설치된 `@company/ui` 버전이 2.0.0인지 보십시오.
2. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
3. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.

로컬에서 `npm ci`로 `node_modules`를 다시 설치한 뒤 빌드하면 CI와 같은 오류가 나는지 볼 수 있습니다. 같은 오류가 나면 원인이 확정됩니다.

`exports`에 `./button`이 없다면 해결 방법은 두 가지입니다. 앱의 import를 2.0.0이 공개한 경로로 바꾸거나, `@company/ui` 담당자에게 `./button` 경로 추가를 요청하십시오. 어느 쪽을 택할지는 2.0.0이 `./button`을 의도적으로 뺐는지에 달려 있으므로, 담당자에게 먼저 물어보십시오.
