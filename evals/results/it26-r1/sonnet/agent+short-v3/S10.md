원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고 CI는 2.0.0을 설치하기 때문으로 보입니다. 아래 내용은 모두 추론이며, 직접 확인한 것은 없습니다.

2.0.0에서 추가된 `exports` 필드(패키지가 외부에 공개하는 import 경로를 제한하는 `package.json` 항목)가 이 에러와 관련 있어 보입니다. `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없으면 `@company/ui/button`을 찾지 못하고 `Cannot find module` 에러가 납니다. 1.4.0에는 `exports`가 없어서 이 경로가 열려 있었습니다.

로컬 빌드가 성공하는 이유는 `node_modules`를 3일 전보다 먼저 설치했기 때문으로 보입니다. 이 경우 로컬에는 1.4.0이 남아 있습니다. CI는 `package-lock.json`이 2.0.0으로 바뀌면서 캐시 키도 바뀌었을 것이므로 2.0.0을 새로 설치합니다.

Node 버전 차이는 주원인으로 보이지 않습니다. Node 18과 20은 둘 다 `exports` 필드를 지원합니다.

원인을 확정하려면 다음 순서로 확인하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 봅니다.
2. 2.0.0의 `package.json`을 열어 `exports`에 `./button`이 있는지 봅니다.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드해서, CI와 같은 에러가 나는지 봅니다.

2.0.0의 `exports`에 `./button`이 없다면 두 가지 중 하나로 고쳐야 합니다. 앱의 import 경로를 2.0.0이 공개한 경로로 바꾸거나, `@company/ui`의 `exports`에 `./button`을 추가합니다. 어느 쪽이 맞는지는 2.0.0에서 `button`을 어떤 경로로 공개하려 했는지에 달려 있습니다.

확인 필요: 2.0.0의 `exports`에 `./button`이 있는지, `button`의 공개 경로가 바뀌었는지.
