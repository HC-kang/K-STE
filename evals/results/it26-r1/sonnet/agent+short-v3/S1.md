로컬 캐시는 서버마다 따로 갖는 임시 저장소이고, Redis 캐시는 서버 4대가 함께 쓰는 임시 저장소입니다. Redis를 도입하면 서버마다 상품 목록이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 매번 원본에서 가져오지 않도록 임시로 저장해 두는 것입니다. 지금 API 서버(고객 요청을 받아 응답하는 서버) 4대는 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 이 방식이 로컬 캐시입니다. Redis는 캐시 전용 서버입니다. 이번에 Redis 서버 1대를 도입하고, API 서버 4대가 이 서버 1대를 같이 씁니다.

| 항목 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대가 각자 자기 메모리에 저장합니다. | Redis 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 달라질 수 있습니다. | 서버 4대가 같은 내용을 봅니다. |
| 가격 변경 시 | 고객에게 최대 5분 늦게 반영됩니다. | 서버 간 차이가 없어집니다. |

현재 문제는 서버마다 캐시를 따로 갖는 데서 생깁니다. 가격을 바꿔도 서버 4대의 캐시가 각자 만료될 때까지 이전 가격이 남아서, 고객에게 최대 5분 늦게 반영됩니다. Redis를 쓰면 캐시가 한 곳에 있으므로 서버에 따라 가격이 다르게 보이는 일이 없어집니다.

확인 필요: 가격 변경 지연이 5분보다 얼마나 줄어드는지는 가격을 바꿀 때 Redis의 상품 목록을 바로 갱신하는지에 달려 있습니다. 이 방식을 이번 도입 범위에 넣는지 아직 모릅니다.
