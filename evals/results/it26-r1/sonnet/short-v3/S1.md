가장 큰 차이는 캐시(자주 쓰는 데이터를 잠시 저장해 두고 빠르게 꺼내 쓰는 방식)를 서버마다 따로 갖는지, 서버 4대가 하나를 같이 쓰는지입니다. Redis를 도입하면 서버마다 상품 목록이 달라지는 문제가 없어집니다.

현재는 로컬 캐시입니다. API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 서버마다 저장한 시점이 달라서 캐시 내용도 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 서버 4대가 같이 쓰는 캐시 서버 1대입니다. 4대가 같은 캐시를 보기 때문에, 고객이 어느 서버에 연결돼도 같은 상품 목록을 봅니다.

가격 반영이 5분보다 얼마나 빨라지는지는 아직 정해지지 않았습니다. 캐시를 보관하는 시간과, 가격을 바꿀 때 캐시를 지우는 방식에 따라 달라집니다. 확인 필요: Redis 도입 후 캐시 보관 시간을 얼마로 하는지, 가격을 바꿀 때 캐시를 바로 지우는지.

단점도 있습니다. Redis는 서버 밖에 있어서, 서버 자기 메모리에서 꺼내는 것보다 조금 느릴 수 있습니다. 또 Redis 서버가 1대라서, 이 서버에 문제가 생기면 API 서버 4대 모두 영향을 받을 수 있습니다. 확인 필요: Redis 서버에 문제가 생기면 API 서버가 어떻게 동작하는지.
