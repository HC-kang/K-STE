로컬 캐시는 각 API 서버가 자기 메모리에 상품 목록을 따로 보관하는 방식이고, Redis는 서버 4대가 함께 쓰는 캐시 서버 1대에 상품 목록을 보관하는 방식입니다. 캐시는 상품 정보의 원본이 있는 데이터베이스(DB)에 매번 가서 가져오지 않도록, 자주 쓰는 데이터를 임시로 저장해 두는 곳입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 서버의 메모리입니다. | 캐시 전용 서버 1대입니다. |
| 서버 4대가 보는 상품 목록 | 서버마다 달라질 수 있습니다. | 항상 같습니다. |
| 데이터를 꺼내는 속도 | 서버 안에서 바로 꺼냅니다. | 네트워크를 거쳐 꺼내므로 로컬 캐시보다 조금 느립니다. |

Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되므로, 서버마다 가격이 다르게 보이는 문제는 사라집니다.

다만 가격 반영이 최대 5분 늦는 문제는 Redis를 도입한다고 자동으로 해결되지 않습니다. 가격을 바꾼 뒤 Redis에 저장된 상품 목록을 언제 지우거나 새로 갱신하는지에 따라 지연 시간이 정해지기 때문입니다.

확인 필요: 이번 도입 설계에 가격을 바꿀 때 Redis의 상품 목록을 바로 지우는 방식이 포함되는지 알려 주세요.

Redis에는 단점도 있습니다. 로컬 캐시보다 꺼내는 속도가 조금 느리고, Redis 서버에 장애가 나면 4대 서버 모두 캐시를 사용할 수 없게 됩니다.

정리하면 Redis 도입으로 얻는 것은 서버 간 상품 목록의 일치입니다. 가격 반영 시간을 줄이려면 별도로 정해야 할 수 있습니다.
