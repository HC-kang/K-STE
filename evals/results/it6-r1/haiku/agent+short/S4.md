# payment-api 운영 배포 롤백 런북

이 문서는 payment-api의 운영 배포를 ArgoCD로 이전 리비전(REVISION)에 되돌리는 절차를 정리한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다. 마이그레이션이 포함됐으면 롤백하지 않고 DBA 박지은에게 연락한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 정상 동작을 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 사전 확인

1. 롤백할 대상 리비전 번호를 확인한다. 확인 필요: 리비전 번호를 찾는 방법과 롤백 대상을 고르는 기준.
2. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법.
3. **경고:** 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다. 확인 필요: 박지은의 연락처와 연락 수단.

## 롤백 절차

4. 마이그레이션이 포함되지 않았음을 확인한 경우에만 다음 단계를 진행한다.
5. 다음 명령으로 payment-api를 롤백한다. `<REVISION>`에는 1번에서 확인한 리비전 번호를 넣는다.

```
argocd app rollback payment-api <REVISION>
```

## 결과 확인

6. 롤백이 끝나면 `/healthz`가 200을 반환하는지 확인한다. 확인 필요: `/healthz`를 호출하는 주소와 확인 방법.
7. 롤백이 끝나면 결제 테스트 주문을 1건 진행하고 성공하는지 확인한다. 확인 필요: 테스트 주문을 실행하는 방법과 테스트 결제 환경.
8. 6번이나 7번이 실패하면 조치 방법을 정한다. 확인 필요: 실패 시 조치 절차와 담당자.

## 기록

9. #deploy 채널에 롤백 이력을 남긴다. 확인 필요: 이력에 넣을 항목(예: 롤백 리비전, 시각, 담당자).
