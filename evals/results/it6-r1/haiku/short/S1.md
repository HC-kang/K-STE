로컬 캐시는 각 서버 안에 자주 쓰는 데이터를 복사해 두는 임시 저장 공간이고, Redis 캐시는 서버 바깥에 있는 공용 캐시 서버 한 대에 같은 역할을 맡기는 방식입니다. (캐시는 매번 원본을 찾지 않도록 데이터를 가까운 곳에 복사해 두는 저장 공간입니다.)

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버 내부 | 서버 바깥의 공용 캐시 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있음 | 4대 서버가 같은 데이터를 봄 |
| 가격 변경 반영 | 최대 5분 늦게 반영 | 캐시 삭제 작업을 함께 하면 바로 반영 가능 (추론) |

Redis를 도입하면 4대 서버가 같은 상품 목록을 보므로, 서버마다 가격이 다르게 보이는 문제가 없어집니다. 다만 가격 반영 속도는 Redis 도입만으로 정해지지 않습니다. 가격을 바꿀 때 캐시를 지우는 작업이 함께 들어가야 고객에게 바로 반영됩니다. 확인 필요: 이번 도입 범위에 캐시 삭제 작업이 포함되는지 개발팀에 확인해야 합니다.

Redis 캐시 서버가 한 대라서, 이 서버에 장애가 나면 4대 서버 모두 캐시를 쓰지 못하는 영향이 생길 수 있습니다. 이 부분은 장애 대응 방식을 개발팀과 함께 정해야 합니다.
