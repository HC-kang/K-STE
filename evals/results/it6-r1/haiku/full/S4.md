# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 되돌리는 절차를 정리한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함되었는지 확인해야 하며, 포함되었으면 롤백하지 않고 DBA에게 연락한다.

## 1. 롤백 전 확인

1. 롤백 대상 배포에 DB 마이그레이션이 포함되었는지 확인한다.
2. 마이그레이션이 포함된 경우 **롤백하지 않는다.** DBA 박지은에게 연락한다.
3. 마이그레이션이 포함되지 않은 경우에만 다음 단계로 진행한다.

## 2. 롤백 실행

4. 롤백할 리비전 번호를 `<REVISION>`에 넣어 다음 명령을 실행한다.

   `argocd app rollback payment-api <REVISION>`

## 3. 롤백 후 확인

5. `/healthz`가 200을 반환하는지 확인한다.
6. 결제 테스트 주문 1건이 성공하는지 확인한다.

## 4. 이력 기록

7. 롤백 이력을 #deploy 채널에 남긴다.

## 미정 사항

- 정보 없음: 배포에 마이그레이션이 포함되었는지 확인하는 방법과 기준.
- 정보 없음: `/healthz`를 확인할 대상 주소와 결제 테스트 주문을 실행하는 방법.
- 정보 없음: #deploy 채널에 남길 이력의 형식과 기록 항목.
