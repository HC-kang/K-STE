원인은 로컬이 `@company/ui` 2.0.0이 아니라 1.4.0을 계속 쓰고 있는 것으로 보입니다. CI는 2.0.0을 새로 설치하고, 2.0.0의 `exports` 필드가 `@company/ui/button` 경로를 막는 것으로 추정합니다.

## 근거

사실로 확인된 내용은 다음과 같습니다.

- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했습니다.
- 2.0.0부터 패키지에 `exports` 필드가 있습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

이 사실에서 다음과 같이 추론합니다.

- 업그레이드로 `package-lock.json`이 바뀌었으므로 CI 캐시 키도 바뀝니다. CI는 캐시 없이 2.0.0을 새로 설치합니다.
- 로컬은 재설치하지 않았으므로 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button` 같은 하위 경로를 파일 경로로 바로 불러올 수 있습니다.
- `exports`가 있는 패키지는 `exports`에 선언한 경로만 불러올 수 있습니다. `./button`이 선언돼 있지 않으면 파일이 존재해도 `Cannot find module`이 발생합니다.

Node 버전 차이는 원인일 가능성이 낮습니다. Node 18과 20 모두 `exports`를 지원하기 때문입니다.

## 확인 필요

아래 항목은 아직 확인하지 않았습니다.

- 로컬 `node_modules/@company/ui/package.json`의 `version`이 1.4.0인지 확인해야 합니다.
- 2.0.0의 `exports`에 `./button`이 있는지, 있다면 어떤 이름으로 있는지 확인해야 합니다.
- Node 버전이 영향을 주는지는 위 두 항목을 확인한 뒤에 판단할 수 있습니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 오류가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에서 `./button` 항목을 확인합니다.

## 해결 방법

`exports`에 `./button`이 없는 경우, 두 가지 방법이 있습니다.

- 앱 코드의 import 경로를 2.0.0이 공개한 경로로 바꿉니다. 예를 들어 루트 import인 `@company/ui`로 바꿀 수 있습니다.
- `@company/ui` 담당 팀에 `./button` 경로를 `exports`에 추가해 달라고 요청합니다.

`exports`에 `./button`이 이미 있는데도 실패하면, 2.0.0의 `types` 또는 `import` 조건 설정을 추가로 확인해야 합니다.

## PM 참고

- 현재 main 브랜치는 CI에서 계속 실패합니다.
- 로컬 빌드 성공은 2.0.0 호환성을 보장하지 않습니다.
- 담당 팀의 `exports` 수정을 기다리면 일정이 외부에 의존하게 됩니다. 앱 코드의 import 경로를 바꾸는 방법은 외부 의존 없이 바로 할 수 있습니다.
