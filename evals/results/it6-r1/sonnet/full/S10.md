원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고 CI만 2.0.0을 설치하기 때문일 가능성이 높습니다.

로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것입니다. 그 뒤에 재설치하지 않았다면 로컬에는 1.4.0이 남아 있고, 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`을 파일 경로로 찾습니다.

2.0.0은 `exports` 필드를 추가했습니다. `exports`는 패키지가 외부에 공개하는 import 경로를 선언하는 목록입니다. 이 필드가 있으면 목록에 없는 경로는 파일이 실제로 있어도 가져올 수 없습니다. `@company/ui/button`이 2.0.0의 `exports`에 없다면 CI는 이 모듈을 찾지 못합니다. 아직 2.0.0의 `exports` 내용은 확인하지 않았습니다.

나머지 두 가지는 원인일 가능성이 낮습니다.

- Node 버전: Node 18도 `exports`를 지원하므로 18과 20의 차이가 주원인일 가능성은 낮습니다.
- CI 캐시: 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀌므로 오래된 캐시가 원인일 가능성은 낮습니다.

원인을 확정하려면 다음 순서로 확인하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오.
2. 로컬에서 `rm -rf node_modules && npm ci`로 재설치한 뒤 빌드하십시오. CI와 같은 에러가 나면 원인이 확정됩니다.
3. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 확인하십시오. 없으면 import 경로를 2.0.0이 공개한 경로로 바꾸거나, 패키지에 해당 경로를 추가해야 합니다.
