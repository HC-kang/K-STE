CI 빌드는 `@company/ui` 2.0.0의 `exports` 필드 때문에 실패하는 것으로 보입니다. 로컬 빌드는 1.4.0 상태의 `node_modules`로 돌기 때문에 성공하는 것으로 보입니다. 두 가지 모두 추론입니다.

## 확인된 사실

- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0부터 패키지에 `exports` 필드가 있습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.
- CI 에러는 `Error: Cannot find module '@company/ui/button'`입니다.

## 추론

`exports` 필드는 패키지가 바깥에 공개하는 import 경로의 목록입니다. 이 필드가 있으면 Node는 목록에 없는 경로를 불러오지 못합니다. 1.4.0에는 `exports`가 없었으므로 `@company/ui/button`처럼 파일 경로로 직접 import해도 됐습니다. 2.0.0의 `exports`에 `./button`이 없으면 같은 에러가 납니다.

로컬과 CI의 결과가 갈리는 이유는 설치된 버전이 다르기 때문으로 보입니다.

- 로컬: `node_modules`를 3일 전보다 먼저 설치했으므로 1.4.0이 남아 있을 가능성이 큽니다.
- CI: 버전을 올릴 때 `package-lock.json`이 바뀌었다면 캐시 키도 바뀝니다. 그러면 CI는 캐시 없이 새로 설치하고 2.0.0을 받습니다.

Node 18과 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 원인일 가능성이 낮습니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오. 1.4.0이면 로컬 빌드는 새 버전을 검증하지 못한 것입니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button` 항목이 있는지 확인하십시오. 2.0.0을 설치한 뒤에 확인해야 합니다.
3. `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 로컬에서 빌드하십시오. CI와 같은 조건이므로 같은 에러가 나는지 볼 수 있습니다.

2번에서 `./button`이 없으면 방법은 둘입니다. 2.0.0이 공개하는 경로로 import를 고치거나, `@company/ui` 담당자에게 `./button` export 추가를 요청해야 합니다.
