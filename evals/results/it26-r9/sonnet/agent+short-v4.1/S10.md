로컬 빌드가 성공하는 이유는 로컬 `node_modules`에 아직 `@company/ui` 1.4.0이 있기 때문으로 보입니다. CI는 2.0.0을 새로 설치해서 실패하는 것으로 보입니다. 이 설명은 추론이고, 아래 검증 단계로 확인해야 합니다.

## 원인 추정

`exports` 필드는 패키지가 외부에 공개하는 import 경로를 `package.json`에 직접 적는 설정입니다. 1.4.0에는 이 필드가 없어서 `@company/ui/button`처럼 패키지 안의 파일 경로를 직접 import할 수 있었습니다. 2.0.0에는 이 필드가 있습니다. 그래서 `exports`에 `./button`이 없으면 Node는 그 경로를 찾지 못하고 `Cannot find module '@company/ui/button'` 오류를 냅니다.

환경별 차이는 다음과 같습니다.

| 환경 | `@company/ui` 버전 | 이유 |
|---|---|---|
| 로컬 | 1.4.0으로 보입니다 | `node_modules`를 3일 전보다 먼저 설치했습니다. |
| CI | 2.0.0으로 보입니다 | 버전을 올리면서 `package-lock.json`이 바뀌었고, 캐시 키가 이 파일의 해시라서 새로 설치했습니다. |

Node 18과 Node 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 주원인이 아니라고 봅니다. 다만 이 부분도 아직 검증하지 않은 추론입니다.

## 검증 순서

1. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. CI와 같은 오류가 나면 원인은 버전 차이입니다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button`이 있는지 보십시오. 없으면 오류의 직접 원인입니다.
3. 2번에서 `./button`이 있는데도 CI가 실패하면, CI의 Node 버전을 20으로 올려서 다시 실행하십시오.

## 해결 방향

1번과 2번에서 추정이 맞으면 해결 방법은 두 가지입니다.

- `@company/ui` 담당 팀에 2.0.0의 `exports`에 `./button`을 추가해 달라고 요청합니다.
- 앱의 import 경로를 2.0.0의 `exports`가 공개하는 경로로 바꿉니다.

확인 필요: 2.0.0이 `./button`을 공개하는지, 다른 경로로 바뀌었는지는 제가 가진 정보에 없습니다. 2.0.0의 릴리스 노트나 `exports` 내용으로 확인해야 합니다.
