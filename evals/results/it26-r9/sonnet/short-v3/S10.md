가장 유력한 원인은 로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있어서, 로컬 빌드가 2.0.0을 한 번도 사용하지 않았다는 점입니다. 이 내용은 추론이며, 아래 검증으로 확정할 수 있습니다.

## 사실

- CI에서만 `Error: Cannot find module '@company/ui/button'`이 발생합니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0 패키지에는 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

## 추론

`exports` 필드가 있는 패키지는 `exports`에 적힌 경로로만 내부 파일을 가져올 수 있습니다. 2.0.0의 `exports`에 `./button`이 없거나 다른 경로로 적혀 있으면 `@company/ui/button`을 찾지 못합니다.

1.4.0에는 `exports`가 없었으므로, 같은 import가 파일 경로로 바로 풀렸을 것입니다. 로컬에 1.4.0이 남아 있다면 로컬 빌드는 성공합니다. 2.0.0을 설치하는 CI는 실패합니다.

다른 후보는 가능성이 낮습니다.

- Node 버전: Node 18과 20은 모두 `exports`를 지원하므로, 두 버전의 차이가 원인일 가능성은 낮습니다.
- CI 캐시: 업그레이드 때 `package-lock.json`이 바뀌었다면 캐시 키도 바뀌어서 CI가 2.0.0을 새로 설치했을 것입니다. 이 경우 캐시는 원인이 아닙니다.

## 미확인

- 로컬에 실제로 설치된 `@company/ui` 버전.
- 2.0.0 `exports`에 `./button`이 있는지, 있다면 어떤 경로인지.
- 업그레이드 커밋에 `package-lock.json` 변경이 포함됐는지.

## 검증 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 본다.
2. `node_modules/@company/ui/package.json`에서 `exports`의 키 목록을 본다.
3. 로컬에서 `rm -rf node_modules && npm ci && npx next build`를 실행한다. CI와 같은 에러가 나면 원인이 확정된다.
4. 원인이 확정되면 import 경로를 `exports`에 있는 경로로 바꾼다. `./button`이 의도적으로 빠진 것이 아니라면, `@company/ui` 쪽에 `./button` export 추가를 요청한다.
