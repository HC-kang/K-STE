가장 유력한 원인은 2.0.0에 추가된 `exports` 필드가 `@company/ui/button` 같은 하위 경로를 막은 것입니다. 다만 패키지 내용과 앱의 import 목록은 확인하지 않았으므로 이 결론은 추론입니다.

### 원인 분석

1.4.0에는 `exports` 필드가 없었습니다. 그래서 `@company/ui/button`처럼 파일 경로를 직접 가리키는 import가 그대로 동작했습니다. 2.0.0은 `exports` 필드를 추가했습니다. 이 필드가 있으면 패키지는 여기에 명시된 경로만 외부에 공개합니다. `./button` 경로가 `exports`에 없거나 다른 경로로 바뀌었다면 import가 실패합니다.

**주의:** 로컬 빌드가 성공한 것은 2.0.0이 정상이라는 근거가 되지 않습니다. 로컬 `node_modules`는 3일 전에 설치되어 1.4.0이 그대로 남아 있을 가능성이 큽니다. 로컬 빌드는 1.4.0으로 실행된 것입니다.

CI에서만 실패하는 이유는 캐시 키 때문으로 보입니다. 캐시 키가 `package-lock.json`의 해시이므로, lock 파일이 바뀐 커밋에서는 캐시가 맞지 않아 새로 설치됩니다. 이때 CI는 2.0.0을 설치합니다. 즉 CI가 2.0.0을 처음으로 제대로 설치하는 환경입니다. 이 부분은 캐시 설정을 확인해야 합니다.

Node 버전 차이는 직접 원인일 가능성이 낮습니다. Node 18도 `exports` 필드를 지원합니다. 다만 두 가지는 확인이 필요합니다. 2.0.0의 `engines` 필드가 Node 20을 요구하는지 확인해야 합니다. 또한 Node 18은 2025년 4월에 지원이 끝났으므로 장기적으로 올려야 합니다.

에러 메시지 형식도 단서가 됩니다. `Cannot find module`은 Node의 모듈 해석 에러 형식입니다. Next.js 빌드 중 웹팩이 낸 에러라면 보통 `Module not found: Can't resolve`로 표시됩니다. 따라서 실패 지점이 `next.config.js`, 빌드 전 스크립트, 테스트 도구 같은 Node 실행 단계일 수 있습니다. 확인 필요: CI 전체 로그에서 실패한 단계와 스택 트레이스를 확인해야 합니다.

### 가설별 확인 방법

| 가설 | 근거 | 확인 방법 |
|---|---|---|
| 2.0.0 `exports`에 `./button`이 없음 | 2.0.0에서 `exports`가 추가되었고 에러 시점과 맞음 | CI에서 `node_modules/@company/ui/package.json`의 `exports` 확인 |
| 로컬 `node_modules`가 1.4.0 그대로임 | 3일 전 설치 이후 갱신 여부가 불명확함 | 로컬에서 `npm ls @company/ui` 실행 |
| CI가 2.0.0을 설치함 | 캐시 키가 lock 해시임 | CI 로그에 설치된 버전 출력 |
| Node 18 차이가 원인임 | CI만 Node 18을 사용함 | 같은 lock으로 Node 18과 Node 20에서 각각 재현 |

### 권장 검증 순서

먼저 CI에 `npm ls @company/ui`와 설치된 패키지의 `exports` 확인 단계를 추가합니다. 그다음 로컬에서 Node 18로 `rm -rf node_modules && npm ci`를 실행해 실패가 재현되는지 확인합니다. 재현되면 앱의 import 경로와 2.0.0의 `exports` 목록을 대조합니다.

### 해결 방향

단기적으로는 `@company/ui`를 1.4.0으로 되돌려 CI를 먼저 살릴 수 있습니다. 근본적으로는 앱의 import 경로를 2.0.0이 공개한 경로로 바꾸는 방법이 있습니다. 2.0.0을 유지해야 한다면 패키지 관리자에게 필요한 경로를 `exports`에 추가해 달라고 요청하는 방법도 있습니다. 2.0.0이 major 버전이므로 변경 내역(changelog)에서 breaking change 항목도 함께 확인하는 것이 좋습니다.

### 미확인 사항

이번 정리에서 확인하지 않은 항목은 다음과 같습니다. 2.0.0 패키지의 실제 `exports` 목록, 앱의 `@company/ui` import 목록, CI 캐시 설정, 2.0.0의 `engines` 값, CI 전체 로그입니다. 위 가설은 모두 이 항목들을 확인한 뒤에 확정할 수 있습니다.
