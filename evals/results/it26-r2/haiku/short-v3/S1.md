Redis를 도입하면 서버 4대가 같은 캐시를 함께 보므로, 가격을 바꿨을 때 모든 서버가 같은 가격을 보여줄 수 있습니다. 다만 5분 지연이 완전히 사라지는지는 캐시를 언제 지우고 갱신하는지에 따라 달라집니다.

캐시는 자주 찾는 데이터를 미리 저장해 두는 임시 공간입니다. 두 방식의 차이는 다음과 같습니다.

| 구분 | 로컬 캐시 (각 서버 메모리에 저장) | Redis 캐시 (별도 공용 캐시 서버에 저장) |
|---|---|---|
| 저장 위치 | 서버마다 따로 저장합니다. | 캐시 서버 1대에 저장하고, 4대 서버가 함께 씁니다. |
| 서버 간 내용 | 서버마다 달라질 수 있습니다. | 4대 서버가 같은 내용을 봅니다. |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영됩니다. | 가격을 바꿀 때 캐시를 지우거나 새 값으로 바꾸면 4대에 같은 시점에 반영됩니다. |
| 조회 속도 | 자기 메모리에서 바로 꺼내므로 가장 빠릅니다. | 별도 서버를 거쳐 가져오므로 로컬 캐시보다 조금 느립니다. |
| 새로 생기는 부담 | 없습니다. | Redis 서버를 따로 운영해야 하고, 이 서버에 장애가 나면 대비책이 필요합니다. |

Redis를 도입해도 캐시 유효 시간을 5분으로 그대로 두면 최대 5분 지연은 남습니다. 가격이 바뀔 때 Redis의 캐시를 지우는 작업을 함께 넣어야 고객에게 바로 반영됩니다. 이 작업은 개발 설계에서 정해야 합니다.

정리하면, Redis 도입으로 서버마다 가격이 다르게 보이는 문제를 없앨 수 있고, 서버를 늘려도 같은 기준을 유지하기 쉬워집니다. 대신 Redis 서버를 운영하는 부담이 생깁니다.
