CI에서만 빌드가 실패하는 원인은 `@company/ui` 2.0.0에 새로 추가된 `exports` 필드일 가능성이 큽니다. 아직 실행해서 확인하지 않은 추론입니다.

### 확인된 사실

- 3일 전 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가되었습니다.
- 빌드 에러는 `Cannot find module '@company/ui/button'`입니다.
- CI는 Node 18을, 로컬은 Node 20을 사용합니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치되었습니다.

### 추론

- 로컬 `node_modules`에는 아직 1.4.0이 남아 있을 가능성이 큽니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button` 경로가 파일 경로대로 해석됩니다.
- CI는 `package-lock.json`에 따라 2.0.0을 새로 설치합니다. 2.0.0의 `exports` 필드가 `./button` 같은 하위 경로를 공개하지 않으면 같은 import가 실패합니다.
- Node 버전 차이가 이 에러의 직접 원인일 가능성은 낮아 보입니다. `exports` 필드는 Node 18과 20에서 모두 지원됩니다.

### 미확인 사항

- 2.0.0의 `package.json`에 `./button` 경로가 `exports`에 정의되어 있는지 확인 필요합니다.
- CI가 실제로 설치한 `@company/ui` 버전이 2.0.0인지 확인 필요합니다.
- 커밋된 `package-lock.json`에 2.0.0이 반영되어 있는지 확인 필요합니다.
- 로컬에서 `npm ls @company/ui`를 실행하면 현재 설치된 버전을 확인할 수 있습니다.

원인이 `exports` 필드라면 import 경로를 2.0.0이 공개한 경로로 바꾸거나, 패키지 쪽에서 `./button` 경로를 `exports`에 추가해야 합니다.
