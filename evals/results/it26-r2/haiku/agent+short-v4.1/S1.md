로컬 캐시는 서버 한 대가 자기 메모리(서버가 작업할 때 데이터를 잠시 올려 두는 공간)에 데이터 사본을 보관하는 방식이고, Redis 캐시는 여러 서버가 함께 쓰는 별도의 캐시 서버 한 대에 사본을 보관하는 방식입니다. 캐시는 자주 읽는 데이터의 사본을 잠시 보관해 두고 매번 원본을 읽지 않도록 하는 장치입니다.

지금은 API 서버 4대가 각자 메모리에 상품 목록을 5분 동안 캐시합니다. 그래서 서버마다 보관한 내용이 달라질 수 있고, 가격을 바꾸면 고객 화면에는 최대 5분 늦게 바뀐 가격이 보입니다.

Redis를 도입하면 서버 4대가 같은 캐시 사본을 읽으므로 서버마다 다른 가격이 보이는 문제는 없어집니다. 다만 캐시 유지 시간이 5분으로 남아 있으면 가격 변경은 여전히 최대 5분 늦게 보일 수 있습니다. 지연을 줄이려면 가격을 바꿀 때 Redis의 캐시를 지우는 작업을 함께 넣는 것을 권장합니다.

팀에서 정할 사항은 Redis의 캐시 유지 시간을 얼마로 할지와 가격 변경 때 캐시를 지우는 작업을 넣을지 여부입니다.
