Redis를 도입하면 서버 4대가 같은 캐시를 함께 쓰게 되어, 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 미리 담아 두는 임시 저장소입니다. 지금은 각 API 서버가 자기 메모리(작업 중인 데이터를 잠시 올려 두는 공간)에 상품 목록을 5분 동안 따로 보관하는 로컬 캐시를 씁니다. 그래서 서버마다 캐시 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 캐시 데이터를 별도의 캐시 서버 1대에 보관하는 방식입니다. 서버 4대가 이 한 곳을 함께 보므로, 같은 시점에 같은 상품 정보를 보게 됩니다. 다만 가격 변경이 고객에게 바로 반영되는지는 Redis 캐시를 언제 지우는지에 따라 달라집니다.

Redis는 서버를 하나 더 운영하는 일이기도 합니다. Redis 서버가 멈추면 4대 서버 모두 캐시를 쓸 수 없게 되므로, 이 서버의 안정성도 함께 살펴볼 부분입니다.

확인 필요: 가격 변경이 고객에게 바로 반영되는지. Redis 캐시를 가격 변경 때 바로 지우는 방식인지, 5분 뒤에 지우는 방식인지 정해야 PM에게 답할 수 있습니다.
