가장 큰 차이는 캐시를 서버마다 따로 갖느냐, 서버 4대가 하나를 같이 쓰느냐입니다. 캐시는 자주 찾는 데이터를 빨리 꺼내려고 임시로 저장해 둔 사본입니다.

현재의 로컬 캐시는 API 서버 4대가 각자 자기 메모리에 상품 목록 사본을 5분 동안 보관하는 방식입니다. 서버마다 사본을 만든 시점이 달라서 서버끼리 내용이 다를 수 있습니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 별도의 캐시 서버 1대에 사본을 하나만 두고, API 서버 4대가 그 사본을 같이 읽는 방식입니다. 서버 간 내용 차이가 없어지므로, 고객은 어느 서버에 연결되어도 같은 상품 목록을 봅니다. 가격을 바꿀 때도 사본 하나만 고치면 됩니다.

다만 가격 반영 지연이 줄어드는지는 구현 방식에 달려 있습니다. 가격을 바꿀 때 Redis의 사본을 바로 갱신하도록 만들면 지연을 줄일 수 있습니다. 5분 만료 방식을 그대로 쓰면 지연은 최대 5분으로 남을 수 있습니다.

확인 필요: 이번 Redis 도입에 가격 변경 시 Redis 사본을 바로 갱신하는 기능이 포함되는지 개발팀에 확인해야 합니다.

Redis 서버가 1대이므로, 이 서버가 멈추면 API 서버 4대 모두 Redis 캐시를 쓰지 못합니다.
