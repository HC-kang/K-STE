로컬 캐시는 서버마다 따로 갖는 저장 공간이고, Redis 캐시는 서버 4대가 함께 쓰는 저장 공간입니다. 이번 도입으로 서버마다 상품 목록이 다르게 보이는 문제가 없어집니다.

캐시(자주 쓰는 데이터를 가까운 곳에 미리 저장해 두는 방식)는 상품 목록을 매번 데이터베이스에서 읽지 않게 해 줍니다. 지금 API 서버 4대는 각자 자기 메모리에 상품 목록을 5분 동안 캐시합니다. 이것이 로컬 캐시입니다. 서버마다 캐시를 저장한 시점이 달라서 서버마다 캐시 내용이 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis(여러 서버가 네트워크로 함께 읽고 쓰는 캐시 전용 서버)는 1대를 도입할 예정입니다. API 서버 4대가 이 Redis 1대의 캐시를 같이 읽습니다. 그래서 서버마다 캐시 내용이 달라지는 일이 없어집니다.

가격 변경이 고객에게 반영되는 시간이 5분보다 줄어드는지는 가격을 바꿀 때 Redis의 캐시를 어떻게 갱신하느냐에 달려 있는 것으로 보입니다. 이 부분은 개발팀의 설계를 들어야 알 수 있습니다.
