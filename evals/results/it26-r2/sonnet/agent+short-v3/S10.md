CI는 `@company/ui` 2.0.0을 설치하고 로컬은 1.4.0을 쓰고 있을 가능성이 가장 높고, 이것이 원인으로 보입니다. 아직 확인한 사실은 아닙니다.

근거는 다음과 같습니다.
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했습니다. 그래서 로컬 빌드는 2.0.0이 아니라 1.4.0으로 돌고 있을 수 있습니다.
- 2.0.0부터 패키지에 `exports` 필드(패키지가 외부에 공개할 파일 경로를 정하는 `package.json` 항목)가 있습니다. `exports`에 `./button`이 없으면 `@company/ui/button`으로 가져오는 코드는 `Cannot find module` 오류를 냅니다. 2.0.0의 `exports` 내용은 아직 보지 않았습니다.
- Node 18과 Node 20은 둘 다 `exports` 필드를 지원한다고 알고 있습니다. 그래서 Node 버전 차이는 원인일 가능성이 낮아 보입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드 때 lockfile이 바뀌었다면 캐시 키도 바뀌므로, 오래된 캐시가 원인일 가능성은 낮아 보입니다. 업그레이드 커밋에 `package-lock.json` 변경이 들어 있는지는 확인 필요입니다.

원인은 다음 순서로 확인하십시오.
1. 로컬에서 `node_modules/@company/ui/package.json`의 `version`이 1.4.0인지 봅니다.
2. 로컬에서 `rm -rf node_modules && npm ci`로 lockfile 그대로 다시 설치한 뒤 빌드합니다. 같은 오류가 나면 원인이 확정됩니다.
3. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 봅니다.

3번에서 `./button`이 없으면 선택지는 두 가지입니다. 하나는 2.0.0의 `exports`가 공개한 경로로 import를 바꾸는 것입니다. 다른 하나는 `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청하는 것입니다. 어느 쪽이 맞는지는 2.0.0이 `./button`을 의도적으로 뺐는지에 달려 있습니다.

확인 필요: `@company/ui` 2.0.0이 `./button`을 의도적으로 공개하지 않은 것인지, 실수로 빠뜨린 것인지.
