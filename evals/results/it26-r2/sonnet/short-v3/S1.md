가장 큰 차이는 캐시(자주 쓰는 데이터를 빠르게 꺼내려고 임시로 저장해 두는 곳)를 서버마다 따로 두느냐, 서버 4대가 하나를 같이 쓰느냐입니다.

지금은 로컬 캐시를 씁니다. API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 서버마다 저장한 시점이 달라서 캐시 내용도 서로 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. 같은 시점에 요청해도 어느 서버가 응답하느냐에 따라 고객이 보는 가격이 다를 수 있습니다.

Redis 캐시는 별도의 캐시 서버 1대에 저장합니다. API 서버 4대가 이 서버를 같이 읽고 씁니다. 그래서 4대가 항상 같은 상품 목록을 보고, 서버끼리 가격이 달라지는 문제가 없어집니다.

다만 Redis를 도입하는 것만으로 반영 지연이 줄어들지는 않습니다. 저장 시간을 지금처럼 5분으로 두면 가격 변경이 고객에게 최대 5분 늦게 반영될 수 있습니다. 가격을 바꿀 때 Redis의 상품 목록을 바로 지우도록 만들면 지연을 5분보다 줄일 수 있습니다.

Redis 서버가 1대라서, 이 서버가 멈추면 API 서버 4대가 모두 캐시를 쓸 수 없습니다. 이때 고객에게 어떤 영향이 있는지는 설계에 따라 달라지므로, 개발팀에 확인이 필요합니다.
