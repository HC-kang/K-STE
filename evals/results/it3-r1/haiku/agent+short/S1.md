로컬 캐시와 Redis 캐시의 차이는 자료를 보관하는 위치입니다. 로컬 캐시는 각 API 서버(고객 요청을 받아 처리하는 서버) 안의 메모리(임시 작업 공간)에 상품 목록 사본을 보관합니다. Redis(여러 서버가 함께 쓰는 공용 저장소 프로그램)는 서버 바깥의 별도 캐시 서버에 사본을 보관하고, API 서버 4대가 이 한 곳을 같이 사용합니다.

지금 문제는 서버 4대가 각자 다른 사본을 들고 있다는 점입니다. 그래서 가격을 바꾸면 서버마다 반영 시점이 달라지고, 최대 5분(저장된 데이터를 그대로 쓰는 기간) 늦게 고객에게 보입니다.

Redis를 도입하면 4대가 같은 사본을 보므로 서버마다 다른 값을 보는 문제가 없어집니다. API 서버를 재시작해도 Redis에 저장된 캐시는 비워지지 않습니다.

다만 Redis 도입만으로 5분 지연이 없어지지는 않습니다. 저장 기간을 5분 그대로 두면 지연도 5분 그대로입니다. 지연을 줄이려면 가격이 바뀔 때 Redis에 있는 해당 상품 사본을 지우거나 새 가격으로 바꾸는 작업을 함께 넣어야 합니다. 이 작업을 넣을지는 개발팀과 확인해야 합니다.

Redis를 거치면 캐시를 읽을 때마다 통신 시간이 추가됩니다. Redis 서버가 멈추면 캐시를 쓰는 API 서버 4대 모두 영향을 받을 수 있습니다.
