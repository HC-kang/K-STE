Redis를 도입하면 서버 4대가 같은 캐시를 함께 보므로, 지금처럼 서버마다 다른 상품 정보를 보는 문제는 줄어듭니다. 다만 가격이 고객에게 바로 반영되는 것은 아니고, 가격을 바꿨을 때 캐시를 지우거나 새로 채우는 방식을 따로 정해야 합니다.

캐시는 자주 쓰는 데이터를 빠르게 꺼내려고 임시로 보관해 두는 곳입니다. 지금은 각 API 서버가 자기 메모리에 캐시를 가지고 있습니다. Redis는 여러 서버가 함께 쓰는 캐시 전용 서버입니다.

| 구분 | 지금: 서버별 캐시 | Redis 도입 후 |
|---|---|---|
| 캐시 위치 | 각 API 서버의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있음 | 4대가 같은 값을 봄 |
| 가격 반영 지연 | 최대 5분 (5분 동안 보관 후 새로 가져옴) | 캐시를 어떻게 갱신하는지에 따라 달라짐. 아직 정하지 않음 |

Redis를 쓰면 API 서버가 상품 정보를 가져올 때 Redis 서버에 한 번 더 요청하므로, 응답이 조금 느려질 수 있습니다. Redis 서버가 1대뿐이라서, 그 서버가 멈추면 캐시를 쓸 수 없게 됩니다. Redis가 멈췄을 때 서비스가 어떻게 동작할지는 아직 확인하지 않았습니다.

가격 반영을 고객에게 몇 분 안에 해야 하는지 기준을 정해 주십시오. 그 기준에 맞춰 캐시를 갱신하는 방식을 결정해야 합니다.
