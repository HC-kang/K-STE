로컬 캐시는 각 API 서버가 자기 메모리에 상품 목록을 따로 저장하는 방식이고, Redis는 4대 서버가 함께 쓰는 캐시 서버 1대에 상품 목록을 저장하는 방식입니다. 두 방식의 차이는 다음과 같습니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 | 별도의 캐시 서버 1대 |
| 서버 4대가 읽는 내용 | 서버마다 다를 수 있습니다 | 모두 같은 내용을 읽습니다 |
| 가격 변경 반영 | 서버마다 최대 5분 늦습니다 | 캐시를 갱신하는 방식에 따라 달라집니다 |

Redis를 도입하면 서버 4대가 같은 데이터를 보므로, 서버에 따라 고객에게 다른 가격이 보이는 문제가 없어집니다. 다만 가격을 바꿨을 때 고객에게 반영되는 시점은 Redis 안의 캐시를 언제 지우거나 고치는지에 따라 달라집니다. 이 부분은 제가 아직 확인하지 못했습니다.

Redis는 서버가 값을 읽을 때마다 네트워크를 거쳐 캐시 서버에 요청하므로, 로컬 메모리를 읽을 때보다 응답이 조금 느려질 수 있습니다. 또한 캐시 서버가 멈추면 서버 4대가 모두 영향을 받습니다. 이는 구조상 예상되는 내용이며, 실제 영향은 측정해 보아야 합니다.

가격 반영을 5분보다 빠르게 만들려면, 가격을 바꿀 때 Redis의 캐시를 함께 지우거나 갱신하도록 설계에 포함해야 합니다.
