원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고 CI만 2.0.0을 설치하는 것일 가능성이 가장 높습니다. 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 경로 목록)에 `./button`이 없으면 `@company/ui/button` import가 실패합니다.

## 사실

- CI에서만 빌드가 실패하고, 에러는 `Cannot find module '@company/ui/button'`입니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 업그레이드 전에 설치했습니다.
- CI는 Node 18, 로컬은 Node 20을 쓰고, CI 캐시 키는 `package-lock.json`의 해시입니다.

## 추론

- 로컬 `node_modules`가 업그레이드 전에 설치됐으므로 로컬에는 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 어떤 하위 경로든 import할 수 있습니다.
- CI는 lockfile 기준으로 새로 설치하므로 2.0.0을 받습니다. `exports` 필드가 있는 패키지는 목록에 적힌 경로만 import할 수 있고, `./button`이 목록에 없으면 위 에러가 납니다.
- Node 버전 차이는 원인일 가능성이 낮습니다. `exports` 필드는 Node 18과 20 모두 지원합니다.
- 캐시도 원인일 가능성이 낮습니다. 업그레이드 때 lockfile이 바뀌었다면 캐시 키가 달라져서 이전 캐시를 쓰지 않습니다.

## 미확인

- 2.0.0의 `exports`에 `./button`이 실제로 있는지 확인하지 않았습니다.
- 로컬에 설치된 `@company/ui`가 1.4.0인지 확인하지 않았습니다.
- 3일 전 커밋에 lockfile 변경이 포함됐는지 확인하지 않았습니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button`이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 조건이므로 로컬에서도 같은 에러가 나면 원인이 확정됩니다.
4. 같은 에러가 나면 2.0.0의 changelog나 `exports` 목록에서 `button`의 새 import 경로를 찾습니다.

## 해결 방향

원인이 확정되면 두 가지 중 하나를 선택합니다. 앱의 import 경로를 `exports`에 있는 경로로 바꾸거나, `@company/ui`에 `./button` 경로를 추가한 버전을 요청합니다. 당장 CI를 복구해야 하면 `@company/ui`를 1.4.0으로 되돌리는 방법도 있습니다.
