Redis를 도입하면 API 서버 4대가 같은 캐시를 보게 되어, 서버마다 상품 가격이 다르게 보이는 문제가 없어집니다.

로컬 캐시는 API 서버가 각자 자기 메모리에 저장해 두는 상품 목록 사본입니다. 지금은 서버 4대가 사본을 4개 따로 가지고, 각자 5분 동안 보관합니다. 그래서 가격을 바꿔도 서버마다 옛 사본이 남아 있고, 고객에게는 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 함께 쓰는 캐시 서버 1대입니다. 사본이 1개이므로 서버끼리 값이 어긋나지 않습니다. 가격을 바꿀 때 캐시를 바로 비우는 방식으로 만들면 반영 지연도 줄일 수 있습니다.

일반적으로 Redis는 서버를 한 번 거쳐 읽으므로 자기 메모리보다 조금 느리고, 캐시 서버가 멈췄을 때의 대비책도 따로 필요합니다. 이번 도입에서 어떻게 대비하는지도 개발팀에 확인이 필요합니다.
