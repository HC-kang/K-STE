가장 가능성이 높은 원인은 CI(코드를 올리면 자동으로 빌드하는 서버)가 `@company/ui` 2.0.0을 설치하는 반면 로컬은 아직 1.4.0을 쓰고 있어서, 2.0.0에서 `@company/ui/button` 경로를 불러올 수 없게 된 것입니다. 이 가설은 아직 확인하지 않았습니다.

근거는 다음과 같습니다.

- 로컬 `node_modules`(설치된 라이브러리를 모아 둔 폴더)는 3일 전 업그레이드보다 먼저 설치한 것이므로, 로컬은 1.4.0 그대로일 가능성이 높습니다.
- 2.0.0은 `exports` 필드(패키지가 외부에 공개하는 import 경로를 정하는 설정)를 추가했습니다. `exports`가 있으면 거기에 적힌 경로만 import할 수 있습니다. `./button`이 `exports`에 없거나 적힌 경로의 파일이 없으면 import가 실패할 수 있습니다.
- Node 18도 `exports`를 지원하므로, Node 18과 20의 차이가 주원인일 가능성은 낮다고 봅니다. 이 부분도 확인하지 않았습니다.
- CI 캐시 키는 `package-lock.json`(설치 버전을 고정하는 파일)의 해시입니다. lock 파일이 2.0.0으로 갱신됐다면 CI는 새 캐시로 2.0.0을 설치합니다. 갱신 여부는 확인하지 않았습니다.

다음 순서로 확인하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오.
2. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 확인하십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 `next build`를 실행하십시오. 같은 오류가 나면 원인은 2.0.0입니다.
4. 3번에서 오류가 나지 않으면 Node 18로 바꿔 다시 빌드하십시오.

3번에서 오류가 재현되면 import 경로를 2.0.0의 `exports`에 적힌 경로로 바꾸십시오.
