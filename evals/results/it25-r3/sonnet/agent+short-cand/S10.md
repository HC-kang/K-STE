원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰기 때문으로 보입니다. 로컬은 1.4.0으로 빌드하고, CI는 2.0.0으로 빌드하는 것으로 추정합니다. 아래 근거 중 확인한 사실은 질문에서 받은 내용뿐이고, 나머지는 추론입니다.

## 추정 원인

- 2.0.0에 `exports` 필드(패키지가 바깥에 공개하는 import 경로의 목록)가 추가됐습니다. `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다.
- 1.4.0에는 `exports`가 없었으므로 `@company/ui/button`처럼 파일 경로를 직접 적어도 import가 됐습니다.
- 2.0.0의 `exports`에 `./button`이 없거나 다른 이름으로 바뀌었다면 `Cannot find module '@company/ui/button'`이 납니다. 이 부분은 `exports` 내용을 아직 보지 않아서 추론입니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것입니다. 그래서 로컬은 1.4.0을 쓰고 있을 가능성이 높습니다. CI는 `package-lock.json`대로 새로 설치하므로 2.0.0을 받습니다.

## 원인이 아닐 가능성이 높은 것

- Node 버전은 원인일 가능성이 낮습니다. `exports`는 Node 18과 Node 20 모두 지원한다고 알고 있습니다. 다만 이 부분은 제가 이 환경에서 실행해 확인한 내용이 아닙니다.
- CI 캐시는 원인일 가능성이 낮습니다. 캐시 키가 `package-lock.json`의 해시이므로, 버전을 올리면 키가 바뀌어 옛 캐시를 쓰지 않아야 합니다. 단, 업그레이드 때 `package-lock.json`이 커밋됐는지는 확인하지 못했습니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다. 1.4.0이면 추정이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 봅니다. 2.0.0 기준으로 봐야 하므로 1단계에서 1.4.0이 나오면 먼저 3단계를 합니다.
3. `rm -rf node_modules && npm ci`로 로컬을 CI와 같은 조건으로 다시 설치한 뒤 빌드합니다. 이때 로컬 빌드가 같은 에러로 실패하면 원인이 확정됩니다.

## 해결 방향

원인이 확정되면 두 가지 중 하나를 고를 수 있습니다. 어느 쪽이 맞는지는 2.0.0의 의도를 아는 `@company/ui` 담당자가 정해야 합니다.

- 앱 코드의 import 경로를 2.0.0의 `exports`에 있는 경로로 바꿉니다.
- `./button`이 공개 경로여야 한다면 `@company/ui`에 `exports` 항목을 추가해 새 버전을 배포합니다.

PM에게 알립니다. 이 문제는 CI 환경 설정 오류가 아니라 의존성 업그레이드에 따른 호환성 문제일 가능성이 높습니다. 그래서 CI 설정을 바꿔도 해결되지 않을 것으로 보입니다.
