Redis를 도입하면 서버 4대가 같은 캐시를 보게 되므로, 서버마다 상품 목록이 달라지는 문제가 없어집니다.

캐시(자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 방식)를 어디에 두느냐가 두 방식의 차이입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대가 각자 자기 메모리에 저장합니다. | 서버 4대가 함께 쓰는 캐시 서버 1대에 저장합니다. |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 4대가 같은 내용을 봅니다. |
| 현재 보관 시간 | 상품 목록을 5분 동안 보관합니다. | 이번 도입 계획에서 정해진 값은 없습니다. |

현재 서버마다 캐시를 따로 가지고 있어서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. 같은 시점에 어떤 고객은 새 가격을, 다른 고객은 이전 가격을 볼 수도 있습니다.

Redis를 쓰면 캐시가 한 곳에만 있습니다. 그래서 가격 변경이 캐시에 한 번 반영되면 서버 4대가 모두 같은 가격을 보여 줍니다.

다만 지연이 5분에서 얼마로 줄어드는지는 아직 모릅니다. 가격을 바꿀 때 Redis의 캐시를 바로 지우는 방식으로 만드는지에 따라 달라지는 것으로 보입니다. 개발팀에 이 방식을 정했는지 물어보시기 바랍니다.
