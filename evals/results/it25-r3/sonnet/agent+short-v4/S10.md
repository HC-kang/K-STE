CI 빌드 실패의 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드로 보입니다. 로컬 빌드가 성공하는 이유는 로컬 `node_modules`에 아직 1.4.0이 설치돼 있기 때문으로 보입니다. 두 내용은 모두 추론이고, 아직 검증하지 않았습니다.

`exports` 필드는 패키지가 외부에 공개할 파일 경로를 제한하는 설정입니다. 2.0.0의 `exports`에 `./button` 경로가 정의돼 있지 않으면 `@company/ui/button`을 불러올 수 없고, 그때 `Cannot find module '@company/ui/button'` 에러가 납니다. 1.4.0에는 `exports` 필드가 없었으므로 같은 import가 동작했을 것입니다.

두 환경의 차이는 다음과 같습니다.

| 항목 | 로컬 | CI |
|---|---|---|
| `@company/ui` 버전 | 1.4.0으로 보임 | 2.0.0으로 보임 |
| 설치 시점 | 3일 전 업그레이드보다 먼저 | 캐시 키가 바뀐 뒤 새로 설치 |
| Node | 20 | 18 |

CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 `package-lock.json`이 바뀌었으므로 캐시 키도 바뀌었고, CI는 2.0.0을 새로 설치했을 가능성이 큽니다. 이 설명은 CI가 업그레이드 뒤 처음 실패했다는 점과 맞지만, CI 로그로 설치된 버전을 확인하지는 않았습니다.

Node 18과 20은 둘 다 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 주된 원인이 아닐 가능성이 큽니다.

추론이 맞는지 다음 순서로 검증하십시오.

1. 로컬에서 `npm ci`로 `node_modules`를 다시 설치하고 빌드하십시오. 같은 에러가 나면 로컬 `node_modules`가 오래돼서 성공했다는 설명이 맞습니다.
2. `node_modules/@company/ui/package.json`을 열어 `exports`에 `./button`이 있는지 보십시오.
3. `./button`이 없으면 import 경로를 `exports`에 정의된 경로로 바꾸십시오. 2.0.0에서 `button`이 다른 경로로 옮겨졌는지는 모르므로 `@company/ui` 담당자에게 물어보십시오.

확인 필요: 2.0.0에서 `@company/ui/button`을 의도적으로 공개하지 않았는지, `exports`에서 실수로 빠졌는지 알 수 없습니다. 어느 쪽이냐에 따라 이쪽에서 import를 고칠지, 패키지 쪽에서 `exports`를 고칠지가 달라집니다.
