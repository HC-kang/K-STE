# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 마이그레이션이 포함된 배포는 롤백하면 안 된다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법. 이 런북에는 확인 방법이 정해져 있지 않다.
3. **경고:** 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때는 DBA 박지은에게 연락해야 한다.
4. 마이그레이션이 포함되지 않았음을 확인한 다음 롤백할 `<REVISION>` 값을 정한다.
5. 확인 필요: `<REVISION>`에 넣을 값을 정하는 방법. 이 런북에는 값을 찾는 기준이 정해져 있지 않다.

## 롤백 절차

1. 마이그레이션이 포함되지 않았음을 확인한 경우에만 다음 명령으로 payment-api를 롤백한다.

```
argocd app rollback payment-api <REVISION>
```

## 결과 확인

1. 확인 필요: `/healthz`를 호출할 주소.
2. 롤백한 뒤 payment-api의 `/healthz`를 호출하여 응답 코드가 200을 반환하는지 본다.
3. `/healthz`가 200을 반환하면 결제 테스트 주문을 1건 넣는다.
4. 결제 테스트 주문 1건이 성공하는지 본다.
