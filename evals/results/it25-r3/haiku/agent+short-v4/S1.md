Redis를 도입하면 서버 4대가 같은 캐시를 함께 읽게 되어, 서버마다 상품 목록이 달라지는 문제가 없어집니다. 다만 가격 변경이 고객에게 바로 보이는지는 Redis 도입만으로 정해지지 않고, 가격을 바꿀 때 캐시를 지우는 작업을 넣는지에 따라 달라집니다.

지금은 각 API 서버(고객의 요청에 응답하는 서버)가 자기 메모리(서버가 작업할 때 쓰는 공간)에 상품 목록을 5분 동안 캐시(자주 쓰는 자료를 미리 담아 두는 임시 저장 공간)합니다. 서버마다 저장된 내용이 달라서, 가격을 바꾸면 서버마다 최대 5분 뒤에 새 가격이 보입니다.

Redis는 캐시만 전담하는 별도 서버 프로그램입니다. Redis 도입 후에는 캐시 서버 1대에 상품 목록을 두고, 서버 4대가 모두 그 한 곳을 읽습니다.

| 구분 | 지금: 서버 안 캐시 | Redis 도입 후 |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 사이의 내용 | 서버마다 다를 수 있습니다 | 모든 서버가 같은 내용을 봅니다 |
| 읽는 방식 | 서버 안에서 바로 읽습니다 | 네트워크를 한 번 거쳐 읽습니다 |

Redis만 도입하고 캐시를 5분 뒤에 지우는 기존 방식을 그대로 두면, 가격이 고객에게 보이기까지 최대 5분이 걸리는 문제는 그대로 남습니다. 가격을 바꿀 때 Redis에 저장된 상품 캐시를 바로 지우면, 지워진 뒤 첫 요청부터 새 가격을 읽습니다. 그래서 가격 변경 반영을 빠르게 하려면 이 작업을 Redis 도입 일정에 함께 넣는 것을 권장합니다.

Redis 서버가 멈추면 서버 4대가 모두 캐시를 쓸 수 없게 되므로, 캐시 서버가 멈췄을 때의 대비책도 함께 세워야 합니다.
