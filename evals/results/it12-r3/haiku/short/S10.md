현재 자료로는 원인을 확정할 수 없습니다. 가장 유력한 가설은 CI가 2.0.0을 설치하고, 로컬은 3일 전에 설치된 `node_modules`를 그대로 써서 1.4.0으로 빌드하고 있다는 것입니다. 이 경우 로컬 빌드 성공은 2.0.0이 정상이라는 근거가 되지 못합니다.

### 확인된 사실

- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 `exports` 필드(패키지 외부에 공개할 파일 경로를 정하는 설정)가 추가되었습니다.
- CI(GitHub Actions 빌드 환경)는 Node 18을 쓰고, 로컬은 Node 20을 씁니다.
- CI 캐시 키는 `package-lock.json`(설치할 패키지 버전을 기록한 파일)의 해시(파일 내용을 요약한 값)입니다.
- 로컬 `node_modules`(패키지가 설치되는 폴더)는 3일 전보다 먼저 설치되었습니다.
- 실패 에러는 `Error: Cannot find module '@company/ui/button'`입니다.

### 추론

- 로컬 `node_modules`가 3일 전에 설치되었으므로 로컬에는 1.4.0이 남아 있을 가능성이 큽니다. 그래서 로컬 빌드는 2.0.0 변경을 거치지 않았습니다.
- `package-lock.json`이 2.0.0으로 갱신되어 커밋되었다면, 캐시 키가 바뀌어 CI는 새로 설치하면서 2.0.0을 받습니다. 그래서 CI에서만 실패하는 현상이 설명됩니다.
- Node 18과 20의 차이가 원인이라고 볼 근거는 현재 없습니다. 두 버전 모두 `exports`를 지원하므로 이 차이는 부차적인 변수로 둡니다.
- 에러 문구는 Node가 `exports`에 없는 경로를 막을 때 내는 메시지(`ERR_PACKAGE_PATH_NOT_EXPORTED`)와 다릅니다. 따라서 `exports` 때문에 생긴 문제인지, 파일이 실제로 없어서 생긴 문제인지, 다른 도구가 에러를 냈는지 구분해야 합니다.

### 미확인

- 에러를 낸 도구가 Next.js 빌드인지, 별도 스크립트인지 확인하지 않았습니다.
- 2.0.0의 `exports`에 `./button` 경로가 포함되어 있는지 확인하지 않았습니다.
- `package-lock.json`에 2.0.0이 기록되어 커밋되었는지 확인하지 않았습니다.
- 로컬에 실제로 설치된 `@company/ui` 버전을 확인하지 않았습니다.
- 아래 확인 순서는 아직 실행하지 않았습니다.

### 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `package-lock.json`에서 `@company/ui`의 `version` 값을 확인합니다.
3. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 확인합니다.
4. CI 로그에서 에러가 난 단계와 설치된 버전을 확인합니다.
5. 로컬에서 `rm -rf node_modules && npm ci`로 새로 설치한 뒤, Node 18로 빌드를 재현합니다.

### 조치 방향

확인 결과가 `exports`에 `./button`이 없다는 것이라면, import 경로를 2.0.0이 공개한 경로로 고쳐야 합니다. 2.0.0이 해당 경로를 제공하지 않는다면 1.4.0으로 되돌리는 방안을 검토해야 합니다. 두 방안 모두 1번부터 5번까지의 확인 결과를 본 뒤에 결정해야 합니다.
