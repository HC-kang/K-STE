Redis를 도입하면 서버 4대가 같은 캐시를 함께 쓰므로, 서버마다 가격이 다르게 보이는 문제가 없어집니다. 다만 Redis를 도입한다고 가격 변경이 바로 반영되지는 않습니다. 반영 속도는 캐시를 얼마나 자주 새로 가져오는지, 가격 변경 시 캐시를 지우는지에 따라 정해집니다.

캐시는 자주 보는 정보를 빠르게 꺼내 쓰려고 임시로 저장해 두는 공간입니다. 지금은 서버 4대가 각각 자기 메모리(서버 안의 작업 공간)에 상품 목록을 5분 동안 저장합니다. 이를 로컬 캐시라고 합니다. Redis(레디스)는 서버 4대가 함께 쓰는 별도의 캐시 서버입니다.

| 구분 | 현재 로컬 캐시 | Redis 도입 후 |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 데이터 | 서버마다 다를 수 있음 | 4대가 같은 데이터를 봄 |
| 가격 변경 반영 | 서버별로 최대 5분 늦음 | 캐시 처리 방식에 따라 결정됨 |
| 장애 영향 | 서버 1대가 문제여도 그 서버만 영향을 받음 | 캐시 서버가 멈추면 4대 전체가 영향을 받음 |
| 응답 속도 | 서버 안에서 읽어 가장 빠름 | 네트워크를 거쳐 읽어 약간 느릴 수 있음 |

Redis 도입으로 좋아지는 점은 두 가지입니다. 첫째, 서버마다 가격이 다르게 보이는 문제가 없어집니다. 둘째, 가격을 바꾼 뒤 Redis의 캐시를 지우는 처리를 넣으면 4대에 한 번에 반영할 수 있습니다.

주의할 점도 있습니다. 캐시 서버가 멈추면 4대 서버 모두 영향을 받습니다. 또한 Redis를 거쳐 읽으므로 응답이 조금 느려질 수 있습니다.

확인이 필요한 사항은 다음과 같습니다.

- 확인 필요: 가격 변경 시 Redis 캐시를 지우는 처리가 이번 도입 범위에 포함되는지 확인해야 합니다.
- 확인 필요: 캐시 유효 시간 5분을 그대로 둘지 줄일지 정해야 합니다.
- 확인 필요: Redis 서버가 멈췄을 때의 대응 방법이 정해져 있는지 확인해야 합니다.
