# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 REVISION으로 되돌리는 절차를 정한다. DB 마이그레이션이 포함된 배포는 롤백하면 안 된다. 롤백한 뒤에는 `/healthz` 응답과 결제 테스트 주문으로 결과를 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
   확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 확인 위치.
2. **경고:** 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때 DBA 박지은에게 연락해야 한다.
   확인 필요: DBA 박지은의 연락 방법.
3. 마이그레이션이 포함되지 않았으면 다음 절차로 넘어간다.

## 롤백 절차

1. 롤백할 REVISION 값을 정한다.
   확인 필요: 롤백할 REVISION 값을 찾는 방법.
2. 다음 명령으로 payment-api를 롤백한다. `<REVISION>`에는 1번에서 정한 값을 넣는다.

```
argocd app rollback payment-api <REVISION>
```

## 결과 확인

1. payment-api의 `/healthz`가 200을 반환하는지 확인한다.
   확인 필요: `/healthz`를 요청할 주소.
2. 결제 테스트 주문을 1건 실행하고, 그 주문이 성공하는지 확인한다.
   확인 필요: 결제 테스트 주문을 실행하는 방법.
3. 1번 또는 2번이 실패하면 이 런북에 따른 다음 조치가 없다.
   확인 필요: 헬스 체크나 테스트 주문이 실패할 때의 조치.

## 기록

1. 롤백 이력을 #deploy 채널에 남긴다.
