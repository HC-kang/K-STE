원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드로 보입니다. 로컬은 아직 1.4.0을 쓰고 있어서 에러가 나지 않는 것으로 추정합니다. 이 추정은 아래 확인 절차로 검증해야 합니다.

## 사실

- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다. `exports`는 패키지가 외부에 공개할 import 경로를 직접 지정하는 설정입니다.
- `exports`가 있는 패키지는 목록에 없는 경로를 import할 수 없습니다. 파일이 실제로 있어도 마찬가지입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 버전을 올리면 이 파일이 바뀌므로 캐시가 새로 만들어집니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것입니다.

## 추론

| 항목 | 로컬 | CI |
|---|---|---|
| `@company/ui` 버전 | 1.4.0으로 보임 | 2.0.0 |
| `exports` 필드 | 없음 | 있음 |
| `@company/ui/button` | 파일 경로로 접근해서 성공 | 목록에 없으면 실패 |

1. CI는 `package-lock.json`이 바뀌어 캐시를 새로 만들고, 2.0.0을 설치합니다.
2. 로컬은 업그레이드 후 `npm install`을 다시 하지 않아 1.4.0이 남아 있는 것으로 보입니다.
3. 2.0.0의 `exports`에 `./button` 항목이 없거나 형식이 달라서 CI에서 모듈을 찾지 못하는 것으로 보입니다.

## Node 버전은 원인이 아닐 가능성이 높습니다

Node 18과 Node 20은 모두 `exports`를 지원합니다. 그래서 Node 버전 차이만으로는 이 에러를 설명하기 어렵습니다.

## 미확인

- 로컬에 설치된 `@company/ui`의 실제 버전
- 2.0.0 `exports`에 `./button`이 있는지 여부
- `exports`에 조건부 경로(`import`, `require` 등)가 있다면 Next.js 빌드가 어느 조건을 따르는지

## 확인 절차

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports`를 열어 `./button` 항목이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 `next build`를 다시 실행합니다. 로컬에서도 같은 에러가 나면 원인이 확정됩니다.

## 해결 방향

- `exports`에 `./button`이 없으면 패키지 담당자에게 항목 추가를 요청해야 합니다.
- 2.0.0이 import 경로를 바꿨다면 앱 코드의 import를 새 경로로 바꿔야 합니다.
- 1.4.0으로 되돌리는 방법은 임시 대응으로만 권장합니다.
- 같은 문제를 막으려면 업그레이드 후 로컬에서도 `npm ci`로 재설치하는 것을 권장합니다.
