Redis를 도입하면 서버 4대가 같은 캐시를 보게 되어, 서버마다 상품 목록이 달라지는 문제가 사라집니다.

캐시는 자주 찾는 데이터를 빠르게 꺼내 쓰려고 잠시 저장해 두는 곳입니다. 지금은 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 이것이 로컬 캐시입니다. 서버마다 저장한 시점이 달라서 같은 시각에도 서버마다 다른 내용을 보여 줄 수 있습니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 함께 쓰는 캐시 서버 1대에 상품 목록을 한 벌만 저장합니다. 서버 4대가 모두 이 한 벌을 읽으므로 서버마다 내용이 달라지지 않습니다.

가격 반영 시간은 Redis만 도입해서는 줄지 않을 수 있습니다. 상품 목록을 5분 동안 저장하는 규칙을 그대로 쓰면 최대 5분 지연이 남을 수 있습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 바로 지우도록 만들면 이 지연을 줄일 수 있습니다. 확인 필요: 이번 도입 계획에 이 방식이 들어 있는지 확인하지 못했습니다.

주의할 점도 있습니다. Redis는 서버 밖에 있는 캐시 서버이므로, 서버 자기 메모리를 읽을 때보다 시간이 조금 더 걸립니다. 또 Redis 서버가 1대이므로 이 서버에 문제가 생기면 API 서버 4대가 모두 영향을 받을 수 있다고 추정합니다.
