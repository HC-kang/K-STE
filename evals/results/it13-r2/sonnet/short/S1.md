가장 큰 차이는 캐시를 서버마다 따로 갖느냐, 서버 4대가 하나를 같이 쓰느냐입니다. 캐시는 자주 쓰는 데이터를 미리 저장해 두고 빨리 꺼내 쓰는 방식입니다.

지금은 로컬 캐시를 씁니다. API 서버 4대가 각자 자기 메모리(서버가 작업 중인 데이터를 잠시 두는 공간)에 상품 목록을 5분 동안 저장합니다. 서버마다 캐시 내용이 달라서, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 캐시 전용 서버 1대에 상품 목록을 저장합니다. API 서버 4대는 이 서버를 같이 읽습니다. 그래서 서버 4대가 같은 캐시 내용을 보게 되고, 서버마다 내용이 달라서 생기던 문제가 사라집니다.

다만 Redis를 도입하는 것만으로 5분 지연이 없어지는지는 확인이 필요합니다. 가격을 바꿀 때 Redis의 상품 목록을 바로 갱신하게 만들면 지연이 줄어들 수 있습니다. 지금처럼 5분이 지나 만료되기를 기다리면 지연은 그대로 남습니다. 개발팀에 가격 변경 시 캐시를 어떻게 처리할지 물어봐야 합니다.

또 캐시 서버가 1대라서, 이 서버에 문제가 생기면 API 서버 4대 모두 영향을 받을 수 있습니다.
