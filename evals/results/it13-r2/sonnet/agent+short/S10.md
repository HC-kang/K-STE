원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰고 있기 때문으로 보입니다. 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개할 import 경로를 제한하는 설정)가 `@company/ui/button` 경로를 공개하지 않을 가능성이 가장 큽니다. 아직 확인한 내용은 아닙니다.

## 추론 과정

로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다. 그래서 로컬에는 1.4.0이 그대로 남아 있을 것으로 보입니다. 1.4.0에는 `exports` 필드가 없으므로 `@company/ui/button`이 파일 경로로 그대로 찾아집니다.

CI는 `package-lock.json`의 해시로 캐시 키를 만듭니다. 2.0.0으로 올리면서 lock 파일이 바뀌었으므로 캐시가 새로 만들어졌고, CI는 2.0.0을 설치했을 것으로 보입니다. 2.0.0은 `exports`에 적힌 경로만 import할 수 있게 하므로, `./button`이 없으면 `Cannot find module` 오류가 납니다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `@company/ui` 버전 | 1.4.0으로 추정 | 2.0.0으로 추정 |
| `exports` 필드 | 없음으로 추정 | 있음 |
| 빌드 결과 | 성공 | 실패 |

Node 버전 차이는 원인일 가능성이 낮습니다. 일반적으로 Node 18과 20은 모두 `exports` 필드를 지원합니다. 다만 이 프로젝트에서 두 버전을 직접 비교해 본 결과는 없습니다.

## 확인되지 않은 것

- 로컬 `node_modules/@company/ui`의 실제 버전
- CI에 설치된 `@company/ui`의 실제 버전
- 2.0.0 `package.json`의 `exports`에 `./button`이 있는지
- `./button`이 없다면 2.0.0이 다른 경로로 옮겼는지, 의도적으로 제거했는지

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오.
2. `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 로컬에서 빌드하십시오. 로컬에서도 같은 오류가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에서 `./button` 항목을 찾으십시오.
4. 항목이 없으면 2.0.0의 변경 내역(changelog)이나 마이그레이션 문서에서 새 import 경로를 찾아 코드의 import를 고치십시오.

2번 결과가 가장 빠른 판별 기준입니다. 로컬 환경을 CI와 같은 조건으로 맞추면 CI에서만 실패하던 문제를 로컬에서 재현할 수 있습니다.
