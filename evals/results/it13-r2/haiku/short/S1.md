로컬 캐시는 서버 4대가 각자 메모리에 상품 목록을 따로 보관하는 방식이고, Redis 캐시는 4대가 함께 쓰는 별도 저장 서버 1대에 같은 목록을 보관하는 방식입니다. 캐시는 자주 쓰는 데이터를 빨리 꺼내 쓰려고 임시로 넣어 두는 사본입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 서버 재시작 시 | 캐시가 사라짐 | 캐시가 남아 있음 |
| 가격 반영 시간 | 최대 5분 | 보관 시간 설정에 따라 다름 |

Redis를 도입하면 서버마다 가격이 다르게 보이는 문제는 없어집니다. 하지만 Redis를 써도 보관 시간을 5분으로 그대로 두면 가격 반영은 최대 5분 늦어집니다. 반영 시간을 줄이려면 보관 시간을 줄이거나, 가격을 바꿀 때 캐시를 바로 지우는 작업을 따로 넣어야 합니다. 이 부분은 개발팀이 설계할 내용입니다.

Redis 도입에는 단점도 있습니다. 캐시 서버를 따로 운영해야 하고, 서버가 캐시를 읽을 때 네트워크를 거치므로 로컬 메모리보다 느립니다. Redis 서버가 멈추면 4대 서버 모두 캐시를 쓸 수 없으므로, 멈췄을 때 서버가 DB에서 직접 읽을지 정해 두어야 합니다.

확인 필요: 가격 변경이 몇 분 안에 고객에게 보여야 하는지 정해 주시면, 보관 시간과 캐시 삭제 방식을 그 기준에 맞춰 설계할 수 있습니다.
