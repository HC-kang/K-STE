# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api의 운영 배포를 지정한 리비전으로 되돌리는 절차를 정한다. 롤백 전에 그 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 마이그레이션이 포함됐으면 롤백하면 안 되고 DBA 박지은에게 연락해야 한다.

## 실행 정보

| 항목 | 내용 |
|---|---|
| 배포 도구 | ArgoCD |
| 대상 앱 | payment-api |
| 롤백 명령 | `argocd app rollback payment-api <REVISION>` |
| 롤백 리비전 | `<REVISION>`에 되돌릴 리비전 값을 넣는다. |
| DB 마이그레이션 포함 여부 확인 방법 | 정보 없음 |
| DBA 담당자 | 박지은 |
| 롤백 이력 기록 채널 | #deploy |

## 절차

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 되고, DBA 박지은에게 연락해야 한다. 이 경우 아래 단계는 진행하지 않는다.
3. 마이그레이션이 포함되지 않았으면 `argocd app rollback payment-api <REVISION>` 명령으로 롤백한다.
4. 롤백한 뒤 `/healthz`가 200을 반환하는지 확인한다.
5. 롤백한 뒤 결제 테스트 주문 1건이 성공하는지 확인한다.
6. #deploy 채널에 롤백 이력을 남긴다.
