원인은 아직 확정되지 않았습니다. 가장 유력한 원인은 2.0.0의 `exports` 필드가 `@company/ui/button` 경로를 허용하지 않는 것입니다. 로컬 빌드가 성공하는 이유는 로컬 `node_modules`가 업그레이드 전인 1.4.0일 가능성이 높기 때문입니다. 이 분석은 전달받은 내용만 근거로 합니다. 코드, 패키지 내용, CI 로그는 확인하지 않았습니다.

## 확인된 사실과 추론

확인된 사실은 다음과 같습니다. CI(Node 18)에서만 빌드가 실패하고, 로컬(Node 20)에서는 성공합니다. 실패 메시지는 `Cannot find module '@company/ui/button'`입니다. `@company/ui`는 3일 전에 1.4.0에서 2.0.0으로 올라갔고, 2.0.0부터 `exports` 필드가 있습니다. 로컬 `node_modules`는 3일 전보다 먼저 설치되었습니다.

다음 내용은 추론입니다. 로컬 `node_modules`가 업그레이드 이전에 설치되었으므로 1.4.0이 들어 있을 가능성이 높습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button` 같은 경로가 그대로 해석됩니다. 반대로 CI는 2.0.0을 설치하므로 같은 경로가 막힙니다.

## 원인 후보

| 후보 | 근거 | 확인 방법 | 가능성 |
|---|---|---|---|
| 2.0.0의 `exports`에 `./button` 항목이 없음 | 2.0.0에서 `exports`가 추가되었고, 실패하는 경로가 하위 경로(deep import)임 | 2.0.0의 `package.json`에서 `exports` 항목 조회 | 높음 (추론) |
| 로컬은 아직 1.4.0 | 로컬 `node_modules`가 업그레이드 전에 설치됨 | 로컬에서 `npm ls @company/ui` 실행 | 높음 (추론) |
| Node 18과 20의 차이 | 2.0.0이 ESM 전용이면 Node 18의 `require`에서 실패할 수 있음 | CI 로그의 `node -v`, 패키지의 `type`과 `exports` 조건 | 중간 (미확인) |
| 대소문자 차이 | CI(Linux)는 대소문자를 구분하고, 로컬(macOS 기본 설정)은 구분하지 않음 | import 경로와 실제 파일명 비교 | 미확인 |
| 캐시 문제 | 캐시 키가 `package-lock.json` 해시이므로 lock이 바뀌면 새로 설치됨 | workflow의 `restore-keys` 설정 확인 | 낮음 |

에러 메시지 형식도 단서가 됩니다. `Cannot find module`은 Node의 `require` 해석 단계에서 나오는 형식입니다. 하지만 Next.js(webpack)의 빌드 오류는 보통 `Module not found`로 표시됩니다. 따라서 이 에러를 낸 단계가 Next.js 빌드인지, 다른 스크립트인지 확인 필요합니다.

## 확인 순서

1. CI 로그에서 에러를 낸 단계, `node -v` 결과, `npm ls @company/ui` 결과를 확인합니다.
2. 로컬에서 `npm ls @company/ui`를 실행하여 실제 설치 버전을 확인합니다.
3. `@company/ui@2.0.0`의 `package.json`에서 `exports`에 `./button` 항목이 있는지 확인합니다.
4. `grep -rn "@company/ui/" src`로 하위 경로 import 목록을 뽑고, 실제 파일명과 대소문자를 비교합니다.
5. 로컬에서 `nvm use 18` 후 `rm -rf node_modules && npm ci && npm run build`를 실행해 CI 환경을 재현합니다.

위 1번과 2번만으로도 "로컬은 1.4.0, CI는 2.0.0"인지 바로 구분할 수 있습니다. 3번에서 `./button`이 없으면 원인이 거의 확정됩니다.

## 수정 방향 (아직 실행하지 않음)

- 2.0.0의 `exports`에 노출된 경로로 import를 바꿉니다. 예를 들어 메인 엔트리에서 가져오는 방식입니다.
- `@company/ui` 쪽에 `./button` 노출을 요청합니다. 요청이 처리될 때까지는 `@company/ui`를 1.4.0으로 고정하는 방법이 있습니다.
- CI와 로컬의 Node 버전을 맞춥니다. `.nvmrc`나 `engines` 필드에 버전을 명시하는 방법을 권장합니다.

## 영향과 주의점

현재 CI 빌드가 실패하는 상태입니다. 로컬 빌드 성공은 2.0.0이 동작한다는 증거가 아닙니다. 로컬에 1.4.0이 남아 있으면 로컬 결과는 업그레이드 이후 상태를 반영하지 않습니다.
