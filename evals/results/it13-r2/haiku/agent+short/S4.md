# payment-api 운영 배포 롤백 런북

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
   - 확인 필요: 마이그레이션 포함 여부를 확인하는 방법(대상 diff, 저장소, 도구 등)이 원문에 없다.
2. 마이그레이션이 포함됐으면 **롤백하면 안 된다.** 이 경우 롤백 담당자가 DBA 박지은에게 연락해야 한다.
   - 확인 필요: DBA 박지은의 연락처와 연락 방법이 원문에 없다.
3. 마이그레이션이 포함되지 않았으면 2번 절차로 넘어간다.

## 2. 롤백 실행

1. 롤백할 REVISION 값을 정한다.
   - 확인 필요: REVISION 값을 고르는 기준(직전 정상 배포 등)이 원문에 없다.
2. `argocd app rollback payment-api <REVISION>` 명령을 실행한다.

## 3. 롤백 후 확인

1. `/healthz`의 HTTP 상태 코드가 200을 반환하는지 확인한다.
   - 확인 필요: `/healthz`를 호출할 주소가 원문에 없다.
2. 결제 테스트 주문 1건을 넣고, 그 주문이 성공하는지 확인한다.
   - 확인 필요: 테스트 주문을 넣는 방법과 테스트 결제 환경 정보가 원문에 없다.

## 4. 롤백 이력 기록

1. #deploy 채널에 롤백 이력을 남긴다.
   - 확인 필요: 이력에 적을 항목(리비전, 시각, 작업자 등)이 원문에 없다.
