Redis(여러 서버가 함께 쓰는 별도의 캐시 서버)를 도입하면 4대 서버가 같은 캐시 데이터를 보게 됩니다. 그래서 서버마다 가격이 다르게 보이는 문제가 없어집니다. 다만 가격 변경이 고객에게 반영되는 시간이 얼마나 줄어드는지는 아직 확인되지 않았습니다.

캐시는 자주 보는 데이터를 미리 복사해 두고 빠르게 꺼내 쓰는 임시 저장 공간입니다. 지금 우리 서버는 각 서버의 메모리(프로그램이 작업할 때 쓰는 임시 공간) 안에 캐시를 둡니다. 두 방식을 비교하면 다음과 같습니다.

| 구분 | 지금 방식 (서버 안 캐시) | Redis 도입 후 (공용 캐시 서버) |
|---|---|---|
| 캐시를 두는 곳 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 데이터 사본 | 서버마다 따로 있어 내용이 달라질 수 있음 | 한 벌만 있어 4대 서버가 같은 값을 봄 |
| 가격 변경 반영 | 고객에게 최대 5분 늦게 반영됨 | 확인 필요 (아래 참고) |
| 응답 속도 | 서버 안에서 바로 꺼내므로 가장 빠름 | 서버 밖의 캐시 서버에 요청하므로 상대적으로 느릴 수 있음 |

확인 필요: 가격을 바꿀 때 Redis에 저장된 상품 값을 바로 지우거나 고치는지, 아니면 지금처럼 일정 시간이 지나야 갱신되는지 정해야 합니다. 이 방식에 따라 고객에게 가격이 반영되는 시간이 달라집니다.

구조상 추론하면, 캐시 서버가 1대뿐이라 이 서버에 장애가 나면 4대 서버가 모두 영향을 받을 수 있습니다. 도입 전에 이 장애에 대비하는 방법을 함께 검토하기를 권장합니다.
