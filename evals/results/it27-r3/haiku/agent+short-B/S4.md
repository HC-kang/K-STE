# 운영 배포 롤백 런북 (payment-api)

이 런북은 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 되돌리는 절차를 설명한다. 롤백할 배포에 DB 마이그레이션이 포함됐으면 롤백하지 않고 DBA에게 연락한다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다. 확인 방법은 확인 필요: 마이그레이션 포함 여부를 어떤 자료나 도구로 확인하는지 정해지지 않았다.
2. **경고:** 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 롤백할 `<REVISION>` 값을 확인한다. 확인 필요: `<REVISION>` 값을 어디서 찾는지 정해지지 않았다.

## 롤백

4. 마이그레이션이 포함되지 않은 것을 확인한 경우에만 다음 명령으로 롤백한다.

```
argocd app rollback payment-api <REVISION>
```

## 결과 확인

5. `/healthz`가 200을 반환하는지 확인한다.
6. 결제 테스트 주문 1건이 성공하는지 확인한다. 확인 필요: 결제 테스트 주문을 어디서 어떻게 넣는지 정해지지 않았다.

## 기록

7. 롤백 이력을 #deploy 채널에 남긴다.

확인 필요 항목 세 가지(마이그레이션 확인 방법, `<REVISION>` 찾는 방법, 결제 테스트 주문 방법)가 정해져야 이 런북으로 실제 롤백을 진행할 수 있다.
