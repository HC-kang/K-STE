Redis를 도입하면 서버 4대가 같은 상품 목록을 함께 봅니다. 그래서 서버마다 가격이 다르게 보이는 차이는 사라집니다.

로컬 캐시는 각 서버가 자기 메모리에 상품 목록의 복사본을 저장해 두는 방식입니다. Redis는 캐시 전용 서버 1대에 상품 목록을 저장해 두고, 4대 서버가 그 서버에서 가져다 쓰는 방식입니다.

| 구분 | 로컬 캐시 (지금) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대 서버가 같은 내용을 봅니다 |
| 조회 속도 | 서버 안에서 바로 읽어 빠릅니다 | 네트워크를 거쳐 읽어 로컬보다 느립니다 |

Redis는 조회할 때마다 네트워크로 Redis 서버에 요청해야 하므로 지금보다 조회가 느려집니다. 가격이 고객에게 반영되는 시간은 가격을 바꿀 때 Redis 캐시를 어떻게 갱신하느냐에 따라 달라집니다. 가격을 바꾸면 Redis 캐시를 바로 지우는 방식이면 반영 지연이 크게 줄어듭니다. 5분 주기로만 갱신하는 방식이면 지연은 최대 5분 그대로입니다.

확인 필요: 가격을 바꿀 때 Redis 캐시를 바로 지우는 설계인지, 5분 주기로만 갱신하는 설계인지. 이 내용에 따라 PM 답변의 마지막 두 문장이 달라지므로 보내기 전에 정해야 합니다.

확인 필요: Redis 서버가 멈췄을 때 API가 어떻게 동작하는지. 주어진 정보에 없어서 PM 답변에는 넣지 않았습니다.
