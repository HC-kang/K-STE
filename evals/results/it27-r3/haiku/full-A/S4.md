# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백하기 전에 그 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다. 마이그레이션이 포함됐으면 롤백하면 안 된다.

## 1. 사전 확인

1. 롤백할 리비전 값(REVISION)을 정한다.
2. 그 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다.

## 2. 롤백 여부 판단

**경고: 마이그레이션이 포함됐으면 롤백하면 안 된다.**

- 마이그레이션이 포함됐으면 롤백을 중단한다. DBA 박지은에게 연락한다.
- 마이그레이션이 포함되지 않았으면 3번 단계로 진행한다.

## 3. 롤백 실행

3. 다음 명령을 실행한다. `<REVISION>`에는 1번 단계에서 정한 리비전 값을 넣는다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

## 4. 롤백 후 확인

4. `/healthz`가 200을 반환하는지 확인한다.
5. 결제 테스트 주문 1건이 성공하는지 확인한다.

## 5. 이력 기록

6. 롤백 이력을 #deploy 채널에 남긴다.

## 확인 필요

- 리비전 값과 마이그레이션 포함 여부를 확인할 방법과 자료. 사실에 없습니다.
- DBA 박지은의 연락 방법, 결제 테스트 주문을 실행하는 방법과 담당자. 사실에 없습니다.
- #deploy 채널에 남길 이력의 항목. 사실에 없습니다.
