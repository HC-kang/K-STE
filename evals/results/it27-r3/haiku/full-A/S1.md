Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되므로, 지금처럼 서버마다 내용이 달라지는 문제는 없어집니다. 다만 가격을 바꾼 뒤 고객 화면에 보이기까지 걸리는 시간은 Redis에 저장한 내용을 언제 새로 고치는지에 따라 달라집니다.

캐시는 자주 쓰는 데이터를 빨리 꺼내 쓰려고 따로 저장해 둔 복사본입니다. 지금은 각 서버가 자기 메모리(작업용 임시 저장 공간)에 캐시를 둡니다. Redis는 서버들이 함께 쓰는 별도의 캐시 서버이며, 이 서버 프로그램의 이름입니다. 두 방식을 비교하면 다음과 같습니다.

| 항목 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 달라질 수 있음 | 4대가 같은 내용을 봄 |
| 조회 속도 | 서버 안에서 바로 꺼냄 | 네트워크를 거쳐 조회하므로 로컬보다 느릴 수 있음 |
| 장애 영향 | 문제가 생긴 서버 1대 | 캐시 서버가 멈추면 4대 전체 |

우리 서비스에서 좋아지는 점은 서버마다 다른 데이터를 보는 문제가 없어진다는 것입니다. 가격 지연은 Redis 캐시를 어떻게 갱신하느냐에 따라 지금처럼 최대 5분일 수 있습니다.
