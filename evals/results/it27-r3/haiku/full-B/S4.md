# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포된 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 다룬다. 롤백할 배포에 DB 마이그레이션이 포함됐으면 롤백하면 안 되고, DBA 박지은에게 연락해야 한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 상태를 확인하고, 롤백 이력은 #deploy 채널에 남긴다.

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
   확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 근거. 주어진 사실에 확인 방법이 없다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때는 DBA 박지은에게 연락하고, 이후 롤백 절차를 진행하지 않는다.
3. 마이그레이션이 포함되지 않았으면 2단계로 넘어간다.

## 2. 롤백 실행

4. 롤백할 리비전 번호를 `<REVISION>` 자리에 넣고, 다음 명령을 실행한다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

## 3. 롤백 후 확인

5. `/healthz`에 요청을 보내고, 응답 코드가 200인지 확인한다.
   확인 필요: `/healthz`가 200을 반환하지 않을 때의 조치. 주어진 사실에 조치가 없다.
6. 결제 테스트 주문 1건을 실행하고, 주문이 성공하는지 확인한다.

## 4. 이력 기록

7. 롤백 이력을 #deploy 채널에 남긴다.
