Redis를 도입하면 4대 서버가 같은 상품 목록을 함께 읽으므로, 서버마다 다른 가격이 보이는 문제가 없어집니다. 다만 가격을 바꿨을 때 고객에게 바로 반영되는지는 아직 확인되지 않았습니다.

로컬 캐시와 Redis 캐시의 차이는 상품 목록을 어디에 두느냐입니다. 로컬 캐시는 각 API 서버 안의 메모리(서버가 작업할 때 쓰는 임시 공간)에 상품 목록을 둡니다. 서버가 4대이므로 사본도 4개이고, 서버마다 따로 갱신되어 내용이 달라질 수 있습니다. Redis 캐시(Redis, 여러 서버가 함께 쓰는 별도 캐시 서버)는 상품 목록을 서버 바깥의 한 곳에 둡니다. 4대 서버가 같은 사본을 읽습니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 상품 목록 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 사본 수 | 4개 | 1개 |
| 서버 간 내용 차이 | 있음 | 없음 |
| 가격 변경 반영 | 서버마다 최대 5분 늦음 | 갱신 방식에 따라 다름 |
| 캐시 장치 장애 시 영향 | 서버별로 따로 영향 | 4대 서버 모두 영향 |

가격 변경이 고객에게 바로 보이려면 가격을 바꿀 때 Redis에 저장된 상품 목록을 지우는 작업이 함께 있어야 합니다. 이 작업을 넣지 않고 5분 만료 시간만 두면 최대 5분 지연은 그대로 남습니다. 이 작업을 넣을지는 아직 확인되지 않았습니다.

정리하면, Redis 도입으로 좋아지는 점은 서버마다 다른 가격이 보이는 문제가 없어진다는 것입니다. 대신 캐시 서버가 멈추면 4대 서버 모두 영향을 받으므로, 그 대비도 함께 봐야 합니다.
