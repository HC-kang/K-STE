Redis를 도입하면 서버 4대가 같은 상품 목록 캐시를 함께 보게 되어, 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

캐시(자주 쓰는 데이터를 미리 저장해 두고 꺼내 쓰는 방식)는 저장 위치에 따라 두 종류로 나뉩니다. 로컬 캐시는 서버 각자의 메모리에 저장합니다. 지금 우리 서비스가 이 방식이고, 서버 4대가 각자 상품 목록을 5분 동안 저장합니다. Redis 캐시는 별도의 캐시 서버 1대에 저장합니다. 서버 4대가 이 한 곳을 같이 읽고 씁니다.

지금은 서버마다 캐시를 따로 가지고 있어서, 가격을 바꾸면 서버에 따라 새 가격과 옛 가격이 섞여 보일 수 있습니다. 고객에게 반영되기까지 최대 5분이 걸립니다. Redis를 도입하면 서버 4대가 같은 캐시를 보므로 서버에 따라 가격이 다르게 보이는 일이 없어집니다.

가격 변경이 고객에게 반영되는 시간이 얼마나 줄어드는지는 Redis 도입만으로 정해지지 않습니다. 이 시간은 캐시를 얼마 동안 보관하는지, 가격을 바꿀 때 캐시를 바로 갱신하는지에 따라 달라집니다.

Redis는 서버 1대로 도입하므로, 이 서버가 멈추면 API 서버 4대가 모두 영향을 받을 수 있습니다.
