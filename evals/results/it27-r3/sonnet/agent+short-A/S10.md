가장 유력한 원인은 CI와 로컬이 서로 다른 버전의 `@company/ui`를 쓰는 것입니다. 다만 이 내용은 주어진 사실에서 추론한 것이고, 아직 확인하지 않았습니다.

**사실**
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0부터 패키지에 `exports` 필드가 있습니다. `exports`는 패키지가 외부에 공개하는 파일 경로를 직접 정해 두는 설정입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20입니다.

**추론**
- 로컬 `node_modules`에는 아직 1.4.0이 있을 가능성이 큽니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로 그대로 열립니다. 그래서 로컬 빌드가 성공합니다.
- 버전을 올리면서 `package-lock.json`이 바뀌었다면 캐시 키도 바뀝니다. 그러면 CI는 캐시 없이 2.0.0을 새로 설치합니다.
- `exports` 필드가 있으면 그 목록에 없는 경로는 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 경로 형태가 다르면 `Cannot find module '@company/ui/button'`이 납니다.

**미확인**
- 로컬에 설치된 `@company/ui`의 실제 버전.
- CI가 설치한 `@company/ui`의 실제 버전.
- 2.0.0 `exports`의 내용.
- Node 18과 Node 20의 차이가 이 오류에 영향을 주는지. 두 버전 모두 `exports`를 지원하므로 주된 원인으로 보이지는 않습니다.

**확인 순서**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오. 1.4.0이면 위 추론이 맞습니다.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 다시 빌드하십시오. 로컬에서도 같은 오류가 나면 CI 환경 문제가 아니라 2.0.0 자체의 문제입니다.
3. `node_modules/@company/ui/package.json`의 `exports`에서 `./button`이 있는지 확인하십시오.

**해결 방향**
- `exports`에 `./button`이 없으면 `@company/ui` 담당자에게 추가를 요청해야 합니다.
- 2.0.0에서 경로가 바뀌었으면 앱의 import 경로를 `exports`에 선언된 경로로 고쳐야 합니다.

확인 필요: 이 버전 업그레이드가 `package-lock.json` 변경을 포함하는지. 포함하지 않으면 캐시 키가 바뀌지 않아서, 위 추론 중 CI의 설치 경위가 달라집니다.
