# payment-api 운영 배포 롤백 런북

이 문서는 ArgoCD로 payment-api 운영 배포를 롤백하는 절차를 정리한다. 순서대로 진행해야 하며, 1단계에서 조건을 충족하지 않으면 롤백하지 않는다.

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
2. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법과 도구는 원문에 정해져 있지 않다.
3. **마이그레이션이 포함됐으면 롤백하면 안 된다.**
4. 마이그레이션이 포함됐으면 DBA 박지은에게 연락해야 한다.
5. 마이그레이션이 포함되지 않은 경우에만 2단계로 진행한다.

## 2. 롤백 실행

마이그레이션이 포함되지 않았음을 확인한 뒤 아래 명령을 실행한다. `<REVISION>`에는 롤백할 대상 리비전 값을 넣는다.

```
argocd app rollback payment-api <REVISION>
```

확인 필요: `<REVISION>` 값을 찾는 방법은 원문에 없다.

## 3. 롤백 후 확인

1. `/healthz`가 200을 반환하는지 확인한다.
2. 확인 필요: `/healthz`를 호출할 서비스 주소는 원문에 없다.
3. 결제 테스트 주문을 1건 진행하고, 그 주문이 성공하는지 확인한다.
4. 확인 필요: 결제 테스트 주문을 누가, 어느 환경에서 진행하는지는 원문에 없다.
5. #deploy 채널에 롤백 이력을 남긴다.
6. 확인 필요: 이력에 포함할 항목은 원문에 없다.
