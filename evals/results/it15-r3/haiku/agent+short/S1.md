Redis를 도입해도 가격 반영이 자동으로 빨라지지는 않습니다. Redis를 도입하면 4대 서버가 같은 캐시를 함께 보게 되어, 서버마다 상품 정보가 달라지는 문제는 없어집니다.

캐시는 자주 쓰는 데이터를 빠르게 꺼내려고 미리 저장해 둔 사본입니다. 현재는 서버 4대가 각자의 메모리에 캐시를 저장하는 로컬 캐시 방식입니다. Redis(여러 서버가 함께 쓰는 별도 캐시 서버)는 캐시 전용 서버 1대에 캐시를 저장하고, 4대 서버가 이 서버를 함께 씁니다.

| 구분 | 현재: 로컬 캐시 | 도입 후: Redis 캐시 |
|---|---|---|
| 캐시 저장 위치 | 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 상품 정보 | 서버마다 다를 수 있음 | 모든 서버가 같음 |
| 가격 반영 시점 | 최대 5분 뒤 | 캐시를 지우거나 갱신하는 방식에 따라 정해짐 |
| 새로 생기는 부담 | 없음 | Redis 서버 장애에 대비해야 함 |

가격 반영 속도는 캐시를 언제 비우는지에 따라 정해집니다. 캐시를 5분 동안 유지하기만 하면 Redis를 써도 가격 반영은 최대 5분 늦어집니다. 반대로 가격을 바꿀 때 그 상품의 캐시를 지우면, 다음 조회부터 바뀐 가격이 4대 서버 모두에 바로 나갑니다.
