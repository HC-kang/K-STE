Redis를 도입하면 4대 서버가 같은 캐시 한 곳을 보므로, 서버마다 상품 값이 달라지는 문제는 사라집니다.

캐시는 자주 보는 데이터를 미리 복사해 두는 저장소입니다. 지금은 각 API 서버가 자기 메모리(서버가 작업할 때 쓰는 임시 저장 공간)에 상품 목록을 5분 동안 보관합니다. Redis는 여러 서버가 함께 쓰는 캐시 전용 서버입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 같은 상품의 값 | 서버마다 다를 수 있음 | 4대 서버가 같은 값을 봄 |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영됨 | 캐시를 언제 새로 채우는지에 따라 달라짐 |

Redis를 쓰면 가격을 바꾼 뒤 고객이 서버마다 다른 가격을 보는 상황은 막을 수 있습니다. 다만 가격 변경이 바로 반영되는지는 캐시를 언제 비우고 다시 채우는지에 달려 있습니다. 이 기준은 개발팀과 따로 정해야 합니다.

Redis에는 단점도 있습니다. Redis 서버가 멈추면 캐시를 쓰는 4대 서버가 모두 영향을 받습니다.
