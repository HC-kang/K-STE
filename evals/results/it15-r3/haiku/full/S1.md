Redis를 도입하면 서버 4대가 같은 캐시(자주 쓰는 정보를 빨리 꺼내 쓰려고 저장해 두는 공간)를 함께 쓰므로, 서버마다 상품 목록이 달라지는 문제는 없어집니다. 다만 가격을 바꾼 뒤 고객 화면에 최대 5분 늦게 보이는 문제는 Redis 도입만으로 줄지 않습니다.

지금 방식인 로컬 캐시는 각 API 서버 자기 메모리에 상품 목록을 저장합니다. 조회가 가장 빠르지만, 서버 4대가 각자 복사본을 가지고 있어서 서버마다 내용이 다를 수 있습니다. Redis(데이터를 메모리에 두고 빠르게 꺼내 쓰는 별도 저장 서버 프로그램)는 서버 4대 바깥에 있는 한 대에 상품 목록을 두고, 서버 4대가 모두 이 한 곳을 봅니다. 그래서 어느 서버에 요청이 가도 같은 내용을 받습니다. 대신 서버가 매번 네트워크를 거쳐 가져오므로 로컬 메모리보다 조금 느릴 수 있고, Redis 서버가 멈추면 4대 모두 영향을 받습니다.

개발팀에 한 가지를 확인해 주십시오. 가격을 바꿀 때 Redis에 저장된 상품 캐시를 바로 지우는지, 아니면 5분이 지나야 바뀌는지입니다. 이 방식에 따라 고객에게 늦게 보이는 시간이 달라집니다.
