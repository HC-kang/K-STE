# 운영 배포 롤백 런북 (payment-api)

이 문서는 ArgoCD로 배포된 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 DB 마이그레이션 포함 여부를 확인한다. 마이그레이션이 포함됐으면 롤백하지 않고 DBA에게 연락한다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문 결과를 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 1. 대상과 도구

- 배포 도구: ArgoCD
- 대상 애플리케이션: payment-api

## 2. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다.
   - 마이그레이션이 포함됐으면 다음을 수행한다.
     - **롤백하지 않는다.**
     - DBA 박지은에게 연락한다.
   - 마이그레이션이 포함되지 않았으면 3번 단계로 진행한다.

## 3. 롤백 실행

2. 다음 명령으로 payment-api를 롤백한다.

   `argocd app rollback payment-api <REVISION>`

## 4. 롤백 후 확인

3. `/healthz` 응답 코드가 200인지 확인한다.
4. 결제 테스트 주문을 1건 실행하고, 그 주문의 결과가 성공인지 확인한다.

## 5. 이력 기록

5. 롤백 이력을 #deploy 채널에 남긴다.
