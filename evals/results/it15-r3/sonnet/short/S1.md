로컬 캐시는 서버마다 따로 가진 메모장이고, Redis 캐시는 서버 4대가 함께 보는 공용 메모장입니다. Redis를 도입하면 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 가까운 곳에 잠시 저장해 두는 방식입니다. 현재는 API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. Redis(여러 서버가 함께 쓰는 캐시 전용 서버)를 도입하면 4대가 같은 저장소 1대를 봅니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 4대가 같은 내용을 봅니다. |
| 가격 변경 시 | 서버마다 최대 5분 늦게 반영됩니다. | 캐시 한 곳만 고치면 4대에 모두 적용됩니다. |

우리 서비스에서 좋아지는 점은 같은 상품을 보는데 고객마다 가격이 다르게 보이는 상황이 줄어든다는 것입니다. 지금은 서버마다 캐시를 따로 가지고 있어서, 가격을 바꾸면 서버에 따라 새 가격과 옛 가격이 최대 5분 동안 섞여 나옵니다.

다만 Redis를 도입하는 것만으로 반영 지연이 사라지지는 않습니다. 가격을 바꿀 때 Redis의 상품 목록 캐시도 함께 갱신하거나 지워야 모든 서버가 바로 새 가격을 보여줍니다. 이 작업 없이 5분 보관 설정만 그대로 두면 최대 5분 지연은 남습니다.

캐시 서버가 1대이므로, 이 서버가 멈추면 API 서버 4대가 모두 Redis 캐시를 쓸 수 없게 됩니다.

확인 필요: 가격 변경 시 Redis 캐시를 갱신하는 작업이 이번 도입 범위에 들어 있는지 개발팀에 확인해야 합니다.
