원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고, CI만 2.0.0을 설치하기 때문일 가능성이 가장 높습니다. 이것은 추론이고, 아래 확인 단계를 실행하기 전에는 확정할 수 없습니다.

**사실**
- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했습니다.
- 2.0.0은 `exports` 필드(패키지가 외부에 공개하는 경로 목록)를 추가했습니다.
- CI에서만 `Cannot find module '@company/ui/button'` 에러가 납니다.

**추론**
- 로컬 `node_modules`에는 1.4.0이 남아 있습니다. 1.4.0에는 `exports`가 없으므로 `@company/ui/button`이 파일 경로 그대로 열립니다.
- CI는 `package-lock.json` 기준으로 새로 설치하므로 2.0.0을 받습니다. `exports`가 있는 패키지에서는 목록에 없는 경로를 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없으면 같은 import가 에러가 됩니다.
- 로컬 빌드가 성공한 것은 2.0.0 코드를 검증했다는 뜻이 아닙니다. 로컬은 업그레이드 전 상태로 빌드했을 가능성이 있습니다.
- Node 18과 20은 둘 다 `exports`를 지원하므로 Node 버전 차이는 주원인으로 보기 어렵습니다.
- 캐시 키가 `package-lock.json` 해시이므로, 업그레이드 때 lock 파일이 바뀌었다면 오래된 캐시가 원인일 가능성도 낮습니다.

**미확인**
- 업그레이드 커밋에 `package-lock.json` 변경이 포함됐는지 확인하지 않았습니다. 포함되지 않았다면 캐시 판단이 달라집니다.
- 2.0.0의 `exports`에 `./button`이 있는지 확인하지 않았습니다.
- 위 내용은 직접 실행해 검증하지 않았습니다.

**확인 단계**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다. 1.4.0이 나오면 추론이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 봅니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 재설치한 뒤 빌드합니다. 같은 에러가 나면 로컬에서 재현됩니다.

**해결 방향**
- 2.0.0의 `exports`에 `./button`이 없으면, `exports`에 있는 경로로 import를 바꿉니다.
- 공개해야 할 경로가 빠진 것이라면, `@company/ui` 패키지 관리자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.
- 빌드를 먼저 복구해야 하면 `@company/ui`를 1.4.0으로 되돌립니다.
