원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드로 보입니다. 로컬은 2.0.0 이전 설치본을 쓰고 있어서 이 변경을 겪지 않은 것으로 추정합니다.

## 사실

- CI 빌드만 `Error: Cannot find module '@company/ui/button'`로 실패합니다. 로컬 빌드는 성공합니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.

## 추론

`exports` 필드는 패키지가 바깥에 공개하는 경로를 직접 정하는 설정입니다. 이 필드가 있으면 목록에 없는 경로는 import(모듈 불러오기)할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 이름이 달라졌다면 `@company/ui/button`을 찾지 못하는 것이 당연합니다.

로컬이 성공하는 이유는 `node_modules`에 1.4.0 이하 버전이 남아 있기 때문으로 보입니다. 1.4.0에는 `exports`가 없으므로 `@company/ui/button` 파일 경로를 그대로 찾을 수 있습니다.

CI는 `package-lock.json`이 바뀌면서 캐시 키도 바뀌었고, 그래서 2.0.0을 새로 설치했을 것으로 추정합니다.

## 미확인

- 2.0.0의 `exports`에 `./button`이 정의돼 있는지 확인하지 않았습니다.
- 로컬에 설치된 `@company/ui` 버전을 확인하지 않았습니다.
- CI가 설치한 `@company/ui` 버전을 확인하지 않았습니다.
- Node 18과 20의 차이가 원인에 관여하는지 확인하지 않았습니다. 두 버전 모두 `exports`를 지원하므로 주원인일 가능성은 낮다고 봅니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오. 1.4.0이면 추론이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬도 같은 오류로 실패하면 CI와 같은 조건에서 재현된 것입니다.

## 해결 방향

`./button`이 `exports`에서 빠졌다면 import 경로를 2.0.0이 공개한 경로로 바꾸십시오. 2.0.0 마이그레이션 문서나 변경 기록에서 새 경로를 찾을 수 있습니다. 새 경로가 없으면 `@company/ui` 담당 팀에 `./button` 공개를 요청해야 합니다.
