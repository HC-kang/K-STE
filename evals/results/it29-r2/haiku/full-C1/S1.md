Redis를 도입하면 서버 4대가 같은 캐시를 함께 보므로, 지금처럼 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 Redis를 쓴다고 가격이 자동으로 즉시 반영되지는 않습니다. 가격을 바꿀 때 캐시를 지우는 처리를 함께 넣어야 바로 반영됩니다.

캐시는 자주 보는 상품 정보를 매번 DB에서 읽지 않도록 임시로 저장해 두는 곳입니다. 지금과 Redis 방식의 차이는 다음과 같습니다.

| 구분 | 지금 (서버 메모리 캐시) | Redis 도입 후 |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 가격 변경 반영 | 캐시 만료까지 최대 5분 늦음 | 캐시 삭제 처리를 넣으면 변경 직후 반영됨 |

Redis는 별도 서버이므로 API 서버가 네트워크를 통해 Redis에 요청해야 합니다. Redis 서버가 멈추면 캐시를 쓰는 모든 API 서버에 영향이 갑니다.

확인 필요: 이번 도입 범위에 가격 변경 시 캐시 삭제 처리가 포함되는지. 포함되지 않으면 가격 반영 시간은 지금과 같이 최대 5분이 됩니다.
