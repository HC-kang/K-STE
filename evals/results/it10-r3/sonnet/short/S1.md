로컬 캐시는 서버 4대가 각자 자기 메모리에 따로 저장하는 방식이고, Redis 캐시는 4대가 캐시 서버 1대에 함께 저장하는 방식입니다. 캐시는 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 방법입니다.

지금은 로컬 캐시라서 서버마다 상품 목록을 5분 동안 따로 저장합니다. 그래서 서버마다 캐시 내용이 다릅니다. 이 때문에 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. 같은 상품을 보는 고객도 접속한 서버에 따라 다른 가격을 볼 수 있습니다.

Redis를 도입하면 서버 4대가 같은 캐시 서버를 읽습니다. 그래서 고객은 어느 서버에 접속해도 같은 상품 목록을 봅니다. 서버마다 캐시 내용이 달라지는 문제는 사라집니다.

가격 변경이 고객에게 얼마나 빨리 반영되는지는 Redis 도입만으로 정해지지 않습니다. 캐시를 언제 갱신하느냐에 따라 달라집니다. 확인 필요: 가격을 바꿀 때 Redis 캐시를 바로 갱신하는지, 지금처럼 5분 뒤에 만료되게 두는지.

주의할 점도 두 가지 있습니다. Redis 서버가 1대라서 이 서버에 문제가 생기면 API 서버 4대가 모두 영향을 받을 수 있습니다. 또 Redis는 네트워크를 거쳐야 해서 서버 메모리에서 꺼낼 때보다 조회 시간이 길어질 수 있습니다.
