원인은 로컬 `node_modules`가 아직 `@company/ui` 1.4.0이고, CI는 2.0.0을 설치해서 `exports` 필드 제한을 받는 것으로 보입니다. 아래 내용은 모두 추론이고, 로컬 `node_modules`의 실제 버전은 아직 확인하지 않았습니다.

근거는 다음과 같습니다.
- `exports` 필드(패키지가 외부에 공개할 import 경로를 제한하는 `package.json` 설정)가 있으면 목록에 없는 경로는 import할 수 없습니다. 2.0.0에서 이 필드가 추가됐습니다.
- 1.4.0에는 `exports` 필드가 없으므로 `@company/ui/button`이 파일 경로로 그대로 열립니다.
- 로컬 `node_modules`(설치된 패키지 폴더)는 3일 전 업그레이드보다 먼저 설치했습니다. 그래서 로컬은 1.4.0을 쓰고 있을 가능성이 큽니다.
- CI 캐시 키는 `package-lock.json` 해시입니다. 업그레이드로 lock 파일이 바뀌었다면 캐시가 갱신되고 CI는 2.0.0을 새로 설치합니다.
- 2.0.0의 `exports`에 `./button` 경로가 없거나 이름이 달라졌다면 `Cannot find module '@company/ui/button'`이 나는 것과 맞습니다. 2.0.0의 `exports` 내용은 아직 보지 않았습니다.

Node 18과 Node 20은 둘 다 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 주원인으로 보이지 않습니다. 다만 Node 버전을 맞추지 않은 채 검증한 적은 없습니다.

확인은 다음 순서로 하십시오.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인하십시오.
2. 2.0.0의 `package.json`에서 `exports` 항목에 `./button`이 있는지 확인하십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 이때 Node 18을 쓰면 CI와 조건이 같아집니다.
4. 3번에서 CI와 같은 오류가 나면 위 추론이 맞는 것입니다.

고치는 방법은 2번 결과에 따라 달라집니다. `exports`에 다른 경로가 있으면 앱의 import 경로를 그 경로로 바꾸십시오. `./button`에 해당하는 경로가 없으면 `@company/ui` 담당자에게 `exports`에 추가해 달라고 요청하십시오.

확인 필요: 업그레이드한 3일 전부터 CI가 계속 실패했는지 알려 주십시오. 그 답에 따라 lock 파일이 CI에 반영된 시점이 달라질 수 있습니다.
