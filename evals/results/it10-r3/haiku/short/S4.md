이 런북은 payment-api 배포를 롤백하는 절차를 정한다. 롤백은 배포에 DB 마이그레이션(데이터베이스 구조나 데이터를 바꾸는 작업)이 포함되지 않았을 때만 실행한다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
2. **마이그레이션이 포함됐으면 롤백하면 안 된다.** 이 경우 DBA(데이터베이스 관리자) 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 다음 절차로 넘어간다.

## 롤백 실행

ArgoCD(배포를 관리하는 도구)에서 다음 명령으로 payment-api를 롤백한다. `<REVISION>` 자리에는 되돌릴 리비전(배포 이력 번호)을 넣는다.

```
argocd app rollback payment-api <REVISION>
```

## 롤백 후 확인

롤백을 마친 뒤에 다음 두 가지를 확인한다.

1. 상태 점검 경로(`/healthz`)가 200을 반환하는지 확인한다.
2. 결제 테스트 주문을 1건 넣고, 그 주문이 성공하는지 확인한다.

롤백 이력은 #deploy 채널에 남긴다.

확인 필요: 롤백할 리비전 번호를 찾는 방법과 #deploy 채널에 남길 이력의 형식은 원문에 없다.
