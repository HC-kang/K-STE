로컬 캐시는 각 서버가 자기 메모리(작업용 임시 저장 공간)에 상품 목록을 저장하는 방식이고, Redis 캐시는 서버 4대가 함께 쓰는 별도의 캐시 서버(Redis) 1대에 상품 목록을 저장하는 방식입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대 서버가 같은 내용을 봅니다 |
| 가격 변경 반영 | 최대 5분 늦게 반영됩니다 | 반영 방식에 따라 달라집니다 |

Redis를 도입하면 서버마다 캐시 내용이 달라지는 문제가 없어집니다. 서버를 더 늘려도 모든 서버가 같은 캐시를 봅니다.

가격 변경이 바로 반영되는지는 Redis 도입만으로 정해지지 않습니다. 가격을 바꿀 때 Redis에 저장된 상품 정보를 지우거나 새 가격으로 고치는 작업이 있어야 고객에게 바로 반영됩니다. 확인 필요: 이 작업이 이번 도입 계획에 포함되어 있는지 확인해야 합니다.

Redis는 별도 서버이므로 운영 부담이 생깁니다. Redis 서버가 멈추면 캐시를 쓸 수 없으니 장애 대비가 필요합니다.
