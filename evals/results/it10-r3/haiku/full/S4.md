# 운영 배포 롤백 런북

이 런북은 ArgoCD로 운영 배포한 payment-api를 이전 리비전으로 되돌리는 절차를 정한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 마이그레이션이 포함됐으면 **롤백하면 안 되며**, DBA 박지은에게 연락해야 한다.

## 1. 사전 확인

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. DBA 박지은에게 연락하고, 이후 절차를 진행하지 않는다.
3. 마이그레이션이 포함되지 않은 경우에만 2절의 롤백을 진행한다.

## 2. 롤백

1. 되돌아갈 리비전 번호를 확인한다.
2. 다음 명령을 실행한다. `<REVISION>`은 1단계에서 확인한 리비전 번호로 바꾼다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

## 3. 롤백 후 검증

1. `/healthz`가 200을 반환하는지 확인한다.
2. 결제 테스트 주문을 1건 진행하고, 주문이 성공하는지 확인한다.

## 4. 이력 기록

1. 롤백 이력을 #deploy 채널에 남긴다.

## 확인 필요

다음 항목은 원문에 정보가 없어 이 런북에 쓰지 않았다. 채우기 전까지 해당 단계를 수행할 수 없다.

- 롤백 대상 배포에 마이그레이션이 포함됐는지 확인하는 방법과 확인 위치가 없다.
- 되돌아갈 `<REVISION>` 번호를 확인하는 방법이 없다.
- `/healthz`의 호스트 주소와 호출 방법이 없다.
- 결제 테스트 주문을 실행하는 환경, 방법, 담당자가 없다.
- 검증 중 `/healthz`가 200이 아니거나 테스트 주문이 실패할 때의 조치가 없다.
- DBA 박지은에게 연락하는 수단이 없다.
- #deploy 채널에 남길 이력의 항목이 없다.
