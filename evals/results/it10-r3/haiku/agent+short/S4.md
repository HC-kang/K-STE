# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백하기 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 하며, 포함됐으면 롤백하면 안 된다. 롤백한 뒤에는 `/healthz` 응답과 결제 테스트 주문 1건으로 결과를 확인하고, 롤백 이력을 #deploy 채널에 남긴다.

## 사전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인한다. 확인 필요: 마이그레이션 포함 여부를 확인하는 방법(도구, 명령, 확인 위치)이 정해져 있지 않다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이 경우 DBA 박지은에게 연락해야 한다.
3. 롤백할 리비전 번호를 확인한다. 확인 필요: `<REVISION>`에 넣을 값을 찾는 방법이 주어지지 않았다.

## 롤백 실행

4. **경고:** 아래 명령은 운영 환경의 payment-api를 되돌린다. 사전 확인 2번에 해당하면 실행하면 안 된다.
5. 3번 단계에서 확인한 리비전 번호를 넣고 다음 명령을 실행한다.

```
argocd app rollback payment-api <REVISION>
```

## 결과 확인

6. `/healthz`가 200을 반환하는지 확인한다. 확인 필요: 요청을 보낼 주소(호스트와 경로)가 주어지지 않았다.
7. 결제 테스트 주문 1건을 넣고 주문이 성공하는지 확인한다. 확인 필요: 테스트 주문을 넣는 방법과 대상 환경이 주어지지 않았다.

## 기록

8. #deploy 채널에 롤백 이력을 남긴다. 확인 필요: 이력에 포함할 항목(시각, 롤백 전후 리비전, 담당자 등)이 정해져 있지 않다.
