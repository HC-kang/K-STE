두 방식의 차이는 캐시 복사본을 어디에 두느냐입니다. 지금은 서버 4대가 각자 메모리에 상품 목록 복사본을 따로 두고 있어서, 가격을 바꾸면 서버마다 반영되는 시점이 달라집니다. Redis를 도입하면 4대가 같은 복사본을 함께 보므로 가격이 같은 값으로 보입니다.

캐시는 자주 찾는 데이터를 미리 복사해 두고 꺼내 쓰는 임시 저장소입니다. 지금 방식은 로컬 캐시(각 서버 안에 둔 복사본)라서 가장 빠르지만, 서버가 4대이면 복사본도 4개입니다. 각 복사본은 5분마다 따로 갱신되므로 서버마다 값이 다를 수 있습니다. Redis(여러 서버가 함께 쓰는 별도의 캐시 서버)는 복사본이 1개뿐이라 4대가 항상 같은 내용을 봅니다.

Redis 도입으로 좋아지는 점은 다음과 같습니다.

- 서버 4대가 같은 가격을 보여 줍니다. 고객이 어느 서버에 연결되는지에 따라 가격이 다르게 보이는 문제가 없어집니다.
- 캐시를 지우는 작업을 Redis 한 곳에만 하면 됩니다. 서버 4대에 각각 같은 작업을 할 필요가 없습니다.
- API 서버를 재시작해도 Redis의 캐시는 남아 있습니다. 재시작 뒤 서버마다 캐시를 다시 채우는 시간이 줄어듭니다.

다만 Redis를 도입하는 것만으로 가격이 바로 반영되지는 않습니다. Redis에 저장한 상품 목록도 5분 뒤에 지워지도록 두면 지연 5분은 그대로 남고, 4대가 같은 값을 보게 되는 효과만 생깁니다. 가격이 바뀔 때 Redis의 캐시를 지우면 다음 조회부터 새 가격이 나갑니다. 또한 서버가 로컬 메모리 대신 Redis를 거쳐 읽으므로 조회가 조금 느려지고, Redis에 문제가 생기면 상품 목록 조회에도 영향이 생길 수 있습니다.

확인 필요: 이번 도입 범위에 가격 변경 시 Redis 캐시를 지우는 작업이 포함되는지 확인해야 합니다. 포함되면 가격 반영이 즉시에 가까워지고, 포함되지 않으면 Redis 도입 후에도 가격 반영은 최대 5분 늦게 됩니다.
