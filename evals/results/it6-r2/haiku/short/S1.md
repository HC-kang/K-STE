로컬 캐시는 각 API 서버가 자기 메모리에 상품 목록을 임시로 저장해 두는 방식이고, Redis는 서버 4대가 함께 쓰는 별도 저장 서버 1대에 같은 목록을 저장하는 방식입니다. 캐시는 자주 쓰는 데이터를 매번 원본에서 가져오지 않도록 미리 담아 두는 곳입니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 공유 | 공유하지 않음 | 4대가 같은 데이터를 사용 |
| 서버 간 값 차이 | 있음 | 없음 |

Redis를 도입하면 서버마다 가격이 다르게 보이는 문제가 없어집니다. 가격을 바꾸면 4대 서버가 같은 값을 보게 됩니다.

다만 Redis도 몇 가지 점을 고려해야 합니다. 서버가 Redis에서 값을 가져올 때 네트워크를 한 번 거치므로 응답이 로컬 메모리보다 느릴 수 있습니다. Redis 서버가 멈추면 4대 서버 모두 영향을 받습니다.

확인 필요: 고객에게 가격 변경이 보이기까지 걸리는 시간이 지금의 최대 5분에서 얼마나 줄어드는지는 아직 정하지 않았습니다. 가격을 바꿀 때 Redis 값을 바로 갱신하는지, 5분 유효 시간을 그대로 두는지에 따라 달라집니다.
