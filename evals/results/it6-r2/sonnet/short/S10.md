원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰는 것으로 보입니다. 로컬은 1.4.0, CI는 2.0.0일 가능성이 높습니다.

**사실**
- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- `exports` 필드가 있으면 Node는 그 목록에 선언된 경로만 외부에서 import하도록 허용합니다. 선언되지 않은 하위 경로는 파일이 실제로 있어도 `Cannot find module`로 처리합니다.
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것입니다.

**추론**
- 로컬 `node_modules`가 업그레이드 전에 설치됐으므로 로컬에는 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로로 그대로 열립니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 버전을 올리면서 lock 파일이 바뀌었다면 캐시가 갱신되고 CI는 2.0.0을 설치합니다. 2.0.0의 `exports`에 `./button`이 없으면 이 에러가 납니다.
- Node 18과 20은 둘 다 `exports`를 적용합니다. 그래서 Node 버전 차이는 주된 원인이 아닌 것으로 보입니다.

**확인 필요**
- 로컬에 실제로 설치된 `@company/ui` 버전이 1.4.0인지 확인해야 합니다.
- 2.0.0의 `exports`에 `./button`이 선언돼 있는지, 아니면 경로 이름이 바뀌었는지 확인해야 합니다.

**확인 방법**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `rm -rf node_modules && npm ci`로 로컬을 CI와 같은 상태로 만든 뒤 빌드합니다. 같은 에러가 나면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports` 항목에서 `./button`이 있는지 확인합니다.
4. 없다면 2.0.0의 마이그레이션 문서나 changelog에서 바뀐 import 경로를 찾아 코드를 수정합니다.

Node 버전을 맞추는 일은 이 문제와 별개로 해 두는 편이 좋습니다. 로컬과 CI의 차이를 하나 줄일 수 있습니다.
