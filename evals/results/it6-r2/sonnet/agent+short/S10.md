CI 빌드 실패의 원인은 `@company/ui` 2.0.0의 `exports` 필드로 보이고, 로컬은 아직 1.4.0이 설치된 상태라 같은 코드가 통과하는 것으로 보입니다. 아래 내용은 주어진 정황에서 추론한 것이며, 실제 설치 버전은 아직 확인하지 않았습니다.

**근거가 되는 사실**
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0부터 패키지에 `exports` 필드가 있습니다.
- `exports` 필드는 패키지 바깥에서 import할 수 있는 경로를 목록으로 제한합니다. 목록에 없는 경로는 파일이 있어도 import할 수 없습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

**추론**
- 로컬은 `node_modules`를 다시 설치하지 않았으므로 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로로 그대로 찾아집니다.
- 버전을 올리면서 `package-lock.json`이 바뀌었으므로 CI 캐시는 새로 만들어졌을 것입니다. 이 경우 CI는 2.0.0을 설치합니다.
- 2.0.0의 `exports`에 `./button` 경로가 없으면 `Cannot find module '@company/ui/button'`이 발생합니다.

**Node 버전 차이는 원인일 가능성이 낮습니다**
Node 18과 Node 20은 둘 다 `exports` 필드를 지원합니다. 다만 이 부분도 직접 확인하지는 않았습니다.

**확인 순서**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 확인하십시오.
2. 2.0.0 패키지의 `package.json`에서 `exports` 항목에 `./button`이 있는지 확인하십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. CI와 같은 오류가 나면 원인이 확정됩니다.

**확인 후 수정 방향**
- `exports`에 `./button`이 없으면, import 경로를 2.0.0이 공개한 경로로 바꾸거나 `@company/ui` 쪽에서 `./button`을 `exports`에 추가해야 합니다.
- 어느 쪽을 고를지는 2.0.0의 변경 안내(릴리스 노트)에서 경로 변경 의도를 확인한 뒤 정하십시오.

확인 필요: `@company/ui` 2.0.0의 `exports`에 `./button`이 포함되는지, 그리고 이 오류가 나는 파일이 앱 코드인지 다른 패키지인지 확인하지 않았습니다.
