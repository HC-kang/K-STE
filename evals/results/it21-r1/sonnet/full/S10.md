원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰기 때문으로 보입니다. 로컬은 1.4.0, CI(코드를 올릴 때 자동으로 빌드하는 서버 환경)는 2.0.0일 가능성이 큽니다.

로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것이어서 1.4.0이 그대로 남아 있을 수 있습니다. CI 캐시(설치한 패키지를 재사용하려고 저장해 둔 것)의 키는 `package-lock.json`의 해시입니다. 업그레이드로 이 파일이 바뀌었다면 CI는 캐시를 새로 만들고 2.0.0을 설치합니다.

2.0.0에는 `exports` 필드(패키지가 외부에 공개할 경로를 정하는 `package.json` 항목)가 추가됐습니다. `exports`가 있으면 Node는 거기에 적힌 경로만 외부에 공개합니다. 2.0.0의 `exports`에 `./button`이 없다면 `@company/ui/button`을 찾지 못합니다. 1.4.0에는 `exports`가 없어서 같은 경로가 파일 경로로 그대로 풀립니다.

Node 18과 20은 둘 다 `exports` 필드를 지원합니다. 따라서 Node 버전 차이만으로는 이 에러를 설명하기 어렵습니다.

아래 순서로 원인을 가려 보십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 위 추정이 맞습니다.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드하십시오. 로컬에서도 같은 에러가 나면 CI와 원인이 같습니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오. 없으면 import 경로를 `exports`에 있는 경로로 바꾸거나, 패키지에 `./button`을 추가해야 합니다.
