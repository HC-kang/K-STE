Redis를 도입하면 서버 4대가 같은 캐시를 읽기 때문에, 서버마다 상품 목록이 다르게 보이는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 임시로 저장해 두는 곳입니다. 로컬 캐시는 API 서버 각각이 자기 메모리에 캐시를 따로 가지는 방식입니다. 지금 우리 서비스가 이 방식으로 상품 목록을 5분 동안 캐시합니다. 서버 4대가 각자 캐시를 가지고 있어서 서버마다 캐시에 든 내용이 다릅니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 함께 쓰는 캐시 서버 1대에 캐시를 두는 방식입니다. 4대가 같은 캐시를 읽으므로 어느 서버에 접속하든 고객은 같은 상품 목록을 봅니다. 가격을 바꿀 때 Redis에 있는 상품 목록도 함께 갱신하면, 4대 모두 새 가격을 읽을 것으로 보입니다. 이 갱신 방식은 아직 정해진 내용이 아니라 제 추론입니다.
