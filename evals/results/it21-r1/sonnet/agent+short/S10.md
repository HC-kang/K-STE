원인은 로컬이 `@company/ui` 1.4.0을 쓰고 CI가 2.0.0을 쓰기 때문으로 보입니다. 아직 확인한 사실은 아닙니다.

주어진 사실은 다음과 같습니다.
- 2.0.0부터 `@company/ui` 패키지에 `exports` 필드(패키지가 바깥에 공개하는 import 경로 목록)가 있습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.

추론은 다음과 같습니다.
- 로컬 `node_modules`에는 아직 1.4.0이 있어서, 로컬에서는 `@company/ui/button`을 파일 경로로 찾아 성공한 것으로 보입니다.
- 버전을 올리면서 `package-lock.json`이 바뀌었다면, CI 캐시 키도 바뀝니다. 그러면 CI는 2.0.0을 새로 설치합니다.
- 2.0.0의 `exports`에 `./button` 경로가 없으면, Node는 목록에 없는 경로를 막습니다. 이때 `Cannot find module '@company/ui/button'` 오류가 납니다.
- Node 18과 20은 둘 다 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 원인일 가능성이 낮습니다.

아직 확인하지 않은 것은 다음과 같습니다.
- 로컬에 설치된 `@company/ui`의 실제 버전.
- 2.0.0 `package.json`의 `exports`에 `./button`이 있는지.
- 버전을 올린 커밋에 `package-lock.json` 변경이 들어 있는지.

원인을 가리는 순서는 다음과 같습니다.
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에서 `./button`이 있는지 봅니다.
3. 로컬에서 `npm ci`로 `node_modules`를 새로 설치한 뒤 빌드합니다. CI와 같은 오류가 나면 원인이 맞습니다.

3번에서 오류가 재현되면 수정 방법은 둘 중 하나입니다.
- `@company/ui` 쪽 `exports`에 `./button`을 추가합니다.
- 앱 쪽 import를 2.0.0의 `exports`가 공개하는 경로로 바꿉니다.

어느 쪽이 맞는지는 `@company/ui` 2.0.0이 `./button`을 공개하려 했는지에 달려 있습니다. 확인 필요: 2.0.0의 공개 경로 설계 의도는 `@company/ui` 담당자에게 물어야 합니다.
