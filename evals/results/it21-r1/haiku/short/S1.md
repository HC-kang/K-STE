Redis를 도입하면 서버 4대가 같은 캐시를 보기 때문에, 서버마다 가격이 다르게 보이는 문제는 사라집니다. 하지만 가격이 고객에게 5분 늦게 보이는 문제는 Redis 도입만으로 해결되지 않습니다.

캐시는 자주 보는 데이터를 미리 저장해 두고 꺼내 쓰는 임시 저장소입니다. 지금은 각 API 서버(고객 요청을 받아 처리하는 서버)가 자기 메모리(서버 안의 작업 공간)에 상품 목록을 따로 저장합니다. Redis는 4대 서버가 함께 쓰는 별도의 캐시 서버입니다.

| 구분 | 현재 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있음 | 모든 서버가 같은 값을 봄 |
| 조회 방식 | 서버 안에서 바로 꺼냄 | 네트워크로 Redis에 요청해서 꺼냄 |

조회 속도는 Redis가 더 빠르지 않습니다. 로컬 메모리에서 꺼내는 쪽이 보통 더 빠르고, Redis는 서버 사이를 한 번 오가야 하므로 조금 더 걸릴 수 있습니다.

**Redis를 도입해도 가격 반영이 자동으로 즉시 되지는 않습니다.** 가격을 바꾼 뒤 캐시 값이 언제 새 값으로 바뀌는지는 캐시를 지우는 방식에 따라 달라집니다.

확인 필요: 가격을 바꿀 때 Redis의 상품 캐시를 바로 지우는 기능을 이번 도입 범위에 포함하는지 확인이 필요합니다.
