CI에서만 실패하는 가장 가능성 높은 원인은 `@company/ui` 2.0.0의 `exports` 필드 때문에 `@company/ui/button` 경로를 Node가 찾지 못하는 것입니다. 로컬 `node_modules`는 3일 전에 설치한 것이므로 아직 1.4.0일 가능성이 큽니다. 1.4.0에는 `exports` 필드가 없어서 같은 import가 통과했을 것으로 보입니다. 즉 로컬은 1.4.0으로, CI는 2.0.0으로 빌드하고 있을 가능성이 큽니다.

원인 흐름은 다음과 같이 추정합니다.

- 1.4.0은 `exports`가 없어서 패키지 내부 파일을 경로로 직접 import할 수 있습니다. 로컬 빌드는 이 경로로 성공했습니다.
- 2.0.0은 `exports`가 있어서 여기에 명시된 경로만 import할 수 있습니다. `./button`이 `exports`에 없으면 같은 import가 실패합니다.
- CI 캐시 키가 `package-lock.json` 해시이므로, lockfile이 2.0.0으로 바뀌었다면 캐시가 무효화되어 CI는 새로 설치했을 것입니다. 이는 CI가 2.0.0을 받았다는 설명과 맞습니다.

Node 버전 차이는 단독 원인일 가능성이 낮습니다. Node 18과 20 모두 `exports`를 지원하기 때문입니다. 다만 에러 메시지가 `Cannot find module`이라는 점은 확인이 필요합니다. Node가 `exports` 제한으로 실패하면 보통 다른 메시지를 내므로, 이 에러를 어느 도구가 냈는지 CI 로그 전체로 확인해야 합니다.

아직 확인하지 않은 항목이 있으므로 원인을 단정하지 않습니다. 다음 순서로 확인하십시오.

1. CI 빌드 단계에 `npm ls @company/ui`를 추가해서 CI가 실제로 설치한 버전을 확인하십시오.
2. 로컬에서 `npm ls @company/ui`를 실행해 1.4.0인지 확인하십시오.
3. 로컬에서 `rm -rf node_modules && npm ci` 후 빌드하여 실패가 재현되는지 확인하십시오. 재현되면 버전 차이가 원인일 가능성이 매우 높습니다.
4. 2.0.0 패키지의 `package.json`에서 `exports` 필드에 `./button`이 있는지 확인하십시오.
5. Node 18로 로컬 빌드를 해서 Node 버전이 영향을 주는지 확인하십시오.

확인 결과에 따라 조치가 달라집니다. `exports`에 `./button`이 있으면 import 경로를 2.0.0 문서의 경로로 바꾸십시오. 없으면 `@company/ui` 제공자에게 경로 추가를 요청하거나, 그때까지 1.4.0 고정을 검토하십시오.
