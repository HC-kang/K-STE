가장 유력한 원인은 `@company/ui` 2.0.0에 새로 추가된 `exports` 필드입니다. `exports`가 있으면 Node는 패키지가 명시적으로 공개한 경로만 불러올 수 있습니다. 2.0.0이 `./button` 경로를 공개하지 않았다면 `@company/ui/button` import가 실패합니다. 로컬에서는 3일 전에 설치된 1.4.0이 그대로 남아 있어 같은 import가 성공합니다. 다만 2.0.0의 `exports` 내용은 아직 직접 확인하지 않았으므로 이 설명은 추론입니다.

| 항목 | 내용 | 근거 수준 |
|---|---|---|
| 2.0.0의 `exports` 추가 | 2.0.0 릴리스에서 `exports` 필드가 추가되었다 | 확인된 사실 |
| 로컬은 1.4.0 사용 | 3일 전 이전에 설치한 `node_modules`이므로 1.4.0이 남아 있을 가능성이 높다 | 추론 (`npm ls @company/ui`로 검증 필요) |
| CI는 2.0.0 설치 | `package-lock.json`이 바뀌면 캐시 키가 바뀌어 CI가 새로 설치하고, 그 결과 2.0.0을 받는다 | 추론 (커밋된 lock 파일에 2.0.0이 기록됐는지 미확인) |
| Node 18과 20 차이 | `exports` 해석은 Node 18에서도 지원되므로 버전 차이만으로는 설명되지 않는다 | 추론 (가능성 낮음) |

원인을 가르려면 다음 네 가지를 확인하십시오.

1. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이나 `./*` 같은 항목이 있는지 확인하십시오.
2. CI 로그에서 `npm ls @company/ui` 결과나 설치 로그를 확인하여 설치된 버전이 2.0.0인지 확인하십시오.
3. 커밋된 `package-lock.json`에 `@company/ui`의 2.0.0 항목이 있는지 확인하십시오.
4. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 Node 18로 빌드하여 실패가 재현되는지 확인하십시오.

1번과 2번 결과가 나오면 원인을 거의 가릴 수 있습니다. 1번에서 `./button`이 빠져 있다면 import 경로를 2.0.0이 공개한 경로로 바꾸거나, 패키지 측에 해당 경로 공개를 요청하는 방법을 검토하십시오.
