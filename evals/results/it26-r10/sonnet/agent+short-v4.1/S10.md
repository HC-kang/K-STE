원인은 `@company/ui` 2.0.0의 `exports` 필드(패키지가 외부에 공개할 파일 경로를 정하는 설정)에 `./button` 경로가 없기 때문으로 보입니다. 이 내용은 추론이고, 아직 확인하지 않았습니다.

## 사실

- CI(GitHub Actions)에서만 빌드가 실패하고, 로컬 빌드는 성공합니다.
- 에러는 `Error: Cannot find module '@company/ui/button'`입니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시(이전에 설치한 파일을 재사용하는 저장소) 키는 `package-lock.json`(설치할 패키지 버전을 고정한 파일)의 해시입니다.
- 로컬 `node_modules`(설치된 패키지가 저장되는 폴더)는 3일 전보다 먼저 설치한 것입니다.

## 추론

1. 로컬 `node_modules`에는 아직 1.4.0이 있어 보입니다. 1.4.0에는 `exports`가 없으므로 `@company/ui/button`을 파일 경로로 찾을 수 있습니다.
2. 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀌어 CI는 2.0.0을 새로 설치합니다.
3. `exports`가 있는 패키지는 `exports`에 적은 경로만 가져올 수 있습니다. 2.0.0의 `exports`에 `./button`이 없거나 이름이 바뀌었다면 이 에러가 납니다.
4. 이 경우 두 환경의 차이는 `@company/ui` 버전입니다.

Node 18과 20의 차이는 원인으로 보이지 않습니다. 다만 이것도 실행해서 확인한 것은 아닙니다.

## 아직 확인하지 않은 것

- 로컬에 설치된 `@company/ui`의 실제 버전.
- 2.0.0 `package.json`의 `exports`에 들어 있는 경로.
- 업그레이드 커밋에 `package-lock.json` 변경이 포함됐는지.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 에러가 나면 추론 1-4가 맞습니다.
3. 2.0.0의 `package.json`에서 `exports` 필드를 열어 `./button`이 있는지 보십시오.

## 해결 방향

`exports`에 `./button`이 없고 대체 경로가 있으면, 앱의 import 경로를 그 경로로 바꿔야 합니다. 대체 경로가 없으면 `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청해야 합니다. 수정 전까지 빌드를 살리려면 `@company/ui`를 1.4.0으로 되돌릴 수 있습니다.
