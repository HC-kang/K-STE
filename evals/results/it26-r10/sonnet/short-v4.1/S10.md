가장 유력한 원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고, CI는 2.0.0을 설치해서 쓰는 것입니다. 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 경로 목록)에 `./button`이 없으면, `@company/ui/button`을 불러오는 코드는 CI에서만 실패합니다.

## 사실
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.

## 추론
- 1.4.0에는 `exports`가 없어서 패키지 안의 어떤 파일 경로든 불러올 수 있습니다. 로컬은 이 버전이 남아 있어서 `@company/ui/button`이 동작합니다.
- 업그레이드 때 `package-lock.json`이 바뀌었으므로 CI 캐시 키도 바뀌었습니다. 그래서 CI는 캐시 없이 새로 설치했고, 2.0.0을 받았을 것입니다.
- 2.0.0은 `exports`에 적힌 경로만 허용합니다. 여기에 `./button`이 없거나 파일 구조가 바뀌었다면 CI에서 모듈을 찾지 못합니다.
- Node 18과 20은 모두 `exports`를 지원하므로, Node 버전 차이가 주원인일 가능성은 낮습니다.

## 확인 필요
- 로컬에 실제로 어떤 버전이 설치돼 있는지 확인하지 않았습니다.
- 2.0.0의 `exports`에 `./button`이 있는지 확인하지 않았습니다.
- `exports` 때문에 실패하면 Node는 보통 `ERR_PACKAGE_PATH_NOT_EXPORTED`를 냅니다. 이번 에러는 `Cannot find module`이므로, 번들러(소스 파일을 묶는 도구)가 다르게 보고했을 수도 있고 다른 원인이 있을 수도 있습니다.

## 확인 순서
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. 로컬에서도 같은 에러가 나면 원인이 확정됩니다.
4. 3번에서 재현되지 않으면 CI의 Node를 20으로 바꿔 한 번 돌려 봅니다.

## 해결 방향
2.0.0의 `exports`에 `./button`이 없다면, 코드의 import 경로를 `exports`에 있는 경로로 바꾸는 방법이 있습니다. `@company/ui` 담당자에게 `./button` 추가를 요청하는 방법도 있습니다. 어느 쪽이든 로컬 `node_modules`를 새로 설치한 뒤에 빌드를 검증하는 것을 권장합니다.
