가장 유력한 원인은 `@company/ui` 2.0.0에서 추가된 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 제한하는 `package.json` 설정)가 `@company/ui/button` 경로를 공개하지 않는 것입니다. 이는 추론이며, 2.0.0의 `package.json`은 아직 확인하지 않았습니다.

로컬 빌드가 성공하는 이유도 같은 원인으로 설명됩니다. 로컬 `node_modules`(설치된 패키지가 들어 있는 폴더)는 3일 전 업그레이드보다 먼저 설치한 것이므로, 로컬은 아직 1.4.0을 쓰고 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`이 파일 경로로 그대로 읽혔을 것입니다. CI는 새로 설치하므로 2.0.0을 받고, 그 경로가 막혀 모듈을 찾지 못합니다.

다른 차이는 원인일 가능성이 낮습니다.

- Node 버전: Node 18과 20은 모두 `exports` 필드를 지원하므로 버전 차이가 원인일 가능성은 낮습니다.
- CI 캐시: 락 파일(`package-lock.json`)이 바뀌면 캐시 키도 바뀌므로 오래된 캐시가 원인일 가능성은 낮습니다. 다만 락 파일이 실제로 2.0.0을 가리키는지는 확인하지 않았습니다.

확인은 다음 순서로 하십시오.

1. 로컬 `node_modules/@company/ui/package.json`의 `version`을 확인하십시오. 1.4.0이면 로컬 빌드는 업그레이드를 반영하지 않은 결과입니다.
2. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 확인하십시오.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치하고 빌드하십시오. CI와 같은 오류가 나면 원인이 확정됩니다.

2번에서 `./button`이 없으면, `@company/ui`의 `exports`에 해당 경로를 추가하거나 앱의 import 경로를 2.0.0이 공개한 경로로 바꿔야 합니다.
