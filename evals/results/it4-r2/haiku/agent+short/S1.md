로컬 캐시는 서버 4대가 각자 메모리에 상품 목록을 따로 저장하는 방식이고, Redis 캐시는 4대가 함께 쓰는 캐시 서버 1대에 상품 목록을 저장하는 방식입니다. 캐시는 자주 쓰는 데이터를 빨리 꺼내 쓰려고 임시로 저장해 두는 공간을 말합니다.

| 구분 | 로컬 캐시(현재) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 저장 시점이 달라 내용이 다를 수 있습니다 | 4대 서버가 같은 내용을 봅니다 |
| 가격 변경 반영 | 서버마다 5분이 지난 뒤에 반영됩니다 | 캐시 내용을 갱신하면 4대 서버에 같은 시점에 반영됩니다 |
| 서버 재시작 | 저장된 내용이 사라집니다 | 캐시 서버가 살아 있으면 내용이 남아 있습니다 |

Redis를 도입하면 다음과 같이 좋아집니다.

- 4대 서버가 같은 가격을 보게 됩니다.
- 서버를 재시작해도 캐시 내용이 남아 있습니다.
- 서버 4대가 상품 목록을 각자 저장하던 중복이 줄어듭니다.

다만 Redis를 도입하는 것만으로 가격 변경이 즉시 반영되지는 않습니다. 가격을 바꿀 때 Redis에 저장된 상품 정보를 지우거나 새 가격으로 고치는 작업이 함께 있어야 합니다. 이 작업이 이번 도입 범위에 들어 있는지는 아직 확인하지 않았습니다.

또한 Redis 서버가 멈추면 캐시를 읽지 못합니다. 이때 서비스가 어떻게 동작할지는 아직 확인하지 않았습니다. Redis는 네트워크를 거쳐 읽기 때문에 서버 메모리에서 읽는 것보다 느립니다.
