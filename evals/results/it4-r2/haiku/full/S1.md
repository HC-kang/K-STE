Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되어, 서버마다 가격이 다르게 보이는 문제가 없어집니다.

지금은 각 API 서버가 자기 메모리(서버 안에 있는 임시 기억 공간)에 상품 목록을 5분 동안 캐시(자주 쓰는 데이터를 빨리 꺼내려고 임시로 저장해 둔 것)합니다. 서버마다 캐시 시점이 달라서 목록 내용도 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis는 서버 바깥에 따로 두는 공용 캐시 서버입니다. 4대가 모두 여기에서 상품 목록을 읽으므로, 가격을 바꾸면 4대가 같은 값을 보게 됩니다.

다만 Redis가 모든 면에서 나은 것은 아닙니다. 서버 메모리는 같은 서버 안에서 바로 꺼내 쓰지만, Redis는 네트워크를 거쳐 가져오므로 조회 한 건당 조금 느릴 수 있습니다. Redis 서버에 장애가 나면 캐시를 쓰는 4대 모두 영향을 받습니다.

Redis를 도입해도 반영 시점은 캐시 유지 시간에 따라 정해집니다. 가격을 바꿨을 때 캐시를 바로 지우는 작업을 함께 넣어야 반영을 5분보다 빠르게 만들 수 있습니다. 이 작업을 이번 범위에 넣을지는 개발팀과 정해야 합니다.
