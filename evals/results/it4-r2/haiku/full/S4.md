# 운영 배포 롤백 런북 (payment-api)

이 문서는 ArgoCD로 payment-api 운영 배포를 이전 REVISION으로 되돌리는 절차를 정리한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다. 마이그레이션이 포함된 배포는 롤백하지 않고 DBA 박지은에게 연락한다.

## 절차

1. 롤백 대상 배포의 REVISION 값을 확인한다.
2. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 반드시 확인한다.
3. 마이그레이션이 포함됐으면 **롤백하지 않는다.** DBA 박지은에게 연락하고 이 절차를 중단한다.
4. 마이그레이션이 포함되지 않은 경우에만 다음 명령으로 롤백한다: `argocd app rollback payment-api <REVISION>`
5. 롤백 후 `/healthz`가 200을 반환하는지 확인한다.
6. 롤백 후 결제 테스트 주문 1건이 성공하는지 확인한다.
7. 롤백 이력을 #deploy 채널에 남긴다.

## 확인 필요 사항

다음 내용은 제공된 정보에 없어 이 문서에 정하지 않았다.

- REVISION 값을 찾는 방법이 정해지지 않았다.
- 마이그레이션 포함 여부를 확인하는 도구와 위치가 정해지지 않았다.
- `/healthz` 확인 대상 주소가 정해지지 않았다.
- `/healthz`가 200을 반환하지 않을 때 조치가 정해지지 않았다.
- 결제 테스트 주문을 생성하는 방법과 사용할 테스트 계정이 정해지지 않았다.
- 롤백을 중단한 경우에도 #deploy 채널에 이력을 남길지 정해지지 않았다.
