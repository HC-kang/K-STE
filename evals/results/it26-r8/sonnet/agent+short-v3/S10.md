`@company/ui` 2.0.0에 추가된 `exports` 필드가 원인으로 보입니다. CI는 2.0.0을 설치하고 로컬은 1.4.0으로 보이는 예전 `node_modules`를 쓰기 때문에 결과가 다릅니다.

`exports` 필드가 있는 패키지는 이 필드에 적힌 경로만 import할 수 있습니다. 2.0.0의 `exports`에 `./button`이 없으면 `button` 파일이 패키지 안에 있어도 `Cannot find module '@company/ui/button'` 오류가 납니다. 1.4.0에는 `exports` 필드가 없어서 같은 import가 동작했습니다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node | 20 | 18 |
| `@company/ui` 버전 | 1.4.0으로 보입니다. `node_modules`를 3일 전보다 먼저 설치했습니다. | 2.0.0으로 보입니다. 버전을 올리면서 `package-lock.json` 해시가 바뀌어 캐시 키도 바뀌었습니다. |
| 빌드 결과 | 성공 | 실패 |

Node 버전 차이는 원인이 아닌 것으로 보입니다. Node 18과 20은 모두 `exports` 필드를 지원합니다.

아직 확인하지 않은 것이 두 가지 있습니다. 하나는 로컬에 설치된 `@company/ui`의 실제 버전이고, 다른 하나는 2.0.0의 `exports`에 `./button`이 있는지입니다. 아래 순서로 확인하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. 로컬에서 `npm ci`로 `node_modules`를 다시 설치한 뒤 빌드합니다. 로컬 빌드도 실패하면 원인이 확정됩니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 봅니다.

`./button`이 없으면 해결 방법은 두 가지입니다. 앱의 import 경로를 2.0.0의 `exports`에 있는 경로로 바꾸거나, `@company/ui` 쪽에서 `./button`을 `exports`에 추가해야 합니다. 어느 쪽이 맞는지는 2.0.0의 변경 내역을 보고 `@company/ui` 담당자와 정하십시오.
