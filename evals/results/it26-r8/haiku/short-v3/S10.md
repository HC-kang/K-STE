현재 가장 유력한 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개하는 경로 목록)가 `button` 하위 경로를 허용하지 않아서 `@company/ui/button` import가 CI에서 해석되지 않는 것입니다. 이는 추론이며, 아직 확인하지 않았습니다.

### 확인된 사실
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에는 `exports` 필드가 추가되었습니다.
- CI는 Node 18을, 로컬은 Node 20을 사용합니다.
- CI 캐시 키는 `package-lock.json`(설치 버전을 기록한 잠금 파일)의 해시입니다.
- 로컬 `node_modules`는 업그레이드 전에 설치되었습니다.

### 추론
- `exports` 필드가 있으면 Node는 목록에 적힌 경로만 허용합니다. 2.0.0 목록에 `./button`이 없거나 경로가 바뀌었다면 `@company/ui/button` import는 실패합니다.
- 로컬 `node_modules`가 업그레이드 전에 설치되었으므로 1.4.0일 가능성이 높습니다. 그래서 로컬 빌드는 성공하고, 이 성공은 2.0.0에서 해당 경로가 정상이라는 증거가 아닙니다.
- 잠금 파일이 바뀌었다면 캐시 키도 바뀌므로 CI는 새로 설치하면서 2.0.0을 받았을 가능성이 높습니다.
- Node 18과 20의 차이가 원인일 가능성은 낮습니다. Node 18도 `exports`를 지원하기 때문입니다.

### 확인 필요 사항
- 로컬과 CI에 실제로 설치된 `@company/ui` 버전은 아직 확인되지 않았습니다.
- 2.0.0의 `exports` 목록에 `./button`이 있는지, 있다면 어떤 경로인지 확인되지 않았습니다.
- CI 캐시가 실제로 복원되었는지는 확인되지 않았습니다.

### 확인 방법
1. 로컬과 CI에서 `npm ls @company/ui`를 실행하여 실제 설치 버전을 비교합니다.
2. 2.0.0 패키지의 `package.json`에서 `exports` 항목을 열어 `./button` 경로가 있는지 확인합니다.
3. CI 로그에서 캐시 복원 여부와 `npm ci`의 설치 내역을 확인합니다.
4. Node 18로 로컬 빌드를 실행하여, Node 버전이 원인인지 분리해서 확인합니다.

### 권장 조치
- 빠른 복구가 필요하면 `@company/ui`를 1.4.0으로 되돌리는 것을 권장합니다.
- 2.0.0을 유지한다면 앱의 import 경로를 2.0.0 `exports` 목록에 있는 경로로 바꿔야 합니다.
- 2.0.0 maintainer에게 `./button` 경로 추가를 요청할 수 있습니다.
- CI와 로컬의 Node 버전을 같은 버전으로 맞추는 것을 권장합니다.
