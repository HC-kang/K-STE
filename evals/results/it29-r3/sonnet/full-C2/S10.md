가장 유력한 원인은 로컬에는 `@company/ui` 1.4.0이 남아 있고, CI에는 2.0.0이 새로 설치되어 `exports` 필드(패키지가 밖에 공개하는 파일 경로를 정하는 설정)의 제한을 받는 것으로 보입니다. 이는 추론입니다.

- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것이므로 1.4.0일 가능성이 있습니다.
- 1.4.0에는 `exports` 필드가 없어서 `@company/ui/button`을 파일 경로로 바로 찾을 수 있습니다.
- 2.0.0의 `exports`에 `./button`이 정의되어 있지 않으면 `Cannot find module '@company/ui/button'` 오류가 납니다.
- CI 캐시 키는 `package-lock.json`의 해시이므로, 업그레이드 때 이 파일이 바뀌었다면 CI는 새 캐시로 2.0.0을 설치합니다.
- Node 18과 20은 모두 `exports`를 지원하므로 Node 버전 차이는 원인일 가능성이 낮습니다.

다음 순서로 이 추론을 검증하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오.
2. `npm view @company/ui@2.0.0 exports`를 실행해 `./button`이 정의되어 있는지 보십시오.
3. 로컬에서 `rm -rf node_modules && npm ci`로 CI와 같은 방식으로 다시 설치한 뒤 빌드하십시오. 같은 오류로 실패하면 이 추론과 일치합니다.

2번에서 `./button`이 없다면, import 경로를 `exports`에 정의된 경로로 바꾸거나 `@company/ui` 쪽에 `./button` 추가를 요청할 수 있습니다.
