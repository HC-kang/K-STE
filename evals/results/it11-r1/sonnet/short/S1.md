로컬 캐시는 API 서버 4대가 캐시(자주 쓰는 데이터를 미리 저장해 둔 곳)를 각자 따로 갖는 방식이고, Redis 캐시는 4대가 캐시 서버 1대를 함께 쓰는 방식입니다. 이번 도입으로 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

지금은 서버 4대가 상품 목록을 각자 5분 동안 저장합니다. 그래서 가격을 바꾸면 서버마다 새 가격을 반영하는 시점이 다르고, 고객에게는 최대 5분 늦게 반영됩니다. 같은 시점에 어떤 고객은 새 가격을, 다른 고객은 이전 가격을 볼 수 있습니다.

Redis를 도입하면 서버 4대가 같은 캐시를 읽습니다. 그래서 고객의 요청을 어느 서버가 받아도 같은 상품 목록이 나갑니다.

확인 필요: Redis 도입만으로 가격 반영이 5분보다 빨라지는지는 아직 알 수 없습니다. 가격을 바꿀 때 캐시를 바로 갱신하는 방식이 함께 들어가는지에 따라 달라지므로 개발팀에 확인해야 합니다.

캐시 서버가 1대라서, 이 서버가 멈추면 API 서버 4대가 모두 영향을 받을 수 있습니다. 실제 영향 범위는 아직 확인하지 않았습니다.
