가장 유력한 원인은 로컬이 2.0.0으로 빌드된 적이 없다는 점입니다. 아직 실행해서 검증한 것은 아니고, 주어진 사실에서 추론한 결과입니다.

## 추론 근거

로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했습니다. 그래서 로컬에는 `@company/ui` 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드(패키지가 외부에 공개할 경로를 정하는 설정)가 없습니다. 이 경우 `@company/ui/button`은 패키지 안의 파일 경로로 바로 찾아집니다.

2.0.0에는 `exports` 필드가 있습니다. `exports`가 있으면 거기에 적힌 경로만 import할 수 있습니다. `exports`에 `./button`이 없으면 파일이 실제로 있어도 `Cannot find module '@company/ui/button'`이 납니다.

CI는 `package-lock.json`에 적힌 2.0.0을 설치합니다. 그래서 CI에서만 실패합니다.

## 다른 후보

- Node 버전: `exports`는 Node 18에서도 지원합니다. 그래서 Node 18과 20의 차이가 단독 원인일 가능성은 낮아 보입니다. 다만 `exports`의 세부 형식에 따라 두 버전의 동작이 다른지는 확인하지 않았습니다.
- CI 캐시: 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀝니다. 그러면 CI가 옛 캐시를 쓸 가능성은 낮아 보입니다. 업그레이드 커밋에 `package-lock.json` 변경이 들어 있는지는 확인하지 않았습니다.

## 검증 순서

1. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. 로컬에서 같은 오류가 나면 위 추론이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 봅니다.
3. 2번에서 `./button`이 없으면 `@company/ui` 2.0.0이 공개하는 경로를 확인합니다. 2.0.0 변경 내역에 import 경로 변경이 있는지도 함께 봅니다.
4. 앱 코드의 import 경로를 2.0.0이 공개하는 경로로 바꾸거나, 의도한 공개 경로라면 `@company/ui` 쪽 `exports`에 `./button`을 추가해야 합니다.
5. 로컬을 Node 18로 맞춰 빌드해 CI와 같은 조건으로 재현하는 것을 권장합니다.

확인 필요: 앱에서 `@company/ui/button`을 import하는 파일이 몇 개인지, 2.0.0 변경 내역에 import 경로 변경이 적혀 있는지.
