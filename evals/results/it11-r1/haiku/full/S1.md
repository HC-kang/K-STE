로컬 캐시와 Redis 캐시의 차이는 자주 쓰는 데이터의 사본을 어디에 두느냐입니다. 로컬 캐시는 각 API 서버 내부의 임시 저장 공간(메모리)에 상품 목록 사본을 따로 두는 방식입니다. Redis는 서버 바깥에 둔 공용 캐시 저장소(여러 서버가 함께 쓰는 별도 저장 프로그램)에 사본을 한 벌 두고, 서버 4대가 모두 그곳을 보는 방식입니다.

지금은 서버 4대가 각자 사본을 5분씩 들고 있어서 사본마다 내용이 다를 수 있습니다. 가격을 바꾸면 서버마다 사본이 갱신되는 시점이 달라서 고객에게 최대 5분 늦게 반영됩니다.

Redis를 도입하면 4대가 같은 사본을 보게 되므로 서버마다 다른 가격이 보이는 문제는 해소됩니다. 다만 가격이 5분 늦게 반영되는 문제는 Redis 도입만으로 해결되지 않습니다. 가격을 바꿀 때 Redis의 사본을 바로 지우는 방식이면 지연을 줄일 수 있고, 5분 뒤에 사본이 지워지는 방식을 그대로 두면 지연도 그대로 남습니다.

확인 필요: "Redis 도입" 계획에 가격 변경 시 캐시를 바로 비우는 방식이나 만료 시간 변경이 포함되어 있는지 제가 받은 정보로는 알 수 없습니다. 포함되어 있다면 마지막 문단을 그 내용에 맞춰 고쳐야 합니다.
