로컬 캐시에서는 서버 4대가 각자 다른 상품 정보를 가질 수 있지만, Redis를 쓰면 4대가 같은 상품 정보를 봅니다. 다만 Redis를 도입하는 것만으로 가격 변경이 바로 반영되지는 않습니다. 가격을 바꿀 때 Redis에 저장된 상품 정보를 지우는 처리를 함께 넣어야 합니다.

| 구분 | 로컬 캐시(지금 방식) | Redis 캐시(도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 | 서버 바깥에 있는 공용 캐시 서버 1대 |
| 서버 4대가 보는 값 | 서버마다 따로 저장되어 서로 다를 수 있음 | 같은 값을 읽음 |
| 가격 변경 반영 | 서버마다 최대 5분 뒤에 반영됨 | 캐시 삭제 처리를 넣으면 같은 시점에 반영됨 |

Redis를 도입하면 고객이 어느 서버에 연결되든 같은 가격을 보게 됩니다. 이것이 우리 서비스에서 얻는 가장 큰 효과입니다.

Redis에는 단점도 있습니다. Redis는 API 서버와 떨어진 별도 서버라서, API 서버가 상품 정보를 읽을 때 Redis에 요청을 보내는 시간이 메모리 조회보다 더 걸립니다. 또한 Redis 서버가 멈추면 캐시를 쓸 수 없습니다.

확인 필요: Redis 서버가 멈췄을 때 API 서버가 상품 정보를 DB에서 직접 읽을지는 아직 정해지지 않았습니다. 이 부분은 개발팀과 함께 확인해야 합니다.
