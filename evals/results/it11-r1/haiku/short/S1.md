Redis를 도입하면 4대 서버가 같은 캐시를 보게 되므로, 가격을 바꿨을 때 서버마다 값이 달라지는 문제가 없어집니다.

로컬 캐시는 각 서버가 자주 찾는 데이터를 빨리 꺼내려고 자기 메모리에 보관하는 사본입니다. Redis 캐시는 같은 역할을 하지만, 서버 바깥의 별도 캐시 서버 1대에 사본을 두고 4대가 함께 씁니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 사본을 두는 곳 | 각 API 서버의 메모리 | 별도 캐시 서버 1대 |
| 사본을 쓰는 서버 | 서버마다 따로 보유 | 4대가 공유 |
| 가격 변경 반영 | 서버마다 최대 5분 차이 | 4대가 같은 값을 읽음 |

현재는 서버마다 사본이 따로 있어서 가격을 바꿔도 서버별로 반영 시점이 다릅니다. Redis에서는 사본이 하나뿐이므로 서버 사이의 불일치가 생기지 않습니다.

다만 고객에게 반영되기까지 걸리는 시간이 0초가 되는지는 확인 필요: 캐시를 언제 지우거나 갱신하는지에 따라 달라지므로, 이 설계는 개발팀에 확인해야 합니다.

Redis 도입에는 단점도 있습니다. 서버가 메모리에서 바로 읽던 것과 달리 네트워크를 거쳐 읽으므로 조회가 조금 느려질 수 있습니다. 또 캐시 서버가 멈추면 4대 서버 모두 영향을 받으므로, 캐시 서버를 따로 운영하고 점검해야 합니다.
