Redis를 도입해도 가격 변경은 지금처럼 최대 5분 뒤에 고객에게 보입니다. Redis로 바꾸면 4대 서버의 캐시 내용이 같아지지만, 캐시를 유지하는 시간이 5분이면 변경 반영 지연은 그대로 남습니다. 가격을 바꿀 때 캐시를 바로 지우는 작업을 함께 넣어야 즉시 반영됩니다.

로컬 캐시는 각 서버의 메모리(작업 중인 데이터를 잠시 올려 두는 공간)에 상품 목록을 저장합니다. 서버 안에서 바로 꺼내 쓰므로 가장 빠르지만, 서버마다 따로 저장하기 때문에 같은 상품이라도 서버에 따라 다른 값을 보여줄 수 있습니다.

Redis(여러 서버가 함께 쓰는 데이터 저장 프로그램)는 서버 바깥의 공용 저장소에 상품 목록을 둡니다. 4대 서버가 같은 저장소를 조회하므로 어느 서버가 요청을 받아도 같은 값을 받습니다. 다만 서버가 매번 Redis에 요청해야 하므로 메모리에서 바로 꺼내는 것보다 조금 느립니다.

Redis 도입으로 좋아지는 점은 서버 4대가 같은 상품 정보를 보게 된다는 것입니다. 고객이 접속하는 서버에 따라 가격이 다르게 보이는 문제도 없어집니다. 캐시를 지울 때도 Redis 한 곳만 지우면 되므로 서버 4대에 각각 지시할 필요가 없습니다.

나빠지는 점도 있습니다. 요청마다 Redis를 거쳐야 하므로 응답이 조금 느려질 수 있습니다. Redis 서버가 멈추면 캐시를 쓰는 기능 전체에 영향이 갈 수 있으므로, Redis를 이중으로 구성할지 검토가 필요합니다.

확인 필요: 가격 변경을 고객에게 즉시 반영해야 하는지 정해야 합니다. 즉시 반영이 필요하면 가격 변경 시 Redis 캐시를 지우는 작업을 이번 도입 범위에 포함해야 합니다.
