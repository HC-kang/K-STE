로컬 캐시는 서버마다 자기 메모리(컴퓨터가 작업 중에 쓰는 임시 저장 공간)에 상품 목록을 따로 보관하는 방식입니다. Redis는 캐시만 전담하는 별도의 서버 프로그램이며, API 서버 4대가 이 서버 한 대에 상품 목록을 함께 저장하고 가져다 씁니다.

지금은 서버 4대가 각자 캐시를 가지고 있어서, 가격을 바꾸면 서버마다 새 가격을 불러오는 시점이 달라집니다. 캐시 유효 시간이 5분이라서 모든 서버가 새 가격을 보기까지 최대 5분이 걸리고, 고객에게도 그만큼 늦게 보입니다.

Redis로 바꾸면 4대가 같은 캐시를 보므로 서버마다 내용이 달라지는 문제는 없어집니다. 다만 Redis를 도입하는 것만으로 5분 지연이 자동으로 사라지지는 않습니다. 가격을 바꿀 때 Redis의 상품 캐시를 지우거나 새 가격으로 갱신하는 작업을 함께 넣어야 반영 시점을 가격 변경 시점에 맞출 수 있습니다. 또 Redis는 서버 바깥에 있어서 요청마다 네트워크를 한 번 거치므로, 서버 메모리에서 바로 읽는 것보다 느릴 수 있습니다. Redis가 멈췄을 때의 대응 방식은 아직 확인하지 않았습니다.

가격 변경이 즉시 반영되어야 하는지, 그렇다면 캐시 갱신 작업을 이번 도입 범위에 넣을지를 개발팀과 먼저 확인하십시오.
