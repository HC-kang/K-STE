가장 유력한 원인은 로컬이 아직 `@company/ui` 1.4.0을 쓰고 있고, CI만 2.0.0을 설치해서 `@company/ui/button` 경로가 막힌 것입니다. 이 결론은 주어진 정보에서 나온 추론이며, 아래 확인 방법으로 검증해야 합니다.

## 사실

- CI 빌드에서만 `Cannot find module '@company/ui/button'` 에러가 납니다.
- `@company/ui`를 3일 전에 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0부터 패키지에 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 제한하는 설정)가 있습니다.
- CI는 Node 18, 로컬은 Node 20입니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다.

## 추론

- 업그레이드로 `package-lock.json`이 바뀌었으므로 캐시 키도 바뀌었습니다. 그래서 CI는 캐시를 쓰지 않고 2.0.0을 새로 설치했을 가능성이 큽니다.
- 로컬 `node_modules`는 업그레이드 전에 설치했으므로 아직 1.4.0일 가능성이 큽니다.
- 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 실제 파일 경로로 바로 열립니다. 2.0.0에서는 `exports`에 `./button`이 없으면 그 경로를 열 수 없습니다.
- Node 18과 20은 둘 다 `exports`를 지원합니다. 그래서 Node 버전 차이는 주원인일 가능성이 낮습니다.

## 확인하지 못한 것

- 로컬에 설치된 `@company/ui`의 실제 버전.
- 2.0.0의 `exports`에 `./button`이 있는지 여부.
- 업그레이드 커밋에 갱신된 `package-lock.json`이 포함됐는지 여부.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드를 열어 `./button` 항목이 있는지 봅니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드합니다. 같은 에러가 나면 원인이 확정됩니다.

## 해결 방향

- 2.0.0의 `exports`에 `./button`이 없으면, 앱의 import 경로를 2.0.0이 공개한 경로로 바꿔야 합니다. 새 경로는 2.0.0 릴리스 노트나 `exports` 필드에서 확인해야 합니다.
- 2.0.0이 `./button`을 공개해야 하는 것이라면, `@company/ui` 쪽에서 `exports`에 추가해야 합니다.
- 재발을 막으려면 로컬에서도 의존성을 바꾼 뒤 `npm ci`로 설치하는 것을 권장합니다.
