CI는 `@company/ui` 2.0.0으로 빌드하고 로컬은 1.4.0으로 빌드하기 때문에 결과가 다르며, 2.0.0의 `exports` 필드에 `@company/ui/button` 경로가 없는 것이 원인일 가능성이 가장 높습니다. 아래 내용은 모두 주어진 정보에서 추론한 것이고, 설치된 버전과 `exports` 내용은 아직 직접 확인하지 않았습니다.

## 추론 근거

`exports` 필드는 패키지가 바깥에 열어 둘 import 경로를 제한하는 package.json 설정입니다. 1.4.0에는 이 필드가 없어서 `@company/ui/button`처럼 패키지 내부 파일 경로로 직접 import할 수 있었습니다. 2.0.0에서는 `exports`에 적힌 경로만 import할 수 있으므로, `./button`이 적혀 있지 않으면 `Cannot find module` 에러가 납니다.

로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것이므로 1.4.0이 그대로 남아 있을 가능성이 높습니다. CI는 `package-lock.json` 해시로 캐시 키를 만들기 때문에, 업그레이드로 lock 파일이 바뀐 뒤에는 2.0.0을 새로 설치합니다. 그래서 로컬에서는 에러가 나지 않고 CI에서만 납니다.

Node 18과 20은 둘 다 `exports`를 지원하므로 Node 버전 차이는 원인일 가능성이 낮습니다. 다만 Node 18에서 직접 재현해 보지는 않았습니다.

## 확인 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 봅니다.
2. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드해, CI와 같은 에러가 나는지 봅니다.
3. 2.0.0이 설치된 `node_modules/@company/ui/package.json`을 열어 `exports`에 `./button`이 있는지 봅니다.

2번에서 같은 에러가 나고 3번에서 `./button`이 없으면 원인이 확정됩니다.

## 해결 방법

해결 방법은 세 가지입니다. 어느 쪽이 맞는지는 2.0.0이 `button`을 어떤 경로로 내보내는지에 달려 있으며, 이 부분은 미확인입니다.

- 앱의 import 경로를 2.0.0의 `exports`에 있는 경로로 바꿉니다.
- `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.
- 위 두 가지가 끝날 때까지 `@company/ui`를 1.4.0으로 되돌려 둘 수 있습니다.

확인 필요: 2.0.0 릴리스 노트에 `exports` 추가와 import 경로 변경이 안내되어 있는지 알려 주세요.
