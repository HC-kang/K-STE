# 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포하는 payment-api의 운영 배포를 롤백하는 절차를 설명한다. 롤백 담당자는 마이그레이션 확인, 롤백 실행, 롤백 후 검증, 이력 기록 순서로 진행해야 한다.

## 1. 마이그레이션 포함 여부 확인

롤백 담당자는 롤백 전에 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
**마이그레이션이 포함됐으면 롤백 담당자는 롤백하면 안 된다.**
이 경우 롤백 담당자는 DBA 박지은에게 연락해야 한다.

## 2. 롤백 실행

마이그레이션이 포함되지 않은 경우에만 롤백 담당자는 다음 명령을 실행한다.

```bash
argocd app rollback payment-api <REVISION>
```

`<REVISION>`에는 롤백 대상 리비전을 넣는다.

## 3. 롤백 후 검증

롤백 후 롤백 담당자는 다음 두 가지를 확인해야 한다.
롤백 담당자는 `/healthz`가 200을 반환하는지 확인한다.
롤백 담당자는 결제 테스트 주문 1건이 성공하는지 확인한다.

롤백 이력은 #deploy 채널에 남긴다.

## 확인 필요 사항

- 확인 필요: 마이그레이션 포함 여부를 확인하는 방법을 정해야 한다.
- 확인 필요: `/healthz`를 호출하는 주소를 정해야 한다.
- 확인 필요: 결제 테스트 주문을 만드는 방법을 정해야 한다.
- 확인 필요: #deploy 채널에 남길 이력 항목을 정해야 한다.
