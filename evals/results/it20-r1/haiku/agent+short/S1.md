Redis를 도입하면 서버 4대가 같은 상품 목록을 보게 되지만, 가격 반영이 자동으로 빨라지지는 않습니다.

캐시(자주 쓰는 데이터를 빨리 꺼내 쓰려고 미리 저장해 두는 공간)는 지금 API 서버(고객 요청에 응답하는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장하는 방식입니다. 이것을 로컬 캐시라고 합니다. 서버마다 저장된 시점이 달라서, 가격을 바꾸면 서버에 따라 최대 5분 늦게 고객에게 보입니다.

Redis는 서버 밖에 있는 캐시 서버 한 대에 상품 목록을 저장하고, 서버 4대가 모두 이 한 곳을 봅니다. 그래서 서버마다 내용이 달라지는 문제가 없어집니다.

| 항목 | 로컬 캐시 (지금) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대 각각의 메모리 | 캐시 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있음 | 4대가 같은 값을 봄 |
| 조회 방식 | 서버 메모리에서 바로 읽음 | 네트워크로 캐시 서버에 요청한 뒤 읽음 |
| 가격 반영 지연 | 최대 5분 | 보관 시간을 5분으로 두면 최대 5분 |

보관 시간을 5분 그대로 두면 Redis를 도입해도 가격 반영 지연은 최대 5분으로 남습니다. 가격 반영을 빨리 하려면 가격을 바꿀 때 캐시를 지우는 작업을 함께 만들어야 합니다. 이 부분은 제 추론입니다. 현재 설계에 가격 변경 때 캐시를 지우는 작업이 있는지는 확인하지 않았습니다.
