로컬은 `@company/ui` 1.4.0을 쓰고 CI는 2.0.0을 쓰기 때문에 빌드 결과가 다른 것으로 보입니다. 아직 두 환경의 설치 버전을 직접 확인하지 않았으므로 이 결론은 추론입니다.

## 추정 원인

2.0.0에서 패키지에 `exports` 필드(패키지가 외부에 공개하는 import 경로를 정하는 `package.json` 항목)가 추가됐습니다. `exports`가 있으면 Node는 그 목록에 없는 경로를 불러오지 못합니다. 2.0.0의 `exports`에 `./button`이 없다면 `@company/ui/button`을 import하는 코드는 `Cannot find module '@company/ui/button'` 오류를 냅니다. 1.4.0에는 `exports`가 없어서 같은 import가 동작했을 것입니다.

로컬 `node_modules`는 3일 전보다 먼저 설치한 것입니다. 그래서 로컬에는 1.4.0이 남아 있을 가능성이 큽니다. CI는 `package-lock.json`을 기준으로 새로 설치하므로 2.0.0을 받았을 것입니다.

## 가능성이 낮은 요인

| 요인 | 낮게 보는 이유 |
|---|---|
| Node 18과 Node 20의 차이 | 두 버전 모두 `exports`를 지원합니다. 다만 두 버전에서 실제로 실행해 보지는 않았습니다. |
| CI 캐시 | 캐시 키가 `package-lock.json`의 해시입니다. 버전을 올릴 때 lock 파일이 바뀌었다면 캐시도 새로 만들어집니다. |

## 확인 방법

1. 로컬과 CI 양쪽에서 설치된 `@company/ui` 버전을 확인하십시오. 로컬이 1.4.0이고 CI가 2.0.0이면 추정이 맞습니다.
2. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `node_modules`를 지우고 lock 파일 기준으로 다시 설치한 뒤 빌드하십시오. 이때 CI와 같은 오류가 나면 원인이 확정됩니다.

## 해결 방향

`exports`에 `./button`이 없으면 두 가지 방법이 있습니다. 하나는 2.0.0이 공개하는 경로로 import를 바꾸는 것입니다. 다른 하나는 `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청하는 것입니다. 2.0.0이 일부러 경로를 비공개로 바꿨다면 import 변경이 맞습니다. 이 의도는 변경 이력에서 확인해야 합니다.

확인 필요: "3일 전에 올렸다"는 `package.json`과 `package-lock.json`을 모두 커밋했다는 뜻인지, `package.json`만 커밋했다는 뜻인지 알 수 없습니다. lock 파일을 커밋하지 않았다면 CI가 2.0.0을 받는 경위와 캐시 상태 판단이 달라집니다.
