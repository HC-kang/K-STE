Redis를 도입하면 API 서버 4대가 같은 상품 목록을 보게 되어, 서버마다 내용이 달라서 생기는 문제가 사라집니다.

캐시는 자주 쓰는 데이터를 빠르게 꺼내 쓰려고 미리 저장해 두는 곳입니다. 로컬 캐시와 Redis 캐시는 이 저장 장소가 다릅니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 서버 4대가 각자 자기 메모리에 저장합니다. | 별도의 캐시 서버 1대에 저장합니다. |
| 공유 여부 | 서버끼리 캐시를 공유하지 않습니다. | 서버 4대가 캐시를 같이 씁니다. |
| 서버 간 내용 | 서버마다 내용이 다를 수 있습니다. | 모든 서버가 같은 내용을 봅니다. |

지금은 서버마다 상품 목록을 5분 동안 따로 저장합니다. 그래서 가격을 바꾸면 고객에게 최대 5분 늦게 반영되고, 고객이 접속한 서버에 따라 다른 가격을 볼 수도 있습니다.

Redis에서는 상품 목록이 한 곳에만 있습니다. 그래서 가격을 바꿀 때 그 한 곳만 고치면 서버 4대가 모두 같은 가격을 보여 줄 수 있습니다.

다만 두 가지는 아직 확인하지 못했습니다. 첫째, 가격을 바꿀 때 Redis의 상품 목록을 바로 고치도록 만들지는 정해진 내용을 받지 못했습니다. 그래서 최대 5분 지연이 얼마나 줄어드는지는 말씀드릴 수 없습니다. 둘째, Redis 서버가 1대이므로 이 서버가 멈추면 서버 4대 모두 Redis 캐시를 쓸 수 없다고 추론합니다. 이때 서비스가 어떻게 동작할지는 개발팀에 확인해야 합니다.
