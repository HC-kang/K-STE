가장 가능성이 높은 원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰는 것입니다. 로컬은 1.4.0, CI는 2.0.0을 쓰는 것으로 추정합니다. 아래 내용은 전달받은 정보로 추론한 것이며, 직접 실행해서 확인한 것은 없습니다.

**추론 근거**

로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치했으므로, 로컬에는 1.4.0이 남아 있을 가능성이 큽니다. CI는 `package-lock.json`대로 새로 설치하므로 2.0.0을 받습니다.

2.0.0에서 추가된 `exports` 필드는 패키지가 외부에 공개하는 import 경로의 목록입니다. 이 필드가 있으면 목록에 없는 경로는 import할 수 없습니다. 1.4.0에는 이 필드가 없어서 `@company/ui/button`이 파일 경로로 바로 열렸습니다. 2.0.0의 `exports`에 `./button`이 없거나 경로가 달라졌다면 `Cannot find module` 에러가 납니다.

**원인에서 제외한 항목**

- Node 버전: Node 18과 20 모두 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 원인으로 보기 어렵습니다.
- CI 캐시: 캐시 키가 `package-lock.json`의 해시입니다. 업그레이드 때 lockfile이 바뀌었다면 캐시도 새로 만들어졌으므로 오래된 캐시는 원인이 아닌 것으로 보입니다.

**아직 확인하지 않은 사항**

- 로컬에 설치된 `@company/ui`의 실제 버전
- `package-lock.json`과 CI 로그에 기록된 설치 버전
- 2.0.0 `package.json`의 `exports`에 `./button`이 있는지

**확인 순서**

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다.
2. `package-lock.json`과 CI 설치 로그에서 `@company/ui`가 2.0.0인지 봅니다.
3. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 봅니다.
4. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 에러가 나면 원인이 확정됩니다.

**수정 방향**

`exports`에 `./button`이 없다면 방법은 두 가지입니다. `@company/ui` 쪽에서 `./button`을 `exports`에 추가하거나, 앱 쪽에서 import 경로를 2.0.0이 공개한 경로로 바꿉니다. 어느 쪽으로 할지는 `@company/ui` 소유자와 정해야 합니다.
