가장 유력한 원인은 `@company/ui` 2.0.0의 `exports` 필드가 `./button` 경로를 노출하지 않아서, 1.4.0에서 되던 `@company/ui/button` import가 2.0.0에서는 해석되지 않는 것입니다. 이는 추론이며, 아직 패키지의 `exports` 값을 직접 확인하지 않았습니다.

로컬과 CI가 서로 다른 버전을 쓰고 있을 가능성이 큽니다. 로컬 `node_modules`는 3일 전보다 먼저 설치됐으므로 1.4.0이 그대로 남아 있을 가능성이 높고, 그래서 로컬 빌드가 성공합니다. CI는 `package-lock.json`의 해시를 캐시 키로 쓰므로, lock 파일이 2.0.0으로 갱신됐다면 캐시가 새로 만들어지고 2.0.0이 설치됩니다. 그 결과 CI에서만 같은 import가 실패합니다.

Node 18과 Node 20의 차이는 원인으로 볼 근거가 아직 없습니다. 배제하지 않은 변수로 남겨 둡니다.

확인 필요: 이번 변경에서 `package-lock.json`이 2.0.0으로 갱신됐는지. 갱신되지 않았다면 CI도 1.4.0을 설치하므로 이 가설은 맞지 않습니다.

확인 필요: CI 로그나 `npm ls @company/ui` 결과로 CI에 실제로 설치된 버전. 아직 이 값을 확인하지 않았습니다.

다음 순서로 확인하십시오.

1. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드하여, 2.0.0에서도 같은 에러가 나는지 확인하십시오.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button` 경로가 있는지 확인하십시오.
3. `./button` 경로가 없다면 import 경로를 2.0.0의 `exports`에 맞게 바꿀지, 패키지 담당자에게 경로 노출을 요청할지 팀에서 정하십시오.
