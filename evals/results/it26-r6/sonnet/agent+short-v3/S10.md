로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰고 있을 가능성이 가장 높습니다. 로컬은 1.4.0이고 CI는 2.0.0으로 보이며, 이 추정은 아직 확인하지 않았습니다.

**사실**
- CI에서만 `Error: Cannot find module '@company/ui/button'`이 나고, 로컬 빌드는 성공합니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0 패키지에는 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20입니다.

**추론**
- `exports` 필드는 패키지가 외부에 공개하는 import 경로를 `package.json`에서 제한하는 설정입니다. 이 필드가 있으면 목록에 없는 경로는 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 경로 이름이 바뀌었다면 이 에러가 납니다.
- 로컬 `node_modules`는 업그레이드 전에 설치했으므로 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`이 파일 경로로 그대로 열립니다.
- 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀌어 CI가 캐시 없이 새로 설치합니다. 그래서 CI는 2.0.0을 받았을 것으로 보입니다.
- Node 버전 차이는 원인일 가능성이 낮아 보입니다. Node 18과 20 모두 `exports`를 지원합니다.

**확인 방법**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오. 1.4.0이면 위 추정이 맞습니다.
2. `node_modules/@company/ui/package.json`의 `exports` 필드에 `./button`이 있는지 보십시오. 로컬이 1.4.0이면 `npm ci`로 다시 설치한 뒤에 보십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`를 실행한 뒤 빌드하십시오. 이때 Node 18을 쓰면 CI와 같은 조건이 됩니다. 이 방법으로 로컬에서 같은 에러를 재현할 수 있습니다.

**수정 방향**
- 2.0.0의 `exports`에 `./button`이 없지만 다른 이름의 경로가 있으면, 앱의 import 경로를 그 이름으로 바꿔야 합니다.
- 어떤 경로도 공개되지 않았다면 `@company/ui` 담당자에게 `exports`에 해당 경로를 추가해 달라고 요청해야 합니다.
- 어느 쪽이 맞는지는 확인 방법 2의 결과로 정해집니다.
