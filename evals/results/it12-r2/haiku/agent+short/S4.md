이 런북은 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 롤백하는 절차를 정리한다.

## 1. 롤백 전 확인

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 반드시 확인해야 한다.
2. 확인 방법은 원문에 없으므로 확인 필요: 마이그레이션 포함 여부를 확인하는 구체적인 방법과 담당자.
3. 마이그레이션이 포함됐으면 롤백하면 안 된다.
4. 마이그레이션이 포함됐으면 DBA 박지은에게 연락해야 한다.

## 2. 롤백 실행

1. 마이그레이션이 포함되지 않았음을 확인한 경우에만 롤백을 진행한다.
2. 롤백할 이전 리비전 번호를 확인한다. 확인 방법은 원문에 없으므로 확인 필요: 리비전 번호를 찾는 방법.
3. 다음 명령을 실행한다. `<REVISION>`은 2번에서 확인한 리비전 번호로 바꾼다.

   `argocd app rollback payment-api <REVISION>`

## 3. 롤백 후 검증

1. `/healthz`가 200을 반환하는지 확인한다. 엔드포인트 주소는 원문에 없으므로 확인 필요: payment-api `/healthz`의 접속 주소.
2. 결제 테스트 주문 1건이 성공하는지 확인한다. 테스트 주문 방법은 원문에 없으므로 확인 필요: 테스트 주문 절차와 테스트 결제 환경.
