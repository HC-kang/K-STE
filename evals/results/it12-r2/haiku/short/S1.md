Redis를 도입하면 4대 서버가 같은 상품 목록을 보게 되므로, 서버마다 내용이 달라지는 문제는 없어집니다. 가격 변경이 고객에게 반영되는 시간이 줄어들지는 캐시를 언제 비우는지에 따라 달라지므로 확인이 필요합니다.

캐시는 자주 쓰는 데이터를 원본에서 매번 가져오지 않도록 미리 복사해 두는 임시 저장 공간입니다. 지금은 각 API 서버가 자기 메모리(서버가 작업할 때 쓰는 내부 저장 공간)에 상품 목록을 따로 저장합니다. Redis(레디스)는 서버 밖에 따로 두는 캐시 전용 서버이며, 4대의 API 서버가 이 한 곳을 함께 씁니다.

| 구분 | 현재: 서버 메모리 캐시 | 도입 후: Redis 캐시 |
|---|---|---|
| 저장 위치 | 서버 4대 각각 | 캐시 서버 1대 |
| 서버 간 데이터 | 서버마다 내용이 다름 | 모든 서버가 같은 데이터를 봄 |
| 읽기 속도 | 가장 빠름 | 서버 메모리보다 약간 느림 (네트워크를 거쳐 가져오기 때문) |
| 가격 변경 반영 | 서버마다 최대 5분 지연 | 캐시 갱신 방식에 따라 결정 (확인 필요) |

Redis 도입으로 확실히 얻는 효과는 서버 간 데이터 일치입니다. 반면 캐시 서버 1대가 멈추면 모든 서버의 캐시 조회에 영향을 주므로, 이 서버의 안정성도 함께 챙겨야 합니다.
