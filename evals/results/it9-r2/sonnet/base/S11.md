# API 키 관리 지침

## 1. 적용 범위

이 지침은 운영 환경과 개발 환경의 API 키 관리에 적용한다.

## 2. 규칙 수준 표기

| 표현 | 의미 |
|---|---|
| **필수** | 예외 없이 지켜야 한다. |
| **금지** | 어떤 경우에도 해서는 안 된다. |
| **권장** | 지키는 것이 좋으나, 지키지 않아도 위반은 아니다. |
| **허용** | 해도 된다. |

## 3. 운영 환경 API 키

### 3.1 교체 주기 (필수)
- 운영 환경 API 키는 **90일마다 교체해야 한다**.
- 이 규칙에는 예외가 없다.

### 3.2 교체 시간대
- **권장**: 평일 업무 시간(10:00-18:00)에 교체한다.
- **허용**: 장애 대응 중이면 업무 시간 밖에 교체해도 된다.

### 3.3 교체한 키의 저장 (필수)
- 교체한 키는 Vault의 `prod/api-keys` 경로에 저장해야 한다.

## 4. 개발 환경 API 키

- 개발 환경 API 키는 90일 교체 규칙의 적용 대상이 아니다. 90일마다 교체하지 않아도 된다.
- 단, 5장의 Git 커밋 금지는 개발 환경 키에도 동일하게 적용된다.

## 5. 저장소 관리 (금지)

- API 키를 Git 저장소에 커밋하는 것은 **금지**한다.

## 6. 참고: Vault

- Vault 웹 화면에는 키를 직접 발급하는 기능이 있다.

---

작성 시 확인할 점 두 가지입니다.

1. **4장의 "단, 5장 …개발 환경 키에도 동일하게 적용된다"**: 원문에는 "Git 커밋 금지"의 적용 범위가 따로 없어서, 환경 구분 없이 적용되는 것으로 읽어 명시했습니다. 개발 환경 키는 커밋해도 된다는 의도라면 이 문장을 빼야 합니다.
2. **6장 Vault 웹 화면 발급 기능**: 원문이 기능의 존재만 서술하고 있어서 사용 허용·권장·금지 중 어느 쪽으로도 쓰지 않고 사실로만 적었습니다. 사용 방침(예: 운영 키 발급은 이 화면에서만 한다)을 정하려면 알려주세요.
