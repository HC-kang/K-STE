원인은 로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있고 CI는 2.0.0을 설치하기 때문으로 보입니다. 이 내용은 추론이며 아직 검증하지 않았습니다.

`exports` 필드는 패키지가 외부에 공개하는 경로 목록입니다. 1.4.0에는 이 목록이 없어서 `@company/ui/button`이 파일 경로로 바로 열립니다. 2.0.0에는 목록이 생겼고, 목록에 `./button`이 없으면 Node는 `Cannot find module '@company/ui/button'` 오류를 냅니다. 2.0.0의 `exports`에 `./button`이 있는지는 아직 보지 않았습니다.

| 항목 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `@company/ui` 버전 | 1.4.0으로 추정 | 2.0.0으로 추정 |
| `exports` 필드 | 없음 | 있음 |

Node 버전 차이는 원인일 가능성이 낮습니다. `exports` 필드는 Node 12.7 이후 버전이 지원하므로 Node 18과 20은 모두 지원합니다.

캐시도 원인일 가능성이 낮습니다. 캐시 키가 `package-lock.json` 해시이므로, lock 파일에 2.0.0이 반영돼 있으면 3일 전에 캐시가 새로 만들어졌습니다. lock 파일에 2.0.0이 반영됐는지는 아직 보지 않았습니다.

다음 순서로 검증하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 봅니다. 1.4.0이면 로컬이 낡은 상태입니다.
2. `package-lock.json`에 `@company/ui`가 2.0.0으로 적혀 있는지 봅니다.
3. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 봅니다.
4. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 오류가 나면 원인이 맞습니다.

3번에서 `./button`이 없으면, 2.0.0이 공개하는 경로로 import를 바꿔야 합니다. 2.0.0에서 `button`을 공개하지 않는 것이 의도인지 누락인지는 `@company/ui` 담당자에게 물어봐야 합니다.
