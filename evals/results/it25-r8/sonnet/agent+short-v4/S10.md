CI 빌드는 `@company/ui` 2.0.0을 설치해서 실패하고, 로컬 빌드는 1.4.0을 계속 써서 성공한 것으로 보입니다. 이 설명은 추론이며, 아래 확인 절차로 검증해야 합니다.

## 원인 추론

2.0.0에서 패키지에 `exports` 필드(패키지가 바깥에서 불러올 수 있는 경로를 제한하는 설정)가 추가됐습니다. `exports`가 있으면 목록에 없는 경로는 불러올 수 없습니다. 그래서 2.0.0의 `exports`에 `./button`이 없거나 다른 형태로 적혀 있으면 `@company/ui/button`을 찾지 못합니다. 이것이 에러 `Error: Cannot find module '@company/ui/button'`의 가장 유력한 원인입니다.

로컬이 성공하는 이유는 `node_modules`가 3일 전보다 먼저 설치됐기 때문으로 보입니다. 그렇다면 로컬에는 `exports`가 없는 1.4.0이 남아 있고, 경로 제한을 받지 않습니다.

CI가 2.0.0을 설치하는 이유는 캐시 키가 `package-lock.json`의 해시이기 때문으로 보입니다. 버전을 올리면서 `package-lock.json`이 바뀌었다면 캐시 키가 달라져서 CI는 2.0.0을 새로 설치합니다. 이 부분은 `package-lock.json`이 커밋됐는지 확인하지 못했습니다.

## Node 버전 차이

Node 18과 Node 20의 차이는 원인일 가능성이 낮아 보입니다. 두 버전 모두 `exports`를 지원합니다. 다만 두 버전의 동작을 직접 비교하지는 않았습니다.

## 확인 절차

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 에러가 나면 원인은 2.0.0의 `exports`입니다.
3. 2.0.0 패키지의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
4. 2단계에서 에러가 나지 않으면 로컬에서 Node 18로 빌드해 Node 버전 차이를 따로 확인하십시오.

## 해결 방향

3단계에서 `./button`이 없으면 두 가지 중 하나를 택해야 합니다. 2.0.0의 새 import 경로로 코드를 고치거나, `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청하는 것입니다. 새 경로가 무엇인지는 아직 모릅니다. 일정에 영향이 있다면 `@company/ui`를 1.4.0으로 되돌리는 방법도 있으며, 이 경우 2.0.0에 올린 이유(변경 사항)를 포기해야 합니다.

확인 필요: 2.0.0으로 올린 이유와 되돌려도 되는지 여부.
