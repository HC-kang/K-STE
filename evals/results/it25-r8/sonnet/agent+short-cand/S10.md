CI 빌드가 실패하는 원인은 CI가 `@company/ui` 2.0.0을 설치하고 로컬은 1.4.0을 쓰기 때문일 가능성이 가장 높습니다. 이 내용은 주어진 사실에서 추론한 것이고, 아직 직접 확인하지 않았습니다.

## 근거

`exports` 필드는 패키지가 바깥에 공개하는 import 경로를 직접 정하는 설정입니다. 2.0.0에는 이 필드가 추가됐습니다. `exports`에 `./button` 경로가 없으면 `@company/ui/button`을 import할 수 없고, 이때 `Cannot find module` 오류가 납니다.

로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치한 것입니다. 그래서 로컬에는 1.4.0이 남아 있을 가능성이 높습니다. 1.4.0에는 `exports` 필드가 없으므로 `@company/ui/button`이 파일 경로로 그대로 찾아져 로컬 빌드가 성공합니다.

CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 lockfile이 바뀌었다면 캐시 키도 바뀌어 CI가 2.0.0을 새로 설치합니다. 그래서 CI에서만 실패하는 현상과 맞습니다.

## Node 버전은 원인일 가능성이 낮음

CI는 Node 18이고 로컬은 Node 20입니다. 이 차이가 원인이라고 볼 근거는 현재 없습니다. 두 버전 모두 `exports` 필드를 지원한다고 알고 있지만, 이번 환경에서 확인한 것은 아닙니다.

## 확인할 것

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 확인합니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드합니다. 같은 오류가 나면 원인이 확정됩니다.

## 해결 방향

2번에서 `./button`이 없으면 두 가지 중 하나를 선택해야 합니다.

- import 경로를 2.0.0의 `exports`가 공개하는 경로로 바꿉니다.
- `@company/ui` 담당 팀에 `./button` 경로를 `exports`에 추가해 달라고 요청합니다.

확인 필요: 2.0.0의 `exports`가 `./button`을 공개하는지 아직 모릅니다. 공개한다면 이 분석은 틀리고, Node 18과 번들러(webpack 등)의 해석 차이를 다시 살펴야 합니다.
