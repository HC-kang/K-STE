결론부터 말씀드리면, Redis를 도입해도 가격 변경이 고객 화면에 늦게 나타나는 문제는 저절로 없어지지 않습니다. 캐시 기간을 5분 그대로 두면 지연도 최대 5분 그대로입니다. 지연을 줄이려면 가격을 바꿀 때 Redis에 저장된 상품 목록을 지우는 기능을 함께 만드는 것을 권장합니다.

### 로컬 캐시와 Redis 캐시의 차이

캐시는 자주 쓰는 데이터를 빨리 꺼내 쓰려고 잠시 저장해 두는 공간입니다. 지금은 API 서버(고객 요청을 받아 상품 정보를 내려주는 서버) 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. Redis는 4대가 함께 쓰는 별도의 저장 서버입니다.

| 구분 | 로컬 캐시 (지금 방식) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리 안 | 4대가 함께 쓰는 별도 서버 1대 |
| 서버 간 상품 목록 | 서버마다 다를 수 있음 | 4대가 같은 목록을 읽음 |
| 가격 변경 후 고객 화면에 바뀌는 시간 | 서버마다 최대 5분 늦음 | 캐시 기간만큼 늦음 (5분이면 최대 5분) |
| 서버 재시작 시 | 캐시가 비어 있는 상태로 시작함 | 캐시가 남아 있음 |

### 우리 서비스에 좋아지는 점

- 4대 서버가 같은 상품 목록을 읽으므로, 서버마다 가격이 다르게 보이는 일이 없어집니다.
- 서버마다 상품 목록을 따로 저장하지 않으므로, 서버 메모리에 저장하는 양이 줄어듭니다.
- 서버를 재시작해도 캐시가 Redis에 남아 있으므로, 재시작 직후 상품 정보를 데이터베이스(상품 정보를 보관하는 원본 저장소)에서 다시 읽는 양이 줄어듭니다.

### 주의할 점

- Redis 서버가 멈추면 4대 서버 모두 영향을 받을 수 있습니다.
- 서버가 Redis를 거쳐 응답을 받아야 하므로, 메모리에서 바로 읽을 때보다 응답이 조금 느려질 수 있습니다.
- Redis 서버를 따로 운영해야 하므로 비용과 관리 부담이 늘어납니다.
- **가격 변경 시 캐시를 지우지 않으면 고객 화면의 5분 지연은 줄어들지 않습니다.**
- 확인 필요: 이번 도입 범위에 가격 변경 시 캐시 삭제가 포함되는지 확인해야 합니다.
