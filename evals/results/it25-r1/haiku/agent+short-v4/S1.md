로컬 캐시와 Redis 캐시의 가장 큰 차이는 캐시를 어디에 두고 누가 함께 쓰느냐입니다. Redis를 도입하면 서버 4대가 같은 캐시를 보기 때문에 서버마다 가격이 다르게 보이는 문제는 없어집니다.

로컬 캐시는 각 API 서버 안의 메모리(프로그램이 작업할 때 쓰는 임시 저장 공간)에 상품 목록을 넣어 두는 방식입니다. 서버가 자기 안에서 바로 꺼내 쓰므로 빠르지만, 서버 4대가 각자 따로 가지고 있어서 내용이 서로 다를 수 있습니다.

Redis는 캐시만 전담해서 저장하는 별도의 서버(캐시 서버)입니다. 4대의 API 서버가 이 한 곳에 요청해서 상품 목록을 가져옵니다. 다른 서버에 한 번 다녀오는 방식이라 로컬 메모리보다 조금 느릴 수 있습니다.

| 구분 | 로컬 캐시 (현재) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | API 서버 4대 각각의 메모리 | 캐시 전용 서버 1대 |
| 서버 사이의 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 읽음 |
| 읽는 속도 | 서버 안에서 바로 읽음 | 서버 사이를 한 번 오가서 읽음 |

서버마다 다른 가격이 고객에게 보이는 문제는 없어집니다. 하지만 가격을 바꾼 뒤 캐시를 언제 새로 채우는지에 따라 고객에게 반영되는 지연은 남을 수 있습니다.

확인 필요: Redis에 상품 목록을 몇 분 동안 보관할지, 가격을 바꿀 때 캐시를 바로 비울지. 두 방식 중 무엇을 택하는지에 따라 고객에게 가격이 반영되는 시간이 달라집니다.
