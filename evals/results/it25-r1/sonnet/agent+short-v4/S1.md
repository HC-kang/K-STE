로컬 캐시는 서버마다 따로 갖는 임시 저장소이고, Redis 캐시는 서버 4대가 같이 쓰는 임시 저장소입니다. 캐시는 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 방식입니다.

지금은 API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 캐시합니다. 그래서 서버마다 캐시 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. 같은 고객이 요청할 때 어느 서버가 받느냐에 따라 다른 가격을 볼 수도 있습니다.

Redis를 도입하면 캐시 서버 1대에 상품 목록을 저장하고 API 서버 4대가 그 목록을 같이 읽습니다. 그래서 서버 4대가 같은 상품 목록을 고객에게 보여줍니다. 서버마다 캐시 내용이 달라지는 문제가 없어집니다.

가격 반영 시간이 얼마나 줄어드는지는 아직 정해지지 않았습니다. 추론입니다. 캐시 서버가 1대이므로 가격을 바꿀 때 그 1대의 캐시만 갱신하면 되고, 이 방식을 쓰면 최대 5분 지연을 줄일 수 있습니다.
