로컬 캐시는 서버마다 따로 있고, Redis 캐시는 서버 4대가 하나를 같이 씁니다. 그래서 Redis를 도입하면 서버마다 상품 목록이 다르게 보이는 문제가 없어집니다.

캐시(자주 쓰는 데이터를 미리 담아 두는 임시 저장소)는 지금 API 서버 4대가 각자 자기 메모리에 두고 있습니다. 서버마다 상품 목록을 5분 동안 보관합니다. 그래서 가격을 바꿔도 서버마다 새 가격을 가져오는 시점이 달라, 고객에게 최대 5분 늦게 반영됩니다. 같은 고객이 새로고침할 때 다른 서버에 연결되면 가격이 다르게 보일 수도 있습니다.

Redis(여러 서버가 함께 쓰는 캐시 전용 서버)는 1대를 도입하고, 서버 4대가 이 1대를 같이 씁니다. 캐시가 한 곳에 있으므로 가격을 바꿀 때 그 한 곳만 갱신하면 4대가 같은 내용을 보여 줍니다.

두 방식의 차이는 다음과 같습니다.

| 구분 | 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리 | 공용 캐시 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있음 | 4대가 같은 내용을 봄 |
| 가격 변경 시 | 서버 4대의 캐시가 각자 만료될 때까지 기다려야 함 | 공용 캐시 한 곳만 갱신하면 됨 |

주의할 점이 두 가지 있습니다. 첫째, 캐시 보관 시간을 그대로 5분으로 두고 가격 변경 때 캐시를 갱신하지 않으면 지연은 남을 수 있습니다. 이번 도입에 가격 변경 시 캐시를 바로 갱신하는 방식이 포함되는지는 확인 필요입니다. 둘째, Redis가 1대이므로 이 서버에 문제가 생기면 4대 모두 영향을 받을 수 있습니다.
