로컬 캐시는 각 서버가 자기 안에 저장해 둔 상품 정보이고, Redis 캐시는 서버 4대가 함께 쓰는 별도 저장 서버 1대에 상품 정보를 두는 방식입니다. Redis를 도입하면 4대 서버가 같은 상품 정보를 보게 되지만, 가격 반영이 빨라진다는 점은 아직 확인되지 않았습니다.

| 구분 | 로컬 캐시 (지금) | Redis 캐시 (도입 예정) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리(서버가 작업할 때 쓰는 임시 공간) | 서버 4대 밖에 있는 저장 서버 1대 |
| 서버 간 상품 정보 | 서버마다 다를 수 있습니다 | 4대가 같은 정보를 봅니다 |
| 가격 변경 반영 | 최대 5분 늦게 반영됩니다 | 아래 확인 필요 항목에 따라 달라집니다 |

Redis를 도입하면 서버마다 정보가 달라지는 문제는 없어집니다. 하지만 상품 정보를 5분 동안 보관하는 설정을 그대로 두면 가격 반영 지연도 그대로 남을 수 있습니다. Redis는 4대 서버가 모두 이 한 대를 거쳐 상품 정보를 읽는 구조이므로, 이 서버에 문제가 생기면 4대가 함께 영향을 받을 수 있습니다.

확인 필요: Redis 도입 후 상품 정보를 몇 분 동안 보관할지, 가격을 바꿀 때 보관된 정보를 바로 지울지 확인이 필요합니다.
