가장 가능성이 높은 원인은 로컬 빌드가 아직 `@company/ui` 1.4.0을 쓰고, CI 빌드가 2.0.0을 쓰는 것입니다. 2.0.0의 `exports` 필드(패키지가 외부에 공개할 파일 경로를 정하는 설정)에 `./button` 경로가 없으면 Node가 `@company/ui/button`을 찾지 못합니다. 이 판단은 추론이며, 아직 직접 확인하지 않았습니다.

**사실**
- 로컬 `node_modules`는 업그레이드 3일 전보다 먼저 설치한 것이므로, 로컬에는 1.4.0이 남아 있을 가능성이 높습니다.
- CI는 `package-lock.json`에 적힌 2.0.0을 설치합니다.
- 2.0.0에 `exports` 필드가 추가됐습니다.

**추론**
- `exports`가 없던 1.4.0에서는 `@company/ui/button`처럼 패키지 안의 파일 경로를 직접 지정해도 가져올 수 있었습니다.
- `exports`가 생기면 Node는 목록에 적힌 경로만 허용합니다. 2.0.0이 `./button`을 목록에 넣지 않았거나 이름을 바꿨다면 같은 에러가 납니다.
- 로컬 빌드가 성공한 것은 2.0.0으로 빌드한 적이 없기 때문일 수 있습니다.

**가능성이 낮은 후보**
- Node 버전: Node 18과 Node 20 모두 `exports`를 지원하므로 주원인일 가능성이 낮습니다. 다만 두 버전을 맞추는 것은 권장합니다.
- CI 캐시: 업그레이드로 `package-lock.json`의 해시가 바뀌었으므로 옛 캐시를 쓰고 있을 가능성이 낮습니다. 확인 필요: 락파일을 2.0.0 상태로 커밋했는지 확인해야 합니다.

**확인 순서**
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다. 1.4.0이면 가설이 맞을 가능성이 큽니다.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치하고 빌드합니다. CI와 같은 에러가 나면 원인이 확정됩니다.
4. CI 로그에서 `npm ci`가 설치한 `@company/ui` 버전을 확인합니다.

**해결 방향**
- 2.0.0이 `./button`을 다른 경로로 공개하고 있다면, 앱의 import 경로를 그 경로로 바꿉니다.
- 2.0.0이 `./button`을 공개하지 않는다면, `@company/ui` 담당자에게 경로 추가를 요청하거나 패키지 루트에서 가져오도록 바꿉니다. 2.0.0의 변경 내역(changelog)에 이 변경이 적혀 있는지도 함께 확인해야 합니다.
