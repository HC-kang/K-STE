가장 유력한 원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개하는 파일 경로의 목록)입니다. 이 분석은 주어진 정보만으로 한 추론입니다.

## 원인

`exports` 필드가 있는 패키지는 목록에 없는 경로를 import할 수 없습니다. 2.0.0의 `exports`에 `./button`이 없거나 경로 형태가 다르면, Node는 `@company/ui/button`을 찾지 못하고 `Cannot find module` 오류를 냅니다.

## 로컬은 성공하고 CI만 실패하는 이유

로컬 `node_modules`는 3일 전보다 먼저 설치한 것이므로, 로컬에는 아직 1.4.0이 들어 있을 가능성이 큽니다. 1.4.0에는 `exports`가 없어서 `@company/ui/button`을 그대로 import할 수 있습니다.

CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀝니다. 그래서 CI는 캐시를 쓰지 않고 2.0.0을 새로 설치했을 것입니다.

Node 버전 차이는 원인일 가능성이 낮습니다. Node 18과 Node 20은 둘 다 `exports`를 지원합니다.

## 검증 순서

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전이 1.4.0인지 보십시오.
2. CI 로그에서 설치된 `@company/ui`의 버전이 2.0.0인지 보십시오.
3. 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
4. 로컬에서 `npm ci`(`package-lock.json`에 적힌 버전 그대로 새로 설치하는 명령)로 다시 설치한 뒤 빌드하십시오. 같은 오류가 나면 위 원인이 맞습니다.

## 해결 방법

3번에서 `./button`이 없거나 경로가 다르면 방법이 두 가지입니다. 첫째, import 경로를 2.0.0이 공개한 경로로 바꿉니다. 둘째, `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다. 배포를 먼저 풀어야 하면 `@company/ui`를 1.4.0으로 되돌려도 됩니다.
