# payment-api 운영 배포 롤백 런북

이 문서는 운영 환경의 payment-api 배포를 ArgoCD로 롤백하는 절차를 정한다. 롤백 전에 해당 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 마이그레이션이 포함된 배포는 롤백하면 안 된다. 롤백 후에는 `/healthz` 응답과 결제 테스트 주문으로 상태를 확인해야 하고, 롤백 이력을 #deploy 채널에 남겨야 한다.

## 1. 롤백 전 확인

롤백 명령을 실행하기 전에 다음을 확인해야 한다.

1. 롤백할 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때 DBA 박지은에게 연락해야 한다.
3. 마이그레이션이 포함되지 않았으면 다음 단계로 넘어가도 된다.

**경고: 마이그레이션이 포함된 배포는 롤백하면 안 된다.**

## 2. 롤백 실행

1. 롤백할 리비전 번호를 확인해야 한다.
2. 다음 명령을 실행해야 한다. `<REVISION>` 자리에 1번 단계에서 확인한 리비전 번호를 넣는다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 검증

롤백 명령이 끝난 뒤 다음을 확인해야 한다.

1. `/healthz` 응답이 200인지 확인해야 한다.
2. 결제 테스트 주문을 1건 실행해 성공하는지 확인해야 한다.

## 4. 이력 기록

1. 롤백 이력을 #deploy 채널에 남겨야 한다.

## 확인 필요

확인 필요: 배포에 DB 마이그레이션이 포함됐는지 확인. 확인할 위치와 방법이 원문에 없다.

확인 필요: `/healthz` 응답 확인. 요청을 보낼 대상 주소가 원문에 없다.

확인 필요: `<REVISION>`. 리비전 번호를 얻는 방법이 원문에 없다.
