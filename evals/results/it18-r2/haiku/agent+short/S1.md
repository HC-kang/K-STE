Redis를 도입하면 4대 서버가 같은 캐시를 보게 되지만, 지금 정보만으로는 가격 변경이 바로 반영된다고 말할 수 없습니다.

캐시는 자주 보는 데이터를 빨리 꺼내려고 따로 저장해 둔 복사본입니다. 지금은 API 서버(앱과 웹이 상품 정보를 요청하는 서버) 4대가 각자 메모리에 상품 목록을 5분 동안 저장합니다. Redis는 4대가 함께 쓰는 캐시 서버 1대입니다.

| 구분 | 지금 (서버마다 로컬 캐시) | Redis 도입 후 |
|---|---|---|
| 캐시 위치 | 서버 4대 각각의 메모리에 있습니다. | 캐시 서버 1대에 있습니다. |
| 서버 간 내용 | 서버마다 다를 수 있습니다. | 4대가 같은 내용을 봅니다. |
| 가격 변경 반영 | 고객에게 최대 5분 늦게 반영됩니다. | 확인 필요: 아래 참고 |

추정으로 좋아질 것으로 보는 점은 세 가지입니다.

- 추정: 4대가 같은 캐시를 보므로 서버마다 다른 가격이 보이는 일이 줄어듭니다.
- 추정: 캐시 값을 지울 때 Redis 한 곳만 지우면 4대에 함께 반영됩니다.
- 추정: 서버마다 따로 두던 복사본이 한 벌로 줄어듭니다.

확인 필요: 가격이 바뀔 때 Redis의 캐시 값을 바로 지우는지 여부. 5분 유효 시간만 두고 지우지 않으면 최대 5분 늦게 반영되는 문제가 그대로 남습니다.

이 점을 개발팀에 확인해 주시면 고객 반영 시간을 정확히 알려 드릴 수 있습니다.
