Redis를 도입하면 서버 4대가 같은 캐시를 읽기 때문에, 서버마다 상품 목록이 다르게 보이는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 공간입니다. 지금 쓰는 로컬 캐시는 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장하는 방식입니다. 그래서 서버마다 캐시 내용이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다.

Redis 캐시는 서버 4대가 함께 쓰는 캐시 서버 1대에 상품 목록을 저장하는 방식입니다. 4대가 같은 저장소를 읽으므로 고객은 어느 서버에 접속해도 같은 상품 목록을 봅니다.

Redis를 도입하는 것만으로 최대 5분 지연이 없어지는지는 알 수 없습니다. 가격을 바꿀 때 Redis에 저장된 상품 목록을 함께 갱신하거나 지우도록 만들면 지연이 줄어들 수 있습니다. 저장 시간을 5분 그대로 두고 가격 변경 때 캐시를 갱신하지 않으면 지연이 남을 수 있습니다.

캐시 서버가 1대이므로, 이 서버가 멈추면 API 서버 4대가 모두 영향을 받을 수 있습니다.
