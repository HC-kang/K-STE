원인은 로컬과 CI가 서로 다른 `@company/ui` 버전을 쓰는 것으로 보입니다. 로컬은 1.4.0이 남아 있고, CI는 2.0.0을 새로 설치합니다. 2.0.0의 `exports` 필드(패키지가 외부에 공개하는 import 경로 목록)에 `@company/ui/button`이 없으면 이 에러가 납니다. 이 설명은 추론이고, 아직 직접 확인하지 않았습니다.

## 근거

- 로컬 `node_modules`는 3일 전 업그레이드보다 먼저 설치했습니다. 그래서 로컬에는 1.4.0이 남아 있을 가능성이 큽니다.
- 1.4.0에는 `exports` 필드가 없습니다. 그래서 로컬에서는 패키지 안의 어떤 파일 경로로도 import할 수 있습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다. 업그레이드 때 lock 파일이 바뀌었다면 캐시가 맞지 않아서, CI는 의존성을 새로 설치하고 2.0.0을 받습니다.
- 2.0.0에는 `exports`가 있습니다. `exports`가 있으면 목록에 없는 경로는 import할 수 없습니다. 에러 `Cannot find module '@company/ui/button'`은 이 증상과 맞습니다.

## Node 버전 차이

Node 18과 20은 모두 `exports`를 지원합니다. 그래서 Node 버전 차이는 주된 원인이 아닌 것으로 보입니다.

## 확인 순서

1. 로컬과 CI 로그에서 각각 `npm ls @company/ui`를 실행해 설치된 버전을 비교합니다.
2. 2.0.0의 `package.json`에서 `exports` 안에 `./button`이 있는지 봅니다.
3. 로컬에서 `rm -rf node_modules && npm ci`로 다시 설치한 뒤 빌드합니다. 로컬 빌드도 같은 에러로 실패하면 원인이 확정됩니다.

## 해결 방향

`exports`에 `./button`이 없으면 방법은 두 가지입니다.

- 2.0.0이 공개하는 경로로 앱의 import를 바꿉니다. 새 경로는 `@company/ui`의 2.0.0 변경 내역에서 찾을 수 있습니다.
- `@company/ui` 담당자에게 `./button`을 `exports`에 추가해 달라고 요청합니다.

두 방법이 모두 어려우면 `@company/ui`를 1.4.0으로 되돌릴 수 있습니다.
