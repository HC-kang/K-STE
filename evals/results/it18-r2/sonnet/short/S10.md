가장 유력한 원인은 로컬 `node_modules`에 `@company/ui` 1.4.0이 남아 있고, CI는 2.0.0을 설치하며, 2.0.0의 `exports` 설정이 `@company/ui/button` 경로를 공개하지 않는 것입니다. 이 결론은 추론이며, 아래 검증 항목으로 확정해야 합니다.

## 확인된 사실
- 빌드는 CI에서만 실패하고 로컬에서는 성공합니다.
- 에러는 `Error: Cannot find module '@company/ui/button'`입니다.
- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0 패키지에는 `exports` 필드(패키지가 외부에 공개할 파일 경로를 정하는 설정)가 추가됐습니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.
- CI 캐시(이전 설치 결과를 재사용하는 저장소) 키는 `package-lock.json`의 해시입니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.

## 추론
1. 로컬 `node_modules`는 업그레이드 전에 설치했으므로 1.4.0일 가능성이 높습니다.
2. 1.4.0에는 `exports`가 없으므로 Node는 `@company/ui/button`을 실제 파일 경로로 찾고, 로컬 빌드는 성공합니다.
3. 업그레이드 커밋에서 `package-lock.json`이 바뀌었다면 캐시 키도 바뀌므로, CI는 2.0.0을 새로 설치합니다.
4. `exports`가 있으면 Node는 `exports`에 적힌 경로만 허용합니다. 2.0.0의 `exports`에 `./button`이 없거나 이름이 다르면 같은 import가 "Cannot find module"로 실패합니다.
5. Node 18과 20은 모두 `exports`를 지원하므로, Node 버전 차이가 주된 원인일 가능성은 낮습니다.

## 확인이 필요한 항목
- 로컬에 실제로 설치된 `@company/ui` 버전이 1.4.0인지 확인해야 합니다.
- 2.0.0의 `exports`에 `./button`에 해당하는 항목이 있는지 확인해야 합니다.
- 업그레이드 커밋에 `package-lock.json` 변경이 포함됐는지 확인해야 합니다.
- Node 버전이 영향을 주는지는 아직 확인하지 않았습니다.

## 검증 순서
1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. 로컬에서 `rm -rf node_modules && npm ci`로 lock 파일 기준 재설치를 한 뒤 `next build`를 실행합니다. 같은 에러가 나면 추론 1-4가 맞습니다.
3. `node_modules/@company/ui/package.json`의 `exports` 필드를 열어 공개된 경로 목록을 확인합니다.
4. 2번에서 재현되지 않으면 Node 18로 같은 절차를 반복해 Node 버전 영향을 따로 확인합니다.

## 해결 방향
- `@company/ui` 담당자가 2.0.0 이후 버전의 `exports`에 `./button`을 추가할 수 있습니다.
- 앱 쪽에서 import 경로를 `exports`가 공개하는 경로로 바꿀 수 있습니다.
- 두 방법이 모두 어려우면 `@company/ui`를 1.4.0으로 되돌릴 수 있습니다. 이 경우 2.0.0의 변경 사항을 쓰지 못합니다.

어느 방법을 쓸지는 3번 결과에서 `./button`이 없는지, 이름만 다른지에 따라 정해야 합니다.
