## 결론

CI에서만 실패하는 가장 유력한 원인은 `@company/ui` 2.0.0에 새로 추가된 `exports` 필드다. 로컬 빌드가 성공하는 이유는 로컬 `node_modules`가 업그레이드 전에 설치돼 1.4.0을 쓰고 있기 때문으로 보인다. 이 판단은 추론이며, 아래 검증 순서로 아직 확인하지 않았다.

## 확인된 사실

- 로컬 `node_modules`는 3일 전보다 먼저 설치됐다.
- 2.0.0에는 `exports` 필드가 추가됐다. 1.4.0에는 이 필드가 없었다.
- CI는 Node 18을, 로컬은 Node 20을 쓴다.
- CI 캐시 키는 `package-lock.json`의 해시다.
- 실패 오류는 `Error: Cannot find module '@company/ui/button'`이다.

## 원인 후보

| 후보 | 근거 | 가능성 | 확인 방법 |
|---|---|---|---|
| 2.0.0의 `exports`가 `./button` 경로를 열어 두지 않았다 | 1.4.0에는 `exports`가 없어 파일 경로로 해석됐고, 2.0.0에서는 정의되지 않은 하위 경로가 막힌다 | 높음 (추론) | 2.0.0의 `exports` 항목에 `./button`이 있는지 읽는다 |
| 로컬 `node_modules`가 1.4.0이라 로컬에서는 재현되지 않는다 | 로컬 설치 시점이 업그레이드 전이다 | 높음 (추론) | `npm ls @company/ui`로 로컬 버전을 조회한다 |
| Node 18과 20의 차이 | 두 버전 모두 `exports`를 지원한다 | 낮음 (추론) | 로컬에서 Node 18로 빌드해 본다 |
| 캐시 또는 lockfile 문제 | 커밋된 lockfile에 2.0.0이 없으면 CI가 다른 버전을 받을 수 있다 | 미확인 | 커밋된 `package-lock.json`의 버전과 CI 캐시 복원 로그를 본다 |

## 오류 메시지에 대한 관찰 (추론)

`Cannot find module`은 Node가 내는 기본 해석 오류 문구다. Next.js 번들러 빌드의 해석 오류는 보통 `Module not found: Can't resolve`로 나온다. 따라서 실패 지점은 번들러가 아니라 Node가 직접 읽는 파일(설정 파일, 테스트, 스크립트)일 수 있다.

또한 `exports`가 경로를 막으면 Node는 보통 `ERR_PACKAGE_PATH_NOT_EXPORTED` 오류를 낸다. 메시지가 다르므로 `exports`가 원인이라는 판단은 전체 로그로 검증해야 한다.

## 확인 필요

- 실패가 나는 단계와 전체 스택 트레이스가 무엇인지 확인 필요: 이 정보가 실패 지점을 가른다.
- 커밋된 `package-lock.json`에 2.0.0이 기록돼 있는지 확인 필요: 기록돼 있지 않으면 CI의 설치 버전도 달라진다.
- CI에서 실패가 처음 나타난 실행이 업그레이드 커밋 이후인지 확인 필요.
- 2.0.0이 `exports`로 열어 둔 경로 목록이 무엇인지 확인 필요.

## 조치 방안

1. 소비 측 import를 2.0.0의 `exports`가 허용하는 경로로 바꾸는 방안을 권장한다. 가장 빠른 수정이다.
2. `@company/ui` 관리 팀에 `button` 경로의 `exports` 추가를 요청할 수 있다.
3. 임시 조치로 `@company/ui`를 1.4.0에 고정할 수 있다.

Node 18은 2025년 4월 30일에 지원이 끝났다. CI의 Node 버전을 20 이상으로 올리는 방안도 함께 검토한다.

**주의: 로컬 `node_modules`를 유지한 채 로컬 빌드만 확인하면 같은 문제를 재현할 수 없다. 재현하려면 `rm -rf node_modules && npm ci` 후 빌드해야 한다.**

## 검증 순서

1. `rm -rf node_modules && npm ci` 후 로컬에서 빌드해 같은 오류가 나는지 본다.
2. `npm ls @company/ui`로 로컬과 CI의 설치 버전을 비교한다.
3. Node 18로 로컬 빌드해 Node 버전의 영향을 분리한다.
4. `node_modules/@company/ui/package.json`의 `exports` 항목을 읽어 `./button` 허용 여부를 본다.
