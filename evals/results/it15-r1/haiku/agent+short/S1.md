Redis를 도입해도 가격이 고객에게 반영되는 시간은 Redis 도입만으로 정해지지 않습니다. 캐시(자주 보는 정보를 빨리 꺼내 쓰려고 잠시 저장해 두는 곳)를 어떻게 지우고 갱신할지에 따라 결과가 달라집니다.

| 구분 | 지금 (로컬 캐시) | Redis 도입 후 |
|---|---|---|
| 캐시 위치 | 각 API 서버의 메모리(작업 중 데이터를 올려 두는 공간) | 별도의 캐시 서버 1대 |
| 서버 간 공유 | 서버 4대가 각자 다른 캐시를 가짐 | 서버 4대가 같은 캐시를 봄 |
| 가격 변경 반영 | 서버마다 최대 5분 늦게 반영됨 | 캐시를 지우는 방식에 따라 달라짐 |

지금은 서버 4대가 각자 캐시를 가지고 있습니다. 그래서 가격을 바꾸면 서버마다 반영 시점이 달라지고, 고객에게는 최대 5분 늦게 반영됩니다.

Redis를 도입하면 4대 서버가 같은 캐시를 봅니다. 그래서 서버마다 가격이 다르게 보이는 문제는 없어집니다. 서버를 재시작해도 캐시가 Redis에 남아 있어서, 서버마다 캐시를 처음부터 다시 채우지 않아도 됩니다.

하지만 Redis에 저장된 값도 5분이 지나야 지워지도록 두면, 가격은 여전히 최대 5분 늦게 반영됩니다. 확인 필요: 가격을 바꿀 때 Redis 캐시를 바로 지우는 작업을 넣을지, 유효 시간을 5분보다 줄일지 개발팀에 확인해야 합니다.

Redis는 별도의 서버라서 값을 조회할 때마다 네트워크를 한 번 거칩니다. 그래서 서버 메모리에서 바로 꺼내는 지금 방식보다 느릴 수 있습니다. Redis 서버 1대가 멈추면 4대 서버 모두 영향을 받을 수 있습니다.
