로컬 캐시는 각 서버가 자기 메모리에 상품 정보를 따로 보관하는 방식이고, Redis 캐시는 서버 4대가 함께 읽는 공용 캐시 서버 1대에 상품 정보를 보관하는 방식입니다. 캐시(자주 보는 데이터를 잠시 저장해 두는 임시 보관소)는 매번 원본을 조회하지 않게 해서 응답을 빠르게 합니다.

| 구분 | 로컬 캐시 (지금 방식) | Redis 캐시 (도입 예정) |
|---|---|---|
| 보관 위치 | 서버 4대 각각의 메모리 | 공용 캐시 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있습니다 | 4대가 같은 값을 읽습니다 |
| 조회 속도 | 서버 안에서 바로 읽습니다 | 네트워크를 거쳐 읽으므로 조금 느릴 수 있습니다 |
| 장애 영향 | 서버 1대가 멈추면 그 서버만 영향을 받습니다 | Redis 서버 1대가 멈추면 4대 서버 모두 영향을 받을 수 있습니다 |

이번 도입으로 좋아지는 점은 서버마다 다른 상품 정보를 보는 문제가 없어진다는 것입니다. 고객이 가격 변경을 최대 5분 늦게 보는 문제는 Redis를 도입한다고 자동으로 없어지지 않습니다. 캐시 값을 유지하는 시간(유효 시간)을 얼마로 둘지, 가격을 바꿀 때 Redis 값을 바로 갱신할지에 따라 지연이 달라집니다. 이 부분은 개발팀이 설계할 때 정해야 합니다.
