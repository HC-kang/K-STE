# 운영 배포 롤백 런북 (payment-api)

## 목적

이 런북은 운영 환경의 payment-api 배포를 ArgoCD로 이전 리비전(revision)으로 되돌리는 절차를 정의한다.

## 1. 사전 확인

1. 롤백 대상 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
2. 마이그레이션이 포함됐으면 롤백하면 안 된다.
3. 마이그레이션이 포함됐으면 DBA 박지은에게 연락해야 한다.

**경고: 마이그레이션이 포함된 배포는 롤백하면 안 된다. 반드시 DBA 박지은과 먼저 상의해야 한다.**

## 2. 롤백 실행

1. 마이그레이션이 포함되지 않았음을 확인한 뒤에만 다음 명령을 실행한다.

   ```
   argocd app rollback payment-api <REVISION>
   ```

2. `<REVISION>`에는 되돌릴 대상 리비전 번호를 넣는다.

## 3. 롤백 후 검증

1. `/healthz`가 HTTP 200을 반환하는지 확인해야 한다.
2. 결제 테스트 주문 1건이 성공하는지 확인해야 한다.
3. 두 검증 중 하나라도 실패하면 롤백 결과를 확정하지 않는다. 실패 원인은 확인 필요: 실패 시 누구에게 어떻게 보고하는지 정해지지 않았다.

## 4. 이력 기록

1. 롤백 이력을 #deploy 채널에 남겨야 한다.

## 확인 필요 사항

- 확인 필요: 배포에 마이그레이션이 포함됐는지 확인하는 구체적인 방법이 정해지지 않았다.
- 확인 필요: `<REVISION>`에 넣을 리비전 번호를 찾는 방법이 정해지지 않았다.
- 확인 필요: #deploy 채널에 남길 이력의 기록 항목이 정해지지 않았다.
