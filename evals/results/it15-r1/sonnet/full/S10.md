원인은 `@company/ui` 2.0.0에서 추가된 `exports` 필드(패키지가 외부에 공개하는 import 경로를 정하는 설정)로 보입니다. 로컬은 아직 1.4.0을 쓰고 있어서 이 차이가 CI(코드를 올릴 때 자동으로 빌드하는 환경)에서만 드러난 것으로 추정합니다.

`exports`가 없는 1.4.0에서는 `@company/ui/button`처럼 파일 위치대로 하위 경로를 import할 수 있었습니다. `exports`가 있는 2.0.0에서는 `exports`에 적힌 경로만 import할 수 있습니다. 따라서 2.0.0의 `exports`에 `./button`이 없거나 다르게 적혀 있으면 `Cannot find module '@company/ui/button'` 오류가 납니다.

로컬 `node_modules`(설치된 패키지가 저장되는 폴더)는 3일 전보다 먼저 설치한 것이므로 1.4.0이 그대로 남아 있을 수 있습니다. 이 경우 로컬 빌드 성공은 2.0.0으로 빌드되는지 검증하지 못한 결과입니다. CI는 `package-lock.json`(설치할 패키지 버전을 고정한 파일)에 2.0.0이 적혀 있다면 2.0.0을 설치합니다.

다른 요인은 원인일 가능성이 낮습니다.
- Node 버전: Node 18과 20은 둘 다 `exports`를 지원하므로 버전 차이가 이 오류의 원인일 가능성은 낮습니다.
- CI 캐시: 캐시 키가 `package-lock.json`의 해시이므로, 업그레이드 때 이 파일이 바뀌었다면 1.4.0 시절의 캐시를 재사용하지 않았을 것입니다.

원인을 확정하려면 다음 순서로 진행하십시오.
1. 로컬과 CI 로그에서 설치된 `@company/ui` 버전을 비교하십시오.
2. `@company/ui` 2.0.0의 `package.json`에서 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `node_modules`를 지우고 다시 설치한 뒤 Node 18로 빌드해 CI와 같은 오류가 나는지 보십시오.
