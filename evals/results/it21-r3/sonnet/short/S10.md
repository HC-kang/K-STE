원인은 로컬과 CI가 서로 다른 버전의 `@company/ui`를 쓰는 것으로 보입니다. 2.0.0에 추가된 `exports` 필드가 `@company/ui/button` 경로를 열어 주지 않아서 CI에서만 모듈을 찾지 못하는 것으로 추정합니다.

## 사실

- 3일 전에 `@company/ui`를 1.4.0에서 2.0.0으로 올렸습니다.
- 2.0.0에서 패키지에 `exports` 필드가 추가됐습니다.
- 로컬 `node_modules`는 3일 전보다 먼저 설치했습니다.
- CI 캐시 키는 `package-lock.json`의 해시입니다.
- CI는 Node 18, 로컬은 Node 20을 씁니다.

## 추론

- 로컬 `node_modules`에는 아직 1.4.0이 있을 가능성이 높습니다. 그러면 로컬 빌드는 `exports` 제한이 없는 옛 버전으로 성공한 것입니다.
- 버전을 올리면서 `package-lock.json`이 바뀌었으므로 CI 캐시 키도 바뀌었습니다. 그래서 CI는 2.0.0을 새로 설치했을 것입니다.
- `exports` 필드가 있으면 Node와 번들러는 그 필드에 적힌 경로만 허용합니다. 2.0.0의 `exports`에 `./button`이 없거나 다른 이름으로 있다면 `@company/ui/button` import는 `Cannot find module`로 실패합니다.
- Node 18과 20은 둘 다 `exports`를 지원하므로, 이 차이는 주된 원인이 아닐 가능성이 높습니다.

## 확인 필요

- 로컬에 실제로 설치된 `@company/ui` 버전은 확인하지 않았습니다.
- 2.0.0의 `exports`에 `./button`이 있는지 확인하지 않았습니다.
- Node 버전이 영향을 주는지 직접 검증하지 않았습니다.

## 확인 방법

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 확인합니다.
2. 로컬에서 `node_modules/@company/ui/package.json`의 `exports`를 열어 `./button` 항목이 있는지 확인합니다.
3. 로컬에서 `rm -rf node_modules && npm ci`를 실행한 뒤 빌드합니다. CI와 같은 에러가 나면 원인이 확정됩니다.
4. 3번 이후에도 결과가 다르면 로컬을 Node 18로 바꿔 다시 빌드해 Node 버전 영향을 따로 확인합니다.

## 해결 방향

- 앱 쪽에서 import 경로를 2.0.0의 `exports`에 정의된 경로로 바꿀 수 있습니다.
- 패키지 쪽에서 `exports`에 `./button` 서브패스를 추가한 버전을 배포할 수도 있습니다.
- 어느 쪽이 맞는지는 2.0.0에서 경로를 의도적으로 바꿨는지에 따라 정해야 합니다. 패키지 담당자에게 확인해야 합니다.
