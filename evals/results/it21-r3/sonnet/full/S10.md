원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개하는 파일 경로를 제한하는 설정)로 보입니다. 로컬은 업그레이드 전 버전으로, CI(코드 변경 때마다 자동으로 빌드하는 서버)는 2.0.0으로 빌드하고 있기 때문입니다.

로컬 `node_modules`는 3일 전보다 먼저 설치한 것이므로, 로컬에는 1.4.0이 남아 있을 가능성이 높습니다. `exports` 필드가 없는 1.4.0에서는 `@company/ui/button`이 패키지 안의 파일 경로로 그대로 찾아집니다. 2.0.0에서는 `exports`에 `./button`이 없으면 이 경로를 찾지 못해 `Cannot find module` 오류가 납니다.

CI는 `package-lock.json` 해시를 캐시 키로 씁니다. 업그레이드로 `package-lock.json`이 바뀌었다면 캐시 키도 바뀌므로, CI는 2.0.0을 새로 설치합니다. 따라서 오래된 캐시는 원인일 가능성이 낮습니다.

Node 18과 Node 20은 둘 다 `exports` 필드를 지원합니다. 그래서 Node 버전 차이는 원인일 가능성이 낮습니다.

다음 순서로 검증하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 조회하십시오.
2. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 같은 오류가 나면 위 추론이 맞습니다.
3. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오.

`./button`이 없으면 import 경로를 `exports`에 있는 경로로 바꾸거나, `@company/ui`를 관리하는 쪽에 `./button` 추가를 요청하십시오.
