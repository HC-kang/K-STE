로컬 캐시는 서버마다 따로 갖는 저장 공간이고, Redis 캐시는 서버 4대가 함께 쓰는 저장 공간입니다. Redis를 도입하면 서버마다 상품 목록이 달라지는 문제가 없어집니다.

캐시는 자주 쓰는 데이터를 미리 저장해 두고 빠르게 꺼내 쓰는 방식입니다. 지금은 API 서버 4대가 각자 자기 메모리에 상품 목록을 5분 동안 저장합니다. 그래서 서버마다 저장한 시점이 다르고, 가격을 바꾸면 고객에게 최대 5분 늦게 반영됩니다. 같은 고객이 요청할 때마다 다른 서버에 연결되면 서로 다른 가격을 볼 수도 있습니다.

Redis는 캐시 전용 서버입니다. 이번에는 Redis 서버 1대를 도입하고, API 서버 4대가 이 Redis 서버 1대의 같은 상품 목록을 읽습니다. 그래서 어느 서버에 연결되든 고객은 같은 내용을 봅니다.

| 구분 | 로컬 캐시 | Redis 캐시 |
|---|---|---|
| 저장 위치 | API 서버 4대 각각의 메모리 | 서버 4대가 함께 쓰는 Redis 서버 1대 |
| 서버 간 내용 | 서버마다 다를 수 있습니다 | 4대가 같은 내용을 읽습니다 |
| 현재 문제 | 가격 변경이 고객에게 최대 5분 늦게 반영됩니다 | 서버 간 내용 차이가 없어집니다 |

확인 필요: 가격 변경이 고객에게 반영되는 시간이 5분보다 짧아지는지는 가격을 바꿀 때 Redis에 저장된 상품 목록을 어떻게 갱신하는지에 달려 있습니다. 이 갱신 방식은 개발팀에 확인해야 합니다.
