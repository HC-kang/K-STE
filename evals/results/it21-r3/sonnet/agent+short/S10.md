원인은 `@company/ui` 2.0.0에 추가된 `exports` 필드(패키지가 외부에 공개하는 import 경로를 제한하는 설정)로 보입니다. 아직 검증하지 않은 추론입니다.

`exports` 필드가 있는 패키지는 필드에 적힌 경로만 import할 수 있습니다. 2.0.0의 `exports`에 `./button`이 없으면 `@company/ui/button`을 찾지 못해 `Cannot find module` 오류가 납니다. 1.4.0에는 `exports` 필드가 없었기 때문에 같은 import가 동작했습니다.

로컬과 CI에서 결과가 갈린 이유도 같은 추론으로 설명됩니다.

| 구분 | 로컬 | CI |
|---|---|---|
| Node 버전 | 20 | 18 |
| `@company/ui` 설치 버전 | 1.4.0으로 보임 | 2.0.0으로 보임 |
| 근거 | `node_modules`를 3일 전보다 먼저 설치했습니다. | 캐시 키가 `package-lock.json` 해시이므로, 3일 전 버전 변경으로 파일이 바뀌었다면 캐시가 무효가 되고 2.0.0을 새로 설치합니다. |

Node 18도 `exports` 필드를 지원하므로 Node 버전 차이가 주원인일 가능성은 낮습니다.

추론을 검증하려면 다음 순서로 하십시오.

1. 로컬에서 `npm ls @company/ui`를 실행해 설치된 버전을 보십시오.
2. `node_modules/@company/ui/package.json`의 `exports`에 `./button`이 있는지 보십시오.
3. 로컬에서 `node_modules`를 지우고 `npm ci`로 다시 설치한 뒤 빌드하십시오. 로컬에서도 같은 오류가 나면 추론이 맞습니다.

2단계에서 `./button`이 없으면, 2.0.0이 `button`을 공개하는 경로를 찾아 import를 고쳐야 합니다.
