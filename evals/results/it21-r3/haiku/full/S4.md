# payment-api 운영 배포 롤백 런북

이 런북은 ArgoCD로 배포한 payment-api의 운영 배포를 이전 리비전으로 되돌리는 절차를 정한다. 롤백하기 전에 그 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다. 포함됐으면 롤백하면 안 되고 DBA 박지은에게 연락해야 한다.

## 1. 롤백 전 확인

1. 롤백할 REVISION 값을 확인해야 한다.
2. 롤백하려는 배포에 DB 마이그레이션이 포함됐는지 확인해야 한다.
3. 2번 확인 결과 마이그레이션이 포함됐으면 롤백하면 안 된다. 이때 DBA 박지은에게 연락해야 한다.
4. 2번 확인 결과 마이그레이션이 포함되지 않았을 때만 2절의 롤백 명령을 실행한다.

## 2. 롤백 실행

5. 롤백 담당자가 다음 명령을 실행해야 한다.

```
argocd app rollback payment-api <REVISION>
```

## 3. 롤백 후 확인

6. 롤백 담당자가 `/healthz`가 200을 반환하는지 확인해야 한다.
7. 롤백 담당자가 결제 테스트 주문 1건을 실행하고, 그 주문이 성공하는지 확인해야 한다.

## 4. 이력 기록

8. 롤백 담당자가 롤백 이력을 #deploy 채널에 남겨야 한다.

확인 필요: 마이그레이션 포함 여부를 확인하는 방법. 원문에 확인 도구나 확인 위치가 없다.
확인 필요: `/healthz`가 200을 반환하지 않거나 테스트 주문이 실패할 때의 조치. 원문에 실패 시 절차가 없다.
확인 필요: #deploy 채널에 남길 이력의 항목. 원문에 기록 형식이 없다.
