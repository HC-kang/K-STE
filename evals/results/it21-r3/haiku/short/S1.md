Redis를 도입하면 4대 서버가 같은 캐시 값을 읽으므로 서버마다 가격이 다르게 보이는 문제는 없어집니다. 다만 가격 반영이 최대 5분 늦는 문제는 Redis 도입만으로 해결되지 않습니다.

캐시(자주 쓰는 데이터를 미리 저장해 두는 임시 보관소)는 지금 서버마다 따로 두고 있고, Redis는 여러 서버가 함께 쓰는 저장 프로그램을 별도 서버 1대에 두는 방식입니다.

| 구분 | 지금 (서버별 로컬 캐시) | 도입 예정 (Redis 캐시) |
|---|---|---|
| 저장 위치 | 각 API 서버의 메모리(실행 중 쓰는 임시 공간) | 캐시 전용 서버 1대 |
| 서버 간 값 | 서버마다 다를 수 있습니다 | 4대 서버가 같은 값을 읽습니다 |
| 값 갱신 | 서버마다 5분이 지나면 각자 다시 가져옵니다 | 한 번 갱신하면 4대 서버에 함께 반영됩니다 |
| 읽는 속도 | 서버 안에서 바로 읽습니다 | 네트워크를 거쳐 읽으므로 일반적으로 조금 느립니다 |

가격 반영 지연은 캐시 유효 시간이 5분으로 그대로면 최대 5분으로 같습니다. 지연을 줄이려면 가격을 바꿀 때 캐시를 바로 지우는 작업(캐시 삭제)을 추가해야 합니다. 이 작업을 이번 도입 범위에 넣는지는 확인 필요합니다.

Redis 서버가 1대뿐이므로 이 서버가 멈추면 4대 서버 모두 캐시를 쓰지 못합니다. 이 장애에 대비할 방법은 확인 필요합니다.
