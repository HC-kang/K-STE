# K-STE

K-STE는 AI가 쓰는 한국어 업무 글을 개발자와 비개발자가 한 번에 이해하게 만드는 Agent Skill이다. ASD-STE100(항공 정비 문서용 통제 언어)의 원칙을 한국어 업무 글에 맞게 옮겼다. 목표는 짧은 글이 아니라 잘못 읽을 수 없는 글이다.

같은 모델에 같은 사실을 주고 Slack 장애 공유 메시지를 쓰게 한 결과다. 두 출력 모두 수정하지 않았다.

## 설치와 적용

규칙은 두 가지 방법으로 적용한다. 상시 적용은 모든 답변에 기본 문체로 적용하는 방법이다. 스킬은 재작성과 검수 요청에 자세한 절차를 적용하는 방법이다. 스킬은 모델이 필요하다고 판단할 때만 실행되므로, 상시 적용은 지침 파일에 짧은판을 넣어서 처리한다.

| 환경 | 상시 적용 | 재작성·검수 |
|---|---|---|
| Claude Code, Codex, Cursor | `CLAUDE.md`나 `AGENTS.md`에 짧은판을 붙인다 | `npx skills add HC-kang/K-STE`로 스킬을 설치한다 |
| Claude.ai | 프로젝트 지침에 짧은판을 붙인다 | `skills/k-ste` 폴더를 zip으로 묶어 스킬로 올린다 |
| ChatGPT | 맞춤 지침에 짧은판을 붙인다 | 프로젝트 지침이나 GPT 지침에 전체판을 붙인다 |
| Gemini | 저장된 정보에 짧은판을 붙인다 | Gem 지침에 전체판을 붙인다 |
| Slack 봇, API 호출 | 시스템 프롬프트에 전체판을 넣는다 | 같은 전체판이 처리한다 |

짧은판(약 1,000자)과 전체판(약 3,000자)은 [`prompts/system-prompt.md`](prompts/system-prompt.md)에 있다. 짧은판에는 검수 표 형식이 없다. 검수는 스킬이나 전체판으로 한다.

## 사용법

- 쓰기: 따로 요청하지 않아도 규칙대로 쓴다.
- 재작성: "이 글 쉽게 바꿔줘", "다듬어줘", "줄여줘"라고 요청한다. 고친 글만 나온다. 원문이 두 가지로 읽히는 곳은 고치지 않고 `확인 필요:`로 묻는다.
- 검수: "이 글 검사해줘"라고 요청한다. `| 규칙 | 원문 | 고친 글 |` 표가 나온다.

## 규칙

K0이 다른 모든 규칙보다 우선한다. 전체 규칙과 예문은 [`skills/k-ste/SKILL.md`](skills/k-ste/SKILL.md)에 있다.

| ID | 규칙 |
|---|---|
| K0 | 의미를 보존한다. 사실을 더하지 않고, 조건, 범위, 확신 정도, 의무 강도를 바꾸지 않는다. 두 가지로 읽히는 곳은 고르지 않는다. |
| K1 | 결론을 첫 문장에 쓴다. |
| K2 | 한 문장에 정보 하나를 쓴다. |
| K3 | 주어, 조사, 어미를 생략하지 않는다. 명사로 끝내지 않는다. |
| K4 | 같은 대상과 같은 동작에는 같은 단어를 쓴다. |
| K5 | 능동형으로 쓰고 이중 피동을 쓰지 않는다. |
| K6 | 사실, 추론, 미확인을 구분한다. |
| K7 | 조건을 동작 앞에 쓴다. |
| K8 | 비개발자 독자에게는 어려운 용어를 처음 나올 때 풀이한다. |
| K9 | 서두, 맺음 제안, 근거 없는 평가어를 쓰지 않는다. |
| K10 | 줄글이 기본이다. 볼드는 경고에만 쓰고, 이모지와 엠대시를 쓰지 않는다. |
| K11 | 답변은 합니다체, 문서는 한다체로 쓴다. 한 글에서 섞지 않는다. |

## 평가

평가 결과는 2차 평가가 끝나면 채운다.

## 한계

- K-STE는 공인 표준이 아니다. ASD-STE100을 번역한 것도 아니다.
- 지시문 20어절, 설명문 25어절 기준에는 한국어 근거가 없다. 그래서 검토 신호로만 쓴다.
- 판정자도 Claude다. 사람이 만든 정답과 대조하지 않았다.
- 홍보 문구, 창작 글, 영어 글에는 적용하지 않는다.
