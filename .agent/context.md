# K-STE 프로젝트 메모리

## 2026-10-15 설계 결정

- 목적: AI가 만드는 한국어 업무 텍스트를 개발자·비개발자 동료가 한 번에 이해하게 하는 범용 Agent Skill.
- 스펙: `docs/superpowers/specs/2026-10-15-k-ste-design.md`.
- 사용자 선택: 상시 적용 + 요청 시 재작성, 세 환경(코딩 에이전트, 웹 채팅, 사내 자동화), 조건부 서식, 답변 합니다체 / 문서 한다체.
- 접근안: 새로 쓴다. ko-ste(fivestar1103), ste-ko(beamonic), SimpleEnglish(AminBlg)는 아이디어만 가져온다.
- 출처 표기: 사용자는 원하지 않는다. 규칙 문장과 예문을 직접 써서 표기 의무를 피한다. 다른 저장소 문장이나 국립국어원 예문(공공누리 제3유형, 변경금지)을 복사하지 않는다.

## 제약

- 상시 적용은 스킬 자동 실행에 맡기지 않는다. 짧은판을 CLAUDE.md, AGENTS.md, 맞춤 지침에 넣는다.
- 평가 격리: 서브에이전트는 사용자 `~/.claude/CLAUDE.md`(한국어 STE 규칙 포함)를 상속한다. 기준선은 `claude -p --setting-sources "" --system-prompt ... --tools ""`로 실행한다. 이 방법은 2026-10-15에 시험했다.
- 한국어 공공 지침에는 문장 길이 수치 기준이 없다. 어절 수는 검토 신호로만 쓴다.
- "~에 대해", "~를 통해"는 사람 글에 더 많다. 일괄 금지하지 않는다.

## 교훈 (참고 저장소)

- SimpleEnglish 감사: 규칙 53개 스킬이 8줄 프롬프트에 독자 체감 지표에서 졌다. 핵심 규칙은 짧게 둔다.
- 린터 점수는 독자 체감과 다르다. 의미 보존은 블라인드 판정으로 잰다.

## 실수와 원인

- 규칙 예문에 평가 시나리오 단어를 넣어 1-4차 평가를 오염시켰다. 예문을 쓸 때마다 `evals/scenarios/S*.txt`와 겹치는 단어를 grep으로 확인한다.
- 오염을 지우면서 "정상적으로" 같은 정도·방식 한정어 범주까지 지웠다. 예문을 바꿀 때는 단어만 바꾸고 범주는 남긴다.

## 2026-10-17 조사: 한국어 정밀 언어 사례

- 사용자 교정: K-STE의 목표는 "쉬운 한국어"가 아니다. 엄밀하고 적확한 용어로 오해를 막는 것이 목표다. 공공 부문의 쉬운 말(전문용어를 일상어로 바꿈)은 방향이 다르다.
- 한국어에 ASD-STE100을 공식 적용한 규격은 없다. 정밀성 장치는 분야별로 흩어져 있다. 아래는 원문과 대조한 핵심 근거다.
  - KS A 0001:2023: 4.3.9(동의어 회피, 용어마다 한 의미), 4.3.10(주관어 금지), 부속서 I(의무 표현: 하여야 한다, 하여서는 안 된다, 하는 것이 좋다, 해도 된다, 할 수 있다=가능, 반드시 하여야 한다=외적 제약), H.2.2(이상·초과·부터·까지의 포함 여부).
  - 방사청 예규 국방규격 작성 지침 제676호: 1.9(2개 이상의 의미를 갖는 단어 회피), 1.9.6(금지 모호어, 의무 3단), 1.12(강조 금지). 2025-09 폐지, 매뉴얼로 옮겨짐(매뉴얼 원문 미확인). MIL-STD-961 번역 과정에서 should/will의 강도가 흐려졌다.
  - 특허·실용신안 심사기준: 불명확 표현 (예2) 목록, "상기 평기어"처럼 지시 대상을 이름으로 쓴다. 목록 단어를 일률적으로 판단하지 않는다.
  - KRISS VIM·GUM 한국어판: 우선 용어 하나를 줄곧 쓴다. "이 뜻으로 쓰지 않는다" 주석을 둔다.
  - 기상청 예보용어(한때, 가끔), 의약품·의료기기 빈도어: 같은 "드물게"가 분야마다 다른 수치다.
- 위험: 개발 문서는 "할 수 있다"를 MAY(허용)로 쓰고, KS는 can(가능)으로 쓴다. 정도어의 정의는 분야마다 다르다. 그래서 보편 표를 싣지 말고 문서나 프로젝트 단위로 선언하게 한다. 재작성에서 모호 동사("반영")를 바꾸면 사실을 지어낸다.
- 규칙 후보(아직 적용 안 함): 의무 표현 어휘표, 모호 업무 동사 결속 규칙, 정도어 수치화, 프로젝트 용어집 연결, 지시어 규칙, 경계 표현. 평가 시나리오부터 만든다.
- 이름 충돌: kdyhg/K-STE(MIT, 2026-05-29 생성)가 있다. 가장 가까운 외국 사례는 mzopedia/simplified-technical-chinese다.
- 제약: 병렬 조사 서브에이전트 여러 개가 WebSearch 한도(200회) 소진을 보고했다. 같은 시점에 메인 세션의 검색은 됐다. 한도의 범위는 확인하지 않았다. 큰 조사는 갈래 수를 줄이거나 원문 URL을 직접 여는 방식으로 한다.

## 2026-10-17 추가 조사: 미확인 항목 정리

- 현행 국방 근거는 방위사업청 「국방규격ㆍ표준서의 서식 및 작성에 관한 매뉴얼」 제2026-02호다. 1.5.6에 금지어와 의무 3단이 남았다. 같은 매뉴얼의 예시문이 금지어("적당한 시간동안")를 어긴다. 그래서 규칙 목록만으로는 지켜지지 않는다.
- 국방기술품질원 「국방 규격 초안 작성 가이드북」(2025): "정상작동"을 범위가 모호하다는 이유로 지양한다. "안정적일 것"은 수치 범위로 바꾸게 한다. 같은 기관은 같은 단어로 부른다.
- 원전 조치동사표(장통일 외, KNS 2010): Ensure와 Verify가 모두 "확인하다"로 옮겨졌다. "확인"은 안전 분야에서도 여러 원어를 합친다.
- KS C IEC/IEEE 82079-1:2019(2023 개정): 한 단계에 작업 하나, 경고는 단계 앞, "표현 하나에, 단순한 의미 하나". 반례: "주의"를 상해(CAUTION)와 재산 피해에 함께 쓴다.
- KS X ISO 704:2009: 단의성, 대체의 원칙, 적합·가능·부적합 용어 구분.
- TTA는 MUST=필수, MAY=선택으로 쓰지만 SHOULD는 표준마다 권고/권장으로 갈린다. ISO/IEC/IEEE 29148은 KS로 채택되지 않았다.
- 저작권: KS 원문에는 "상업적 활용을 금지" 표시가 있다. KS·국방·국립국어원 문장을 저장소에 복사하지 않는다. 규칙 문장과 예문은 직접 쓴다.
- 도구: e-나라표준인증은 viewMachine(일부 표준)이나 viewerAjax와 streamdocs 경로로 KS 본문을 준다. 국가건설기준센터 API는 인증을 요구해서 받지 않았다. Chrome 확장은 연결돼 있어도 탭 조회가 "Tab not found for session ID"로 실패할 수 있다.

## 2026-10-18 독자 패널 평가 (`evals/reader/`)

- 결과: 글 전체를 읽는 LLM 독자는 모든 조건에서 천장(약 99.5%)이었다. K-STE의 이득은 훑어 읽기(+7.9%p)와 길이(-30%)에서, 비용은 "확인 필요"에서 나왔다. 수치는 `evals/reader/README.md`의 결과 절에 있다.
- 실수: Codex 한도 오류를 확인 없이 믿고 3시간을 기다리려 했다. 원인은 계정이었다. Orca는 셸의 `CODEX_HOME`을 계정별 폴더로 지정하는데, 스크립트는 `~/.codex/auth.json`(다른 계정)을 연결했다. 한도 오류가 나면 먼저 `echo $CODEX_HOME`과 기본 설정의 호출을 비교한다.
- 실수: 문항을 "원문을 읽은 독자가 맞힌 것"만 남기면 원문 정답률이 설계상 100%가 된다. 그러면 원문과 비교하는 비열등성 검정은 모든 조건에 불리하다. 20개 원문으로는 3%p 기준을 보일 수 없었다(문항 1개가 0.83%p). 다음에는 선별 독자와 평가 독자를 나누고, 표본 크기를 기준에 맞춰 먼저 계산한다.
- 교훈: 모호하지 않은 사실 메모로 쓴 새 글은 base도 오독이 거의 없다. 천장을 깨려면 모호한 메모, 긴 문서, 훑어 읽기 같은 조건이 필요하다.
- 교훈: "확인 필요"는 독자에게 "알 수 없음"으로 읽힌다. 원문이 실제로 모호해도 정답률은 내려간다. 이 비용과 "뜻을 말없이 바꾸지 않음"(다듬기에서 base와 clarity만 4건)을 함께 보고한다.
- 제약: 블로그 원문과 그 파생물(다듬은 글, 문항, 실행 로그)은 저장소에 올리지 않는다. `.gitignore`에 경로가 있다.
