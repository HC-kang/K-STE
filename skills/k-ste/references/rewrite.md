# 재작성과 검수

## 재작성

다음 순서로 고친다.

1. 원문에서 보존 목록을 뽑는다. 이 목록은 출력하지 않는다.
   - 사실, 수치, 단위, 시점
   - 조건과 예외("~하면", "단,", "~하는 경우")
   - 범위 표지(모두, 만, 까지, 이상, 이하, 최대, 되도록)
   - 정도와 방식을 한정하는 말(완전히, 즉시, 끝까지)
   - 인과 관계("때문에", "따라서", "그래서")
   - 확신 정도("~수 있다", "~로 보인다", "~이다")
   - 의무 강도("해야 한다", "권장한다", "해도 된다", "해 주세요")
   - 행위자(누가 하는가)
   - 상태어("처리", "확인", "반영", "완료", "적용", "조치", "대응", "정상")와 지시어("해당", "위", "관련")
   - 두 가지로 읽히는 곳
2. 규칙(K0-K15)을 어긴 부분만 고친다. 바꾼 문장마다 규칙 ID를 댈 수 있어야 한다. 댈 수 없으면 원문을 둔다.
3. 두 가지로 읽히는 곳은 원문의 표현과 범위를 그대로 둔다. 그 문장을 나누거나 합치지 않는다. 연결어미와 어순도 바꾸지 않는다. 문장을 나누면 조건이 걸리는 범위가 바뀌기 때문이다.
4. 결과를 보존 목록과 대조한다. 목록의 항목이 모두 남았는지, 원문에 없는 것이 생겼는지 본다.
5. 원문의 문체(합니다체, 한다체, 해요체)를 유지한다.

### "짧게" 요청

짧게 하려면 다음 순서로 지운다.

1. 군말: "진행하다", "~하는 것이 필요하다", "~의 경우" 같은 말.
2. 중복: 같은 뜻을 두 번 말한 부분. 앞에 나온 주어를 조건절("~하면")에서 다시 쓴 것은 중복이 아니다. 예를 들어 "이미지 빌드가 끝났는지 확인하고, 실패하면"은 확인이 실패한 경우로도 읽힌다.
3. 한 문장에 정보가 둘 이상이면 문장을 나눈다. 나눌 때 원문의 접속 관계(원인, 결과, 대조)를 "그래서", "하지만"으로 남기고, 뒤 문장에도 주어를 다시 쓴다.

조사, 주어, 조건, 범위 표지, 정도·방식 한정어, 확신 정도, 의무 표현은 지우지 않는다. "~하는 것으로 판단됩니다"는 "~로 보입니다"로 줄인다. "~입니다"로 줄이면 추정이 사실이 된다. "용량 초과 시 삭제" 같은 명사형 압축은 짧아 보이지만 무엇을 삭제하는지 흐린다.

예:
- 원문: "회의실 예약은 최대 2시간까지 가능하며, 이를 초과하여 사용하고자 하는 경우에는 사전에 총무팀의 승인을 받아야 합니다."
- 고친 글: "회의실은 최대 2시간까지 예약할 수 있습니다. 2시간을 넘겨 쓰려면 미리 총무팀의 승인을 받아야 합니다."
- 잘못 줄인 글: "회의실 2시간 제한, 초과 시 승인." 이 글은 "미리"와 의무 표현이 빠졌고, 명사로 끝난다. 누가 승인하는지도 빠졌다.

### 출력 형식

고친 글만 낸다. 다음은 붙이지 않는다.

- 서두("쉽게 바꾼 글입니다", "다음과 같이 다듬었습니다")
- 수정 설명, 변경 목록
- 대안 버전("더 짧은 버전", "캐주얼 버전")
- 원문에 없던 제목("[공지] ...")
- 맺음 제안("필요하시면", "원하시면")

`확인 필요:`는 문맥상 한 해석만 자연스러우면 쓰지 않는다.

가리키는 대상이 원문에 아예 없으면 후보를 지어내지 않는다. 후보로 든 이름도 원문에 없는 사실이다.
예:
- 원문: "지난 점검에서 모든 서버에 보안 패치가 적용되지 않았습니다."
- 잘못 고친 글: "지난 점검에서 어느 서버에도 보안 패치를 적용하지 않았습니다." 원문은 "한 대도 적용되지 않았다"와 "일부만 적용됐다"로 모두 읽힌다. 이 글은 첫 번째 해석을 골랐다.
- 올바른 출력: 원문을 그대로 둔다. 그리고 아래에 "확인 필요: '모든 서버에 보안 패치가 적용되지 않았습니다'. 한 대도 적용되지 않았는지, 일부 서버만 적용되지 않았는지 정해지지 않았습니다."를 붙인다.

원문의 상태어("처리", "확인", "반영", "완료", "적용", "조치", "대응", "정상")와 지시어("해당", "위", "관련")는 다른 동사나 이름으로 바꾸지 않는다. "[문서명]" 같은 자리표시자로도 바꾸지 않는다. 바꾸면 원문에 없는 사실이 생긴다. 무엇을 가리키는지에 따라 독자의 행동이 달라지면 `확인 필요:`로 묻는다. 문맥상 뜻이 하나로 정해지면 묻지 않는다.

예:
- 원문: "요청하신 계정 권한은 처리해 두었습니다."
- 잘못 고친 글: "요청하신 계정 권한을 부여했습니다." 원문은 권한을 부여했는지 회수했는지 말하지 않는다.
- 올바른 출력: 원문을 그대로 둔다. 그리고 아래에 "확인 필요: '처리해 두었습니다'. 계정 권한에 무엇을 했는지 원문에 없습니다."를 붙인다.

원문이 이미 규칙을 지키면 원문을 그대로 낸다. 그리고 고칠 곳이 없다는 한 줄을 원문의 문체로 붙인다.

사용자가 수정 이유나 비교를 요청하면 검수 표 형식으로 낸다.

### 흔한 합리화

| 생각 | 실제 |
|---|---|
| "안내문이니 '제출해야 합니다'를 '제출해 주세요'로 부드럽게 바꾸자." | 의무가 요청으로 약해진다. K0 위반이다. |
| "중요한 내용이니 '반드시'를 더하자." | 원문에 없는 의무다. K0 위반이다. |
| "최대한 짧게 해 달라고 했으니 조사와 주어를 빼자." | 짧게 쓰려면 군말과 중복을 지운다. 조사, 주어, 조건은 남긴다(K3). |
| "문장을 나눴으니 '따라서', '그 결과' 같은 연결어는 지우자." | 앞 문장이 뒤 문장의 이유라는 정보가 사라진다(K0, K2). "그래서"로 남긴다. |
| "'모두', '즉시', '끝까지' 같은 부사는 군말이니 지우자." | 정도와 방식을 한정하는 말은 조건이다(K0). "모두 삭제한다"와 "삭제한다"는 다른 지시다. |
| "짧게 하려면 '제출해야 합니다'를 '제출합니다'로 줄이자." | 의무가 사실 서술로 바뀐다(K0). 의무 표현은 남긴다. |
| "'인증서를 점검하고, 문제가 있으면'의 대상을 분명히 하자." | 원문이 인증서를 가리키면 "인증서에 문제가 있으면"으로 쓴다. 원문에 대상이 없으면 짐작하지 않고 `확인 필요:`로 묻는다(K0). |
| "쉽게 바꾸려면 용어 풀이를 붙이자." | 원문 독자가 이미 아는 용어에 풀이를 더하면 글만 길어진다. 틀린 풀이는 뜻을 바꾼다(K8). |

## 검수

다음 표로 낸다. 행은 원문에 나오는 순서로 쓴다.

```
| 규칙 | 원문 | 고친 글 |
|---|---|---|
| K9 | 서버 점검을 실시할 예정입니다 | 서버를 점검할 예정입니다 |
```

- 원문에 정보가 빠져서 고칠 수 없는 곳(누가, 언제, 얼마나)은 고친 글 열에 "정보 없음: <빠진 정보>"라고 쓴다. 빠진 정보를 지어내지 않는다.
- 표 아래에는 고친 전문을 한 번 쓴다. 고친 전문에도 지어낸 사실을 넣지 않는다.
